# 测试规范与方式

测试与调试手段按侵入程度分三级，从低到高逐级升级：**能 Remote 不重编译，能重编译不碰鼠标**。

## 1. Remote 测试（BRP）——首选

- 前提：宿主运行时带 `bevy_remote`（3.12 起 ash_renderer 默认开启，HTTP 端口 15702），App 处于运行状态。
- 工具：`tools/brp.py`（3.12 薄客户端）；可用官方内置方法族 + 宿主三个场景语义自定义方法（`src/remote.rs`）。
- 适用：组件/资源当前值检查、实体关系查询、经自定义方法触发的写操作与行为验证。
- 优点：零代码改动、零重编译、不占用输入设备，App 全程持续运行。
- 边界：只能看到已落为组件/资源的 CPU 侧状态；GPU 侧状态与帧内时序不可见，属第 2 级的领地。
- **扩建优先级（2026-10-10 用户定案）：需要新的变更驱动或写操作手段时，优先扩 BRP 自定义方法族，不写一次性探针或临时 UI 按钮。**缘由：①方法可复用——后续段测同类变更走同款通道；②BRP 住外层（`src/remote.rs`），不污染 lowlevel 代码；③沉淀为引擎工具面；④BRP 面=AI 能力面，给自动化验收更多可调用的操作。临时探针保留给"验证一次即删"的内部诊断（3.10 惯例场景），不承担变更驱动。

## 2. 打 Log + 重新编译

- 适用：Remote 观测不到的内部路径——渲染队列内容、管线/资源选择、生命周期时序、GPU 提交前的 CPU 侧数据、帧内执行序。
- 方式：在目标代码位置加 log，重新编译运行后复现问题，从输出取证。
- 调试用的临时 log 属于临时取证手段，随该次测试任务收敛清理；确有长期价值的保留时须注明理由。

## 3. 控制鼠标——仅限无人模式

- 真实输入注入（移动光标、按键、拖拽、抢焦点）只在用户声明"无人模式"的当次任务中执行，授权不跨会话、不默认延续。
- 适用场景：Remote 与 log 都覆盖不了的真人输入链路——相机 orbit、egui 命中/拖选、焦点行为等。
- 完整红线与既证坑点见《鼠标操作与输入注入纪律》。

## 与其他规则的关系
