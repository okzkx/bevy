# 临时文件与工具脚本存放

> 适用场景：任何在仓库内落盘的临时产物（运行日志、审计输出、临时截图、调试转储、探针中间产物等）与工具性 Python 脚本的存放位置。对仓库全部工作目录生效，不限于 `ash_renderer`。

## 规则

### 1. 临时文件统一进 `.temp/`

- 所有临时文件一律写入仓库根的 `.temp/` 文件夹，不在源码目录、示例目录或仓库根散落。
- `.temp/` 必须保持被 `.gitignore` 忽略（条目 `.temp/`），任何临时文件不得被跟踪、提交或出现在 `git status` 中。
- `.temp/` 内容无长期价值，可随时整目录删除；需要留档的结论写入文档，不靠临时文件本身留存。

### 2. Python 工具脚本统一进 `tools/`

- 可复用的 Python 脚本（截图取证、输入注入、审计、批处理等工具性脚本）一律放在仓库根 `tools/` 文件夹。
- 脚本按用途命名，可直接 `python tools/<脚本>.py` 运行；文件头注释写明用途与调用方式。
- `tools/` 内的脚本是仓库正式文件，正常提交跟踪；脚本运行产生的临时输出必须落 `.temp/`（新写脚本默认把输出路径指向 `.temp/`，不写死在源码目录旁）。

## 原因

临时文件散落在源码目录会污染 `git status`、干扰分支操作（合并/变基要求干净工作区，散落的未跟踪文件会让每次操作多一步 stash）并有被误提交的风险；统一进被忽略的 `.temp/` 后这些成本归零。工具脚本集中 `tools/` 与临时输出分离，是为了"脚本可复用可入库、产物可丢弃可清理"两条生命周期互不牵连。
