# 画面功能视觉验证

> 适用场景：`ash_renderer` 实现了一个大的画面功能（新渲染能力首画、光照/材质/UI overlay 等画面有可见变化的段或任务）收尾时。纯数据链路、无画面变化的功能不适用。

## 规则

### 1. 截图取证

- 按窗口句柄用 PrintWindow 抓图，不用全屏截图——前台全屏应用会遮挡目标窗口，造成"画面冻结"假象。
- 主窗口选择用 EnumWindows 按 PID + 可见 + 有标题 + 最大面积过滤，避免选到 winit 事件窗；DPI 125% 下 PrintWindow 尺寸与 swapchain 尺寸不同，记录尺寸时注明来源。
- 测量坐标/注入输入的脚本进程要先 `SetProcessDpiAwareness(2)`，否则 GetClientRect/SetCursorPos 全部被虚拟化（÷缩放系数），量出的"尺寸不匹配"是测量通道的假象。

### 2. 当前模型读图验证

- 截图落盘后，用当前会话模型直接读图（Read 工具读 PNG）做视觉验证，不依赖外部视觉模型服务。
- 提问要携带"期望画面描述"（本功能应当画出什么），先描述实际看到的内容，再对照预期找异常：黑屏、花屏、缺几何、颜色/光照明显异常、UI 错位等。
- 结论分三档如实记录：通过 / 发现异常（列具体现象）/ 无法判定；"看了一遍没发现问题"不得写成"画面正确"。

### 3. 判定线

- **视觉验证是外观 sanity check，不替代既有验收证据**：零 VUID 运行、判定线数值、退出码、截图哈希等仍按原标准执行，两者互补。
- 验证结果随施工记录入档（结论 + 截图路径）；报告异常时先排除截图手法问题（遮挡、DPI、抓图时机），再定位渲染问题。

## 原因

画面正确性最终以肉眼所见为准；大画面功能只用日志和数值验收，"跑通零 VUID 但画面黑屏/错乱"这类问题会被漏掉。当前模型直接读图省去外部模型服务依赖，把"看起来对不对"从主观确认变成可记录、可复核的验证证据。
