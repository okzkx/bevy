# 登记处与记录文件夹规范

> 适用场景：项目里“需求清单 + 实现记录”类文档的落位与维护——当前为 `开发步骤/待修复清单/` 与 `开发步骤/外置拓展需求/` 两个登记处；新增同类登记处照此办理。

## 目录结构

```text
开发步骤/
├── 待修复清单/
│   ├── README.md              ← 材料目录（读法 + 条目记录索引）
│   ├── 待修复清单.md           ← 正本（唯一登记处）
│   └── 1.显存纹理压缩/         ← 已完成项记录（每项一个文件夹）
│       └── 显存纹理压缩施工记录.md
└── 外置拓展需求/
    ├── README.md              ← 材料目录（读法 + 条目记录索引 + 条目索引）
    ├── 外置拓展需求.md         ← 正本（唯一登记处）
    └── N.<条目名>/             ← 已开工/完成条目（当前暂无）
```

## 规则

### 1. 三件套：README + 正本 + 逐项记录

- **正本是唯一登记处**：条目的来源 / 内容 / 状态 / 关闭条件写在正本里；施工叙事与读数不进正本正文。
- **README 只做材料目录**：写读法、状态口径与“条目记录”索引表（文件夹 → 内容 → 对应条目 → 状态），不重复登记条目。
- **记录放逐项文件夹**：每完成一项（外置条目为“已开工”即可）在该登记处下建 `N.<名称>/` 子文件夹，施工记录、选型与实测数据放进去。

### 2. 编号与勾掉

- `N` 用清单里的条目编号（待修复清单 §9 的 1、2…；外置拓展条目 1～16），目录内唯一、只增不复用。
- 完成后在正本里把条目勾掉 ✅（待修复清单写状态或条目后标注；外置拓展在条目标题或条目后标注）；条目本身保留，不物理删除。
- 走追加段转正的条目按原流程移出正本或标记已转正，记录文件夹留在登记处。

### 3. 命名与配套

- 文件夹名用 `N.<名称>`（如 `1.显存纹理压缩`），与开发步骤的 `N-中文名/` 区分：步骤用连字符，登记项用点号。
- 正本、README、记录文件夹三者随同一功能一起提交；新增或移动记录时同步更新 README 索引与相关链接。

## 原因

- 需求清单会随会话累积，正文里混施工叙事会迅速膨胀；把“登记”与“记录”分开，正本保持可扫描，记录可按项归档与引用。
- 逐项文件夹与开发步骤“每段一个文件夹”同构，查找路径一致；README 提供入口，避免登记处变成一坨平铺文件。
- 编号保留不复用，历史引用不失效。
