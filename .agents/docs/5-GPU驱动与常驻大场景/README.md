# 步骤 5：最小 GPU-driven 与常驻大场景（M4）

对应[执行路线图](../学习目标实现步骤.md)。本 README 是步骤索引与材料目录；各段任务面板在段目录 README（开工时立），段施工计划随立案入段目录。

**目的**：先让 GPU 独立决定画哪些实例，再扩大规模；不能用逐对象 CPU draw 的结果验证 GPU-driven 大场景目标。

**完成标准**：小场景验证正确后再扩到 1 万、5 万、10 万档实际渲染实例；CPU 不回读可见集、不逐对象重建 draw list。1 万为起始档、5 万为目标档、10 万为压力档，能承载的规模由测量给出，不预先声称三档都能达到固定帧率。

**当前验收状态：⬜ 已立案（2026-10-15 用户指令，纯文档立案）——[施工计划：最小GPU驱动闭环与常驻大场景五段拆解](施工计划：最小GPU驱动闭环与常驻大场景五段拆解.md)已建；**5.1 段目录与[段施工计划](5.1-常驻绘制数据/施工计划：常驻绘制数据拆解.md)已同日立案，5.2~5.5 段目录开工时立；未施工。**

**场景与规模定案（2026-10-15）**：5.1～5.3 以 FlightHelmet 小场景验正确性；5.4 起交付"常驻大场景生成器"程序化铺实例（bevy_city 参照），不找更大 glTF；5.5 按 1 万/5 万/10 万三档压测。

## 施工顺序

| 段 | 文件夹 | 范围 | 状态 |
|---|---|---|---|
| 5.1 | [5.1-常驻绘制数据](5.1-常驻绘制数据/README.md) | 实例、mesh 范围、材质索引与包围体驻留 GPU；从逐 draw push constants 过渡到 GPU 按实例索引读取；顺带处理 3.6 立账的 host/frames 摊薄结构债 | ⬜ 已立案（2026-10-15：段目录+施工计划已建，未施工） |
| 5.2 | `5.2-GPU视锥剔除`（开工时立） | compute 生成可见标记；前置闸门 = compute 环境四件（队列族/编译链/spirv-val/空转首跑）；明确 compute 写到绘制读取的依赖 | ⬜ 已立案（2026-10-15） |
| 5.3 | `5.3-indirect闭环`（开工时立） | GPU 写 indirect 参数、GPU 可取得对象/材质索引、图形提交消费结果；起步口径 = 固定槽位、不可见 `instanceCount=0` | ⬜ 已立案（2026-10-15） |
| 5.4 | `5.4-常驻大场景组织`（开工时立） | 常驻大场景生成器（程序化铺实例）+ 共享资产大量实例、空间 chunk 身份与边界、整块增删；补基础 mip 链；数据先全常驻 | ⬜ 已立案（2026-10-15） |
| 5.5 | `5.5-分档压测`（开工时立） | 按"统一验收与性能口径"测 1 万/5 万/10 万三档实例规模、静态/动态比例与成本增长 | ⬜ 已立案（2026-10-15） |

一次只施工一段：5.1→5.2→5.3 是同一条依赖链（数据常驻→GPU 剔除→indirect 消费），顺序不可倒置；5.4 依赖 5.1～5.3 成立后扩规模，5.5 收口压测。验证与讲解后消化，再进下一段。
