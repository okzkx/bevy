# 5.2.1-5.2.5 GPU 视锥剔除施工记录：compute 管线、可见标记与验证通道

> 2026-10-15 当日立案当日施工（/plan-execute，分支 `goal/5.2`）。对应[段施工计划](施工计划：GPU视锥剔除拆解.md) §3 任务拆解：5.2.1 前置闸门 → 5.2.2 可见标记与视锥数据 → 5.2.3 compute shader 与 dispatch → 5.2.4 验证通道 → 5.2.5 验收回归。本文记"实际做了什么"与待决落定；机制讲解归[流程导读](GPU视锥剔除流程：从相机平面到标记环的各级账面.md)，立案动机归[段施工计划](施工计划：GPU视锥剔除拆解.md)。
> **一句话说明**：5.2 用一个 compute shader 每帧对 GPU 常驻对象表逐实例做"世界包围盒 vs 视锥六平面"求交并写出可见标记，让 GPU 自己判断谁该画，为 5.3 indirect 只画可见部分铺路；本段只验"标记算得对"，不改画面、不做规模压测。

## 1. 前置闸门（5.2.1）：compute 环境四件

四件按序过闸，全部留痕：

1. **图形队列族 compute 支持**：立案期核实选族只过滤 GRAPHICS（`context.rs` find 谓词）；施工把 COMPUTE 升格为选族硬条件（不支持即出局，1.3 基线同纪律——"compute 是 1.0 core 无 feature 位"不等于"不用钉"）。RTX 2060 实测：图形族 0 = GRAPHICS+COMPUTE+PRESENT，就绪日志钉明。**同族同队列定案**：dispatch 录在图形命令缓冲内，无跨队列信号量。
2. **naga compute 编译链**：build.rs 本就按模块整体编译（无 stage 过滤），新落 `cull.wgsl`（`@compute @workgroup_size(64)`）直接过全链。**闸门①②顺手实撞一枚钉子**（见 §4 钉 1：新增 .wgsl 不触发 build.rs 重跑）。
3. **spirv-val**：`--target-env vulkan1.3` 原生通过、零补丁（compute 模块不含 descriptor indexing 面板，补丁器路径不触发）。
4. **compute pipeline 空转首跑**：`CullPass::new`（shader module → layout[set2] + 112B COMPUTE push range → `vkCreateComputePipelines`）+ 首个有实例帧的 dispatch，验证层零 VUID。首跑实撞 VUID-07988/08600（见 §4 钉 2），订正后三进程零 VUID。

## 2. 数据面与消费面（5.2.2/5.2.3）

- **标记环（第四族）**：`InstanceTables` 增 `mark_rings`——HOST_VISIBLE `BufferRole::Storage` ×2 帧槽（131072 槽 × 4B = 1MB/槽），与模型/材质环同链（`wait_for_slot` fence 纪律）。**compute 每帧全量重写本帧槽**（dispatch 上界 = 实例槽 bump bound）；开关关闭时 host 直接填全可见（零 GPU 工作的 A/B B 面）。set2 扩 b3（read_write storage，stage 收窄 COMPUTE-only；b0/b1/b2 超集声明不动），描述符仍 init 一次写入。
- **视锥平面走 push constants（112B）**：CPU 从 view_proj 提取六平面（Gribb-Hartmann，D3D 型 clip volume：near=row2、far=row3−row2；identity 下的半空间=NDC 盒由单测钉死），+ bound 打包 `pack_cull_push`。**对立案倾向的偏离**：计划倾向"平面随帧 UBO 走"，施工核实 UBO 128B 恰满（pad 只是 16 对齐垫）——扩 UBO 要动 graphics WGSL + descriptors 三方断言链；帧级全局量每帧一次 push 是 push constants 的本职（5.1 退役的是**逐对象** push，不是帧级 push），改走 112B push，graphics 侧零涟漪。
- **compute shader**：`cull.wgsl`——8 角点世界推导（与 CPU 参照 `conservative_world_aabb` 同款，判定线 1 逐位可比）→ 六平面 p 顶点保守求交（法线不归一化，只看符号）→ 写 `marks[slot]`（普通 store，每 invocation 写互不重叠槽，无原子）。bound 外的槽不写（陈旧值只被停尸房/free list 在途槽占用，账本行永不枚举）。
- **消费面**：本段无 GPU 消费者（绘制侧零改动，画面不变）——判定线 3 的屏障是 5.3 预置形状；标记环的现役读者只有宿主诊断（每帧读数进 `CullDiagnostics`）与 BRP 对照。

## 3. 验证通道（5.2.4）

- **egui**："ash 调试"面板新增剔除段——checkbox（写 `CullSettings`，`AshHostPlugin::build` init_resource）+ 读数行"标记 可见 X/Y 行（bound Z，帧槽 N 读数，诊断不驱动绘制）"。
- **BRP**：`remote/cull.rs` 两方法——`ash_renderer/cull_stats`（GPU 标记 vs CPU 参照逐实体对照 + mismatch 清单 + 陈旧性说明）、`ash_renderer/cull_set_enabled`（开关写）；`brp.py` 增 `cull-stats`/`cull-set` 子命令（合计十八）。handler 在 RemoteLast 跑，`&mut World` 直取账本/池/标记环——零一次性探针（测试规范"BRP 优先"）。
- **A/B 数据层开关**：`cull-set --enabled false` → host 全可见填充 → gpu_visible=7/7（视锥外对象也被标可见，与 CPU 几何参照差 1 = 开关语义本身，非 bug）；恢复 true → 6/6 零 mismatch。画面两态一致（标记不进绘制路径）。

## 4. 钉子（施工实撞与取舍）

1. **新增 .wgsl 不触发 build.rs 重跑**：`rerun-if-changed=目录` 声明在位，但首次 `cargo build` 未跑 build.rs（cull.spv 缺席、include_bytes! 未报错——lib 尚未引用）。`touch build.rs` 强制重跑后闸门②③一次过。3.4 的旧注释已说明此坑（"逐文件声明只盯已知文件"），本次实锤：**目录声明对"新增文件"生效的前提是 build.rs 本身被调度**，首个新 shader 的落地轮必须手动 touch 一次。
2. **组号随管线布局走，不随描述符集对象的"出身"**（首跑 VUID-07988/08600 实抓）：set2 描述符集对象在 InstanceTables 的命名里叫"set2"（图形管线布局 [set0,set1,set2] 的位次）；compute 管线布局只挂这一个 set，shader 里必须写 `@group(0)`——初次按惯性写 `@group(2)`，创建与 dispatch 双双被验证层拒（"binding was not declared in pSetLayouts[2]"）。订正：cull.wgsl 全部 `@group(0)`，binding 号不变（0/1/3）。**判定线 3 的同步验证层在 device 侧真实执法**——与"host 写全盲"互补的另一面，这次抓的是真错。
3. **标记环 HOST_VISIBLE 选型**（`BufferRole::Storage`，与立案计划一致）：本段标记的读者是宿主诊断（每帧直读、fence 纪律内两帧陈旧），DEVICE_LOCAL 反而要铺 staging 回读路径。**翻面条件**：5.3 GPU 消费进来（compute 读标记组装 indirect）时评估迁 `DeviceStorage`——迁移 = 角色改名 + 验证路径换 readback，描述符与 shader 不动。
4. **dispatch 上界 = bump bound（`used_object_slots`）**：free list 归还槽号恒小于 bump 游标，bound 覆盖在场/在途全部槽；bound 内的停尸房在途槽被 compute 用旧记录算出旧标记——无人读（账本行只枚举在场槽），非 hazard。全容量 131072 dispatch 浪费 99.9% workgroup，bound 上界是正确性与成本的双赢（待决 6 落定）。
5. **画面对照的"零回退"在本段有了新含义**：5.2 引入了每帧 dispatch 与新 buffer，但绘制路径零改动——三模式截图与 5.1 基线一致是"新半边静默"的直接证据（判定线 5），比纯回归多验了一层"剔除不越权"。

## 5. 待决落定（立案计划 §5 七项全落定）

| 待决 | 落定 | 依据 |
|---|---|---|
| 1 屏障 API 形状 | 传统 `cmd_pipeline_barrier`（sync2 不启用） | 立案期核实+用户知情；buffer/global barrier 覆盖 compute→graphics，本段够用 |
| 2 视锥平面来源 | CPU 算好随 **112B compute push**（非 UBO） | UBO 128B 恰满，扩容涟漪大；帧级全局 push 是本职（对计划倾向的偏离，见 §2） |
| 3 标记组织 | 1 字 u32/槽 + HOST_VISIBLE + set2 b3 | 验证直读优先；1 位/DEVICE_LOCAL 留翻面条件（§4 钉 3） |
| 4 AABB GPU 形状 | 8 角点重紧（与 CPU 参照同款） | 判定线 1 逐位可比的前提 |
| 5 画面级 A/B | 数据层 A/B 在 5.2、画面级顺延 5.3 | 2026-10-15 用户拍板（无脚手架；顶点级剔除方案否决） |
| 6 compute 提交形状 | 图形命令缓冲内 dispatch（同族同队列） | 闸门①实测图形族含 COMPUTE；无跨队列同步 |
| 7 诊断性回读 | 放行——每帧读数进诊断账面，单独标注 | 2026-10-15 用户拍板（只进计量，不驱动绘制） |

## 6. 遗留与顺延

- 画面级 A/B（"只被剔除的不可见"）归 5.3 判定线⑤（主计划已接收挪入）。
- `CullDiagnostics` 读数为每帧全量读（bound×4B memcpy）——小场景零负担；5.4 规模化时若成为热点，改增量或低频。
- 真实透视相机的端到端 BRP 对照已验（helmet 场景 + set_transform），透视投影的平面提取未做专门单测（identity/正交单测钉提取约定，与投影类型无关的行组合）。
