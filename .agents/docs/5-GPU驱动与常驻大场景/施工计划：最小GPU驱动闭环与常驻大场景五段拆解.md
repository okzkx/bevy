> 2026-10-15 立案（用户指令，纯文档立案）。对应[路线图](../学习目标实现步骤.md)步骤 5：先让 GPU 独立决定画哪些实例，再扩大规模。本文管步骤 5 做什么、按什么顺序、验收什么；段目录与段级施工计划开工时立（一次只施工一段），"实际做了什么"开工后另立施工记录，不回写本文。

> **场景与规模定案（2026-10-15）**：**5.1～5.3 以 FlightHelmet 小场景验正确性**——小场景足以暴露数据依赖、剔除与 indirect 的错误；**5.4 起小场景不够**，交付"常驻大场景生成器"程序化铺实例（bevy_city 为参照不是底座），不找更大的 glTF 文件；**5.5 按 1 万/5 万/10 万三档压测**（起始档/目标档/压力档），能承载的规模由测量给出。

## 0. 定位：现状与要换掉的东西

M2 前置契约已注明"全量拓扑快照与逐 draw push constants 是阶段实现，不是步骤 5 的终态"。步骤 4 之后**增量侧已经成立**（`InstanceLedger` 稳态零盘点零上传），但**绘制侧仍是 M2 形状**：

- DrawList 每帧由账本行重建，CPU 绘制调用数随在场对象数线性增长；
- 逐对象绘制参数走逐 draw push constants（`vulkan/frames.rs` 两处 `cmd_push_constants` + `cmd_draw_indexed` 实证），CPU 必须逐对象推送；
- 可见性 = 全画：无剔除，无 indirect。

步骤 5 把这三件事依次交给 GPU，三段是同一条依赖链：**5.1 绘制数据常驻**（GPU 按实例索引读，push constants 退役）→ **5.2 GPU frustum 剔除**（compute 写可见标记）→ **5.3 indirect 闭环**（GPU 写绘制参数，CPU 提交与对象数解耦）。5.1 不收官则 5.2 没有可剔除的数据底座，5.3 依赖 5.2 的可见集——顺序不可倒置，一次只施工一段。5.4 扩规模、5.5 压测收口。

## 1. 五段拆解

| 段 | 交付范围 | 判定线草案（独立验收） |
|---|---|---|
| 5.1 常驻绘制数据 | 实例、mesh 范围、材质索引与包围体驻留 GPU；从逐 draw push constants 过渡到 GPU 按实例索引读取 | CPU 不必逐对象推送绘制参数（push 字节数与对象数解耦）；非均匀缩放等变换下包围体保守正确 |
| 5.2 GPU frustum | compute 生成可见标记；明确 compute 写到绘制读取的依赖 | 不做 CPU 每对象可见性剔除，不回读可见集驱动绘制 |
| 5.3 indirect 闭环 | GPU 写 indirect 参数、GPU 可取得对象/材质索引、图形提交消费结果 | CPU 绘制调用不随对象数线性增长；固定槽位且不可见 `instanceCount=0` 即可起步 |
| 5.4 常驻大场景组织 | 常驻大场景生成器 + 共享资产大量实例、空间 chunk 身份与边界、整块增删；补基础 mip 链；数据先全常驻 | 对象复用和块边界可观察，合并不破坏独立运动、剔除与后续卸载粒度 |
| 5.5 分档压测 | 按路线图"统一验收与性能口径"测实例规模、静态/动态比例与成本增长 | 报告实际实例数、CPU/GPU 时间、显存与瓶颈，不只给"流畅"截图 |

### 5.1 常驻绘制数据

- **交付**：把对象信息驻留成 GPU 可按实例索引读取的结构——mesh 池区间索引、材质/贴图槽索引、Transform、包围体（含非均匀缩放的保守处理）。全局每帧数据（相机/光照）留 UBO 不动，逐对象 push constants 退役；shader 改为按实例索引读对象表。DrawList 的终态（全退役 vs 退化为槽位枚举）施工时定。
- **落点**：`vulkan/resources.rs` / `vulkan/pool.rs`（表与池）、`vulkan/frames.rs`（提交侧）、shader 侧（build.rs 编译链已通，接口变化）。
- **顺带债**：3.6 立账的 host/frames 摊薄结构债，原定兑现位就是"步骤 5 GPU-driven 结构大改"——随本段表结构改造一并处理，避免两次返工（见[3.6 段索引](../3-静态取数链路/3.6-代码全量整理/README.md)）。
- **判定线**：①push constants 每帧字节数与在场对象数解耦；②非均匀缩放 + 旋转下包围体保守正确（旋转后仍包住几何，取样验证不误剔）；③画面与 4.x 基线一致（三模式截图零回退）——本段换数据通路不换渲染结果；④4.x 判定线零回退（稳态零上传零盘点）、零 VUID、WM_CLOSE exit 0、clippy 全净。

### 5.2 GPU frustum

- **前置闸门**（最先做，独立小任务）：compute 环境四件——图形队列族 compute 支持确认（当前按打分选族未显式查 compute，施工时实测钉明；备选=独立 compute 队列族）、naga compute WGSL→SPIR-V 编译链验证（build.rs 现只走图形入口）、spirv-val 过、compute pipeline 首跑空转通过。当前 1.2/1.3 只启用了 timeline_semaphore、descriptor_indexing、dynamic_rendering，compute 是 1.0 core 无 feature 开关，但**支持≠验证，前置闸门补齐前不开工本段主体**。
- **交付**：compute shader 对对象表做视锥→可见标记；compute 写→图形读的依赖显式化（barrier 形状，synchronization2 已启用）。
- **判定线**：①可见标记与 CPU 参照对照一致——**CPU 参照只做正确性验证，不驱动绘制**；②CPU 每对象剔除不存在、可见集不回读驱动绘制（红线，与 5.3 共同遵守）；③剔除开关 A/B 画面一致（只被剔除的都不可见）。

### 5.3 indirect 闭环

- **交付**：compute 写 indirect 参数（`drawIndirectCount` 为 1.2 core、`multiDrawIndirect` 为 1.1 core，进程已请求 API 1.3，无需额外 feature——施工时以 capability 日志钉明）；图形提交消费 GPU 写的参数；起步口径 = **固定槽位、不可见 `instanceCount=0`**（路线图已定，不做压缩合批起步）。
- **判定线**：①CPU 绘制调用数固定不随 N 增长（1 万档实测读数）；②不可见对象 `instanceCount=0` 且不产生对应 GPU 工作；③不回读可见集（红线）；④5.1/5.2 判定线零回退。

### 5.4 常驻大场景组织

- **交付**：**常驻大场景生成器**（程序化铺实例：共享资产大量实例、规模参数化、随机种子固定可复现；运行期 spawn 复用 4.1 账本链路为倾向方案，待决见 §5）+ 空间 chunk 身份与边界、整块增删接口 + 基础 mip 链 + 数据先全常驻。bevy_city 的消息驱动加载、observer 补组件、静态变换优化、车型内部网格合并是**借鉴点不是照抄**——它主要是全量生成的压力场景，`merge_car_meshes` 是车型内部合并再跨车辆复用，不是全城大网格或完整流送系统。
- **判定线**：①对象复用和块边界可观察（BRP/计量读数 + 读图）；②整块增删走 4.1 增量链路，不触发全量重传（增量计量读数为证）；③若有静态零件合并，不破坏独立运动、剔除与后续卸载粒度；④mip 链上屏不糊不闪、包围体在 mip 层级间自洽；⑤数据全常驻期间无按需加载路径（流送归步骤 6）。

### 5.5 分档压测

- **交付**：按路线图"统一验收与性能口径"§1～§7 对 1 万/5 万/10 万三档测量，覆盖零变化/少量变化/全动态与静态/动态比例。
- **判定线**：①报告实际实例数、CPU/GPU 时间（p50/p95/p99）、显存与瓶颈归因；②静态场景仅移动相机时不重传全部实例；③若仍有 O(N) CPU 扫描如实报告；④预算先写后测（16.7 ms 初始预算、通过阈值开跑前固定），不以"肉眼流畅"替代数据。

## 2. 边界（不主张什么，归哪一步）

- **Hi-Z 遮挡、GPU LOD、粗/细粒度流送、mip 细粒度驻留** → 步骤 6（6.1～6.4）；5.4 只补基础 mip 链、数据先全常驻。
- **descriptor buffer 实验** → 6.5 独立专题，不并入。
- **CPU 侧每对象可见性剔除** → 5.2 明确不做；"CPU 不回读可见集"是 5.2/5.3 共同红线（诊断性计数回读是否放行、以什么边界放行，施工时钉明并单独标注）。
- **mesh shader / compute 驱动顶点生成** → 不在 M4 范围。
- **F22（IME 桥接）、计量欠账、小账两保留项** → 留[待修复清单](../待修复清单.md)不搭车；**F1（槽位 churn）**按路线图闸门口径随 5.1 容量设计评估，不把未复现项写成运行级已过。
- **全城大网格合并**不是主张：默认先实例复用，仅当兼容材质、运动方式与 chunk 边界才考虑静态零件合并，且须过 5.4 判定线③。

## 3. 测试方案与证据形态

- **BRP 优先惯例延续**（测试规范"扩建优先级"条）：spawn/despawn/replace/set_transform/load 方法族已在库（4.1/4.3 收官），大场景驱动 = 生成器 + BRP 增删改；brp.py 子命令随需扩，不为一次性验证写临时探针。
- **计量分报**：延续 4.x 五项（扫描数/处理数/上传字节/存量/耗时）+ 新增 CPU draw 调用数、push constants 字节数、可见集计数；egui 计量面板挂现有 overlay（3.7 底座）。
- **截图读图**按[画面功能视觉验证](../../rules/画面功能视觉验证.md)执行：PrintWindow + 当前会话模型读图。
- **回归矩阵**：3.5 三模式截图零回退、全程零 VUID（含拆 Device）、WM_CLOSE exit 0、clippy 全净；compute 引入后补"resize/最小化与 compute 资源生命周期共存"一条。
- **性能记录**条件固定（统一口径 §2：提交版本、GPU/驱动、Release、分辨率、材质光照、present、节流、种子、相机轨迹）。

## 4. 待决问题（施工时钉明，不写死）

- **compute 队列族与依赖形状**：图形队列兼用 vs 独立 compute 族；compute→draw barrier 落点与是否涉跨族所有权（5.2 前置闸门一并钉明）。
- **对象表布局**：独立 storage buffer vs 既有 bindless 双表扩展；与 `InstanceLedger` 行的映射（槽位即实例索引，沿用 4.1 稳定槽语义）。
- **DrawList 终态**：全退役 vs 退化为槽位枚举。
- **包围体表示**：世界空间 AABB vs 球；非均匀缩放保守化时机（CPU 上传时预扩 vs GPU 读时变换）。
- **可见标记组织**：每对象 1 位/1 字；是否引入压缩合批（若做须过 5.4 判定线③）。
- **生成器形态**：运行期 spawn（复用增量链路、BRP 可观测）vs 程序化生成 glTF 走 3.1 加载链——倾向前者，施工时钉明。
- **chunk 粒度**（空间网格 vs 生成批次）与"整块增删"的 BRP 入口形状。
