>
> **一句话说明**：这一段是 GPU-driven 的地基——逐对象绘制参数从 CPU 逐 draw 推送换成 GPU 常驻三表（对象表写一次、模型环增量、材质环全量重写），shader 按实例索引读表，push 从 96B 缩到 4B。剔除和 indirect 归 5.2/5.3，本段只立"数据在 GPU 上"。
> 本文管 5.1 段做什么、按什么顺序、验收什么；"实际做了什么"开工后另立施工记录，不回写本文。段任务面板随开工转[段 README](README.md)。

## 0. 判定线（验收草案）

1. **逐对象绘制参数不再走 CPU 推送**：现 96B/对象的 `PushData`（model 64B + 贴图/采样器槽 + base_color）全部进 GPU 常驻表；push 每帧只余全局量 + 每对象 ≤4B 实例标识（若 gl_DrawID 直读路线可行则做到每对象 0B，施工钉明）；mesh 范围（vertex_base/first_index/index_count）同样离开 CPU 组装。计量新增"push 字节/帧"读数。
2. **画面与 4.x 基线一致**：3.5 三模式截图零回退——本段换数据通路不换渲染结果。
3. **包围体数据正确**：非均匀缩放 + 旋转下包围体保守包住几何（取样对照参考计算/手算）；**剔除消费端到端的保守性归 5.2 判定线**，本段只验数据形状正确（5.1 包围体入库不生效）。
4. **增量链零回退**：稳态零上传零盘点保持；移动只动一行（对象表对应槽字节差 = 该行）；换柄只换绑；材质内容变化只更新材质表对应行（4.2 通道）；4.1~4.4 判定线全量回归。
5. **既有判定线零回退**：全程零 VUID（含拆 Device）、WM_CLOSE exit 0、clippy 全净。

计量对齐"统一验收与性能口径"§1/§3：对象表槽位数、材质表槽位数、push 字节/帧、上传字节（对象表/材质表分列）四项新增读数与既有五项并存。

## 1. 定位：现状与要换掉的东西

M2 前置契约明文"逐 draw push constants 是阶段实现，不是步骤 5 的终态"。当前绘制侧逐对象参数的完整链路（已核实）：

- **push 常量**：`vulkan/pipeline.rs` `PushData` 96B/对象——model（`InstanceRow.model`，传播后终值直进 push）+ tex_index + sampler_index + base_color；`pack_push` 手工排布。
- **绘制参数**：`DrawCall` 另带 vertex_base/first_index/index_count（来自 `MeshSlot`），`cmd_draw_indexed` 逐对象录制。
- **组装**：`driver/host/frame.rs` draw_frame 每帧走访账本**全部行**——驻留现查 + 材质容器现查 + push 组装，O(在场对象) 每帧 CPU，绘制调用数 = O(N)。

也就是说：**实例数据终值已经跨帧存活在账本行里（4.1 的成果），但它每次使用都要 CPU 搬到命令流里**。5.1 把"搬"改成"索引"——数据常驻 GPU，CPU 只递一个实例标识；5.2/5.3 的剔除与 indirect 都以这张表为前提。

## 2. 三线拆解

| 线 | 交付 | 落点 |
|---|---|---|
| ① 常驻数据结构 | 对象表（实例槽）+ 材质表两份 DEVICE_LOCAL 常驻 buffer：对象行 = model + mesh 范围 + 材质索引 + 包围体；材质行 = 贴图/采样器槽 + base_color（独立 vs 折叠待决，见 §5）；Entity→实例槽跨帧账（第三层账：资产层 residency、实体层 InstanceLedger 之上加实例槽层） | `vulkan/resources.rs`、`vulkan/pool.rs`、`scene/mechanism/assets/ledger.rs` |
| ② 增量写入 | 对象表行走既有 flush_uploads 增量链（账本脏行→槽字节）；材质行走 4.2 资产事件失效通道；包围体计算与随行写入（mesh AABB 源头 + 非均匀缩放保守变换）；槽位分配/回收 | `driver/upload.rs`、`vulkan/mesh_convert.rs` |
| ③ 消费端改造 | shader 按实例索引读对象表/材质表；push 缩减为实例标识或 gl_DrawID；DrawCall/DrawList 终态落定（全退役 vs 槽位枚举，§5 待决）；descriptor layout 变更连带 | `vulkan/pipeline.rs`、`vulkan/frames.rs`、`driver/host/frame.rs`、shader 侧 |

三线枢纽 = **对象表**：①立结构，②喂数据，③换读法。同段一次架构改动，不拆段施工；任务拆解见 §3。

**与冻结边界的关系**：3.6 冻结的"set/binding 表与 UBO 128B 布局不动"在 5.1 解冻——对象表/材质表要新 binding（扩 set0 还是新 set，§5 待决），解冻范围在 5.1.1 落清单；UBO 128B 的"全局量"语义本身不变（相机/灯光仍走 set1）。

## 4. 测试方案与证据形态

- **BRP 驱动**（既有方法族全在库）：set_transform（移动→对象表单槽字节差）、spawn/despawn（槽位分配/回收+画面进出）、replace（换 mesh→重绑槽）、mutate_asset（材质基色/贴图槽→材质表行更新）；brp.py 子命令随需扩。
- **计量读数**：push 字节/帧（判定线 1 的直接证据）、对象表/材质表槽位数、上传字节按表分列、稳态零上传保持。
- **截图读图**（按[画面功能视觉验证](../../../rules/画面功能视觉验证.md)）：三模式零回退；增删对象进出画面。
- **包围体专项**：BRP spawn 非均匀缩放 + 旋转对象，读数对照参考计算（保守 = 包住几何；不追求紧致最优）。
- **负例**：材质缺贴图 fallback 行为保持、despawn 后槽位复用不串内容（读回对照）。
- **回归矩阵**：4.x 全量判定线、3.5 三模式、零 VUID 含拆 Device、WM_CLOSE exit 0、clippy 全净、增删后 resize×2 不炸。

## 5. 待决问题（施工时钉明，不写死）

- **push 终态**：每对象 4B 实例标识 vs gl_DrawID 直读（后者要求 draw 序与槽位严格对应，槽位稀疏时需间接层）。
- **材质表独立 vs 折叠进对象行**：折叠违背共享去重（N 实例共享材质则 N 份重复），倾向独立材质表 + 两跳索引；对齐 4.2"按 AssetId 记账"语义。
- **mesh 范围**：对象行存副本 vs 引用 mesh 表（引用省字节、多一跳；副本上传时机简单）。
- **实例槽分配**：first-fit free list vs Entity 有序；draw 顺序从 BTreeMap Entity 序变为槽位序的影响（3.5 对照截图不依赖绘制序，但需如实记）。
- **包围体表示**：世界空间 AABB vs 球；保守化时机（CPU 上传时预变换 vs shader 读时变换）。
- **表落位**：set0 扩 binding vs 新 set；3.6 冻结边界解冻范围清单（哪些声明允许动）。
- **DrawList 终态**：全退役（录制层直接按槽位序遍历）vs 退化为槽位枚举。
