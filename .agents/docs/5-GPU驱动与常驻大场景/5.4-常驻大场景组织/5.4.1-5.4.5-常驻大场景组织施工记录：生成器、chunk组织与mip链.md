## 1. 5.4.1 常驻大场景生成器

- **形态落定**（待决 1 倾向采纳）：运行期 spawn 走 4.1 账本链路——新机制层 `scene/mechanism/scene_gen.rs`（`generate_instances` 批量克隆共享柄），BRP 薄壳 `remote/generate.rs`（`ash_renderer/generate_scene`，source 缺省 = 场景第一个 primitive）。不生成 glTF：资产形状真实性换不来"验证面翻倍"的代价，账本三入口天然覆盖批量 spawn（实测 4096 实例次帧全部入行、一个批次收账）。
- **复现纪律**：位置抖动 = splitmix64 纯函数散列 `hash01(seed, index, channel)`，无顺序状态——同参数重跑逐实例同位；跨块平坦 index 保证 chunk 化生成同参数同位。
- **计量**：批量 spawn 的账本/上传读数走既有 `increment_stats`（无新计量字段）——块规模对账靠操作前后差值，判定线 2 的证据形态。

## 2. 5.4.2 空间 chunk 身份与整块增删

- **粒度**（待决 2 倾向采纳）：空间网格——每轴 `chunk_grid` 块，块边长 `extent = ceil(√instances_per_chunk) × spacing`，相邻块原点相距 extent（块间不重叠、边界即空间边界）。
- **身份落点**（待决 3 倾向采纳）：实体组件 `SceneChunk { id, origin, extent }` 挂 chunk 根实体，实例为其子实体（`add_child`）。census/despawn 按 id 寻址；**跨块移动不更新归属**（chunk = 生成期组织，运行期归属更新语义另立账——钉进模块注释）。
- **整块增删**：`generate_chunks`（每块一根 + 子树铺实例）/ `chunk_despawn`（按 id 找根 → `try_despawn` 递归删子树）/ `chunk_census`（只读盘点）。批量 despawn = 多个整树 despawn 的聚合，逐行 Removed 通道天然兼容——**实测精确**：chunk 27 删除 → removed_rows_total +64（= 块成员数，零多删零漏删）。
- **chunk 不进 GPU**（待决 8，开工先钉）：GPU 侧零改动兑现——对象表/标记环/在场环/命令环六族布局与写入语义全部不动，本段剔除仍逐槽。

## 3. 5.4.3 基础 mip 链（含施工订正：blit 续批 graphics 队列）

- **静态 mip0 退役**：`UnsupportedMipLevels` 错误删除、`ImageSpec` 携带全链级数（`full_mip_chain = floor(log2(max(w,h)))+1`）、view 全链层级、采样端 `max_lod = VK_LOD_CLAMP_NONE`（可用层级由 view 决定；采样器键不携带级数，同键共享语义不变）。
- **"上传全 mip 子资源"订正**：加载器只给 mip0（FlightHelmet PNG 单级），TextureDataOrder 排布解析不引入——落地为"staging 只排 level 0 字节（w×h×4）+ GPU blit 生成其余层级"，带链描述符进来不再拒绝。
- **施工订正（运行实抓，本段最大钉）**：**blit 不落 transfer 批**。首跑实抓 `VUID-vkCmdBlitImage-commandBuffer-cmdpool`（transfer-only 命令池录 blit 违规）连锁**设备丢失**（无效命令提交后 timeline 票据信号量读数 u64::MAX，后续提交全灭、优雅退出）。落定形状：
  - transfer 批只做 level 0 拷贝 + 迁出为 blit 源（TRANSFER_DST → TRANSFER_SRC）；
  - **graphics 队列续批**：等 transfer 票据（timeline wait @ T）→ 高层级 UNDEFINED→TRANSFER_DST → blit 逐级缩（级 i 从级 i-1，LINEAR，两维 .max(1) 收底）→ 逐级迁回 TRANSFER_SRC → 全链收口 SHADER_READ_ONLY → **signal 票据 T+1**；发布给消费方的票据 = 续批票据（"链可用"的完成点），等待语义不变；timeline 信号量同提交内 wait+signal 合法（wait 在前 signal 在后）。
  - `Uploader` 增 graphics 队列/blit 池/逐槽 blit 命令缓冲（与 transfer 槽同 index 配对；两池同族设备仍走同一续批路径）。
- **同步订正二**（同步验证层实抓 `READ_AFTER_WRITE`）：layout transition 自带一次写，`dstAccessMask` 为空时这次写对跨提交读者不可见——`src_ready`/`level_ready` 补 `TRANSFER_READ`；收口屏障补 `SHADER_READ` + **`FRAGMENT_SHADER` 阶段**（`VUID-02820`：BOTTOM_OF_PIPE 不支持任何 access 位，配 SHADER_READ 直接违规）。
- **能力判定**：格式缺 `BLIT_SRC|BLIT_DST|SAMPLED_IMAGE_FILTER_LINEAR` 时降级单级创建（本机 RGBA8 两档全含，判定留证据日志）；fallback 白图/overlay 图集显式单级（无 blit 段）。
- **落点**（待决 4 倾向采纳）：资产就绪首次上传一次性完成（传输批 + 续批，非每帧）；无链/带链资产同批混载实测零 VUID（2048×64 单级图集与 512×512 十级链同批）。

## 6. 5.4.5 验收回归记录

- **增量计量分档**：spawn 4096（一个批次 196608B）→ despawn 64（零上传）→ respawn 64（3072B）→ 混合增删（despawn id 27 + generate 1×1×64 交叉）全部与块规模同量级；`dirty_rows` 收敛 0（稳态零盘点）。
- **负例**：chunk 999 不在场（协议错误 -32602 带指引文案）；generate count=0/columns=0（InvalidParams 专属文案——订正了误用 NothingToDo 报 replace_handles 专属消息的失真）；resize ×2 存活 + **resize 途中 spawn/despawn** 存活；带链/无链资产混载（图集单级 + 贴图链同批零 VUID，无链路径未回归——单级图照常上传采样）；拆 Device 排空（WM_CLOSE teardown 完整 ×2）。
- **回归矩阵**：5.1 稳态零上传零盘点、5.2 cull-stats 零 mismatch ×3（含 4096 规模下 3744/4102 逐实体对照）、5.3 draw_calls 恒 1（commands 1030/4102 两档）、零 VUID ×6 进程、WM_CLOSE exit 0 ×2（bash `wait` 采真实退出码）、clippy 全净、库测试 12/12。

## 7. 钉子

1. **blit 是图形操作**：transfer-only 命令池录 blit 直接违 VUID-cmdpool，且无效命令提交连锁设备丢失（timeline 信号量读数 u64::MAX）——"上传队列 = transfer 队列"的直觉对 blit 不成立；mip 生成挂 graphics 队列续批，发布票据 = 续批票据。
2. **layout transition 是一次写**：跨提交的 transition→read 依赖必须把 transition 写挂进屏障 dstAccessMask（空 dstAccessMask = 写不可见 = READ_AFTER_WRITE）；同族 CONCURRENT 共享不豁免这一点。
3. **VUID-02820 配套约束**：dstAccessMask 里的每个位都要被 dstStageMask 支持——SHADER_READ 配 BOTTOM_OF_PIPE 违规， BOTTOM_OF_PIPE 是"无消费者"专用。
4. **轨道限位/远平面是 FlightHelmet 小场景钉子**：MAX_ORBIT_RADIUS 10、far 1000 都按半身尺头盔取景钉死——5.4 起 256+ 单位场景直接顶死；放宽到 2000/4000（5.5 压测同够用）。
5. **截图通道环境受阻是本轮事实**：DLP 水印 TOPMOST 双屏全覆盖时 PrintWindow 拿不到内容（白图自愈/focus/TOPMOST 压制均无效）——读图类判定线的证据采集要留"环境遮挡"这个失败分支，按遗留处理不硬凑。
6. **NothingToDo 的协议文案有专属语义**（"至少一项变更（mesh_from/material_from）"）：通用错误变体被多个操作共享时，专属文案会失真——数值域问题走 InvalidParams 自带消息。

## 8. 追加：WASDQE 漫游与右键环视（2026-10-19 收官后追加）

用户提出 5.4 新增功能：Unity Scene 式视角控制（WASDQE 平移 + 右键拖拽控制朝向），落点 `scene/mechanism/camera_control.rs`（系统更名 `orbit_camera_control` → `camera_control`）。

**设计：漫游与轨道共用一套球坐标状态，不引入第二套模式状态。**
- **右键环视 = pivot 跟随**：相机位置钉住不动，yaw/pitch 随拖拽旋转，环绕中心搬到新视线正前方等距处（`look_rotate`）——松开右键后左键轨道绕新中心继续，与 Unity Scene 同款；拖拽方向与左键同号（右拖 = 视线右转、下拖 = 视线下俯）。
- **WASD 沿视线系 + Q/E 世界升降**（`fly_vector`，纯函数可测）；速度 = `radius × 0.5` 每秒——缩放档位即速度档位，头盔近景与大场景俯瞰同一手感。
- **仲裁**：鼠标侧沿用 `layer_id_at` egui 门；键盘侧 `egui_wants_keyboard_input()`（面板文本编辑中让键）。BRP `camera` 给值路径零改动（同一状态）。
- **局限**：环视不做指针抓取，光标拖出窗口即无增量（会话保活、回窗续拖，与左键会话同款防跳变）。

**验证**：新增库测试 3 条（环视位置钉住+右转方向、下拖下俯、漫游轴向 W/D/E/Q）→ 库测试 15/15、clippy 全净；冒烟零 VUID、BRP `camera` 给值回归正常、WM_CLOSE exit 0（EnumWindows 投递）。键盘/鼠标手感属实握通道，待用户自测。
