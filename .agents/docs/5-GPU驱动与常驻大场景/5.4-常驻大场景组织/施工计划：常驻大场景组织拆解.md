## 0. 判定线（验收草案）

1. **对象复用和块边界可观察**：生成器铺出的场景里共享资产实例的复用关系、chunk 的成员边界可从 BRP/计量读数对照，并配读图证据（如单块 despawn 前后画面只缺该块覆盖区域）。
2. **整块增删走 4.1 增量链路，不触发全量重传**：整块 spawn/despawn 后计量读数 = 上传字节与处理行数与块规模同量级、存量外其余零上传（4.1 五项计量口径）；"块外零扰动"以增删前后帧计量对照为证。
3. **若有静态零件合并，不破坏独立运动、剔除与后续卸载粒度**：默认不做（见待决 5）；若施工中引入，须逐项验证合并零件仍可独立运动、仍被 5.2 剔除正确覆盖、仍能按 chunk 粒度整块卸载。
4. **mip 链上屏不糊不闪、包围体在 mip 层级间自洽**：带 mip 贴图上屏（近景清晰、远景不闪烁）；mip 链落地不改变剔除包围体语义——5.2 视锥剔除读数在 mip 链前后一致（包围体来自几何，不随贴图 LOD 变）。
5. **数据全常驻期间无按需加载路径**：全部实例数据一次性常驻（4.1/4.3 链路），运行期不出现"用到才加载"的旁路；流送归步骤 6。
6. **常规回归**：5.1/5.2/5.3 判定线零回退（cull-stats 对照零 mismatch、draw_calls 恒 ≤1、对象增量稳态零上传零盘点、槽位闭环）、零 VUID、WM_CLOSE exit 0、clippy 全净、3.5 三模式截图零回退、resize/最小化与 compute 及命令环共存、拆 Device 排空不炸、库测试全过。

## 1. 定位：现状与要加的东西

5.3 收官后的形状：提交侧已是"GPU 写命令、一次 `cmd_draw_indexed_indirect`"（`ash_renderer/src/vulkan/frames.rs:454`），push 恒 0；场景侧仍靠 BRP spawn/despawn 手工铺少量实例。本段加三样东西，全部叠在既有链路上、不改 5.1～5.3 已定的表布局与提交形状：

- **生成器**：程序化铺大量实例，共享已有资产柄；规模参数化、随机种子固定可复现。倾向运行期 spawn 复用 4.1 账本链路（主计划 §5 倾向口径，待决 1）——spawn 走 `ash_renderer/spawn_primitive`（共享资产柄，`tools/brp.py:335`）已验证的通道，账本三入口发现机制天然覆盖批量 spawn。
- **chunk 身份与整块增删**：给实例一个空间 chunk 归属，提供按块 spawn/despawn 的入口；chunk 粒度（空间网格 vs 生成批次）与身份落点（实体组件 vs 生成器账面）待决 2/3。
- **基础 mip 链**：现状 = 静态 mip0——`images.rs:20-21` 模块注释钉明"只收单级贴图、只传 level 0、`max_lod` 钉 0"，带链数据直接拒绝（`images.rs:52` 错误、`images.rs:80` 转换检查）。本段退役该策略：接受带链资产、上传全 mip 子资源、采样端放开 `max_lod`，生成方式待决 4。

**容量前提已就位（立案期核实属实）**：对象表容量 131072，注释钉明覆盖 5.5 压测 10 万档（`instance_table.rs:46`）；命令环按在场行数上界分配，10 万条 `VkDrawIndexedIndirectCommand`（20B/条，约 2MB DEVICE_LOCAL）无压力——压缩合批无容量翻案理由（待决 6）。

**如实计量的继承项**：材质环全量重写的账本 O(N) 走访仍在（5.3 已钉明口径：走访组装常驻环写侧允许，不是 draw list 重建、不是可见集回读）；规模上去后该走访成本如实进计量，是否成为瓶颈归 5.5 判定。

## 2. 任务拆解草案（开工时转段 README 任务面板）

| 任务 | 内容 | 验收锚点 |
|---|---|---|
| 5.4.1 常驻大场景生成器 | 程序化铺实例：共享资产大量实例、规模参数化、随机种子固定可复现；形态待决 1（倾向运行期 spawn 走 4.1 账本链路）；BRP 驱动入口随需扩 | 判定线 1 的复用读数；spawn 读数进计量 |
| 5.4.2 空间 chunk 身份与整块增删 | chunk 粒度与身份落点（待决 2/3）；按块 spawn/despawn 接口走 4.1 增量链路（despawn 走 Removed 整树清账的整块版）；chunk 读数方法族 | 判定线 1/2 证据成形 |
| 5.4.3 基础 mip 链 | 静态 mip0 策略退役：转换检查接受带链、上传全 mip 子资源（含子资源范围与 view 放宽）、采样端 `max_lod` 放开；生成方式与落点（待决 4）；包围体自洽核实 | 判定线 4 |
| 5.4.4 验证通道 | chunk 边界可观察读数（BRP chunk census 族 + egui 计量行）+ 读图取证（块增删前后画面对照）；增量计量分报接入现有面板 | 判定线 1/2/5 读数 |
| 5.4.5 验收回归 | 判定线全量 + 负例（空 chunk、跨块混合增删、resize 途中整块增删、带链/无链资产混合）+ 回归矩阵 | §0 全过 |

顺序理由：生成器先行（有场景才有 chunk 的对象），chunk 次之（组织建立在实例之上），mip 链可与 5.4.1 并行推进（贴图链路独立于实例组织），验证通道在读写两侧都成立后收口。5.4.1~5.4.2 是本段主体。

**与冻结边界的关系**：对象表/材质表/模型环/标记环/在场环/命令环六族布局与写入语义全部不动（5.1～5.3 已定）；chunk 是账本行之上的组织概念，不给 GPU 侧新表（chunk 身份是否需要进 GPU 见待决 2）；mip 链只动 `images.rs` 上传/采样策略，不动 bindless 表结构。

## 3. 测试方案与证据形态

- **BRP 驱动**（既有方法族全在库，brp.py 二十三子命令起步）：生成器参数化 spawn（规模、种子、资产形状）→ chunk 读数；整块 spawn/despawn 前后增量计量对照（判定线 2 核心证据）；set_transform 移动对象跨块（chunk 归属变更语义待决 3 钉明后验证）；cull-stats/draw_stats 照旧回归。
- **计量分报**：4.1 五项（扫描数/处理数/上传字节/存量/耗时）按块增删分档读数；chunk 数、块均实例数、共享资产去重读数；egui 挂 3.7/4.7/5.3 现有面板。
- **截图读图**（按[画面功能视觉验证](../../../rules/画面功能视觉验证.md)）：chunk 边界可观察（单块 despawn 前后对照裁剪放大）；mip 上屏（近景清晰、远景无闪烁伪影——连拍亮度爬升伪影已知的背景下以结构差异为准）。
- **负例**：空 chunk 增删不炸不产生上传；跨块混合增删读数逐块对账；resize/最小化途中整块增删与六族环共存；带链/无链资产混载（mip 退役后无链路径不得回归）；拆 Device 排空。
- **回归矩阵**：5.1～5.3 判定线全量零回退（cull-stats 零 mismatch、draw_calls 恒 ≤1、稳态零上传零盘点、槽位闭环）、零 VUID、WM_CLOSE exit 0、clippy 全净、3.5 三模式、增删后 resize ×2、库测试。

## 4. 待决问题（施工时钉明，不写死）

1. **生成器形态**：运行期 spawn 复用 4.1 账本链路（主计划 §5 倾向：BRP 可观测、增量计量直读、与 4.x 全链同源）vs 程序化生成 glTF 走 3.1 加载链（资产形状更真实，但绕开账本直改、验证面翻倍）。倾向前者；生成器放哪一层（BRP 自定义方法 vs 场景组装 system）随形态一并钉明。
2. **chunk 粒度**：空间网格（按世界坐标分块，边界即空间边界）vs 生成批次（按生成时批次分块，实现最简）。倾向空间网格——"整块增删"的语义要空间边界才有画面意义；网格尺寸/每块实例数参数化留 5.5 调。
3. **chunk 身份落点与跨块移动**：身份落在实体组件（Bevy 侧可查、despawn 树语义自然）vs 生成器账面（不动 ECS 结构）。整块 despawn 走账本 Removed 整树清账是否覆盖"按块批量 despawn"（批量 = 多个整树 despawn 的聚合，逐行发现机制天然兼容——施工核实）；对象被 set_transform 移出块边界时归属是否更新（倾向不更新：chunk 是生成期组织而非运行期归属，更新语义另立账）。
4. **mip 链生成方式与落点**：GPU blit（`vkCmdBlitImage` 逐级缩，须实测格式 blit 支持与线性过滤 feature 位；一次传输期完成）vs CPU 预生成（上传前内存过滤，零 GPU 管线改动但 CPU 耗时）vs compute（管线布局动刀，本段不值）。倾向 GPU blit；落点在资产就绪首次上传（一次性，非每帧）；`images.rs` 四处联动（转换检查/上传子资源/view 范围/`max_lod`）与"带链拒绝"错误退役。
5. **静态零件合并**：主计划"仅当兼容材质、运动方式与 chunk 边界才考虑，且须过判定线③"——倾向本段不做（实例复用已是主张本体，合并收益要 5.5 计量说话）；做则按判定线 ③ 全项验证。
6. **压缩合批**（可见标记组织）：5.3 落定起步不做（固定槽位逐槽命令）；10 万条命令约 2MB、`maxDrawIndirectCount` 读数 u32::MAX（5.3 留痕），容量与计数均无翻案压力——倾向不翻案；若 5.5 实测命令环成为瓶颈再议（届时过判定线 ③ 同款审视）。
7. **默认验证档位与资产形状**：本段验收用什么规模（1 万档以下，如 4096/8192；档位读数归 5.5）与复用哪些资产（FlightHelmet 复用铺多实例 vs 混合程序化形状增加材质/网格多样性）——施工钉明；生成器参数本身规模无关。
8. **chunk 与 GPU 侧的关系**：chunk 身份是否需要进对象表/标记环（本段剔除仍逐槽，chunk 不参与剔除决策）——倾向不进（GPU 不知道 chunk；chunk 是 CPU 侧组织与增删粒度），若步骤 6 流送/Hi-Z 需要 GPU 侧块身份届时再扩。此钉直接影响 5.4.2 实现面，开工先钉。
