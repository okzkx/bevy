## 实际做了什么

按计划技术路线落地，一处返工（见下节首钉）：

- 新模块 `overlay/axis_gizmo.rs`：相机旋转取逆得世界→视空间旋转，世界三轴投到屏幕 `(d.x, -d.y)`；背景圆盘 + 三轴线 + 端点字母；背向轴先画、近轴压上层。相机缺席整帧让路。
- `DebugWindowsOpen` 加 `axis_gizmo` 开关（默认开）+ 总控 checkbox + `run_egui_pass` 显示门；相机查询收进 `DebugUiParams`（pass 签名 15 参已顶到系统参数上限 16，照 3.7 惯例新面板件全走参数束，不撑大签名）。
- 纯读侧 widget：零写路径、零 Vulkan 符号，形状走既有 `EguiFrame` shapes 通道。

## 钉子

1. **投影归一化抹掉前缩 = "指示器冻结"假象（本段核心教训）**：首版把投影方向归一化到盘半径，深度信息（前缩短线）被抹平——pitch 0 的纯偏航拖拽里 Z 轴投影方向恒为"右"、恒满长，16 帧跟拍指示器逐位相同，看起来像没读相机；实际每帧都在按相机姿态正确重画，只是编码无区分度。修复 = 端点不做归一化（前缩短线正是"轴指向观察者"的 Unity 读法），明暗/线宽/点径改随视空间 `d.z` 平滑（背向 0 → 侧向 0.5 → 朝观察者 1）。修完同协议跟拍，逐帧可辨。
2. **target/ 被外部清掉 → 宿主无声退出**：验证中途 `target/` 整目录消失（磁盘剩 235GB，非空间所迫，系外部 cargo clean 类操作），运行中的 exe 被连带删除，进程无声死亡——无 panic、无 WER 事件、日志无退出记录，`Get-Process` 才发现进程没了。排查"进程消失"类异常时先查 exe 是否还在，再怀疑代码。重建后原样复跑全过，非本段代码缺陷。
3. **egui 0.36 API 微差**：`ctx.screen_rect()` 已退役，用 `ctx.viewport_rect()`；`Painter::circle_stroke` 是三参（stroke 整体 `Stroke::new(w, c)`，不是老四参 width+color）。
4. **虚拟鼠标点 checkbox 的坐标换算**：egui points 域 → 截图物理像素 = `pt × ppp + 标题栏/边框`（本机 ppp 1.265、标题栏 ~37px），换算错会点空且**静默无效果**（连拍 md5 相同即"没点中"的信号）——先裁剪放大定位再点，比盲试快。
5. **验证取材复用 4.6 通道**：主屏 DLP 水印遮挡下 PrintWindow 白图，一律先 `f24_move.py` 挪副显示器再截（沿用 4.6 首钉结论）；`brp.py camera --yaw-deg/--pitch-deg` 直接给已知姿态，L2 无需写任何新 BRP 方法。
