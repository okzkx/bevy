# 施工计划：资产增量与同柄内容变化（4.2）

> 2026-10-10 立案（用户开工指令"先写计划，创建对应文件夹"），**同日施工收官**——实际落地与验收见[段 README](README.md) 与[施工记录](4.2.1-4.2.5-资产增量施工记录：事件读侧、失效联动与同柄重传.md)（含待决项的施工定案：关联方式=重扫账本行、mesh 区间=迁移新区间孤儿化、image=停尸房+原槽重写）。本文保持立案时点原貌，只在本行追记状态。对应[路线图](../../学习目标实现步骤.md)步骤 4 第二段，接在已收官的[4.1 对象增量](../4.1-对象增量/README.md)之后：对象增量管"实体层的增删改"，本段管"资产内容本身变了"这条资产层通道。

## 0. 判定线（验收草案）

1. **同柄内容变化全量生效**：运行期改某 Mesh 内容（同 `AssetId`），引用它的全部实体画面更新，重传恰一次。
2. **共享资产去重**：N 个实体共享同一资产，内容变化只重传一份——处理数按资产计不按实体计；材质贴图槽变化、Image 内容变化同理。
3. **事件不误伤**：稳态零事件零重传；`Added`/`Unused` 等非内容事件不触发重传（`Removed`/`Unused` 的回收语义归 4.4，本段只主张"收到事件不误动作"）。
4. **零变化零上传不回退**：4.1 稳态基准（首次清账后稳态帧零盘点零上传）保持；事件数/失效数/重传数/上传字节分开报——不把"零重传"说成"零事件读成本"。
5. **既有判定线零回退**：3.5 三模式截图对照、全程零 VUID（含拆 Device）、WM_CLOSE exit 0、clippy 全净。

计量口径对齐步骤 4 完成标准：事件读数（按变体分列）、失效资产数、重传资产数、上传字节、处理耗时分开报。

## 1. 定位：现状与要打通的东西

4.1 之后上传链的形状是"账本脏行 → 按资产身份查驻留 → 查无才转换上传"（`ash_renderer/src/driver/upload.rs` 的 `flush_uploads`：`pool.resident`/`image_cache.resident` 查无才进本批）。这套形状对**同 `AssetId` 内容变化天然失明**：内容变了驻留缓存照样命中，既不重传也不通知任何使用者——4.1 收官校准里点名的"横向通道"缺口。

本段就是把这条通道接上：`AssetEvent` 读侧（发现）→ 驻留失效 + 关联实体重挂脏标（失效）→ 既有转换/上传链复用重传（写入）。4.1 定案"写侧刻意不碰账本"，本段在发现侧加**资产粒度的第二条入口**，与对象粒度的五类变更并轨进同一份脏行队列。

**各资产类型的驻留内容与失效范围**（立案时点核实，施工时钉细）：

| 资产 | GPU 驻留内容 | 内容变化的牵连 |
|---|---|---|
| Mesh | 池区间（顶点/索引） | 区间替换或原地重传（待决 §5）；账本行持 `Handle<Mesh>` 不变，无实体侧动作 |
| Image | `ImageCache` 驻留 + bindless 槽位 | 重建/重传后槽位重发布，引用它的材质槽与实体跟着换 |
| StandardMaterial | 参数走每帧 UBO 统一给值（`driver/host/frame.rs`），**无驻留内容**；驻留的只有贴图槽指向的 Image 与采样器槽 | 参数变化画面自动生效（既有链路兜着，可作事件读侧的观测锚）；贴图槽变化 → 关联 Image 失效传播 |

## 2. 拆解：发现 / 失效 / 重传

| 线 | 交付 | 落点 |
|---|---|---|
| ① 资产事件发现 | 三类资产 `MessageReader<AssetEvent<A>>` 读侧；事件计量接入报告口径 | 新发现系统（`scene/mechanism/` 或 `driver/`，施工钉明） |
| ② 失效与联动 | `Modified` → 驻留缓存失效 + 资产→实体关联重挂脏标（反向索引 vs 重扫账本，施工钉明） | 账本（`scene/mechanism/ledger.rs`）+ 驻留缓存 |
| ③ 内容重传 | "查无才传"改"查无或失效才传"；转换/上传链、槽位发布复用；替换时序安全 | `driver/upload.rs`、`vulkan/pool.rs`、`vulkan/images.rs` |

三线是一次架构改动里的三个面，同段施工不拆段（4.1 惯例）；任务拆解见 §3。

## 3. 任务拆解草案（开工时转段 README 任务面板）

| 任务 | 内容 | 验收锚点 |
|---|---|---|
| 4.2.1 资产事件读侧 | `AssetEvent<Mesh/StandardMaterial/Image>` 三读侧接入 + 事件计量（事件数按变体分列） | §0.3/§0.4 事件读数成立；`Unused`/`Removed` 收到不误动作 |
| 4.2.2 失效与联动 | `Modified` → 驻留失效 + 关联实体重挂脏标；资产→实体关联方式钉明 | 同柄改内容后引用实体全部入重传批 |
| 4.2.3 内容重传 | 重传批复用既有转换/上传/槽位发布链；mesh 区间替换与 image 槽重发布的时序安全（借 4.1.1 帧侧等待闸门） | §0.1~§0.3 可测；零 VUID |
| 4.2.4 BRP 改内容方法 | 运行期改资产内容的 BRP 入口（测试驱动，沿 BRP 优先纪律；范围见 §4） | 各类内容变化有驱动入口；负例宿主存活 |
| 4.2.5 验收回归 | 判定线全量 + 计量报告 + 既有判定线零回退 | §0 全过 |

顺序理由：先有读侧（知道谁变了），再接失效（把变化变成重传批），最后改消费端（有批可传）。4.2.4 依赖 4.2.1 的事件口径定形后写。

## 4. 测试方案：BRP 驱动与证据形态

**驱动纪律沿 4.1 定案：变更驱动一律优先 BRP**（[测试规范](../../../rules/测试规范与方式.md)"扩建优先级"条）。本段要新驱动的是"改资产内容"，对象侧五方法已够用：

| 驱动 | 手段 | 状态 |
|---|---|---|
| 改材质参数 | mutate（`Assets::get_mut` 改 `StandardMaterial`，触发 `Modified`） | ⬜ 本段新增 |
| 换材质贴图槽 | mutate 贴图槽字段 | ⬜ 本段新增 |
| 改 Mesh 内容 | mutate（改已有 mesh 几何或重填内容——具体形态施工钉明） | ⬜ 本段新增 |
| 改 Image 内容 | mutate 或 CPU 侧重填 | ⬜ 本段新增，形态施工钉明 |

BRP 方法边界：只加"改内容"族，不为验收预铺查询类方法；薄入口直调可复用封装，不污染 lowlevel。

**证据形态**（判定线 §0 的证据来源）：

- **计数日志定去重**：N 实体共享同 mesh 改内容——事件数按变体分列、失效资产数、重传资产数、上传字节；关键读数=重传资产数=1（非 N）。
- **截图定画面**（PrintWindow + 读图，按《画面功能视觉验证》执行）：改内容前后画面变化且全部引用者同变。
- **材质参数作事件锚**：参数变化本就走每帧 UBO 自动生效，用它先钉"`Modified` 确实收到"，再测重传路径。
- **负例**：改不存在的资产、改后立刻移除等时序——宿主存活、错误原码回传（沿 3.12/3.13 惯例）。
- **回归矩阵**：3.5 三模式、零 VUID 含拆 Device、WM_CLOSE exit 0、clippy 全净、4.1 五类变更判定线零回退（重点：换柄与内容变化叠加不串账）。

## 5. 待决问题（施工时钉明，不写死）

- **读侧挂点与时序**：`AssetEvent` 读侧系统挂哪个 schedule、与 `flush_uploads`（Last）和 4.1 对象发现系统的先后；事件跨帧积压语义（读侧漏帧处理）。
- **资产→实体关联方式**：账本反向索引（AssetId→实体集，要维护）vs 变化时重扫账本行（O(账本行数) 但零维护）；按资产数量级与变化频率施工时定。
- **mesh 区间替换时序**：容量足够时原地重传（在飞 draw 读旧内容风险——借 4.1.1 帧侧等待闸门挡）vs 新区间迁移 + 旧区间延迟回收（回收归 4.4，本段只保证安全）；对[责任边界契约②](../../3-静态取数链路/3.2-buffer侧上传/责任边界冻结：上传完成、图形消费与退出排空的时序契约.md)的落点施工时钉明。
- **image 槽位重发布**：重建走新槽还是原槽重传；与 3.3.4 槽位发布、bindless 索引稳定性的取舍。
- **包围体失效落点**：路线图 4.2 范围列"关联包围体失效"，但现状宿主无包围体/剔除消费方（立案时 grep 零命中）——本段只立"资产变化时包围体（若有）随之失效"的原则，消费方落地归后续步骤。
- **错误处理分级**：事件读侧遇悬空资产、失效失败等路径按[两 Tier 宪法](../../错误处理/错误处理体系：两Tier思想与优雅退出.md)分级（非必要不 panic），具体分级施工时钉。

## 6. 边界：不在本段主张什么

- **异步到货**（pending/票据状态机/就绪门/失败与取消）→ 4.3；本段的"Modified 重传"以资产已到货为前提，未到货路径归 4.3。
- **回收**（`Removed`/`Unused` 后的 GPU 资源回收、池区间归还、描述符槽 retire）→ 4.4；本段对这两个事件只主张"收到不误动作"。
- **热重载**（文件监听、WorldAsset 重载回归）→ 4.4；本段不接文件监听，内容变化一律由显式 mutate 驱动。
- **共享资产多份驻留的去重**不在本段主张——驻留缓存按 `AssetId` 键控，天然单份。
- **实例数据迁 GPU / GPU-driven**（实例表/indirect）→ 5.1/5.3，本段不动 push constant 现状。
