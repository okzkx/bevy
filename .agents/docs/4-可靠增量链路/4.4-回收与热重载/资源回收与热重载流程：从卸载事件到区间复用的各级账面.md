# 资源回收与热重载流程：从卸载事件到区间复用的各级账面

对应[段 README](README.md)；机制讲解见[施工记录](4.4.1-4.4.4-回收与热重载施工记录：卸载回收、双停尸房与热重载链.md)（本篇面向下一个读代码的人：数据怎么流、账面怎么转、谁在哪个调度点动手）。4.3 的[异步就绪流程篇](../4.3-异步就绪/异步就绪流程：从load请求到就绪上屏的各级账面.md)管"资产到货之前"，本篇接它的出口——"资源不再被需要之后去哪"，以及"文件变了怎么自动跟上"。

## §0 判定线（先行）

**销毁必受"上传票据 ∧ 图形最后使用"双条件保护；反复增删存量回基线**。三条销毁路径（池区间/旧 GpuImage/描述符槽）共用同一排空点；判定线读数 = `brp.py stats` 的 `recycle` 段（驻留条目/字节、双停尸房、free list、槽位），对账以驻留条目数与停尸房为主（纹理槽计数被字体图集死代干扰，见施工记录钉子 5）。

## §1 账面全景（五层，按资产生命周期排）

| 级 | 账面 | 文件 | 寿命与职责 |
|---|---|---|---|
| ① | `InstanceLedger`（4.1） | scene/mechanism/ledger.rs | 实体粒度跨帧行集；despawn 清行 = 回收链的免费起点（RemovedComponents 通道） |
| ② | `AssetInvalidations`（4.2） | scene/mechanism/asset_events.rs | 资产身份粒度失效凭据；"内容变了要换条目"的横向通道 |
| ③ | `AssetReadiness`（4.3） | scene/mechanism/asset_readiness.rs | pending/failed 身份账；本段新增 `clear_failure_*`（卸载出清）与复活集联动（4.4.3） |
| ④ | `AssetRetirements`（4.4 新增） | scene/mechanism/asset_events.rs | 待回收身份账（Removed 读侧记、flush 开头消费）+ `RecycleStats` |
| ⑤ | GPU 侧三条回收账（4.4 新增） | vulkan/pool.rs + images.rs + descriptors.rs | 网格区间停尸房 + free list；贴图 graveyard（4.2.3 复用）；槽待回收账（retired_textures/samplers） |

同步流方向：**事件 → ④（PostUpdate 读侧）→ ⑤ 的停尸房（Last 的 flush 消费）→ 排空归还（下帧 flush 步骤 0）**。与 4.2 的"事件→凭据→flush"同形，只是语义从"换内容"翻成"出账销毁"。

## §3 逐时刻走读：一次"load→despawn"完整回收周期

以 BRP `load-mesh --source 441 --path models/cube/cube.gltf#Mesh0/Primitive0` 后 despawn 为例：

1. **受理帧**（BRP handler 在 RemoteLast）：`spawn_with_loaded_mesh` 挂柄 → 次帧 `Changed<Mesh3d>` → 账本入行 → Last 的 flush 盘点查无 → pending → 到货转换上传 → `pool.commit` 登记（第 7 行）。
2. **despawn 帧**：实体递归删 → `Mesh3d` 摘除 → update_ledger 清行（removed_rows=1）；柄 Drop 强计数掉零 → bevy_asset 确定性释放资产 → `AssetEvent::Removed` 进消息。
3. **同帧 PostUpdate**：`propagate_asset_changes` 读 Removed → `AssetRetirements.retire_mesh(id)` + `readiness.clear_failure_mesh`（若曾失败）。
4. **同帧 Last（flush_uploads）**：
   - 步骤 0：上一轮的停尸房先排空（等帧侧 fence → 销毁/归还）；
   - 步骤 0.5：取走待回收身份 → `pool.retire(id)`：驻留条目移除、区间进停尸房、`RecycleLedger` 退休累计 +1；
   - 步骤 1 盘点：无行引用该身份（行已清）→ 无重试、无上传；
   - 稳态收账：`recycle` 读数 pool_resident_count 回落 1、graveyard_groups=1。
5. **次帧步骤 0**：`pool.drain_graveyard` → wait_draws（全部帧槽 fence）→ 区间归还 `free_vertex/free_index` → 日志"网格回收停尸房排空:归还 1 组区间"。
6. **再下一次同尺寸加载**：alloc first-fit 直接取回该空洞（bump 游标不推进，peak 不涨）——**复用即对账**：第 3 轮 cube 复用第 1 轮的 768B 实测。

贴图腿同构，差别只有两处：旧图本体进 `ImageCache` 停尸房（排空 = GpuImage Drop，sampler/view 先于 image/memory）；描述符槽 retire 带同键条件（采样器槽是共享槽，同键最后一张退场才请求回收，`retire_sampler_by_slot` 按槽号反查功能键摘除去重账目）。

## §4 失败与稳态路径

- **排空失败**（帧侧等待错）：停尸房保留、下帧重试——旧件多活一帧，无悬空（三条路径同款容错）。
- **稳态**：事件零命中 → propagate 早退；停尸房空 → 排空零等待；free list 空 → alloc 纯 bump。稳态帧零盘点零上传零销毁（既有 4.1 基准不回退）。
- **失败资产修复**（判定线 4 的链）：load 失败 → failed 集 + 行出队 → 文件修复 + reload → `Added` 事件 → 复活联动（revive + 重挂引用行）→ flush 重试 → 到货上屏。**修复前无循环**（无自动重试，事件驱动一次性）。
- **WorldAsset 重载**：Modified → 官方 spawner despawn+respawn（实体号换代）→ update_ledger 清 6 行 + 入 6 行 → 子资产驻留命中零重传（容器级身份稳定）→ 相机/灯光不动。
