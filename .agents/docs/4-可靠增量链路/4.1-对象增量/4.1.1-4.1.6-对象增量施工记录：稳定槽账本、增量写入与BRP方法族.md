## 1. 任务 4.1.1 pool 前置闸门：销毁旧池前补帧侧等待

**面板要求**：3.6.3 §3 立账——pool.rs 容量维护销毁旧池前只等上传票据、不等在飞 draw 对旧池的读取（责任边界契约②的图形半边无落点）；本任务补齐，验收=迁移路径可常态触发且零 VUID。

**实现原理**：旧池销毁的 hazard=还有命令缓冲在 GPU 上执行且引用旧池。"帧侧等待"的最小正确形状=等全部帧槽 fence——fence 只证提交完成，全部槽位 fence 皆 signaled ⇒ 没有命令缓冲仍在 GPU 执行 ⇒ 在飞 draw 对旧池的读取必然已收口。池不认识帧资源，以回调参数接线保持 vulkan 层内依赖单向（pool 不依赖 frames）。

**过程与落点**：
- `vulkan/frames.rs`：新增 `FramePool::wait_all_inflight`——对全部帧槽 fence `wait_for_fences`（SIGNALED 槽立即通过，正常至多等 MAX_FRAMES_IN_FLIGHT−1 个尾帧；只等不重置，与 wait_for_slot 纪律一致）。
- `vulkan/pool.rs`：`ensure_capacity` 增第 4 参 `wait_draws: &mut dyn FnMut() -> Result<()>`，迁移路径在等完迁移票据之后、销毁旧池之前调用；模块头/Drop 注释同步（缺口补齐、责任边界契约②双条件齐）。
- `driver/upload.rs`：flush_uploads 经 `Res<FramePool>` 传闭包 `|_| frames.wait_all_inflight()`。
- `examples/upload_probe.rs` 组 C：`upload_asset` 与手工调用点补回调；新增断言"wait_draws 迁移恰等一次、初建不触发"。

**验收实跑**：`cargo run --example upload_probe` 全绿——组 C 迁移后新旧资产逐字节一致、断言过、全程零 VUID（验证层+同步验证常开）。

**反思**：回调形状是"依赖单向"与"等待点正确"的折中——池知道何时该等、调用方知道怎么等；真实宿主的迁移常态化仍归 4.4（本机素材规模不触发，探针覆盖机制本身）。

## 2. 任务 4.1.2 + 4.1.3 稳定槽账本与变更发现

**面板要求**：稳定 Entity→GPU 实例槽关联（跨帧账本）；新增/矩阵变化/换柄/组件移除/despawn 五类变更各有入口；扫描成本计量接入。

**实现原理**：三条变更入口——①移除走 `RemovedComponents<Mesh3d>`/`RemovedComponents<MeshMaterial3d>`（**despawn 递归删子树走组件移除路径**，bevy_ecs `bundle/remove.rs:239` 对每个被删实体写 `removed_components`，每个 primitive 各发一次，整树清账免费拿到）；②新增/换柄走 `Or<(Changed<Mesh3d>, Changed<MeshMaterial3d>)>`（**插入也置 changed tick，不需要 Added**）；③矩阵走 `Changed<GlobalTransform>`（bevy_transform 传播用 `set_if_neq`，systems.rs:719——静态场景恒不触发，这是"扫描≠处理"的结构根据）。两条源码语义立案时已对 checkout 核实（施工计划附录）。

**过程与落点**：`scene/mechanism/ledger.rs` 新文件（collect.rs 退役删除）——`InstanceLedger` Resource（`BTreeMap<Entity, InstanceRow>` 按 Entity 有序迭代保证 DrawList 顺序确定 + `BTreeSet` 脏集 + `IncrementStats` 计量）+ `update_ledger` 系统（PostUpdate `.after(TransformSystems::Propagate)`，同 3.1.4 采集时机；移除先于新增处理，同帧"摘了又挂回"终态正确）+ `AshLedgerPlugin`。计量口径：scan_candidates=三样俱全候选实体数（tick 比较全集）、processed_rows=真实动手行数、四个 *_rows_total 累计（操作前后差值=该操作的账本动作数）。

**反思（两枚编译期钉）**：①`ResMut` 字段经 DerefMut 借用会锁整个账本——`let stats = &mut ledger.stats` 与 `ledger.rows` 修改不能并存，计量先落局部变量收口后写回；②doc comment 不能标系统参数，改行注释。

## 3. 任务 4.1.4 增量写入

**面板要求**：上传清单从"每帧全量快照重建"改为"账本增量驱动"；flush_uploads/DrawList 消费端适配；判定线④的计数口径成立。

**实现原理**：上传链只盘点**脏行**（新增/换柄置位）：每行查其资产身份驻留状态——全驻留就地清标（清标不依赖提交成败，是账本事实）；有未驻留身份的行保持脏标下帧重试（与全量快照时代的"每帧重扫"同语义，只是重试队列从全部在场行收敛为脏行）。资产身份去重跨行跨帧不变（3.2.2.2 驻留缓存）。DrawList 仍逐帧重建（读账本=纯 BTreeMap 走访，零组件扫描零 tick 比较）——计划 §5 待决项"账本与快照的关系"按消费端适配代价定案：**账本取代快照**，CollectedScene 类型退役。

**过程与落点**：`driver/upload.rs` 重写（脏行盘点→转换→容量保证→合批提交；上传计量进账本 stats）；`driver/host/frame.rs` DrawList 改读 `ledger.rows()`；`scene/content/collect_report.rs` 一次性核验改读账本（6/6、传播契约全过——判定线期望值不背在账本上）；scene/mod、mechanism/mod、content/mod、lib.rs、main.rs 的出口与注释同步（AshCollectPlugin→AshLedgerPlugin）。

**反思（首跑实抓一 bug）**："增量链首次清账"日志原放在空批 early-return 之后——清空脏集的那帧多半正是空批帧，日志永远打不出。首跑宿主即实证（清账日志缺席），修正为清标后、early-return 前检查，复跑出现。教训：日志哨兵的可达路径要对着"它该出现的那一帧"推演，不能只看逻辑对不对。

## 4. 任务 4.1.5 BRP 变更方法族

**面板要求**（计划 §4，2026-10-10 用户拍板 BRP 优先）：五类变更各有 BRP 入口；操作封装可复用函数、BRP 薄入口不污染 lowlevel。

**实现原理与分工（按"不重复造官方已有"钉子收敛）**：**despawn/摘组件复用官方内置**——`world.despawn_entity`（0.20-dev `World::despawn` 默认递归删 Children 子树）与 `world.remove_components`（反射通道按组件名摘除，无值构造），brp.py 直接封装官方方法名；**spawn/replace 自研**——官方 `world.spawn_entity` 经反射构造组件值，表达不了"引用既有资产的柄"（Handle 无法经反射指到现有资产身份），克隆/拷柄是场景语义操作。object_ops 层只留有消费者的两件（spawn_primitive_clone/replace_handles）；despawn_tree/remove_component 曾预写后裁撤——无 egui 消费者前不养零调用代码（"宏已在役"判断失真教训的正面执行）。

**过程与落点**：`scene/mechanism/object_ops.rs`（可复用实现：克隆共享资产柄+平移偏移+Name 后缀；换柄拷柄+AssetId 读回；ObjectOpError 四态映射协议错误码）+ `remote_objects.rs` 顶层模块（spawn_primitive/replace_handles/increment_stats 三方法，注册收 AshRemotePlugin 单点）+ `tools/brp.py` 五子命令（spawn/despawn/replace/remove/stats，合计十六）。

**反思（0.20-dev API 形状三钉）**：`EntityWorldMut::remove` 链式返回 &mut Self 非 Option（"摘没摘到"须先 get 探明）；`Children::iter()` 产 Entity 本体非引用（3.10 钉子再现）；`bevy::core::Name` 路径已不存在（Name 走 prelude）。

## 6. 钉子汇总

1. **despawn→RemovedComponents**：递归 despawn 走组件移除路径（bundle/remove.rs:239），`RemovedComponents<T>` 对子树内每个 primitive 各发一次——整树清账免费，不需要遍历 Children。
2. **Changed 覆盖 insert**：组件插入置 changed tick，发现侧 `Or<(Changed<A>, Changed<B>)>` 一个查询覆盖新增与换柄，不需要 Added。
3. **传播 set_if_neq**（bevy_transform/src/systems.rs:719）：静态场景零 `Changed<GlobalTransform>`；**同值重写也拦下**（set-transform 同值复写 T 不增——测试意外捕获的活证据）。
4. **ResMut 字段借用的 DerefMut 陷阱**：`&mut res.field` 经 deref_mut 锁整个资源，不能与该资源其他字段/方法的访问并存——局部计数器再写回。
5. **日志哨兵可达性**：一次性收账日志必须放在它所属路径的分叉之前（early-return 吞日志，首跑实抓）。
6. **计量两口径**：per-frame 值（上一帧快照，事件帧过后归零）只配实时观察；测试对账用 *_total 累计差值。
7. **官方 BRP 内置已有 world.despawn_entity/world.remove_components/world.get_resources**——自研方法族只补官方表达不了的（柄引用克隆/拷柄、非反射结构的统计读数）。
8. **graceful 退出码链**：Git Bash `$!` 是 MSYS PID 不能喂 Windows API，但 `wait` 可收其退出码；Windows 侧按进程名 Get-Process 找窗（3.2 钉子复用）。
