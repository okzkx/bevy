## 0. 判定线（验收草案）

1. **移动物体只更新相关实例数据**：运行期改某实体 Transform，被处理（发现→动手）的实体只有它一个，其余实体的账本行、上传批内容零动作。处理计数与上传字节对照"在场总数"如实分报。
2. **替换引用和删除不残留旧对象**：换 mesh/material 句柄，画面换新内容、不再画旧对象；despawn 与组件移除（摘 `Mesh3d`）后对象当帧或次帧从绘制消失，账本无残留行。GPU 池与描述符槽的回收时机归 4.4，本段只主张"不再绘制、账本不残留"。
3. **新增对象增量入账**：运行期 spawn 的可渲染实体增量进账并画出，不触发他人重传（驱动走 BRP spawn，见 §4）。
4. **零变化零上传**：稳态帧上传字节为 0；扫描数（Query 匹配并做 tick 比较的实体数）单独上报——**不把"零上传"说成"零 CPU 每对象成本"**（路线图步骤 4 完成标准原文）。
5. **既有判定线零回退**：3.5 三模式截图对照、全程零 VUID（含拆 Device）、WM_CLOSE exit 0、clippy 全净。

计量口径对齐路线图"统一验收与性能口径"§1/§3：扫描数、处理数、上传字节、账本存量（行数/池占用）、处理耗时五项分开报。

## 1. 定位：现状与要换掉的东西

M2 静态链路的取数是**每帧全量重建**：`scene/mechanism/collect.rs` 的 `collect_scene`（PostUpdate、传播后）每帧扫全部可渲染实体重建 `CollectedScene` 快照，`driver/upload.rs` 的 `flush_uploads` 每帧消费整份快照按资产身份去重——静态场景稳态上传为零是"去重"买的，不是"增量"买的，且 O(在场实体数) 的扫描成本每帧照付。

这套形状是 M2 阶段实现（[3.1.4 施工记录](../../3-静态取数链路/3.1-ECS侧取数/3.1.4-采集系统：PostUpdate帧末直读与CollectedScene快照.md)立项时已注明"增量/脏标记归步骤 4"）。步骤 4 起实体可增删、句柄可替换、资产可异步到货，全量重建撑不住三件事：

- **删除没有信息来源**：`RemovedComponents<T>` 只给 Entity 不给旧内容，没人知道被删实体原来占着哪个槽、连着哪些资产。
- **变更没有归属**：全量重建天然"每帧都变"，回答不了"移动物体只动了谁"。
- **回收没有依据**：旧资产、旧对象何时可安全释放，需要一份跨帧存活的账。

4.1 就是把这份账立起来——它是步骤 4 后三段（资产增量、异步就绪、回收热重载）共同的地基。

## 2. 三线拆解

| 线 | 交付 | 落点 |
|---|---|---|
| ① 变更发现 | 新增/矩阵变化/换柄/组件移除/despawn 五类变更各有入口进账；扫描成本计量接入报告 | `scene/mechanism/`（发现系统），机制选型见 §4 待决 |
| ② 稳定槽账本 | Entity→GPU 实例槽跨帧账本：槽位登记、换绑、删除清账（despawn 连 `Children` 子树整树清） | 新账本（Resource），与 `CollectedScene` 的关系见 §4 待决 |
| ③ 增量写入 | 上传清单从"每帧全量快照重建"改为"账本增量驱动"；`flush_uploads` 与 DrawList 消费端适配 | `driver/upload.rs`、`driver/host/` |

**账本是三线的枢纽**：删除处理的信息来源是它（线①的输出落进它），增量写入的定位依据是它（线③的输入来自它）。三线是一次架构改动里的三个面，同段施工不拆段；任务拆解见 §3。

对象口径与 3.1.4 采集一致：带 `Mesh3d` + `MeshMaterial3d<StandardMaterial>` + `GlobalTransform` 的 primitive 实体。相机/灯光不进账本——每帧 UBO 统一给值，没有"按对象"的槽（bindless 四通道既定口径：统一给值的东西不表化）。

| 4.1.4 增量写入 | 上传清单改为账本增量驱动；`flush_uploads`/DrawList 消费端适配；一次性核验（`collect_report.rs`）接线跟进 | §0.1~§0.4 判定线可测 |

## 4. 测试方案：BRP 驱动与证据形态（2026-10-10 用户定案 BRP 优先）

**驱动运行时变更的测试手段一律优先写 BRP 方法**（用户拍板）：①可复用——后续段测同类变更（如换 Mesh）走同款通道；②BRP 住外层 `src/remote.rs`，不污染 lowlevel；③沉淀为引擎工具面；④BRP 面即 AI 能力面——自动化验收的操作 API 越全，AI 驱动的自动化越强。临时探针退役为"验证一次即删"的内部诊断专用（3.10 惯例场景），不再承担变更驱动。

**变更驱动：五类变更各有 BRP 入口**

| 变更 | BRP 方法 | 状态 |
|---|---|---|
| 矩阵变化 | set_transform | ✅ 3.12 已有 |
| 新增 | spawn（克隆既有 primitive 柄+偏移，还是按资产路径新建——施工钉明） | ⬜ 本段新增 |
| 删除 | despawn（递归整树，`World::despawn` 默认语义） | ⬜ 本段新增 |
| 换柄 | replace（mesh/material 柄替换；目标资产的引用方式施工钉明） | ⬜ 本段新增 |
| 组件移除 | remove（摘 `Mesh3d` 退出可渲染集） | ⬜ 本段新增 |

方法族边界：只为 4.1 五类变更配齐，不为后续段预铺；操作按 3.11 惯例封装可复用函数（将来 egui 面板同款调用），BRP 是薄入口——两层各归其位，lowlevel 不因测试多一行代码。

**证据形态**（判定线 §0 的证据来源）：

- **计数日志定增量**：每帧报扫描数/处理数/上传字节/账本存量。读数——稳态帧处理 0、上传 0（扫描数照实报，O(匹配实体) 是 Changed 语义的已知成本）；单实体移动处理恰 1；despawn 父节点整树清账。**M2 的按资产去重在静态场景本就稳态零上传，必须把"去重买来的零"和"增量买来的零"分开——处理数是关键读数**。
- **截图定画面**（PrintWindow + 读图，按《画面功能视觉验证》执行）：spawn 后可见、despawn 后消失、换柄后内容变化；只验"不残留旧对象"，不验池回收（归 4.4）。
- **到帧时延实测**：BRP 写在 RemoteLast、采集在 PostUpdate——spawn/despawn 生效是当帧还是次帧，实测后如实记，顺手钉明 §5 的时序待决项。
- **负例**：despawn 不存在实体、重复 despawn、摘不存在的组件——宿主存活、错误原码回传（沿 3.12/3.13 惯例）；空 DrawList 帧渲染存活。
- **回归矩阵**：3.5 三模式截图零回退、零 VUID 含拆 Device、WM_CLOSE exit 0、clippy 全净；加一条"增删实体后 resize/最小化不炸"——账本生命周期与 swapchain 重建路径从此开始互动。

## 5. 待决问题（施工时钉明，不写死）

- **发现机制选型**：查询过滤（`Changed<T>`/`Added<T>` + `RemovedComponents<T>`）vs 组件钩子（`ComponentHooks` 的 on_add/on_insert/on_remove/on_despawn）vs 生命周期观察者（0.20-dev bundle 型事件 `Add<B>`/`Remove<B>` 等，`bevy_ecs/src/lifecycle.rs`）。按路线图边界：**查询过滤是默认起点**，扫描成本先单独计量，确认瓶颈前不上脏队列、不重写 ECS；钩子/观察者作候选补充，触发语义（何时收增、能否拿到旧值）施工时对源码钉明。
- **发现挂哪个组件**：改 `Transform` 经传播才改 `GlobalTransform`；发现挂哪个组件、与 PostUpdate `Propagate` 之后的既有采集时序怎么排，施工时钉明。
- **账本与快照的关系**：账本取代 `CollectedScene`，还是 `CollectedScene` 降级为逐帧绘制拓扑层（DrawList 排序/在场集合仍逐帧重建，上传链改吃账本）？按消费端适配代价施工时定。
- **错误处理分级**：despawn 后账本清账遇悬空/重复行、Query 拿不到已删实体等路径按[两 Tier 宪法](../../笔记/错误处理体系：两Tier思想与优雅退出.md)处理（非必要不 panic），具体分级施工时钉。

## 6. 边界：不在本段主张什么

- **资产内容变化**（同句柄内容更新、`AssetEvent`、共享资产去重与关联失效）→ 4.2；4.1 只处理实体侧的句柄替换。
- **异步到货**（pending/票据状态机/就绪门/失败与取消/等待期间删除）→ 4.3。[开放世界流送设计](../../3-静态取数链路/材料/开放世界流送设计：滑动窗口驻留、淘汰与预算环.md)在步骤 4 的落点（就绪门、账本逆操作）分别归 4.3/4.4，不进本段。
- **GPU 资源回收**（mesh 池区间归还、描述符槽 retire、在飞销毁延迟、容量淘汰常态化）→ 4.4；4.1.1 只补"销毁前等帧侧"这一个缺口，淘汰常态化仍按 3.6.3 立账归 4.4。
- **热重载**（文件监听、WorldAsset 重载、旧实体身份不默认保留）→ 4.4。
- **实例数据迁 GPU**（逐 draw push constants → 实例表/indirect）→ 5.1/5.3；本段"实例槽"是账本层的关联概念，不动 push constant 现状。
- **流送预算环/决策层** → 步骤 6（开放世界流送设计 §8 落位）。
