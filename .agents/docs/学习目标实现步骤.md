## 步骤 1：简单熟悉 Bevy 的结构

**目的**：建立“哪些是宿主、哪些是要绕开的渲染栈”的心智地图。熟悉到能组装即可，深度理解在后续施工中按需补。

**做什么**（已完成的学习范围）：

1. 跑 `hello_world`、`empty_defaults`、`3d_scene` 三个最小示例。
2. 读 `App` / `Plugin` / `SubApp` 与 `App::run()` 生命周期。
3. 把 DefaultPlugins 分成宿主族、渲染族、无关项，形成禁用清单。
4. 理解 Query、Resource、Commands、变更检测与系统排序。
5. 对照入口篇边界表识别需要使用和仅作参照的 crate。
6. 查窗口创建、事件进入 ECS 与 raw handle 的路径。

**产出**：[Bevy 结构笔记](1-熟悉Bevy结构/Bevy结构笔记.md)及该目录材料，回答帧循环、禁渲染后剩余职责、系统执行顺序、glTF 到实体四个问题。

**完成标准**：能解释帧循环时序和插件分类，能逐行说明 `3d_scene.rs`；不以读完所有源码为目标。

## 步骤 2：宿主壳（M1）

**目的**：验证禁渲染 Bevy、winit 窗口和自建 Vulkan 可以共存。

**做什么**（已落地的范围）：

1. 建 workspace member `ash_renderer`，复用本仓库 Bevy 依赖。
2. 组装 App，禁用渲染族及必要连带插件；保留资产、窗口和 ECS。
3. 通过 `PrimaryWindow` 上的 `RawHandleWrapper` 建 Win32 Surface，连接 Instance / Device / Queue / Swapchain。
4. 跑 acquire、清屏、present；处理 resize、最小化与退出。

**产出**：可运行宿主和[《宿主壳搭建记录》](2-宿主壳/2-宿主壳搭建记录.md)。

**完成标准**：清屏持续、窗口生命周期正常、无 wgpu 初始化。历史实跑已经通过；2026-09-23 同步复核闸门四项已全部关闭（逐项记录见[执行记录归档](学习目标执行记录归档.md)与[缺陷文档 §9/§10](3-静态取数链路/3.2-buffer侧上传/已实现缺陷与修复验收.md)），不据旧收官状态豁免。

## 步骤 3：静态取数链路（M2）

**目的**：先打通资产到 GPU 的正确静态版本，为增量和 GPU-driven 提供可复用资源基础。（✅ 2026-09-29 全段收官，逐段证据见[步骤索引](3-静态取数链路/README.md)）

**做什么**：按[五段施工计划](3-静态取数链路/施工计划：Bindless起步五段拆解.md)推进：

1. **3.1 ECS 取数**：glTF WorldAsset 实例化，材质、相机、灯光就位，PostUpdate 在变换传播后采集。
2. **3.2 buffer 上传**：顶点/索引池、合批 staging、transfer 提交、跨族共享或所有权转移、上传完成与内存复用。
3. **3.3 贴图与 bindless**：先验证最小 WGSL → SPIR-V 接口，再确定纹理/采样器 binding、descriptor indexing、槽位发布与安全回收边界。
4. **3.4 管线与绘制**：明确 CPU/shader 布局、反向 Z、viewport/绕向、颜色空间；从清屏长成直接绘制。
5. **3.5 对照验收**：统一调试条件检查几何、base color、UV 和光照方向，收官。

**前置契约**：

- PostUpdate 采集、Last 同帧提交；GPU 异步完成不等于 CPU 跨帧采集。
- 合批是减少提交的基础，独立 transfer 队列是所选路径，不预先保证它比同队列快；timeline 不替代队列族所有权转移。
- staging 等上传完成再复用；目标资源和描述符槽等最后一次使用完成再覆盖或回收。
- M2 的全量拓扑快照与逐 draw push constants 是阶段实现，不是步骤 5 的终态。

**验证**：FlightHelmet 六个 primitive 在统一不透明调试模式下核对完整几何；base color/UV 和方向光另做受控对照。原模型有 `BLEND` 镜片，不能一边丢弃透明材质、一边要求原样完整。Lambert 简化不要求与官方完整 PBR 像素一致。验证层实际启用，上传正常路径不逐资源 `wait_idle`，resize/退出与异常分支复测通过。

预备知识见[glTF 加载链路](1-熟悉Bevy结构/材料/glTF加载链路：从磁盘到Mesh3d.md)。frenderer 的逐 buffer staging 提交是结构参照，不是无需控制条件就能归因的性能基准。

## 步骤 4：可靠增量链路（M3）

> ✅ 验收归档（2026-10-14）：4.1～4.4 全链收官 + 追加段 4.5 缺陷修复 / 4.6 实测缺陷修复 / 4.7 坐标轴指示器清账；验收复核 11 项按关闭口径逐条对账见[验收复核 §8](4-可靠增量链路/4-验收复核.md)。以下保留范围拆解；施工与收官记录见[执行记录归档](学习目标执行记录归档.md)。

**目的**：从“一次正确上传”发展成能长期处理变更、异步到货、删除和替换的资源链路。

**段落**（4.1～4.4）：

| 段 | 交付范围 | 独立验收 |
|---|---|---|
| 4.1 对象增量 | 稳定的 Entity→GPU 实例槽关联；新增、矩阵变化、mesh/material 句柄替换、组件移除与 despawn；不再每帧重建完整上传清单 | 移动物体只更新相关实例数据；替换引用和删除不残留旧对象 |
| 4.2 资产增量 | Mesh / Material / Image 的 `AssetEvent`；同句柄内容变化、共享资产去重、关联材质/包围体失效 | 多实体共享资产时只上传必要的一份内容，各使用者正确更新 |
| 4.3 异步就绪 | pending、上传票据、可使用、失败与取消；到货时检查实体和引用仍有效 | 延迟到货、加载失败、等待期间删除或换柄，不读空槽、不错误复活对象 |
| 4.4 回收与热重载 | 在飞资源延迟销毁、槽位安全复用、容量变化；文件监听配置与 WorldAsset 重载回归 | 反复增删/热重载资源不持续泄漏，不覆盖 GPU 尚在读取的内容 |

**重要边界**：

- **增量上传 ≠ 增量发现**：`Changed<T>` / `Added<T>` 仍扫描匹配实体；先单独计量扫描成本，确认瓶颈后再考虑静态/动态分离或显式脏队列，不先重写 ECS。
- `RemovedComponents<T>` 不带旧组件内容，删除处理依赖自己保存的实例槽与旧资产关联。
- 资产内容变化不一定导致实体上的句柄变化；只监听 `Changed<Mesh3d>` 不足以实现资产热重载。
- 文件变更到磁盘读取、解析、子资产和 GPU 就绪是异步链，不能承诺“改文件当帧全部生效”。CPU 已就绪且在本帧采集前可见的变更，应进入本帧准备；GPU 消费必须受上传完成依赖保护，另记等待帧数。
- 整 WorldAsset 热重载可能 despawn 后重新 spawn，旧 Entity 身份和运行时附加状态不默认保留。

**产出**：对象/资产/上传状态与回收责任清单、增量系统、热重载回归记录。

**完成标准**：零变化时实例与资产上传为零；共享资源、换柄、同柄改内容、延迟到货、删除取消、反复加载卸载全覆盖。分别报告扫描数、上传字节、资源存量和处理耗时，不把“零上传”说成“零 CPU 每对象成本”。

**判定线草案**：场景规模超出驻留预算仍可持续游历（6.3 兑现、无悬空引用）；材质/几何多样性足以支撑步骤 8/9 的 A/B 判定；加载与增删走 4.x/6.3 既有账面，零泄漏、静态游历零重传（对照统一验收口径 §4/§6）。

**边界**：不把本步当成渲染画质问题的解——光照模型/材质模型/阴影归步骤 8，GI 归步骤 9；mesh shader/蒙皮仍不进主线（沿用上方边界句）；“找更大 glTF 文件”不是内容路线本身（5.4 立案时已钉明）。

## 步骤 8：完整延迟渲染管线（M7）

**一句话说明**：本步把现行“不透明管线单方向光直出”改造成无烘焙、传统结构的 PC 端完整延迟管线——Filament BRDF 材质、多光源光照累积、CSM+PCSS 级联软阴影、HDR/ToneMapping/Bloom/SMAA——为步骤 9 的 SCGI 提供 G-buffer 原料与光照注入点；本步不主张 GI 本体与反射。

**范围拆解**（详细施工计划在步骤 7 收官后立案）：

| 段 | 范围 | 验收重点 |
|---|---|---|
| 8.1 G-buffer 与不透明几何 pass | G-buffer 布局（albedo/normal/深度+世界位置重建；**为 motion vectors 附件留位**——SCGI 屏幕侧时域重投影依赖，实证见 SCGI 调研篇）；透明拆前向 | G-buffer 内容与现行 forward 语义逐项对齐（单光源 A/B 对照） |
| 8.2 Filament BRDF 与多光源光照累积 | 材质参数面扩容（metallic/roughness/normal/AO 进材质环记录与贴图槽）、光照累积 pass、多光源列表 GPU 驻留 | 漫反射项与 Filament 参考对照收敛；多光源开关 A/B |
| 8.3 CSM + PCSS 级联软阴影 | 级联划分、shadow depth pass、PCSS 滤波半径 | 阴影开关 A/B、级联边界无跳变、性能成组记录 |
| 8.4 HDR、ToneMapping 与 Bloom | 不透明+透明合成进 HDR 契约、Bloom（HDR 域）、ToneMapping、**输出编码恰好一次**（终结 swapchain 编码判定线悬案） | 与现行 LDR 直出亮度分布对照、Bloom 开关 A/B |
| 8.5 SMAA 抗锯齿 | 边缘检测/权重计算/邻域混合三 pass（LDR 域、tonemap 后；延迟管线不用 MSAA 的标准搭档） | 几何边缘锯齿读图对照、无时域类伪影（SMAA 非时域） |

**SCGI 前置接口（设计约束，非独立段）**：G-buffer 三原料（albedo/normal/世界位置）、光照累积 pass 预留间接光注入项、深度语义与 6.1 反向 Z 对齐。时域稳定手段（缓存侧 Temporal Smoothing/样本预算/求交器）不在本步主张，归步骤 9；TAA 不做（SCGI 主噪声在缓存侧 patch 粒度，屏幕空间逐像素重建帮不上，平滑靠 SCGI 自带机制）。

**判定线草案**：同场景同光照下延迟输出与现行 forward 分项对照（材质各分项、阴影开关、Bloom 开关、抗锯齿前后）；透明物体正确合成且不破不透明结果；GPU-driven 闭环不回退（draw_calls 与 N 的关系维持 5.3 口径）；性能按统一验收口径成组记录——G-buffer 带宽随分辨率不随实例数，应可实测验证。

**边界**：GI 归步骤 9；反射（Realtime probe/SSR）不主张；蒙皮/mesh shader/通用 RenderGraph 仍不进主线；材质贴图面以 Filament BRDF 所需为界，不主张材质编辑器。

## 步骤 9：全局光照（M8）

**一句话说明**：本步已定案 SCGI 路线（2026-10-19 用户拍板）：在步骤 8 的 G-buffer 与光照累积地基上，按 Unity Surface Cache GI 范式做世界空间表面缓存 diffuse GI——把稀缺射线花在贴表面的缓存 patch 上、多跳靠缓存自查询、屏幕侧 per-pixel gather 注入；本步只主张间接漫反射，不主张场景内容（归步骤 7）与镜面反射。

**调研底座**：[Unity SCGI 调研](笔记/渲染/Unity%20SCGI%20调研：Surface%20Cache%20GI%20与世界空间辐射缓存.md)、[全局光照谱系调研](笔记/渲染/全局光照谱系调研：烘焙、探针、屏幕空间与世界空间缓存.md)与用户级《Unity/渲染/光照》文档组（SCGI 总览、SCGI 算法原理、实时 GI 缓存空间策略比较）。段拆解按谱系调研选型阶梯的顺序约束排布——**顺序不可倒：查询端（档 2）→ 求交器 → 动态缓存（档 4）**；档 2 的查询端在动态档原样保留，只是数据来源从"常量环境光"换成"自更新的缓存"。

**范围拆解**（详细施工计划在步骤 8 收官后立案）：

| 段 | 范围 | 验收重点 |
|---|---|---|
| 9.1 间接光注入端与 SH 查询接口 | 谱系阶梯档 2、全步公共接口、零射线起步：单个全局 SH 环境探针（实时随环境光更新、无遮挡——即 SCGI 的 Volume 外 Global Probe fallback，终点保留件）接入步骤 8 光照累积 pass 的间接光注入项；着色端集成走材质环扩通道 | GI 开关 A/B 首次出现间接光差异；探针值随环境光变化；既有判定线零回退 |
| 9.2 求交器与射线基建 | 谱系调研钉明"比选 DDGI 还是 SCGI 更前置"的真缺口：统一射线抽象（UnifiedRayTracing 同构——硬件 RT 与 compute 软件求交同一接口）；软件路线的场景求交结构选型（BLAS/TLAS 或体素化/距离场简化）与构建/更新时机、显存账目；本机 RTX 2060 具备 Vulkan ray query 能力，双后端是否都做立案时拍板 | 任一后端可对场景求交并返回命中点属性（位置/法线/albedo）；feature 启用面与闸门留痕（沿 5.2/5.3 前置闸门惯例）；空转首跑零 VUID |
| 9.3 世界空间表面缓存：patch 池 | SCGI 核心数据结构：patch（位置+法线+SH L1+方差统计+访问计数，对标 4.x 表布局断言纪律）；Volume 球形覆盖 + Cell 网格 + cascade 近细远粗；ring buffer 固定预算分配/回收（回收启发式=活跃数×最后贡献帧×相机距离，加随机抖动防边界闪烁）；patch 从 G-buffer 屏幕反推投放（tile 覆盖率驱动，不从 mesh/UV）；patch 跟随几何（局部位置+transform 每帧重算，与 4.1 账本联动；无"移动即失效"硬开关，irradiance 过渡交给时域累积） | patch 分布可视化（Cell Index 式调试视图）；预算封顶显存不涨；chunk 增删/移动后 patch 跟随（复用 5.4 生成器）；静态场景 patch 池稳态零增长 |
| 9.4 irradiance 更新：射线采样、多跳与时域/空间滤波 | 每活跃 patch 余弦加权半球发射少量射线（自适应射线数：方差高多射、dormant 少射，全局 ray budget 硬约束）；命中点取光=直接光（复用步骤 8 光照累积/CSM 阴影）+命中点所在 Cell 缓存查询——缓存自查询构成多跳隐式反馈环；albedo 从 G-buffer 实时提取（Unity Meta Pass 同构，本项目 G-buffer 天然具备）；时域累积在 patch 空间（方差感知 MSME 式；明确不做屏幕空间重投影——无 SSGI 式拖影，代价是响应 lag，由 Temporal Smoothing 参数控制）；邻域 patch 空间滤波（Irradiance Sharing）可关 | Cornell Box 式色渗（红墙染白地板）多跳可见；开关灯 lag 量级如实记录（慢慢亮/慢慢灭是设计内代价非缺陷）；简单场景收敛后 ray budget 降至低位（"几乎免费"实测）；空间滤波开关 A/B |
| 9.5 屏幕 gather 与最终注入 | per-pixel gather（非 splat）：像素查所在 Cell patch 列表，距离/法线一致/年龄渐入/Chebyshev 软可见性加权；SH L1 × per-pixel shaded normal（normal map 细节进间接光）；低分辨率 lookup + 上采样两段式；抗漏光件=patch 微型深度矩+Chebyshev 软测试（薄墙/零厚度单面墙是所有无网格方案公共盲区，如实标注边界）；结果注入光照累积 pass | GI 关闭时画面与步骤 8 逐像素一致；漏光案例（贴墙灯/单面墙）读图对照；patch 粒度色斑可接受；性能随分辨率不随实例数成组记录 |
| 9.6 动态验收、压测与局限对照 | 动态几何（5.4 生成器 chunk 增删/整块重生）与动态光照（开关灯/昼夜）下的收敛行为；Volume 边界外 fallback 行为（远处偏亮/无遮挡如实记录）；按统一验收口径成组压测（patch 数/射线预算/各 pass 分计时/显存，沿 5.5 计量底座）；对照 SCGI 已知局限清单（cascade 切换闪烁、轴对齐平面闪烁、薄几何漏光、远处色偏、显存增量）逐项自检 | 静态游历零重传零泄漏；动态场景无永久残影；压测报告成组；局限自检留档——命中哪条如实报告 |

**判定线草案**：GI 贡献开关 A/B 画面与统计对照（同场景同光照）；多跳色渗可见、开关灯响应滞后量级如实记录；抗漏光案例不穿墙；静态收敛后 ray budget 降至低位、成本按 patch 数不按像素数成组记录（对齐统一验收口径 §3/§4）；GPU-driven 闭环不回退（draw_calls 维持 5.3 口径）；零 VUID、clippy 全净。

**边界**：
- **diffuse-only 照抄 SCGI 刀法**：镜面间接（SSR/Reflection Probe）不主张；AO 不由 GI 自带（半径外探针兜底 + SSAO 伪造是官方同款组合）。
- 屏幕锐利阴影仍归步骤 8 的 shadow map——SCGI 只吸收 patch 粒度低频遮挡；GI 越真、无阴影悬浮感越明显，阴影须先落。
- 不做烘焙/lightmap 路线（用户级《烘焙》《Lighting Mode》调研仅作对照，不进主线）；TAA 不做（沿用步骤 8 决策——SCGI 主平滑在缓存条目内，屏幕侧 GI 项的时域处理用步骤 8 预留的 motion vectors 留位）。
- 光源支持对齐 SCGI 现状：Directional + Emissive 起步；Point/Spot/Area 的 GI 采样立案时评估（步骤 8 多光源光照累积已落地，命中点直接光可复用其光照/阴影通道）。
- 软件求交是本步主张底线：不把"本机有硬件 RT 就能跑"当完成——射线抽象必须保留 compute 回退语义。
- 不做完整离线烘焙管线；不与步骤 7 的内容生成耦合（场景独立演进）；VT 仍按调研结论不立项（外置条目 6）。

## 统一验收与性能口径

1. **计数清楚**：区分 World 总实体、可渲染实例、唯一 mesh/material/image、可见实例与实际 draw；`--size 50` 不代替实例计数。
2. **条件固定**：记录提交版本、GPU/驱动、Release、分辨率、材质/光照、抗锯齿、present 模式、节流配置、随机种子和相机轨迹。默认 60 Hz 节流下的帧率不是吞吐量；基准需区分真实工作耗时与主动等待，不拿 present 返回当上屏完成。
3. **指标成组**：CPU 的传播、采集/扫描、上传准备、提交分别计时；GPU 用对应工作区间计时；报告 p50/p95/p99、加载/增删尖峰、上传字节、提交次数、显存和待回收资源数。
4. **增长斜率**：1 万/5 万/10 万实例，分别测零变化、少量变化和全动态。静态场景仅移动相机时不应重传全部实例；若仍有 O(N) 查询扫描必须如实报告。
5. **预算先写后测**：以 60 Hz 的 16.7 ms 作为初始帧预算，在每段基准开跑前固定场景与通过阈值，记录实际达到的规模、p95/p99 和瓶颈；不以“肉眼流畅”替代数据。
6. **等待统计有边界**：上传热路径不得逐资源或逐批 `device_wait_idle` / `queue_wait_idle`；显式重建、退出和容量维护单列，不隐去停顿，也不把 fence/timeline 的必要复用等待称为违规。
7. **A/B 控制变量**：frenderer 保留为端到端参照；资产、画质、可见性策略等不同，只能报告系统差异，不能直接归因 bindless。描述符存储模型的收益优先在本渲染器内控制变量比较。
