## §1 目标与取舍

调试 GUI 立起来之后（3.7），检视模型只能改写死的取景参数——补一个环绕相机控制，3.7 的单选钮/统计面板和后续步骤的资产检检视都受益。

取舍句式：**官方 0.21 新增的 `bevy_camera_controller::pan_orbit_camera` 是完整版**（bevy_picking 命中测试决定旋转中心、动量/平滑可调、`bevy_render` 不可选依赖），禁渲染宿主挂不上也用不着——我们只要"固定中心点的检视轨道"这一档，球坐标参数化自写，语义取 three.js OrbitControls 同款（拖动按窗口高度归一、滚轮每格 ×0.95 指数缩放）。结构上**不重写官方渲染器**的边界不受影响：这是 ECS 侧交互件，零 Vulkan 代码。

## §2 结构：机制半边驱动，业务半边给值

| 落位 | 内容 |
|---|---|
| `scene/mechanism/camera_control.rs` | [`CameraOrbit`] 组件（target/yaw/pitch/radius 球坐标）+ `from_pose` 反解构造 + [`AshCameraControlPlugin`] 的 Update 系统 `orbit_camera_control` |
| `scene/content/camera.rs` | `spawn_camera` 里随相机 spawn `CameraOrbit::from_pose(CAMERA_POS, CAMERA_TARGET)`——环绕目标属于场景内容（看哪件东西），按取景参数给出 |
| `main.rs` | 一行 `add_plugins(AshCameraControlPlugin)` |

分家理由与 scene 两半的既有约定一致：控制逻辑对任意带 `CameraOrbit` 的相机通用（机制半边），目标点与初始机位是场景参数（业务半边）。`from_pose` 从现役机位反解球坐标，初始机位零跳变接管（yaw=0.611/pitch=0.317/radius=1.285 与手算 atan2/asin 一致），相机就位核验的 0° 判定线在启动时不受影响。

**帧内时序**：Update 改 `Transform` → PostUpdate 传播（TransformSystems::Propagate）→ Last 的 draw_frame 直读 `GlobalTransform` 建 VP（`FrameInput.cameras`）——同帧生效，无跨帧滞后。写 Transform 只在参数变化帧（dirty），朝向恒 `look_at(target, Vec3::Y)`，与业务半边进场的 `looking_at` 同语义。

**参数**（全 const，集中在文件头）：环绕转速 `2π/窗口高`（拖满一屏高 = 转一整圈，three.js 同款，窗口 resize 手感不漂移；位移用 points 域，DPI 无关）；滚轮每格 ×0.95（three.js 默认 zoomSpeed）；半径限位 [0.5, 10.0]（下限防穿模，头盔半身尺 ~0.3）；俯仰限位 ±89°（距极点留 1°，`cos(pitch)` 恒非零，look_at 的 up=Y 不退化）。

**方向语义**（three.js"拖动世界"约定）：右拖 = 相机绕左、物体呈顺时针转（`yaw -= dx·turn`）；下拖 = 相机升、露头顶（`pitch += dy·turn`）。

## §3 egui 仲裁门：两轮翻车与 layer_id_at 定案

面板（3.7）浮在视口左上，"点在面板上的拖拽归 egui、点在视口的归轨道"需要一个仲裁门。两轮实现都被实测打回：

**第一轮 `egui_wants_pointer_input()`**——按下时 egui 已通过输入桥收到同帧的 PointerButton 事件，`any_down` 已置位，该函数返回值随本系统与 `run_egui_pass` 的执行序漂移（两者同在 Update 无显式序）。实测现象：门的行为不稳定。

**第二轮 `is_pointer_over_egui()`**——看似与执行序无关，实测门**永远关死**：拖拽/滚轮全部无响应。读 egui 0.36.2 源码定位根因：该函数对 Background 层的判定依赖 `root_ui_available_rect`（context.rs:2952），而这个字段**只在 `run_ui` 闭包式 API 里写入**（context.rs:817，`run_ui_dyn` 尾部）；我们的集成（照 bevy_egui 形状）走 `begin_pass`/`end_pass`，该字段恒 None → 指针在背景上时走 "We shouldn't get here, but who knows" 兜底分支**恒返回 true**。两个查询 API 在我们的 pass 形状下都不可用。

**定案：`ctx.layer_id_at(cursor)`（context.rs:3104，公开 API）**——直接问"光标这个点上最顶层是谁"，非 `Order::Background` 层 = 悬在调试面板（浮动层）上，就让给 UI。光标 points 域与 egui 同域直比；查询读最近一次 pass 的层序，最多滞后一帧（点击瞬间指针不会瞬移，调试 UI 场景可接受）。滚轮同门：悬在面板上滚轮让给面板（该帧半径不动），拖拽中指针扫过面板同理。

## §4 视觉验证实录（注入输入 + PrintWindow + 读图）

工具三件（入 `tools/`，可复用）：`capture_window.py`（EnumWindows 按 PID+可见+有标题+最大面积选主窗，PrintWindow PW_RENDERFULLCONTENT 抓图，stdout 报 hwnd/rect/尺寸/md5）、`inject_mouse.py`（SendInput 注入 drag/wheel，DPI 感知）、`focus_window.py`（AttachThreadInput 套路置前台——后台启动的窗口 Z 序靠后，注入前必须先置前台）。

**验证序列**（每轮重启宿主保证单变量）：
1. 置前台 → 注入拖拽 (+300,+150) @ 视口 → 首次接管日志落账（首帧 yaw/pitch/radius）→ 截图读图：正视变俯视后脑勺 ✓
2. 滚轮 −5 格 → 日志 yaw 0.611/pitch 0.317 与初始严格一致、radius 1.285→1.352 ✓（角度不动、距离变远）
3. 滚轮 −15 格（放大差异）→ 头盔显著变小、视角不变 ✓
4. 滚轮 +10 格 → 显著变大、视角不变 ✓
5. 面板内拖拽 → 面板文本被 egui 拖选高亮、相机分毫未动 ✓

**仪器与方法论钉子**（三枚，都实抓过）：

- **PrintWindow 连拍亮度爬升伪影**：无输入连拍，背景色 (40,72,108)→(63,120,161) 指数收敛到稳态（每帧 ×~1.09），整帧等比 ~7% 亮度漂移 → 全图 diff 均值被判据污染（max 78 的均匀低幅差异淹掉结构差异）。BitBlt 对 flip-model 交换链读不到内容（抓到过期垃圾）——PW_RENDERFULLCONTENT（DWM 合成快照）是唯一可用通道，**截图判定必须读图看结构差异，不能只比哈希/diff 均值**。若渲染内容真在逐帧变亮，3.5/3.7 的视觉回归早该崩——伪影在抓图通道，不在渲染。
- **winit 滚轮合并**：SendInput 以 80ms 间隔连发 5 格 WHEEL，应用只吃到 ~1 格（radius ×1.05 而非 ×1.30）；间隔放大到 120ms 后正常。程序化回归滚轮时事件间隔必须拉开。
- **窗口位置层叠漂移**：winit 未显式设 position，每轮启动位置由 Windows 层叠策略决定（实测 (32,32)→(224,224)→(96,96) 各不同）——注入坐标**必须按当轮 `ClientToScreen` 实时推算**，硬编码上一轮的屏幕坐标会落到面板外（负例假阳性）或别的窗口上。

排障过程如实记录：正例拖拽首轮"无反应"，先后排查了窗口遮挡（WindowFromPoint 证伪——三点全在宿主窗上）、焦点（前台 pid 漂移，但鼠标消息不依赖焦点）、孤儿实例（早期后台任务链 `&` 把 `build && exe` 整体挂后台，bash 退出后 cargo 孤儿继续拉起第二个 exe 占着文件导致链接 error 5）——最后靠临时探针日志（`just_pressed` 帧打印 cursor/egui_wants）一击定位是门恒真，撤探针收尾。

## §5 边界与待决

- 无平移（pan）：用户需求只有环绕+推拉，右键/中键拖拽平移不做（官方 PanOrbitCamera 的 picking 命中定中心、动量平滑等也不做）。
- 拖拽中窗口 resize/最小化：会话就地作废（`DragSession` 复位），重按重新开始；未做"拖拽中持续 resize"专项回归（3.2 专项的 resize 矩阵在相机位姿变化下的组合未跑）。
- `layer_id_at` 门依赖 egui 内部层序的公开查询，若将来面板变多窗口/弹层，语义仍是"最顶层非背景让给 UI"，无需改。
- 相机控制与 3.5 官方对照进程（examples/official_reference.rs）无关，不改对照判定。
