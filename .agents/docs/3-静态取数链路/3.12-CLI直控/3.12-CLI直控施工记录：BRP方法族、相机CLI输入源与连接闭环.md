## 1. 结构定案

按侦察笔记 §5 的形状接线：**handler 就是一个 Bevy system**，`RemoteLast`（Last 之后）按帧节拍执行——写值下一帧渲染（BRP 天然以帧为单位量化延迟）。

- **读侧零自研**：官方 inspection 方法族（`world.inspect`/`world.query`/`world.summarize` 等）与内置 CRUD 随 `RemotePlugin` 默认注册（lib.rs:913 `add_inspection_methods`），`rpc.discover` 可列全量。宿主只补一个读方法：`ash_renderer/scene_tree`（层级树）——官方 query 返回扁平行，没有树形与相关性过滤；该方法的行数据/过滤谓词/节点命名**复用 3.10 egui 树窗口的 `EntityRow`/`is_relevant`/`node_label`**（overlay mod.rs `pub(crate)` 重出口），CLI 树与面板树看到同一棵树、同一套"相关"语义。
- **写侧全复用（3.11 定案兑现）**：`ash_renderer/set_transform` 独占 `&mut World` 直调 `apply_transform_edit`（不排队不走 UI）；相机给值按同款形状在机制半边新增 `apply_camera_command`（camera_control.rs）——限位常量、target+offset 加 look_at 的 Transform 写路径与鼠标输入共用，3.9 鼠标与 3.12 CLI 汇入同一套球坐标状态，无两套机位。
- **模块落位**：新顶层模块 `src/remote.rs`（自含 `AshRemotePlugin`，照 scene/overlay 样式）——它横跨 overlay 与 scene，与 driver 的"横跨"性质同层，main 只 `add_plugins`。依赖图注释已更新（lib.rs）。
- **feature 面偏离合账**：bevy 加开 `bevy_remote`（路线图立案要求，区别于"默认 feature 审计口径"的偏差随 3.11 `debug` feature 先例记在 Cargo.toml 注释）；ash_renderer 侧新增直接依赖 `serde_json`（`Value`/`json!`）与 `serde`（derive，参数结构体反序列化）。

## 4. 钉子

### 4.1 handler 错误路径的机制口径（实测收账）

内存钉"system 返回 Result 须 `Result<T, BevyError>` 否则 Err 静默吞"说的是**调度内系统**（Update 等走错误处理器那一层）；BRP handler 走 `world.run_system_with(id, params)`（bevy_remote lib.rs:1705），返回的 `Ok(result)` 直接就是 handler 的 `BrpResult`，`Err(BrpError)` 原样 force_send 给客户端——负例实抓 -23401 原码回传为证。两处机制不同，勿混。

### 4.2 `World::query::<D>()` 单泛型（编译器实抓）

独占系统里的 `world.query::<D>()` 只收 `QueryData` 一个泛型，不能带 `With<F>` 过滤（lib.rs:1862 `pub fn query<D: QueryData>`）——相机查询把 `&Camera` 并进数据元组代替 `With<Camera>`（第三位拆出弃用）。`QueryState::single_mut(world)` 形状无误。

### 4.3 `rpc.discover` 的 methods 是对象表（薄客户端首版崩）

响应 `methods` 是 `[{name, params: [...]}]` **对象数组**而非字符串数组——薄客户端首版按字符串排序直接 TypeError。修后顺带把 params 形参名带出（`discover` 输出即协议速查，AI 免查文档）。

### 4.4 后台起宿主 = 窗口最小化（验收链新前置）

后台（无前台权）直跑 exe，winit 主窗落在最小化态（GetWindowRect 返回 -32000 占位，PrintWindow 只能抓到 199×34 标题条）。解法：**PostMessage WM_SYSCOMMAND SC_RESTORE**（3.5 专项钉子复用；PostMessage 属不受限手段，不碰用户鼠标键盘）——还原后 PrintWindow 抓到完整 1618×947（DPI 125%，swapchain 1280×720pt/物理 1600×900）。**后台起宿主的验收轮，抓图前先查最小化**。

### 4.5 CLI 与鼠标的胜负时序（立案边界钉明）

两输入源写**同一个** `CameraOrbit` 状态：鼠标在 Update（帧中增量），CLI 在 RemoteLast（帧尾绝对值/系数覆盖）——**同帧谁后写谁生效（CLI 帧尾覆盖鼠标帧中）**；且因状态共享，鼠标下一帧从 CLI 给的值继续（与 `from_pose` 零跳变接管同构），不存在两套机位漂移。CLI 写值本身走 `apply_camera_command` 的限位（pitch ±89°、radius 0.5~10），与拖拽/滚轮同界。

### 4.6 相机初值回读链（复原判定线的依据）

初始机位 (0.7,0.7,1.0)→(0,0.3,0) 反解为 yaw 34.992°/pitch 18.144°/radius 1.2845——`camera` 读回值与该值浮点级一致（`CameraOrbit::from_pose` 球坐标反解 + `apply_camera_command` 读回链自证），复原后才抓 `05-restored.png`。

## 5. 视觉验证（画面功能视觉验证规则 §2 口径）

五张证据图均以当前会话模型直接读图，先描述实际所见再对照预期：基线=头盔侧前 3/4 视图带软管环；transform 后=软管垂直抬升出画顶；yaw75=转至侧后视角（受光面变化与固定世界系灯光自洽）；zoom0.7=推近充满画面；restored=与基线同构。**结论：五张全部通过，无黑屏/花屏/缺几何/UI 错位**；截图全部 PrintWindow 按句柄抓取（窗口还原后），无遮挡/干扰。
