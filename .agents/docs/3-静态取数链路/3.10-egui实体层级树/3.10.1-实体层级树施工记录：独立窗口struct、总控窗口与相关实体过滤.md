# 3.10.1-实体层级树施工记录：独立窗口struct、总控窗口与相关实体过滤

> 2026-10-09 施工当日收官。立案原文见[路线图](../../学习目标实现步骤.md)步骤 3 节尾；本记录只写实际做了什么。

## 0. 判定线

**树形结构、点选落账、增删当帧反映、数值一致、帧率无感、零回退，六条全过；全程零 VUID、WM_CLOSE exit 0。**

## 1. 结构定案：独立文件 struct + 总控窗口（用户当日拍板，立案调整）

立案时设想"层级树作为 debug_window.rs 的新增页"。施工时用户改为两条结构要求：

1. **层级树单独用一个 rs 文件 struct 表示**——落位 `overlay/entity_tree_window.rs`，照 `debug_window.rs` 的业务面板模式（"画什么"住窗口文件，"怎么跑"住 ui.rs）；
2. **再一个总的调试 UI 窗口可以打开关闭各个调试 UI**——新增 `overlay/debug_hub_window.rs`：显隐开关住 `DebugWindowsOpen` 资源（每窗口一个 bool 字段），总控面板逐行 checkbox，`run_egui_pass` 的显示门读同资源；egui `Window::open(&mut bool)` 的 [×] 与总控 checkbox 写同一字段，关了从总控再开。

由此立下 overlay 加窗三步惯例（写进三个文件的模块注释）：**新窗口 = 独立 rs 文件 struct + `DebugWindowsOpen` 加开关字段 + 总控加一行 checkbox + pass 里加显示门**。总控自身不可关（"总有一个能再开别的"）。

## 2. 交付形状

| 文件 | 内容 |
|---|---|
| `overlay/entity_tree_window.rs` | `SelectedEntity(Option<Entity>)` 点选资源；`EntityRow` 查询元组（11 项：Entity/Name/Children/Has\<ChildOf\>/Has\<Camera\>/Has\<DirectionalLight\>/Mesh3d/MeshMaterial3d/Has\<WorldAssetRoot\>/Transform/GlobalTransform，抽 type alias 免 clippy type_complexity）；`EntityTreeData` SystemParam 束（单查询完成根定位 + 按实体号取行）；`EntityTreeWindow` struct（递归 CollapsingHeader + 叶子 selectable_label + 选中详情区：Name/柄 AssetId/局部与全局 Transform） |
| `overlay/debug_hub_window.rs` | `DebugWindowsOpen` 资源（stats/entity_tree 两个开关，默认全开）+ 总控面板 |
| `overlay/ui.rs` | `init_egui` 插两个资源；`DebugUiParams` SystemParam 束（stats/mode/windows_open/selected/tree 五字段）；pass 内总控先行 + 两窗口按显隐门调用 |
| `overlay/debug_window.rs` | `DebugWindow` 加 `open: &mut bool` 字段，窗口 [×] 生效 |

## 3. 排障与钉子

### 3.1 系统参数上限 16 束手就擒（合成束）

`run_egui_pass` 原签名正好 16 个参数（bevy `SystemParam` 实现上限，[[bevy-system-param-limit-16]] 的现役实证），3.10 新增的三件（总控开关/点选/树查询）直接爆 `IntoSystem` 不实现。解法：合成 `DebugUiParams` SystemParam 束——嵌套自定义 SystemParam（含 `RendererStats`）合法，pass 签名回到 15 项，后续 3.11/3.12 的新增取数也全走这里，不再撑大签名。

### 3.2 384 个内部实体淹没场景树 → 相关性过滤

首版全量树截图里全是"实体 #N"平铺根行。诊断探针（临时）计数：**全实体 384 / Name 13 / ChildOf 13 / Mesh3d 6 / Camera 1 / Transform 16**——DefaultPlugins 注册的数百个 observer 等内部实体（每个 observer 是一个实体、零被关注组件）把十几个场景实体挤出了滚动视口。解法：`is_relevant` 过滤（至少带一个被关注组件才进树，不相关子树整枝跳过），窗口首行"**相关 X / 全部 Y**"如实报被滤计数。这与立案"递归展示 World 实体"的取舍：全量在计数里保留证据，展示面给可用的树。

### 3.3 迭代项是值不是引用（E0614 三连）

bevy tuple `QueryData` 的 `iter()` 产出 `Entity`/`bool` **本体**；`Children::iter()` 也产 `Entity` 本体（relationship target 自有 iter）。三处 `*x` 解引用全数编译器抓回（`!*has_parent`/`*entity`/`*child`），去星即过。

### 3.4 glTF primitive 是 node 的子实体（树形证据）

树里看到 `Hose_low #370 ▼ → Hose_low.HoseMat #376 [mesh][mat]`——bevy glTF 展开后**每个 part node 实体下挂 primitive 子实体**（名字 = node.mesh 材质名拼接）。6 node + 6 primitive + Scene0 + WorldAssetRoot + 相机 + 灯光 = 场景树全形，与 3.1.4 "primitive 6/6 带父链 6/6" 互证；`WorldAssetRoot` 标记组件在展开后被消费（树里仍作为根行出现——靠 `Has<ChildOf>` 定根，不靠该 marker）。

### 3.5 注入验证与真人操作并发 → 坐标污染（方法论钉子）

注入式点击验证时出现过"未点击的三个节点自行展开"假象。复盘：**用户当时正在手动操作同一窗口**（窗口 rect 从 (224,224) 漂到 (513,103)，后由用户证实自己同时在试），注入坐标按旧 rect 计算打到了别的行上。与 3.9 "窗口层叠漂移"钉子同族：**注入验证期间必须独占窗口，人工输入与 SendInput 并发会互相污染坐标判定**。用户随后实测确认点击行为本身无问题，以真人操作为准收账。

### 3.6 临时探针（已撤）

增删判定线用临时探针验证：`probe_add_remove.rs` 每 2.5s spawn/despawn 一个 `Name::new("【探针】增删测试")` 实体，树根行与"相关"计数当帧反映（计数 384↔385、16↔17 随探针切换）。该探针兼作组件计数诊断（定位 3.2 的淹没问题），**验证完毕后整文件删除**，不进收官提交。

## 6. 收官后追记（2026-10-09）

**帧率显示平滑**：用户反馈 fps 窗口数字逐帧跳变——`debug_window.rs` 加 `FpsMeter` 资源（0.5s 累计窗口出一次平均快照，fps 与平均毫秒同源），pass 每帧 `tick(delta)` 喂数、面板读快照；`DebugWindow` 的 `time` 字段随之退役。实测 1.2s 间隔读数 78→70 每秒至多两变，无逐帧抖动；clippy 全净、零 VUID、WM_CLOSE exit 0。

## 7. 追记：拖选蓝色选区卡死修复（2026-10-09）

**症状**：用户在详情区拖选文字后松开，蓝色选区不释放、跟随鼠标移动。

**根因**（egui 0.36.2 源码钉死）：egui 的按键状态 `down[button]` 只由 `PointerButton` 事件翻转（input_state/mod.rs:1201），`PointerGone` 故意不清（注释明说拖 slider 出视口要继续拖）、`WindowFocused(false)` 只清键盘（:440）。而输入桥 `input.rs` 只在 `pointer_pos` 为 Some 时转发按键事件——指针按住拖出窗口时 winit 依客户区矩形判定 `Leave` 照发（event_loop.rs:1671 `get_pointer_move_kind` 不看是否持有 capture），桥随后收到 Release 却因位置已空整条丢弃，egui 从此永久"按住"。失焦路径同理：按住拖到别的窗口上松开，bevy 收不到 Release，桥也没兜底。

**修复**（`overlay/input.rs`）：桥记"欠账"——已向 egui 报过按下的键（`buttons_down`）其 Release 必须补报，指针离窗时用 `last_pointer_pos`（CursorLeft 不清空）补落点；失焦时统一兑清全部欠账按键。顺手补 `entity_tree_window.rs` `is_relevant` 的 `#[expect(too_many_arguments)]`（3.10 漏网警告，clippy 复查实抓）。

**验证边界**：clippy `--all-targets` 全净；实跑注入验证因与用户手动操作并发冲突中止（rect 被双方拖动污染坐标），按当日新立的[鼠标操作与输入注入纪律](../../../rules/鼠标操作与输入注入纪律.md)不再注入，修复版宿主交用户手动复测；拖选修复的零 VUID/exit 0 回归待用户确认后补记。

## 8. 追记：残留"选区跟随"的定位与处置（2026-10-09，用户拍板不再修）

**桥修复后的残留症状**：拖选详情区文字松开后，选区仍跟随鼠标，点击可清空。用户解锁工作站后由自动哨兵（PostMessage/SendInput 注入）实测，事件流经相机侧（手势落到场景拖拽），详情面板未被命中，**未能取得有效目视实证**；结合解锁前锁屏期的四层探针数据，残留症状的根因定位到 egui 0.36.2 的**跨标签文字选区机制**（`multi_widget_text_select`：端点在多标签间迁移 + 悬停位置逐帧重投影选区），真实宿主的树+ScrollArea 几何触发其连续形态。隔离复现（vendored egui 纯 RawInput 驱动）验证了干净事件流下选区正常冻结、该开关关闭后跨标签异常消失；真实宿主的目视复测因锁屏期三条注入路线被 OS 封死（SendInput 吞输入/聚焦被拒/PostMessage 被 WM_MOUSELEAVE 回收清空指针位置）与解锁后手势落到相机侧而未取得实证。

**已落处置**（均保留在树上）：①桥欠账修复（§7，已提交 ab52d6139）；②`ui.rs` init_egui 设 `interaction.multi_widget_text_select = false`——调试面板选区限制在单标签内，跨标签投影路径（跟随的载体）整体消失，隔离复现验证开关有效。**用户拍板**：不再继续修；若日常使用中再现跟随，再启 vendored-egui 日志 bisect（方法钉子在记忆 `egui-dragselect-follow-bug`）。

**验证方法钉子**：锁定会话下 DWM 不合成 swapchain（PrintWindow 恒白）且真实光标不在窗口导致系统对合成指针重发 WM_MOUSELEAVE——**锁屏期间一切指针注入验证（SendInput 与 PostMessage 皆）物理不可用**，仅日志可读；解锁后 SendInput 会落入场景拖拽（egui 指针未建立时仲裁归相机），验证 egui 交互需先让真实光标完成一次窗口内移动。

**追记（2026-10-10，3.13 Remote 虚拟鼠标复现成功——用户实测"抬起仍跟随"为真，前一轮同日追记的"未复现"结论系悬停点采样错误，已订正）**：以 3.13 的 BRP 虚拟鼠标（应用层注入，不经 OS 输入队列、不受锁屏/焦点约束）在属性面板组件名文本上按原手势复测。**复现关键手势=松开后把指针移回被选中那一行文字内**——首轮验证的三个悬停点（场景区/树行区/相邻组件行）全在被选行之外，选区表现冻结（bbox 逐位不变）；把指针移回 GlobalTransform 行内三个 x 位置后，**选区右边界紧贴光标 x 逐处重投影**（悬停 x280/310/355 → 右边界 359/398/447，六张证据图（编号 11~16）为临时取证产物不入知识库，读图结论即本段悬停点/边界值记录）；垂直离开该行选区保持原值（跨标签投影仍死，`multi_widget_text_select=false` 只杀了跨标签半边），回到该行重投影继续。**机制修正：残留跟随的载体不是跨标签投影，而是单标签（同 galley）内的无按键悬停重投影**——即本记录上一段钉的 egui 0.36.2 源码路径（cursor_for 的 has_reached 分支+停车端点+586-630 无条件回写）的单 galley 形态，`multi_widget_text_select=false` 管不到它。附带语义实测：点击他行文本清空选区、点击面板空处选区保留（egui 选区清除只在文本交互时发生）；桥释放欠账全程干净（历次松开 `mouse_status.held` 恒空，§7 修复无回归）；全程零 VUID、WM_CLOSE exit 0。**修复候选方向（动不动由用户拍板）：重投影回写需加 any_down（按键按下态）门控，或松开时清选区状态**——当年"隔离复现选区冻结"与此不矛盾：隔离工程四种序列均未包含"松开后悬停回原 galley"。

**修复追记（2026-10-10 当日晚，用户拍板方向"松开仍可见"，当日修复并验证全过）**：根因不在 egui 选区状态机本身，而在**本集成漏跑了 egui 默认插件的逐帧账本**——`LabelSelectionState` 的 `on_begin_pass`/`on_end_pass` 只在 `run_ui` 闭包 API（run_ui_dyn，egui context.rs:811-813）里被驱动，`begin_pass/end_pass` 裸集成不会执行，于是 `is_dragging` 首次拖选置位后**永不清零**（唯一清零点在 on_end_pass 的 any_released 分支），`cursor_for` 的重投影块（门=is_dragging）永远带电：指针悬在被选标签上就按悬停位置重写 primary。**修复=overlay/ui.rs 的 run_egui_pass 照 run_ui_dyn 同款形状补跑插件生命周期**（空 root Ui 作钩子宿主；公开 API：`Context::plugin_opt` + `Plugin` trait + `Ui::new`，on_begin_pass 在窗口构建前、on_end_pass 在 end_pass 前）——不 vendor egui、不动上游；其余默认插件不补（CallbackPlugin 零注册 no-op 且类型不可名，DragAndDrop/DebugTextPlugin 钩子在本宿主零负载）。附带恢复两条此前静默失效的 egui 语义：点空处清选区（clicked_something_else）与选中后 Ctrl+C 拷贝；文本 galley 离屏/窗口关闭时选区自动清（glitch 保护）。**验证（3.13 虚拟鼠标全序列，选区蓝 bbox 量化，量化即证据）**：拖选中段（按住）选区跟随=927px@半程（右边界 398 贴光标）；松开仍可见=1913px (331,608)-(467,626)；**同线晃动 x280/310/355 + 离行 + 回行五处 bbox 逐位冻结**（修复前同位重投影：359/398/447、回行 379）；点击空处与点击他行文本均清空；重新拖选可用；RenderMode 单选与树行点选回归正常（unlit 高亮实测）；零 VUID、WM_CLOSE exit 0、clippy 全净。修复行=ash_renderer/src/overlay/ui.rs（run_egui_pass 前后两段 + init_egui 注释订正）。
