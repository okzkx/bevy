# 3.10.1-实体层级树施工记录：独立窗口struct、总控窗口与相关实体过滤

> 2026-10-09 施工当日收官。立案原文见[路线图](../../学习目标实现步骤.md)步骤 3 节尾；本记录只写实际做了什么。

## 0. 判定线

**树形结构、点选落账、增删当帧反映、数值一致、帧率无感、零回退，六条全过；全程零 VUID、WM_CLOSE exit 0。**

## 1. 结构定案：独立文件 struct + 总控窗口（用户当日拍板，立案调整）

立案时设想"层级树作为 debug_window.rs 的新增页"。施工时用户改为两条结构要求：

1. **层级树单独用一个 rs 文件 struct 表示**——落位 `overlay/entity_tree_window.rs`，照 `debug_window.rs` 的业务面板模式（"画什么"住窗口文件，"怎么跑"住 ui.rs）；
2. **再一个总的调试 UI 窗口可以打开关闭各个调试 UI**——新增 `overlay/debug_hub_window.rs`：显隐开关住 `DebugWindowsOpen` 资源（每窗口一个 bool 字段），总控面板逐行 checkbox，`run_egui_pass` 的显示门读同资源；egui `Window::open(&mut bool)` 的 [×] 与总控 checkbox 写同一字段，关了从总控再开。

由此立下 overlay 加窗三步惯例（写进三个文件的模块注释）：**新窗口 = 独立 rs 文件 struct + `DebugWindowsOpen` 加开关字段 + 总控加一行 checkbox + pass 里加显示门**。总控自身不可关（"总有一个能再开别的"）。

## 2. 交付形状

| 文件 | 内容 |
|---|---|
| `overlay/entity_tree_window.rs` | `SelectedEntity(Option<Entity>)` 点选资源；`EntityRow` 查询元组（11 项：Entity/Name/Children/Has\<ChildOf\>/Has\<Camera\>/Has\<DirectionalLight\>/Mesh3d/MeshMaterial3d/Has\<WorldAssetRoot\>/Transform/GlobalTransform，抽 type alias 免 clippy type_complexity）；`EntityTreeData` SystemParam 束（单查询完成根定位 + 按实体号取行）；`EntityTreeWindow` struct（递归 CollapsingHeader + 叶子 selectable_label + 选中详情区：Name/柄 AssetId/局部与全局 Transform） |
| `overlay/debug_hub_window.rs` | `DebugWindowsOpen` 资源（stats/entity_tree 两个开关，默认全开）+ 总控面板 |
| `overlay/ui.rs` | `init_egui` 插两个资源；`DebugUiParams` SystemParam 束（stats/mode/windows_open/selected/tree 五字段）；pass 内总控先行 + 两窗口按显隐门调用 |
| `overlay/debug_window.rs` | `DebugWindow` 加 `open: &mut bool` 字段，窗口 [×] 生效 |

## 3. 排障与钉子

### 3.1 系统参数上限 16 束手就擒（合成束）

`run_egui_pass` 原签名正好 16 个参数（bevy `SystemParam` 实现上限，[[bevy-system-param-limit-16]] 的现役实证），3.10 新增的三件（总控开关/点选/树查询）直接爆 `IntoSystem` 不实现。解法：合成 `DebugUiParams` SystemParam 束——嵌套自定义 SystemParam（含 `RendererStats`）合法，pass 签名回到 15 项，后续 3.11/3.12 的新增取数也全走这里，不再撑大签名。

### 3.2 384 个内部实体淹没场景树 → 相关性过滤

首版全量树截图里全是"实体 #N"平铺根行。诊断探针（临时）计数：**全实体 384 / Name 13 / ChildOf 13 / Mesh3d 6 / Camera 1 / Transform 16**——DefaultPlugins 注册的数百个 observer 等内部实体（每个 observer 是一个实体、零被关注组件）把十几个场景实体挤出了滚动视口。解法：`is_relevant` 过滤（至少带一个被关注组件才进树，不相关子树整枝跳过），窗口首行"**相关 X / 全部 Y**"如实报被滤计数。这与立案"递归展示 World 实体"的取舍：全量在计数里保留证据，展示面给可用的树。

### 3.3 迭代项是值不是引用（E0614 三连）

bevy tuple `QueryData` 的 `iter()` 产出 `Entity`/`bool` **本体**；`Children::iter()` 也产 `Entity` 本体（relationship target 自有 iter）。三处 `*x` 解引用全数编译器抓回（`!*has_parent`/`*entity`/`*child`），去星即过。

### 3.4 glTF primitive 是 node 的子实体（树形证据）

树里看到 `Hose_low #370 ▼ → Hose_low.HoseMat #376 [mesh][mat]`——bevy glTF 展开后**每个 part node 实体下挂 primitive 子实体**（名字 = node.mesh 材质名拼接）。6 node + 6 primitive + Scene0 + WorldAssetRoot + 相机 + 灯光 = 场景树全形，与 3.1.4 "primitive 6/6 带父链 6/6" 互证；`WorldAssetRoot` 标记组件在展开后被消费（树里仍作为根行出现——靠 `Has<ChildOf>` 定根，不靠该 marker）。

### 3.5 注入验证与真人操作并发 → 坐标污染（方法论钉子）

注入式点击验证时出现过"未点击的三个节点自行展开"假象。复盘：**用户当时正在手动操作同一窗口**（窗口 rect 从 (224,224) 漂到 (513,103)，后由用户证实自己同时在试），注入坐标按旧 rect 计算打到了别的行上。与 3.9 "窗口层叠漂移"钉子同族：**注入验证期间必须独占窗口，人工输入与 SendInput 并发会互相污染坐标判定**。用户随后实测确认点击行为本身无问题，以真人操作为准收账。

### 3.6 临时探针（已撤）

增删判定线用临时探针验证：`probe_add_remove.rs` 每 2.5s spawn/despawn 一个 `Name::new("【探针】增删测试")` 实体，树根行与"相关"计数当帧反映（计数 384↔385、16↔17 随探针切换）。该探针兼作组件计数诊断（定位 3.2 的淹没问题），**验证完毕后整文件删除**，不进收官提交。

## 6. 收官后追记（2026-10-09）

**帧率显示平滑**：用户反馈 fps 窗口数字逐帧跳变——`debug_window.rs` 加 `FpsMeter` 资源（0.5s 累计窗口出一次平均快照，fps 与平均毫秒同源），pass 每帧 `tick(delta)` 喂数、面板读快照；`DebugWindow` 的 `time` 字段随之退役。实测 1.2s 间隔读数 78→70 每秒至多两变，无逐帧抖动；clippy 全净、零 VUID、WM_CLOSE exit 0。
