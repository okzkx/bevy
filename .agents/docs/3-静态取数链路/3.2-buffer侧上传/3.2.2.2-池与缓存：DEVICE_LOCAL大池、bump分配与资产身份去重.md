# 3.2.2.2 池与缓存:DEVICE_LOCAL 大池、bump 分配与资产身份去重

对应[施工 3.2](README.md)任务 3.2.2.2。代码落位 `ash_renderer/src/vulkan/pool.rs`(`MeshPool` / `PoolRange` / `MeshSlot`),内存规则全部引用 [3.2.2.1 契约](3.2.2.1-内存契约：memory type、usage、绑定与对齐.md)——本模块只做池化,不另立内存规则。

**状态:已实现并验收(2026-09-24)。**App 实跑:6 资产单批进池、驻留去重收账"重复快照不再上传";探针组 B:两批票据 + 四段读回逐字节一致 + 重复身份零提交(票据不增)。全程验证层 + 同步验证零 VUID。

## §1 定案

| 项 | 定案 | 依据 |
|---|---|---|
| 池数量 | 顶点/索引**两条** DEVICE_LOCAL 池,各自独立 bump | 扩容迁移互不牵连;索引偏移的 4B 对齐与顶点 stride 对齐各自表达 |
| 分配方式 | bump:`used` 游标单调推进,不回收空洞 | 静态场景只增不删;回收/淘汰/碎片整理留步骤 4(施工计划 §4) |
| 偏移对齐 | 顶点区间按 32B(stride)对齐、索引区间按 4B(U32)对齐 | `vkCmdCopyBuffer` 偏移 4 倍数条款(VUID-00113/00114)、`vkCmdBindIndexBuffer` 偏移按索引类型大小对齐(VUID-08783) |
| 去重键 | `AssetId<Mesh>`(资产身份,非 Handle 弱引用) | 施工计划 §0 判定线 3"mesh/贴图去重驻留";同身份的重复快照零成本短路 |
| 初次容量 | 首个非空批次时懒建,容量 = 需量 ×4/3 与 1MiB 取大,对齐 1MiB | "按收齐的静态需求加余量"(README 任务口径),不预付猜测容量 |
| 账本行 | 每驻留资产记顶点/索引区间 + 顶点数/索引数 + 完成票据 + `vertex_base`(字节偏移÷32)/`first_index`(字节偏移÷4) | 3.4 draw 的 firstIndex/vertexOffset 与"上传完成才可使用"的等待值由账本行直接携带 |

## §2 机制

### 2.1 为什么 bump 而不是逐 mesh 分配

`vkAllocateMemory` 受 `maxMemoryAllocationCount` 约束(VUID-vkAllocateMemory-maxMemoryAllocationCount-04101)——FlightHelmet 6 个 mesh 就 6 次分配,大场景必炸。一把大分配 + 子区间偏移把分配次数与 mesh 数解耦;3.2.2.1 冻结的四条绑定条款里,`memoryOffset` 是 alignment 整数倍(01036)在 offset 0 单分配时代是平凡的,**在 bump 模式才真正活跃**——由本模块的对齐纪律担保(顶点 32B、索引 4B,均为 requirements.alignment=16 的倍数,RWX 2060 实测 alignment 16B,32B 对齐覆盖)。

### 2.2 去重判定:身份命中即短路

`flush_uploads` 每帧从快照收集"在场且未驻留"的身份;`MeshPool::resident(id)` 命中即跳过。同帧两个 primitive 共享一个 mesh 也只算一个身份(保序去重)。重复上传的判定面有两层:编排层身份过滤 + `commit` 对重复登记报错(账本纪律被打破是 Tier② 事件,不是覆盖旧数据)。

### 2.3 容量保证是 alloc 的前置,不是 alloc 的一部分

`ensure_capacity` 与 `alloc` 分离:先保证(必要时走 [3.2.2.3 维护路径](3.2.2.3-容量与销毁：显式维护迁移与停顿分账.md)),后划段。`alloc` 里的 debug_assert 只防编程顺序错误,不做静默扩容——"不写越界"由顺序契约 + 容量保证的结构位置共同担保,而不是运行期兜底。

## §4 边界

- **不含维护/销毁**:容量不足的迁移、等待、停顿记账与销毁纪律见 [3.2.2.3](3.2.2.3-容量与销毁：显式维护迁移与停顿分账.md)。
- **不回收**:资产卸载/重载的失效语义、碎片整理、淘汰留步骤 4(M2 静态场景只增不删,`commit` 重复即报错)。
- **不知 Vulkan 提交**:池只划段记账,拷贝提交在 [`Uploader`](3.2.4-flush_uploads：合批提交、timeline票据与跨族依赖.md)。
