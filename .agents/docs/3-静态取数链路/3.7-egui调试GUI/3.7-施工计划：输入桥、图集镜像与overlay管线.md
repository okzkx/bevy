# 3.7 施工计划：egui 裸接 ash——输入桥、图集镜像与 overlay 管线

> 状态：**已定设计**（本文）。对应[执行路线图](../../学习目标实现步骤.md) §3.7 与[研究篇 §11.2 定案](../../笔记/Bevy GUI 实现研究：布局、渲染、交互三层链路.md)。路线一句话：禁渲染宿主上 `bevy_egui` 挂不上（依赖 bevy_render 的 render graph），egui 官方后端只有 wgpu/glow——Vulkan 集成自己写：消费 epaint 顶点、自建 overlay 管线、字体图集走既有上传链、绘制接在场景之后。

## §0 判定线（先行）

1. **overlay 窗口内可见可交互**：egui 调试窗口在画面之上可见，能拖动、能滚动、能点选 `RenderMode`（unlit/lambert/normal）并当帧生效；
2. **零 VUID**：运行全程 + 退出拆 Device 时刻（含 overlay 新增的图集/顶点环/第二管线）；
3. **不干扰既有同步闸门与帧循环**：D2（fence 提交前重置）/D3（present 信号量按 image）/D4（退出排空）/D6（进场屏障落点）纪律零推翻；3.5 判定线数值零回退；
4. **resize/最小化/WM_CLOSE exit 0** 回归通过；
5. **blend 与色彩约定以 egui 官方 wgpu 后端 0.36.2 源码为据**（判据已钉，见 §2.2，不拍脑袋）。

边界：只做窗口内调试 UI（帧统计、渲染参数实时调），不做运行时产品 UI；BRP web console 是另一条线不并入。IME 不桥接（bevy `Ime` 事件留在原地，输入中文走系统级结果，属显式边界非缺陷）。用户贴图（`TextureId::User`）与 `Primitive::Callback` 不实现，出现时 warn 一次跳过（Tier①）。

## §1 架构：四件与数据流

```
Update（纯 CPU，零 Vulkan）
  bevy 输入事件 ──输入桥──▶ egui RawInput
  ctx.begin_pass → 调试窗口 UI（egui::Window）→ ctx.end_pass
  ├─ 纹理增量就地消费：折进图集 CPU 镜像（3.7.2 资源，Update 侧折入——
  │   最小化帧 Update 照跑而 draw_frame 让路，增量不跨系统存放即不丢）→ clear
  │   （TexturesDelta 的 Drop 审查要求增量被消费，3.7.1 过渡期 clear = 文档化弃置）
  └─ 产 EguiFrame 资源 { shapes, pixels_per_point, screen_points }

Last：draw_frame 内（既有帧循环骨架不动，两处插入）
  wait_for_slot（fence——UI 顶点环复用安全与帧 UBO 同一闸门）
  acquire
  ▶ paint_overlay（新）：
      图集镜像有新代 → 整图重传新 GpuImage（uploader 独立批）
      → tables.publish 新槽（旧图进 graveyard，与表同寿）
      → ctx.tessellate(shapes, ppp) → 顶点/索引写进本帧槽 HOST_VISIBLE 环
      → 产 UiPaint { draws: [index_count/first_index/vertex_base/tex+scissor/…] }
  ▶ record_frame（扩）：同一 dynamic rendering 实例内、场景 draws 之后追加 UI draws
      （管线切换 → 绑 set0/顶点/索引 → 逐 clip：push 16B + scissor + draw_indexed）
  present
```

### 2.2 egui-wgpu 0.36.2 的 blend/色彩判据（GitHub tag 0.36.2 源码，履行 §11.2 "以官方 wgpu 后端为准"）

- **混合状态**：color = `(src: ONE, dst: ONE_MINUS_SRC_ALPHA, ADD)`；alpha = `(src: ONE_MINUS_DST_ALPHA, dst: ONE, ADD)`。Vulkan 镜像写死进 overlay 管线。
- **图集纹理**：Rgba8Unorm（**非** sRGB-aware），LINEAR 滤波——对应本项目的 `R8G8B8A8_UNORM` + `ImageSamplerDescriptor::linear()`（采样器键与 fallback 槽 0 同键去重）。
- **着色路径**：顶点色（gamma 预乘）× 采样值（gamma）相乘后，**gamma 目标**走 `fs_main_gamma_framebuffer` 直出；**sRGB 转换目标**走 `fs_main_linear_framebuffer`：rgb 做 gamma→linear 转换（alpha 原样带过）、ROP 编码恰好一次、blend 落在线性域。本项目 swapchain 正是 UNORM 底板 + SRGB view 别名（3.4 定案）——**官方 linear 路径与本管线输出编码约定逐字同构**，overlay_draw.wgsl 照此实现，连"预乘在 gamma 域完成、转换不拆预乘"这一非理想数学也照抄官方（保真目标 = 与官方 egui 视觉一致，不是理论最优线性预乘）。
- 官方 shader 有 dithering（interleaved gradient noise）与可预测滤波分支——3.7 不搬（项目全管线无 dithering，显式边界）。

## §3 设计决策与理由（六条）

1. **图集更新 = CPU 镜像 + 整图重传 + 新槽 + graveyard**。epaint 图集增量是 dirty-rect 局部补丁（`pos=Some`），而 uploader 图像段只支持整图 (0,0) 拷贝；扩局部区拷贝要引入**新同步方向**——同一图上帧被 graphics 读、本帧被 transfer 写，写前须等读完成，现有票据机制是 transfer→graphics 单向（图形提交只等票据不发票据）。镜像整传把问题归零：每次都是全新 GpuImage（UNDEFINED 起步、屏障合法），`publish` 只写新槽（UAB 无覆盖竞态的结构安全），旧图进 graveyard 与表同寿（retire 前置条件在飞未定，运行时淘汰归步骤 4）。**增量的消费点在 Update pass 出口**（折进镜像后就地 clear），不随 EguiFrame 跨系统传给绘制半边——两个理由：`TexturesDelta` 的 Drop 审查要求增量被消费否则 panic（3.7.1 冒烟已抓现行：未消费增量在覆写时被丢，第二帧即 panic）；最小化帧 Update 照跑而 draw_frame 整帧让路，增量若攒在 EguiFrame 会被下帧覆写丢失（恢复后镜像缺字形、静默花屏）。代价：图集变化帧整图上传（≤2048²×4B≈16MB staging，仅新增字形帧发生，调试 UI 字形集稳态收敛）+ 槽位消耗（容量 1024，静态资产 15 张 + fallback 占 16，余量充足）。
2. **UI 顶点/索引 = 每帧槽 HOST_VISIBLE `GpuBuffer`（新 `BufferRole::DynamicDraw`）**，固定容量（顶点 64K×20B/索引 96K×4B 每槽），复用安全 = `wait_for_slot` 的 fence——与帧 UBO 写入同一纪律同一条闸门。不进 MeshPool：池是 DEVICE_LOCAL 资产级 bump（写入走 staging+transfer），UI 顶点每帧整换、宿主直写更诚实。超容量 = Tier① warn 丢弃当帧 UI（可交互性损失不影响帧循环）。
3. **UI draws 接在同一 dynamic rendering 实例内、场景 draws 之后**（"LOAD 接画"的落法）。光栅序 + ROP 同附件 blend：实例内先后即重叠次序，无需实例间依赖；清屏仍一次。UI 管线声明与渲染实例同格式的深度附件、深度测试/写入全关（订正 2026-10-08：原设计“不声明深度附件”被 VUID-08914 否——未启用 dynamicRenderingUnusedAttachments 时管线 depthAttachmentFormat 必须与实例深度附件相等，“不用即可 UNDEFINED”不成立、首跑被验证层逐 draw 抓获，见[3.7.4 回归收官](3.7.4-回归收官：判定线全量、ppp双域订正与输入排查链.md) §4）。
4. **`RenderMode` 资源化**：从 frame.rs 的 `Local`（env 解析一次）挪成 overlay 模块产出的 Resource（env 解析仍为初值），UI 单选钮写、draw_frame 读——依赖方向 driver→overlay 正向；env 语义保留（默认值 + 文档口径不变）。
5. **set0 跨管线共享**：overlay 管线 layout = `[tables.set0_layout()]` + push 16B，**不声明 set1**（UI 无 UBO）；切换管线后 set0 需按 overlay 的 layout 重绑（同句柄、不同 layout 对象）。表在飞更新对两管线同时生效——"布局=未来管线公共 ABI"的兑现位。
6. **overlay push 16B**：`screen_size: vec2f @0`（**points 域** = 物理尺寸 ÷ ppp，与 tessellate 顶点同域——tessellate 不按 ppp 缩放顶点，ppp 只进字形栅格化/取整/圆半径。域认定两轮反复的完整账：原文"逻辑点"本正确 → 3.7.3 误改"物理像素"（引入用户实测点击偏移）→ 2026-10-08 晚订正回 points，判据 = epaint tessellator 源码 + egui-wgpu uniform 字段 `screen_size_in_points` + DPI 感知像素实测，见[3.7.4 回归收官](3.7.4-回归收官：判定线全量、ppp双域订正与输入排查链.md) §7）+ `tex_index: u32 @8` + `sampler_index: u32 @12`——照 3.3/3.4 三方互证纪律：Rust 镜像 struct `offset_of!` 断言 + WGSL PushParams + pipeline layout range 三方一致。

## §5 时序与同步（零新闸门，逐条对账既有闸门）

| 时刻 | 机制 | 复用的既有闸门 |
|---|---|---|
| Update：egui pass | 纯 CPU | 无 Vulkan 参与 |
| draw_frame：UI 顶点环写入 | 宿主写 HOST_VISIBLE，GPU 上帧在飞读 | `wait_for_slot` fence（同帧 UBO 写入纪律） |

## §7 风险与对策

- **同帧两批的 staging 峰值**：图集变化帧 = flush_uploads 批 + 图集批（16MB），staging 环按需增长已验证（3.2 压力问答）；仅在字形新增帧发生。
- **槽位消耗**：每次图集整传耗 1 个纹理槽；字形集收敛后稳态零消耗。容量监控进调试窗口（used/capacity 实时可见，判定线自证）。
- **egui 修饰键状态**：0.36 无独立 Modifiers 事件，只随 Key/PointerButton/MouseWheel 携带——输入桥每事件附加当前修饰键快照，egui 内部状态由事件流维持。
- **首帧图集 delta 为局部**（理论）：镜像缺失时 warn 一次跳过该补丁（下个整图 delta 自愈）；实际首个 delta 是全新图集（dirty=EVERYTHING）。
- **绕向**：egui 官方明言顶点绕向不一致——overlay 管线剔除保持 NONE（与场景管线同值，理由各自成立）。
