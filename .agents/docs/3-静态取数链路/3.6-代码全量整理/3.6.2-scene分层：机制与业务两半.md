# 3.6.2-scene分层：机制与业务两半

**任务**：3.6"简单分组"第一件（2026-10-08 用户拍板）。`scene/` 拆 `mechanism/`（禁渲染补位 + 采集机制）与 `content/`（FlightHelmet 业务 + 施工核验）两个子目录。**定案：不开新顶层、不细拆**——步骤 5 做 GPU data-driven 时还会有结构大改，现在深拆会返工；本件只做粗粒度归位，零行为变化。

## §1 为什么拆（评估结论，2026-10-08）

用户问"scene 是否该业务与底层框架分层"。通读结论：**混点三处、纯件两件，切线是现状里长出来的**：

| 位置 | 混法 |
|---|---|
| `collect.rs` | 通用采集机制（`collect_scene`/`CollectedScene`）与 FlightHelmet 判定核验（`report_scene_collected`，"期望 6"）同文件、同插件、`.chain()` 锁死 |
| `camera.rs` | 通用宽高比补位（`sync_projection_aspect`，管任意相机）与业务取景（写死 `CAMERA_POS`）同文件 |
| `scene/mod.rs` | `SceneEntryPlugin` 把三个业务 spawn 清单焊在模块组装点 |

纯件：`material_hook.rs` 100% 机制（材质缝补位，与 FlightHelmet 无关）、`world_asset.rs` 100% 业务（写死模型路径）。

**切线证据**：`driver`（upload.rs、host/frame.rs）对 scene 的消费只有一个名字 `CollectedScene`——引擎半边依赖的恰好全是机制半边，业务半边零引擎侧消费者。切开后 `driver → scene::mechanism` 依赖一行不改。

**否掉的方案**：机制半边升格出 scene 进 common 或开第五顶层——common 是纯工具层，塞机制稀释；且 3.6.1 刚定形四层（main → driver → {scene, vulkan} → common），现在破它得不偿失。

## §2 施工内容（零行为变化）

**目录前后**：

```
scene/ 前: mod.rs util.rs material_hook.rs world_asset.rs camera.rs lights.rs collect.rs
scene/ 后: mod.rs util.rs
           mechanism/{mod.rs, material_hook.rs, collect.rs, camera_aspect.rs}
           content/{mod.rs, world_asset.rs, camera.rs, lights.rs, collect_report.rs}
```

| 新位置 | 内容 | 来源 |
|---|---|---|
| `mechanism/material_hook.rs` | 材质缝插件 + 三钩子 + 缝自检 | 原文件整搬，零改动 |
| `mechanism/collect.rs` | 采集插件 + 快照类型 + `collect_scene` | 原 collect.rs 机制半边；核验拆走 |
| `mechanism/camera_aspect.rs` | **新插件 `AshCameraAspectPlugin`** + `sync_projection_aspect` | 原 camera.rs 的宽高比补位 |
| `content/world_asset.rs` / `camera.rs` / `lights.rs` | 业务 spawn + 就位核验（取景/灯参数/`FLIGHT_HELMET` 常量原地） | 原文件搬移，camera.rs 摘掉 sync |
| `content/collect_report.rs` | `report_scene_collected` + `CollectData`/`CollectState` | 原 collect.rs 核验半边 |
| `content/mod.rs` | `SceneEntryPlugin`（业务组清单 + 核验挂载） | 原 scene/mod.rs |

**三处调度变化（语义等价）**：

1. `report_scene_collected` 从 `AshCollectPlugin` 的 `.chain()` 拆出，改挂 `SceneEntryPlugin` 的 PostUpdate、`.after(collect_scene)`——仍在 PostUpdate、仍在传播后、仍链在采集后；`collect_scene` 因此升 `pub(crate)` 当**排序锚点**（语义 = "快照已重建完毕"），锚点知识写在 mechanism/mod.rs。
2. `sync_projection_aspect` 原来由 `SceneEntryPlugin` 的 Update 挂载，现随 `AshCameraAspectPlugin`（机制插件挂机制系统），main.rs 增一行 `add_plugins`（冻结边界允许的操作）。
3. main.rs 的 use 增 `AshCameraAspectPlugin`；lib.rs 的 scene 模块描述改两半结构。`pub use` 链保持 `crate::scene::CollectedScene` 等对外路径不变——driver 零改动。

**分层判定线**（写进 mechanism/mod.rs 文档）：机制 = 换任何场景内容都不变的那半边；业务 = 写死 M2 场景参数与施工核验期望值；一次性核验（"期望 6"）属业务侧脚手架，机制本体不背这些数。
