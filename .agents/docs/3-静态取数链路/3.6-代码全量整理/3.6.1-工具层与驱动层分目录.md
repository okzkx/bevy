# 3.6.1-工具层与驱动层分目录：src 五层分层定形

**任务**:3.6 代码全量整理的第一个施工动作(2026-09-29,用户拍板"error/syntax 作为工具单独分类一个文件夹,host/upload 作为渲染驱动也分类一个文件夹,根目录保持干净")。本记录同时固化 3.6 开工前理清的**代码分层全景**——它是后续所有整理项的坐标系。

## §1 分层全景(2026-09-29 全量通读 24 文件 use 关系核对)

纠正直觉:**不是 `main → scene → vulkan` 的链,而是一棵无环依赖树**——`scene` 与 `vulkan` 零耦合,靠 `CollectedScene` 纯数据快照(只带柄与矩阵)解耦;真正横跨两侧的是 host/upload 两个编排模块。

```
main.rs ──────────── 纯组装:只 use 两个层的插件,零 Vulkan 符号
   │
   ├── scene/        【第 1 层 ECS 取数】纯 bevy,零 Vulkan 符号,产 CollectedScene 快照
   │
   ├── driver/ ─────┐【第 2 层 渲染驱动】两个平级编排模块(本次自 src 根收拢)
   │   ├─ host      │    host   = 帧循环编排(闸门/acquire/DrawList/UBO/提交/present/拆除)
   │   └─ upload    │    upload = 资产进场编排(快照去重→转换→容量保证→合批提交)
   ▼                ▼
   vulkan/ ◄────────┘【第 3 层 Vulkan 资源层】10 子模块,内部有依赖梯度(§3)
   │
   common/           【第 0 层 工具(横切)】error + syntax,零业务依赖,本次自 src 根收拢
```

Unity 类比:`scene` ≈ 场景数据侧;`driver` ≈ render pipeline 的取数与调度环节;`vulkan/` ≈ RHI 资源层。

## §2 本次施工:目录重组(零行为变化)

**目录前后**:

```
src/ 前:main.rs lib.rs error.rs syntax.rs host.rs upload.rs scene/ vulkan/
src/ 后:main.rs lib.rs common/{mod,error,syntax}.rs driver/{mod,host,upload}.rs scene/ vulkan/
```

- `common/` 命名对齐 frenderer 血统(syntax 注释自述移植自其 `modules/common/syntax` crate);
- `driver/` = "渲染驱动"(驱动帧循环/上传链的编排代码,**非 GPU 驱动**,mod.rs 有命名澄清);
- 两个新 mod.rs 带职责表 + 层内依赖说明;`driver/mod.rs` 重出口 `AshHostPlugin`/`AshUploadPlugin`,main.rs 的 use 收拢为 `driver::{AshHostPlugin, AshUploadPlugin}`(main 冻结边界=只许增删 add_plugins,use 路径机械更新不破精神);
- 引用路径变更(全库引用点 grep 清点后机械替换,examples 零波及):`use crate::error::VulkanError` ×10(vulkan/ 全员)、host.rs 嵌套 use ×1、`crate::host` 代码 1 处(upload.rs 的 `.before(crate::driver::host::draw_frame)` 排序)+ 注释 4 处、宏体内 `$crate::syntax::` ×5(syntax.rs);
- lib.rs 模块总览重写为四层 + 依赖方向图(main → driver → {scene, vulkan} → common,单向无环)。

## §3 vulkan/ 内部依赖梯度(现有代码天然成立,无环;mod.rs 文档化归 P0 批次)

| 梯度 | 成员 | 依赖 |
|---|---|---|
| 0 设备事实层 | `context` / `resources` / `mesh_convert`(纯函数) | 只依赖 common::error,互不依赖 |
| 1 执行件 | `uploader`(transfer 队列) / `frames`(graphics 队列) | 事实层;frames→pipeline(pack_push 契约) |
| 2 资产件 | `pool` / `images` / `descriptors` | 事实层+uploader(发票据);pool→mesh_convert(VERTEX_STRIDE 契约) |
| 2 接口件 | `pipeline`(类型上不依赖 descriptors,layout 作参数) / `swapchain`(只依赖 context) | — |

好设计点名:pipeline 不类型依赖 descriptors("集与布局同源"靠 host 接线保证);资产件之间除两条契约依赖外互不引用。**文件位置不再细分目录**(10 文件再分层导航成本反升),分层知识写入 mod.rs 文档即可。
