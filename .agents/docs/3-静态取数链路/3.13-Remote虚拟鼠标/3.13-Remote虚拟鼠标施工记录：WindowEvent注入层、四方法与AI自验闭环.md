## 0. 判定线

**不碰真实鼠标/焦点（全程零 SendInput/SetCursorPos/抢焦点），AI 经 BRP 完成"移动→按下→拖拽→抬起→滚轮"轨道闭环（orbit 读回逐位吻合 + 六张证据图当前模型读图验证通过）；虚拟鼠标可操作 egui 面板（远程点选树行 → 属性面板弹出）并顺带收账 3.12 遗留"属性面板数值联动"的 AI 自验轮（CLI 改值 → 面板同步，证据图 05）；负例三连宿主存活；零 VUID（宿主全日志 grep 计数 0）；WM_CLOSE exit 0；clippy 全净、既有判定线零回退（复原图与基线同机位同场景，唯一可见差异=树选中态保留，见 §4.6）。**

## 1. 结构定案

- **注入层选型（本段最关键的一刀）**：候选三层，实比后定 `Messages<WindowEvent>`——
  1. `Window::set_cursor_position`：公开 API 但**同时写 `cursor_position_request`**，bevy_winit 会拿去真实挪动 OS 光标（碰用户真实输入，违反输入注入纪律）——出；
  2. 直注类型化消息（`CursorMoved`/`MouseButtonInput`/`MouseWheel`）：`ButtonInput`/滚轮累计/egui 桥都能吃到，但 **`Window` 内部光标位没人更新**——相机轨道（3.9）读 `window.cursor_position()` 拿到 None 或真实旧位，拖拽会话开不起来/增量算错——出；
  3. 注 `WindowEvent` 原始层：官方拆分系统 `send_typed_window_events`（bevy_window/src/system.rs:20，PreUpdate `WindowEventSystems`，`.before(InputSystems)`）代拆类型化消息，其中 `CursorMoved` 分支**顺带更新 `Window.internal.physical_cursor_position`**（system.rs:45-62）——光标位走官方通路自管，下游四家（`Window::cursor_position()`/`ButtonInput<MouseButton>`/`AccumulatedMouseScroll`/egui 输入桥）**零特判、零改动**全部吃到——定案。
- **模块落位**：新顶层模块 `src/remote_mouse.rs`（照 `remote.rs` 自含样式）；**注册单点不变**——四个方法仍收在 `AshRemotePlugin` 的 `with_method_main` 链，实现按域分模块（场景语义住 remote.rs、虚拟鼠标住 remote_mouse.rs）；`invalid_params` 升 `pub(crate)` 复用（错误口径一处）。
- **坐标口径**：points 域逻辑像素、左上原点（与 `Window::cursor_position()`/egui 同域），handler 内按窗口 `scale_factor` 换算物理像素（DVec2）。窗口外坐标允许（如实转发；读取侧 `physical_cursor_position` 越界返回 None，应用视作指针离场——与真实鼠标"按下后拖出窗"行为同构）；非有限值 handler 拒 -32602。
- **主窗寻址**：`world.query_filtered::<(&Window, Entity), With<PrimaryWindow>>()`——`World::query` 单泛型钉（3.12 §4.2）的过滤版出路就是 `query_filtered`（bevy_ecs world/mod.rs:1886）。
- **feature/依赖面**：零新增（`bevy_remote`/`serde`/`serde_json` 均为 3.12 已开）。

## 4. 钉子

### 4.1 注入层三层对照（§1 的展开，将来接键盘/手势时照此比）

| 层 | 真光标 | Window 光标位 | ButtonInput/滚轮/egui | 结论 |
|---|---|---|---|---|
| `set_cursor_position` | **挪动** | 更新 | 到 | 出（碰真实输入） |
| 类型化消息直注 | 不动 | **不更新** | 到（相机拖拽死/增量错） | 出（状态劈叉） |
| `WindowEvent` 原始层 | 不动 | 拆分系统代管 | 到 | **定案** |

### 4.2 时序账

handler 在 RemoteLast 写消息 → 次帧 First 换缓冲 → PreUpdate `send_typed_window_events`（`WindowEventSystems`）拆分并更新 Window 光标位 → 同 PreUpdate `InputSystems`（排序 `.before` 已由 bevy_window 配死）更新 `ButtonInput`/`AccumulatedMouseScroll` → Update 相机轨道与 egui pass 消费。**写值下一帧生效，与 set_transform/set_camera 同口径**。`mouse-status` 读的是 RemoteLast 时点状态（本帧消费结果），操作者反馈环即以此为准。

### 4.3 合流语义 = 第二只鼠标

真实与虚拟事件进同一缓冲，**后到者赢**：虚拟 move 覆盖真实光标位、真实一动又盖回来。不做独占/屏蔽（需求出现再立案）；`mouse-status` 无来源标记（合流后不可分辨，如实不报）。

### 4.4 与 `inject_mouse.py` 的分界（无人模式纪律的适用边界）

`inject_mouse.py` 走 SendInput=OS 真输入队列，动的是用户真实光标与焦点——**受无人模式纪律管束**；本段注入发生在应用层消息缓冲（bevy 引擎内），OS 与其他进程完全无感——**不受该纪律约束**。分界线 = 消息是否进 OS 输入队列。

### 4.5 egui 桥与相机的按压前提

egui 桥（3.7）对"无指针位置的按压"整条丢弃（egui 按压无落点），相机轨道以 `cursor.is_some()` 开拖拽会话——故操作序列**先 `mouse_move` 再 press**。虚拟指针悬在调试面板上时，3.9 的 `layer_id_at` 仲裁门照常生效（轨道让 UI）——远程点选树行能成功正是这门的正向用例。

### 4.6 复原判定线的已知差异

复原图与基线差一处可见 UI 状态：树选中态（Hose_low 高亮 + 属性面板开）保留——3.10 的选中态无反选路径（`SelectedEntity` 资源，点选只写不清），属既有行为非本段回退；场景与相机已逐位复原（transform 0/0/0 读回 + orbit 初值读回双证）。

### 4.7 `all` 全释的结账时点

`release --all` 按 RemoteLast 时点的 `ButtonInput` 按住态结账——**同帧连发的 press 尚未落账**（次帧 PreUpdate 才更新），故 press 后立刻 all 释放不到，需隔一帧。正常操作序列（press→move→release）不受影响。

### 4.8 排障实录：WM_CLOSE 发错句柄

收账轮首版 PowerShell 把**进程句柄**（`$p.Handle`）当窗口句柄 PostMessage，消息进无效目标、进程不退、`Wait-Process` 挂死——改 `$p.MainWindowHandle` 后 exit 0。与 3.12 §4.4"后台起宿主=最小化"同属"句柄要拿对"族钉子。
