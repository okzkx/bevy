## §1 3.5.1 相机与光照 UBO（128B）

**要求**：相机 view/projection、方向光、`GlobalAmbientLight`（含相机组件 `AmbientLight` 覆盖）每帧进 UBO；每帧在飞一份，复用前等旧使用完成；非 coherent 映射按需 flush。

**原理/定案**：

- **布局**：`FrameUniforms = view_proj(mat4 @0) + dir_to_light(vec4 @64) + ambient_color(vec4 @80) + light_color(vec4 @96) + mode(u32 @112)`，总长 64B→**128B**。Rust 镜像 `descriptors.rs::FrameUniformsLayout`（`offset_of!` 静态断言 ×5 + size 128）与 WGSL `debug_draw.wgsl`、描述符 range（`FRAME_UBO_SIZE`）三方互证——沿 push 96B 的同款纪律。binding 形状（set1 b0 UNIFORM_BUFFER）与 pipeline layout **不变**：range 住在写入时的 `DescriptorBufferInfo`，扩容不动 ABI（管线机制篇"layout=公共 ABI"的活例）。
- **数值链与 bevy GPU 侧逐字段同源**（`bevy_pbr/src/render/light.rs` prepare_lights 为锚）：
  - `dir_to_light = GlobalTransform::back()`——bevy 写 `dir_to_light: light.transform.back()`（"ready for N.L"），**表面到光**方向，符号混淆在此斩断（面板待决的"传播还是到光"按 bevy 同款定案：存到光，Lambert 直接 `dot(n, dir_to_light)`）；
  - `light_color = LinearRgba(light.color) × illuminance`（20000 lx 白光 → rgb=(20000,20000,20000)）；
  - `ambient_color = LinearRgba(ambient.color) × brightness`（GlobalAmbientLight 默认 80 → (80,80,80)）；
  - 亮度收敛在 shader 常量：Lambert 除 π（bevy `Fd_Burley` 的能量归一同款）+ 曝光 `exp2(-EV100)/1.2`，EV100=9.7 = bevy `Exposure::BLENDER` 默认（`bevy_camera/src/camera.rs` `Exposure::exposure()`），常量 0.0010019。链路同构：bevy 终式 `view.exposure × (direct + indirect)`，我方 `albedo × (direct + ambient) × EXPOSURE`（albedo 可提出）。
- **取数**：Last 直读（与相机 view_proj 同款，灯/相机是"取景与光照数据"不进 CollectedScene 渲染拓扑快照）。方向光取第一盏（多灯 warn 一次），无灯直射项归零 + 方向留合法占位；环境光优先级 = 相机 `AmbientLight` 组件 > `GlobalAmbientLight` 资源 > 归零 warn。
- **在飞安全**：UBO 写发生在 `wait_for_slot` 的 fence 之后（draw_frame 步 1 → 步 4）——同槽两次写之间隔着上一轮提交完成的 fence 等待，安全证据是 fence 而非轮转计数（面板条款照单兑现）。
- **flush 纪律**：`GpuBuffer::write` 内建非 coherent 分支（atom 对齐 flush，3.2.2.1 定案）；本机 FrameUniform 落 `HOST_VISIBLE|HOST_CACHED|HOST_COHERENT`（日志证据），走"免 flush"分支——分支存在且按类型自动分流，调用方无"忘记 flush"入口。

**过程/落点**：`descriptors.rs`（镜像+pack+初值 identity_frame_uniforms）、`host.rs`（FrameInput 扩 lights/ambient 查询 + 打包写入 + 收账日志"3.5 灯光 UBO 收账：方向光 1 盏（dir_to_light = back()，light = (20000.0, 20000.0, 20000.0, 1.0)）；环境 = (80.0, …)（来源 GlobalAmbientLight）"）。

## §2 3.5.2 材质三模式

**要求**：保留不透明调试覆盖、base-color/unlit 测试与简单 Lambert 模式。

**定案**：模式走 UBO `mode` 字段（shader 分支，每帧可切），env `ASH_RENDER_MODE` 选（lambert 默认 / unlit / normal；拼错 warn 后按默认，Tier①）：

| mode | 着色 | 用途 |
|---|---|---|
| 0 lambert | `albedo × (NdotL × light_color/π + ambient) × EXPOSURE` | 数据驱动光照（默认） |
| 1 unlit | `albedo` 直出 | base color/UV/颜色空间对照 |
| 2 normal | `n×0.5+0.5` | 法线方向验收仪器 |

- shader 端 `dir_to_light` 防御性归一化（零向量 normalize 会出 NaN 且 NaN×0≠0，先 select 回退向）；
- 不透明调试覆盖不变（blend 关、BLEND 镜片照画、贴图只采 base color 槽）；
- 3.4 的固定光 `vec3(0.5,1.0,0.3)` 退役为 identity 初值的占位方向。

## §3 3.5.3 对照载体与条件（官方对照进程）

**要求**：独立官方 Bevy 进程 + 并排截图，不为"同屏"重构宿主；条件固定、分项验收。

**载体定案**：`ash_renderer/examples/official_reference.rs`——本 crate 的 bevy 依赖默认 feature 本就全开（主程序只是运行时 disable 渲染族插件），一个普通 example 即完整的官方 wgpu 渲染宿主，零新依赖零 workspace 改动。进程 6s 自动退出（`AppExit::Success`）供脚本定时抓图。

**条件表**（两侧行为逐项钉死）：

| 条件 | 官方侧（official_reference） | 自研侧（主程序） |
|---|---|---|
| 资产 | FlightHelmet.gltf #Scene0（仓库 assets/） | 同 |
| 场景 | 仅头盔（无地面/方块/环境贴图/雾） | 同 |
| 相机 | (0.7,0.7,1.0) 看 (0,0.3,0)，Perspective 默认 | 同（scene/camera.rs） |
| 分辨率 | 1280×720 显式 | winit 默认同值 |
| 方向光 | 20000 lx，rot ZYX(0,−0.15π,−0.15π)，shadow 显式关 | 同（scene/lights.rs） |
| 环境光 | GlobalAmbientLight 默认 80 | 同值进 UBO |
| 材质覆盖 | `OFFICIAL_REF_MODE=unlit` 时全容器置 unlit | `ASH_RENDER_MODE=unlit` |
| 输出链 | LDR 直出 + Tonemapping::None + DebandDither::Disabled + Msaa::Off | 线性着色 → SRGB view ROP 编码 |
| 清屏 | ClearColor 默认灰 | 呼吸蓝（非对照项） |

**分项结论**：

1. **几何**（unlit 图）：六 primitive 轮廓两侧一致，无镜像无颠倒（承 3.4 朝向定案：正高度 viewport 直出）。
2. **base color/UV**（unlit 图）：皮革棕/橡胶绿灰/镜片米黄/木座红棕色相对齐；UV 特征（缝线、盔徽、面罩阀点）两侧同位。编码各恰一次（官方 sRGB 目标 ROP 编码；我方 SRGB view 同机制）。
3. **光照方向**（lambert 图）：亮侧同在左上（盔顶左、面部/面罩前、木座左前亮），右耳罩侧同暗，明暗界线走向一致。官方多出：镜面高光（风镜反光）、Burley 漫反射的回弹、（此对照场景无 IBL/雾/阴影）——差异全部落在"已声明的未对齐项"内（§6），方向判定不受影响。

**工具方法论**（继承 3.2 的 PrintWindow 钉子，新增两条）：

- 截图 = PowerShell PrintWindow（PW_CLIENTONLY|PW_RENDERFULLCONTENT）按进程 MainWindowHandle 抓客户区；全屏截图会被前台窗口遮挡（3.2 钉子）。
- **新钉 ①：进程多顶层窗口，`MainWindowHandle`/`FindWindow` 会选错**——winit 事件窗（14×14）、conhost、IME 辅助窗在场；主窗最小化后"最大可见窗"必是冒充者。回归脚本用 `EnumWindows` 按 PID + 可见 + 有标题 + 最大面积选窗（[窗口闸门专项](../../2-宿主壳/材料/窗口闸门：最小化死锁与resize卡顿的实测与修复.md) §方法论 1 的教训在 3.5 复演了一遍，本次"窗口缩成 14×14/自行还原"的观测全部是它在冒充）。
- **新钉 ②：最小化/还原一律 `WM_SYSCOMMAND`（SC_MINIMIZE/SC_RESTORE）**，`ShowWindow(SW_*)` 绕过 winit 的 WM_SYSCOMMAND 标志同步（同专项 §方法论 3；本轮实测 SC 通道下闸门两日志准时翻转）。

## §4 D7：VkShaderModule 泄漏（回归轮实抓，3.4 遗留）

- **发现**：WM_CLOSE 退出路径验证层收账 `VUID-vkDestroyDevice-device-05137`（"1 leaked objects: VkShaderModule"）。3.4 段"全程零 VUID"结论只覆盖运行中与正常收尾日志，**拆 Device 时刻的泄漏告警没人看过**——3.5 的逐分支回归把它翻了出来。
- **根因**：`GraphicsPipeline::new` 建 module 后把裸句柄传给 `new_inner`，成功路径无人接管（结构体不存、Drop 不拆）；失败路径反而有 `new()` 兜底。每次启动泄漏 1 个。
- **修复**：管线创建成功后立即 `destroy_shader_module`（规范允许：module 与 pipeline 对象无生命周期耦合，编译收口即告别）；失败路径维持原兜底，双拆不可能。
- **登记与复测**：缺陷文档 §11；修复后三模式 + 全套窗口回归退出路径零 VUID。

## §6 诚实边界（未对齐与未做项，不为收官隐藏）

- **官方 PBR 全链未对齐**：Burley 漫反射（roughness 相关回弹）、GGX 镜面、IBL（EnvironmentMapLight）、雾、CSM 阴影、tonemap（官方默认 TonyMcMapface；本对照两侧 None+线性削顶）——光照对照只主张**方向/明暗界线一致**，不主张像素等值（面板口径）。
- **曝光常量硬编码**：EXPOSURE=0.0010019 对应 bevy 默认 EV100=9.7；相机 `Exposure` 组件未读（裸 Camera 无此组件），将来接组件时改 UBO 传参。
- **单方向光**：多灯取第一盏 warn；聚光/点光/级联不在 M2。
- **镜片 BLEND 仍按不透明覆盖**（两侧统一），真实混合归正式材质段（步骤 4 后）。
- **RenderDoc 描述符可见性验证未执行**（承 3.3/3.4，环境未就绪；非本段判定项）。
- wgpu 侧的验证由 wgpu 自己的后端验证承担，本段不对其取证——对照只看画面产物。
