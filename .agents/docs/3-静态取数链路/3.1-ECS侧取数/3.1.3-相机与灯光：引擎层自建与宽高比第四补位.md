## §1 为什么手动建：引擎只搭台，不代建演员

DefaultPlugins 里跟"场景内容"相关的引擎插件都在且不依赖渲染——CameraPlugin 预插 ClearColor（bevy_internal/src/default_plugins.rs:52），LightPlugin 预插全局环境光资源（:54）。但 **Camera 与 DirectionalLight 实体从来都是场景代码自己 spawn 的**——官方每个 3d 示例的 `setup` 里都有这两条 `commands.spawn`。

对比 Unity：新建场景自带 Main Camera + Directional Light，那是"模板"代建；bevy 连模板都不给，引擎层元素一件件自己放。资产这边也指望不上：glTF 只有 `KHR_lights_punctual` 扩展能带灯，FlightHelmet 没启用，更没有相机的概念。这就是[术语篇](场景三层含义：glTF scene、WorldAsset与引擎World.md)的分层结论：**WorldAsset 展开的是资产里有的东西；相机灯光是引擎层元素，走引擎侧 spawn。**

## §2 相机：裸 Camera 三件套

`Camera` + `Projection` + `Transform`（施工计划 §3.1 既定口径），**不用 `Camera3d`**：

- Camera3d 携带渲染图（CameraRenderGraph）、HDR、管纹理用法等一串渲染族组件，禁渲染宿主里全是死重；我们只消费三样数据——从哪看（GlobalTransform）、怎么投（Projection）、活没活（Camera.is_active）。
- 文档明言"无渲染图的 Camera 运行时会报错"（bevy_camera/src/camera.rs:368-371）——报错者是渲染侧系统，禁渲染后无人报，正合"数据先行、渲染后置"。
- `#[require(...)]` 自动带来 Frustum / RenderTarget / VisibleEntities 等（camera.rs:377-384）；相机是根实体、无父链，Transform require 出的 GlobalTransform 种子值即终值——核验系统据此逐字验证 looking_at 语义（偏差 0.0000°）。

取景参数抄官方 FlightHelmet 示例（examples/3d/anti_aliasing.rs `setup`，多个 3d 示例共用）：相机 (0.7, 0.7, 1.0) 看向 (0, 0.3, 0)，常量 `CAMERA_POS`/`CAMERA_TARGET` 落在 scene/camera.rs 顶部。**同源是为了 3.5 同屏对照**——bevy wgpu 渲染同参数场景，几何与光照方向判定才可比。

## §3 灯光：方向光一个实体，环境光一份资源（订正计划 §6.4）

- **方向光**：`DirectionalLight` 沿实体 forward 照射（bevy_light/src/directional_light.rs:25），所以灯只写朝向不写位置（`Transform::from_rotation`）。illuminance 取 `light_consts::lux::FULL_DAYLIGHT`（20000 lx），欧拉角 ZYX `(0, -0.15π, -0.15π)`——均为官方 FlightHelmet 示例取值。require 链自动插入的 CascadeShadowConfig 等照常在场，但阴影是渲染语义，本步不取值。
- **环境光（订正）**：施工计划 §6.4 旧记"AmbientLight 是全局 Resource"已过时——0.20-dev 里 **AmbientLight 是组件**（ambient_light.rs:11 `#[require(Camera)]`，挂在相机上覆盖全局），全局环境光真身是 **GlobalAmbientLight 资源**，由 LightPlugin::build 预插（bevy_light/src/lib.rs:167），默认白光亮度 80。本项目不挂相机级 AmbientLight（与官方默认配置一致），3.5 读 GlobalAmbientLight 进 UBO。

## §4 第四个禁渲染补位：宽高比无人更新

`PerspectiveProjection.aspect_ratio`（初值 1.0，bevy_camera/src/projection.rs:417-427）的官方维护者是 `camera_system`（bevy_render/src/camera.rs:354）：监听窗口创建/resize/DPI 变化改写。它住在渲染族——禁用后**窗口再怎么变，宽高比永远停在初值**，3.4 建 VP 矩阵时画面横向拉伸。

补位两段：spawn 时按主窗口物理尺寸写初值（实测 1.7778）；Update 里 `sync_projection_aspect` 对比-修正幂等（值没变不动组件、变了才写并 debug 日志；宽/高为 0 即最小化时跳过）。至此四个补位凑齐：**资产根、ImageLoader 注册、反射注册（3.1.2 三件）+ 宽高比（本节）**。

## §5 代码落点

场景元素**解耦成组**（2026-09-22 用户定案：相机是相机、灯光是灯光，不放一个方法里）——**一组 = spawn + 就位核验（+ 专属修正）**，组间零耦合；以后任意搭场景，就是在 SceneEntryPlugin 的系统清单里增删组：

| 组 | 落点 | 内容 |
|---|---|---|
| 相机 | scene/camera.rs `spawn_camera`（Startup） | 裸 Camera + Projection（宽高比初值）+ looking_at；进场 info |
| 相机 | scene/camera.rs `sync_projection_aspect`（Update） | 主窗口宽高对比-修正（幂等，变更才写） |
| 相机 | scene/camera.rs `report_camera_setup`（Update 报一次） | 前向夹角判定、宽高比 |
| 灯光 | scene/lights.rs `spawn_lights`（Startup） | DirectionalLight + 朝向；环境光不 spawn（全局资源）；进场 info |
| 灯光 | scene/lights.rs `report_lights_setup`（Update 报一次） | 方向光前向、GlobalAmbientLight 在位 |
| 公共 | scene/camera.rs 顶部 + scene/util.rs | `CAMERA_POS` / `CAMERA_TARGET` 常量（3.5 对照复用）、`fmt_vec3` |

main.rs 零改动（SceneEntryPlugin 已挂载，符合 main 只统筹纪律）。
