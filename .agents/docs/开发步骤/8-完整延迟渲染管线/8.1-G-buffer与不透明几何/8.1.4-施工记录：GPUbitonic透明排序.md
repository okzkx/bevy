# 8.1.4 施工记录：GPU bitonic 透明排序

> 2026-10-22 施工（提交 283b45e15）。任务对应[段施工计划 §1 8.1.4](施工计划：G-buffer与透明层拆解.md)。

## 实际做了什么

- **`transparent_sort.wgsl`（新）**：经典 bitonic 升序网络，N=TRANSPARENT_CAPACITY(16384, pow2)，每线程管一对 (i, i^j)，105 次派发（k: 2..=N ×2，j: k/2..1 ÷2）；push (k, j) 8B 段参数，宿主 `bitonic_sequence` 建管线时一次预生成、逐帧 clone 840B（免借用纠缠）。
  - **首跑钉子**：方向参数最初写成 `(i & j)==0`——经典网络升/降由 `(i & k)==0` 决定、j 是段内配对距离；方向用 j 会让网络破碎（首跑 sort_check 抓到尾部残留 -inf + 陈旧索引）。
- **全容量排序 + padding 语义**：帧首 `cmd_fill_buffer` 把键 buffer 填成 0xFF800000（f32::NEG_INFINITY 位型）+ TRANSFER→COMPUTE 屏障；collect 写真实键，排序后 -inf padding 沉底、真实条目占据数组尾部 [CAP-count..CAP) 升序。
- **gather 反向取数**：`slot = index_list[count-1-i]`（count=min(t_count, CAP)）——升序数组尾部反向 = 最远先画（back-to-front，物体级精度与 CPU 排序同档）。排序缺席帧（见下）数组未排，真实行仍在 [0..count)，尾部反向读取仍覆盖全部真实行（内容对、序未排）。
- **空排让路**：prev 透明计数（本帧槽 t_count 两帧前输出，fence 纪律，先读后清）为 0 的帧 sort=None——不跑 105 次空派发；读数只决定是否跑空排序，不决定画什么（红线边界：跳过的是"已知空的工作"，语义同空场整段跳过）。
- **`ash_renderer/transparent_sort_check`（BRP，判定线③读数口）**：索引/键全量回读（hiz 一次性 staging 形状复用）；CPU 参照 = 账本可绘行走访（alpha<1 行，`conservative_world_aabb` + view_proj 同公式算键）升序排后逐元素对照（键 ≈ 容差 1e-4 + 行槽号集合相等）。

## 验证

clippy 全净、库测试 34/34、零 VUID；3 个不同深度半透明方块：sort_check 零 issues（键序/行集合/键值全对）；换机位（yaw 0→150）重跑仍零偏差——排序随视角正确重排。判据口径：判定线③"GPU 排序结果与 CPU 深度排序参照一致（物体级）"照此兑现。

## 遗留

- 排序每帧恒 105 派发（全容量网络）；透明行常年为 0 的场景由空排让路兜住，行数小但非零的场景仍跑满网络——按需缩容（ceil_pow2(count) 动态序列）留作性能优化项，不主张。
- 键 = 包围盒中心视图深度（物体级）；穿插正确性归精确 OIT（外置拓展），不主张。
