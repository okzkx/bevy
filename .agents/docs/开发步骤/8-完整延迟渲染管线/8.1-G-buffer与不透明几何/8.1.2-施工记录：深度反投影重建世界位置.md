# 8.1.2 施工记录：深度反投影重建世界位置

> 2026-10-22 施工（提交 ee7048a06）。任务对应[段施工计划 §1 8.1.2](施工计划：G-buffer与透明层拆解.md)。

## 实际做了什么

- **set1 二次解冻 128B → 192B**（照 5.1.1 解冻清单先例，一次只解冻本段所需）：`FrameUniforms` 尾部加 `inv_view_proj`（offset 128，mat4）；descriptors.rs 的 `FrameUniformsLayout` 静态断言链（offset 128 / size 192 / FRAME_UBO_SIZE==192）三方互证，pack_frame_uniforms 手工排布。**与 8.2 光源扩容分开解冻**（§3 待决落定——本段只动 inv_view_proj，光源记录的形状归 8.2 立案时再钉）。
- host 侧 `draw_frame`：`inv_view_proj = view_proj.inverse()`（与 view_proj 同帧同源，相机缺席 identity 兜底）。
- **position 可视化模式（FRAME_MODE_POSITION = 3）**：gbuffer_composite 新分支——uv → shader-NDC（`ndc.y = 1 - 2·uv.y`，与全屏三角形 uv 推导同链）→ `world = inv_view_proj × vec4(ndc.x, ndc.y, depth, 1)` → `world.xyz / w`，输出 `world × 0.0625 + 0.5` 编码。RenderMode 加 Position 变体（egui 单选钮 + ASH_RENDER_MODE=position 环境变量双入口）。
- normal 编码钉明（§3 待决）：**世界空间 xyz 直存 R16G16B16A16_SFLOAT（8B/px）**——half 精度足够法线；八面体压缩（4B/px）的带宽账留作后续优化项，学习项目取数便利优先。
- motion vectors 留位钉明（§3 待决）：**不分配附件本体**，槽位契约（G-buffer 布局表槽位 2）在 gbuffer.rs 模块注释钉死，9.x 前置施工件建本体时插入不动既有槽位语义——"留位不写内容"落在布局契约而非空附件（省 8B/px 无消费带宽）。

## 验证

clippy 全净、库测试 34/34、零 VUID；`ASH_RENDER_MODE=position` 读图（`.temp/8.1/8.1.2_position.png`）：世界位置重建呈连续平滑渐变、墙面无碎片跳变、几何边缘清晰——深度反投影机制成立，步骤 9 SCGI 播种/gather 的取数面就位。
