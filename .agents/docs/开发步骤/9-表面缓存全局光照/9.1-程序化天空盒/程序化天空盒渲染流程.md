# 程序化天空盒渲染流程

在这套帧结构里，天空**不是**一个独立的 pass，也没有自己的管线、描述符集或渲染目标。它是延迟合成 pass（帧编排的第 ⑤ 段）里背景像素的一个分支返回值——一帧只写一次，写进 HDR 颜色附件，然后和其他像素一起走透明混合与后链。

本篇讲它在帧里的位置、GPU 侧的读写形状、以及写出之后会被谁改。天空颜色怎么算见[算法原理](程序化天空盒算法原理.md)；参数从面板/BRP 到 UBO 的完整走读见[功能流程导读](程序化天空：从参数到背景像素.md)。

## 一帧里的位置：G-buffer 之后，透明层之前

帧录制按九段组织（`ash_renderer/src/render/frame/record.rs`）。与天空有关的是这一段：

1. **进入 ⑤ 段**（`record.rs:250` 起）：G-buffer 的四张颜色附件转成只读（供采样），深度附件转成只读。这是合成 pass 能读 G-buffer 的前提。
2. **合成 pass**（`record.rs:270`）：全屏、无深度附件，读 G-buffer 算光照写 HDR 目标。天空在它里面。
3. **透明前向层**（`record.rs:291` 起）：在同一个 HDR 目标上 LOAD + 混合，深度转回附件做深度测试。合成写 HDR → 透明读写的内存屏障在同一处建立。

三条顺序约束：

- **必须在 G-buffer 之后**：背景判定要用 G-buffer 深度（`depth == 0` 即 reverse-Z 远平面）。
- **必须在透明之前**：透明层是混合，必须有一个已经存在的底色。天空写在合成里，透明才会叠在天空上；如果把天空挪到透明之后，透明会先和清屏色混合，边缘出现一圈暗边。
- **不新开渲染实例**：合成 pass 本来就要给每个像素写一个值（背景写清屏色），天空只是把这个值换掉。

## 合成 pass 绑了什么，天空用了什么

管线 `gbuffer_composite`（`src/render/passes/lighting/composite_pipeline.rs:16`）一次绑四个描述符集：

| 集 | 内容 | 天空分支用不用 |
|---|---|---|
| set0 | 帧 UBO（272B，相机矩阵 / 灯光 / 模式 / 天空参数） | **用**（`sky_enabled`、`sky_intensity`、四行 `sky_*`、`dir_to_light`、`light_color`、`camera_pos`、`inv_view_proj`） |
| set1 | G-buffer 采样集（albedo / normal / matparam / emissive / depth / 采样器） | 只用 **depth**（判背景） |
| set2 | 光源分簇集 | 不用 |
| set3 | 阴影集 | 不用 |

管线本身没有深度附件（`depth_format: None`），颜色格式是 HDR（`R16G16B16A16_SFLOAT` 族）；全屏三角覆盖整幅画面，所以录制时给的清屏值 `[0.02, 0.06, 0.14, 1.0]` 实际会被着色器覆盖，**决定背景色的不是这个清屏值，而是着色器里的 `CLEAR_COLOR` 常量**——两者必须同值，它管的是"万一有像素没被覆盖"的兜底。

## 像素级：一次深度采样决定走哪条路

```wgsl
let albedo = textureSampleLevel(albedo_tex, gbuf_sampler, in.uv, 0.0);
let depth  = textureSampleLevel(depth_tex,  gbuf_sampler, in.uv, 0.0);
if (depth.r <= 1e-6) {                       // reverse-Z：0 = 远平面 = 背景
    if (frame.sky_enabled == 0u || frame.mode != MODE_SHADING) {
        return vec4f(CLEAR_COLOR, 1.0);      // 天空关 / 调试模式：旧基线
    }
    let v   = world_from_depth(in.uv, 1.0) - frame.camera_pos.xyz;
    let dir = select(vec3f(0.0, 1.0, 0.0), normalize(v), dot(v, v) > 1e-12);
    return vec4f(sky_radiance(dir, true) * EXPOSURE, 1.0);
}
// —— 以下是不变的光照分支
```

（`shaders/scene/gbuffer/gbuffer_composite.wgsl:225-240`）

- **几何像素零变化**：分支在 `if` 里，几何像素不进这段代码，光照累积的逐灯 BRDF、阴影采样、环境项、自发光全按原样执行。
- **背景像素的求值成本**：一次反投影（矩阵乘 + 除 w）、一次归一化、一次 `acos`、三个 `pow`。相对它替代的光照分支（逐灯循环 + PCSS 16~32 tap）可以忽略。
- **方向怎么来的**：用 **近平面**点（`ndc.z = 1`）减相机位置。坑：`ndc.z = 0` 在 reverse-Z + 无限远投影下是 `w = 0` 的无穷远点，反投影出 `NaN`，整片天空会退化成地平线色。
- **退化兜底**：相机与近平面点重合（不可能但便宜）时给 `(0, 1, 0)`，保证不把 `NaN` 写进 HDR。

## 写出 HDR 之后的四个接手者

背景像素的旅程没有在合成 pass 结束：

1. **透明层**（同一次录制的下一段）：在 HDR 目标上 LOAD + 混合。天空是它的底色，所以透明边缘不再和清屏色混。
2. **Bloom**（`shaders/post/bloom/bloom_prefilter.wgsl:5`）：软膝阈值 1.0（HDR 域）。天空本体乘曝光后是 0.13～0.23，**低于阈值、不进 bloom**；太阳圆盘约 4.8，**会**在它周围形成光晕。所以"太阳周围那一圈柔光是 bloom，不是天空函数的光晕项"——两者都存在，量级不同。
3. **tonemap**（`shaders/post/present_tonemap.wgsl:217`）：`frame.mode != 0` 或 tonemap 关时 HDR 直出，不套 ACES。这解释了为什么调试模式下背景是**原始清屏色的 sRGB 编码值**（实测 `(38, 69, 105)`），而 Shading 模式 sky 关时是过 ACES 的值 `(13, 59, 108)`。
4. **SMAA**：在 tonemap 之后做边缘检测与混合，会把天空和几何轮廓的边界混合几个像素。所以要做"天空只改背景"的逐像素对照，必须先关掉 bloom 与 SMAA。

## 同步与资源上新增了什么：什么都没有

- **没有新屏障**：天空只改变背景像素的返回值，不引入新的附件读写。合成 pass 前后的附件状态转换（G-buffer 转只读、HDR 写 → 透明读写、HDR 转只读）与之前完全一样。
- **没有新描述符集 / 管线 / 渲染目标**：天空参数塞进既有的帧 UBO（set1 b0 的 range 从 208 改 272，binding 形状不变），天空函数是公共片段，被合成 shader 静态展开进去。
- **UBO 写入时机不变**：帧槽 UBO 在 `wait_for_slot` 的 fence 之后整块重写（`draw_frame` 的"帧槽 UBO 与环写入"段），与本帧录制、上一轮在飞 draw 都不重叠。
- **每帧槽一份**：帧 UBO 有 2 组在飞，天空参数随帧槽轮转；BRP/面板改参后，下一帧写的是另一个槽，画面照样在下一帧生效。

## 降级矩阵

| 条件 | 背景像素结果 |
|---|---|
| `sky_enabled = 1` 且 `mode = Shading` | `sky_radiance(dir, true) * EXPOSURE` |
| `sky_enabled = 0` | `CLEAR_COLOR`（与步骤 8 逐位一致） |
| `mode = 1..8`（任意天空开关） | `CLEAR_COLOR`（调试视图不被天空污染） |
| 无方向光 | `light_color` 全零 → 渐变色照常，圆盘与光晕自然消失 |
| 相机缺席（identity 兜底） | `camera_pos = 0`、`inv_view_proj = identity`，方向仍有有限值；画面是"站在原点看天空"，不崩 |
| 太阳在地平线以下 | 圆盘落在地平线以下，屏幕上自然看不到（不需要分支） |

## 9.2 的接入点

环境 cubemap 捕获会用同一个函数、传 `include_sun = false`，参数来自同一份帧 UBO。它是一条独立的捕获链（离屏、自己的 pass），**不经过合成 pass**，所以可见画面的天空路径不变；"太阳不进环境项"的边界靠这个参数表达，不靠改合成 shader。

## 边界

- 不动透明层着色、阴影链、后处理链、G-buffer 布局、GPU-driven 闭环、光源常驻表。
- 天空不提供遮挡（室内漏光属已知局限），不提供反射，不参与任何深度/阴影/分簇数据。
