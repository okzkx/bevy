# 9.1.2 帧 UBO 扩列与宿主链

> 施工记录。对应[段施工计划 §0.3/§1 9.1.2](施工计划：程序化天空盒.md)、[八段拆解 §2 9.1](../施工计划：天空盒、IBL 与表面缓存全局光照八段拆解.md)。

## 做了什么

帧 UBO `208 → 272` 字节，新增四个 vec4 槽 + 三个标量，沿用每帧槽一份、整块重写的既有纪律（不新开 set）。

| offset | 字段 | 说明 |
|---|---|---|
| 112 | `mode: u32` | 不变 |
| 116 | `sky_enabled: u32` | 0 关 / 1 开 |
| 120 | `sky_intensity: f32` | 辐亮度缩放 |
| 124 | `_pad: u32` | 对齐垫（原垫位剩余） |
| 128 | `inv_view_proj: mat4` | 不变 |
| 192 | `camera_pos: vec4` | 不变 |
| 208 | `sky_zenith: vec4` | xyz = 天顶色，w = 地平线→天顶过渡幂 |
| 224 | `sky_horizon: vec4` | xyz = 地平线色，w = 地平线→地面过渡幂 |
| 240 | `sky_ground: vec4` | xyz = 地面色，w = 太阳角半径 |
| 256 | `sky_sun: vec4` | x=圆盘增益, y=光晕强度, z=光晕衰减幂, w 未用 |

三方同步清单（一次改齐）：

- `shaders/common/frame.wgsl`：`FrameUniforms` 字段与头注（272B、偏移表）。
- `src/render/resident/tables/frame_uniform_table.rs`：`FRAME_UBO_SIZE = 272`、`FrameUniformsData` 六个新字段、`FrameUniformTableLayout` 镜像 + `offset_of!` 断言（116/120/208/224/240/256、`size_of == 272`）、`pack_frame_uniforms` 六处 `put_*`、`identity_frame_uniforms` 初值（天空关）。
- `src/driver/host/frame/scene.rs`：`SceneInput` 加 `sky: Res<SkySettings>`；`write_frame_ubo` 扩参 `sky: &SkySettings`，在打包处把 `zenith/horizon/ground` 的 w 填成配套标量。
- `src/driver/host/frame.rs`：调用点传 `&scene.sky`。
- `src/render/mod.rs`：`pub use passes::sky::SkySettings`。
- `src/driver/host/mod.rs`：`init_resource::<SkySettings>()`（纯 ECS 侧状态，overlay 缺席时 BRP 照常可写）。
- 注释同步：`shaders/scene/gbuffer/gbuffer_write.wgsl` 的 "208B" → "272B"。

## 坑

- WGSL uniform 里 `vec3f` 成员按 16B 对齐，不能按 12B 紧凑排。所以三个颜色各占一个 vec4 槽，尾部 4B 塞配套标量（幂/角半径），`sky_sun.w` 空置。
- 偏移的唯一闸门是 Rust 侧 `offset_of!` 静态断言：WGSL / 布局镜像 / 打包三者不一致时**编译期**就炸，不靠运行期症状发现。
- 打包 `sky_horizon.w = ground_exponent`、`sky_ground.w = sun_radius`：字段名与它在着色器里的用途跨行，容易填错行；`cargo fmt` 后四行紧凑成对，改动时逐行核对。

## 验证

- 编译期断言全过（`cargo build -p ash_renderer`）。
- 运行期通路：`sky_stats` 回显默认值、`sky_set` 改三色后画面下一帧跟着变（证据见 [9.1.5](9.1.5-判定线与计量.md) 判定线④）。
