# 程序化天空盒算法原理

屏幕背景的天蓝色不是调出来的：它是**沿视线对大气做散射积分**的结果——太阳光进入大气后被空气分子、气溶胶和臭氧分别散射/吸收，进入相机的每一段路径贡献一点光，积分起来就是天空。

> `sky_radiance(dir, include_sun)` 收一个归一化方向，沿这条射线积分大气单次散射（外加被阳光照亮的地面与太阳圆盘），返回线性辐亮度（pre-exposure 域）。

实现口径照 Unity HDRP Physically Based Sky：三介质 + Chapman 解析透射率 + 16 步积分 + 地面反照率；不做多次散射（没有 LUT）。它在帧里怎么被调用见[渲染流程](程序化天空盒渲染流程.md)，参数怎么进来见[功能流程导读](程序化天空：从参数到背景像素.md)。

## 为什么颜色是"算"出来的

一颗蓝光散射更强的分子（瑞利散射 ∝ 1/λ⁴）意味着：

- 抬头看天顶，视线短，蓝光被散射出来的比例高 → 天顶是蓝的；
- 看地平线，视线长，蓝光在路上被散射掉、剩下的光偏红 → 地平线偏白偏暖；
- 太阳落到地平线附近，阳光斜穿几倍厚的大气，蓝光几乎被散射殆尽 → 晚霞是橙红的。

这些不是三条独立规则，是同一个积分在不同几何下的结果。HDRP 的 Gradient Sky（上一版实现）用三个颜色 + 两个指数去手工模仿这三种情况，所以只能"待在某个太阳高度附近好看"；物理模型换太阳高度是连续的。

## 积分式

对一条从相机出发、方向为 `dir`、在大气内结束于 `t_end` 的射线：

```
L = Σ 步  T_view(t) · (S(t) − S(t)·T_seg) / σ_e(t)
S(t) = E_sun · T_sun(t) · [ σ_R(h)·P_R(cosθ) + σ_M(h)·P_M(cosθ) ]
```

逐项拆开：

| 符号 | 含义 | 本工程取值 |
|---|---|---|
| `σ_R(h)` / `σ_M(h)` | 瑞利/米氏散射系数，随高度指数衰减 | 海平面 5.8/13.5/33.1 ×10⁻⁶ 与 10 ×10⁻⁶（1/米），标高 8000 / 1200 米 |
| 臭氧 | 只吸收，20–40 km 的三角剖面 | 0.65/1.88/0.08 ×10⁻⁶ /米 |
| `P_R` | 瑞利相函数 `3/(16π)(1+cos²θ)` | 前后对称 |
| `P_M` | 米氏相函数（Cornette-Shanks，g=0.8） | **前向峰**：正对太阳时最亮 |
| `T_sun(t)` | 从该点到太阳的透射率 | Chapman 解析近似（见下） |
| `T_view(t)` | 相机到该点的透射率 | 沿积分逐步累乘 |
| `E_sun` | 太阳辐照度 | 帧 UBO 的 `light_color`（约 2×10⁴） |

`(S − S·T_seg)/σ_e` 是"段内均匀介质"的解析积分（Frostbite 2015 的写法），比 `S·dt` 更准，且在高消光段不会过冲。

## 视线与行星求交：地平线是几何

把相机放在半径 `R + h` 的行星球面上（海平面 = 世界 y 0，`h = camera_pos.y`）。对每个像素方向做两次球求交：

- 大气顶（`R + 55 km`）的出交点 = 积分的终点 `t_end`；
- 行星表面（`R`）的交点若更近，射线就在地面结束——这就是**地平线**：它由 `R`、`h` 和视线仰角决定，不是两个颜色函数的接缝。相机在 3 米高时地平线约在 6.2 km 外（`sqrt(2Rh)`）。

求交用先除半径再开方的形式（`d = (Rs/r)² − (1−cos²χ)`），避免在两个 6.4×10⁶ 量级的数之间做减法损失精度。

## 为什么透射率用 Chapman 解析

每一步都要算"从这个点到太阳"的透射率。三条路：

1. **嵌套 march**（每步再走一遍到太阳）：16 步 × 8 步 = 128 次密度评估，太重；
2. **透射率 LUT**（方向 × 高度预计算）：要多一张纹理、一个绑定、一套重建时机——9.1 的"天空零新资源"结构就被打破了；
3. **Chapman 解析近似**：指数剖面的光学深度有一个小有理近似，O(1) 算完。HDRP 用的就是它。

本工程走第三条。`sky_optical_depth` 里，瑞利/米氏套 `ChapmanUpperApprox`（另有 `ChapmanHorizontal` 处理太阳在地平线附近/以下的情形），臭氧因为剖面不是指数，单独沿射线取 2 个样本积分（乘以 HDRP 的 0.6 修正）——复刻它的 `ComputeAtmosphericOpticalDepth`。

代价是近似误差（HDRP 也带着），换来的是**没有任何新 GPU 资源**：天空仍是纯函数，参数全在帧 UBO 里。

## 16 步积分与二次分布

主视线取 **16 步**（HDRP 烘焙 SkyView LUT 也是 16 步）：

- 步长按 `t = ((s/N)² · t_end)` 分布——近端密、远端疏。近端密度大、贡献变化快，远端稀薄、可以粗；
- 每步用起点与终点的中点求密度，段内按解析式积分；
- 密度评估只有 2 个 `exp`（瑞利/米氏）加一个三角剖面（臭氧），消光与散射共用。

视线贴近地平线时路径可达上千公里，`σ_e` 可能非常小，解析式分母用 `max(σ_e, 1e-12)` 兜底。

## 地面：Lambert 反照率 + 阳光透过率

射线打中行星表面时，那个点是"地面"：

```
L_ground = E_sun · albedo/π · max(N·L, 0) · T_sun(地面点)
```

反照率默认取中性灰 0.25（HDRP 默认 0.12/0.10/0.09 是地球土色，在本工程的灰色场景里像一条褐色带）。这一项没有天空照地的二次光——所以**暮光时地面接近全黑**：太阳的直射几乎被长光程吃光，而补上这部分需要的正是 HDRP 的"地面辐照度 LUT"，属多次散射/预计算那一档。

## 太阳圆盘与米氏前向峰的分工

- **圆盘**：解析项（角度软化），颜色 = `light_color × sun_gain`，不进积分——太阳角径远小于积分步长，塞进去只会得到噪声。
- **太阳附近的亮区**：不再有手写的 `glow` 参数，它来自米氏前向峰（`g=0.8` 的 Cornette-Shanks 在 `cosθ→1` 时急剧升高）。抬头正对太阳时，整片天空被这个峰抬亮——这是物理正确的结果，也是"太阳在那边"的方向感来源。
- `include_sun=false`（9.2 的环境 cubemap 捕获）只排除圆盘，米氏前向峰仍留在捕获里；HDRP 的 cubemap 烘焙同口径。

## 曝光与亮度标定

天空输出与直接光同处 pre-exposure 域，合成 pass 末尾统一乘 `EXPOSURE = 0.00016`（`brdf.wgsl`）。

物理天空在 2 万 lux 的输入下比旧渐变暗数倍（旧渐变是艺术值，不是物理值），所以 `SkySettings.intensity` 是**标定旋钮**：默认 2.0，让天顶落在 0.1 左右的 HDR 值、经 ACES 后是舒服的蓝。HDRP 建议的 13 万 lux 是"物理正确的一天"，把它搬到我们的曝光锚点上会直接把直接光过曝，不需要跟。

## 没有做的部分，以及它们各自补什么

| 缺项 | 后果 | 补法（档位） |
|---|---|---|
| 多次散射 | 背光面天空偏暗、暮光偏暗，暗部偏饱和 | 32×32 多次散射 LUT（B 档，HDRP 同构） |
| 天空照地（地面辐照度） | 暮光时地平线以下接近全黑 | 地面辐照度 LUT（C 档） |
| 大气透视（雾） | 远景没有空气感，山地不会随距离变蓝 | 体积雾 + 3D 散射 LUT（C 档） |
| 云、星空、行星纹理 | 没有 | 与天空模型正交 |

## 已知边界

- **室内会看到天空**：天空只出现在"没有几何写深度"的像素上，遮挡是 GI/AO 的事（9.4 起）。
- **天空的"地面"和场景地面是两套几何**：物理天空的地面是 6 千公里外的球面，场景地板是有限几何，交界处可能看出色差/缝；把 `ground_albedo` 调到接近场景地面最省事。
- **无方向光时天空全黑**：`light_color` 全零，散射积分没有光源——物理上正确（夜里），但不像旧渐变那样还有一个恒定底色。
- **f32 精度**：行星半径 6.4×10⁶ 的 ulp ≈ 0.5 m，高度用 `r − R` 计算误差 <1 m，对密度（标高 8 km）的影响约 1e-4，可接受。

## 可复算的两个校验

**太阳位置**：竖直 FOV 45°、客户区高 900 px → 焦距 `f = 450/tan22.5° ≈ 1086 px`；太阳仰角 `el`、相机俯仰 0 时圆盘中心在屏幕中心上方 `f·tan(el)`。仰角 5/10/15° 实测 y = 354/257/158，理论 355/259/159（差 ≤2 px）。

**日落红移**：太阳仰角 0° 时地平线采样 `(251,174,96)`（R 远大于 B），仰角 70° 时天顶 `(69,106,148)`（B 大于 R）——同一套系数、同一套相函数，只换了太阳高度，颜色翻转来自光程而不是任何颜色参数。
