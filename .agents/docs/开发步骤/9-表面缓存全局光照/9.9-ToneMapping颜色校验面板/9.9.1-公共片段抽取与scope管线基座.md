# 9.9.1 公共片段抽取与 scope 管线基座

**状态：✅ 已完成并验证（2026-11-26）。** 抽取后 present 输出逐字节不变；颜色校验管线（bindings/布局/登记/接线）就位，关闭时不产生任何命令。

## 为什么先做抽取

校验面板要报"校色输入"（B 域）的分布，而这个量的定义就写在 `present_tonemap.wgsl` 的 `fs_main` 里：`(hdr + bloom * strength) * exposure_scale`。如果面板自己再写一遍这个式子，以后调 Bloom 或曝光就很容易出现"面板显示的数学和画面用的不一致"。所以先把它抽成唯一真源，让 present 与 scope 都 import 同一段。

抽取边界是刻意画窄的：只抽"Bloom 叠加 + 曝光乘"，**不抽曲线、不抽 `mode != 0` 直出分支**。曲线分支里含两种完全不同的映射和矩阵常量，抽出去会让公共片段变成第二个后处理入口；直出分支是调试路径，判断留在各自 `fs_main` 更清楚。

## 实现

新增 `ash_renderer/shaders/common/tonemap_shared.wgsl`：

- `struct BloomParams { strength, enabled, tonemap, curve, gain }`（本任务仍是 5 个 f32；9.9.8 才追加 `tonemap_strength`）。
- `fn exposure_scale_of(state: vec4f) -> f32`：`select(1.0, state.y, state.y > 0.0)`，与旧代码逐字相同。
- `fn tonemap_input_color(hdr, bloom, params, exposure_scale) -> vec3f`：`(hdr + bloom * params.strength) * exposure_scale`。

`present_tonemap.wgsl` 删掉本地 `BloomParams`、加 `// #import tonemap_shared`，`fs_main` 改为：bloom 仍按 `enabled > 0.5` 条件采样（只取采样值、不乘强度），然后一行 `let color = tonemap_input_color(hdr, bloom, bloom_params, exposure_scale_of(exposure_state[0]));`。乘法顺序保持"采样 × strength → 加 hdr → 乘 scale"，与抽取前逐位相同。

新 `ash_renderer/shaders/post/color_scope.wgsl` 也 import 同一片段，B 域直接复用 `tonemap_input_color`，保证"面板的校色输入"和"画面实际用的校色输入"是同一个函数算出来的。

管线基座（`ash_renderer/src/render/passes/post/color_scope.rs`，初期约 300 行，最终 747 行）：`COLOR_SCOPE_SET_DESC`（8 个 binding，全 COMPUTE 阶段：hdr 采样图 / blit_sampler / bloom 采样图 / bloom_sampler / Bloom 参数 UBO / 曝光状态 / LDR 采样图 / bins SSBO）、`COLOR_SCOPE_PIPELINE`、`ColorScopeSettings`（默认 `enabled = false`）、`ColorScopeTargets`（按帧槽持有 bins 缓冲、描述符集、池、layout，`Drop` 回收）、`ColorScopePipelines`、`ColorScopeDraw`。录制用 `ComputeHandles::record_grid`（本任务新加的二维 dispatch 原语，见 `ash_renderer/src/render/core/record/compute.rs`），因为线程网格按 `ceil(w/stride) × ceil(h/stride)` 铺开，一维 dispatch 不能整除时会在窄分辨率上多出无效线程。

登记与接线：`layout_registry.rs` 的 `ALL_PIPELINES` / `ALL_SETS` 各追加一项（契约测试 `every_pipeline_matches_shader_abi`、`every_shader_entry_has_a_pipeline`、`every_set_declaration_is_valid_and_uniquely_named` 全过）；`init.rs` 建 `ColorScopeTargets`、把 layout 并进 `SetLayouts`、建 `ColorScopePipelines`、加进 `InitChain`（拆除顺序：管线先于目标）；`post_chain.rs` 加可选字段并在 LDR 转 `color_to_sampled` 之后、SMAA 之前录制；`post.rs` 提供 `color_scope_draw`，`frame.rs` 在拿 `SceneResources` 的不可变借之前取可变借（否则 gbuffer 的借会冻结 `post`）。

## 读数与验证

- 抽取无损（判定线①⑧）：`main` 分支同场景、同曝光 `frame_dump` PPM 与 `goal/9.9` 逐字节相同（1600×900、4320016 B，含 16 B 头）；goal 连续两帧相同。曝光用 `{"mode":"auto","min_scale":1.37,"max_scale":1.37}` 钉死，确保覆盖"乘非 1 曝光"路径（纯 manual 会让 scale 恒 1，测不到乘法）。
- 关闭（默认 `enabled=false`）：不录 dispatch、不 copy、不重建描述符集，帧时间与引入前同量级（判定线②⑪）。
- `cargo test -p ash_renderer --lib -- layout_contract color_scope`：契约测试 + color_scope 单测全过；clippy `-D warnings` 0；日志 VUID 0。

## 踩过的坑

- `#import` 只展开 `shaders/common/` 下的片段且名字限 `[A-Za-z0-9_]`；公共片段里不能出现 `@group/@binding`，否则被多个入口 include 时会重复声明。
- 新管线必须同时登记进 `ALL_PIPELINES` 与它用到的 `ALL_SETS`，否则 `every_shader_entry_has_a_pipeline` 或布局契约测试会报"管线用了未登记的 set"。
- `frame.rs` 里 `res`（含 `gbuffer: &post.gbuffer.targets`）的不可变借会冻结整个 `post`，scope 的可变借用必须提前到它之前。
