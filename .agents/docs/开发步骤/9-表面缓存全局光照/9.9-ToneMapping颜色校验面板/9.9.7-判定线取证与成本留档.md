## 关键修复：bins 从宿主内存挪到设备本地

第一版 bins 用 `BufferRole::Storage`，该角色带 `HOST_VISIBLE`（为了能直接 `write` 头区）。每帧 250 万次原子写落在宿主可见内存上，8 Hz 档 `gpu_present` p95 冲到 **40.0 ms**、`cpu_total` p95 42.5（CPU 在等 GPU）——原子经 PCIe/系统内存串行化，比采样本身贵两个数量级。

改成 `BufferRole::DeviceStorage`（`DEVICE_LOCAL`）后连带一串改动：

- 头区不再由 CPU 写：`vkCmdFillBuffer` 清 bins → `MemoryBarrierDesc{TRANSFER/TRANSFER_WRITE → COMPUTE/SHADER_WRITE}` → dispatch 里 `(0,0,0)` 线程用 `atomicStore` 写 magic/stride/宽高/帧号/曝光快照。
- 帧号走 push constant：naga 30 只认 **`var<immediate>`**（`var<push_constant>` 报 `unknown address space: push_constant`），仓库既有写法见 `shaders/gpu_driven/cull.wgsl:31`。
- 样本计数先在组内合并：`Workgroup` 存储类的原子数组被 `spirv-val` 拒（`VUID-StandaloneSpirv-None-10684` 显式布局），所以用单个标量 `var<workgroup> wg_samples: atomic<u32>`，`workgroupBarrier()` 后由 0 号线程把组计数加到三域的 `samples`（三域样本数恒等）。越界线程不能提前 `return`（会破坏 barrier 一致性），改成 `if (in_bounds) { ... }` 包住采样体。
- stride 2 → 4（计划允许的降级顺序）：每域样本 90000，p95 再降 0.15 ms。

## 关键修复：同步校验的 READ_AFTER_WRITE

8 Hz 回读的 `vkCmdCopyBuffer` 在另一个 command buffer、后续 submit 里读 bins，而 bins 刚被 `vkCmdFillBuffer` / dispatch 写过，验证层报：

```
vkQueueSubmit(): READ_AFTER_WRITE hazard detected. vkCmdCopyBuffer ... reads VkBuffer ..., which was previously written by vkCmdFillBuffer ...
```

修法：dispatch 之后补 `MemoryBarrierDesc { src COMPUTE/SHADER_WRITE → dst TRANSFER/TRANSFER_READ }`。注意 ash 0.38 用 Vulkan 1.3 命名，**阶段是 `vk::PipelineStageFlags::TRANSFER` 不是 `COPY`**（写 `COPY` 会编译失败 `E0599`）。修后连续 10 次强制回读 + 8 Hz 档，VUID 0。

## 链未启用时的行为（判定线③补录，2026-11-26）

`tonemap=false`（或调试 `mode!=0`、非 Lambert）时：

- 录制侧 `chain_active=false`，`color_scope_draw` 直接返回 `None`：不录 dispatch、不回读、不推进 bins 帧号（`ColorScopeTargets::frame_index` 也不动）。
- 实测：开采样后帧号 32150 → 关 tonemap 后停在 32151，`color_scope_get` 拿到的仍是这一帧（`frame_age=1`），说明没有偷偷继续采样；恢复 tonemap 后下一帧才继续（32199 → 32224）。
- `once` 在链未启用期间保持排队，不会被消费掉（避免"按了一下没录到"）；恢复后录一帧再复位。
- 面板顶部此时显示"链未启用（当前非 Lambert 或 tone mapping 关闭）：present 直出 HDR，C 域无数据"横幅，横幅下方的直方图是上一帧的旧样本，按 `frame_age` 判断即可。
