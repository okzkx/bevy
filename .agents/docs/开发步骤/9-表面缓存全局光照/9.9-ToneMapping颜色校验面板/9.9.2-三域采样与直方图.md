# 9.9.2 三域采样与直方图

**状态：✅ 已完成并验证（2026-11-26）。** 单次 dispatch 同时产出 A/B/C 三域直方图、CbCr 64×64 与五类计数；三域账平。

## 三个域是什么

后处理链上取三个点，正好对应"调色调的时候，人想知道的三件事"：

| 域 | 采样源 | 含义 | 轴 |
| --- | --- | --- | --- |
| A | `hdr_tex` 原始 HDR（未加 Bloom、未乘曝光） | 场景本来的亮度分布 | log2 绝对亮度，−16…+8 EV |
| B | `tonemap_input_color(hdr, bloom, params, scale)` | 校色曲线的真实输入 | 同上 |
| C | tonemap 写进 LDR 的线性 UNORM 值（面板显示前做 sRGB 编码） | 曲线输出，最终能显示成什么颜色 | sRGB 编码后 0…1 |

B 域不由面板重算，而是直接调 9.9.1 抽出来的公共函数；C 域取 LDR 目标本身，所以它能反映 SMAA 之前的真实输出（dump 是线性值，直接当 sRGB 看会偏暗，这是后面读图时踩过的坑）。

## bins 布局（u32 下标，0 基）

| 区段 | 长度 | 内容 |
| --- | --- | --- |
| 头 | 16 | magic `CSCP`、stride、宽、高、帧号、曝光快照 `[adapted, scale, avg_log2, 1]`（float bitcast） |
| A | 1029 | luma 256 + R 256 + G 256 + B 256 + 计数 5（samples / below / above / zero / clip） |
| B | 1029 | 同上（`clip` 对 A/B 恒 0，位置保留） |
| C | 1029 | 同上，但轴是 sRGB 0…1 |
| CbCr | 4096 | 64×64，行 = Cr、列 = Cb |
| 合计 | 7199 | 28796 B |

轴参数：`AXIS_MIN_EV = -16`、`AXIS_SPAN_EV = 24`，即 256 bin / 24 EV = 0.09375 EV/bin；luma 权重 `(0.2126, 0.7152, 0.0722)`，下限 `1e-6`。C 域用 `bin = clamp(encoded, 0, 1) * 255.999`，所以两端都能落到 bin 0 与 bin 255。

采样：`coord = gid.xy * STRIDE`，越界线程不采样；`uv = (coord + 0.5) / dims`。最终 stride 取 4（9.9.7 定），1600×900 下每域 400×225 = 90000 样本。

## 计数口径（三域统一）

每条样本先记 `samples += 1`，然后：

- 全部分量 ≤ 0 → `zero += 1`，**不落 bin**；
- 否则按 luma / 三通道分别算 bin：落在轴外记 `below` / `above`，在轴内才 `atomicAdd` 到对应 bin；
- C 域另记 `clip`：线性值任一 ≥ 1 记 `clip += 1`（触顶比例，判定线⑥⑬用）。

因此恒等式 `Σ luma_bins + below + above + zero == samples` 对三域都成立，这条"账平"校验后来一次抓出了两个 bug。

## 实现（`ash_renderer/shaders/post/color_scope.wgsl`）

- `@workgroup_size(8, 8)`、`cs_main`；bins 声明为 `array<atomic<u32>>`（`array<u32>` 不能 `atomicAdd`）。
- `add_log2_axis(domain, rgb)`：RGB parade 写各自通道窗口，luma 写第 0 窗口；`add_unit_axis(domain, encoded)` 同理给 C 域；`add_chroma(encoded)` 用 BT.709 算 CbCr，写 64×64 热力图。
- 头区由 `(0,0,0)` 线程写（9.9.7 之后帧号走 push constant，头由 GPU 写）。
- A/B 的 `clip` 恒 0，是布局占位；C 的 `below/above` 恒 0，因为 C 已经 clamp 在 0…1。

## 踩过的坑

- **parade 与 luma 共用窗口**：第一版把 RGB parade 和 luma 都写进同一个 256 窗口，结果"luma 和 = 4 × 样本数"。修法是加 `const CHANNEL_STRIDE: u32 = 256u;`，RGB 写 `domain + (ch + 1) * CHANNEL_STRIDE + bin`，luma 独占第 0 窗口。
- **C 域零样本重复计数**：`add_unit_axis` 里也加了 `samples`/`zero`，`cs_main` 底部又加一次，导致 `luma 和 + zero = samples + 1824`。修法是把计数集中到 `cs_main` 一处：先 `atomicAdd(samples)`，零样本走单独分支记 `zero` 并跳过所有 bin。
- WGSL 数字不能写 `_` 分隔（`0.0031308`、`0.999999` 才是合法写法）；`array<u32>` 不能原子操作，必须 `array<atomic<u32>>`。
- `spirv-val` 拒绝对 `Workgroup` 存储类的数组做显式布局（`VUID-StandaloneSpirv-None-10684`），所以组内计数只能用标量原子变量（见 9.9.7）。
