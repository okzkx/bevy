# 说明：室内外色调与曝光标定

> 2026-11-26 立案记录（纯文档，未开工）。对应[9.9 施工计划](施工计划：ToneMapping颜色校验面板（9.9 追加）.md) §9.9.9。触发：用户当日追问「没有自动白平衡是什么意思，现在还是会出现纯天空盒整体白茫茫」，随后要求「9.9 还需要把 ToneMapping 室内室外的颜色调对」。本文记录诊断口径、数字与候选做法；实测与施工另立 `9.9.K-*.md`，不回写本文。

**一句话**：纯天空白茫茫不是缺白平衡，是曝光下限（`min_scale=0.25`）与固定增益（ACES `gain=8`）把天空送进了曲线肩部；室内外要同时成立，得把"压暗能力"和"测光排除"从室内标定里解耦，而不是加灰世界 AWB。

## 1. 「自动白平衡」是什么，为什么现在没有

- 自动白平衡（AWB）是相机的一步**颜色**校正：估计光源色度，给 R/G/B 乘不同增益，让"应该是中性灰/白"的东西不变色。它改色相，不改亮度。
- 过曝以后三通道都贴在 1，AWB 救不回细节；纯蓝天做灰世界 AWB 反而会把蓝推成灰白——所以"白茫茫"不是它的问题。
- 当前链没有 AWB：`present_tonemap.wgsl:221-242` 只有 `(hdr + bloom) * exposure_scale` 与固定曲线，曝光是标量倍数；没有任何色温估计或 per-channel 增益。
- 不做灰世界 AWB 的理由：物理天空、IBL、太阳颜色都按物理量标定，灰世界假设会把蓝天推灰、把夕阳的橙吃掉，破坏 9.1/9.2 的颜色基线。真要白点校正，应按物理白点单列（见 §4），默认不在 9.9 做。
- 可见后果：没有 AWB 时色偏会保留——这在物理渲染里通常是正确的（阴影偏蓝、夕阳偏橙）；9.9.9 要修的是过曝与灰平，不是把物理色偏抹掉。

## 2. 白茫茫的机制

下表是标定口径与估算，实测在 9.9.9 补：

| 量 | 值 | 出处 |
|---|---|---|
| 曝光锚点 `EXPOSURE` | 0.00016 | `ash_renderer/shaders/common/brdf.wgsl:15` |
| 太阳照度 | 20000 lx | `ash_renderer/src/scene/content/lights.rs:33` |
| 天空本体 HDR | 约 0.1–0.5（intensity 2.0） | [9.1 链路说明](../9.1-程序化天空盒/程序化天空盒渲染流程.md) |
| 太阳圆盘 HDR | 约 9.6（20000 × 1.5 × 2.0 × 0.00016） | `sky.wgsl:177-259`、`sky/mod.rs:61`、`:73` |
| 曝光 `key` | 0.01（室内基线 `avg_log2=-6.65` → `2^-6.65≈0.00996`） | `exposure.rs:150-151` |
| 纯天空需要的 `scale` | 0.02–0.1（`0.01 ÷ 0.5…0.1`） | 上两行 |
| `min_scale` | 0.25（即最多压暗 4×） | `exposure.rs:151` |
| 实际比测光目标亮 | 2.5–12.5× | 上两行 |
| ACES `gain` | 8.0（ACES_LEGACY 观感补偿） | `bloom.rs:158-177` |
| 进曲线的输入（天顶/地平线） | 0.2 / 1.0（`0.1…0.5 × 0.25 × 8`） | 上三行 |

- `min_scale` 是 `scale` 的**下界**，也就是"最多能压暗多少倍"；0.25 = 4×，而纯天空需要 10–50×。它和暗部噪声无关（噪声顾虑在 `max_scale` 的上界），所以调低它只影响强光场景。
- `gain=8` 在 ACES 曲线内部（brightness 参数），是为暗室内景做的观感补偿，不随场景变化；天空进了曲线肩部以后三通道趋同 + ACES 高光去饱和，看起来就是白。
- 太阳圆盘在 HDR 域约 9.6，任何曝光下都必白——这是允许的，验收只看天空本体与地面是否过曝，不要求太阳盘有细节。
- 低太阳：9.1.7 记录仰角 15° 时整片天空被米氏前向峰抬到近白，属物理预期；这一项会和钳位叠加，不能全算在曝光头上。
- 适应：从暗处转到天空，`rate_darken=3.0/s`，且每个帧槽两帧才更新一次（`MAX_FRAMES_IN_FLIGHT=2`），约 1–1.5 s 才收敛。**瞬时白是适应，长期白才是钳位。**

## 3. 先量再改：判别步骤

1. 纯天空视角读 `exposure_get`：`scale` 是否恰为 **0.25**、`adapted_log2` 是否在 -3～-1。是 → 钳位。
2. A/B：`exposure_set {"min_scale": 0.05}`，再试 0.02；天空变暗/回蓝 → 确认是下限。
3. 换太阳高度：`sun_set {"elevation": 45}`（再 70）仍白 → 不是低太阳米氏。
4. `bloom_set {"gain": 1.0}`：白退多少 → 分离 gain 的贡献。
5. `sky_set {"intensity": 1.0}`：只是天空太亮，还是曝光不压？→ 分离天空标定。

| 现象 | 更像 | 对应动作 |
|---|---|---|
| `scale=0.25`、纯天空整体白 | 曝光下限 | 调 `min_scale` |
| `scale` 1–4、刚从室内转来白 1–2 秒 | 适应未收敛 | 等收敛，不改参数 |
| `scale` 0.9–1.1 仍白 | `gain`/曲线或天空标定 | 调 `gain` 档位或 `sky_intensity`，别动下限 |
| 只有太阳附近白、周围正常 | 太阳盘/米氏，物理 | 允许；必要时测光排除太阳盘 |
| 室内正常、室外白、室外读数 `avg_log2` 明显偏暗 | 测光被太阳或暗部带偏 | 测光排除 |

## 4. 修法候选与取舍

| 层 | 动作 | 代价/风险 | 验收 |
|---|---|---|---|
| 曝光下限 | `min_scale` 0.25 → 0.02–0.05（最大压暗 4× → 20–50×） | 只影响强光场景，不放大暗部噪声 | ⑬ |
| 室内外分档 | `key`/`gain` 两套默认（室内保留 0.01/8；室外试 `key 0.02–0.03`、`gain 1–2`） | 需要预设状态与默认选择；切换要可预期 | ⑭ |
| 测光排除 | 太阳盘/极亮 tile 用 per-tile 上限或百分位从 `avg_log2` 剔除 | 改测光统计口径，要写清与面板读数的差 | ⑬ |
| 曲线肩 | 软肩/高光去饱和 | 换曲线数学，属 8.6 边界，须单列裁决 | 先不做 |
| AWB | 默认不做；确认是非物理色偏时按物理白点单列 | 灰世界会杀蓝天 | 另立 |

顺序：先做曝光下限 A/B；若下限调到位后室内 `scale` 掉出 0.9–1.1，说明要和 `key` 一起标定，再做室内外分档；测光排除是太阳入画时的补充，不替代下限。

## 5. 室内外验收矩阵（草案，实测后收紧）

| 场景/机位 | 必读 | 通过线（草案） |
|---|---|---|
| 室内大厅（9.9 立案机位） | `scale`、C 域 p50/钳位、读图 | `scale` 0.9–1.1；C 域 p50 与基线差 ≤2%；读图不灰平 |
| 纯天空，太阳 45°/70° | 同上 + 天顶色相 | C 域 p99 钳位 ≤5%；天顶中位 B > R；太阳盘允许白 |
| 日照地面 | C 域 p50/p99、材质色相 | 地面 p99 钳位 ≤10%；材质色相可辨，不糊成一片 |
| 日落 5°/15° | 地平线 R/B、太阳盘 | 地平线 R/B ≥1.3；不压成灰白；太阳盘允许白 |
| 室内→室外切换 | 8 Hz 读数序列 | 2 s 内收敛；无 >1 帧尖峰 |

## 6. 与 9.9.9 的接线

- 9.9.9 用 §9.9.1–9.9.6 的读数与控件；工具未完工时先用 `exposure_get` + `frame_dump` 临时取证，不改变交付顺序。
- 允许改：`min_scale`/`key`/`gain` 的默认值、室内外预设、测光排除规则。
- 不允许：换曲线数学、加灰世界 AWB、LUT/色轮/对比度/饱和度算子（8.6 边界）。
- 判定线：9.9 计划文末⑬⑭⑮；不达标不合并。9.9.9 改默认参数后，9.8 压测与 9.10 对照要复跑这三条读数。
