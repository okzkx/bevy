# 9.9.8 校色强度

**状态：✅ 已完成（2026-11-26）。** `tonemap_strength` 默认 1.0 时输出逐位不变；滑杆与 BRP 写同一个字段，拒绝 0…=1 之外或非有限值。

## 为什么要这个旋钮

面板能看图、能调曝光和曲线，但"这版调色到底上多少"是另一个问题：美术稿/对照截图往往希望一键在"原始画面"和"调色后"之间插值，而不是靠人反复改 gain。`tonemap_strength` 就是末端插值：`0` = 完全不校色（直接显示线性 LDR clamp 后的画面），`1` = 完整曲线，中间线性 mix。它只作用在最终颜色上，不影响 A/B 域与 bins 布局——统计量仍然是原始量。

## 落位与语义

- `BloomParams` 追加第 6 个 f32 `tonemap_strength`，`BloomParamsLayout` 补 `_pad: [f32; 2]`，UBO 仍 **32 B**（有 size const assert），打包偏移 **20**。选择放进 BloomParams 而不是新开 UBO，是因为它和 `curve`/`gain` 属于同一组"最终映射"参数，present 已经绑了这块缓冲。
- 着色器（`shaders/common/tonemap_shared.wgsl`）：

```wgsl
fn apply_tonemap_strength(linear: vec3f, mapped: vec3f, params: BloomParams) -> vec3f {
    let t = clamp(params.tonemap_strength, 0.0, 1.0);
    if (t >= 1.0) { return mapped; }
    return mix(clamp(linear, vec3f(0.0), vec3f(1.0)), mapped, t);
}
```

`t >= 1.0` 提前返回是刻意的：`mix(x, y, 1.0)` 在浮点上不保证逐位等于 `y`，而默认值必须是 1.0 且"默认不改画面"是判定线⑧的硬要求。提前返回让默认路径就是原来那行 `return mapped`。

`present_tonemap.wgsl` 的 `fs_main` 改成两个曲线分支都先算 `mapped`，再统一 `apply_tonemap_strength(color, mapped, bloom_params)`：Narkowicz 分支 `mapped = aces_narkowicz(color)`，ACES 分支 `mapped = REC2020_TO_SRGB * ACES(SRGB_TO_REC2020 * color, gain)`。这样强度对不同曲线语义一致。

## 入口

- 面板：颜色页曲线区 `egui::Slider::new(&mut bloom.tonemap_strength, 0.0..=1.0).text("校色强度")`，hover 说明"0 = 不校色，1 = 完整曲线，中间线性插值"。
- BRP：`ash_renderer/bloom_set` 增可选 `tonemap_strength`；`!(0.0..=1.0).contains(&v)` 或非有限 → `invalid_params("tonemap_strength 须为 0…=1 的有限值")`。面板与 BRP 都写 `BloomSettings.tonemap_strength`，没有第二份状态。

## 验证

- 三档读图（默认机位、自动曝光、Filament ACES）：强度 1.00 / 0.50 / 0.00 的 C 域 p50 分别为 0.268 / 0.221 / 0.150、p99 0.428 / 0.342 / 0.209，单调下降，图像可辨（`.temp/ui_strength_100.png`、`ui_strength_050.png`、`ui_strength_000.png`）。
- 判定线⑧：默认 `1.0` 时 `main` 与 `goal/9.9` 的 present 输出逐字节相同（抽取无损 A/B 同时覆盖了这条路径）。
- 判定线⑩：面板滑杆与 BRP 字段同源；越界/NaN/∞ 被拒。
- `BloomParamsLayout` 的 size assert、`pack_bloom_params` 偏移单测、`cargo test -p ash_renderer --lib` 163 passed、clippy `-D warnings` 0。
