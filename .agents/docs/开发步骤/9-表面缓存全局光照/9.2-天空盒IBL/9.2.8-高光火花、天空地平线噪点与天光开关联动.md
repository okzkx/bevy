# 9.2.8 高光火花、DFG 积分器、天空地平线噪点与天光开关联动

> 施工记录。9.2 收官后现场复检（2026-11-23，用户实时看画面提出）：本段修三处观感/语义问题，不改 9.2 的数据链；相关判定线重跑（见 §3）。前置：[9.2.7 判定线与计量](9.2.7-判定线与计量.md)、[天空盒IBL流程](天空盒IBL流程.md)。

## 1. 现场复检发现的问题

### 1.1 双面织物/叶片上的高光椒盐噪点（新缺陷，主因是 DFG 积分器用错形态）

- **现象**：Sponza 帘布、植物、石饰边在阴影里出现逐像素白点，只在 IBL 开时出现；IBL 关、`ibl_diffuse` 视图都干净。
- **定量**（同机位默认机位，5×5 中值差分的高频能量 / 超阈值白点占比）：
  | 区域 | IBL 关 | 只 diffuse | 只 specular | 全开 |
  |---|---|---|---|---|
  | 红帘 | `0.93 / 0.00%` | `1.28 / 0.00%` | `4.82 / 1.63%` | `4.25 / 1.61%` |
  | 绿帘 | `0.81 / 0.00%` | `1.55 / 0.00%` | `3.73 / 0.98%` | `2.78 / 0.79%` |
  | 石墙 | `2.09 / 0.00%` | — | `5.03 / 2.01%` | `4.58 / 1.38%` |

  噪声全部来自高光项，且与 diffuse/SH、环境 cubemap 都无关。
- **隔离实验**（临时改 `ibl_specular`，各一次重编译 + 同机位截图）：

  | 实验 | 红帘 `hf / sparkle` | 结论 |
  |---|---|---|
  | 正常 | `4.82 / 1.63%` | 基线 |
  | 强制最粗 mip（p=1） | `4.14 / 1.50%` | 与环境 mip 无关 |
  | 只出 `pre`（屏蔽 DFG） | `1.56 / 0.02%` | **环境采样干净**，噪声在 DFG 项 |
  | 只出 `pre · B`（去 F0） | `4.94 / 1.85%` | 与 F0/金属度无关，是 B |
  | DFG 的 NoV 固定 0.5 | `0.06 / 0.00%` | 噪声来自 NoV 变化 × B 的陡变 |

- **根因**：`brdf_lut.wgsl` 把 `V_SmithGGXCorrelated`（**可见性**形态 V，已含 `1/(4·NoL·NoV)`）当成几何项 G 再除一次 `NoH·NoV`，等于多除 `4·NoL·NoV`，掠射端按 `1/NoV³` 发散（9.2.4 记录的"Inf → Bloom 黑块"就是它）。9.2.4 的"钳到 1"只压住了 Inf，留下的是**掠射端一大段 A=B=1 的平台 + 陡崖**：修复前 `ibl_census(lut:true, row:127)` 的 B 在 NoV≈0.03 还是 1.0、0.25 时掉到 0.057（20×）；8bit 法线 + 法线贴图给出的 NoV 抖动（0.01 级）落在这段陡崖上，就被放大成整屏白点。
- **次要因素**（同批修掉，不是主因）：① IBL 项用未翻面的法线——G-buffer 管线 `cull_mode = NONE`、全工程无 `@builtin(front_facing)`，双面几何背面 `dot(n,V)<0` 时 DFG 落到掠射端；② 没有 specular AA——法线贴图的屏幕空间细节没有任何粗糙度补偿。

### 1.2 地平线以下整片椒盐噪点（9.1 遗留，地下机位）

- **现象**：相机拖到 y<0 后（实测 `set_camera` 读回 target.y=18.02、pitch=−3.8°、radius=456.3 → 相机 y≈−12.2 m），可见天空的地平线以下整片出现**两值跳变**的噪点；`sky_uniform` 打开后消失——噪点在 `sky_radiance` 的物理分支里。
- **根因**：`r0 = planet_r + max(camera_pos.y, 0.0)`。相机在地下时 `r0` 与行星半径重合，地面球求交退化：`d = ratio² − (1 − cos²)` 是两个近 1 数相减，`d` 的符号逐像素随机 → `hit_ground` 时真时假 → 地面项（暖、亮）与大气项（冷、暗）逐像素二选一。像素实测只有两级（如 `(193,189,179)` 与 `(125,145,152)`）。
- **影响面**：可见天空；IBL 捕获的下半球（`ibl_census` −Y 面 min/max = 2350/2926 的散布就是它）；以及由它们喂出的天光亮度。

### 1.3 天空开关不联动环境光（语义缺口）

- 9.2 原设计：`sky_enabled` 只管可见天空，`ibl_enabled` 管材质环境项，两者正交（流程导读 §5 写过"可以'有 IBL 无可见天空'"）。
- 用户定案（本段）：**天空是环境光的上游**——`sky_enabled = false` 时 ①不做捕获（不耗 GPU、不沿用旧 cubemap）②环境项回退步骤 8 的常量 `albedo × ambient_color`（不是黑）。等价 Unity 的 Ambient Mode = Skybox：关掉天空盒回到 flat ambient。

## 2. 修法

| # | 改动 | 落点 |
|---|---|---|
| A | **DFG 积分器**：`G = 4·NoL·NoV·V_SmithGGXCorrelated(...)`，`G_Vis = G·VoH/(NoH·NoV)`；钳 1 降级为数值护栏 | `shaders/scene/ibl/brdf_lut.wgsl` |
| B | IBL 项改用**视向侧法线**：`n_ibl = dot(n,V) < 0 ? −n : n`，漫反射与高光都用它（直接光不动，保住"IBL 关逐位一致"） | `gbuffer_composite.wgsl`、`transparent_forward.wgsl`、`common/ibl.wgsl` |
| C | 屏幕空间 **specular AA**：`p_ibl = sqrt(p² + |dpdx(n)|² + |dpdy(n)|²)`（钳 1），只用于 IBL 高光 | 同上 |
| D | `sky_enabled` 联动：帧 UBO 的 `ibl_enabled = ibl_settings.enabled && sky.enabled`；`prepare` 同条件，天空关不捕获 | `driver/host/frame/scene.rs`、`driver/host/frame.rs` |
| E | 天空海拔兜底 0 → **1 m**，球求交改 `d = c² − k`（`k = (r0² − S²)/r0²` 由高度差算），近切线不再两个近 1 数相减 | `shaders/common/sky.wgsl` |
| F | `ibl_census` 加 `row`：读回 DFG 单行 128 个 A/B（本段定位与验收的工具） | `src/remote/features/ibl.rs` |

- A 是主修：修完后 DFG 形状回到教科书口径——`row 0`（p≈0）A `0.019→1.000`、B `0.980→0`；`row 127`（p=1）A `0.847→0.313`、B `0.043→0`，掠射端不再有钳 1 平台。
- B 的取舍：只改 IBL 项的入射法线，不动 G-buffer 存法与直接光——双面几何的"背面受光"是既有的另一类问题，不卷进本段（保住 9.2.7 逐位基线）。
- C 的取舍：修正 A 之后火花已消失，AA 只作残余抗锯齿保留（平滑表面导数近 0，增量可忽略）。
- E 的稳定式与 1 m 兜底等价于原式（相机海拔 ≥1 m 时只有浮点尾数差异），只在退化区改变行为。

## 4. 已知局限（更新）

- 修正 DFG 后，**掠射端的天光高光整体变暗**（原先的钳 1 平台把它抬高了 2 倍以上）——这是正确的能量，不是回退；室内漏光、L2 截断、100 m 海拔量化、0.1 s 节流等 9.2.7 的已知局限不变。
- 天空海拔兜底 1 m：相机在 y<1 m 时，可见天空按"站在 1 m 高处"求值（地下机位看到的是 1 m 高度的天空）。这是兜底，不是物理。

## 5. 坑

1. **`ibl_census` 的 `row` 是这次定位的关键**：只看 LUT 的 min/max 完全看不出来（0..1 都合法），必须逐行看形状才发现"掠射端一大段 A=B=1"。
2. **隔离实验要一次只动一个变量**：先屏蔽 DFG 确认 env 干净（`pre` 单独 hf 1.56），再去 F0（噪声仍在，锁定 B），最后固定 NoV（噪声归零），才敢下"DFG 的 NoV 陡变"这个结论；靠单张图猜会把方向带偏（中途一度以为是金属度贴图）。
3. **`V_SmithGGXCorrelated` 不是 G**：本工程 `brdf.wgsl` 给它的是**可见性**形态（含 `1/(4·NoL·NoV)`），算 `G_Vis` 必须先乘回 `4·NoL·NoV`；Filament 的 `G_SmithGGXCorrelated` 才是几何项。同名不同义是这次缺陷的源头。
4. **PrintWindow 抓图的亮度/白点判据**：本段所有"火花"结论都用 **hf/sparkle 相对指标**（同一区域、同一机位、IBL 开/关对照）而不是绝对亮度——抓图通道的亮度漂移不影响结构差异。
