### 0.1 判定口径订正

#### 0.1.1 "静态游历零重传零泄漏"在本段的口径

路线图的"零重传"是账本口径，不是"GI patch 一条都不新增"：相机移动必然让新 cell 进入视野、旧 cell 出界，patch 的 alloc/freed 会持续发生。本段把判定线①拆成两层：

- **账本层（硬线）**：`residency_stats.requested_rows_last == 0`、`ejected_last == 0`（预热后每个采样点）；`perf_stats.memory.upload_bytes_total` 全程不变；`scale.ledger_rows` 不变；`draw_stats.command_count` 不变。即"移相机不触发资产/实例重传，也不改绘制命令形态"。
- **池层（稳定性线）**：`gi_stats.counters.failed == 0`、`pool.active <= pool.capacity`、`pool.watermark <= pool.capacity`、`memory.total_bytes` 不变；20 机位回到起始位姿后 `pool.active` 不超过起始值的 1.1 倍 + 64 条；`alloc - freed` 不出现随时间单调增长。允许 patch 播种/回收，不允许池只涨不还。

"泄漏"的反例（判定失败）：failed>0；watermark 顶到 capacity；回位姿后 active 明显高于起始且继续上涨；memory 增长；账本 requested/ejected 非零；upload_bytes_total 增长。

#### 0.1.2 "动态场景无永久残影"的操作定义

需要区分**暂态**（可接受）与**永久残影**（不可接受）。按实现，patch 的心跳淘汰是 240 帧（`ash_renderer/src/render/passes/gi/mod.rs:52`），陈旧 rank 0 还要先降 rank 1 再等一轮（`shaders/scene/gi/eviction.wgsl:33-60`），所以 60fps 下最多约 8 秒才彻底回收；低帧率下按帧数折算更久。本段测试统一：

1. 参考帧：静态测试场 + 固定太阳 + 手动曝光，静置 ≥15 秒后 `frame_dump`；
2. 施加动态（移动/增删/流送/开关灯/扫日），再回到与参考完全相同的位姿与光照，静置 ≥15 秒；
3. 再 `frame_dump`，与参考帧在 **sRGB 显示域**逐像素比较（与 `tools/gi_scene_regression.py::display_srgb8` 同口径）。

通过阈值（首测先标定噪声底，再定稿）：

- 整屏平均绝对差 ≤ 1/255；
- 逐像素差 p99 ≤ 3/255；
- "变化像素"（|diff| > 2/255）面积 ≤ 全屏 0.5%，且不集中在原动态物体覆盖区；
- 读数侧：`scgi_stats.non_finite == 0`、`negative == 0`，`coverage`/`alpha.mean` 与参考差 ≤ 0.02；
- 读图无可见局部亮斑/暗块（按《画面功能视觉验证》结论分"通过/异常/无法判定"）。

若 15 秒未回线、30 秒回线 → 记为"暂态过长"（报告写明时长与归因，判定线②按"无永久残影"仍可过，但附条件）；30 秒仍不回线 → 判失败，按 9.8.3/9.8.4 的修复路径处理。阈值最终以首轮噪声底标定结果写进 9.8.1 记录，后续不得放宽。

#### 0.1.3 TOD 与太阳扫描

全仓没有 TOD/太阳循环系统，唯一相关的是 IBL 捕获节流注释（`ash_renderer/src/render/passes/ibl/environment.rs:76`："TOD 连续变化时 IBL 允许滞后这个窗口"，最小间隔 0.1s）。因此本段的"昼夜/TOD 天空"用**脚本逐帧 `sun_set` 扫描**替代：方位角 0→330° 每 30°、仰角 45°，以及 90° 方位下仰角 10/45/80°；每步保持 0.4 秒。这不等于新增 TOD 系统，也不改天空模型；目的只是验证"太阳连续变化时缓存与 IBL 捕获能跟上、回到原太阳后能复原"。

#### 0.1.4 读数可信边界

- `scgi_stats.l0_*` 已在 9.7.7 证实不可靠（同一锚不同轮次读到 1.17、3.14、-5.9、509，原因未查明），**不得作为任何判定线的通过依据**；只用 `coverage`、`alpha.mean/max`、`non_finite`、`negative`。
- `scgi_low_probe` 只作调试，不进判定。
- 画面判定只用 `frame_dump`（渲染器自回读），`capture_window.py`/PrintWindow 只作辅助，不用于判据（9.7.7：窗口失焦会返回同一帧）。
- `gi_stats`/`draw_stats` 陈旧一帧，采样时保持静置 ≥2 帧再读；`perf_stats` 的 percentile 来自窗口，报数时带样本数与窗口长度。

#### 0.1.5 压测口径

按路线图 `:288-303`：

- 条件单先写：提交版本、GPU/驱动、Release、分辨率、材质/光照、抗锯齿、present/节流、种子、相机轨迹、预算 16.7ms；
- 指标成组：CPU 分段（`perf_stats.sections_mean` 与 p50/p95/p99）、GPU 工作区间、上传字节、提交次数、显存、待回收资源数；
- 报 p50/p95/p99 与样本数，报加载/增删尖峰；60Hz 节流下区分"真实工作"与"主动等待"（`wait_slot`/`present` 单列）；
- 增长斜率：1 万/5 万/10 万实例 × 零变化/少量变化/全动态；静态仅移相机不得全量重传；
- 预算 16.7ms 先固定，达不到就如实写瓶颈，不拿"肉眼流畅"替代读数；
- 热路径不得逐资源 `device_wait_idle`；A/B 控制变量，Unity 251/Atrio 只作质量参照，不逐像素对比。

压测环境额外约束：**Release 构建 + 验证层常开**（`ash_renderer/src/render/core/device/context.rs:24`）——报告注明"含验证层开销"，同一构建内比较；压测独占 GPU，先停掉开发实例；每个矩阵格独立进程/独立端口，避免跨格状态污染。

### 0.2 边界

**做**：

- 建验收基座、条件单与三脚本；固定条件；
- 静态游历、动态几何/流送、动态光照/TOD 扫描的收敛与残影读数+读图；
- Volume 边界、fallback、上采样边界环留档；

- 本段内发现且阻塞判定的缺陷小修（含产品默认值拍板）。

**不做**：

- 不新增 GI 机制/算法：视图 16/17、`scgi_ms`、`GI_COUNTER_WORDS` 扩容、AO、SSR/局部反射、透明 GI、烘焙/lightmap/APV、TAA、学习式 denoiser 均不在本段；
- 不替 9.10 做 Unity 源码对照审计，不修 9.10 的 P0；若读数依赖未修项，如实标"待 9.10 后复测"；
- 不宣布步骤 9 收官；不改 9.9/9.10 范围；
- 不引入新资产管线；alpha 裁切用 Sponza 自带 MASK 材质就地对照，不新造资产；
- 不追求"更好看"，不把 GI 参数调到 9.7 调档结论之外；质量档只在既有参数面内组合。

**缺陷处理**：

- 阻塞判定线且改动 ≤ 一个文件/一个机制（如默认值、淘汰阈值、一个分支）→ 本段修、复测、补提交；

## 2. 任务拆解

### 9.8.1 验收基座、条件单与基线冻结

**交付**：`tools/gi_acceptance.py` 基座 + 条件单 + Sponza 基线读数。

1. 宿主自启/接管：`ASH_HOST_EXE` 指定 exe（Release 优先），子进程日志落 `.temp/gi98/host/`，等待 BRP 就绪；PID、命令行、端口写进条件单。
2. 条件单：git HEAD/分支、exe 路径+时间戳+SHA256、GPU/驱动（`nvidia-smi` 或 Vulkan 读数）、OS、分辨率、场景、曝光、sun、IBL/GI 设置全量、预算 16.7ms、验证层开关。
3. `sample_all()`：一次取 `gi_stats/scgi_stats/ibl_stats/perf_stats/residency_stats/draw_stats/light_stats`，存 JSON。
4. `snapshot()`：`frame_dump` → PPM → sRGB PNG → 均值/p10/p50/p99/black_fraction；同时记录 `orbit_before/after` 校验位姿。
5. 新鲜度自检：转太阳前后差分必须 >0.5/255（9.7.7 的 23.8 同口径）。
6. 基线：Sponza 默认机位 + `gi_scene_regression.CAMERAS` 四机位，静置后采一组读数，存 `.temp/gi98/baseline.json`。

**落点**：`tools/gi_acceptance.py`、`9.8.1-验收基座与条件单.md`。**判定线支撑**：③的前置、①②的采样口径。

### 9.8.2 静态游历与账面稳定（判定线①）

**交付**：20 机位静态游历的读数与结论。

1. 固定 Sponza、`sun_hi`、手动曝光、0.1.6 基线设置；预热 ≥15 秒。
2. 20 机位：绕大厅 yaw 0～330°（步 30°，半径 8，target `[0,3,0]`，pitch 10°）12 个 + 4 个室内近景/俯视 + 4 个沿走廊高低机位；只动相机，不动太阳/灯/几何。
3. 每个机位静置 2 秒后采 `sample_all()`；在起始/中段/末段 6 个机位 `snapshot()`。
4. 逐点核对账本层与池层（口径见 0.1.1）；计算 `alloc-freed`、`watermark`、`active` 的走势。
5. 回起始位姿静置 5 秒，比较首末 `active/watermark/memory/ledger_rows`。
6. 读图：6 张 PNG 逐张看有无黑屏、条纹、NaN 样色块。

**失败路径**：若账本层破线 → 查 `upload_bytes_total` 增量来源（资产失效/驻留请求）；若池层破线 → 查 `scrolling/eviction` 的回收计数与 `cell_patch` 对账（`gi_census`）；小修后复跑整条 tour。

**落点**：`9.8.2-静态游历与账面稳定.md`。**判定线**：①。

### 9.8.3 动态几何与流送（判定线②前半）

**交付**：移动/增删/流送三类动态的收敛曲线与残影差分。

1. 在 x=80 测试场用 `spawn_shape` 搭地面、背墙、白箱、红柱、绿球、自发光面板（沿用 9.7.7 场地）。
2. 参考帧：固定位姿与太阳，静置 ≥15 秒，`frame_dump` + 全读数。
3. 动态 A（移动遮挡体）：红柱沿 x 轴平移 4m（8 步，每步 0.5m），再移回；每步 0.5 秒；随后回参考位姿。
4. 动态 B（增删）：在测试场 `spawn_shape` 20 个球（同参共享资产），5 秒后逐个 `despawn_entity` 清空；回参考位姿。
5. 动态 C（流送）：`generate_chunks{chunk_grid:2, instances_per_chunk:16, spacing:2, seed:7}` 生成，再用 `chunk_despawn{id}` 逐块删；记录 `chunk_census` 前后。
6. 动态 D（变更源）：`workload{enabled:true, rows:50}` 跑 3 秒再关；确认它只影响前 50 个实体、不改变相机。
7. 每类动态后：按 0.5 秒采样 `frame_dump` 均值/`gi_stats`/`scgi_stats` 连续 20 秒，画"时间→整屏均值/coverage/active"曲线；回参考位姿静置 15 秒后做差分。
8. 判定按 0.1.2；若 15 秒未回线、30 秒回线 → 记"暂态过长"并给出 `EVICT_AGE` 折算与实测帧率；30 秒仍不回线 → 判失败，读 `patch_alloc.wgsl` 的"已有 cell 保留辐照度历史"与 `eviction.wgsl` 心跳路径，提出最小修（如几何变化时重置 update_count/辐照度，或缩短淘汰窗口）先报用户。

**落点**：`9.8.3-动态几何与流送收敛.md` + `.temp/gi98/dynamic/`。**判定线**：②。

### 9.8.4 动态光照与 TOD 扫描（判定线②后半）

**交付**：点灯开关、太阳扫描、IBL 捕获节流的收敛与残影结论。

1. 测试场 `light_spawn{pos:[80,2,0], radius:10, color:[1,0.9,0.8], intensity:10}`；用 `light_update` 做 0→5→10→20→0（每档 2 秒）再 `light_remove`；每档静置 5 秒采读数与 `frame_dump`。
2. 太阳扫描：保持测试场/机位，方位 0→330°（步 30°，仰角 45°，每步 0.4 秒）→ 90° 方位下仰角 10/45/80° → 回 `az 45°/el 55°`。
3. 记录 `ibl_stats.capture.count` 随帧增长、`last_capture_gpu_ms/window_max`、`perf_stats.gpu_ibl_capture_ms`；核对捕获间隔 ≥0.1 秒（`environment.rs:76`），确认不是每帧重烘。
4. 回参考太阳与位姿静置 15 秒，差分（同 0.1.2）；若失败，按 9.8.3 同一路径定位是 patch 历史还是 IBL 捕获。
5. 额外 sanity（不作判定）：`exposure_set{mode:auto}` 跑 10 秒看有无振荡，再切回 `manual`；记录"自动曝光是否掩盖了 GI 收敛"。

**落点**：`9.8.4-动态光照与TOD扫描.md`。**判定线**：②。

### 9.8.5 Volume 边界与兜底（接 9.7 顺延②/③）

**交付**：size 32/128/512 的边界、fallback、上采样边界环读图。

1. GI 关态改规格（`gi.rs:191-193`）：`size=32` 与 `size=512`（`cascades` 按需 4/6，`capacity` 不够时同步提），改完再开，静置 10 秒。
2. 边界：size 32 下把相机放在原点看 x≈20m 的墙（外 cascade 之外），用 `scgi_stats{roi}` 量该区域 `coverage≈0`、`alpha≈0`；同一机位 SCGI on/off 的 `frame_dump` 应几乎相同（回 IBL 基线）。
3. 滚动：size 32 下沿 -Z 移动 40m 再回原位（触发 `scrolling` 回收），记录 `counters.freed`、`pool.active`、回位姿差分；读图看边界环/带状台阶（9.7.7 §七③的顺延项）。
4. fallback 对照：`ibl_set{diffuse_mode:"sh_l2"}` vs `"probe16"`，在 Volume 外同一机位 A/B，记录均值差与读图；结论只作"兜底走哪条基线"的证据，不改默认。
5. 上采样：同一机位 `upsample_bilinear=true/false` A/B，边界环是否随上采样变化；有环则记录位置/宽度，不强行调参。
6. size 128（默认）与 512（大世界档）重复第 2 步的 coverage/边界读图，确认规格越大边界越远、Sponza 全场被覆盖。

**落点**：`9.8.5-Volume边界与兜底.md` + `.temp/gi98/boundary/`。**判定线**：②（边界回位姿无残留）、④（边界环留档）。

### 9.8.7 局限自检与 A/B（判定线④）

**交付**：`局限自检：SCGI已知局限对照.md`，九项逐条 + 五组 A/B。

九项与做法（每项写"预期/实测/证据/裁决"）：

1. **diffuse-only**：金属球/粗糙球 A/B，高光只来自 IBL，无场景反射；预期通过。
2. **透明不参与 SCGI**：Sponza 玻璃/帷幕前放色墙，SCGI on/off 的透明像素不变（代码路径 `transparent_forward.wgsl` 未接 SCGI）；读图 + 像素 ROI。
3. **无 SSR/局部反射**：镜面球只映 cubemap，不映场景；预期通过，记录为已知局限。
4. **无天空遮挡（室内漏光）**：封闭盒/厚墙室内，IBL 天光仍从墙外漏入；与 SCGI on/off 对照，记录漏光量级。
5. **alpha 裁切**：用 Sponza 自带 3 个 `alphaMode=MASK` 材质（`Sponza.gltf:6938,6993,7319`）就地读图；预期"GI 按不透明处理，镂空后仍挡光"；裁决"首版按不透明"是否维持。
6. **CSM 覆盖不足**：室外远景超出 CSM 级联，直射阴影缺失、GI 仍按几何遮挡；`shadow_set{enabled:false}` A/B，记录差异。
7. **BVH LOD 精度**：`spawn_lod` 阶梯球放 30m 外，最粗 LOD 进 BLAS，GI 遮挡与最细档对照；预期低频差异可接受。
8. **薄几何漏光**：薄墙（cuboid scale 0.02）两侧，点光/太阳在另一侧；记录是否漏光（受 0.5m 体素限制）。
9. **单相机一份缓存**：当前只有一台 `CameraOrbit` 相机（`set_camera` 歧义会报错）；记录为结构边界，不做运行时测试。

五组 A/B（每组 `frame_dump` + 均值/分位差 + 读图）：IBL 开/关；SH-L2 vs probe16；SCGI 开/关；质量低/高；空间滤波开/关。

四项裁决落点：AO（提案不乘，记录室内漏光）；alpha（提案首版不透明）；自发光上限 32768（读 `emissive_triangles`，超限则记录并另立扩容）；CSM 覆盖差（接受并记录漏光案例）。

**落点**：报告 + `9.8.7-局限自检与AB.md` + `.temp/gi98/limits/`。**判定线**：④。

## 4. 显存与性能口径

- 当前 65536 池、`res=32`、`cascades=4`、`size=128` 的实测账：cell 16,777,216 B + patch 22,282,240 B + misc 4,653,840 B = 43,713,296 B（立案时 `gi_stats.memory`）。
- 大世界档 `size=512`、`cascades=6` 的 cell 表按 README 参数基线约 12/24 MiB；patch 池可提 2^18 ≈ 48 MiB；6GB 显存账内，压测报告必须单列 peak。
- `upload_bytes_total` 是累计值，判"零重传"用前后差分，不用绝对值。
- `draw_calls_recorded`/`command_count` 是录制层读数，陈旧一帧；报数带"上一帧"说明。
- 报 p50/p95/p99 必须带样本数；`perf_samples` 上限 2048，超过窗口的压测按多窗口分段。
- 验证层常开，报告注明"含验证层"；同一张表内不混用 debug/release 或不同 exe。
