# 9.7.9 自动曝光（显示段）

> **状态：已实现并实测（2026-11-26）。** 这是一个**纯显示段**模块：只读 HDR 颜色目标、只输出一个全帧曝光倍数，由 present tonemap 乘上。它不参与 GI/IBL 的任何物理量——辐照度、`EXPOSURE = 0.00016`、Bloom 的 `gain` 都没有为它改动。

## 为什么要有这一集

9.7 的注入是 **replace 语义**：不透明表面把 IBL 的漫反射项整项换成"经过遮挡的缓存辐照度"。这在物理上是对的——室内只看到 5%–10% 的天穹，缓存 E 自然比未遮挡的 IBL 基线低 2–3 倍。实测也确认了这不是接线错误：

- 屏幕链逐段核对：`最终 SCGI / b15` 的中位数 1.025（高太阳）与 0.987（低太阳），Gather、去噪、上采样都没有丢能量。
- 天空锚点：孤立平面真值 E = πL 误差 0.7%。
- 参考实现对照：Unity URP 的 `SAMPLE_GI` 对不透明表面同样是整项替换 ambient probe，我们的实现反而更宽容（有覆盖率回退，URP 直接写黑）。

问题在显示段：固定曝光 `EXPOSURE = 0.00016` 加 ACES `gain = 8` 是按露天日照标定的。日照地面（20000 lx、反照率 0.16）线性值 0.163，经 ACES 得 222 码；室内 E ≈ 40 时线性值只有 0.0003，8-bit 线性量化直接落到 **0 码**——整帧 42% 的像素落在这个区间。用户看到的"全局光近乎没有"，就是这个跨度。

用户裁决（2026-11-26）：加自动曝光，**但必须独立成模块，写在 tonemapping 旁边，不要混进 SCGI 代码**。本集按此边界实现。

## 数据流与数学

```
HDR (R16G16B16A16_SFLOAT, SHADER_READ_ONLY)
  └─ cs_measure  64×36 = 2304 tile，每 tile 取 4×4 格心 textureLoad
       measures[i] = mean(log2(max(luma, 1e-6)))         luma = Rec.709 点积
  └─ cs_adapt    单线程累加 2304 个 tile
       avg_log = mean(measures)
       adapted = w>0.5 ? mix(prev, avg_log, 1 - exp(-rate·dt)) : avg_log
       scale   = clamp(key / 2^adapted, min_scale, max_scale)
       state[0] = vec4(adapted, scale, avg_log, 1)
  └─ tonemap     color = (hdr + bloom) * scale
```

- `rate` 分两档：变亮 `0.7`、变暗 `3.0`——变暗快是为了进出暗室时不拖影，变亮慢是为了避免走出洞口瞬间闪白。
- `dt` 是墙钟时间，写入前钳在 `[1/240, 0.1]`，防止断点续跑或卡顿时一步跳到位。
- `scale ≤ 0` 时 tonemap 兜底成 1.0（`select(1.0, exposure_state[0].y, ... )`），这样曝光段没跑也不会黑屏。
- NaN 与负亮度在测光端就落到 `1e-6`，不污染整帧。

参数 UBO 48 字节：`mode, tiles_x, tiles_y, pad / key / min_scale / max_scale / rate_brighten / rate_darken / dt`。逐偏移都有单测 `params_layout_matches_shader_offsets` 对照 WGSL 结构。

## key 的标定（这一集最容易踩的坑）

`present_tonemap.wgsl` 里的 `ACES(rec2020, bloom_params.gain)` 中，`gain` 是**曲线曝光参数**（Filament 的 `1/0.6 ≈ 1.667` 观感补偿），不是纯美学增益。曝光倍数会与它相乘。

第一版按 HDRP 习惯取 `key = 0.18`，实测 `scale` 顶到上限 6.0，与 `gain = 8` 叠成 48 倍：线性均值 89.5、日照地面整片死白、帷幕褪成粉彩。

改成用已验收基线反推：manual 档同场景实测 `avg_log2 = -6.65`，即 `2^-6.65 ≈ 0.00996`。取 **key = 0.01**，该场景倍数≈1.003——画面与没有这个模块时逐像素一致；只有更暗的场景才提亮。默认太阳实测 `avg_log2 ≈ -7.927`，倍数 2.372。

```
key 0.01 / min 0.25 / max 4.0 / rate_brighten 0.7 / rate_darken 3.0 / mode Auto
```

合同测试 `default_key_matches_accepted_baseline_exposure()` 锁住两条：已验收基线场景的倍数必须在 1±0.06，默认太阳必须在 [2, 3]。以后谁改 key 或改 `gain`，这条会先响。

## 每槽两帧更新一次

`params`/`measures`/`state` 每帧槽一份（`MAX_FRAMES_IN_FLIGHT`），同一槽要两帧才更新一次，因此 `rate_*` 是"每次更新"的速率，实际适应速度约为 `rate/2` 每帧。这是刻意的：单槽会让 CPU 写 UBO 与 GPU 读状态打架。模块头注释写明了这一点。

配套的一处同步修正：[barrier.rs](<F:/okzkx/bevy/ash_renderer/src/render/core/record/barrier.rs>) 的 `color_to_sampled` 原来 `dst_stage` 只有 `FRAGMENT_SHADER`。曝光 compute 在 HDR 转 `SHADER_READ_ONLY` 之后读它，dst 不含 COMPUTE 是真实的 hazard，已加宽为 `FRAGMENT_SHADER | COMPUTE_SHADER`。

## 调试显示模式的中性状态

调试视图（albedo / metallic / roughness 等）不跑曝光，但 tonemap 仍然会读 set3。如果沿用该帧槽上一次 Lambert 的倍数，0–1 的可视化值就被乘了一遍。

第一版修法是每调试帧写 `[0, 1, 0, 1]` 进该槽——显示对了，但**清掉了适应历史**：切回 Lambert 后倍数从 1 重新爬（2.445 → 1.366）。

最终方案是不碰槽内状态：`ExposureTargets` 额外建一个 `neutral` 缓冲和 `neutral_set`（描述符池 `max_sets(2*slots+1)`，状态集分配 `slots+1` 后 `pop()` 出中性集）。调试帧绑中性集，Lambert 走原状态集。

A/B 证据（`.temp/neutral_ab.py`）：

- roughness 视图在 Lambert 倍数 **2.4506 与 4.0** 下，`frame_dump` 哈希**逐字节相同**（`d13300451cb85d2b629a9f5cc7fd473b`）→ 调试视图不再被曝光缩放。
- 切回 Lambert 后倍数 `2.4506 → 2.4517`，连续 → 适应历史没被打断。

## 已知边界

- **只用全帧几何平均 log 亮度**，没有直方图、百分位、中心权重或 AE mask。天空占比大的构图会把室内压暗——矩阵里 `gallery-high` 组的 IBL 侧就是这样被压到 85 的。要更接近相机测光需要直方图或加权测光，属后续增强。
- **没有曝光补偿（+EV）**，也没有亮度/对比度曲线联动。
- **没有频闪抑制**（50/60 Hz 光源的时域滤波）。本渲染器目前没有随时间变化的光源，暂不需要。
- **暗面细颗粒噪声不是曝光问题**：那是 1/4 分辨率 SCGI 的采样噪声，被 2.4× 放大后变得可见。要压下去需要更多样本或更好的空间滤波，属 GI 侧遗留项。
- 未专门验证：窗口 resize 瞬态下的适应速度、HDR 超白输出、多显示器。
- 一次**未定位的停滞**：某次实例在 `set_camera`/`sun_set` 之后帧不再前进（窗口截图 md5 恒定、`frame_dump` 两次相同、`gi_stats` 计数不动，日志无错误）。随后两次新实例按同一序列逐步操作均未复现，原因未查明，如实记录。

## 可执行命令

```powershell
cargo run -p ash_renderer -- --scene sponza/glTF/Sponza.gltf
```

BRP（端口 15702）：

```python
call("exposure_get")                                  # 读设置与当前 adapted/scale/avg
call("exposure_set", {"mode": "manual"})              # 手动档：倍数恒 1，用于 GI/IBL A/B
call("exposure_set", {"mode": "auto", "key": 0.012})  # 调 target 亮度
call("exposure_set", {"max_scale": 2.0})              # 收窄上限，防止暗场景过曝
```

A/B 对照务必先 `mode: manual`：否则 SCGI 开关两侧各自适应不同曝光，亮度对比失去意义。
