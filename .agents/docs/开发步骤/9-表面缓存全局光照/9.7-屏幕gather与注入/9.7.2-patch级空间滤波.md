# 9.7.2 patch 级空间滤波（切平面抖动 taps）

> 2026-11-24 施工。依据 [施工计划](施工计划：屏幕gather与最终注入.md) §9.7.2。本文件记录"实际做了什么"。

**一句话**：每活跃 patch 沿**着色法线**的切平面按 `spatial_radius × 该级联体素边长` 投 4 个抖动样本，
用 9.7.1 的只读查表取邻居 patch 本帧的辐照度，按 `1 − |jitter|/√2` 归一化混合后写**独立的**
`filtered_irradiance0`（GI 集 b14）——不原地改 estimation 的输出，因为同一 dispatch 里边写边读邻居
会让结果取决于工作组调度顺序。

## 做了什么

### 1. `surface_cache.rs`：新增两张滤波表与两个绑定

| 项 | 内容 |
|---|---|
| 描述符 | GI 集新增 `b14`（空间滤波输出 A）、`b15`（9.7.3 时域滤波输出 B），均 `StorageBuffer` + `GI_STAGES` |
| 缓冲 | `filtered_irradiance0/1`：各 `capacity × 64B`（65536 → 4 MiB ×2），初值全 0 |
| 显存账 | 进 `SurfaceCacheMemory::misc_bytes`（随 `gi_stats` 的 `mem` 一起报） |
| 访问器 | `filtered_irradiance0()` / `filtered_irradiance1()`（只读，宿主不写） |

### 2. `shaders/scene/gi/spatial_filter.wgsl`（新）

- 线程 = 池槽位；空槽（`patch_cell == INVALID`）直接返回，活跃判据与 estimation 完全一致。
- 读**本帧** estimation 写的那份（奇偶 `gi.frame.x & 1`），写 `b14`。
- 门槛：自身与邻居都要求 rank 0 且 `update_count ≥ 1`——rank 1 与刚分配的 patch 身上只有 IBL 种子。
- 采样：`gi_r2_init(low_bias_hash_32(slot), frame·64)` + `gi_r2_sample2`，jitter 在 `[-1,1]²`，
  经 `gi_tangent_basis(normal)` 投到切平面（`local z = 0`），半径按**该 patch 所在级联**的体素边长缩放。
- 查表用 9.7.1 的 `lookup_cell_key`（同一个方向桶、同一条定位链）；查不到 / 邻居是自己 / 邻居不合格
  一律 `continue`，不强行混合。
- push 24B：`enabled / taps / frame_index / capacity / radius_cells / reserved`。

### 3. `src/render/passes/gi/filtering.rs`（新）

`GiSpatialFilterDraw`（两集：帧 UBO / GI）+ `pack_spatial_filter_push` + `spatial_filter_groups`
（= `ceil(capacity/64)`）+ 三条单测（push 布局、关态标志位、组数取整）。

### 4. 管线与录制

- `SPATIAL_FILTER_PIPELINE` 进 `layout_registry::ALL_PIPELINES`（**不受光线求交门控**，任何设备都建）。
- `GiPipelines.spatial_filter()` 恒有；`GiFrameDraw.spatial_filter` 在 estimation 录了才录。

### 5. 参数面

`GiSettings` 新增 `spatial_filter: bool`（默认 `false`）、`spatial_radius: f32`（默认 `1.5`）；
`gi_set` 新参数 + 越界校验（`0..=8`）；egui 面板复选框 + 滑条，与 BRP 同源。抖动样本数暂为
宿主常量 `SPATIAL_FILTER_TAPS = 4`（Unity 默认值），9.7.7 若要 A/B 再抬成参数。

## 钉明（相对计划的裁决）

1. **开关关时仍录 dispatch，push 里 `enabled = 0` 做直拷**。计划的措辞是"关 = 直拷 estimation 结果
   （A 与源逐位一致）"，而不是"关 = 不录"。这样 `filtered` 表在任何时刻都是"本帧可消费的完整一份"，
   9.7.3/9.7.4 不必再判断该读哪张表——少一个状态位就少一处漏判。代价是估计开着时多一条
   纯拷贝的 compute（每槽一次读写，无分支开销）。
2. **累加器以自身值 × 权重 1 起头**。计划只写了邻居权重公式，没写"是否含自身"。取"含自身、
   权重 1"有三个好处：查不到邻居时输出与输入**逐位相同**（无需额外分支，也不会出现除零）；
   不会因为邻居全是暗面而整块能量漂移；A/B 时"关"与"开但无邻居"两条路径给出同一结果，读数干净。
3. **邻居也要求 rank 0 且已估计过**。计划只对"被滤波的 patch"提了门槛；邻居侧同样筛，否则会把
   rank 1 的 IBL 种子抹进正常 patch——那正是计划要避免的"把种子铺开"。
4. **半径按 patch 自己所在级联的体素边长缩放**，不是按最细级。粗级联的采样半径因此自然放大，
   与"粗级联本来就该更平滑"一致。
5. **本段（9.7.2～9.7.5）只要 estimation 开着就录；整条屏幕链的关态豁免留给 9.7.6**。计划把
   "关态零新增命令"列在判定线第 8 条，但那时 `scgi` 开关还不存在——9.7.6 接上 `scgi` 后，屏幕链
   （含本滤波）改由 `scgi` 把关，"`scgi = 0` → 零新增命令"才可成立。这一点已在代码注释里写清。

| 9.6 判定线回归 | ✅ 13/13、零 VUID | `python tools/gi_estimation_test.py`（退出码 0）：estimation 开关硬线与 ①/③/④ 整屏差分全过，说明新增的滤波 dispatch 没有扰动估计链 |

**本任务无法直接验证的一条**："关态 A 与源逐位一致"没有读回通道可测——`gi_dump` 读 LDR 视图、
`gi_census` 只做 cell↔patch 一致性，两者都读不到 `filtered` 表。这条判据的证据是：shader 在
`enabled == 0` 时走的是 `var out = source; filtered[slot] = out;` 的直拷路径（逐字段赋值，无算术），
以及现场零 VUID + 开关回切不断帧。真正的数值验证要等 9.7.4 把 `filtered` 接到屏幕查表、
9.7.7 给出命中/覆盖读数之后。
