# 9.7.6 注入：合成第 6 集与 `scgi` 独立开关

> 2026-11-24 施工。依据 [施工计划](施工计划：屏幕gather与最终注入.md) §9.7.6。本文件记录"实际做了什么"。

**一句话**：把 `scgi` 开关加进帧 UBO（336 → 352B 的新 `scgi` 槽），合成 pass 绑第 6 集读
`scgi_irradiance`，在 `MODE_SHADING` 路径里把 Volume 内不透明像素的 **IBL 漫反射项**按覆盖率 `a`
换成 SCGI 求值——高光不动、透明层不碰、`a = 0` 逐像素回 IBL 基线。这是整段唯一改变画面的地方，
也是 9.8 动态验收要读的那张图。

## 做了什么

### 1. 帧 UBO 336 → 352B

新增 `scgi: [u32; 4]`（x = 开关，y 预留质量档，zw 保留），四处同步：`FRAME_UBO_SIZE`、布局镜像
`FrameUniformTableLayout` + 偏移静态断言（`scgi` @336、`size_of` = 352）、`pack_frame_uniforms`、
`FrameUniformsData::default`、WGSL `FrameUniforms`。值由 `write_frame_ubo` 从 `GiSettings::scgi` 取。

### 2. 合成第 6 集

- 新集 `scgi_sample`（b0 = `scgi_irradiance`，`SampledImage`，**片元阶段**）；与 compute 侧的
  `scgi_targets`（5 个 storage image、compute 阶段）分开——片元既不能写存储图，也不该混绑。
- `GBUFFER_COMPOSITE_PIPELINE` 的 sets 追加第 6 集；`record.rs` 的合成 `FullscreenPass` 多绑一个
  `feature.scgi_set`（`RenderFeatures` 新字段，由 `gi.scgi.sample_set()` 供）。
- **集恒绑，开关只决定 shader 读不读**：这样 pipeline layout 恒定，"关 = 基线"不需要重建管线。
  图在 init 就按初始尺寸建好并迁到 GENERAL（不是在帧里），所以 GI 关掉的帧绑它也有合法布局。

### 3. 注入代码（`gbuffer_composite.wgsl`）

在 `MODE_SHADING` 路径内、`ibl.diffuse` 与 `let environment = ...` 之间：

```wgsl
var scgi_diffuse = ibl.diffuse;
if (frame.scgi.x != 0u && frame.ibl_enabled != 0u) {
    let irr = textureLoad(scgi_irradiance, vec2i(i32(in.clip.x), i32(in.clip.y)), 0);
    let replacement = pixel.diffuseColor * Fd_Lambert() * irr.rgb * frame.ibl_intensity;
    scgi_diffuse = mix(ibl.diffuse, replacement, clamp(irr.a, 0.0, 1.0));
}
let environment = select(ambient, scgi_diffuse + ibl.specular, frame.ibl_enabled != 0u);
```

- 调试档 9/10/11（IBL 漫反射/高光/桶）在插入点**之前**就 return 了，不会被污染。
- `mix` 两侧都已算好 → `a = 0` 逐像素精确回 IBL，不存在"IBL 侧写 0 再混"的整屏变暗。
- 层叠：`frame.ibl_enabled == 0` 时注入**不进**（计划 §6 的顺序 `sky → ibl → scgi`）。

### 4. 屏幕链改由 `scgi` 把关

`prepare_gi` 里 `screen_chain = estimation.is_some() && settings.scgi`；空间/时域滤波、查表、去噪、
上采样全部挂在它下面。于是 `scgi = 0` 时**一条新命令都不录**（判定线第 8 条的"关态零新增命令"）。

## 钉明（相对计划的裁决）

1. **不建"常驻 1×1 零纹理"**。计划 §9.7.6 想用零纹理做关态占位，实现改成"恒绑真图 + shader 开关"：
   布局本来就恒定，省掉一张常驻纹理和它的布局迁移；代价是关态也绑一张内容未定义（但从不被读）
   的图——为了让校验层满意，那张图在 init 就迁到了 GENERAL。
2. **迁移放在 `ensure()` 里一次性做**（一次性命令缓冲 + `queue_wait_idle`），不是每帧录屏障。
   理由：合成 pass 每帧都绑这张图，而 GI 关掉的帧不录 ④.5 段，那类帧同样要合法布局；resize 本来
   就让帧循环暂停重建，等空闲不进每帧路径。
3. **`ibl_intensity` 乘进 SCGI**（计划 §5 的待决项，选了"乘"，与 IBL 同域）。首次 A/B 的读数见下，
   **这一条很可疑**，留给 9.7.7 用常量天空锚定后再定。
4. **片元像素坐标用 `in.clip`**（`VsOut` 的 `@builtin(position)`）而不是另加一个片元参数：naga 报
   "Built-in Position 出现两次"。

### 一条必须先关掉的坑（记录在案）

第一轮核验"开 SCGI 画面不变"（差值 0.00）。原因不是注入没接上，而是 **IBL 默认是关的**
（`IblSettings::default().enabled = false`，9.2 的段内纪律），而按计划 §6，`ibl_enabled = 0` 时
SCGI 也不许生效——于是注入点根本不进。核验脚本补上 `sky_set{enabled:true}` + `ibl_set{enabled:true}`
后，注入立刻显现（21.83/255）。**这条要写进 9.8 的验收前置**：验收 SCGI 必须先开 IBL。

### 画面读数（诚实标注）

开关打开后画面**明显变暗**：整屏均值 33.38 → 11.55（/255），差值均值 21.83、最大 71。
两种可能：① 缓存辐照度本身就比 IBL 基线低（室内只见天光的场景，缓存只有少量弹射能量）；
② 单位/尺度有一处写错（例如 `ibl_intensity` 是否该乘、或 L0 与 IBL 的辐照度口径差一个 π）。
**本任务不猜**：判定线②给了判据（`sky_uniform` 常量天空下 `E = πL`，SCGI 应与 IBL 落在同一区间），
那条要等 9.7.7 的读数与视图做完才能量。当前只确认"注入链路通、开关能回基线、零 VUID"。
