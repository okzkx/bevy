# 9.7.5 3×3 去噪与全分辨率双边上采样

> 2026-11-24 施工。依据 [施工计划](施工计划：屏幕gather与最终注入.md) §9.7.5。本文件记录"实际做了什么"。

**一句话**：在 1/4 目标上做 0～4 遍 3×3 去噪（步长 `{1,2,2,3}`，权重 = 高斯 × 法线点积 8 次方 ×
平面距离衰减），再把结果按 4 邻居双边加权插值到全分辨率，用**全分辨率着色法线**对 L0+L1 求值成
`E(n)`，写 `scgi_irradiance`（RGBA16F，a = 覆盖率）——这是"缓存的值变成屏幕上每个像素的辐照度"的
最后一步，9.7.6 的注入就从这个目标取值。

## 做了什么

### 1. 全分辨率目标与新描述符集方向

- `ScgiTargets` 增加全分辨率 `scgi_irradiance`（RGBA16F，单缓冲），描述符集扩到 5 个绑定
  （b0/b1 = 主组 P0、b2/b3 = 副组 P1、b4 = 全分辨率辐照度）。
- **两个方向的描述符集**：`set()`（b0/b1 = P0、b2/b3 = P1）与 `set_reverse()`（交换）。
  去噪每遍换一次集，于是"读一组写另一组"落在集上而不在 shader 分支里，同 dispatch 永不边写边读。

### 2. `shaders/scene/gi/denoise.wgsl`（新）

一遍 3×3：权重 = 高斯（按 1/4 像素偏移） × `pow(dot(n_c, n_n), 8)` × `exp(-|Δd|/d / 0.05)`；
三个权重任一为 0 的邻居直接跳过（跨边不混）。深度/法线取全分辨率 G-buffer 的**块心像素**
（`low*4 + (2,2)`）。读写目标由描述符集决定。

### 3. `shaders/scene/gi/upsample.wgsl`（新）

全分辨率逐像素：把像素中心映射到 1/4 空间做双线性，四个邻居各自的权重 = 双线性 × 法线点积 8 次方
× 平面距离衰减 **+ 0.01 倍纯双线性兜底**（保证四邻居全被拒时不出黑块）；解码 L1 三轴比值乘回 L0
颜色，再 `scgi_evaluate(l0, l1x, l1y, l1z, n_full)` 写 `scgi_irradiance`，`a` = 四邻居覆盖率最大值。
`mode = 1` 走纯双线性（A/B 对照，判定线⑤用）。

### 4. 录制与参数

`DENOISE_PIPELINE` / `UPSAMPLE_PIPELINE`（set0 帧 UBO / set1 G-buffer / set2 目标）恒建、进
`ALL_PIPELINES`；`GiFrameDraw.denoise` 是 `Vec<GiDenoiseDraw>`（遍数决定条数，按 `k % 2` 选集），
`upsample` 跟查表同生灭。参数面：`denoise_passes`（0..=4，默认 1）、`upsample_bilinear`（默认 false）。

## 钉明（相对计划的裁决）

1. **去噪的 ping-pong 落在描述符集上**：计划只说"覆盖写 ③ 的缓冲"，但那在 3×3 邻域下是
   边写边读（结果取决于调度）。实现改成"每遍换方向集"，与 9.7.3 的"角色固定"不同——这里必须
   交换，因为去噪本身要读邻居。
2. **遍数与最终结果的所在组绑定**：`denoise_passes` 为奇数时最终结果在 P1（用 `set_reverse` 上采样），
   偶数时在 P0。这条映射写死在 `prepare_gi`，是"集方向"这套设计的直接后果，记录下来免得后人踩。
3. **去噪/上采样只吃 `set0 帧 UBO / set1 G-buffer / set2 目标` 三集**，不绑 GI 集：它们不再查缓存，
   少绑一集就少一次描述符写（shader 的 group 也因此从 0/2/3 重编为 0/1/2）。
4. **L1 颜色近似的代价在本段第一次真正影响画面**：`l1_decode_axis` 把比值乘回 L0 的颜色，所以
   间接光的色向性仍是"跟随 L0"。是否够用由判定线⑤的读图判，但**9.7.6 接上注入之前看不到画面**，
   故这条待决顺延到 9.7.6/9.7.7。
