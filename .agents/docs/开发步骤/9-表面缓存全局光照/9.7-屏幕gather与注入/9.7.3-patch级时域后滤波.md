# 9.7.3 patch 级时域后滤波

> 2026-11-24 施工。依据 [施工计划](施工计划：屏幕gather与最终注入.md) §9.7.3。本文件记录"实际做了什么"。

**一句话**：把 9.7.2 的空间滤波输出（`filtered_irradiance0`，b14）与**上一帧**的时域输出
（`filtered_irradiance1`，b15）按 `w = lerp(0.9, 0.95, temporal_smoothing)`、`B = lerp(A, B_prev, w)`
混合，结果仍写 b15——B 主要保留上一帧，只吸收 5%～10% 的本帧新值，与 Unity `TemporalFiltering`
同形。

## 做了什么

- `shaders/scene/gi/temporal_filter.wgsl`（新）：线程 = 池槽位；读 b14（本帧空间输出）与 b15（上一帧
  时域输出），写 b15。`update_count ≤ 1` 的 patch **直取 A**（说明它本帧才拿到第一个估计值，b15 里
  那个槽还是别人的历史）。`enabled = 0` 时 `B = A` 直拷。
- `filtering.rs` 追加 `GiTemporalFilterDraw` + `pack_temporal_filter_push` + push 布局单测。
- `TEMPORAL_FILTER_PIPELINE` 进 `ALL_PIPELINES`；`GiPipelines.temporal_filter()` 恒有。
- `GiFrameDraw.temporal_filter`：跟空间滤波同生灭（没有 A 就没有可混合的输入），排在它之后录。
- 参数面：`GiSettings.temporal_filter`（默认关）、`temporal_smoothing`（默认 0.5，范围 `0..=1`）；
  `gi_set` + egui 面板同源，越界拒绝。

## 钉明（相对计划的裁决）

1. **不做 A/B 双缓冲的角色交换**。计划 §9.7.3 的坑写的是"滤波 A/B 由自己的帧奇偶决定，别复用
   estimation 的索引"。实现取更简单的形状：**b14 恒为"本帧空间输出"、b15 恒为"时域输出并自读
   上一帧"**——两者角色固定，不参与任何奇偶。每个线程只读写自己那个槽（读同下标旧值再写同下标
   新值，同一 invocation 内无跨线程访问），因此不需要奇偶，也不会出现"读到上一帧的上一帧"。
   省掉一次角色交换，代价是 b14 与 b15 不能互换（若将来要做"跳过时域"的快照，再加奇偶）。
2. **门槛用 `update_count > 1` 而不是计划的 `== 0`**。`update_count` 在 estimation 里每次估计自增，
   patch 刚分配、种子还在时是 0，第一次估计完变成 1。若只在 `== 0` 时直取，第一次估计的结果会与
   **上一条占用该槽的 patch** 的历史混合（槽被回收后 b15 里仍是旧值）——所以门槛取"已有两帧以上
   历史"（`> 1`），把首帧就直取的范围从计划的一帧扩到两帧。
3. **平滑度是 `[0,1]` 的归一化参数**，映射到 `w = lerp(0.9, 0.95, s)`（而不是直接暴露 0.9～0.95 的
   权重），与 9.6 的 `short_hysteresis` 同一习惯：面板上拖的是"平滑程度"，不是物理权重。
4. **本段仍不接 `scgi` 开关**：与 9.7.2 同一条理由，整条屏幕链的关态豁免留到 9.7.6。
