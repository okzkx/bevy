# 9.7.3 patch 级时域后滤波

> 2026-11-24 施工。依据 [施工计划](施工计划：屏幕gather与最终注入.md) §9.7.3。本文件记录"实际做了什么"。

**一句话**：把 9.7.2 的空间滤波输出（`filtered_irradiance0`，b14）与**上一帧**的时域输出
（`filtered_irradiance1`，b15）按 `w = lerp(0.9, 0.95, temporal_smoothing)`、`B = lerp(A, B_prev, w)`
混合，结果仍写 b15——B 主要保留上一帧，只吸收 5%～10% 的本帧新值，与 Unity `TemporalFiltering`
同形。

## 做了什么

- `shaders/scene/gi/temporal_filter.wgsl`（新）：线程 = 池槽位；读 b14（本帧空间输出）与 b15（上一帧
  时域输出），写 b15。`update_count ≤ 1` 的 patch **直取 A**（说明它本帧才拿到第一个估计值，b15 里
  那个槽还是别人的历史）。`enabled = 0` 时 `B = A` 直拷。
- `filtering.rs` 追加 `GiTemporalFilterDraw` + `pack_temporal_filter_push` + push 布局单测。
- `TEMPORAL_FILTER_PIPELINE` 进 `ALL_PIPELINES`；`GiPipelines.temporal_filter()` 恒有。
- `GiFrameDraw.temporal_filter`：跟空间滤波同生灭（没有 A 就没有可混合的输入），排在它之后录。
- 参数面：`GiSettings.temporal_filter`（默认关）、`temporal_smoothing`（默认 0.5，范围 `0..=1`）；
  `gi_set` + egui 面板同源，越界拒绝。

## 钉明（相对计划的裁决）

1. **不做 A/B 双缓冲的角色交换**。计划 §9.7.3 的坑写的是"滤波 A/B 由自己的帧奇偶决定，别复用
   estimation 的索引"。实现取更简单的形状：**b14 恒为"本帧空间输出"、b15 恒为"时域输出并自读
   上一帧"**——两者角色固定，不参与任何奇偶。每个线程只读写自己那个槽（读同下标旧值再写同下标
   新值，同一 invocation 内无跨线程访问），因此不需要奇偶，也不会出现"读到上一帧的上一帧"。
   省掉一次角色交换，代价是 b14 与 b15 不能互换（若将来要做"跳过时域"的快照，再加奇偶）。
2. **门槛用 `update_count > 1` 而不是计划的 `== 0`**。`update_count` 在 estimation 里每次估计自增，
   patch 刚分配、种子还在时是 0，第一次估计完变成 1。若只在 `== 0` 时直取，第一次估计的结果会与
   **上一条占用该槽的 patch** 的历史混合（槽被回收后 b15 里仍是旧值）——所以门槛取"已有两帧以上
   历史"（`> 1`），把首帧就直取的范围从计划的一帧扩到两帧。
3. **平滑度是 `[0,1]` 的归一化参数**，映射到 `w = lerp(0.9, 0.95, s)`（而不是直接暴露 0.9～0.95 的
   权重），与 9.6 的 `short_hysteresis` 同一习惯：面板上拖的是"平滑程度"，不是物理权重。
4. **本段仍不接 `scgi` 开关**：与 9.7.2 同一条理由，整条屏幕链的关态豁免留到 9.7.6。

## 补漏：defrag 搬表时漏了 b14 / b15（2026-11-25）

屏幕链跑起来之后有两个现场症状，都在**这一段的输出（b15）**上：

1. **注入能量只有缓存的一半**：同一机位（radius 55、target `(0,4,4)`、yaw 35°/pitch 25°）读
   `scgi_stats`，滤波开 `E=[1434, 1846, 2278]`（max 2920），滤波旁路 `E=[3362, 3946, 4582]`
   （max 5136）——差 2.4 倍。空间滤波已排除嫌疑（`spatial_radius` 从 3.0 调到 0.01 读数不变）。
2. **最终画面逐帧闪**：用户报"Surface cache 视图在时间上一直闪（这是对的），但现在最终渲染也一直闪"。

### 根因

9.5 的 ring 整理（`shaders/scene/gi/defrag.wgsl`）搬 patch 时搬了 **5 张表**：
`patch_geometry` / `patch_irradiance0` / `patch_irradiance1` / `patch_statistics` / `patch_cell`
（外加 `cell_patch` 反向指针），但 9.7.3 的两张时域表 `filtered_irradiance0/1` 是**按槽位**存历史的，
它们没被搬。

整理是**每帧推进**的：池里 1006 条活跃 patch 时 `defrag_moved = 1003`/帧，13476 条时也每帧搬
1024 条（每帧两个 wave × 512）。只要 ring 里出现一个洞，后续条目就整体前移一位，于是**几乎每条
patch 每帧都换槽位**，而新槽位上留着的是别人（或已回收的旧 patch）的历史。指数平均
`B = lerp(A, B_prev, 0.925)` 因此每帧都混进陌生值：收敛点从"自己的值"变成"全池均值附近"，
并且逐帧抖动 —— 上面的两个症状是同一个根因。

**冻结实测（决定性证据）**：把 `estimation` 关掉让缓存完全不动，理论上 b15 必须收敛到 A。
修前 b15 稳定停在 A 的 **0.42 倍**且 15 秒不再变化；修后 3 秒内收敛到 A。

### 修法（只改 `defrag.wgsl`，不动数值口径）

- 增加两个绑定：`@group(0) @binding(14/15) filtered_irradiance0/1`（GI 描述符集本来就有这两个
  槽位，9.7.2/9.7.3 一直在用，只是整理这一遍没声明）。
- 读相位：存活条目把两条历史读进私有存储（和其余五张表同一套"先读后写 + barrier"）。
- 写相位：`dst != src` 时跟着落笔（原地不动就不写，省掉两笔 32B 拷贝）。
- 顺带把文件头的接口注释补上 b14/b15。

修完，"整理过的槽位"和"时域历史"重新绑定在同一个 patch 身份上：搬谁的历史跟谁走。

### 仍未收口

1. **整理每帧搬全场——已修（同一轮）**。两道闸门：
   - shader 侧：`dst == src` 的存活条目整块跳过写回（`counters[3]` 也只在真搬时累加），
     稳态下"搬"从 1024 条/帧降到 0；
   - 宿主侧：按空洞比例开波（`DEFRAG_HOLE_PERCENT = 12`，低于阈值一波都不录），另加安全阀
     （ring 区间 ≥ 池容量一半时强制压紧，防止 `start + offset` 绕圈覆盖条目）。
   实测：稳态 `defrag_moved = 0`（改前 1024/帧，活跃 13576）；接 10 次甩机位造空洞，把阈值
   临时置 0 验证压紧路径本身正常（每跳后空洞归 0、`moved` 500–1000），阈值 12 时稳态不再
   触发（该场景空洞率 0–10%，够不到阈值）。
2. 时域平滑系数仍取 `temporal_smoothing = 0.5`（w 0.925）；修后实测 std 已低于半级量化，
   没有继续加大平滑的依据——计划 §5 的"是否保留时域后滤波"按"保留 + 默认档"收口。
### 判定线脚本的两处修正（本次一并做）

1. **新增"常量天空就绪"前置**：`sky_uniform` 只是改开关，环境 cube/SH 要等下一次捕获。不等待直接取帧会读到上一张天空下的 IBL——本轮实测出现过 `IBL 4.59` 的假读数（真值 29 左右）。现在先轮询 `ibl_stats.probe16.center_energy ≈ π`（实测 3.1416）再取帧，锚点从此可复现。
2. **"墙背面必须变暗"改成"必须有实质差异（≥2%）"，另加"悬挑遮挡"正例**：孤立的墙背面朝开阔天空、又被日照地板的多跳补光，它比 IBL **亮**才是对的（旧断言把直射遮挡与 GI 遮挡混为一谈，修前之所以能过，是因为时域链把能量吃掉了）。真正的遮挡正例改用**近黑悬挑板下的地板**，用 `scgi_stats` 的物理辐照度对账（不受色调映射影响）：开阔处 E=2701 / 板下 E=909 → **0.336**，与几何估计（板把天空挡到约 1/3）吻合。
