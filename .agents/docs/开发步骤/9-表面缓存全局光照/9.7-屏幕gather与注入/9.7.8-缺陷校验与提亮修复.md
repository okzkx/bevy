## 从缓存到像素检查了什么

七个原实现步骤及其上下游均已走读。实际链路是：G-buffer 深度/法线播种 → 射线估计写原始 RGBL1 双缓冲 → patch 空间滤波写 A → patch 时域滤波写 B → 四分之一分辨率查表、压缩 → 屏幕去噪 → 全分辨率上采样并按着色法线求值 → 合成仅替换 IBL 漫反射。

未预曝光的最终辐照度记为 `E(n)`，最终反射仍是 `diffuseColor × E(n) / π`；余弦卷积不是再乘一次 π 的理由。IBL 高光和透明层不是本段的替换对象。

| 原步骤 | 校验与修复 |
|---|---|
| 9.7.1 查表与网格映射 | 沿用同一体素定位函数、16 帧子像素轮转；位置 BRP 查询也复用 CPU 镜像与实际提交 UBO |
| 9.7.2 patch 空间滤波 | 读原始本帧估计、写独立 A，不原地混写；修复预算跳帧时原始双缓冲版本没有传递的问题 |
| 9.7.3 patch 时域滤波 | 不再用 warmup 的等效更新次数判断历史有效；新槽清历史、整理随身份搬历史，使用完整有限 32 位帧身份；GI 重启首帧旁路旧屏幕历史 |
| 9.7.4 屏幕 Gather | 有效样本才贡献颜色；几何权重进入覆盖分母，再计缓存覆盖；参考子像素编号放进 L1 第四通道，不再用固定块心冒充几何 |
| 9.7.5 去噪与上采样 | 先解码 L1 物理系数再混合；无缓存零值不稀释有效 RGB；不再用最大邻居 alpha 接管被拒绝的像素；引导法线使用真实深度平面，最终求值使用面对视向的着色法线 |
| 9.7.6 注入 | 移除最终重复的 `ibl_intensity`；消费开关取本帧实际 upsample 是否存在，而非只看用户设置；低阶 SH 求值后的负瓣不作为负能量注入或多跳传递 |
| 9.7.7 验收 | 增加精确 HDR 锚、生产者停机矩阵、默认场景多机位/光向、实际 resize 和提交快照回归；修正旧锚被水平太阳照墙、真实反弹污染的问题 |

## 会直接丢光的代码错误

### 命中位置、法线和 UV 重心权重错位

[射线公共段](<F:/okzkx/bevy/ash_renderer/shaders/common/raytracing.wgsl>)曾把 Vulkan 返回的两分量权重当成顶点 0/1 权重。正确顶点权重是 `(1-u-v, u, v)`。本机 Naga 直接保存 `OpRayQueryGetIntersectionBarycentricsKHR`，没有替调用者重排。

位置错误会让阴影和多跳查表访问同一三角形上的另一个点，UV 错误则取错反照率。这是上游既有错误，不应误记为 Gather 新引入。依据：[Khronos 原文](<https://raw.githubusercontent.com/KhronosGroup/Vulkan-Docs/main/chapters/raytraversal.adoc>)。

### 半球和压缩合同不一致

平面播种法线面对相机，原上采样却直接使用未翻面的着色法线。常量天空的半球系数在 `N` 方向给出 `πL`，错误地用 `-N` 求值可恰好得到零。

[压缩与引导函数](<F:/okzkx/bevy/ash_renderer/shaders/common/gi_compression.wgsl>)采用已折基常数系数的合法范围 `|L1| ≤ 2L0`，编码比例改为 `1/4`。等权混合 `(L0,L1)=(100,100)` 与 `(1,-1)`，正确同向求值是 100；平均方向比值只得到 50.5。去噪和上采样必须先解码、混系数，而不是混比值。

### 视口边缘不是几何断层

[平面法线函数](<F:/okzkx/bevy/ash_renderer/shaders/common/gi_cell.wgsl>)在视口边缘使用有效内侧单边差分，仍拒绝内部深度断层。引导函数即使传入 clamped 深度，也不能把它当成真实视口外 tap。叉积退化时返回零，避免归一化产生 NaN。

### 停机、重启和快照必须按实际提交判断

[帧编排](<F:/okzkx/bevy/ash_renderer/src/driver/host/frame.rs>)只在本帧实际存在 upsample 时允许消费 SCGI。原始估计在预算跳帧前传递上一版本，避免偶数 stride 永远只更新一份。

GI 帧号在总开关关闭时冻结。因此除了[时域 shader](<F:/okzkx/bevy/ash_renderer/shaders/scene/gi/temporal_filter.wgsl>)的完整帧身份，还要在[GI 编排](<F:/okzkx/bevy/ash_renderer/src/driver/host/frame/gi.rs>)识别重启首帧，不能把冻结后的相邻编号误认为连续历史。

FramePool 的 current 指向下一待复用槽。位置 probe 和 census 使用[表资源](<F:/okzkx/bevy/ash_renderer/src/render/resident/tables/surface_cache.rs>)记录的最近实际 GI 提交槽，先排空 GPU，再读同一槽 UBO 和共享缓存；最近提交没有 GI 段时明确返回未就绪。

## 这一轮修掉的两类闪烁缺陷（2026-11-26）

两个缺陷都在同一处症状上：静态机位下，1/4 分辨率目标的块内容在"正常值"与"空/零"之间整块翻转，合成端 `mix(ibl.diffuse, replacement, a)` 于是在未遮挡的 IBL 基线与遮挡后的 SCGI 之间来回跳。定位手段是新加的 [1/4 目标回读探针](<F:/okzkx/bevy/ash_renderer/src/remote/features/gi.rs>)（BRP `scgi_low_probe`）与逐帧 `gi_estimate_probe`，两者读同一提交帧。

### 覆盖率建立在每帧旋转的抖动样本上

[屏幕 Gather](<F:/okzkx/bevy/ash_renderer/shaders/scene/gi/screen_gather.wgsl>)原先把 `coverage` 定义为"可用样本权重 / 试探权重"，而分子分母都来自[每帧旋转的采样偏移](<F:/okzkx/bevy/ash_renderer/shaders/common/gi_lookup.wgsl>)（`(sub, opposite, center)`，子样本 `(frame*7)%16`）。子样本落到没有 patch 的格子时覆盖率掉到 0.004–0.005（≈ `SEED_SAMPLE_WEIGHT 0.01 / 2.01`），合成端立刻回未遮挡 IBL（亮 8–13 倍），16 帧后又回到 1.0。

修复：覆盖率只由**确定性参考几何**决定——参考像素固定落在 `low*4 + (1,1)`，几何有效但未估计时按固定次序扫描 16 个相位取第一个可用者，颜色则以参考样本打底（`var acc_l0 = reference.l0; var weight_sum = 1.0;`），覆盖率写 `select(0.0, 1.0, reference.usable)`。抖动样本只影响颜色精度，不再影响覆盖率与有无。

### patch 分配的纪元标签让奇数帧全部被跳过

[patch 分配](<F:/okzkx/bevy/ash_renderer/shaders/scene/gi/patch_alloc.wgsl>)与[反弹分配](<F:/okzkx/bevy/ash_renderer/shaders/scene/gi/bounce_alloc.wgsl>)用 `frame_index | 1` 做"本帧已经有人分配过这个 cell"的纪元标签。`|1` 让相邻的偶数帧与奇数帧算出**同一个**标签：偶数帧第一个线程交换成功并分配，奇数帧第一个线程读到的旧值正是该标签，于是直接 return——**所有奇数帧的新 cell 分配被整体跳过**。被回收的 cell 因此隔帧缺映射，屏幕块在 0 与 600 之间整块跳。

修复：`epoch = frame_index * 2 + 1`，并加合同测试 `patch_allocation_epoch_is_unique_per_frame()`（4096 帧内非零且两两不同）。

两处修复后，原先四个闪烁像素的 `coverage` 与 `screen_a` 稳定在 1.0 / 0.9995（10 帧无变化），块值波动 <2%。

## 为什么没有继续给 GI 乘一个提亮系数

真实取证没有找到百倍 π 因子错误。默认太阳横穿中庭，而源几何屋顶开口仅约 3 米宽，中央地板基本不接直射。沿大厅长轴照入后，默认机位的未预曝光 GI 从约 `39/51/70` 升至 `480/419/350`，真实反弹在工作。

近距离命中只占射线约 6%，不足以解释整体暗化；源材质面积加权线性反照率约 0.16，多跳会自然衰减。MR 源纹理及加载角色也已核对：主石砖 metallic 均值约 0.0034，不是“石墙被当成全金属”。这些源资产计量不等同于 GPU 全部采样值证明。

[预览设置](<F:/okzkx/bevy/ash_renderer/src/render/passes/post/bloom.rs>)的全帧 tonemap 增益从 1.667 校准到 8，使含遮挡的暗部可见；原预曝光锚、GI 辐照度和环境强度默认值保持不变。该增益在 GI/IBL 对照两边相同。曾试过 ENV×8，但没有采用：它也会把未遮挡的 IBL 高光抬高，不能作为 GI 修复证据。

这个增益后来被证明是 **ACES 曲线曝光参数**（Filament 的 `1/0.6` 观感补偿），不是纯美学增益——它和自适应倍数会相乘，因此真正的显示段补偿改由 [9.7.9 自动曝光](9.7.9-自动曝光.md)承担，其 `key` 正是按"增益 8"这条管线标定的（室内倍数 ≈1、默认太阳 ≈2.37）。增益本身保持 8 不动。

## 覆盖边界

本轮不是全渲染器正确性的穷举证明。L1 颜色跟随 L0、diffuse-only、透明层不接 SCGI 是既定近似；上游射线 MASK/Blend 不完整及非均匀缩放法线近似仍是能力边界，未借提亮修复扩建另一套渲染体系。多设备、任意深度反弹、动态大世界压测与驱动失败注入不在已验证结论中。
