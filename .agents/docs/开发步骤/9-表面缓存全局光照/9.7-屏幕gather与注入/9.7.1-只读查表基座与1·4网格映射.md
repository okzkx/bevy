# 9.7.1 只读查表基座与 1/4 网格映射

> 2026-11-24 施工。依据 [施工计划](施工计划：屏幕gather与最终注入.md) §9.7.1。本文件记录"实际做了什么"，
> 计划文档只流转状态。

**一句话**：把 9.6 `cache_evaluate` 里那段"世界位置 + 法线 → 级联/体素/桶/cell"的定位链抽成公共片段
`shaders/common/gi_lookup.wgsl` 的纯函数（只读、无副作用），estimation 改为调它再叠自己的 bounce 分配；
同时把播种与 gather 必须共用的 1/4 网格口径（`sub = (frame·7) % 16`、`full = low·4 + sub`）落到同一份
算术上，并在 CPU 镜像侧加单测钉住。

## 做了什么

### 1. 新公共片段 `shaders/common/gi_lookup.wgsl`

| 符号 | 作用 |
|---|---|
| `struct LookupKey { cascade, cell, bucket }` | 定位结果；`cascade == INVALID_PATCH` = 位置在 Volume 外 |
| `lookup_cell_key(p, n, center, voxel_min, res, cascades, offsets)` | 球判据选级联 → 体素边长 → 体积坐标 → 存储槽 → 方向桶 → cell 索引 |
| `lookup_eval(irr, n)` | `E(n) = l0 + l1·n`（基常数与余弦卷积已折在存储值里，不再二次折叠） |
| `seed_subsample(frame)` / `low_to_full(low, sub)` | 1/4 网格映射（与播种同式） |
| `gather_sample_offsets(frame)` | gather 的 3 个块内样本点：本帧播种点、它的对角、块心 `(1,1)` |

### 2. `shaders/scene/gi/estimation.wgsl` 改调用

`cache_evaluate` 的定位段（原来 24 行内联算术）换成一次 `lookup_cell_key` 调用，保留它自己的两个
副作用（落空计数、bounce 请求追加），末尾求值改调 `lookup_eval`。`res`/`voxel_min`/`cascade` 等局部
变量随之消失——算术没有任何一项被改动（同一函数、同一顺序、同一取整），这是"行为逐位不变"的依据。

### 3. `src/render/passes/gi/volume.rs` CPU 镜像 + 单测

新增 `seed_subsample` / `low_to_full` / `gather_sample_offsets` 三个镜像函数与三条单测
（`seed_subsample_walks_whole_block_once`、`low_to_full_matches_seeding_formula`、
`gather_samples_stay_inside_block`），对应前置闸门 3。

## 钉明（相对计划的裁决）

1. **"片段注册"不需要改 Rust**：计划落点写了 `src/render/passes/gi/mod.rs`（片段注册），实际不需要——
   `build.rs` 递归枚举 `shaders/common/` 下的所有文件，`// #import <name>` 直接按文件名展开，新片段
   落盘即可被任何入口引用。`mod.rs` 本任务零改动。
2. **`lookup_patch` 改名 `lookup_cell_key` 并把 patch 索引留给入口**：`gi_cell.wgsl` 的既有纪律是
   "公共片段只放纯函数、不声明 `@group/@binding`"，而计划要的返回值含 `patch` 与 `rank`，那两步必须读
   `cell_patch` 与 `patch_statistics` 两张表。抽成"到 cell 为止"的纯函数后，estimation 与 9.7.4 的
   screen_gather 各自读表、各自回传，公共部分仍是唯一一份算术。若强行把表传进片段，要么在公共片段里
   声明 binding（破坏纪律），要么传 `ptr<storage>` 指针（本仓库无先例，且 naga 对运行时数组指针支持
   未验证）——两条都更差。
3. **`offsets` 用定长数组传参可行**：`array<vec4i, MAX_CASCADES>` 作为函数参数被 naga 30 接受
   （WGSL 允许可构造类型作参数），无需退化成"先查级联再查 cell"的两段式。
4. **块心取 `(1,1)`**：4×4 块的四个中心像素 `(1,1)/(1,2)/(2,1)/(2,2)` 等价，取左上那个与
   `low_to_full` 的整数算术一致；写进注释，9.7.4 若读图看出块状可改。
5. **样本数先写死常量 `GATHER_SAMPLE_COUNT = 3`**：计划 §5 的"查表样本数默认 3/5/9"待决项留到 9.7.4
   真正接上 1/4 查表时按命中率与噪声拍板，本任务只把口径与代数落定。

**关于"estimation 字节输出逐位不变"的口径**：`gi_dump` 只能读 LDR 调试视图帧，读不到 patch 辐照度缓冲，
所以拿不到"同一帧槽的 GPU 缓冲字节"做跨构建对比；跨进程再比 PPM 又正是 9.6 记过的假失败源
（驱动调度差异）。本任务的证据是"算术逐项未动（同函数同顺序，见 diff）+ 9.6 判定线 13/13 无回退 +
零 VUID"，**不宣称**做过 GPU 缓冲级的逐位对比。9.7.4 接上屏幕查表后，判定线④/⑤会给更硬的读数。
