# 9.5.2 常驻表与描述符集

> 2026-11-24。计划 [§0.2 / §9.5.2](施工计划：patch池与分配回收.md)。落点
> `src/render/resident/tables/surface_cache.rs`、`src/render/layout_registry.rs`。

## 做了什么

- **`SurfaceCacheTables`**（进程级 Resource）：九类 buffer + 每帧槽 UBO/计数，建表时一次性写满
  初值，之后只由 GPU 读写。
  - `cell_patch` / `cell_marks`：`cell_count × 4B`，起步档 8 MiB × 2；初值前表 `0xFF…`（INVALID）、
    后表全 0。
  - `patch_geometry` 32B / `patch_irradiance0/1` 各 64B / `patch_statistics` 48B / `patch_cell` 4B，
    ×池容量（65536）；初值全 0（`patch_cell` 全 INVALID）。
  - `ring`：12 个 u32（flip / active / watermark / pad + 两份 `{start,count,scan,pad}`）48B，初值 0。
  - `counters`：每帧槽 16 个 u32（分配/失败/释放/整理搬移/视图空洞/偏离/覆盖），64B，宿主每帧清。
  - `ubos`：每帧槽 256B `FrameUniform`，初值 identity + 默认规格。
- **`GI_SET_DESC`**：b0..b8 storage + b9 uniform，可见阶段 `COMPUTE|FRAGMENT|VERTEX`（compute 写、
  覆盖图片元读、方片顶点按实例号读）。
- **`GiSetLayout`**（进程级）：布局的单独持有者。表重建（BRP 改规格）只换 buffer/pool/sets，不换
  布局——布局被全部 GI 管线的 pipeline layout 引用。
- **登记**：`layout_registry` 的 `ALL_SETS` 加 `GI_SET_DESC`，`ALL_PIPELINES` 加六条 GI 管线。
- **显存读数**：`SurfaceCacheMemory{cell_bytes, patch_bytes, misc_bytes}`，`gi_stats` 出账。

## 实际字节（起步档，`gi_stats` 实测）

| 组 | 字节 |
|---|---|
| cell 双表 | 16,777,216（8 MiB × 2） |
| patch 表（几何 2 MiB + 辐照度 8 MiB + 统计 3 MiB + 反向 256 KiB） | 13,893,632 |
| ring + 计数 ×2 + UBO ×2 | 688 |
| **合计** | **30,671,536（≈29.25 MiB）** |

与计划 §0.2 的差异：`PatchStatistics` 计划写 32B，但两份 vec4（mean/variance）之后还有
state/request/update_count/heartbeat 四个 u32，32B 装不下；取 48B，统计表 3 MiB，总计从 ≈28.5 到
≈29.25 MiB（加 ring/计数/UBO 后 ≈29.25）。大世界档（6 级 / 池 2^18）实测 cell 表 25.2 MiB、
patch 表 ≈53 MiB。

## 裁决与坑

- **初值一次性写满，不用 GPU 清零 dispatch**：零 size dispatch 与未初始化读都踩 VUID；16+13 MiB
  的宿主直写在建表期完成，实测总初始化在几十毫秒量级（日志只记总表就绪，未单独计时）。
- **内存角色用 `Storage`（HOST_VISIBLE）**：计划 §5 的待决项取 HOST_VISIBLE 直写，省 staging +
  copy 一套；GPU 每帧只触碰活跃 cell 附近与整目录的 eviction 扫描，实测 `gi_ms` 可接受。
- **布局与表解耦**（施工中发现并修复的 bug）：首个实现把 `GI_SET_DESC.create()` 放在
  `SurfaceCacheTables::new` 里、`Drop` 里销毁布局。BRP 改规格重建表之后，已建管线（`gi_scrolling`
  等）的 pipeline layout 仍引用旧布局，`vkCmdBindPipeline` 报
  `VUID-vkCmdBindPipeline-pipeline-parameter`（日志 20 行，`gi_test` ⑥ 抓到）。改为
  `GiSetLayout` 进程级持有；表 `new(ctx, config, layout)` 借句柄分配集，`Drop` 只拆 pool。
- **`GI_SET_DESC` 阶段含 VERTEX**：方片（形态 B）在顶点着色器里按 `instance_index` 读 patch 表；
  布局契约测试第一次跑就报了 `vs_marker @group(2) … 不含 VERTEX`，扩阶段后过。
- **每帧槽计数**：清本槽发生在 `wait_for_slot` 之后（上一轮 GPU 已用完本槽），与 ray_tracing 统计
  缓冲同款；读数两帧内新鲜。
- **BRP 改规格的时序**：先 `device_wait_idle` 再建新表、`insert_resource` 替换；旧表 Drop 只拆
  pool（布局不归它）。

## 证据

`layout_contract_tests`：`every_pipeline_matches_shader_abi`、`every_set_declaration_is_valid_and_
uniquely_named`、`every_shader_entry_has_a_pipeline` 全过（113 项单测）。运行期：`gi_stats` 的
`memory.total_bytes = 30,671,536`，`gi_test` ⑤ 大世界档 `cell_bytes = 25,165,824`。
