# 求交器流程：从驻留事件到射线命中重建

面向下一个读代码的人：9.4 的求交器没有"CPU 调一次 intersect"的接口。CPU 只在资产期建
BLAS、每帧写地址表与录命令；射线由 compute 线程现场生成，命中属性回网格池取。本文按
"谁写什么、谁读什么"走一遍，最后附代码改动解析。

## 一、账面与缓存全景

| 数据 | 住在哪 | 写法 | 读者 |
|---|---|---|---|
| 网格顶点/索引池 | `MeshPool`（光线求交开 = `RayTracingPool` 角色） | 上传批 transfer 写；扩容迁移 | BLAS 构建输入（BDA）、命中重建（storage）、图形绘制 |
| BLAS 注册表 | `BlasRegistry`（`render/ray_tracing/blas.rs`） | 驻留事件驱动排建/排销毁 | TLAS 构建（经实例地址） |
| BLAS 地址表 | `InstanceTables` set2 b10（`u64/槽` ×2 帧槽，HOST_VISIBLE） | 宿主：模型脏行 + generation 变化整表重写 | `tlas_build` compute |
| 在场环 / 模型环 | set2 b4 / b1（既有） | draw_frame 每帧写 | `tlas_build` compute |
| TLAS 实例数组 | set2 b11（64B/条 ×2 帧槽，DEVICE_LOCAL） | `tlas_build` compute 全量写 | TLAS 构建命令（BDA） |
| TLAS | `TlasFrame`（`render/ray_tracing/tlas.rs`，每帧槽 AS+storage+scratch） | 每帧全量重建 | ray query |
| 光线求交描述符集 | `RayTracingTargets`（b0 TLAS / b1 顶点 / b2 索引 / b3 调试图 / b4 统计） | 句柄变化才重写 | `ray_debug` |
| 调试图 + 统计 | `RayTracingTargets`（RGBA16F ×2、u32×2 ×2） | `ray_debug` compute 写；宿主每帧清统计 | `ray_tracing_dump` / `ray_tracing_stats` |

## 二、新文件分工（一层一句话）

- `render/core/device/ray_tracing.rs`——能力判定纯函数 `RayTracingSupport`（三项 feature + 三个扩展）。
- `render/ray_tracing/blas.rs`——BLAS 注册表：排建、合并录制、地址、停尸房。
- `render/ray_tracing/tlas.rs`——每帧 TLAS：容量、构建命令、前后屏障。
- `render/ray_tracing/mod.rs`——`RayScene` 宿主入口 + `RayTracingSettings`。
- `render/passes/ray_tracing/mod.rs`——光线求交描述符集、调试图/统计、两条管线、`RayTracingFrameDraw` 录制束。
- `driver/host/frame/ray_tracing.rs`——帧侧编排（容量→换绑→地址表→统计清零→产物束）。
- `remote/features/ray_tracing.rs`——BRP 四口（`ray_tracing_set` / `ray_tracing_stats` / `ray_tracing_dump` / `ray_tracing_census`）。
- `shaders/common/raytracing.wgsl`——求交面（`trace_scene` + 命中重建），换后端只换它。
- `shaders/scene/ray_tracing/tlas_build.wgsl`、`ray_debug.wgsl`——两个 compute 入口。
- `tools/ray_tracing_test.py`——判定线一键驱动（15 项）。

## 三、逐时刻走读

### 1. 资产驻留（上传链，`flush_uploads` 开头）

```
drain_graveyards: 等全部在飞帧 → 拆 BLAS 停尸房（旧 AS/storage、构建用过的 scratch）
reclaim_retired:  资产退场 → pool.retire + ray.retire_blas（地址归 0 的整表重写在下帧）
reconcile_blas_builds（LOD 组代数变化/上批有提交或回收时）:
    每行锚档资产（LOD 组取"最粗已驻留变体"）→ ensure_blas（幂等）→ 待建表
```

### 2. 上传批（同一 `flush_uploads` 后半）

`pool.commit/replace` 之后：新资产下一轮 flush 被重扫到并排建；replace 当场
`retire_blas` 旧条目。待建条目只记**槽内偏移**，不记绝对地址（池扩容会换 buffer）。

### 3. 每帧 `draw_frame`（`prepare_rt`）

```
TLAS 容量保证（不够时等全部在飞帧重建两帧槽）
光线求交描述符集换绑（TLAS 句柄 / 网格池 buffer 变了才写）
地址表：generation 变了 → 全部行写两帧槽；否则只写本帧模型脏行
统计缓冲清零（本槽上一轮已 fence 等完）+ 记本帧实例数
产物束：tlas_build（count>0 才有）+ ray_debug（count>0 才有）+ 本帧池基址
```

### 4. 每帧 `record_frame` ② 段最前

```
BLAS 待建命令（一次 cmd_build_acceleration_structures，逐条独立 scratch）
    → 屏障（构建写 → 后续 TLAS 构建/ray query 读）
tlas_build compute（每线程一条实例：变换转置、Packed24_8、地址 lo/hi）
    → 屏障（compute 写 → 构建读）
TLAS 构建命令（instances geometry，实例 buffer 设备地址）
    → 屏障（构建写 → compute 读）
ray_debug compute（主射线 → trace_scene → 三种子视图 + 原子计数）
```

### 5. 提交之后

- `wait_for_slot` 等上上帧 fence → `GpuTimer::fetch_ray_tracing` 取 T9/T10（tlas_ms / rays_ms）。
- BRP：`ray_tracing_stats` 读统计与账；`ray_tracing_dump` 一次性拷贝调试图 → PPM；`ray_tracing_census` 读实例/地址字节。

## 四、失败与稳态路径

- **光线求交不支持**：`RayScene::new` 返回 None，三件资源不插入；`RayTracingSettings.enabled=false`；
  帧路径与 9.3 逐位一致。
- **`ray_tracing_set enabled=false`**：BLAS/TLAS 资源保留但不录命令、不写图、不清统计；`ray_tracing_stats`
  回 `enabled:false`，`ray_tracing_dump` 拒绝。
- **空场景（0 实例）**：不录 TLAS 组装/构建，也不打射线（未构建的 TLAS 读是未定义行为）。
- **池扩容迁移**：地址表在 generation 变化时整表重写；BLAS 构建输入地址每帧从池基址现拼。
- **资产换内容（replace）**：旧 BLAS 进停尸房 → 地址置 0（整表重写）→ 新 BLAS 下一轮排建。
- **稳态**：地址表/描述符零写入（generation 不变、句柄不变），每帧只有两次 dispatch + 一次
  build + 三条屏障。
