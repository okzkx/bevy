# 9.4.3 BLAS 生命周期：锚档排建、地址表与两级停尸房

**做什么**：按 `AssetId<Mesh>` 缓存 BLAS，构建输入直接指 `MeshPool` 区间；生命周期由驻留
事件驱动（提交排建、换内容重建、退场排销毁），销毁等全部在飞帧；地址写进 set2 b10 地址表，
供每帧 TLAS 组装读取。

## `BlasRegistry`（`render/ray_tracing/blas.rs`）

- 一个 BLAS = AS 对象 + 独立 storage buffer（`AccelerationStructureStorage`）+ 独立 scratch
  （`AccelerationStructureScratch`）。首版不池化、不 compaction（施工计划 §5 待决项照原样）。
- `ensure_build`（幂等）：查构建尺寸 → 建 storage + AS（offset 0，天然满足 VUID-03734）→
  建 scratch（多分配一个 `minScratchOffsetAlignment` 窗口，按取整后的地址切段，满足
  VUID-03708）→ 记入待建表。几何：
  `vertexFormat = R32G32B32_SFLOAT`、`vertexStride = 32`、`indexType = U32`、
  `maxVertex = vertex_count - 1`、`primitiveCount = index_count / 3`。
- `record_builds`：一次 `cmd_build_acceleration_structures` 带本帧全部待建条目（每条独立
  scratch）；录完的 scratch 进停尸房（命令还要执行一帧），AS/storage 转正进缓存并取设备地址。
- `retire`：AS/storage 进停尸房，`generation += 1`；`drain` 等全部在飞帧后先销毁 AS 再释放
  buffer。地址表由 `generation` 变化触发整表重写。

## 坑（实抓）：排建与录制之间池会扩容迁移

第一版在 `ensure_build` 时就把 `vertex_address + offset` 存进待建条目。`scene_stream` /
`scene_fine` 压测里池扩容迁移（8MB → 16MB）后，旧 buffer 被销毁，而待建条目的地址仍指向
旧内存 → `vkCmdBuildAccelerationStructuresKHR` 报 VUID-VkDeviceAddress-size-11364 /
device lost。

**修法**：待建条目只存**槽内偏移**（`vertex_offset` / `index_offset`），`record_builds` 收
当帧池基址（`prepare_rt` 里 `pool.vertex_address()` / `index_address()` 现取）再拼绝对地址。
排建到录制永远同帧，基址一定是最新池。这条与"地址不能缓存"是同一个根因的两处体现。

## 地址表（set2 b10）

- 每实例槽一条 `u64`，HOST_VISIBLE 环 ×2 帧槽（`BufferRole::Storage`）。
- 写入时机：① 模型脏行随模型环写（新行写满两个奇偶槽）；② `blas_generation` 变化 → 整表
  重写两个帧槽（锚档会随 LOD 变体到货/退场切换，增量集追不上）。
- 值 = 该行锚档资产（LOD 组取"最粗已驻留变体"，`driver/host/drawlist.rs::blas_asset_id`，
  与 `anchor_level` 同源、不依赖 floor_anchor 开关）的 BLAS 地址；未建/未驻留写 0
  （VUID-12281 允许 0，射线自然不命中）。

## 与驻留事件的接线（`driver/upload.rs`）

- `reclaim_retired`：`pool.retire(id)` 旁边 `ray.retire_blas(id)`；回收了东西置 `blas_dirty`。
- `upload_batch`：换内容（replace）先 `retire_blas`（旧地址失效），提交成功后置 `blas_dirty`。
- `flush_uploads` 开头：LOD 组代数变化、上一批有提交/回收时，重扫 `reconcile_blas_builds`
  ——对账本每行的锚档资产各排一份（幂等），锚档未驻留就跳过（地址 0，到货后下一轮再排）。
- `drain_graveyards`：与贴图/网格/对象槽共用同一次 `wait_all_inflight` 排空 BLAS 停尸房。

## 实测（Sponza，光线求交开）

- 首帧批量排建 103 份，一次构建命令；累计 `blas_bytes` ≈ 17.9 MiB。
- 单份最大 23,208 三角形 → storage 1,641,600B + scratch 492,544B。
- `ray_tracing_census` 可读每槽地址表（两帧槽）与实例数组字节（见 9.4.6）。
- 新增盒子 spawn → `blas_count` 104 → despawn → 103（`ray_tracing_test` ③）。

## 钉子

- AS 存储首版每 BLAS 独立 buffer；`blas_count` 过百再议池化（施工计划 §5）。
- 构建命令的 scratch 不得共用同一段（多 build 同帧时逐条独立）。
- 销毁顺序恒为"先 AS 后 buffer"。
