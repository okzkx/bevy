# 9.4.5 TLAS 每帧构建：实例数组、构建命令与帧槽分家

**做什么**：每帧从在场环 × 模型环 × BLAS 地址表组装实例数组（compute），再用一次
`cmd_build_acceleration_structures` 全量重建 TLAS；TLAS 与实例数组按帧槽各一份，实例数 =
本帧在场行数（`indirect_count`，宿主已知，不回读 GPU）。

## `shaders/scene/rt/tlas_build.wgsl`（新）

- 只用 set2（组号 0 = 实例表）：b1 模型环、b4 在场环、b10 地址表（读成
  `array<vec2<u32>>` 的 lo/hi，**不用 u64** —— shaderInt64 feature 没启用）、b11 实例数组
  （read_write）；push 4B = 在场行数。
- 每线程写一条 `TlasInstance`（64B 字节镜像 `VkAccelerationStructureInstanceKHR`）：
  - 变换：模型环是列主序 `mat4x4f`，VK 要行主序 3×4 —— 第 i 行 =
    `vec4f(m[0][i], m[1][i], m[2][i], m[3][i])`（写错 = 整体镜像/错位）；
  - Packed24_8：低 24 位 custom index（槽号）、高 8 位 mask = 0xFF；第二字低 24 位 SBT
    偏移 0、高 8 位 flags = `TRIANGLE_FACING_CULL_DISABLE`；
  - 地址 lo/hi 直接抄地址表（0 合法，未就绪实例自然不命中）。

## `TlasFrame`（`render/rt/tlas.rs`）

- 每帧槽一份 AS + storage + scratch；初始容量 1024（空场景也要给描述符一个合法句柄——
  0 实例的 AS 不合法）。
- `ensure_capacity`：实例数超容量时先等全部在飞帧，再按"×4/3 且至少翻倍、1024 对齐"重建
  **每个帧槽**（两帧槽各自 build/读，一帧的改写不能掀翻另一帧正在读的结构）。
- `record_build`：屏障（compute 写实例数组 → 构建读，`ACCELERATION_STRUCTURE_BUILD_KHR` +
  `ACCELERATION_STRUCTURE_READ_KHR`）→ 构建（`PREFER_FAST_BUILD`，instances geometry，
  数据经实例 buffer 设备地址）→ 屏障（构建写 → compute/ray query 读）。
  scratch 同样按 `minScratchOffsetAlignment` 取整切段。

## 帧内插入点（`render/frame/record.rs` ② 段最前，IBL 烘焙之后）

```
BLAS 待建命令（若有） → 屏障
tlas_build compute（groups = ceil(在场行数/64)）→ 交接屏障
TLAS 构建命令 → 屏障
ray_debug compute（主射线）    ← 仅当在场行数 > 0
```

- 空场景（0 实例）：`tlas_build_draw` 返回 None，不录 compute、不录构建、**也不打射线**
  （TLAS 从未构建时 ray query 读它是未定义行为；"没东西可撞"由宿主判定，不靠 0 长度命令）。
- RT 关/未就绪：整段 None，帧路径与 9.3 逐位一致。

## 帧槽分家与容量

- 实例数组与 TLAS 都按帧槽：一帧的 build 写不能掀翻另一帧正在读的 TLAS（WAR）。
- 实例数组容量 = 对象表容量（2^17 × 64B = 8MiB/槽），与槽号同址；TLAS 容量按在场高水位增长
  （本机 Sponza 103 实例 → 容量 1024、storage 合计 343,552B）。
- 实例数组 16B 对齐（VUID-03715）：buffer 基址 16B 对齐 + 索引自然对齐。

## 实测（Sponza，RT 开）

- `rt_stats.tlas = { instances: 103, capacity: 1024, bytes: 343552 }`。
- `rt_census` 读回第 0 条实例：`custom_index=103`、`mask=255`、`flags=1`、
  变换 = `[40,0,0,0, 0,40,0,2, 0,0,40,0]`（新增盒子的世界变换），地址与地址表一致。
- GPU 计时（新增 T9/T10 两位）：`tlas_ms ≈ 0.12ms`、`rays_ms ≈ 2.3–2.7ms`（1600×900 主射线）。
