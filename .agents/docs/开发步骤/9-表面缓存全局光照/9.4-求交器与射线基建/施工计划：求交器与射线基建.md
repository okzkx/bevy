### 0.1 后端：硬件 ray query 主后端，软件求交不入本段

- 主后端 = `VK_KHR_acceleration_structure` + `VK_KHR_ray_query` 的 inline ray query；与 Unity SCGI 的 Hardware 后端同形态（[Unity SCGI 实现](../../../笔记/光照与材质/Unity%20SCGI%20实现.md) §"需要重写的部分"）。
- compute 软件求交**不进 9.4 任务表**，也不作为步骤 9 完成门槛（沿用 2026-11-20 选型修订）。接口保留后端可替换语义：Rust 侧只暴露 `RayScene`（构建/更新/查询入口，不泄漏 `vk::AccelerationStructureKHR` 等硬件类型）；WGSL 侧所有 ray query 调用收在 `shaders/common/raytracing.wgsl` 一个片段里，换后端 = 换这份片段 + 换 `render/rt/` 的后端模块。
- 软件后端若将来要做（跨设备或无 RT 机器），登记进[外置拓展需求](../../外置拓展需求/外置拓展需求.md)再立项，不占 9.x 段号。

### 0.2 BLAS：挂 6.x 驻留资产，每组只建"最粗已驻留变体"一份

- **归属**：BLAS 按 mesh 资产身份（`AssetId<Mesh>`）缓存，与 `MeshPool` 同一生命周期——`commit` 时排建、`replace`/换内容时重建、`retire` 时排销毁；销毁要等在飞帧用完（复用池的停尸房/`wait_draws` 时序）。构建输入**直接用 `MeshPool` 的顶点/索引区间**，不复制几何（加 usage 位即可，见 9.4.2）。
- **几何档位（裁决自八段拆解 §3 "BVH 几何 LOD"）**：每个 LOD 组只给**最粗的已驻留变体**建一份 BLAS，无 LOD 组的资产自为组；同一组的其它变体不建。理由=漫反射 GI 只吃低频遮挡，省 AS 显存与构建时间；代价=遮挡边界略粗、最粗变体被淘汰时该实例掉出 TLAS（记 9.8 局限）。规则与 `anchor_level` 同源但不依赖 `floor_anchor` 开关（按"最粗已驻留"实算）。
- **不做**：逐 LOD 变体各建 BLAS、AS compaction（`cmd_copy_acceleration_structure` 压缩）、异步主机端构建（deferred host operations 的异步用法）。AS 字节进 BRP 读数，compaction 是否值得 9.8 压测后回看。
- **alpha 裁切**：首版按不透明（Unity 6.7 同款，MASK/Blend 几何都进 BVH）；any-hit 里做 alpha 判定需要 UV+贴图取样，归 9.8 局限自检时定（八段拆解 §3 同款待决）。

### 0.3 TLAS：每帧从在场环全量重建，未就绪实例写 0 引用

- 动态场景是前提（GI 不要求静态），首版**每帧全量重建** TLAS；增量/间接构建不做，9.8 压测后再判。
- 实例数组由 compute 从"在场环 + 模型环 + 每槽 BLAS 地址表"写出；**实例数 = 本帧 `indirect_count`（宿主已知的在场行数）**，不需要 GPU→CPU 回读。实例数组顺序 = 在场环顺序，`gl_InstanceID` 即在场序号。
- `instanceCustomIndex` = 实例槽号（24 位足够：表容量 2^17）；`gl_InstanceCustomIndex` 是命中侧回实例槽的唯一钥匙。几何双面参与 GI → instance flags 置 `TRIANGLE_FACING_CULL_DISABLE`。
- **未就绪实例（流送缺席/BLAS 未建）写 `accelerationStructureReference = 0`**：VUID-12281 允许 0（"must be 0 or a valid … address"），不需要 dummy 退化 BLAS；这类实例在相交时自然不命中。
- TLAS 与实例数组**按帧槽各一份**（两帧在飞：一帧的 build 写不能掀翻另一帧正在读的 TLAS）；容量按在场 high-water 向上取整，容量不足时重建（复用池的"停尸房 + wait_draws"语义）。
- 同步：compute 写实例数组 → 屏障到 `ACCELERATION_STRUCTURE_BUILD_KHR` 读；build 写完 → 屏障到 `COMPUTE_SHADER`/`ACCELERATION_STRUCTURE_READ_KHR` 读。两处都用现有 `MemoryBarrierDesc`（阶段+访问四元组现成，`barrier.rs:242-250`）。

### 0.4 命中重建：读既有顶点/索引池，不用 position fetch、不在 shader 里用 BDA

- WGSL 没有指针，也表达不了"shader 里按 device address 取顶点"；`VK_KHR_ray_tracing_position_fetch` 虽在 2060 上可用，但只补三角形顶点位置，补不了法线/UV。**命中属性统一从既有池读**（Unity 的 GeometryPool 同路）：顶点池/索引池以 storage buffer 绑定进 RT 集，对象记录给 `first_index` / `vertex_base`（= 顶点区间字节偏移 ÷ 32）——命中重建链：
  ```
  instance_custom_data → 对象记录 → 三角形三索引 → 三顶点（pos/normal/uv）
  → barycentrics 插值 → object_to_world（ray query 自带）→ 世界位置/法线/UV + material_index → 材质环取 albedo/emissive
  ```
- 因此：不启用 position fetch（少一个 feature 与 BLAS 构建旗标）；BDA 只用于 **host 侧** 构建 BLAS/TLAS，shader 侧不出现 device address。
- 9.4 只把这条链打通并由调试图取证；"命中点取光"是 9.6 的消费面。

### 0.5 调试与计量：BRP 读数 + 调试图 PPM 取证，不接合成 shader

- **不往 `gbuffer_composite.wgsl` 里塞 ray query**：含 `RayQueryKHR` 的 shader 在未启用 RT 的设备上无法建管线，会把"RT 关 = 9.3 逐位一致"的降级路径弄脏。调试图走**独立 compute**（`passes/rt/`），输出 RGBA16F 调试图 + 统计缓冲。
- 子视图（push 常量选）：命中距离（t 色阶）/ 命中世界法线 / 实例槽 hash；另加命中率与总射线数统计。
- 取证 = BRP `rt_stats`（feature 分位、BLAS 数/字节、TLAS 实例数、构建耗时、射线计数/命中率）+ `rt_dump`（调试图 → PPM，复用 `frame_dump` 的 P6 写法与读回管线）；锁屏/遮挡环境下也能取证。
- 屏幕实时显示（调试图当 render mode）**不做**：本段不加 `FRAME_MODE_*`、不接后链；若 9.6/9.8 需要实时看，再按最小改动加（写 HDR 的独立 RT 全屏 pass）。

### 0.6 边界（本段不主张什么）

- **不改画面**：RT 开只多基建命令、不接任何现有 pass 的着色；RT 关（`rt_set enabled=false` 或设备不支持）= 与 9.3 收官态逐位一致。不产 GI 缓存、不发 GI 射线。
- **不做**：软件求交；AS compaction；增量 TLAS；`VK_KHR_ray_tracing_pipeline`（着色器绑定的 traceRay，只用 inline ray query）；多相机/多 TLAS；蒙皮/形变网格的 AS 特殊化（出现该类资产时按 Unity 同款"不进 TLAS"再定）；alpha 裁切；GPU 侧 AS 地址分配器（首版每 BLAS 一条独立 buffer + AS 对象）。
- **不碰绘制闭环**：draw 命令、indirect、剔除都不动；TLAS 只多一条 compute + 一条 build 命令。
- **不承诺**跨设备覆盖：不支持 RT 的设备走 GI 关闭路径（本段验证该路径不崩、不报 VUID）。

## 1. 数据流总览

```
mesh 资产驻留（MeshPool::commit）
   └─ BLAS 排建（host 申请 AS+buffer+scratch，frame ② 段录 vkCmdBuildAccelerationStructuresKHR）

每帧 ② 段：
   ① tlas_build.wgsl（compute）读 在场环/模型环/地址表 → 写 TLAS 实例数组（reference 0 容忍缺席）
   ② 屏障（COMPUTE→AS_BUILD）
   ③ vkCmdBuildAccelerationStructuresKHR（TLAS，全量）
   ④ 屏障（AS_BUILD→COMPUTE）
   ⑤ ray_debug.wgsl（compute）：主射线 → ray query → 命中重建 → 调试图 + 计数

BRP：rt_stats（读数）/ rt_dump（调试图 → PPM）
```

## 2. 任务拆解

### 9.4.1 设备能力与 feature 门

**做什么**

- 设备创建加能力查询链：`PhysicalDeviceBufferDeviceAddressFeatures` / `PhysicalDeviceAccelerationStructureFeaturesKHR` / `PhysicalDeviceRayQueryFeaturesKHR`（chained 到现有 `features2` 查询，`context.rs:336-341` 的形状）＋扩展枚举（`VK_KHR_acceleration_structure` / `VK_KHR_ray_query` / `VK_KHR_deferred_host_operations`，AS 扩展的 vk.xml `depends` 已核）。
- 三项 feature + 三个扩展齐 → 建设备时启用：`vulkan12.buffer_device_address(true)`、AS/RQ feature 各一、扩展名进 `dev_exts`；缺任一 → **不报错**，记 info 日志，RT 关。
- 纯函数 `RtSupport::resolve(caps) -> Enabled/Disabled`——宿主只存结果，可单测（用假 caps 走"无 RT 设备"分支，不需要真设备）。
- `RtSettings` 资源（默认值 = "支持则开，见下方裁决"）＋ BRP `rt_set {"enabled": bool}`；BRP `rt_stats` 的 `enabled` / feature 分位段。

**落点**：`render/core/device/context.rs`、`render/rt/mod.rs`（`RtSupport`/`RtSettings`/feature 门）、`remote/features/rt.rs`、`driver/host/init.rs`（资源插入）。

**坑 / 钉子**

- 启用 BDA 是**开发时决定**：RT 开则 BDA 必须开（AS 构建全走 device address）；RT 关则 BDA 也不开——`DevicePool` 等既有池的创建参数必须与今天逐位一致，所以 `MeshPool` 构造要拿到 RT 开关（9.4.2）。
- `VK_KHR_deferred_host_operations` 没有 feature，只需扩展名；漏启用它 `VK_KHR_acceleration_structure` 不合法。
- 初始值提案（施工可推翻，9.4.7 复核）：`RtSettings.enabled` 默认 = `RtSupport` 支持的**开**（与 IBL 默认关不同——RT 开关不改画面，只决定基建是否活跃；每帧多一条 compute + 一条 build 的成本由 9.4.7 计量）。若首发成本超预期，改默认关 + BRP 开，9.4.7 记录依据。
- 能力查询要保持"先查再用"的既有纪律（`context.rs:333-335` 的注释先例）；feature 结构体必须先读出来再决定启用，不能凭 `vulkaninfo` 结论写死。

### 9.4.2 内存与描述符基建

**做什么**

- `BufferRole` 新成员（名字施工时定，示意）：
  - `DevicePool` 的 RT 变体：`VERTEX_BUFFER|INDEX_BUFFER|TRANSFER_DST|TRANSFER_SRC|STORAGE_BUFFER|SHADER_DEVICE_ADDRESS|ACCELERATION_STRUCTURE_BUILD_INPUT_READ_ONLY_KHR`——顶点/索引池既要被 compute 以 storage 读（命中重建），又要作 BLAS 构建输入（VUID-03673）。
  - `AccelerationStructureScratch`：`STORAGE_BUFFER|SHADER_DEVICE_ADDRESS`，DEVICE_LOCAL。
  - `AccelerationStructureStorage`：`ACCELERATION_STRUCTURE_STORAGE_KHR|SHADER_DEVICE_ADDRESS|STORAGE_BUFFER`，DEVICE_LOCAL（VUID-09542 要求 AS 所在 buffer 带 SHADER_DEVICE_ADDRESS）。
  - `TlasInstances`：`STORAGE_BUFFER|SHADER_DEVICE_ADDRESS|ACCELERATION_STRUCTURE_BUILD_INPUT_READ_ONLY_KHR`。
- `GpuBuffer` 分配：usage 含 `SHADER_DEVICE_ADDRESS` 时，`MemoryAllocateInfo` 链 `MemoryAllocateFlagsInfo { DEVICE_ADDRESS }`（VUID-03339）。**从 usage 推导**而不是新增角色字段，避免两份真源漂移。
- `DescKind::AccelerationStructure` → `vk::DescriptorType::ACCELERATION_STRUCTURE_KHR`；`pool_sizes_vec` 补一类；`DescriptorWriter` 补 `write_acceleration_structure`。
- `MeshPool::new` 收 RT 开关（决定用哪个 `DevicePool` 角色），暴露 `vertex_address()` / `index_address()`（`vkGetBufferDeviceAddress`，扩容后地址会变，调用方每次现取，不缓存）。
- AS scratch 对齐：`minAccelerationStructureScratchOffsetAlignment` 从 `PhysicalDeviceAccelerationStructurePropertiesKHR` 查；AS 存储 buffer 内 offset 必须 256 倍数（VUID-03734）——首版每 BLAS 一条独立 buffer，offset = 0，天然满足。
- 契约：新 set 与新管线要在 `layout_registry` 登记（`ALL_SETS` / `ALL_PIPELINES`），否则库测试 `every_shader_entry_has_a_pipeline` 报（`layout_contract_tests.rs:92`）。

**落点**：`render/core/device/memory/{role,buffer}.rs`、`render/core/binding/{set_layout,descriptor_writer}.rs`、`render/resident/assets/pool.rs`、`render/layout_registry.rs`。

**坑**

- `SHADER_DEVICE_ADDRESS` usage 位在 BDA 未启用时**非法**——所有新角色只能 RT 开时创建（资源都在 `RtSupport` 门内，不能进无条件初始化路径）。
- 池扩容迁移：旧 buffer 销毁前必须等所有在用它的命令（含 BLAS 构建）完成——现有 `ensure_capacity` 已等上传 + `wait_draws`，9.4 只需保证构建命令录在帧内（受帧 fence 约束），不额外加等待。
- 顶点池的 `vertex_base` 语义是"字节偏移 ÷ 32"（`MeshSlot` 注释），命中重建时别把它当字节数用。

### 9.4.3 BLAS 生命周期

**做什么**

- `BlasRegistry`：`HashMap<AssetId<Mesh>, BlasSlot { as_: vk::AccelerationStructureKHR, buffer: GpuBuffer, address: u64, build_pending: bool }>`——按资产去重，与 `MeshPool::residency` 同源。
- 触发点（都在 `driver/upload.rs` 的提交/回收路径上，`pool.commit` / `pool.replace` / `pool.retire` 的旁边）：
  - commit 且命中"锚档资产"规则（§0.2 的组选择）→ 记 pending；下一帧 ② 段建。
  - replace / 换内容 → 旧 AS 排销毁 + 新 AS pending。
  - retire → AS 排销毁（进停尸房，`wait_draws` 后排空）。
- 建：`get_acceleration_structure_build_sizes`（host，commit 时）→ 建 storage buffer + AS 对象 → 录 `cmd_build_acceleration_structures`（一次调用可带多条，逐条独立 scratch 切片）→ 取 device address 写地址表。
- 几何：一条 triangles geometry，`vertexFormat = R32G32B32_SFLOAT`、`vertexStride = 32`、`maxVertex = vertex_count-1`、`indexType = U32`、`transformData = null`；`firstVertex = 0` 的相对区间由 buffer address + 区间偏移表达。
- 构建旗标：BLAS 用 `PREFER_FAST_TRACE`（一次构建、长期查询）；不加 `ALLOW_COMPACTION`。
- 地址表：**每实例槽一条 u64**（`instance_blas`，set2 新增 b10，COMPUTE，HOST_VISIBLE 环 ×2 帧槽，按模型环同款"增量写 + 新行写满两槽"）。值 = 该槽当前锚档资产的 BLAS 地址（宿主在写对象记录/模型环时同步写）；锚档未驻留/AS 未就绪写 0。
- 一次 build 的时序证据：几何来自本帧或更早的上传批次，帧提交等上传票据（`UploadWait` 在 `ALL_COMMANDS` 等），所以构建命令读到的顶点数据一定可见。

**落点**：`render/rt/blas.rs`、`driver/upload.rs`、`render/resident/tables/instance_table.rs`（b10 地址表）、`render/rt/mod.rs`。

**坑 / 钉子**

- `cmd_build_acceleration_structures` 的 `pGeometries` 是二级指针形状（ash 的 SoA 调用签名），一次多 build 时每条 geometry 的切片生命周期要活到调用结束。
- build 的 scratch 只在 build 命令执行期有效，多 build 同一次调用时**不能共用**同一段 scratch（给每条独立偏移）。
- AS 对象必须在 buffer 分配**之后**创建，且 buffer offset 256 倍数（VUID-03734）。
- 销毁顺序：先 `destroy_acceleration_structure` 再释放 buffer（AS 引用 buffer 内存）。
- 池扩容后 `address` 变化：地址表由宿主按"新地址"重写两帧槽；AS 本身不受影响（构建完成后的 AS 自含数据）。
- 组内最粗变体尚未到货时：该组暂不建 BLAS（地址 0），到货后下一帧建；不阻塞渲染。

### 9.4.4 命中几何取数与射线抽象

**做什么**

- **build.rs**：校验 caps 加 `Capabilities::RAY_QUERY`；`resource_kind` 补 `AccelerationStructure` 分支（handle 空间 → `DescKind::AccelerationStructure`）。其余（入口枚举、`#import`、spirv-val）零改动；naga 自己发 `SPV_KHR_ray_query` 扩展，不需要补丁。
- `shaders/common/raytracing.wgsl`（公共片段，只放结构/函数，**`enable` 指令由入口文件第一行携带**——`#import` 是文本展开，指令不能放片段）：
  - `struct SceneHit { kind, t, instance_slot, primitive, bary, front_face, object_to_world }` 与 `fn trace_scene(tlas, origin, dir, tmin, tmax, mask) -> SceneHit`（内部 `var q: ray_query; rayQueryInitialize(q, tlas, RayDesc(...));` → `Proceed` → `GetCommittedIntersection`）。
  - 命中重建：`fn hit_geometry(instance_slot, primitive, bary) -> HitGeometry`（读 set2 对象记录 + 顶点/索引池 storage）；`fn hit_world_pos/normal/uv(...)`；材质索引直接出对象记录字段。
  - 坑：naga 的 `RayIntersection` 成员名是 `instance_custom_data` / `instance_index` / `geometry_index` / `primitive_index` / `barycentrics` / `front_face` / `object_to_world`（不是 `instance_custom_index`）；`RayDesc` 字段 `flags/cull_mask/tmin/tmax/origin/dir`（`type_gen.rs:25-110/157-260`）。
- RT 集（新 set，名字施工时定）：b0 `acceleration_structure`（COMPUTE）、b1 顶点池 storage、b2 索引池 storage、b3 调试图 storage、b4 计数/统计 storage；**不动 set0/set1/set2 的既有绑定语义**（set2 只加 b10 地址表与 b11 TLAS 实例数组，见 9.4.5）。
- Rust `RayScene`：`render/rt/mod.rs` 暴露 `build/update/query` 入口与 `RaySceneStats`；宿主侧不出现 ash 的 AS 类型（内部字段私有）。
- 管线：`passes/rt/` 一条调试图 compute 管线（配方进 `layout_registry`）；RT 关时不创建（资源也都不存在）。

**落点**：`build.rs`、`shaders/common/raytracing.wgsl`、`shaders/scene/rt/`、`render/rt/mod.rs`、`render/passes/rt/`、`render/layout_registry.rs`。

**坑**

- `run spirv-val` 必须接受 ray query 模块；本地 SDK 1.4.357 支持 `SPV_KHR_ray_query`，施工首日先跑一个最小模块确认（不合规就退回手写 SPIR-V 分支——这是本段唯一的高风险点，前置闸门里先验）。
- WGSL 的 `ray_query` 变量必须在函数内 `var`（指针语义由 naga 处理），`rayQueryInitialize` 第二参是全局 `acceleration_structure` 变量本身。
- 命中重建的一条硬依赖：对象记录的 `first_index` 是索引池下标、`vertex_base` 是 32B 单位；两个池的地址基址每次现取（扩容会变）。
- 调试图尺寸不在帧 UBO 里：push 里带 `width/height` 或从 workgroup 布局推，别去扩帧 UBO（会牵动 9.2/9.3 的布局断言）。

### 9.4.5 TLAS 每帧构建

**做什么**

- `shaders/scene/rt/tlas_build.wgsl`（compute，只用 set2）：线程数 = 在场行数（`indirect_count` 上界），每线程读 `presence[i]` → 槽 `s`；`models[s]` → `VkTransformMatrixKHR` 3×4（**mat4 列主序 → 3×4 行主序要转置**，写错会让几何整体镜像/错位）；`instance_blas[s]` → reference；写实例数组第 i 条（set2 新增 b11，写入输出）：custom index = s、mask = 0xFF、flags = `TRIANGLE_FACING_CULL_DISABLE`、SBT offset = 0。
- `TlasFrame`：按帧槽各一份 AS + 实例 buffer + scratch；容量按在场 high-water 取整，不足时重建（等 `wait_draws`）。
- 录制（② 段，IBL 烘焙之后、剔除之前）：tlas_build compute → 屏障 → `cmd_build_acceleration_structures`（`PREFER_FAST_BUILD`，mode = BUILD）→ 屏障。
- 空场景（`indirect_count == 0`）：不录 compute 与 build（判定"无实例不构建"在宿主侧做，不靠 0 长度命令的边角合法性）。
- BRP `rt_stats.tlas`：实例数、容量、`tlas_ms`（帧计时新增打点或 BRP 侧计时）。

**落点**：`shaders/scene/rt/tlas_build.wgsl`、`render/rt/tlas.rs`、`render/frame/record.rs`（② 段插入点）、`render/frame/render_features.rs`（新束）、`render/stats/*`。

**坑**

- 两帧在飞：TLAS 必须按帧槽分家（一帧 build 写、另一帧 query 读）；只用一个 TLAS 会撞 WAR。
- 实例数组必须 16B 对齐（VUID-03715）：buffer 基址 16B 对齐 + 索引偏移自然对齐。
- 实例数组的 `accelerationStructureReference` 0 是合法值（VUID-12281），不要为缺席实例造退化 BLAS。
- `VkAccelerationStructureInstanceKHR` 打包字段是 `Packed24_8`（custom index 低 24 位、mask 高 8 位；SBT offset 低 24 位、flags 高 8 位）——顺序写反会让 mask 变成 0（全遮挡剔除）或 flags 失效。
- TLAS 构建读实例 buffer 走 BDA：buffer 必须 `BUILD_INPUT_READ_ONLY_KHR`（VUID-03673）+ `SHADER_DEVICE_ADDRESS`；compute 写它还要 `STORAGE_BUFFER`。

### 9.4.6 调试视图与 BRP

**做什么**

- `shaders/scene/rt/ray_debug.wgsl`（compute）：每像素主射线（`inv_view_proj` 反投影 + `camera_pos`）→ `trace_scene` → 按 push 子视图写调试图：
  - 0 = 命中距离 t（色阶；未命中=背景色）；
  - 1 = 命中世界法线（`n*0.5+0.5`）；
  - 2 = 实例槽 hash（区分相邻实例）。
  命中/未命中计数用原子计数写统计缓冲。
- `passes/rt/`：调试图 compute 的录制与资源（图 + 统计缓冲 + set）。
- BRP：
  - `rt_set {"enabled": bool}`——总开关（feature 门之上再一层，供 A/B 与降级验证）。
  - `rt_stats`：`enabled`、feature 分位（AS/RQ/BDA/deferred）、`blas_count`/`blas_bytes`、`tlas{instances, capacity, bytes}`、`debug{rays, hits, hit_rate, last_ms}`。
  - `rt_dump {"path": "...ppm", "view": 0|1|2}`：调试图 → PPM（RGBA16F → 8bit，clamp + 取 rgb；复用 `frame_dump` 的 P6 写法与 `readback_buffer` 的拷贝+fence）。
- 调试图尺寸 = 当前 swapchain 尺寸；resize 时重建调试图（与现有 target 重建同链）。

**落点**：`shaders/scene/rt/ray_debug.wgsl`、`render/passes/rt/`、`remote/features/rt.rs`、`remote/mod.rs`（方法注册）、`driver/host/init.rs`。

**坑**

- 调试图只在 `RtSettings.enabled && RtSupport` 时存在；BRP 在关闭时回 `enabled:false` 而不是报错。
- `frame_dump` 现在读的是 LDR 后链目标；`rt_dump` 是另一条读回（调试图），不共用目标但共用 PPM 写法。
- 调试图写 RGBA16F storage image：格式支持面按 `vkGetPhysicalDeviceFormatProperties` 查（2060 必支持），不做 `write_without_format` 特性。

### 9.4.7 判定线与计量

**做什么**

- 判定线脚本（BRP + 帧取证，按[测试规范与方式](../../../../rules/测试规范与方式.md)三级优先，不注入鼠标）：
  1. **求交正确**：Sponza 中庭机位 `rt_dump view=0/1/2`，命中距离图与深度图结构一致（读图：墙/柱/地面分层吻合）；`rt_stats.hit_rate` 稳定 > 0；近距离墙面 t 与 G-buffer 深度反投影的手算值对得上（允许像素级偏差，记录口径）。
  2. **移动跟随**：`set_transform` 把某物体沿视线推近/移开，前后 `rt_dump` 对照 + `rt_stats` 命中率变化；无陈旧帧（连续三帧 dump 稳定一致）。
  3. **流送无悬空**：`residency_set` 逼预算淘汰 + `chunk_despawn` 后连跑 ≥60 帧：零 VUID、零 panic；`rt_stats.blas_count` 随驻留下降；调试图不再显示已卸载几何。
  4. **降级路径**：`rt_set enabled=false` → 调试图/统计口报关闭，画面与 9.3 收官态逐位一致（`frame_dump` 对照）；`RtSupport::resolve` 的"无 RT 设备"分支由单测覆盖（不需要真设备）。
  5. **不破底座**：回归五脚本（`hiz_test` / `scene_lod` / `scene_stream` / `scene_fine` / `scene_sponza`）零回退；库测试含新增单测；clippy 全净、fmt 全绿、零 VUID、WM_CLOSE exit 0。
- 计量：每帧多出的 `tlas_ms` + `blas_build_ms`（一次性）进帧计时账；BRP 读数与 9.8 压测同口径。

**落点**：`tools/` 下判定脚本、`render/stats/*`、施工记录。

## 4. 显存与性能口径

- **BLAS**：`get_acceleration_structure_build_sizes` 实测值逐资产累计，BRP 报 `blas_count` / `blas_bytes`；估算量级 = 三角形数 × 数十字节量级（施工首日实测，不预付结论）。
- **TLAS**：实例数组 64B × 高水位 ×2 帧槽 + AS 存储（build sizes 实测）+ scratch（最大实例数档）；`rt_stats.tlas.bytes` 读数。
- **AS scratch**：只在构建期有效，按最大单次构建的 `buildScratchSize` 分配，可跨 build 复用（不同 build 不得同段并发，见 9.4.3 坑）。
- **每帧成本**：`tlas_ms`（compute + build + 两条屏障）单独打点；与 8.1～8.3 的既有 compute 段并列进帧计时。
- 显存成组口径沿用八段拆解 §7 第 4 条：BLAS/TLAS 单列，与 cell 表/patch 池/IBL 目标同场测。
