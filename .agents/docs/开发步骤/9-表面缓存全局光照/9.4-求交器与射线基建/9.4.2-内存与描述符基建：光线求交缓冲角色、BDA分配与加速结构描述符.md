# 9.4.2 内存与描述符基建：光线求交缓冲角色、BDA 分配与加速结构描述符

**做什么**：把 光线求交需要的四种 buffer 用途、设备地址分配、加速结构描述符种类接到既有内存/
绑定设施上，并让 `MeshPool` 在 光线求交开时换成多用途池、能给出顶点/索引设备地址。

## BufferRole 四个新角色（`core/device/memory/role.rs`）

| 角色 | usage | 用途 |
|---|---|---|
| `RayTracingPool` | `VERTEX_BUFFER INDEX_BUFFER TRANSFER_DST TRANSFER_SRC STORAGE_BUFFER SHADER_DEVICE_ADDRESS ACCELERATION_STRUCTURE_BUILD_INPUT_READ_ONLY_KHR` | 光线求交变体网格池：命中重建 storage 读 + BLAS 构建输入（VUID-03673）+ BDA |
| `AccelerationStructureScratch` | `STORAGE_BUFFER SHADER_DEVICE_ADDRESS` | 构建期 scratch（DEVICE_LOCAL） |
| `AccelerationStructureStorage` | `ACCELERATION_STRUCTURE_STORAGE_KHR SHADER_DEVICE_ADDRESS STORAGE_BUFFER` | AS 存储（VUID-09542） |
| `TlasInstances` | `STORAGE_BUFFER SHADER_DEVICE_ADDRESS ACCELERATION_STRUCTURE_BUILD_INPUT_READ_ONLY_KHR TRANSFER_SRC` | TLAS 实例数组：compute 写、构建经 BDA 读 |

角色只在 光线求交开时使用——`SHADER_DEVICE_ADDRESS` 在 BDA 未启用时非法，资源全部在能力门内创建。

## BDA 分配从 usage 推导（`core/device/memory/buffer.rs`）

`create_inner` 在 `role.spec().usage` 含 `SHADER_DEVICE_ADDRESS` 时给 `MemoryAllocateInfo`
链 `MemoryAllocateFlagsInfo { DEVICE_ADDRESS }`（VUID-03339）。不新增角色字段：两份真源会漂移。

## 描述符：`DescKind::AccelerationStructure`

- `DescKind::AccelerationStructure` → `VK_DESCRIPTOR_TYPE_ACCELERATION_STRUCTURE_KHR`。
- `DescriptorWriter::acceleration_structure(binding, handle)`：写入走
  `VkWriteDescriptorSetAccelerationStructureKHR` pNext。**坑（实抓）**：AS 写入没有
  buffer/image 那种"顺带写 count"的构造器，`descriptorCount` 默认 0，首跑撞两条验证错误
  （`VUID-VkWriteDescriptorSet-descriptorCount-arraylength` 与 `-descriptorType-02382`）；
  修法 = 显式 `.descriptor_count(1)`，且 AS 写入逐条提交（pNext 结构体要活到调用返回，
  与批量写入的借用形状不兼容；光线求交集只在换绑时写，频次低）。
- `set_layout.rs` 的 `vk()` 映射与 `pool_sizes_vec` 自动覆盖新种类（按 `kind.vk()` 聚合）。

## MeshPool 的 光线求交变体（`resident/assets/pool.rs`）

- `MeshPool::new(..., rt: bool)`：`rt` 决定 `pool_role()` 用 `RayTracingPool` 还是 `DevicePool`；
  关时与 9.3 逐位一致。
- 新口：`vertex_buffer_info()` / `index_buffer_info()`（句柄 + 分配字节，光线求交集按整池绑
  storage）、`vertex_address()` / `index_address()`（BDA 每次现取，扩容后地址会变，不缓存）。

## 实例表 b10/b11（`resident/tables/instance_table.rs`）

- 新常量 `BLAS_ADDRESS_SIZE = 8`、`TLAS_INSTANCE_SIZE = 64`。
- 光线求交开时新建两族帧槽环：地址表（`u64/槽`，HOST_VISIBLE `Storage`）与实例数组
  （`64B/条`，`TlasInstances`）；容量都按对象表容量（2^17）对齐 1MiB。
- set2 加 b10/b11（COMPUTE）。**坑**：光线求交关时这两个环不存在，描述符不能写——两条 binding
  声明带 `PARTIALLY_BOUND`，不写也合法（光线求交关的管线根本不用它们）。

## 契约与登记

- `layout_registry.rs` 登记 `RAY_TRACING_SET_DESC` 与两条 光线求交管线，库测试
  `every_shader_entry_has_a_pipeline` / `every_set_declaration_is_valid_and_uniquely_named`
  通过（102 项库测试全过）。
- `build.rs` 的 ABI 反射补 `TypeInner::AccelerationStructure` 分支（handle 空间 →
  `DescKind::AccelerationStructure`），否则含 TLAS 全局量的模块在反射期 panic。

## 验证

- 光线求交开首跑：AS storage/scratch/TLAS/实例数组全部按各自角色建成，零 VUID（VUID-03339 未出现）。
- 网格池 `vertex_buffer_info` 在首个上传批次后可用（8 MiB 顶点池、5 MiB 索引池，Sponza）。
- 102 项库测试全过（含布局契约与 `RayTracingSupport` 单测）、clippy 全净、`cargo fmt --check` 全绿。
