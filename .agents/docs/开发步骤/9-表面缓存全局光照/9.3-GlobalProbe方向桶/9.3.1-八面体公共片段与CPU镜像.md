# 9.3.1 八面体公共片段与 CPU 镜像

**做什么**：把"方向 ↔ 4×4 八面体方格 ↔ 桶索引"做成一份公共 shader 片段（GPU 正本）与一份
逐式镜像的 Rust 实现（宿主侧摘要/单测），并先用单测把映射关系钉死，再让投影与着色复用。

## GPU 正本：`shaders/common/octahedral.wgsl`（新）

- `oct_wrap` / `octahedral_sphere_to_square` / `octahedral_square_to_sphere`：与 Unity
  `Common.hlsl:161-182` 同式；零向量用 `max(denom, 1e-20)` 兜底，不静默产 NaN。
- `direction_to_bucket_index(n, res)`：**方图坐标 × res、截断、再钳 res−1**（Unity
  `GlobalProbe.hlsl` 同式）。计划立案版曾写 `×(res−1)`，复核时对照 Unity 源码改成 ×res；
  两者桶边界不同，乘 `res−1` 会让方向→桶与桶→方向不互逆。
- `bucket_index_to_direction(index, res)`：`(x+0.5, y+0.5)/res` 反投影。
- 自带 `clamp`，不引用 `brdf.wgsl` 的 `saturate`——被不引 brdf 的 entry 导入时也能单独编译。
- 分量序统一 x/y/z（Unity 的 `RGBL1` 是 y/z/x，只借公式不借序）。

## CPU 镜像：`src/render/passes/ibl/octahedral.rs`（新）

- `sphere_to_square` / `square_to_sphere` / `direction_to_bucket` / `bucket_to_direction` /
  `eval_probe_bucket`，逐式对应 shader；`direction_to_bucket` 的截断用 Rust `as u32`（向零、
  饱和）与 WGSL 的 f32→u32 转换同语义。
- 桶数/分辨率常量不另立：直接用 `environment.rs` 的 `IBL_PROBE_RESOLUTION` / `IBL_PROBE_BUCKETS`
  （与 shader 的 `BUCKET_RESOLUTION` 同值 4），避免两处各写一个 4。
- `eval_probe_bucket` 与 shader 的 `probe16_eval` 同式：`E = l0 + l1x·n.x + l1y·n.y + l1z·n.z`
  （存储系数已折基函数常数）。
- 消费方：`ibl_stats` 的六方向摘要/桶中心能量、`ibl_census` 的桶中心回显、单元测试。
  因此 `pub(crate) mod octahedral` 由 `render/mod.rs` 转出口，remote 不越层拿私有模块。

## 单测（`cargo test -p ash_renderer --lib octahedral`，4/4 过）

| 用例 | 断言 |
|---|---|
| `six_axes_hit_expected_buckets` | ±X/±Y/±Z → 11/8/14/2/10/15（与 Unity 同式手算） |
| `sphere_square_sphere_round_trips` | 512 个黄金角方向，球→方→球点积 > 0.99999 |
| `bucket_round_trip_stays_inside_cell` | 方向→桶→桶中心夹角 ≤ 55°（方格在八面体空间、非球面 Voronoi，最坏实测约 48°） |
| `eval_matches_plain_l1` | 求值式与逐通道点积一致 |

## 钉子

- 正向索引乘的是 `res` 不是 `res−1`；往返单测就是为这条立的。
- CPU/GPU 两份必须同步改：镜像文件头和计划 §0.3 都写了"改一处必须同步另一处"。
- 单测的三角函数用 `bevy::math::ops`（仓库 clippy 禁用 `f32::sin/cos/acos` 族）。
