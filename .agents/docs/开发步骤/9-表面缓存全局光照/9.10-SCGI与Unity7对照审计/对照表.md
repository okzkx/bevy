# 9.10.1 SCGI 与 Unity 7 对照表

**状态：✅ 已完成（2026-11-26）。** 覆盖 Unity URP 17.7 的 40 个 SCGI 源文件（core 26 + URP 14），逐文件给出职责、本仓库落点（`file:line`）、语义判定与证据出处；同一张表下再按 kernel / 入口函数拆一层，确保"每个 kernel、每个对外函数都有归属"。

口径按施工计划 §0.1：**按功能语义对照，不按文件一一对应**。判定分六档：

| 判定 | 含义 |
| --- | --- |
| 等价 | 功能与数学语义一致，允许实现形态（dispatch、存储布局、RNG）不同 |
| 机制不同 | 承担同一职责但路径不同，已写明等价物位置；不计缺漏 |
| 实现错误 | 语义偏差且可观测，进 9.10.2 清单并分级处理 |
| 缺漏 | 影响本步主张（Volume 内不透明 diffuse 注入）的功能缺失 |
| 冗余 | 重复实现，或无调用方的死代码/死字段 |
| 不适用 | 平台/语言/资产形态差异，本仓库不需要对应物 |

## 四、结论与移交

1. 40 个文件全部有归属与判定，无"未审"；缺漏 **0**（本步主张——Volume 内不透明 diffuse 注入——的所有环节都有对应实现）。
2. 实现错误 2 处：`Scrolling` 释放判据（P0，本段已修）、上采样权重（P2，不做，写明差异）。其余偏差归 9.10.2 三清单（见 [审计报告](审计报告.md)）。
3. 机制不同 13 处已逐条写明等价物；其中 4 处（SurfaceCacheWorld/EntityChangeBridge/EntityRecords/WorldAdapter/ChangeSet）属"ECS 驱动 vs Unity 世界镜像"，是根本架构差异，不按缺漏计。
4. 反向冗余（本地有、Unity 无）：视图 16 cell 分类、`counters` 16 字、`gpu_gi_ms` 计时、屏幕侧 `denoise/upsample` 独立管线、BRP 远程取证口——均为本地取证/调试增强，进 9.10.2 冗余清单但不删。
