# 9.10.1 对照面建表

状态：✅ 完成（2026-11-26）。产物：[对照表.md](对照表.md)。

## 做了什么

把计划 §1 的 40 行"立案期估计"逐行落成**实落点**：Unity 侧 40 个文件（core 26 + URP 14），每行给

- Unity 文件与行数（`wc -l` 实测，非 meta）；
- Unity 内职责（kernel 名、关键函数）；
- 本仓库落点 `file:line`（落到函数/入口，不写目录）；
- 判定：等价 / 机制不同但等价 / 实现错误 / 缺漏 / 冗余 / 不适用；
- 一段证据（为什么这么判）。

另出一张 **18 行 kernel 归属表**（每个 `#pragma kernel` → 本仓库 `cs_main` 或 Rust 入口），因为 Unity 一个 `.compute` 里常有两个变体（`*Compute` / `*Hardware`、`Mono` / `SinglePassStereoInstancing`），逐 kernel 归属才能证明"没有漏读的入口"。

## 计划估计错误（已修正并记录原因）

| 计划原文 | 实测 | 说明 |
|---|---|---|
| `SurfaceCacheWorld.cs` → "场景接驳/变更集"落在 `passes/gi/volume.rs` | `volume.rs` 是**格点数学**（`BUCKET_RESOLUTION`、`cell_index`、`volume_position`、`resolve_cascade` + 大量单测），不含场景接驳 | 场景接驳的真实等价物在 `src/scene/mechanism/assets/ledger.rs`（ECS 变更）+ `render/ray_tracing/`（AS）+ `render/resident/tables/*`；`volume.rs` 只对应 Unity `Common.hlsl` 的坐标/桶数学 |
| `SurfaceCache.cs`（录制顺序/常量/资源）→ `passes/gi/mod.rs` | 录制顺序与逐帧参数在 `driver/host/frame/gi.rs`，常量/资源描述符在 `passes/gi/mod.rs` + `resident/tables/surface_cache.rs` | 一行拆成三处，照原计划会漏掉 driver 层的顺序 |
| URP 侧只有 14 文件都属 9.7 | `FallbackMaterial.mat` 是材质资产（非代码），`FallbackMaterial.shader` 由合成端 `mix(...)` 取代 | 后者判"机制不同、等价"，前者判"不适用" |
| 八段 §8 索引 12 行可直接回填 | 原表列是 `| 源码 | 本工程落点 | 段 |`，粒度粗（如 `SurfaceCache.cs RecordPreparation → passes/gi/allocation.rs`，实为 `driver/host/frame/gi.rs`） | 采用"保留原 12 行 + 追加 9.10 补全版 40 行"（计划 §5 待决六的裁决），原行不改历史、补全版给实落点 |
