# 9.6.4 L1 投影、余弦卷积与方差引导时域混合（施工记录）

> 2026-11-24。依据[施工计划](施工计划：irradiance更新与多跳.md) §9.6.4 与 §0.5。
> 本记录写"实际做了什么"与"裁决结果"，计划文档只流转状态。

**一句话**：把时域从"精确累计平均"升级成 Unity `ProcessAndStoreRadianceSample` +
`FilterTemporallyVarianceGuided` 的两段数学（短期均值/方差 → 漂移引导的 lerp(0.995, 短滞后)，
`update_count != updateMax` 时仍是精确累计平均）；并用"清场景 + 常量天空 L=1 + 顶视相机"
的现场自检钉住 L1 折叠口径——**实测 E(n) 均值 3.1380，解析真值 π = 3.1416（差 0.12%）**。

## 落地清单（按文件）

| 文件 | 性质 | 要点 |
|---|---|---|
| `shaders/scene/gi/estimation.wgsl` | 改 | 新增 `filter_temporally_variance_guided`；`cs_main` 的时域段改成"短期均值/方差 → 漂移权重 → 混合 → 写统计" |
| `src/render/passes/gi/estimation.rs` | 改 | 常量天空 πL 的解析单测（用与 WGSL 同值的两个折叠乘数做纯算术验证） |

时域的具体式子（与 Unity 逐项对齐，`short_hysteresis` 取 GI UBO 的 `estimation_f.x`）：

```
newUpdateCount = max(sample_count / samples, 1)          // 预热那一趟 = warmup
newCount       = min(oldCount + newUpdateCount, updateMax)
shortWeight    = oldCount == 0 ? 0 : min(oldCount/(oldCount+newUpdateCount), shortHysteresis)
newL0Short     = mix(estimate.l0, oldMean, shortWeight)
varianceSample = (estimate.l0 - newL0Short) * (estimate.l0 - oldMean)
newVariance    = mix(varianceSample, oldVariance, shortHysteresis)
stdDev         = sqrt(newVariance)
drift          = |newL0Short - oldL0| / stdDev
driftWeight    = smoothstep(0, 1, drift / 4)
updateWeight   = oldCount == updateMax ? lerp(0.995, shortHysteresis, driftWeight)
                                       : oldCount/(oldCount + newUpdateCount)   // 精确累计平均
output         = lerp(estimate, oldEstimate, updateWeight)
```

## 裁决与偏差（相对计划）

1. **`update_count` 按"相当于几帧"记账**：预热那一趟一次吃 `samples × warmup` 条样本，等价于
   `warmup` 次更新（`newUpdateCount = sampleCount / samples`），所以预热 patch 的 `update_count`
   一帧就跳到 `warmup`。这也是"预热结束即进入稳态"的判据，和 Unity 同款。
2. **`oldCount == 0` 时权重是 0**：输出直接是本次估计——种子（IBL 基线）被整体替换，不做混合。
   于是"首帧噪声"完全由预热倍率决定，这也是把 `warmup`（1/2/4/8）放进参数面的原因。
3. **`drift` 的 StdDev 加了 1e-9 下限**：方差为 0（常量天空、单样本）时 `drift` 会炸成 inf，
   `smoothstep` 收到 inf 得到 1（完全跟手），数值上能跑但会吃掉滞后；加下限后等价于"方差为 0
   视为完全稳定"，与 Unity 的浮点行为一致（它靠 IEEE 的 inf 语义，本工程显式写出来）。
4. **πL 自检分两层**：解析层（单测，两个折叠乘数与 `π·Y00`、`2π/3·Y1` 的等价）与现场层
   （清场景 + 常量天空 + 顶视相机，直接读 patch 的 `E(n)`）。计划写"常量天空下估计应等于 πL"，
   这两层合起来才算钉住——单测过而现场过不了，说明采样/求值哪一段写反了。

## 现场证据

**解析自检**（`cargo test -p ash_renderer --lib constant_sky`）：

- `GI_FOLD_L0 = π·Y00`、`GI_FOLD_L1 = (2π/3)·Y1` 两条等价式在 1e-6 内成立；
- 半球均匀常量 `L`：`l0` 与 `l1·n` 各等于 `πL/2`，求值合计 `πL`（1e-4 内）。

**GPU 自检**（`.temp/gi96_pi.py`，常量天空 `L = 1`、顶视相机 `pitch -85°/radius 8`、8 样本档、
多跳关）：

| # | 检查 | 读数 |
|---|---|---|
| 1 | estimation 起跑 | rays = 3168（预热期） |
| 2 | probe 拿到 patch | 8 条 |
| 3 | **E(n) ≈ π** | 八条 patch：3.1475 / 3.1386 / 3.1458 / 3.1293 / 3.1524 / 3.1329 / 3.1270 / 3.1304，**均值 3.1380（π = 3.1416，差 0.12%）** |
| 4 | 收敛到位 | 8 条 patch 的 `update_count` 全部到 32（updateMax） |
| 5 | 零 VUID / VK-ERROR | 可疑行 0 |

代码验证线：`cargo test -p ash_renderer --lib` 116 项全过（新增常量天空单测）、
`cargo clippy -p ash_renderer` 零告警。

## 待决项落定与顺延

- §5 待决落定：`short_hysteresis` 默认 0.85（0.5～0.99 可调，BRP/面板同源）；`updateMax = 32`
  沿用 9.5 的常量；`prev_view_proj` 确认**不参与**（patch 身份跨帧固定，没有重投影需求），
  字段保留不删——施工记录钉这一句，免得后来者以为漏了实现。
- 顺延：开关灯 lag 的量级记录（判定线②）与降档稳定性（判定线③）在 9.6.7 的脚本里做；
  预算随活跃数降档（9.6.5）；方差/更新次数的调试视图（9.6.6）。
- 已知边界：时域只在 patch 空间做，**不做** patch 级空间滤波与时域后滤波（归 9.7）；
  首帧噪声由预热倍率决定，倍率越大越稳但首帧越贵。
