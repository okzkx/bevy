# 9.6.5 射线预算、降采样与优先级（施工记录）

> 2026-11-24。依据[施工计划](施工计划：irradiance更新与多跳.md) §9.6.5 与 §0.6。
> 本记录写"实际做了什么"与"裁决结果"，计划文档只流转状态。

**一句话**：把"活跃 patch × 样本档 × 每样本最坏 3 条射线 ≤ budget"落成宿主侧一次换算
（`plan_estimation_budget`），产出**有效样本档**与**帧稀释步长**两个数写进 GI UBO；档位先降、
降到 1 还超才按 patch 哈希取模稀释（不按池下标，避免成块跳档）；`gi_stats` 补
`samples_effective / stride / budget_active / converged_ratio / variance_mean` 五个读数。

## 落地清单（按文件）

| 文件 | 性质 | 要点 |
|---|---|---|
| `src/render/passes/gi/estimation.rs` | 改 | `RAYS_PER_SAMPLE_WORST = 3`、`EstimationBudget`、`plan_estimation_budget`（含三组单测：宽裕/降档/稀释） |
| `src/driver/host/frame/gi.rs` | 改 | 每帧 48B 读 ring 的活跃数 → 换算 → 写 UBO（`samples` / `estimation_stride` / `estimation_active`） |
| `shaders/scene/gi/estimation.wgsl` | 改 | 帧稀释：`low_bias_hash_32(patch_idx) % stride != frame.x % stride` 时整条 patch 本帧跳过 |
| `shaders/scene/gi/estimation.wgsl` | 改 | 射线计数改成**真实条数**：重连接与自发光阴影各自 `atomicAdd(&counters[9], 1)`，半球那趟按样本数一次加 |
| `src/remote/features/gi.rs` | 改 | 五个读数进 `gi_stats.estimation`（收敛占比与平均方差抽前 64 条 patch） |

## 裁决与偏差（相对计划）

1. **优先级只落成"先降档、后稀释"两段**：计划写"rank 0 且心跳新的 patch 先保；其余按
   budget/(活跃数×3) 换算样本档"。实现上"换算"是全场统一的（一个 UBO 值），没有做 per-patch
   的差异档位——per-patch 档位要往统计表里再塞一个字段、且会让同一帧内不同 patch 的收敛速度
   不同（读数与判定线更难解释）。用"档位 + 稀释"两级已经能保证预算不被打穿，per-patch 优先级
   留到 9.8 压测时按需再细化。
2. **活跃数取 ring 水位（上一帧）**：48B 主机读，误差一帧，换来"预算换算不需要 GPU 回读"。
   它与 `gi_stats.patches` 同一个字，读数能互相印证（现场：`budget_active=15768` vs
   `patches=15950`）。
3. **稀释用 patch 哈希取模**（计划 §9.6.5 的钉子）：`low_bias_hash_32(patch_idx) % stride`
   对 `frame.x % stride`。用池下标取模会按池顺序成块跳档，出现可见的条带。
4. **射线数是真实发射条数，不是样本数**：一开始 `counters[9]` 只累加 `sample_count`，读数比
   预算模型小 1～3 倍（漏了重连接与自发光阴影两条）。改成在两处 `trace_scene` 之前各
   `atomicAdd` 一条后，现场 `rays=15704` 与活跃数同量级，预算判定才有意义。
5. **默认预算 262144 在"开了 bounce"的场景里会降到 4 档**：现场活跃 15768 条时
   `262144/(15768×3) ≈ 5.5` → 取 4 档。这是设计内的行为（预算优先于画质），但它意味着
   9.8 的压测要同时看"活跃数"和"实际档位"，不能只看设置值。

代码验证线：`cargo test -p ash_renderer --lib` 117 项全过（含三组预算换算单测）、
`cargo clippy -p ash_renderer` 零告警。

调试坑（记下来）：加 `estimation_active` 到 UBO 时，旧的 `put_u32(&mut out, 300, 0)` 填充行
还留着，**后写覆盖前写**，读数恒 0——一度以为是 ring 读错。UBO 打包函数里"先填后补零"的
顺序要盯住。

## 待决项落定与顺延

- §5 待决落定：起步预算 262144 射线/帧、样本档上限取设置值（1/2/4/8）、稀释上限 64 帧。
- 顺延：per-patch 优先级（rank/心跳差异档位）留 9.8 压测；样本档分布的直方图读数不做
  （只给"有效档位"这一个数）；`estimation_ms` 单列计时点位仍按 §5 待决——当前 `gi_ms`（T5）
  已包含估计与清单，9.6.6 的视图改造后一起定。
- 已知边界：预算换算用"最坏 3 条射线"估，实际条数取决于命中率（未命中不跑重连接），
  所以实际射线数通常小于预算——9.8 若要更紧的预算，需要按"期望射线数"而不是最坏值换算。
