- 新增 `overlay/windows/monitor_window.rs`：**持续监控窗口**（总控"持续监控"开关，默认开）。FPS 走势曲线（egui painter 折线，10 分钟窗）+ 窗内 fps min/p50/p95/max 与帧耗 p50/p95 + 内存行（进程工作集 GetProcessMemoryInfo / 系统 GlobalMemoryStatusEx）+ 显存两口径行（VK_EXT_memory_budget 堆级 usage/budget 与 MeshPool/ImageCache 进程内部账并列）。

## 7.5.4 根因定位与修复 ✅

**逐窗二分**（每步重编译 + monitor_stats 采样）：全关=60fps 锁定 / 只开层级树=稳 / 只开监控窗=稳 / 只开"ash 调试"窗=复现（egui 8.6→23.1ms 线性涨）→ 元凶是调试窗的分位数行。禁用分位数行（临时 env 探针）→ 4.2ms 恒定，闭环。

**根因**：`PerfLedger` 派生 `Default`（capacity=0），宿主 `init_resource` 按 Default 装配 → `push` 的裁剪条件 `len == capacity` 永不成立 → 环形账退化为**无界增长**（基线实测 n=3208 > 容量 2048 即铁证）→ 调试窗每帧 9 次对越来越大的窗口全量 clone+sort → 每帧成本线性涨。此前 F26"帧时间空洞"同类观察在本场景的真身即此账。

**修复三件**（feat `8e1fc999b`）：

1. `PerfLedger` 手工实现 `Default`（= `new()`，capacity 2048），环形账收敛；
2. `PerfLedger::percentiles` 多分位数一次读（每字段一趟排序）+ `PerfPanelCache` 面板缓存跟 0.5s fps 快照节奏重算——调试窗逐帧零排序，且分位数文本 0.5s 才变（egui galley 缓存可命中）；
3. 计量仪器转正：`frame_wall_ms` / `EguiPassTiming` 常驻账面。

## 首钉与遗留

- **首钉**：`derive(Default)` + `init_resource` 组合下"capacity 字段归零"的环形账退化——`Default` 必须等于 `new()`，已在结构体注释钉死。与 3.7.4（裸集成漏跑插件生命周期）同族：**资源派生默认值与真实构造分歧是 egui/宿主集成层的复发坑**。
- 挂账联动：F26（zero_day 帧时间空洞）的仪器半边由本段落地（frame_wall_ms / egui_pass_ms），zero_day 场景的空洞归因复验留待 F26 处理时用新仪器。
- egui 面板常开基线 ~5.5ms（纯文本塑形成本，恒定不增长）；如需进一步压（0.2s 节流/行合并）留待需要时再做。
