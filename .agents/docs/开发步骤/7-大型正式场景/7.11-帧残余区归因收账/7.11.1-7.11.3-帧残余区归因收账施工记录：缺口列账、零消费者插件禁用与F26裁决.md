## 2. 治理与立账（7.11.2）

**顺手修（已落）**：
- **UiPlugin 禁用**（main.rs 装配面）：ui_focus/ui_layout/ui_picking ~0.1ms/帧零消费（交互全走 egui 裸接与 BRP）——与 7.10 可见性豁免同款治理。实测 wall 21.56→21.34 / 缺口 19.98→19.75，零 ERROR、宿主照常。
- update_ledger 候选计数（0.2ms 级）已在 7.10 落地，本段列账归位。

**实摘受挫转立账（实抓，不硬凑"已修"）**：
- **picking 家族 ~0.23ms/帧**：`DefaultPickingPlugins` 是 PluginGroup 非 Plugin——装配面 `.disable::<>()` 类型不满足，整族无法摘除（逐成员摘除需重建装配组）。转引擎侧装配语义议题。
- **gizmo 空转 ~0.09ms/帧**：GizmoPlugin 禁用后 `update_gizmo_meshes`（per-config 内部插件注册）残注册，`LightGizmoConfigGroup` 报 `Assets<GizmoAsset>` 缺席进 Tier 通道（宿主 ERROR 实抓）——收益/风险不成比例，回退，立账。
- **animate_targets 0.35ms/帧**：glTF loader 的动画写入以 `#[cfg(feature = "bevy_animation")]` 直依赖 `Assets<AnimationClip>`——禁插件会断场景加载链，不可摘，立账。

**结构级（如实立账，去向写明）**：
- update_ledger 残余 0.75ms：4.1 已知成本（Changed/Removed 查询 O(匹配实体) 迭代），进一步收敛需组件生命周期钩子化——引擎侧议题。
- mark_dirty_trees 0.54ms：bevy_transform 关系脏标记走访（16k 节点树），bevy 内部。
- calculate_bounds 0.17ms + light visibility 0.10ms：查询形状不含 Visibility（7.10 豁免不命中），bevy 内部。
- run_fixed_main_schedule 0.5ms：bevy_time 固定循环机械成本（空调度）——bevy 内部。

## 3. F26 裁决（7.11.3）：**关闭**

F26（zero_day 帧时间空洞）的证据链在本段闭合：缺口 = 呈现节拍合法空闲（p50 ≈ 60Hz）+ 已逐段归主的调度工。原立案时的 "Last+winit ~8ms + First/PreUpdate ~1.5ms" 粗口径，经 7.8（egui 节拍）/7.9（组装增量）/7.10（可见性豁免）/7.11（本段列账+UiPlugin）四段治理后：**cpu_total 1.59ms/帧、调度工 ~7ms（trace 口径）**，其中 draw_frame 1.59ms 是"拿图+录恒定命令+提交+present"的真实渲染工，其余大项均已在 §2 写明引擎侧去向。空洞里已无可归主的"神秘项"——判定线 3 满足，关闭。
