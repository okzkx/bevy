**7.3.1 资产获取脚本**：`tools/fetch_polyhaven.py`——`api.polyhaven.com/files/<Asset>` 取打包 gltf URL；**待决 1 落定：gltf 包非自含**（.gltf + 同目录 .bin + `textures/` 相对 URI），脚本按 URI 基名映射 `Models/jpg/<res>/<Asset>/` 通道补链（实测 200；缓冲 URI 走 gltf 同目录兄弟路径）。**待决 2 落定，选件终表四件**：ArmChair_01（布+木）/ antique_ceramic_vase_01（陶瓷）/ brass_vase_01（黄铜金属）/ carved_wooden_elephant（木雕）——材质互补，各 1 primitive/1 材质/3 贴图（normal+baseColor+ARM 或 rough）。curl 兜底（urllib 对 dl.polyhaven.org 偶发 403 UA 敏感）；`.fetched` 标记幂等。资产落 `assets/polyhaven/`（exclude 层）。

**7.3.3 贴图字节预算列实测**：fine_grained 开档 + `budget_image_bytes` = 实占 1/2（324.4MB，**待决 3 落定：下限 50MB 现算口径**）——used_image 精确收敛到 324.4MB（贴图淘汰按"引用行最近距离远优先"整资产口径消化）、关闭沿回 648.9MB、over_budget_image=False。**6.4 第二列第一次吃真实大贴图（7.2 因 zero_day 无变体未竟项清账）**。

## 首钉（实抓即修）

1. **BRP residency_stats 的贴图字节字段住 `fine` 嵌套对象**——顶层 `used_image_bytes` 不存在，脚本误读为"未填充"（7.2 的 used_image=0.0 误读同源——当时字段无消费者所以没暴露）。协议形状以 `rpc.discover`/本文件为准。
2. **同资产重载去重**：AssetServer 按 AssetId 去重，重复 load_world 只增实体不增 pool 条目——等待条件只能看行数差值与上传排空，resident 差额不可靠。
3. **换场 despawn 传播滞后**：整树回收后 3s 读数可能仍是旧账——段间基线必须现读（陈旧基线让 Δrows 误判）。
4. fetch 脚本 curl exit 23 = 目标目录未建（makedirs 补）。
