## 1. 5.3.1 能力面闸门三件

- **闸门① `multi_draw_indirect`**：支持查询走 5.2 已有的 features2 链（`features2.features.multi_draw_indirect`），硬校验不满足即 Init 出局（RTX 2060 = true）；设备创建**新增 `enabled_features`**（此前 DeviceCreateInfo 不传 base features，全 0）——`PhysicalDeviceFeatures::default().multi_draw_indirect(true)`，就绪日志钉 `multiDrawIndirect true→on（5.3 闸门①）`。
- **闸门② `draw_indirect_count`**：**不启用**（待决 2 倾向采纳）——count 形状选 `cmd_draw_indexed_indirect`，命令条数上界是在场行数（CPU 在账），无"只有 GPU 知道条数"的形状；翻案条件随 5.4 压缩合批再评。
- **闸门③ `limits.maxDrawIndirectCount`**：就绪日志留痕（本机 4294967295 = u32::MAX）；`IndirectPass` 建链时读入并作 drawCount 硬上界，超界显式报错不截断（与对象表容量耗尽同纪律）。
- **首跑留痕**（对计划的一处偏离）：计划原文"host 写一条 instanceCount=1 命令空转首跑"——命令环是 DEVICE_LOCAL，host 写命令需要一次性 staging 脚手架，与 5.2 否决 A/B 脚手架同理不值得；改为**真实路径首跑收账**（首个在场行数 > 0 的帧打 `indirect 提交首跑（前置闸门②）`），合法性由验证层对 `cmd_draw_indexed_indirect` 全链执法（实测：首帧在场行 6，零 VUID）。

## 2. 5.3.2 indirect 命令 compute pass

- **独立组装 pass**（待决 1 倾向采纳）：新 `vulkan/indirect.rs`（IndirectPass：set2 单集 + 4B push count）+ `build_indirect.wgsl`（`@compute @workgroup_size(64)`，bound = 在场行数），与 cull 两步分工同构于 Bevy `mesh_preprocess` → `build_indirect_params`。
- **新增第五/第六族环**（InstanceTables，按"写形状"三分法的前例归类）：
  - **在场环**（b4，HOST_VISIBLE ×2 帧槽，u32/行）：`draw_frame` 全量重写可绘行槽号列表——见 §3 钉明；
  - **命令环**（b5，`BufferRole::IndirectCommands` 新角色：STORAGE + INDIRECT_BUFFER usage、DEVICE_LOCAL、单族 EXCLUSIVE——纯设备侧，宿主零访问）：build_indirect 每帧重写，20B/条 `VkDrawIndexedIndirectCommand` 镜像（indexCount/instanceCount/firstIndex/vertexOffset/firstInstance，`indirect_command_layout_mirror` 测试钉布局）。
- set2 扩 b4/b5（COMPUTE-only，与 b3 同款收窄），描述符仍 init 一次写入；命令环生命周期照标记环先例（×2 帧槽 + `wait_for_slot` fence 纪律，不新增等待闸门；拆 Device 排空随 InstanceTables 既有路径）。
- **屏障施工订正**：计划 §1 写"本段不新增屏障形状"——**不属实（立案期核实遗漏）**。预置屏障（cull::record 尾部，dst `VERTEX|COMPUTE_SHADER`）只盖标记的 compute/vertex 读；indirect 命令消费走 `DRAW_INDIRECT` 阶段 + `INDIRECT_COMMAND_READ` 访问，须单独立一条屏障（indirect::record 尾部：src `COMPUTE_SHADER/SHADER_WRITE` → dst `DRAW_INDIRECT/INDIRECT_COMMAND_READ`）。实测同步验证层零误报，依赖链 = 标记写→组装读（预置屏障）→ 命令写→绘制读（新屏障）两段拼接。

## 3. 施工期结构发现：固定槽位的幽灵对象盲区（待决 5/6 钉明）

**计划盲区**：计划与主计划的起步口径是"固定槽位逐 bound 槽发命令（不可见 instanceCount=0）"，并假设"未驻留槽天然无命令 = 自动缺席"。核实发现该假设只对"实例槽缺"的行成立；两类行**有槽有记录但暂缓**：
1. **已 despawn 未复用槽**：槽进停尸房/free list 后旧记录仍在表里（`used_objects` bump 游标不缩），bound 覆盖它——cull 照算标记（旧 AABB）、build_indirect 照发命令，**幽灵对象持续绘制直到槽被复用**；
2. **资产卸载后的暂缓行**（4.4 回收语义）：mesh/material `Removed` 只出账驻留条目，行与槽不动——旧记录的池引脚可能指向已回收复用的池区间，indirect 会画出张冠李戴的几何（DrawList 时代被 `pool.resident` 检查拦住）。

**钉明（对计划的偏离）**：命令宇宙从"全部 bump bound 槽"改为"**在场环**"——DrawList 槽位枚举（`DrawAssembly.slots`，账本可绘行 O(N) 走访的既有产物）每帧全量重写进在场环，build_indirect 以它为行宇宙（dispatch 上界 = 在场行数），drawCount = 在场行数。效果：
- 退休槽/暂缓行**不在列表 = 自动无命令**，4.x 暂缓语义在源头精确保留（GPU 侧零特判）；
- 判定线 1 不受影响（绘制调用与 push 字节仍与 N 解耦；O(N) 走访是账本在账信息的组装写侧，红线口径照计划 §1 允许）；
- 与 Bevy 同构：`current_input` MeshInput 数组就是 CPU 供给的每帧在场清单（[batching/gpu_preprocessing.rs](../../../crates/bevy_render/src/batching/gpu_preprocessing.rs)），我们只是把它显式命名为"在场环"并按写形状归入第五族。

**DrawCall 退役**（待决 5）：`DrawAssembly.draws: Vec<DrawCall>`（槽号+池引脚）改为 `slots: Vec<u32>`——池引脚归 GPU 自取（对象记录三引脚），录制层零逐对象参数；`DrawCall` 结构从 frames.rs 删除。

## 4. 5.3.3 图形提交消费

- **push 4B 退役**（待决 3 倾向采纳）：命令 `firstInstance` = 实例槽号，`vs_main` 改收 `@builtin(instance_index)`（instanceCount=1 时 instance_index == firstInstance == 槽号，Vulkan InstanceIndex 语义从 firstInstance 起算）；图形 pipeline layout 的 push range 删除（`PUSH_CONSTANTS_SIZE` 退役），场景绘制 push 字节恒 0——5.1 遗志（96B→4B→0）收尾。连带订正：`increment_stats` 的 `push_bytes_per_draw` 硬编码 4 → 0（字段保留供 5.5 对照）。
- **一次提交**：`record_frame` 场景段从逐 draw 循环改为 `cmd_draw_indexed_indirect(indirect_buffer, 0, indirect_count, 20)`；`indirect_count = 0` 时场景段整段跳过（空场/全暂缓），"在场行非空但池缺席"仍按状态矛盾 Tier② 退出。
- **DrawList 终态**（待决 5）：`drawlist.rs` 只剩可绘判定 + 三环写入（模型增量/材质全量/在场全量），判定以录制层代码面为准（frames.rs 场景段无循环）。
- **空场与暂缓行**（待决 6）：count=0 → dispatch/提交全跳过（实测不 crash 不产生绘制）；暂缓行不进在场环 = 自动缺席，诊断读数口径对齐（`walk_rows`/`pending_rows` 单列，与命令条数分报）。

## 6. 5.3.5 验收回归记录

- **画面级 A/B 三连**：①spawn 视锥外 → off/on 场景区域零像素差（差异全在面板读数文本）；②移入视锥 → on/off 仅 checkbox 图标差；③移出 → `zero_instance_count` 1↔0 随 set_transform 翻转，cull-stats 三轮零 mismatch。
- **三模式基线重留**：lambert/unlit/normal 三次进程（`ASH_RENDER_MODE`），indirect 路径渲染正确（unlit albedo 直出、normal 法线可视化），各轮零 VUID、WM_CLOSE 优雅退出。
- **负例**：空场（despawn 全部 primitive → commands=0、draw_calls=0、UI 存活不 crash）；单对象；despawn 后槽位复用（retired→graveyard→free list 闭环，旧命令不串）；resize ×2（命令环/在场环与 swapchain 生命周期共存）；拆 Device 排空（teardown 序完整，`device_wait_idle` 先行）。
- **回归矩阵**：4.x 增量链（稳态零盘点零上传、槽位闭环 retired_total 精确 +1）、5.2 cull-stats 对照（零 mismatch ×3）、3.5 三模式、零 VUID ×4 进程、WM_CLOSE exit 0（显式 ExitCode=0 采集 + 优雅退出日志 ×3）、clippy 全净、库测试 11/11（+2：命令布局镜像、push 形状）。

## 7. 钉子

1. **屏障形状两段拼**：标记消费的预置屏障（5.2）+ 命令消费的 `DRAW_INDIRECT/INDIRECT_COMMAND_READ` 屏障（本段）——indirect 的读者不是 shader stage，屏障 dst 必须开到 `DRAW_INDIRECT` 阶段，这是与"屏障 dst 开到读方 shader stage"惯例不同的一条。
2. **firstInstance 语义**：Vulkan `InstanceIndex` 从 firstInstance 起算（与 GLSL gl_InstanceID 不同），naga 把 WGSL `@builtin(instance_index)` 直映 InstanceIndex——instanceCount=1 时 `instance_index == firstInstance` 逐位成立，是 push 退役的映射前提。
3. **PS 采退出码的老坑复踩**：`ProcessStartInfo` 带 `RedirectStandardOutput` 会因日志写满管道缓冲堵死消息泵（WM_CLOSE 后超时）——采退出码用 `UseShellExecute=true`（记忆钉"管道重定向堵死消息泵用文件"的变体：重定向到不读的管道同样堵）。
4. **`enabled_features` 是 DeviceCreateInfo 的独立字段**：此前"未传 base features 全 0"的状态在 ash 里无声合法——multi_draw_indirect 这类 1.0 时代位的启用面第一次被本工程触碰（此前全部走 vk12/vk13 聚合结构），就绪日志把 base 位启用状态并入了 features 清单。
