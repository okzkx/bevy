## 1. 逐任务实录

### 5.1.1 数据结构定案与实现

新增 `vulkan/instance_table.rs`（`InstanceTables` 资源）：

- **对象表**：`BufferRole::DeviceStorage`（新角色：STORAGE|TRANSFER_DST|SRC，DEVICE_LOCAL 硬契约），固定容量 131072 槽（覆盖 10 万档）× 48B = 6MB；CONCURRENT 双族共享（transfer 写 graphics 读，与顶点/索引池同款定案）。记录 = 范围三参数 + 材质槽号 + 局部包围盒（`pack_object_record` 手工排布 + `ObjectRecordLayout` 静态断言镜像）。
- **模型环**：HOST_VISIBLE（复用 `BufferRole::Storage`）× MAX_FRAMES_IN_FLIGHT，131072 × 64B/帧槽。
- **材质环**：HOST_VISIBLE × 帧槽，65536 材质槽 × 32B。
- **set2**：三条只读 storage binding（stage 超集含 COMPUTE，5.2 备用），自建 pool（不占 UAB pool），每帧槽一套，**描述符 init 一次写入永不更新**（buffer 固定容量不重建）。失败路径逐段回收（布局→池的逆序，全有或全无）。
- **实例槽**：bump + free list（first-fit），回收经停尸房（`drain_graveyard` 等帧侧等待）；**材质槽 bump-only 不回收**（量级 = 唯一材质数，泄漏有界；材质 Removed 无驻留内容不进回收账——4.2/4.4 口径一致）。

接线：init 链在 BindlessTables 之后建表（`InstanceTables::new(device, contract, sharing_families)`），`GraphicsPipeline::new` 增 set2 参数；teardown 在管线之后、Uploader 之前拆表（layout 借用 set2 layout）。

**槽位账的归属**：`Entity→instance_slot` 挂账本行（`InstanceRow.instance_slot`）——账本保持"零 Vulkan 代码"，槽只是整数；删行/换绑换下的旧槽走 `ledger.freed_slots` 交接账，flush 开头消费进停尸房。

### 5.1.2 包围体

- **源头**：`convert_mesh` 在顶点交错同一遍里扫出局部 AABB（POSITION 逐点 min/max），`ConvertedMesh.local_aabb` → `MeshSlot.local_aabb`（commit/replace 增参，upload_probe 同步适配）——**记录存局部 AABB**，对象记录保持"每槽写一次"不变式（世界 AABB 随 model 变化会失真，不能入库）。
- **保守变换**：`conservative_world_aabb(model, local)` = 8 角点全变换后重收紧，纯函数 + 单测（非均匀缩放 × 旋转样本点内包 / 恒等变换精确 / 打包布局 / 模型环往返）。消费端（GPU compute 变换）归 5.2。

### 5.1.3 增量写入接入

`flush_uploads` 三处扩展：

1. **停尸房段（步骤 0.4）**：`ledger.take_freed_slots()` 逐个 `retire_object_slot` → `drain_graveyard(wait_draws)`——与网格/贴图停尸房同一节拍，共用同一次帧侧等待；排空先于本帧槽位分配（复用槽的旧读者已收口）。
2. **行扫描内**：mesh 腿完成（驻留且不待换）才动槽——记录身份 `(mesh_id, mesh_ticket, material_id)` 与行内 `bound` 比对，不变则免重写（**材质/贴图内容变化不触发换槽**，见 §2 材质环）；变化则分配新槽 → 写 48B 记录进本批 staging（`StagingCopy` 定址 `slot×48`）→ 旧槽进停尸房 → `mark_model_dirty`（两个帧槽的环都要补写）。
3. **计量**：记录字节并入 `upload_bytes_total`（staging 实发），日志分列"对象记录 N 条"；`stats.object_slots/material_slots` 存量字段 + BRP `gpu_tables` 段。

`InstanceRow` 扩展：`instance_slot: Option<u32>`（None = 未驻留成表）、`bound: Option<(AssetId<Mesh>, u64, AssetId<StandardMaterial>)>`（记录身份）。

### 5.1.4 shader 与提交侧

- **shader**（`debug_draw.wgsl`）：push 缩到 4B（`PushParams{instance: u32}`）；set2 三条只读 storage（对象表 / 模型环 `array<mat4x4f>` / 材质环）；VS 读 `objects[instance]` + `models[instance]`，材质槽号经 `@interpolate(flat)` varying 传 FS；FS 读 `materials[material_index]`（base_color/贴图槽）。逐 draw 的 push 字节 = 4B 槽号，参数本体零推送。
- **录制**（`frames.rs`）：`DrawCall{instance, vertex_base, first_index, index_count}`（PushData 退役）；`cmd_push_constants` 推 4B；`cmd_bind_descriptor_sets` 绑三集。
- **DrawList 终态钉明**：**退化为槽位枚举**（`driver/host/drawlist.rs::assemble`）——逐行查实例槽 + 池引脚组 DrawCall，逐对象参数组装职责随 PushData 退役；行级可绘判定与 4.x 语义一致（槽缺/mesh 未驻留/材质缺席 = 暂缓）。
- **双环写入**（`drawlist::write_rings`，`wait_for_slot` 之后、与帧 UBO 同一条 fence 证据）：模型环**增量**（本帧奇偶集的改动行，每改动行两帧写满两个环，静态场景零写入）；材质环**全量**（可绘行的去重材质从容器现读——材质参数/贴图槽变化自动次帧生效，4.2 的材质半边语义由本环吸收，flush 零新增通道）。

## 2. 待决七项落定（计划 §4 逐项钉明）

| 待决项 | 落定 | 理由 |
|---|---|---|
| push 终态 | **4B 实例槽号** | gl_DrawID 要求 draw 序 == 槽序，free list 复用下槽位稀疏不成立；4B 标识已满足判定线 1（"每对象 ≤4B"） |
| 材质表独立 vs 折叠 | **独立材质环，且不 swap** | 计划倾向"独立"兑现；但内容更新不走 swap-on-commit——材质环**每帧全量重写**（量级 = 可绘唯一材质数，头盔 5 个），内容每帧从容器现读，材质/贴图变化自动次帧生效，换槽→引用行重写的链式 churn（10 万实例共享 5 材质时一次贴图变更 = 10 万对象槽重写）被结构性地消灭 |
| mesh 范围 | **副本进对象记录** | GPU 消费者（5.2/5.3）就绪面；CPU 侧 draw args 在 5.1 仍从 MeshSlot 现查（indirect 归 5.3），副本与引脚暂时并存 |
| 实例槽分配 | **free list（停尸房排空后归还）+ bump** | 与 MeshPool 同构；draw 顺序保持账本 BTreeMap Entity 序（槽只是索引），3.5 对照零影响 |
| 包围体表示 | **局部 AABB**（记录）+ `conservative_world_aabb` 纯函数（世界推导归消费端） | 局部 AABB 保住"记录写一次"不变式；世界 AABB 入库会在 model 变化后失真；8 角点保守变换够 5.2 compute 用 |
| 表落位 | **新 set2**（三条只读 storage，自建 pool），set0/set1 不动 | 3.6 冻结边界解冻范围最小化：set0/set1 的 binding 表与 UBO 128B 布局原样，仅新增 set2 + push 缩 4B |
| DrawList 终态 | **退化为槽位枚举** | 全退役不可行（cmd_draw_indexed 的 args 在 5.1 仍需 CPU 侧值；indirect 归 5.3）；枚举器保留行级可绘判定与收账日志 |

**设计过程的结构发现（对计划的重要偏离）**：计划草案曾把 model 列为对象表行字段。施工设计时发现**模型是易变数据**——移动对象 = 原地覆盖记录 = "transfer 写 vs 在飞 draw 读"的规范级 hazard（同步验证层可抓的 buffer hazard，非良性竞态），而 swap-on-commit 每移动一槽会让 free list 常空、`drain_graveyard` 的 wait_draws 每帧全停。落定 = **model 从对象记录拆出到模型环**（帧槽 ×2 的 HOST_VISIBLE buffer，`wait_for_slot` fence 纪律与帧 UBO 同一证据链），对象记录只装跨帧稳定字段——三份存储按"写形状"分家（对象表写一次 / 模型环增量 / 材质环全量），各自 hazard 闭合。

## 3. 钉子

1. **移动一行 ≠ 零工作**：移动驱动模型环写（64B host-visible 直写）+ 账本行改写，不经上传链不发票据——与 4.1"移动零上传"判定线的口径兼容（上传 0、处理数照报）。
2. **材质槽 bump-only 是有界泄漏**：材质 Removed 不回收槽（回收账不收材质，4.2 立的口径）；量级 = 会话期内唯一材质数，与 TABLE_CAPACITY 同级的显式上界（65536），超限报错不截断。
3. **批号跳号是图集批**：run1 日志"上传批次 #2 → #4"——#3 是 overlay 图集整传（独占 Uploader 的另一批），对象记录批次号不连续属正常。
4. **PS 里 `$p.ExitCode` 前必须先 `$null = $p.Handle`**（对已退出进程取 ExitCode 需先持句柄；WaitForExit 之后补碰 Handle 拿到的是 null）——4.4 钉子"先碰 Handle"的补充：先于 WaitForExit。
5. **PowerShell Add-Type 类型不跨调用存活**：每个 `powershell -Command` 是独立会话，Add-Type 的类只活当次——多步窗口操作写进临时 .ps1 脚本执行（本次 resize 回归实录）。
6. **记录身份含 mesh ticket 而非裸身份对**：同 AssetId 内容变化（Modified）票据必换，`(mesh_id, ticket, material_id)` 三元组相等才能判定"记录内容不变"——只比身份对会漏掉同柄内容重传的包围盒/范围更新。
