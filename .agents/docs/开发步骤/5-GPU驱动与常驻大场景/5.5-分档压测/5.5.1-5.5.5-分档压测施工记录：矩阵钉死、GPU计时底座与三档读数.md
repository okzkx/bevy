## 2. 待决六项落定（对计划 §4）

1. **GPU 侧计时手段 = timestamp query**（倾向采纳）：每帧槽一只 query pool、4 采样位（T0 进场后/T1 compute 后/T2 rendering 后/T3 提交前，全 TOP_OF_PIPE），取三区间（compute/graphics/全帧）；队列族 64 有效位、period 1 ns 实测，不支持时降级停用不阻断渲染链。
2. **分位数落点 = 两段式**（倾向采纳）：进程内 PerfLedger 环形账（2048 帧）+ egui 面板/BRP perf_stats 现算分位数 + BRP perf_samples 原始导出供报告期离线汇总。
3. **变更形态定义 = rows 参数化前缀注入**：零变化（off）、少量（100 行/帧）、全动态（rows=在场行数）；静/动比例由 rows 参数承载，本段只跑三档三形态九组（10%/50% 比例档未单独采样——rows 参数化已备，属采集面不属代码面，如实记录）。
4. **相机轨迹 = 固定轨迹回放**（倾向采纳）：BRP set_camera 驱动 yaw 0→90 十步 + 种子/轨迹进条件记录单；10 万档下漫游输入不污染被测工作。
5. **10 万档真机复核 = 通过**：对象槽 100006/131072、命令环 10 万条约 2MB、`maxDrawIndirectCount` u32::MAX（留痕）；`timestampPeriod` 1 ns、timestamp 64 有效位留痕。
6. **5.4 读图遗留补证 = 已顺带完成**（PrintWindow 恢复）：chunk 增删画面 A/B（4 块 1030 命令 → despawn 2 块 518 命令，画面点阵减半 + 面板读数成对）；mip 近景清晰（半径 1.5 软管纹路清晰）；三模式基线重留（lambert/unlit/normal 三帧分化正确）。**mip"远景不闪"半项未关**：静态帧无法判读闪烁，需连拍对照——不承 5.5 判定线责任，记 5.4 施工记录口径的半项遗留。

## 5. 施工钉子（五枚）

1. **QUERY_RESULT_WAIT 对"reset 过但未执行"的查询永久阻塞**（首跑挂死实抓）：GPU 帧计时的可用性保证只能靠 fence（本槽 fence 已等完 = 上轮 timestamp 已写入），不挂 WAIT 旗标；VK_NOT_READY 归"无读数"分支而非失败。
2. **创建期 host reset 需要 hostQueryReset feature 位**（VUID-02665 首跑实抓）——不开 feature 的替代：`recorded` 闸门保证每槽首次取结果必在其首次 record（`cmd_reset_query_pool` 起周期，命令侧 reset 无 feature 要求）之后，"未初始化态不可达"（VUID-09401 同路关闭）。
3. **GPU 区间读数是混合口径**：GPU 区间 = 本槽上轮（两帧前）提交的时间戳，CPU 分段 = 当前帧——稳态同构、逐帧错位两帧，[分档性能记录](分档性能记录：三档压测读数与瓶颈归因.md)如实标注。
4. **BRP 读数的 JSON-RPC 信封**：自定义方法返回 `{jsonrpc,id,result}` 信封，业务字段在 `result` 里——驱动脚本首轮 `census.get("chunks")` 取到顶层空转，清场失效跨档累积 170006 行撞对象表容量 131072 显式报错（**渲染器侧行为正确**：容量耗尽硬校验按设计执法、Tier② 优雅退出零截断；缺陷在驱动脚本，修正为取 `result` 再取字段）。教训：BRP 采集脚本对信封取字段是高频坑（perf-samples 的 total 同踩一次）。
5. **perf-stats 分位数是环窗全量快照**（2048 帧，跨形态混样）——采集口径改为"形态稳定后记 n0、扫掠后记 n1，导出 [n0,n1) 帧段"做每形态权威窗；慢帧档位（GPU-bound ~4 fps）下 2048 窗跨多个形态，切片是唯一纯净口径。
