# 步骤 10：表现与使用体验优化

对应[执行路线图](../学习目标实现步骤.md)。本 README 是步骤索引与材料目录；各段任务面板在段目录 README（开工时立），段施工计划随段立案入段目录。

**目的**：步骤 8 交付完整延迟管线、步骤 9 交付 SCGI 间接漫反射之后，画面侧还缺两块屏幕空间补丁——接触阴影（AO）与场景内镜面反射（SSR）；使用侧则一直靠 BRP 命令与脚本驱动调试 UI。本步补齐这两块画面能力，把三处已实测的帧时间浪费收干净，并把 egui 工具窗口整理成可持续使用的调试面板，让后续内容与压测有"看得准、调得动"的现场。

**一句话说明**：本步先拿回两处确定浪费（10.1：光线求交调试图按需 + `rings` 分段打点），再在现有延迟管线与 SCGI 之上加屏幕空间环境光遮蔽（10.2）与屏幕空间反射（10.3），然后把阴影命令环与档位收干净（10.4），最后把 egui 工具窗口整理成可持久化、可快捷键、可 A/B 的调试面板（10.5）；本步不重写渲染管线、不做光追 AO/反射、不改 BRP 方法名与参数语义，也不承担 9.11 的 SCGI P1 收尾。

**当前状态：⬜ 已立案（2026-11-26 用户增补），五段均未开工**；10.1 段计划已于 2026-11-27 细化（纯文档，未开工）。范围和段拆解见[施工计划：表现与使用体验优化三段拆解](施工计划：表现与使用体验优化三段拆解.md)（2026-11-26 立案，含 24 条立案期核实、五段边界与判定线草案、11 项待决记录，其中 D9/D11 已定）。执行顺序即段号顺序 **10.1 → 10.2 → 10.3 → 10.4 → 10.5**（2026-11-26 用户授权调整并按执行顺序重排段号，映射见主计划头注，理由见主计划 §3），每段独立分支与判定线；与 9.11（SCGI P1 修复）相互独立。

## 判定线与验收口径

- 段级判定线草案见主计划 §2 各段（10.1 四条、10.2 七条、10.3 七条、10.4 三条、10.5 八条），其中 10.1 分门控、rings、回归、契约四组；施工时"先写后测"，读数与读图留档到段 README 与施工记录。
- 通用口径沿用[路线图 §统一验收与性能口径](../学习目标实现步骤.md)：计数分开、条件固定、指标成组、预算先写后测、A/B 控制变量。
- 画面类判定必须配读图：`frame_dump` 导 PPM（linear sRGB）→ sRGB 编码 → 当前会话模型读图，结论分"通过 / 部分 / 不通过"。
- 每段收尾要求：目标 crate clippy 全净、零 VUID/VK-ERROR、无新依赖、判定线逐条有证据。

## 边界（步骤级）

- 不做光追 AO、光追反射、平面反射、SSGI 与外置条目 19 的屏幕空间 GI（条目 19 是 SSGI，不是本步 10.3）。
- 不做 TAA 时域抗锯齿：10.2 只做空间去噪，时域累积若需要另立段。
- 不改 SCGI 缓存与采样链（9.11 的范围）、不改 G-buffer 布局、不改透明层（Clustered Forward）的既有行为。
- 不改 BRP 方法名与参数语义；新方法只做增量（`ssao_set`/`ssr_set`、`ray_tracing_set.debug`）。
- 不为对齐 Unity/商业引擎牺牲 GPU-driven 与 6 GB 预算（沿用九段边界）。
- 10.1 与 10.4 只动 dispatch 门控、阴影命令环、BRP 增量字段与 perf 打点，不改渲染结果与画质档位；任何提速必须保留"关回基线"路径，且不碰 SCGI 采样与缓存（9.11）。
