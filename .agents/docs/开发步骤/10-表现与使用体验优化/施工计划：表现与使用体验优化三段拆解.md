## 1. 为什么现在做

- **画面侧**：9.10 的现场评价把"没有接触阴影、没有场景内镜面反射"列为两条最明显的观感缺口；前者让墙角/柱础发飘，后者让金属、湿地面只能靠 IBL 环境图，画面"贴纸感"重。二者都是屏幕空间问题，不需要动 SCGI 缓存与射线链。
- **纪律侧**：9.8 的局限自检已经把这些写成"已知接受"；10.3 落地后该条从"无 SSR"收窄为"屏幕空间、单次命中、离屏不可见"，局限表述更准确，也便于后续判断是否值得上光追反射。
- **使用侧**：egui 工具窗口是日常调试的唯一入口（10 页、单页最大 742 行），却每次重启都回到默认位置、无快捷键、页内参数无复位。10.2/10.3 还会再加开关与读数，若不先整理信息架构，面板只会更挤。
- **与 9.11 独立**：9.11 是 SCGI 采样链的 P1 修复（自发光/心跳/锥采样/阴影射线），本步不碰 `estimation.wgsl` 的采样语义，也不改缓存池布局，两线可并行。

### 2.2 10.2 SSAO（屏幕空间环境光遮蔽）

**段计划**：[施工计划：SSAO](10.2-SSAO/施工计划：SSAO.md)（2026-11-27 立案细化；未开工）。

**一句话说明**：本段用当帧深度与法线做半分辨率屏幕空间环境光遮蔽，把 AO 乘到环境项（IBL/常量环境）上，补足墙角、柱础、拱底的接触阴影；不做光追 AO、不做时域累积、不乘 SCGI。

**范围**

- 新增 SSAO 计算 pass（半分辨率 + 深度感知上采样），shadowing 只依赖当帧 depth/normal。
- 输出单通道 AO 目标，合成 pass 读取后乘到环境项；材质 AO（`matparam.g`）与 SSAO 的组合关系在 §5 D1 拍板。
- BRP：`ash_renderer/ssao_set`（开关 + 半径/强度/样本面）、`ash_renderer/ssao_stats`（gpu 计时与平均 AO 读数）。
- 面板：先在现有 GI 页加一小节控制（10.5 再做页面级整理），保证能手动 A/B。
- 文档：段 README、施工记录、判定线取证与读图。

**边界**

- 不做光追 AO（RT AO 无立项，归外置/后续）、不做 GTAO 多弹射补偿、不做 bent normal 照明弯曲。
- 不做时域累积与 TAA（另立）；只做空间去噪（旋转核 + 深度感知上采样）。
- 透明层（Clustered Forward）不消费 AO；透明保持 8 段现状。
- 不乘 SCGI 辐照度（缓存自带遮挡，双计会让暗部更暗且与 9.10 标定冲突）；不改直射阴影（CSM/PCSS 归步骤 8）。
- 不改 G-buffer 布局（材质 AO 仍写 `matparam.g`），SSAO 只活在合成前的一张贴图里。
- 9.11 的 SCGI P1 不归本段。

**接口与数据流（现状 → 目标）**

```
现状  G-buffer ──► 合成（occlusion = matparam.g，只乘直射）──► HDR ──► Bloom ──► …
目标  G-buffer ──► SSAO(半分辨率) ──► 上采样 ──► 合成（环境项 × AO）──► HDR ──► …
```

**判定线草案（施工时先写后测）**

1. `ssao_set {enabled:false}` 时，与立案基线在同一机位、同一曝光下逐字节一致。
2. 平地/天空 AO ≈ 1（无 halo）：固定机位 AO 均值 ≥ 0.98，且最大暗化为 0。
3. 接触区有效：Sponza 柱础/拱底同一机位，AO 均值 < 0.8 的像素占比 ≥ 5%，读图可见连续阴影带。
4. 上采样无 2×2 块：半分辨率与全分辨率开关对比 diff 的 p99 ≤ 0.05（线性域）。
5. 不破坏既有画面：SCGI 开/关 A/B 的注入方向不变（9.10 锚点复跑，l0_covered_mean 偏差 ≤ 2%）。
6. 性能：`ssao_ms` p50 ≤ 0.3 ms（1600×900、RTX 2060、Release）；帧时间 p50 增量 ≤ 0.5 ms。
7. 零 VUID/VK-ERROR；无新 crate 依赖；clippy 目标 crate 全净。

**风险与备选**

- 半分辨率 + 双边上采样在小尺度细节（柱头雕花）可能糊；备选：半径按视空间自适应、或对 AO 做 3×3 中值。
- 视空间半径需要世界尺度换算（`radius_m / 视距`），否则近处过黑、远处失效；施工时用固定机位标定读数。

### 2.3 10.3 SSR（屏幕空间反射）

**一句话说明**：本段在合成后的 HDR 上做屏幕空间光线步进，为光滑金属/湿地面补当帧场景内反射，命中失败回退 IBL；不做光追反射、不做平面反射、不做多次弹射。

**范围**

- 新增 HDR 场景色拷贝（合成后一次全屏 copy）与 SSR pass（半分辨率步进 + 全分辨率合成）。
- 眼空间 ray march：线性步进 + 二分细化、厚度判据、屏幕边缘 fade、粗糙度/金属度门控、反射强度参数。
- 命中颜色取自同帧拷贝；命中失败像素保持 IBL 高光，不做"黑反射"。
- BRP：`ash_renderer/ssr_set`（开关、步数、厚度、粗糙度阈值、强度）、`ash_renderer/ssr_stats`（`ssr_ms`、命中率、平均步数）。
- 面板：先挂到现有天空/IBL 页或管线页（10.5 再整理）；文档同 10.2。

**边界**

- 不做光追反射（RT reflection 另立）、不做平面反射/反射探针、不做 SSGI（外置条目 19）。
- 不做多次弹射；命中点用已着色颜色，不再追踪二次反射。
- 不改善屏幕外信息：边缘 fade 是显式局限，写入段 README 与 9.8 局限自检的订正行。
- 透明层不接 SSR（仍只 IBL）。
- 不改 SCGI 采样与注入；不承担 9.11。
- 第一版不依赖 Hi-Z；只有当 `ssr_ms` 超预算时才评估复用 `visibility/hiz` 金字塔（§5 D4）。

**任务拆解**

| 编号 | 任务 | 交付 |
|---|---|---|
| 10.3.1 | HDR 拷贝通道：合成后 copy 到可采样贴图，屏障与复用关系写清 | `src/render/passes/post/` 或新 `reflection` 模块 |
| 10.3.2 | 步进核心：视空间步长、厚度、命中测试、二分细化、边缘 fade | `shaders/scene/reflection/ssr.wgsl` |
| 10.3.3 | 反射合成：Fresnel/粗糙度权重、与 IBL 高光的混合、强度与门控 | 同上 + 合成端接线 |
| 10.3.4 | BRP/计时/读数：`ssr_set`、`ssr_stats`、`ssr_ms` 查询点 | `render_settings.rs`、`perf.rs` |
| 10.3.5 | 标定场景：BRP 造自发光条 + 光滑地面（`spawn_shape` 已有 emissive 字段）或用现有 glTF 中的金属件 | `.temp/` 脚本 + 留档图 |
| 10.3.6 | 取证与文档：镜面标定、粗糙度门控、边缘 fade、性能、判定线逐条 | 段 README + 施工记录 |

**接口与数据流（目标）**

```
… 合成 ──► HDR ──┬─► copy ──► SSR(半分辨率步进，读 copy+depth+normal+matparam) ──► 反射图
                 └─► SSR 合成（全分辨率，加到 HDR）──► Bloom ──► tonemap ──► …
```

**判定线草案**

1. `ssr_set {enabled:false}` 时与 10.2 收官基线逐字节一致（HDR dump 同口径）。
2. 镜面标定场景：反射像与源几何的屏幕偏移 ≤ 2 px（1600×900），强度与解析预期同量级（±20%）。
3. 粗糙度门控生效：`perceptualRoughness > cutoff` 的表面 SSR 贡献为 0，仅 IBL 高光；无"全屏反射"。
4. 屏幕外/背面：命中失败像素回退 IBL，无拉丝、无黑块；边缘 fade 后带状伪影可解释。
5. 性能：`ssr_ms` p50 ≤ 1.5 ms（1600×900、半分辨率步进、RTX 2060、Release）。
6. 零 VUID/VK-ERROR；无新依赖；透明层画面不变。
7. A/B 图 + 读数留档（含至少 3 个机位与标定场景）。

**风险与备选**

- 屏幕空间反射在掠射角易拉丝；备选：命中置信度权重（深度差/边缘距离）与更强的 fade。
- 同帧 copy 增加一次全屏带宽；若 `ssr_ms` 超预算，退到"上一帧 HDR"（时域滞后、但省 copy），按 §5 D3 拍板。

### 2.4 10.4 阴影减负（命令环压缩 + 质量档位）

**一句话说明**：本段收 `gpu_shadow_ms` 10.4–10.8 ms 的两处浪费——每级联按全量在场行发空命令、远级联 texel 过粗；先做行为等价的命令环压缩，再按 `texel_world` 与读图决定档位，预期 −3～6 ms，且不改级联划分算法、不回退阴影相关判定线。

**立案期实测**（Emerald Square，1600×900，160 帧中位数；脚本 `.temp/9.10/ab_perf.py`，2026-11-26）

| # | 项 | 读数 | 判定 |
|---|---|---|---|
| 1 | 阴影命令环 | `gpu_shadow_ms` p50 10.42–10.78（占 GPU 57%）；每级联录两次 indirect 且都用 `command_count = 2476`，而每级联可见行仅 70 / 403 / 1617 / 2324；级联 1–3 的 MASK 绘制为 0 实例命令 | 确定浪费（命令侧）+ 质量档位可调 |

**范围**

- **10.4.1 阴影命令环压缩**：每级联按实际可见行写 `command_count`；MASK 族只给级联 0 录制（`MASK_SHADOW_CASCADES = 1` 已是这个语义，只是命令没省）。行为等价，预期省下 ~19 800 条空命令的间接绘制开销。
- **10.4.2 阴影减负档位**：在 10.4.1 之后按 §5 D10 拍板择一实施（远级联降 1024² / 级联 4→3 / far 127.5→80 m），并留 `texel_world` 与同机位读图对照。预期 −3～6 ms。
- **10.4.3 取证与文档**：A/B 前后 `shadow_stats`（每级联可见行、`texel_world`、`splits`）与同机位读图，结论三档写进段 README 与施工记录。

**边界**

- 命令环压缩必须先出同机位逐字节 diff；档位变化（`texel_world`）写进段记录，不回退既有 `gi_test` / `gi_estimation_test` / `gi_gather_test` 判定线。
- 不改 `shadow_map.rs` 的级联划分算法（只改分辨率/数量/命令环）；不改 SSAO/SSR（10.2/10.3）、SCGI（9.11）、G-buffer、透明层。
- 不引入新依赖；不为提速牺牲 GPU-driven 提交与 6 GB 预算；每处单改 ≤80 行，超则拆独立段。

**任务拆解**

| 10.4.2 | 阴影档位（D10 拍板后）：分辨率/级联数/far，附 `texel_world` 与读图对照 | `passes/shadow/cascades.rs`、`shadow_map.rs` |

## 6. 验收口径

- 每段判定线"先写后测"；测试手段按[测试规范与方式](../../../rules/测试规范与方式.md)三级选择（BRP 读数优先 → 打 Log 重编译 → 鼠标注入仅无人模式）。
- 计数、条件、指标成组、增长斜率、预算先写后测、等待统计边界、A/B 控制变量按[路线图统一验收与性能口径](../学习目标实现步骤.md)执行。
- 画面类判定必须配读图：`frame_dump` → sRGB 编码 → 当前会话模型读图，结论分"通过 / 部分 / 不通过"三档并写清依据。
- clippy 按目标 crate 全净；不为对齐 Unity 牺牲 GPU-driven 与 6 GB 预算（沿用九段边界）。
- 10.1 与 10.4 以帧时间读数为主要验收、以逐字节/读图 diff 防回退；所有提速必须给"关回基线"路径，且 A/B 用同一机位、同一曝光（`exposure_set {"mode":"manual"}`）。
