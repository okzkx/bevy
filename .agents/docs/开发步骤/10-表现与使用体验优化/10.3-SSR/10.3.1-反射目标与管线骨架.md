# 10.3.1 反射目标族、管线骨架与登记

**目的**：先把「反射图存在哪里、谁写谁读、开机时怎么建、resize 怎么重建」钉死，再谈步进算法。本任务不产生可见画面变化（关档为默认，开档也只是目标与管线就位）。

## 交付
- `ash_renderer/src/render/passes/reflection/targets.rs`：`REFLECTION_FORMAT = HDR_FORMAT`；`REFLECTION_STORAGE_SET_DESC`（b0 `StorageImage`，`COMPUTE`）、`REFLECTION_SAMPLE_SET_DESC`（b0 反射图、b1 `hdr_copy`，均 `FRAGMENT`）；`ReflectionTargets { half: Vec<ColorTarget>, copy: Vec<ColorTarget>, … }` 与 `new/ensure/storage_set/sample_set/copy_target/half_extent/full_extent/mark_written/written_slot`。
- `ash_renderer/src/render/passes/reflection/mod.rs`：`ReflectionSettings { enabled, steps, max_distance_m, thickness_m, roughness_cutoff, edge_fade, intensity }`，默认 `{ false, 64, 16.0, 0.35, 0.35, 0.10, 1.0 }`。
- `ash_renderer/src/render/core/target/color.rs`：新增 `new_storage_sampled`（本段唯一核心小改动：既有 `new` 不给 storage、`new_storage` 不作附件，反射图要「compute 写 + 片元读 + 回读」三用途）。
- `ash_renderer/src/render/layout_registry.rs`：`ALL_PIPELINES` +3、`ALL_SETS` +2（52/30 → **55/32**）。
- 接线：`driver/host/init.rs`（建目标、登记两组布局、建三条管线、插入五个资源）、`driver/host/frame/resize_gate.rs`（`ensure` + 「反射目标重建失败，渲染链无法继续」）、`driver/host/frame/input.rs`、`render/mod.rs` re-export。

## 关键口径
- 尺寸分四级里的 **resize 级**：布局与描述符池在 `new` 建一次，`ensure` 只换 image/view 并重写同一批集（沿用 10.2 的教训，避免布局悬空 VUID）。
- 反射图为半分辨率（`800×450`），全分辨率 `hdr_copy` 为 `1600×900×8 B ≈ 11.5 MB`。
- 每槽一份（与 G-buffer 槽一一对应），提交成功后 `mark_written(slot)`，供 `ssr_stats` 回读。

## 验证
- `cargo build --release -p ash_renderer --bin ash_renderer` 通过；`BRP ash_renderer/layout_contract` = **55 管线 / 32 set**，三条新管线与两个新集的数据形状符合预期。
- 启动、开关、连续回读期间日志零 VUID（`grep -ci 'vuid\|VK_ERROR'` = 0）。
