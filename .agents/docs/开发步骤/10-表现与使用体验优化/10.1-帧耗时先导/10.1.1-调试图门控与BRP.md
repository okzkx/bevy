# 10.1.1 调试图门控与 BRP

> 施工日期：2026-11-27；状态：✅ 完成（随 10.1 收官）。
> 依据：[施工计划：帧耗时先导](施工计划：帧耗时先导.md) §1 R1/R2、§2 10.1.1。

**一句话**：把“只要 TLAS 有实例就每帧全屏跑”的调试图改成显式 `debug` 门控（默认关），并给 `ray_tracing_set` / `ray_tracing_stats` / `ray_tracing_dump` 补齐开关与可观测字段；不自动跨帧等待，不改 `enabled` 的默认语义。

## 实际改动

| 文件 | 改动 | 现锚点 |
|---|---|---|
| `ash_renderer/src/render/ray_tracing/mod.rs` | `RayTracingSettings` 增加 `pub debug: bool`；doc 写明默认 false、只门控调试图 dispatch、TLAS 仍随 `enabled` | 29–38 行 |
| `ash_renderer/src/driver/host/init.rs` | 初始化 `debug: false` | 292–296 行 |
| `ash_renderer/src/driver/host/frame/ray_tracing.rs` | `let debug = (instance_count > 0 && settings.debug).then(...)` | 93–96 行 |
| `ash_renderer/src/remote/features/ray_tracing.rs` | set 参数/返回加 `debug`/`previous_debug`；stats 加 `debug.enabled` 与零值规则；dump 加 debug 拒绝 | 36–65、73–159、173–227 行 |

### `ray_tracing_set`

请求从 `{"enabled": bool, "view"?: 0|1|2}` 扩为：

```json
{"enabled": true, "view": 0, "debug": true}
```

- `debug` 是 `Option<bool>`，缺省保留当前值；旧客户端只传 `enabled`/`view` 时行为不变。
- 返回 `{enabled, previous, view, debug, previous_debug, supported}`；`previous` 仍只表示旧的 `enabled`，`previous_debug` 单独回旧 debug。
- 不新增方法名，`ray_tracing_set` 仍是唯一开关入口。

### `ray_tracing_stats`

`debug` 对象增加 `enabled`，并改为按 `debug_active` 给读数：

```text
debug_active = supported && settings.enabled && settings.debug
```

- `debug_active == false`：`rays = hits = 0`、`hit_rate = 0.0`、`last_rays_ms = 0.0`。
- `last_tlas_ms` 不看 `debug`，只看 `settings.enabled`：TLAS 仍随总开关运行，关调试图后仍能观察 TLAS 成本。
- `enabled` 关时 `last_tlas_ms = 0.0`；`supported` 仍回设备能力，不因关档变 false。

### `ray_tracing_dump`

检查顺序固定为 **view → enabled → debug → targets**：

1. `view` 必须等于当前 `settings.view`；
2. `enabled` 与设备支持必须为真；
3. `debug` 必须为真，否则返回 `INVALID_PARAMS`，文案：
   `调试图未开启——先 ray_tracing_set {"debug":true}，等至少一帧后再 dump`。

`record_debug` 原本就在 `debug == None` 时早退，本次不改它；门控只发生在 `prepare_ray_tracing` 是否构造 `RayDebugDraw`。

## 为什么不做“请求时自动开一帧再恢复”

BRP handler 在 `RemoteLast` 同步执行，`draw_frame` 在 `Last`；同一次 BRP 调用里本帧 draw 已经跑完，请求内再等“下一帧”会阻塞帧循环，也拿不到同一次调用内的新图。因此契约定为：

- `debug` 是显式常驻布尔，默认 false；
- 调用方/脚本先 `ray_tracing_set {"debug":true}`，等至少一帧，再 `ray_tracing_stats` / `ray_tracing_dump`；
- 取证后显式关回；进程重启回到 false，不做持久化。

这与主计划立案时“请求时临时打开并在之后恢复”的措辞有偏差，已在主计划 §2.1、判定线 1 与 D9 行同步说明；实现理由以本节为准。

## 遗留

- `debug` 不持久化、不写配置；这是有意的：调试图只用于取证，默认画面不承担它的成本。
- `debug` 为 true 但 `enabled=false` 时，stats 仍按 `debug_active` 清零，dump 先在 enabled 检查处拒绝；不额外报错。
- 10.1.2 的 rings 字段与本任务无耦合；两者在同一分支施工，但可独立回退。
