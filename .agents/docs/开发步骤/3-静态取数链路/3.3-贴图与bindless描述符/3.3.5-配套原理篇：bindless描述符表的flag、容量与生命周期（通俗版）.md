# bindless 描述符表原理篇：flag、容量、生命周期与三组易混概念（通俗版）

> 定位：**3.3.5 配套原理篇**。3.3.2~3.3.4 的施工记录与[特性族篇](描述符索引特性族：能力位全景、三层配套与限额双轨.md)是"给已经进过场的人"看的机制记录；本篇把同一套机制**从零重讲一遍**，一个比喻贯穿到底，每处给出比喻与实现的对应。施工实证（钉号、探针、VUID）不重复展开，出处一律指向[施工记录](3.3.2-3.3.4-描述符与槽位：特性解禁、常驻描述符表与发布链路.md)。
> 读者假设：知道"贴图最终放在显存里、shader 要去显存取它"，其余概念从零立。

## 1. 先立问题：没有这张表之前，GPU 怎么"找到"一张贴图

传统绑定（教科书默认路线）的形状是：CPU 对每个 draw 说"这次画这个网格，用 3 号贴图配 2 号采样器"——`vkCmdBindDescriptorSets` 换一次集合。画 100 个不同的东西就要换 100 次，每次都是一次"重新布置工作台"。

**bindless 的判定线一句话：把"用哪张贴图"的决定权，从"绑定状态"（CPU 每次布置）搬进"数据"（shader 拿到的索引号）。** 工作台整帧布置一次，之后画什么、用几号贴图，全部写在数据里随 draw 走。

这就是"常驻描述符表"：一张**常驻在 GPU、整帧不换**的大表，里面一格格放"资源引用"。

## 2. 比喻基座：一个"常驻取货柜"

| 比喻 | 实现 | 补充 |
|---|---|---|
| 快递柜（1024 格，建成就不动） | `BindlessTables`（vulkan/descriptors.rs），启动时一次建成 | 与 App 同寿，退出整体拆 |
| 格子里放的"取货凭证" | set0 b0：SAMPLED_IMAGE 描述符 × 1024（指向某张 VkImage） | 放进去 = vkUpdateDescriptorSets 写一个槽 |
| 格子编号 | 槽号（free list 分配，publish 返回） | 存进驻留账本（ImageCache/MeshPool 的行） |
| "这单已放入柜子" | publish：上传批次**提交成功后**登记 | 失败不留账本行 |
| 你对柜子说"拿 7 号格" | shader 里 `texture_array[7]`——索引是数据 | 7 号写在哪？push constant 里的两个 u32 |
| 柜门整帧开一次 | set0 整帧只绑一次 | 柜内换货、补货，无需再开门 |
| 同款柜子里的另一格 | set0 b1：SAMPLER × 1024（采样器数组） | 采样器=滤波/寻址等功能参数，15 张贴图实测只收敛到 2 种配方 |

记两句话就够：**"群退化成一个"（set0 整帧绑一次）、"材质退化成两个 u32"（纹理槽号 + 采样器槽号进 push）**。

## 3. 那几个吓人的英文 flag，各自在防什么

创建这张表时 capability/feature/pool 要打一串旗标，逐个翻译成"它在防什么/允许什么"：

- **`shader_sampled_image_array_non_uniform_indexing`（非均匀索引）**：GPU 的 shader 是"一批线程齐步走"的模型。没有这个位，数组的下标默认要求整批一致（uniform）——像全队只能拿同一个柜格号。我们让每个三角形各拿各的槽号，这就是 non-uniform 的意思；它把"逐实例不同索引"合法化，代价是驱动不能再按"整批同槽"做激进优化。
- **`descriptor_binding_update_after_bind`（UAB）**：默认纪律是"集合一旦绑给正在跑的管线，内容冻结"。UAB 把纪律放宽为**绑着也允许写**——贴图到货一批就补一批，不用等帧结束。它同时带来限额双轨和时序责任（见 §4.2）。
- **`descriptor_binding_partially_bound`（部分绑定）**：声明"这个数组允许有一部分格子是空的，绑照样绑、用照样用"。我们的表 1024 格启动时只占 0 号一格——没有这个 flag，这个形状直接非法。⚠ 但"允许空"只对"没被读到的空格"成立：**读空格 = 未定义行为，验证层不保证能抓**（探针实测读错空槽读回"全对"且零告警——所以槽位只认 publish 的返回值，不心算）。
- **三层配套，缺一即拒**：上面这些不是各管各的——shader 层要 capability（`RuntimeDescriptorArray`，本项目的由 build.rs 补丁器插进 SPIR-V）、设备层要 feature 位、pool 要 `UPDATE_AFTER_BIND` 旗标，**VUID-08740 在创建管线布局时执法"三层说的是同一件事"**；VUID-03000 再钉一层"带 UAB 的 layout 必须配 UPDATE_AFTER_BIND_POOL 的 pool"。
- 记忆锚：**能力类 flag 决定"能不能表达"（纯表达力），契约类 flag（UAB/PARTIALLY_BOUND）决定"放宽哪条时序纪律"（安全责任从驱动转给应用）**。

## 4. 三组最容易混的成对概念（本篇核心）

### 4.1 "支持"≠"启用"——体检合格 ≠ 报了这门课

- **支持（supported）**：问硬件"有没有这个能力"，走 Features2/扩展查询，答案是能力清单。
- **启用（enabled）**：`vkCreateDevice` 时**显式声明**要开。不声明，能力再强也是零——用了就在管线创建时被 VUID 拒。
- 本项目落点：五位硬校验（1 个总开关 `descriptor_indexing` + 4 个分位），缺一 Init 直接报错出局，不建降级回退渲染器（立案原话）。但"不启用≠不查"——20 个分位的支持值照样全量进启动日志，为后续段留证据（D1 惯例）。
- 第二层坑：支持了还要**限额够**。UAB 轨的限额（每阶段能挂多少张图）**不在普通 `Limits` 结构里**，在 properties2 扩展结构 `PhysicalDeviceDescriptorIndexingProperties` 里——"查不到就换结构，不是不存在"。

### 4.2 "补新槽"≠"覆盖旧槽"——UAB 允许写的两种方式，安全等级天差地别

- **补新槽**：往一个**从未在飞使用**的空格放新凭证。正在跑的 draw 根本不知道这个格子的存在，结构上绝无交叠——**这是生产链唯一的写法**（`publish()` 只写新槽，free list 保证拿到的槽不在飞）。
- **覆盖旧槽**：把 7 号格内容换成别的。这是 UAB 的存在意义（资源更新），但"正在读 7 号格的 draw"会当场读到新内容——时序安全从驱动转给应用：同格式可换、或等旧读者全部完成。**验证层对这类在飞改写不保证执法**。
- 本项目落点：M2 只补不覆盖；覆盖语义由探针组 C 实证过（update-after-bind 改写读回成立），生产侧留给步骤 4 的资源更新路径。释放入口（retire）带三条前置契约（等票据/共享句柄/无交叠），就是为将来"安全地覆盖/回收"立的规矩。

### 4.3 "上传完成"≠"最后使用完成"——两个"完成"，管两件不同的事

- **上传完成**＝**搬运**完成：拷贝进显存的那一跳做完，凭"票据"（timeline 信号量到值）确认。此时柜子里的凭证指向的内容**才真正可采样**。
- **最后使用完成**＝**消费**收尾：这个槽最后一次被 GPU 使用（被某个 draw 采样）的那条命令也执行完了。它是**淘汰/回收**的前提——想复用/释放一个槽，先等这个（retire 契约第一条）。
- 由此得出全篇最重要的钉子：**进表 ≠ 可采样**。登记进柜子（描述符写入）只是"凭证放进去了"，内容可能还在路上——两个相隔一段 GPU 拷贝时间的时刻，**槽位有效不等于内容就绪**。消费侧的解法是票据信号量挂进图形提交的 wait 列表（"用新资源前有完成依赖"，3.4 接线）。
- 一句话版本：**外卖放进柜格 ≠ 外卖已到柜格 ≠ 你吃完可以把盒子扔了。**

## 5. 容量与生命周期

- **容量 1024 的依据**：UAB 轨五项限额实测全满足（每阶段/每 set 的 sampledImages 与 samplers 各 1048576、全池总额 4294967295；本表 1024×2 + 每帧 UBO×2 = 2050 描述符）。对账不过 = 显式报错，**不静默截断**。
- **"无界"与"容量"是两个词**：WGSL 里数组不写长度（shader 观感无界）；布局账本里 `descriptor_count = 1024`（容量是簿记数字）。前者是观感、后者是契约。
- **生命周期**：表与 App 同寿——启动建一次（只有 fallback 白图占 0 号）→ 贴图随资产到货流式进表 → 消费整帧绑一次、逐 draw 推编号 → 退出整体拆除。中途**没有**"逐个销毁"这件事：VUID-00312 说无 FREE 位的 pool 只能整体回收（生产表的 Drop 即整体销毁）。
- **槽位循环**：free list = bump 游标 + 回收栈（分配取回收栈顶，栈空取 bump）。回收（retire）运行期不调用，运行时淘汰归步骤 4。
- **fallback 槽 0**：1×1 白图常驻 0 号——"东西没到货先画白"的兜底格；采样器槽 0 与真实贴图共享（去重的自然结果：采样器是功能参数，不是贴图）。

## 6. 误区速查表

| 误区 | 实际 | 出处 |
|---|---|---|
| "feature 查到 true 就能随便用" | 不启用就用 = 管线创建被拒；支持≠启用≠限额够 | VUID-08740 / 特性族篇 §2 |
| "集合绑了就冻结，什么都改不了" | UAB 允许绑着写；但只有"补新槽"结构安全，"覆盖旧槽"时序责任在应用 | 施工记录 §3 |
| "空格子读了会报错" | 读空槽 = UB，验证层不保证抓（实测读回"全对"零告警） | 探针组 B；槽位以 publish 返回值为准 |
| "限额在 Limits 里查" | UAB 轨限额在 properties2 专属结构 | `PhysicalDeviceDescriptorIndexingProperties` |
| "进表了就能采样" | 进表≠可采样，等票据（上传完成）| 票据 @ALL_COMMANDS |
| "槽用完 free 掉即可" | 无 FREE 位 pool 只能整体回收 | VUID-00312 |
| "WGSL 无界数组 = 随便多大" | 无界是观感，容量是布局账本（1024 定案） | §5；限额对账 |
