## §1 ppp 双域订正——本段唯一的真 bug

> **⚠ 本节结论已被 §7 推翻**：tessellate 顶点其实是 points 域，"物理像素订正"才是真 bug 的引入点。本节原文保留作教训存档，勿按此施工。

**判定线：tessellate 的顶点是物理像素（points × ppp），push 的 screen_size 必须与它同域。**

机制：`ctx.tessellate(shapes, pixels_per_point)` 按调用方给的 ppp 把 points 换算到像素再出顶点——ppp 1.25 下顶点已经是 ×1.25 的物理坐标；顶点着色器 `pos * 2.0 / push.screen_size - 1.0` 里 screen_size 若给逻辑 points（1280×720），NDC 就再乘一次 1.25，UI 整体 ×ppp²（1.5625 倍）放大并越界。计划 §3.6 写的“screen_size（逻辑点，顶点 pos 同域）”前提错在“顶点 pos 是逻辑点”——同域没错，错的是域的认定。

症状链（当时为何难定位）：UI 画面本身“能看”（放大但完整、文字清晰），截图对账才发现 egui 声明的窗口矩形 [12,12]..[352,205]pt 与实测渲染位置对不上（标题绘制在 image (210..300, 63..90) ≈ ×1.56）；点击计算从渲染图反推坐标，全部落在 egui 命中测试的 points 域之外——**点击失灵是渲染域错位的下游症状，输入桥无辜**。此前 3.7.1“输入桥已证可用”的旧结论即由此误判，已在本段撤回重证。

修复：`UiPaint::screen_px`（物理像素，`vulkan/overlay_pipeline.rs`）贯穿 `paint_overlay` 产数据 → `frames.rs` 取用 → `pack_ui_push` 写 16B；scissor 本就按物理像素（`scissor_pixels` 以 `screen_px` 收参），修复后顶点/边界/push 三处同域。`EguiFrame::screen_points` 保留 points 域（egui 的屏幕域，RawInput screen_rect 同源）——**两个域都活着，各喂各的消费者**。

防复发句式：见到“UI 整体等比放大且比例 ≈ ppp 或 ppp²”，先查 push 常量与顶点域是否同域；见“点击命中测试错位”，先对账渲染域（拿 egui 声明 rect 对照实测渲染 rect），再查输入。

## §2 输入排查链（五个根因，按发现顺序）

点击验证从全灭到全通的排查链，每环都是独立钉子：

1. **取景遮挡**：PrintWindow 对被前台全屏应用遮挡的窗口照样出图（内容冻结假象）——既有钉子（3.2 方法论），回归用按窗口句柄抓图天然规避。
2. **标题栏偏移**：PrintWindow 的 image 空间含 30.4 逻辑像素标题栏——image y − 30.4 = 客户区逻辑 y，image x = 客户区逻辑 x；物理 = 逻辑 × 1.25。所有“图上坐标 → 点击坐标”换算都要过这一关。
3. **WM_MOUSELEAVE 清指针**：posted WM_MOUSEMOVE 触发 winit Enter → `TrackMouseEvent(TME_LEAVE)`，而真实光标在窗外，系统同帧回投 WM_MOUSELEAVE → 输入桥 `pointer_pos = None` → 同帧按钮事件被 `if let Some(pos)` 整条丢弃。**posted 点击与“光标在窗外”结构性互斥**——不是 bug，是 leave 语义的正确行为。
4. **DPI 虚拟化 posted 消息**：DPI-unaware 进程 PostMessage 的 lparam 被系统按接收方 DPI ×1.25、bevy_winit 又 ÷scale_factor——两跳抵消，posted 坐标“原样”进事件（实测 posted (500,600) → 日志 (500,601)）。结论：**输入桥吃逻辑域本来就是对的**，真实用户输入不受影响（真输入不走 DPI 虚拟化）。
5. **渲染 ×ppp² 双重放大**（当时的"根因"认定）：§1——**此环已被 §7 推翻**：当时测得的"×1.56"与"点击错位"是 DPI 不感知测量通道的假象（量与注入两把虚拟尺子互相抵消），渲染侧其实只有 §7 的一重域错。前四环排查方法论仍然有效。

工具论结论：注入点击的可靠路径 = **真实输入**（SetCursorPos 入位 → 回读实际光标做框内校验 → `mouse_event` LEFTDOWN/UP → 复位），posted 消息只适合无指针语义的命令（WM_CLOSE、WM_SYSCOMMAND）。附带经验：机器上有真实用户在用，注入与用户鼠标会互相干扰（漂移入框校验可容、同帧竞争重试即可）；373i 的 i5 帧模式被外部真实输入切回 lambert 即其例——UI 被真人点动，本身就是可交互的又一实证（373j 对照组证明最小化/还原不重置状态，故归因外部输入而非代码路径）。

5. **bevy 系统参数上限 16**：`run_egui_pass` 逐项声明参数到顶（16 个），vulkan 侧统计收拢成 `RendererStats`（SystemParam 组）才放得下——bevy 的系统参数元组上限 16 是硬约束，收拢组是标准解法。

另记一段内教训：**本仓库禁 `cargo fmt -p ash_renderer`**——手工排版的注释对齐/表格会被整体重排（本段内误触一次，`git checkout` 还原）；格式纪律靠人工对齐既有风格 + clippy。

## §7 订正：tessellate 顶点域与点击偏移真因（2026-10-08 晚，用户实测触发）

**判定线（现行有效）：`ctx.tessellate(shapes, ppp)` 输出顶点在 POINTS 域——ppp 不缩放顶点位置；push 的 screen_size 必须同 points 域 = 物理尺寸 ÷ ppp。**

触发：用户报告"鼠标点击要在按钮下方才点得到，之前某个版本能正确点击"。复查三重证据定案：

1. **epaint tessellator 源码通读**（egui/epaint 0.36.2）：ppp 只进三处——字形栅格化密度（galley ppp 不匹配才重栅格）、像素栅格取整（round_to_pixels）、圆盘半径缩放；顶点位置**从不乘 ppp**。
2. **egui-wgpu 0.36.2 官方渲染器**（crates/egui-wgpu/src/renderer.rs）：shader uniform 字段名即 `screen_size_in_points`，取值 `size_in_pixels / pixels_per_point`（ScreenDescriptor::screen_size_in_points）。
3. **像素实测**（DPI 感知工具链）：声明 [700..800×300..350]pt 的探针色块——物理域 push（订正前 HEAD）画在 (700,300) 尺寸 100×50（=pt 原样）；points 域 push（修复后）画在 (875,375) 尺寸 125×62.5（=pt×1.25 恰确）。注入点击画出来的 unlit 按钮中心 → 模式切换成功；用户真实鼠标同窗点击同样命中。

三版本演进账（git 钉死）：

| 版本 | push 值 | UI 绘制 | 命中区 | 结果 |
|---|---|---|---|---|
| 3.7.3 首版（005fea031^，`screen_points`） | 1280×720 points | pt×1.25 ✓ | pt×1.25 | **正确**——用户记忆里"能正确点击的某个版本"即此 |
| 3.7.3 定稿（1a233a3ad，`screen_px`） | 1600×900 物理 | pt×1.0（×0.8 缩小锚左上） | pt×1.25 | **用户实测 bug**：须点画面的右下 ×1.25 处 |
| 本订正（`screen_pt` = extent ÷ ppp） | 1280×720 points | pt×1.25 ✓ | pt×1.25 | 正确，且尺寸基准换实测 extent（更诚实） |

§1 的"×ppp² 双重放大"从何而来：当时整套测量（PrintWindow 尺寸解读 + SetCursorPos 注入点击）跑在 **DPI 不感知进程**里——GetClientRect/SetCursorPos/PrintWindow 全被系统虚拟化 ÷1.25，两把虚拟尺子互相抵消，注入点击"看似命中"、尺寸对账"看似 ×1.56"——假阳性链一路把首版的正确实现"订正"成了错的。**首版提交信息里的"×ppp² 双重放大、点击全部错位"是不成立的误诊**（提交历史不重写，以本节为准）；用户"之前版本能点击"的体感与此互证。§2 的输入排查五环中 1~4（遮挡/标题栏偏移/WM_MOUSELEAVE/posted DPI 虚拟化）作为注入方法论仍然有效，仅第 5 环的渲染侧归因作废。

修复内容（本订正的代码面）：`UiPaint::screen_px` → **`screen_pt`**（`vulkan/overlay_pipeline.rs`），取值 `swapchain extent / frame.pixels_per_point`（`overlay/paint.rs` 组装）；`frames.rs` pack 调用点随真改名；`overlay_draw.wgsl` 与模块头三处失真注释订正（"tessellate 已按 ppp 换算"→"ppp 只进字形栅格化/取整/圆半径，换算是渲染目标职责"）。scissor 保持 clip×ppp 物理域（该半边本来就对）。防复发句式更新：**UI 等比 ×ppp 缩小且锚左上 + 点击要偏右下才中 → push 尺寸域与顶点域不同域；egui 顶点域问题的权威判据 = epaint tessellator + egui-wgpu uniform 字段名，不是推断**。

回归（订正后全量，探针 build + 干净 build 双轮）：clippy 全净、零 VUID（含拆 Device）、3.5 判定线零回退（primitive 6/6、顶点 55392/索引 284166、材质 6、Image 17）、resize×3 域探针跟随新 extent、最小化/还原闸门正常、WM_CLOSE exit 0、干净 build 视觉验证（当前模型读图，按规则文件）：面板文字尺寸/位置正常、头盔完整、探针色块清零——**通过**（选中态显示 unlit 为用户实测期间真实点击所致，非渲染异常）。视觉验证规则同日修订：deepseek-flash 外部路线退役（当日连续 503），改当前模型直接读图。
