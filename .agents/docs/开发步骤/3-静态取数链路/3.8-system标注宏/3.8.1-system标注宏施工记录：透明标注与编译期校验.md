## §1 设计定案

**宏形状：透明 attribute 宏。** 收下函数 → 语法级校验 → 原 token 吐回。不生成包装对象、不注册清单、不改调用点。运行时与编译期产物均为零（除 parse 一次 token 流）。

校验只钉**语法铁律**（宏在编译期可判定、且在任何调用点都恒真的命题）：

1. **只能标注函数**——`ItemFn` / `ImplItemFn` 两条 parse 路径都不成立即拒；
2. **不能带 `self`**——Bevy 的 `System` 无业务 self（`System::run` 没有业务状态位），带 self 的函数永远变不成 system，但编译器要到 `add_systems` 调用点才报 trait 不匹配且信息难读；宏把失败提前到标注点，错误信息直接给出对策（"状态走 Local/Resource"）。

两条**刻意不做**：

- **不做参数白名单校验**——`SystemParam` 是开放集合（可 `#[derive(SystemParam)]` 自定义），白名单必然误伤；参数合法性留给 `add_systems` 调用点的 trait 检查，那里本来就是 Bevy 报签名错误的地方。
- **属性参数位留空但拒绝带参**——`#[system(set = "...")]` 这类写法当前在编译期报"暂不支持参数"。参数位是后期元数据扩展的预留；静默吞掉会变成"看着生效、没人读取"的失真标注。

## §2 落位清单

**`ash_macros/`**（workspace 成员，proc-macro crate）：

- `src/lib.rs`——`#[system]` 本体（约 50 行）：`system_impl` 做校验，`parse_signature` 兼容自由函数与 impl 关联函数两条路径，错误经 `syn::Error::new_spanned` 定位到标注点。
- 依赖锁 lock 现有版本：syn 2.0.119（feature `full`）、quote 1.0.47、proc-macro2 1.0.107，零新增依赖面。

**`ash_macros/compile_fail/`**（workspace 成员，照 `crates/bevy_ecs/compile_fail` 同款基建）：

- `tests/ui.rs` 挂 `compile_fail_utils::test`（`ui_test` 0.30.4）；五负例在 `tests/ui/`，`//~` 注解为判据（常规模式 `ignore_output_conflict`，stderr 以注解为准），BLESS 产物 `.stderr` 随库留档。

## §3 排障实录：ui_test "no artifact found"（钉子）

compile-fail 首跑即翻车：`panic!("no artifact found for ash_macros")`，且 panic 打印的 cargo stdout 里只有一行 `build-finished`——`DependencyBuilder` 的 `cargo build` 一个编译单元都没产。

**根因链**：

1. `DependencyBuilder` 跑 `cargo build --manifest-path Cargo.toml --target-dir <pkg>/target/ui`（独立 target 目录），从 JSON 输出收集 `compiler-artifact` 产物表，再按 compile-fail crate 的 `[dependencies]` 清单查产物；
2. compile-fail crate 只有 `[[test]]`（`harness = false`），**没有任何 lib/bin 构建目标**——`cargo build` 对无目标包不构建任何单元；
3. 但 `bevy_ecs_compile_fail` 同款结构却能过——差异在依赖类型：`bevy_ecs` 是普通 lib，cargo 对无目标包**仍会编译普通 lib 依赖**（实测：bevy 侧编译出 227 个产物文件）；**proc-macro 依赖没有消费者目标时被 cargo 直接跳过**（实测：我方编译 0 个产物）；
4. 产物表为空 → 查 `ash_macros` 产物时 panic。

**修复**：给 compile-fail crate 加占位 `src/lib.rs`（`pub use ash_macros::system;`）——lib 目标给了 cargo 一个消费者，proc-macro 依赖随之进产物表。副作用为零：该 lib 不被任何测试文件引用，仅作构建目标存在。

**顺带钉**：

- `ui_test` rustc 模式以 **edition 2021** 编译测试文件（排障时 rustc 命令实录 `--edition 2021`）——测试文件不能用 2024-only 语法；
- `ui_test` 的 `CommandBuilder::cargo()` 自动追加 `--manifest-path`，手动复现命令时容易漏；
- 注解方向：`//~^` 指上一行、`//~v` 指下一行——attribute 宏的诊断 span 落在属性行（宏收到的 item 不含属性本身），标注需用 `//~v` 放在属性行上方（`attr_args.rs` 用例）。

## §4 边界与顺延

- **闭包系统不标**：`run_if(|messages: ...| ...)` 内联闭包无法标注，也不值得标（就地可见）。
- **属性参数未实现**：`#[system(...)]` 当前恒拒；元数据（调度位、set 归属等）将来长在这个参数位上，属预留设计，不立账。
- **compile-fail 成本**：`DependencyBuilder` 用独立 target 目录，首次构建 syn/quote 全树（数十秒级），之后走缓存；不影响 clippy/宿主构建。
- 宏 crate 文档注释已声明边界（参数白名单不做、校验范围），注释随代码同真的责任落在 `ash_macros/src/lib.rs` 自身。
