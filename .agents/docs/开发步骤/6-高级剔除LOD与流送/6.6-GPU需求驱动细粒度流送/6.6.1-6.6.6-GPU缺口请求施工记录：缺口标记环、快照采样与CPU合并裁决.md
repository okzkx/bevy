## 1. 逐任务落账

### 6.6.1 缺口身份与判定点

- 身份表达钉明（计划待决 1，倾向采纳）：**GPU 写实例槽号位图，CPU 经账本反查**——对象记录不加字段、不建旁路身份表；位图 = 逐槽 u32（bit L = 该槽选中档 L 未驻留），"同身份多实例"在 CPU 组级归并去重。
- 判定执行点钉明（待决 2，倾向采纳）：**build_indirect 查引脚处**（`pick_lod_entry` 前）——"命中且未驻留"的差集在 GPU 执行时现成，缺口只记录不改变绘制（回退链照旧）。
- cull 负责清零（dispatch 覆盖全部槽）+ build_indirect 负责置位（只派在场行）——两段合成"缺口环每帧全量重写"（标记环同款纪律），不在场槽无陈旧缺口。

### 6.6.2 去重、优先级与限额

- 去重结构钉明（待决 3，倾向采纳）：**槽号位图**（标记环先例最近）——每槽每帧一个 store，无原子。
- 限额：位图天然有界（bound × 4B），无溢出形态——判定线 3 的"溢出可恢复"由"载荷恒有界 + 丢失帧自愈"承担（钉明，无溢出计数器）。
- 优先级载荷钉明（待决 5，倾向采纳）：**纯身份位图**（无距离/屏占比权重），CPU 按账本行距离自行排序——"GPU 出优先级意见"（UE 流送优先级小 buffer 完整形）留升级口子。

### 6.6.3 读回环（快照采样）

- **GapSnapshot 资源**：帧起在 fence 纪律内读缺口环（本帧槽 = 两帧前 compute 输出，与档位环诊断同链）采样——tick 挂 Last 在帧提交后，**直读环会与在飞 compute 写竞争，消费口统一走快照**（tick 与 BRP census）。
- cull 关闭时清零段不跑 → host 补零（在场槽由 build_indirect 照常写新鲜值）。
- 频率钉明（待决 4，倾向采纳）：每帧采样、每帧合并（持续信号模型——行在脏集 = 免费幂等续期，无 ACK/无重试协议）；禁 busy wait（5.5 QUERY_RESULT_WAIT 挂死钉子的反面纪律）。

### 6.6.4 CPU 合并裁决

- `gap_mode` 三态（ResidencySettings）：**Off** = 6.5 CPU 预测独走（默认，A/B 对照面）；**GpuOnly** = CPU 期望档预测请求让位（锚/缺口仍供需求——GPU 独走形态）；**Merged** = 双源合并。
- 缺口归并：逐槽位图 → 账本反查行 → LOD 组 → 聚合到基准身份（`gap_asset_ids` 纯函数拆位）；逐档复核驻留（两帧延迟内可能已到货）→ 仍缺的触发行置脏。
- **缺口请求豁免请求半径但保留冷却窗**（钉明）：缺口 = 本帧已命中可见的证据，半径是相机预测口径；冷却窗防抖仍归 CPU。
- 需求位图（LodDemand）与淘汰口径升级为 **merged**（CPU 预测 ∪ GPU 缺口）：缺口点名的档位由此获得 flush 上传通道、且不进淘汰候选——"需求−驻留=缺席集→请求（进）、驻留−需求=无用集→淘汰（出）"的双向差集在合并需求上闭合；淘汰权本身仍在 CPU（判定线 4）。

### 6.6.5 验证通道与压测

## 2. 首钉与诊断实抓

1. **对照口径订正（压测 ①c 实抓）**：lod_census 行宇宙在 floor_anchor 下是缺席行的**子集**（基准缺席但保底在场的行可绘，lod_census 的 CPU 参照需基准槽位而跳过）——"缺口只来自在场行"的正确可测形式 = 缺口槽数 ≤ 命令条数（命令条数 = 在场行数）。结构保证本身由"cull 清零全部槽 + build_indirect 只派在场行"承担。
2. **tick 直读环竞争（设计期钉死）**：tick 挂 Last 在帧提交之后，两帧槽都可能在飞——直读缺口环会与在飞 compute 写竞争。消费口统一收敛到帧起采样的 GapSnapshot（fence 纪律内），tick/BRP 都不碰环。
3. **缺口请求必须进需求位图**（设计期钉死）：缺口点名的档位若不进 LodDemand，flush 的位图过滤会跳过它 → 缺口永远无法被满足（ perpetual 缺口 + 拉锯）。缺口归并进 merged 位图是"CPU 拍板接受缺口"的执行点，不只是请求行置脏。
