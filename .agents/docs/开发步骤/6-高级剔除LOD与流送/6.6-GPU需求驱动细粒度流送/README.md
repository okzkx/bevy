# 6.6 GPU 需求驱动细粒度流送

对应[执行路线图](../../学习目标实现步骤.md)步骤 6 追加段（2026-10-20 用户增补），[段施工计划](施工计划：GPU稀疏缺口请求拆解.md)（2026-10-20 立案，未施工；**前置依赖 6.5 施工收官**）。本 README 是段任务面板与材料目录；任务面板随开工转入。

**目的**：升级时机从纯 CPU 预测改为 GPU 一手证据参与——GPU 每帧真实知道哪些实例被遮挡、选了哪档、哪些引脚缺席，把"命中且未驻留"的差集变成稀疏缺口清单读回，作为 CPU 预载的第三输入源。

**一句话说明**：6.6 让 GPU 在选档/查驻留索引时把本帧命中而未驻留的资产身份写成稀疏缺口清单，去重限额后每隔若干帧经 readback 环跨帧异步读回，CPU 合并缺口与 6.4 预测、显式预载后按预算裁决上传，不当帧等 GPU、延迟期间 6.5 保底持续可画。本段不做外置 VT 页表（仍挂[外置拓展条目 6](../../外置拓展需求.md)），不做 GPU 发起 IO，不做当帧同步等待，缺口清单不驱动淘汰（补货专用，淘汰仍在 CPU）。

**当前状态：✅ 施工收官（2026-10-20 当日立案当日施工，[施工记录](6.6.1-6.6.6-GPU缺口请求施工记录：缺口标记环、快照采样与CPU合并裁决.md)判定线五条全过，[流程导读](GPU缺口请求流程：从查引脚置位到缺口合并裁决的各级账面.md)已入档；并回/推送由用户 merge-chain 指令驱动）。**
