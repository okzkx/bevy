# 4.4.1-4.4.4 回收与热重载施工记录：卸载回收、双停尸房与热重载链

对应[段 README](README.md) 与[施工计划](施工计划：回收与热重载拆解.md)（2026-10-12 立案并当日施工收官，goal/4.4 分支）。体例：每任务四问（面板要求 / 实现原理 / 过程含落点 / 反思），文末判定线总账与钉子清单。计量读数通道 = `tools/brp.py stats` 的 `recycle` 段（4.4.4 新增）。

## 4.4.1 资产卸载读侧与驻留回收

**面板要求**：`AssetEvent::Removed`/`Unused` 从"只计数"到出账；驻留条目出账（mesh 区间 / 贴图显存 / 描述符槽）；failed 集与 pending 联动出账。

**实现原理**：`Removed` = 资产离开容器（最后一个强柄 Drop 的确定性释放）——账本行持强柄（`InstanceRow` 存 `Handle<Mesh>`），能发 Removed 的身份必然无行引用，retire 天然安全。读侧把 Removed 身份记进独立账面 [`AssetRetirements`]（`scene/mechanism/assets/asset_events.rs`），flush_uploads 开头消费出账；`Unused`（引用掉零但资产仍被容器持有）只计数——探针口径。

**过程与落点**：
- `asset_events.rs`：`AssetRetirements` 资源（待回收身份集 + `RecycleStats` 计量）+ 三 reader 的 Removed/Unused 分支（Added 分支见 4.4.3 复活联动）；`Removed` 同时出清 readiness 失败记录（新增 `clear_failure_*`，与 revive 的语义区分：不是"重试放行"而是账面出清）与失效凭据（flush 消费时 `consume_*`）。
- `upload.rs`：步骤 0.5 消费段（**先于脏行盘点**——同帧"卸载又重载同身份"的行要看到驻留已出账，不能被旧条目"驻留命中"误判完成）；`pool.retire`/`image_cache.retire` 出账，区间/旧图进停尸房、槽进待回收账。
- 材质 `Removed` 只出清失败记录（无驻留内容）。

**反思**：retire 幂等（未驻留身份 no-op）——重复 Removed/竞态不误动作；卸载的贴图若其采样器槽仍被同键其他驻留条目共享，槽不回收（`ImageCache::retire` 内重扫驻留条目判定）。

## 4.4.2 在飞安全销毁与槽位复用

**面板要求**：旧资源销毁受"上传票据 ∧ 图形最后使用"双条件保护（契约②）；mesh free list 建立；容量收缩只主张读数。

**实现原理**：三条销毁路径（池区间 / 旧 GpuImage / 描述符槽）**统一排空点**——flush_uploads 步骤 0（贴图停尸房 4.2.3 现成、网格停尸房与槽待回收账 4.4 新增），排空前 `frames.wait_all_inflight()` 等全部帧槽 fence，此刻无在飞 draw 再读旧件，销毁/归还才发生。**描述符槽不能立即复用**：在飞 draw 在 GPU 执行时才读描述符，槽复用 = 在飞 draw 看到新贴图（覆盖）——retire 请求进 `BindlessTables` 的待回收账（`retired_textures/samplers`），排空点才回 free list。

**过程与落点**：
- `pool.rs`：`MeshPool` 加 `graveyard`（待回收区间组）+ `free_vertex/free_index`（可复用空洞）+ `retire/drain_graveyard`；`alloc` 改 first-fit（free 查无才 bump 划新，区间对齐倍数切分保持偏移对齐）；`replace` 的旧区间从"孤儿化"改为进停尸房（4.2 时代注释"回收归 4.4"的兑现）；`RecycleLedger` 读数口（驻留字节现算、退休累计、free/graveyard 当前态）。
- `descriptors.rs`：`retire_texture/retire_sampler` 语义改为"回收请求"（进待回收账不进 free list），新增 `drain_retired_slots` + `retire_sampler_by_slot`（按槽号反查功能键——ImageCache 持驻留条目的槽位绑定，功能键在表内）。
- `images.rs`：`ImageCache::retire`（旧图进现有 graveyard、纹理槽请求回收、采样器槽按"同键最后一张退场"条件请求）。
- 容量收缩：只主张读数（`RecycleLedger.resident_*`），收缩实装留显存压力（计划 §5 倾向兑现——`need = used + extra` 高估安全，free 复用不推进 used 游标，capacity 收敛到"峰值并发需求 × 2"）。

**反思**：排空失败（帧侧等待错）保留停尸房下帧重试，旧件多活一帧无悬空——与 4.2.3 同款容错形状；碎片不合并（first-fit 够用，合并/Slab 升级留显存压力）。

## 4.4.3 热重载链

**面板要求**：file_watcher 开关决策；单资产/WorldAsset 两档重载回归；失败资产修复自动恢复（含上限）。

**实现原理**：`file_watcher` feature 链 = `notify-debouncer-full + watch + multi_threaded`（multi_threaded 本就在 bevy 默认特征面内，Cargo.lock 零新增）；watch 开关 `watch_for_changes_override.unwrap_or(cfg!("watch"))`——开 feature 即默认监听，不改宿主配置。WorldAsset 重载执行底座 = 官方 `WorldAssetSpawner` 的 Modified→unload/reload（despawn+respawn），宿主 `WorldAssetRoot` 走官方 spawner 零新代码。revive 链：`AssetServer::reload` 重走加载链 → `Added` 事件 → 复活。

**过程与落点与一个实抓缺口**：
- `ash_renderer/Cargo.toml`：features 加 `file_watcher`。
- **复活联动缺口（施工实抓，4.3 留口的另一半）**：首轮实测"失败 → 修复 → reload"后资产到容器（arrivals 不涨的镜像面：arrivals 压根不动）——`Added`/`Modified` 事件把身份移出 failed 集（revive 放行 ✓），但**失败行在 flush 盘点时已出队（清脏标），没有脏行驱动重试**，修复后的资产永不重传。修 = `propagate_asset_changes` 的 Added 分支加复活联动：身份在 failed 集时 revive **且**加入复活集参与引用行重扫重挂脏标（材质复活借 `modified_materials` 同路）。修复后 ghost 资产全链复活上屏（判定线 4 证据图）。
- 恢复上限落定：**无循环面**——revive 只由文件变更/手动 reload 事件触发，无自动重试循环；修复后再次失败重新进 failed 集（`Added` 复活双保险幂等）。维持 4.3"失败一次出队"口径。
- 手动重载入口落定：**加**（`ash_renderer/reload_asset` BRP 方法，`AssetServer::reload(path)` 薄封装）——文件监听是自动通道、reload 是测试与 AI 的确定性对照（不依赖 watcher 时序，失败资产修复重演必须有它，实测 watcher 对"容器内已存在的失败身份重载"不可靠）。

**WorldAsset 重载对宿主附加物的冲击盘点**（计划 §5 待决落定）：账本 6 行自动清+入（despawn→RemovedComponents 整树清账免费）；实体号全换代（旧 Entity 身份不保留，路线图边界既有口径）；相机/灯光不在场景资产内不重建；egui 选中态若引用旧实体号会悬空（测试时未选中无影响，面板侧悬空处置属 3.11 既有语义）。

**反思**：glTF 子资产 load 后管线追加一次 Modified（4.3 钉子）在重载场景同样触发——重载一次 = WorldAsset Modified（整场景 despawn+respawn）+ 子资产链 Modified，事件读侧全部按"失效→查驻留"判定消化，零误动作（判定线"事件不误伤"重载版验证）。

## 钉子

1. **复活联动缺口（本段实抓）**：4.3 留口"自动恢复链归 4.4"缺的是两半——事件源（file_watcher，开 feature 即接通）**与失效联动**（失败行出队后无脏行驱动重试，revive 放行了重试身份却没人盘点它）。修 = Added 且身份在 failed 集 → revive + 复活集参与重扫重挂。教训：**"放行重试"与"有行可重试"是两件事，失败出队把后者一并没收了**。
2. **描述符槽回收不能立即进 free list**：在飞 draw 在 GPU 执行时才读描述符（bindless UAB），槽立即复用 = 在飞 draw 读到新贴图（覆盖）——三条销毁路径（区间/旧图/槽）共用同一排空点（帧侧等待后），3.3.4"只写新槽"的覆盖竞态防线在回收侧的镜像。
3. **Unused 事件本宿主大量触发**（测试窗口 12 次——每次换指/兜底材质柄掉零即 Unused），Removed 才是回收触发器；unused_events_total 探针读数收账，不做动作。
4. **同路径 load 已驻留资产是 no-op**：资产在容器内时 `AssetServer.load` 直接返回既有柄——删除文件不触发失败也不触发重载；失败重演必须换从未加载过的新路径；`AssetEvent::Removed` 的来源 = 最后强柄 Drop 的确定性释放（despawn 动态加载实体即触发）。
5. **纹理槽计数被字体图集死代干扰**（3.7 图集"与表同寿"占槽 ~13 个且随内容变化逐帧整传新代）——判定线对账以驻留条目数/双停尸房/graveyard 为主读数，texture_slots_used 只看趋势不抠绝对值。
6. **池容量收敛语义**：`need = used + extra` 对 free 复用高估（安全方向），capacity 收敛到"峰值并发需求 × 2"而非随循环轮次增长——判定线"不持续泄漏"在容量维度同样成立（peak 1826624B 三轮不变）。
