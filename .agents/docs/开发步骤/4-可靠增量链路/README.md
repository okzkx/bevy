# 步骤 4：可靠增量链路（M3）

对应[执行路线图](../学习目标实现步骤.md)。本 README 是步骤索引与材料目录；各段任务面板在段目录 README（开工时立），段施工计划随立案入段目录。

**目的**：从"一次正确上传"发展成能长期处理变更、异步到货、删除和替换的资源链路。

**完成标准**：零变化时实例与资产上传为零；共享资源、换柄、同柄改内容、延迟到货、删除取消、反复加载卸载全覆盖。分别报告扫描数、上传字节、资源存量和处理耗时，不把"零上传"说成"零 CPU 每对象成本"。

**当前验收状态：✅ 验收归档（2026-10-14，[验收复核 §8](4-验收复核.md)）：复核问题 1～11 已按关闭口径逐条对账——问题 4～11 运行级关闭（CPU 探针+BRP），问题 1～3 代码级关闭（交叠窗口运行级复验挂账 V1 验证环境）；归档轮 clippy/库测试/运行冒烟全过（工具链 rust-1.98.0 实抓 3 处新 lint 已修），开放项（F22、计量欠账、小账两保留、槽位 churn）不阻塞步骤 5。历史施工与修复记录见下。**

**历史施工状态：✅ 全段收官（2026-10-12）。**4.1 对象增量 ✅ 收官（2026-10-10，当日立案当日施工：稳定槽账本 + 变更发现 + 增量写入 + BRP 变更方法族，判定线五条全过）；4.2 资产增量 ✅ 收官（2026-10-10，当日立案当日施工：AssetEvent 读侧 + 失效联动 + 同柄内容重传 + BRP mutate 方法族，判定线全过、零修复项）；4.3 异步就绪 ✅ 收官（2026-10-12，当日立案当日施工：pending 显式账面 + 失败与取消读侧 + BRP 动态加载方法族，判定线五条全过）；4.4 回收与热重载 ✅ 收官（2026-10-12，当日立案当日施工：卸载回收读侧 + 双停尸房 + 槽位回收 + 热重载链，判定线六条全过）——M3 完成，完成标准全覆盖（零变化零上传、共享资源、换柄、同柄改内容、延迟到货、删除取消、反复加载卸载）。
