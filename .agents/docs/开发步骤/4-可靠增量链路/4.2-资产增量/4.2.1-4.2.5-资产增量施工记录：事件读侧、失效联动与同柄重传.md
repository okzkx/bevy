## 1. 4.2.1 资产事件读侧

**面板要求**：三类资产 `MessageReader` 读侧 + 事件计量。
**实现**：`scene/mechanism/assets/asset_events.rs` 新增 `AshAssetEventPlugin`——`propagate_asset_changes` 挂 PostUpdate、账本对账之后；三个类型化 reader 分开处理（`AssetEvent<A>` 的 Item 类型随泛型而异，不并链）；`Modified` 进 `AssetInvalidations`，其余四变体只计数；计量（帧事件数/累计/失效数/重挂行数）入 `IncrementStats` 与 BRP `increment_stats` 的 `asset_events` 块。
**原理与取舍**：只有 `Modified` 触发失效——`Added`/`LoadedWithDependencies` 是首次驻留链的事（flush 查无即传），`Removed`/`Unused` 回收归 4.4。稳态零事件早退，不付重扫成本。
**坑点钉子**：`MessageReader::read()` 推进游标——同一 reader 循环两遍，第二遍拿不到内容；计数与处理必须一遍完成。

## 2. 4.2.2 失效与联动

**面板要求**：Modified → 失效凭据 + 引用行重挂脏标；关联方式钉明。
**实现**：`AssetInvalidations`（mesh/image 身份集）+ 重扫账本行定案——遍历账本行，命中（行 mesh ∈ 失效集 ∨ 行材质 ∈ 本帧 Modified 材质 ∨ 行材质五槽命中失效贴图）即 `mark_dirty`。材质不进失效集（无 GPU 驻留内容），只做行级联动。
**待决落定**（计划 §5"资产→实体关联方式"）：**重扫账本行**（O(行数) 零维护）——行数量级百级、Modified 帧稀疏，反向索引的维护成本买不回什么。贴图失效经"材质五槽"反向找引用者，关联 Image 失效传播免费拿到（材质改槽 → 新槽贴图失效 → 引用行重挂）。
**坑点钉子**：账本 `rows()` 不可变借用与 `mark_dirty` 可变借用冲突——先收集命中行再统一重挂。

## 3. 4.2.3 内容重传

**面板要求**："查无或失效才传"；替换时序安全。
**实现**（三条 swap-on-commit 通道，驻留全程不留空洞、过渡帧引用者照画旧内容）：
- **mesh**：flush 盘点判定放宽（`pool.resident(id).is_none() || invalidations.mesh_pending(id)`）→ 新区间重传 → `MeshPool::replace` 原子换槽返回旧槽。**旧区间孤儿化**：池从不写旧区间，在飞 draw 读它天然安全——零新增同步原语；空间回收归 4.4（与 3.2.2.2"bump 不回收空洞"同一笔账）。
- **image**：`ImageCache::take` 把旧 `GpuImage` 移入**停尸房**（就地 Drop = 在飞采样悬空）→ 新图建好 → `BindlessTables::rebind` **原槽重写**描述符（UAB 在飞可写契约；纹理槽占用不因内容变化增长，实测槽位 33→33）→ 换条目。停尸房排空挂 flush 开头：`FramePool::wait_all_inflight`（4.1.1 闸门第二次兑现）等图形最后使用后销毁。
- **材质**：无 GPU 驻留内容，参数变化每帧 UBO 自动生效；贴图槽变化走行级联动。
- **凭据消费**：换内容成功的身份 `consume_mesh/consume_image` 销账；未成功（未到货/被拒）保留，行保持脏标下帧重试——失效凭据不会丢。

**待决落定**（计划 §5"mesh 区间替换时序"）：**迁移新区间**而非原地重传——零新增同步（不写旧区间 → 无在飞读冲突），代价是孤儿空间（4.4 回收）。"原地重传 + 等在飞"的 stall 方案被淘汰。
**待决落定**（计划 §5"image 槽位重发布"）：**原槽重写**（rebind）——槽占用稳定；新采样键首次出现才占新槽（老键采样器槽孤儿化，罕见路径同归 4.4）。
**坑点钉子**：`pool.commit` 对同身份重复登记报错（4.1 去重纪律）——换内容路径必须持凭据分流 commit/replace，编排层保证"无凭据不替换"；排批 loop 借用 `&gpu_images`、发布 loop 移交所有权（GpuImage 进 cache），两段 zip 的借用形状不同。

## 4. 4.2.4 BRP 改内容方法族

**面板要求**：改资产内容的 BRP 入口（BRP 优先纪律）。
**实现**：`ash_renderer/mutate_asset`（`remote_assets.rs` 薄壳）+ 操作本体 `asset_ops.rs::mutate_asset`（可复用层，将来 egui 面板同款调用）。定位锚定实体（与换柄同口径），四驱动：`base_color`（材质参数）/ `slot_base_color_from`（贴图槽拷贝）/ `mesh_vertex_scale`（POSITION 顶点缩放）/ `image_tint`（4 字节 RGBA 族逐像素乘色调，其余格式明确拒绝）。**`Assets::get_mut` 即触发 Modified**（bevy_asset assets.rs），写入方零配合——发现与写入解耦的验收面。`tools/brp.py` 新增 `mutate` 子命令（合计十七）。
**错误分级**：实体缺席/非 primitive → 协议错误原码回传；格式不支持/资产查无 → COMPONENT_ERROR 带原因；空请求 → INVALID_PARAMS。全部不 panic、宿主存活（负例实测）。

## 6. 钉子汇总（六枚）

1. `MessageReader::read()` 推进游标：同 reader 二次 read 拿不到内容，计数+处理必须单遍完成。
2. `pool.commit` 严格登记 + 编排层凭据分流：去重纪律（重复登记报错）与换内容（replace）并存的关键是"无失效凭据不替换"。
3. mesh 旧区间孤儿化 = 零新增同步的替换方案：不写旧区间，在飞读天然安全；与 bump 不回收同一笔 4.4 账。
4. image 换内容三件套：停尸房（在飞安全）+ rebind 原槽重写（槽占用稳定）+ flush 开头等帧侧排空——4.1.1 闸门第二次兑现。
5. 失效凭据"成功才销账"：未到货/被拒的身份保留，行保持脏标重试——凭据不丢，重传不丢。
6. overlay 调试面板的"graveyard N 张/图集 N 代"是 3.7 字体图集的退役计数，与本段贴图停尸房同名不同物——读截图证据先分辨。

## 7. 边界对账与遗留

- 计划 §6 边界全部未越界：异步到货归 4.3（本段重传以资产已到货为前提）、回收常态化归 4.4（旧区间孤儿化/采样器老键孤儿化/停尸房排空时机已立账）、热重载归 4.4（本段内容变化全由显式 mutate 驱动）。
