# 8.2.6 施工记录：spawn 增量链缺陷修复（材质记录全零与运行期 spawn 无片元）

> 2026-10-22 当日立案当日施工收官（`goal/8.2-filament-ref` 续工）。对应[施工计划](施工计划：spawn增量链缺陷修复（8.2.6）.md)：修复 8.2.5 G-buffer 调试仪器验收轮受控复现的缺陷①（primitive 材质记录全零）与缺陷②（运行期 spawn 无片元）。**结论先行：两条缺陷同一根因——WGSL 侧 `MaterialRecord` 结构体步长 80B ≠ 宿主打包 64B，材质槽 ≥1 全体错位读垃圾**；8.2.1 材质记录扩列引入，缺陷①②为此同根的两张脸。

## 一句话总结

shader 端 `MaterialRecord` 结构体尾垫写成 `vec3<u32>`（对齐 16 被排到 offset 64..76，结构体 76B→对齐后步长 80B），宿主 `pack_material_record` 按 64B 步长写——材质槽 0 恰好不受影响（offset 0 = 记录 0 起点，glTF 场景永远只有它正确），槽 ≥1 全体按错位字节解读：透明判定读到垃圾 alpha → `instanceCount=0` 无片元（缺陷②），G-buffer 材质通道读到垃圾标量（缺陷①）。修复 = 五个 shader 的尾垫改三个 `u32` 标量（步长恰回 64）+ build.rs 加跨端布局互证闸门防复发。

## 定责过程（8.2.6.1，方法链实录）

逐层收窄、每步用可复现读数排除一片嫌疑面：

1. **画面+账面矛盾**：五球场景只有部分球可见；`cull_stats` 全可见零 mismatch、`drawlist verify` 零 mismatch（注意：后者只对账 CPU 两侧组装，不证明 GPU 光栅化——本次定的方法论钉）。
2. **set_transform 铁证**：受影响球挪进画面正前后截图 md5 一字不变 → 受影响行对帧缓冲零贡献。
3. **环读回（新仪器 `ash_renderer/ring_census`）**：模型环/材质环双帧槽逐字节 vs 宿主重打包期望——全对，写侧环写无责。
4. **对象表读回**（复用 8.1.3 `readback_buffer` 一次性 staging 拷贝，`DeviceStorage` usage 已冻结 TRANSFER_SRC）：对象记录逐字节全对——写侧对象表也无责。
5. **indirect 命令环读回**（`IndirectCommands` usage 当时缺 TRANSFER_SRC，实抓 VUID-00118 后补齐）：受影响行命令 `instance_count=0`，其余字段全对 → 嫌疑收窄到 build_indirect 的三条件输入。
6. **gap 位图哨兵**（TEMP-DEBUG 钉，`gap_marks[slot]` 打包 marks/transparent/pins 逐条件）：`marks[slot]=1`（标记环无罪）、`pins≠0`（LOD 引脚无罪）、**`transparent=1` 且 alpha 位型 = 0x00000000**——shader 眼里 `materials[1].base_color.a = 0.0`，而宿主读回同一环同一槽 = 1.0。
7. **f32 位型终极钉**：三槽 alpha 位型 = {0x3F800000(1.0), 0x00000000, 0xFFFFFFFF(NaN)}——与"宿主 64B 记录被按 80B 步长解读"的预测逐槽吻合（elem1.a 落在记录偏移 28 的 `_pad0`=0.0，elem2.a 落在偏移 44 的 `tex_occlusion`=0xFFFFFFFF）。**步长错位实锤。**

## 代码改动解析（面向下一个读代码的人）

- **shaders/*.wgsl（5 文件）**：唯一实质修复点。`MaterialRecord` 的 `_pad: vec3<u32>` 意图是"垫至 64"，但 vec3 对齐 16 使其在 sampler_index（48..52）之后只能落到 64..76，结构体 span 76→对齐 16 = 80。改三个标量后 52..64 恰好填满。`debug_draw.wgsl` 是退役 A/B 参照管线，同结构同修（保持可编译）。
- **build.rs**：`compile()` 在 naga parse 之后、validate 之前插入 `assert_host_layout`——遍历 module.types 按名字匹配闸门表，`TypeInner::Struct{span}` 与宿主常量比对。负向验证：临时改回坏结构，构建以 `span 80B ≠ 64B` panic 拦截（消息带修复指引）。新增记录结构时需在 `HOST_LAYOUT_GATE` 登记。
- **ring_census.rs**：诊断读数方法族新成员。借用法：账本/容器只读借用收齐期望值 → 环可变借用逐槽直读 → 对象表/命令环（DEVICE_LOCAL）走 `render::readback_buffer`（hiz 一次性 staging 同款，crate 级重出口）。与 cull_stats 同一"handler 不等帧"纪律；判读口径 = 两帧槽一致地错才算定责证据。
- **resources.rs**：IndirectCommands usage 补 TRANSFER_SRC——纯为诊断读回合法化，绘制面零变化。

## 钉子与遗留

- **方法论钉：`drawlist verify` 的对账边界**——它对账的是增量组装 vs CPU 全量参照（两侧都在 CPU），GPU 光栅化结果不在其覆盖面；"画面异常而账面正常"时直接上 `ring_census`。
- **WGSL 记录结构体纪律**：尾垫永远用标量 u32，不用 vec3/vec4（对齐陷阱）；新记录结构在 build.rs `HOST_LAYOUT_GATE` 登记，跨端步长由闸门执法。
