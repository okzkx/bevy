> **一句话说明**：步骤 8 要把"画什么"（步骤 5/6 已交给 GPU）之后的"怎么画"补成 PC 端完整管线——8.1 G-buffer 与透明层拆分打底，8.2 Filament BRDF 与多光源光照累积，8.3 CSM+PCSS 级联软阴影，8.4 HDR/Bloom/ToneMapping，8.5 SMAA 收尾；五段共用一条依赖链（G-buffer 原料 → 光照累积 → 阴影进累积 → HDR 合成 → 抗锯齿直出），为步骤 9 SCGI 提供 G-buffer 原料与光照注入点；本步不主张 GI 本体（归步骤 9）、反射与精确 OIT。

## 0. 定位：现状与要换掉的东西

步骤 7 收官后的绘制侧形状（核实 2026-10-21）：

- **不透明管线单 pass 直出**：`vulkan/frames.rs` dynamic rendering 单 color 附件（swapchain）+ 深度附件（`vulkan/depth.rs` D32_SFLOAT，反向 Z）；场景着色 = `examples/shaders/debug_draw.wgsl` Lambert（albedo × (direct + ambient) × 曝光），无材质参数面（无 metallic/roughness/normal/AO）。
- **单方向光**：`scene/content/lights.rs` 单盏 DirectionalLight（20000 lx 沿实体 forward）+ `GlobalAmbientLight` 资源；光源数据在 set1 FrameUniforms UBO 内（`bindless_probe_fixed.wgsl` `@group(1) @binding(0)`），不随光源数扩展。
- **无 HDR 域**：LDR 直出 swapchain（UNORM 底板 + SRGB view，3.4 拍板），无中间渲染目标、无 tone mapping、无抗锯齿。
- **步骤 5/6 底座全部在役**：常驻对象表 + 标记链 + build_indirect（5.1~5.3）、Hi-Z 遮挡（6.1）、GPU LOD（6.2）、流送与保底（6.3~6.6）；真实资产验收场（Sponza/zero_day/Poly Haven，步骤 7）就位，7.3 已交付真 PBR 贴图面供料（Diffuse/nor_gl/Metal/Rough）。

步骤 8 换的是**着色与合成的组织方式**，不动步骤 5/6 的 GPU-driven 骨架：G-buffer/透明层拆分（8.1）是所有后续段落的原料，光照累积（8.2）是阴影与步骤 9 间接光的注入点。**"GPU-driven 闭环不回退"（draw_calls 维持 5.3 口径）是贯穿全程的红线**：本步加 pass 不许把绘制决策搬回 CPU。

### 8.1 G-buffer 与不透明几何 pass（透明层拆分）

- **一句话说明**：把不透明几何从"直出颜色"改成"写 G-buffer"、把透明拆成带分簇光源列表的 forward 层——为 8.2 光照累积供原料、为步骤 9 SCGI 备好 G-buffer 三原料；本段不主张光照模型变化（仍单方向光对照）与任何画质提升。
- **交付**：
  - G-buffer 附件布局（albedo / normal / 深度；**世界位置取法已拍板=深度重建**（2026-10-22，[段施工计划 §0](8.1-G-buffer与不透明几何/施工计划：G-buffer与透明层拆解.md)）；normal 编码（世界空间 xyz 直存 vs 八面体压缩）随布局一并定，带宽账与取数便利的取舍施工时钉明。
  - motion vectors 附件**只留位不写内容**（本体归步骤 9.x 前置施工件，需 InstanceLedger prev/curr 双份模型环，9.x 立案时单列）。
  - 透明拆 Clustered Forward 前向层：**开工即 3D cluster**（视锥 AABB 分簇，用户 2026-10-20 拍板——学习项目，2D tile 起步的省略不划算），分簇光源列表 compute + 逐 tile×深度片光源列表；不透明 pass 深度对透明可见（深度附件复用形态施工时钉明——6.1 已实证深度附件 usage 不可采样，须走附件重绑或取数通道）。
  - 透明 draw 顺序 GPU 侧排序：bitonic sort 按深度键排 draw 索引 → indirect draw（消掉最后一个逐对象 CPU 决策残留）；物体级精度与 CPU 排序同档，穿插正确性靠精确 OIT 属[外置拓展](../外置拓展需求.md)，不主张。
  - **落点目录已钉明 `render/pipeline/`**（2026-10-22 用户拍板，见 §5）：下列既有文件为现状路径引用，随 8.1 开工迁移进 `render/pipeline/` 后叠加新代码。
- **落点**：`vulkan/images.rs`（G-buffer 附件分配）、`vulkan/frames.rs`（多 pass 帧编排）、`vulkan/pipeline.rs`（多渲染目标管线）、`vulkan/descriptors.rs`（透明层光源列表）；新 shader：G-buffer 写入、cluster 构建、bitonic 排序、透明前向绘制。
- **前置闸门**：多 color 附件渲染首跑（dynamic rendering 附件引用数与格式声明——VUID-08914 纪律沿用：管线声明面=实例附件全集）+ 渲染目标从 swapchain 直出改为中间目标的 resize/最小化生命周期回归；HDR 中间格式（R16G16B16A16_SFLOAT）的 blending 支持待实测。
- **判定线草案**：①G-buffer 各附件内容与现行 forward 输出语义逐项对齐（单光源 A/B 对照，读图）；②透明层多光源与不透明主体同场景光照一致；③GPU 排序结果与 CPU 深度排序参照一致（物体级）；④resize/最小化回归、零 VUID、WM_CLOSE exit 0、clippy 全净。

### 8.2 Filament BRDF 与多光源光照累积

- **一句话说明**：把 Lambert 换成 Filament BRDF、把光照从"绘制时直算"改成"全屏光照累积 pass 读 G-buffer"——多光源自此与光源数解耦着色成本，为 8.3 阴影与步骤 9 间接光注入立接口；本段不主张阴影（8.3）与 GI（步骤 9）。
- **交付**：
  - 材质参数面扩容：metallic/roughness/normal/AO 进材质环记录与贴图槽（bindless 双表扩列——表结构改造沿 5.1.1 解冻清单先例）；7.3 供料四件（真 PBR 贴图面）为验收资产。
  - 光照累积 pass：全屏 pass 读 G-buffer（albedo/normal/世界位置）× 光源列表，输出 HDR 颜色（8.4 正式接 HDR 契约，本段可先 LDR 中转钉明）。
  - 多光源列表 GPU 驻留（**头号待决**：常驻表〔set2 式〕vs 每帧环——现 UBO 单方向光在 set1 128B 冻结边界内，扩光源必解冻一次）；光源记录**预留 shadow 标志位**，8.3 接管采样选择权。
- **落点**：材质环/实例表（`vulkan/instance_table.rs`、`vulkan/pool.rs`）、光源组装（`scene/content/lights.rs` 扩族）、光照累积新 shader、BRP 方法族扩（多光源 spawn/参数改——BRP 优先定例沿用）。
- **判定线草案**：①漫反射项与 Filament 参考对照收敛（参考=本地 Filament 源码检出 `F:\okzkx\filament` @ `373190d49`，2026-10-22 登记；对照基准已由[源码参考篇](../笔记/渲染/Filament%20源码参考：标准模型%20BRDF%20与%20多光源（8.2%20对照基准）.md)钉明=D_GGX + V_SmithGGXCorrelated + F_Schlick + Lambert；Khronos MetalRoughSpheres/DamagedHelmet 单体对照，沿用 3.5 受控对照法）；②多光源开关 A/B；③金属/粗糙度梯度读图；④既有判定线零回退（4.x 零泄漏、5.3 draw_calls 口径、零 VUID、exit 0、clippy 全净）。

### 8.3 CSM + PCSS 级联软阴影

- **一句话说明**：给多光源里的方向光接 CSM 级联 shadow map + PCSS 软阴影，shadow depth pass 走 GPU-driven（逐 cascade 复用标记链与 build_indirect，CPU 只发矩阵）；本段不主张 VSM（外置条目 7）、不做阴影降噪时域滤波。
- **交付**：
  - shadow depth pass 逐 cascade：cascade 视锥代主相机视锥进 5.2 六平面标记（新标记族或分列施工时钉明），标记后 build_indirect 生成 shadow draw——CPU 只发 cascade 矩阵，剔除/决策归 GPU 既有链（行业同构=GPU-driven shadow culling）。
  - **两枚语义钉（2026-10-20 复核钉入，照此执行）**：①遮挡标记不参与 shadow pass——Hi-Z 金字塔是主相机深度语义，对 shadow 视锥不合法，shadow pass 不做遮挡剔除是行业默认；②shadow draw 取主 LOD 档**再粗一档**——6.2 档位是主相机覆盖语义，shadow 视角直接沿用会过细。
  - 级联划分（数量/分割比例施工时钉明）、PCSS 滤波半径（blocker search + 半影估计）；阴影采样进 8.2 光照累积 pass。
- **判定线草案**：①阴影开关 A/B；②级联边界无跳变（读图）；③逐 cascade `draw_calls ≤ 该级可见数`（cull_stats 对照口径复用，5.2 同款）；④性能成组记录（shadow pass 计时区间并入 5.5 计量底座）；⑤零 VUID、exit 0、clippy 全净。

### 8.4 HDR、ToneMapping 与 Bloom

- **一句话说明**：把合成从 LDR 直出改成 HDR 契约——高动态中间目标、Bloom、tone mapping、输出编码恰好一次，终结 swapchain 编码判定线悬案；本段不主张 GI 与反射。
- **交付**：
  - 不透明 + 透明合成进 HDR 契约：中间渲染目标改浮点格式（8.1 已留位，本段正式启用）；swapchain 写入只发生在 tone mapping 之后。
  - Bloom（HDR 域，亮度阈值 + 降采样模糊链——实现形态施工时钉明）；ToneMapping（曲线选型施工时钉明，ACES 近似族为默认候选）。
  - **输出编码恰好一次**：终结 3.4 起挂账的 swapchain 编码判定线悬案——UNORM 底板 + SRGB view（3.4 拍板）与 HDR 链的衔接落点施工时钉死，编码次数数学核对入判定线。
- **判定线草案**：①与现行 LDR 直出亮度分布对照（同场景同光照读图）；②Bloom 开关 A/B；③输出编码单次性验证（灰阶/亮部不重复 gamma）；④resize/最小化回归、零 VUID、exit 0、clippy 全净。

### 8.5 SMAA 抗锯齿

- **一句话说明**：tonemap 后接 SMAA 三 pass（边缘检测/权重计算/邻域混合），作为延迟管线的抗锯齿标准搭档收口步骤 8；本段不主张 TAA 与任何时域手段。
- **交付**：SMAA 三 pass（LDR 域、tonemap 后）；输入查找表（area/search 贴图）获取方式施工时钉明（官方预生成 texture vs 运行时计算）；接线在 tone mapping 输出与 swapchain 直出之间。
- **判定线草案**：①几何边缘锯齿读图对照（开关 A/B）；②无时域类伪影（SMAA 非时域——静止与相机移动两种机位连拍）；③性能成本成组记录；④零 VUID、exit 0、clippy 全净。

## 3. SCGI 前置接口（设计约束，非独立段）

- G-buffer 三原料（albedo/normal/世界位置）从 8.1 起就是步骤 9 播种/gather 的取数面——世界位置取法的待决裁决必须把步骤 9 的取数需求当输入。
- 光照累积 pass 预留间接光注入项（8.2 立接口，9.1 接单个全局 SH 环境探针）。
- 深度语义与 6.1 反向 Z 对齐（已钉，无新动作）。
- **motion vectors 本体 = 步骤 9 前置施工件**（2026-10-20 钉入）：8.1 只留附件位不写内容；本体需要 InstanceLedger 双份模型环 prev/curr——前帧矩阵账是新结构，9.x 立案时单列前置件。
- 时域稳定手段（缓存侧 Temporal Smoothing/样本预算/求交器）不在本步主张，归步骤 9；TAA 不做（SCGI 主噪声在缓存侧 patch 粒度，屏幕空间逐像素重建帮不上）。

## 4. 边界

- **GI 归步骤 9**：本步只管直接光与合成；光照累积 pass 的间接光注入项只立接口不填内容。
- **反射不主张**（Realtime probe/SSR 均不在本步）。
- **精确 OIT 不主张**：透明排序买到的是物体级深度键排序（与 CPU 同档），透明物体间穿插的正确性归[外置拓展](../外置拓展需求.md)。
- **VSM 不进本步**：其收益绑定 Nanite 级几何负载与页管理工程量（≈又一套驻留管理器），已登[外置拓展条目 7](../外置拓展需求.md)；shadow map 的 GPU-driven 性由 8.3 的"标记链 + build_indirect 逐 cascade"兑现，不靠 shadow map 本体换技术。
- **蒙皮/mesh shader/通用 RenderGraph 仍不进主线**（沿用路线图总边界句）；材质贴图面以 Filament BRDF 所需为界，不主张材质编辑器。
- **TAA 不做**（SMAA 收口；理由见 §3）。
- 一次只施工一段：8.1 是底座（G-buffer/透明拆分是后续全部的原料），依赖链 8.1 → 8.2 → 8.3 → 8.4 → 8.5 顺序不可倒；8.3 阴影采样进 8.2 光照累积，8.4 合成依赖 8.1/8.2 的 HDR 契约，8.5 最后直出。
- **开工前置**：步骤 5/6 的步骤级验收归档欠账仍先于本步骤开工（[路线图当前位置](../学习目标实现步骤.md)原欠账保留）；F25/F26 不阻塞本步 G-buffer/材质链/CSM 施工（[待修复清单 §7](../待修复清单.md)）。

## 5. 目录组织定案（2026-10-21 用户拍板）

实施时创建 `Render` 文件夹归置渲染相关代码，渲染管线、BRDF 着色、后处理等按职责分文件夹——不再往 `src/vulkan/` 平铺家族（现行 21 文件单层）里继续堆步骤 8 的五段增量。

- **模块名沿仓库小写惯例落 `render/`**（与 `overlay/`、`scene/`、`remote/` 同级，src 根直挂）。
- **提案形状**（子目录细则随 8.1 段施工计划钉明）：

  ├── pipeline/    # 渲染管线：pass 编排、G-buffer/deferred/透明 forward、管线与附件对象（8.1 主体）
  ├── shading/     # BRDF 着色：材质参数面、光照累积、光源数据（8.2/8.3 主体）
  ├── post/        # 后处理：HDR/Bloom/ToneMapping/SMAA（8.4/8.5 主体）
