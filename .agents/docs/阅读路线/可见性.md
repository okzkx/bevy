# 可见性

场景有十万级实例时，CPU 不能逐对象判断“画不画、用哪档、命令怎么写”。这条链把决策搬到 GPU：CPU 只给候选行和常量，GPU 依次算可见、遮挡、档位、命令。这一篇按帧内顺序读。

## 一、链的形状

```text
① 视锥剔除（cull）
     主视图标记 b3 + 四级阴影视锥标记 + 诊断
        ▼
② 遮挡测试（occlusion，读两帧前的 Hi-Z）
     b3 = 视锥 ∧ 遮挡；独立标记 b6 只进诊断
        ▼
③ LOD 选档（lod_select）
     写档位环 b8
        ▼
④ indirect 组装（build_indirect）
     读在场环 b4、标记 b3、对象表、LOD 表 b7/b8 → 写命令环 b5
        ▼
图形侧一条 cmd_draw_indexed_indirect

阴影命令：cull 产四级标记 → shadow_build 逐 cascade 写命令环
透明命令：transparent_collect/sort/gather 单独出，不走 b5
```

顺序即依赖。每一步的交接屏障在各自的 `record` 里；跨步的读写关系不靠调用顺序猜，靠屏障和 `Handoff` 明确。

## 二、先有可对账的 shader 表

`build.rs` 在编译期做完四件事：

1. 展开入口 shader 的 `// #import` 公共片段。
2. naga 解析并校验 WGSL；`assert_host_layout` 检查 `MaterialRecord` 64、`ObjectRecord` 48、`LightRecord` 64、`LodEntry` 12、`IndirectCommand` 20 的字节尺寸。
3. 生成 SPIR-V。naga 不发射 runtime descriptor array 的 capability，`spirv-val` 拒绝后打最小补丁（`RuntimeDescriptorArray`、`SampledImageArrayNonUniformIndexing`、`SPV_EXT_descriptor_indexing`）。
4. 逐入口点列出实际用到的 `(set, binding, 描述符种类, 数组形状)` 与 push 字节数，写进 `OUT_DIR/shader_abi.rs`。

`shader_abi.rs` 里每个 shader 一个 `Shader` 静态项，spv 字节也挂在上面。管线取 shader 字节只认这一处。

**为什么要逐入口**：shader 声明了但没用的 binding 不进表，管线布局对它没有义务。布局是超集，不是逐项相等。

## 三、配方与交接屏障

`PipelineDesc` 是一条管线的布局配方：shader、入口、按 set 编号排好的布局声明、push 范围、附件格式。`build` 统一完成对账、组装 pipeline layout、建 shader module。

对账口径（`problems`）：

- shader 用到的每个 `(set, binding)` 必须在第 set 个声明里有同种类的 binding。
- 数量覆盖 shader 数组形状；runtime 长度数组必须带 `PARTIALLY_BOUND`。
- 可见阶段要包含入口阶段；用了 push 时范围要覆盖字节数和阶段。
- 图形管线至少声明一种附件格式，compute 管线必须没有。

`ComputeHandles::dispatch` 在 dispatch 后录一条全局内存屏障，形状由 `Handoff` 决定。src 恒为 `COMPUTE_SHADER + SHADER_WRITE`，六个变体只换下游：

| 变体 | dst 阶段 | dst access | 典型下游 |
|---|---|---|---|
| `VertexComputeReadWrite` | VS + CS | READ + WRITE | 后续 VS 读、compute 写同一 buffer |
| `VertexComputeRead` | VS + CS | READ | VS 读、后续 compute 只读 |
| `ComputeReadWrite` | CS | READ + WRITE | 后续 compute 写 |
| `ComputeRead` | CS | READ | 后续 compute 只读 |
| `ComputeFragmentRead` | CS + FS | READ | 透明 FS 读 |
| `IndirectCommandRead` | DRAW_INDIRECT | INDIRECT_COMMAND_READ | `cmd_draw_indexed_indirect` 读命令环 |

读 `Handoff` 的方法：先问“下一步谁读这份输出”，再核对 dst stage/access 是否覆盖它。覆盖不全时验证层不一定报，因为同步错误经常是“看起来能跑”的。

## 四、视锥剔除

`src/render/passes/visibility/cull.rs` 与 `shaders/gpu_driven/cull.wgsl`：

- **视锥平面**：CPU 从 `view_proj` 提取六平面（`frustum_planes`），每帧随 push 进 compute。clip volume 是 D3D 型（Z∈`[0,1]`）；reverse-Z 不改变半空间集合。
- **保守判定**：AABB 不被任何平面整盒排除即可见（p 顶点判定，法线无需归一化）。宁多画不错杀。
- **一次 dispatch 产两份标记**：主视图 `marks`（b3）和四级阴影视锥标记。主视图开关不能靠停 dispatch 来关——停 dispatch 会连阴影标记一起停；开关随 push 进 shader，关 = 主视图 marks 恒写 1。
- **dispatch 上界 = 实例槽 bump bound**（`used_object_slots`）。空闲栈归还的槽号恒小于 bump 游标，bound 覆盖全部在场/在途槽；bound 外的陈旧标记无人读。
- push 112 B：6×vec4 平面 + bound + 主视图启用位 + 垫。

CPU 侧有同款参照实现，结果可与 GPU 逐位对比；诊断读数在 `wait_for_slot` 之后读，读的是本帧槽两帧前的输出。

## 五、遮挡测试与 Hi-Z

`occlusion.rs` + `hiz.rs` + `shaders/gpu_driven/occlusion.wgsl`、`hiz_downsample.wgsl`。

**Hi-Z 是什么**：上一轮深度逐级 MIN 归约成的层级深度图（R32F × 2 帧槽），遮挡测试从这里取数。每帧由归约链重写本帧槽。**选层**：按 AABB 投屏像素最大边取 `ceil(log2(...))`，下限 1、clamp 进级数；level 0 从不归约也从不采样（首级归约的源是深度附件）。

**时序**：

```text
② 遮挡测试：读同槽金字塔 = 两帧前本帧槽的归约输出
③ 渲染写深度
⑥ 透明层之后：归约链逐级重写本帧槽金字塔
```

“遮挡读旧、归约写新”在同一条命令缓冲内，由屏障收口。同槽读不需要额外跨帧同步：`wait_for_slot` 的 fence 已证明上一次用本槽的提交执行完。深度附件渲染后转 `DEPTH_READ_ONLY` 供归约采样，下帧 `UNDEFINED` 进场丢弃；金字塔才是跨帧持久层。

**跳过条件**（任一命中，整段不 dispatch；1–4 记一个 fallback 原因）：

1. 开关关闭。
2. 视锥剔除关闭：遮挡不独立于视锥开启。
3. 金字塔未就绪：首建或 resize 后前 2 帧。
4. 相机跳变：与两帧前机位比，位移 > 0.5 世界单位或旋转 > 15°。金字塔正是两帧前的深度；连续缓慢环绕不触发，2 帧滞后的短暂误剔除会在数帧内恢复。
5. 空场：`bound == 0`（没有实例槽）同样整段不派发；无人读 b3/b6，诊断 fallback 记 `None`，不算上面四种原因。

1–4 跳过时 b3 保持视锥纯结果，b6 host 填全可见，原因记入诊断；空场无行可填。遮挡把 b3 清零成“视锥 ∧ 遮挡”；b6 是独立标记，只进诊断读数，不参与绘制。

push 80 B：`view_proj` 64 + screen 8 + bound 4 + 垫。

## 六、LOD 选档

`lod.rs` + `lod_select.wgsl`：

- **判据**：AABB 投屏 clamp 后的最大边（屏幕覆盖尺寸）。
- **自然档位** = `floor(log2(threshold / s))`。
- **迟滞**：向粗切换需越过自然边界 ×(1−h)，向细切换即时。默认 `threshold_px = 256`、`hysteresis = 0.25`。
- **prev 读档位环本槽** = 两帧前本帧槽输出；host 读同样在 fence 之后。2 帧滞后由迟滞带吸收，静态场景收敛值不受影响。
- **没有跨帧真值**：选档每帧从当前相机现算，档位环只是迟滞状态；未驻留档由 `build_indirect` 的表内回退承担。
- **关闭** = 不 dispatch，档位环 host 填 0（最细档），命令三字段回到对象记录基准。
- push 96 B：`view_proj` 64 + screen 8 + bound 4 + threshold 4 + hysteresis 4 + 垫。

## 七、indirect 组装

`indirect.rs` + `build_indirect.wgsl`：

- **在场环是命令范围**：不是全部 bound 槽，而是 DrawList 枚举的可绘行。全 bound 发命令会让“已 despawn 未复用槽”和“资产卸载后暂缓行”的旧记录继续画。
- 每个 invocation 写一条 `VkDrawIndexedIndirectCommand`：引脚来自 LOD 选档（缺档回退基准），`firstInstance = slot`，不可见或透明 `instanceCount = 0`。
- 透明判定：读材质记录 `base_color.a < 1`；透明行由透明层单独出命令，不重复画。
- **命令条数 = 在场行数**；CPU 传给 `cmd_draw_indexed_indirect` 的上界就是它。只启用 `multi_draw_indirect`；条数只有 GPU 知道时才需要 `draw_indirect_count`。
- push 只有 4 B：count。

## 八、阴影标记与命令

阴影不是另起一条完全独立的可见性链：cull 的同一个 dispatch 顺带产出四级阴影视锥标记；`shadow_build` 读标记与 LOD 档位，逐 cascade 往四张命令环写命令；`shadow` 的 depth pass 再消费。细节见《[绘制](绘制.md)》。

## 九、诊断回读

`src/render/core/device/readback.rs` 提供同步回读：独占一次提交并阻塞到 fence。只被 BRP 读数、Hi-Z/透明层诊断调用，不进帧循环。**诊断只进计量，任何系统不得据它决定画什么。**

## 十、检查点

- `Handoff` 六个变体分别覆盖哪些下游？挑一个变体，说出它的 src/dst stage 和 access。
- 剔除为什么一个 dispatch 同时产主视图和阴影视锥标记？主视图关闭时为什么不能停 dispatch？
- 遮挡测试在哪些情况下整段跳过（四种 fallback + 空场）？读数为什么是两帧前的？
- 相机跳变阈值是多少？为什么连续缓慢环绕不触发？
- LOD 的自然档位公式、阈值、迟滞各是什么？为什么说“没有跨帧真值”？
- indirect 命令的 `firstInstance` 为什么等于实例槽号？透明行为什么 `instanceCount = 0`？
- Hi-Z 的“遮挡读旧、归约写新”为什么不需要额外跨帧同步？resize 后为什么要 warmup 两帧？
- `PipelineDesc::problems` 的对账口径里，“布局是超集”是什么意思？
