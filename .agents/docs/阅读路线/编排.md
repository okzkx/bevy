# 编排

这一篇读最后一段：ECS 侧的一次组件变更，怎么变成这一帧的环写入、九段录制和一次提交。前半是场景账本与上传编排，后半是 `draw_frame` 与 `record_frame`。

## 一、场景账本：一行一个可渲染 primitive

`src/scene/mechanism/assets/ledger.rs` 的 `InstanceLedger` 是 CPU 侧的唯一真相：每个可渲染 primitive 一行，存两个柄（mesh、material）、传播后的世界矩阵、实例槽和绑定凭据。行随实体生命周期增删换绑，跨帧存活——`RemovedComponents` 不带旧组件内容，删除处理全靠账本自己存的那行。

**变更发现**在 `PostUpdate`，排在 `TransformSystems::Propagate` 之后，三条入口：

- **移除**：`RemovedComponents<Mesh3d>` / `RemovedComponents<MeshMaterial3d>` 清行。despawn 递归删子树时每个 primitive 各发一次组件移除，整树清账免费拿到。
- **新增/换绑**：`Or<(Changed<Mesh3d>, Changed<MeshMaterial3d>)>`。插入也会置 changed tick，所以新增不需要 `Added`。
- **矩阵**：`Changed<GlobalTransform>`。传播只在矩阵变化时更新终值，静态场景不触发。

发现的结果落进账本：行被标记脏。上传链只消费脏行，不做每帧全量扫描。**稳态是“零脏行、零上传、零组装走访”，不是“每帧全量扫一遍”。**

账本旁边还有几本账：

| 账面 | 管什么 |
|---|---|
| `AssetInvalidations` | 内容被修改的 mesh/image 身份（`AssetEvent::Modified`），上传成功后销账 |
| `AssetReadiness` | 异步资产的 pending / failed 身份；pending 失去全部引用时取消 |
| `AssetRetirements` | 卸载事件，flush 消费后把驻留条目出账 |
| `LodGroups` | 逻辑 mesh → 各档变体柄；上传链按它盘点档位资产，DrawList 按它取各档引脚 |
| `AssemblyCache` | 可绘行集合的增量缓存，账本变更点标重估 |
| `ResidencySettings`/`ResidencyStats` | 显存预算、保底锚、请求/淘汰计量 |

`residency_tick` 在 `Last`、`flush_uploads` 之前运行：按相机、预算和 LOD 需求请求或淘汰资产，动作进同帧上传账。淘汰有冷却期，避免预算边界来回切换；淘汰档位要重挂引用行的 LOD 脏标，避免表里留下指向已回收区间的槽号。

## 二、上传编排

`src/driver/upload.rs` 的 `flush_uploads` 七步的逐级账面见《[数据](数据.md)》§六；本节只记结论。

**失败分流**：资产未到货/转换拒绝是逐项降级，warn 后下帧重试或出队，不进错误通道；Vulkan/账本失败是致命，冒泡退出。提交失败不留下指向未上传数据的账本行。

## 三、DrawList：可绘行与四个环

`src/driver/host/drawlist.rs` + `scene/mechanism/assets/assembly_cache.rs`。

**可绘行**由 `assemble_update` 维护：实例槽缺、锚 mesh 未驻留、材质容器缺席 = 该行暂缓，就绪后自愈；缺贴图用 fallback 白图照画。暂缓行不进在场环，自然没有绘制命令，GPU 侧无特判。

组装是增量的：账本变更点标记待重估行，`AssemblyCache::update` 只重估这些行；首帧、锚开关翻转、LOD 登记换代才全量重建。全量走访 `assemble_reference` 只用于 BRP 对照模式逐帧核对。

`draw_frame` 在 `wait_for_slot` 之后写四个环：

| 环 | 写法 | 内容 |
|---|---|---|
| 模型环 | 增量写脏行；新行两个帧槽各写一次 | 世界矩阵 64 B/槽 |
| 材质环 | 每帧全量重写可绘材质 | PBR 标量 + 四个贴图槽 + 采样器 |
| 在场环 | 每帧全量重写可绘行槽号 | GPU 命令范围 |
| LOD 变体表环 | 增量写脏行；换槽时档位环一并清 0 | 4 档 × 12 B 引脚 |

环写入全部发生在 `wait_for_slot` 之后：fence 证明本槽上一轮使用完成，重写不会撞上在飞 draw。

## 四、draw_frame：一帧的 CPU 侧

`src/driver/host/frame.rs`，`Last` 调度。`FrameInput` 是 16 个字段的系统参数束（Bevy 系统参数上限 16，再加字段前要先合并分组）。顺序：

1. **让路**：窗口最小化/无尺寸就早退，不进错误通道。
2. **resize**：`gate.rebuild_if_pending` 重建尺寸相关资源（深度、G-buffer、cluster、Bloom、SMAA、Hi-Z）。
3. **等帧槽**：`wait_for_slot` 等本槽上一轮提交完成，重置命令缓冲。
4. **acquire**：过时/次优在 `Swapchain::acquire_index` 内消化，重建交给下个帧首。
5. **组装 DrawList**：`assemble_update` + 对照模式校验；取走奇偶脏集，之后账本只读。
6. **写 UBO 与环**：帧 UBO、shadow UBO、Bloom 参数、cluster 参数、透明计数清零；模型/材质/在场/LOD 四环。
7. **造功能输入**：剔除 → 遮挡 → LOD → 缺口快照 → indirect → UI（图集整传 + 镶嵌 + 顶点环）；shadow、cluster、transparent 在组装 `RenderFeatures` 时建；诊断读数在各自写入路径之后取。
8. **录制提交**：`record_frame`（下一节）。
9. **present**：`present_digest`；失败先暂存，`advance` 照常推进，收尾冒泡。

**acquire 之后任何真失败都必须致命退出**：同步状态无法恢复，warn 后继续会等一个没人 signal 的 fence。

## 五、record_frame：九段

`src/render/frame/record.rs`。`record_frame` 收三个参数：本次 acquire 的 `PresentTarget`、功能门控 `RenderFeatures`、场景资源 `SceneResources`。

九段固定顺序：

1. **进场**：开始 cb、帧计时、颜色/深度/G-buffer 进场屏障、透明排序键预填 `-inf`。
2. **compute 前置**：视锥剔除 → 遮挡 → LOD → indirect → shadow 命令组装 → 光源列表 → 透明 collect/sort/gather。
3. **shadow depth**：逐级联 indirect draw，进出屏障每帧都录。
4. **G-buffer**：三色附件 + 深度，一次 indirect 画完不透明物体。
5. **合成 + 透明前向**：G-buffer 转只读、深度转只读；合成写 HDR；透明层 LOAD + 混合；HDR 转只读。
6. **Hi-Z**：深度转回只读，逐级归约本帧槽金字塔。
7. **Bloom**：prefilter/down/up。
8. **tonemap + SMAA + UI**：tonemap 写 LDR，edge/blend/neighborhood，最后 UI 接在同一次渲染里。
9. **出场 + 提交**：swapchain 转 `PRESENT_SRC_KHR`、结束 cb、重置 fence、`queue_submit`。

**段界就是布局迁移点和计时打点**。段内输入全部来自 `feature`（功能门控）和 `res`（场景资源），段间只靠布局屏障衔接。①⑨ 是槽基建段（cb/fence/等待列表），不属于任何业务模块。

`RenderFeatures` 的字段按九段消费时序排：`timer`、`frustum_cull`、`hiz`、`lod`、`indirect`、`shadow`、`cluster`、`transparent`、`post`、`ui`、`upload_wait`。`SceneResources` 是 ④⑤ 场景链的底座：场景管线与三集、网格 buffer、命令环、G-buffer 目标与合成管线；它不装功能门控。

**提交等待**：`image_available` 在 `COLOR_ATTACHMENT_OUTPUT` 等；上传票据在 `ALL_COMMANDS` 等。`UploadWait::snapshot` 必须在 overlay 图集整传之后取——图集批可能多发一张票据，取早了本帧 UI 贴图不在等待值里。票 0 = 从未上传，不挂等待（VUID-03242）。

## 六、检查点

- 账本一行存什么？三条变更入口各处理什么？为什么新增不需要 `Added`？
- 驻留管理器为什么排在 `flush_uploads` 之前？淘汰后为什么要有冷却期？
- `flush_uploads` 七步里，哪一步失败是致命、哪一步是逐项降级？
- 可绘行暂缓的条件是什么？暂缓行为什么不需要 GPU 侧特判？
- 四个环各怎么写？为什么新行要写两个帧槽？
- `draw_frame` 从 resize 到 present 的顺序；`FrameInput` 为什么卡在 16 个字段？
- 九段录制的段界为什么就是布局迁移点？每段输入来自 `RenderFeatures` 还是 `SceneResources`？
- `UploadWait::snapshot` 为什么必须在图集整传之后取？
