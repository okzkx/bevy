# 数据

一份 mesh 或贴图要能被 shader 用，必须过三道关：CPU 侧整形、搬运到显存、登记驻留。每一关都可能失败、等待、回收。这一篇按这三关读，最后看一轮上传怎么把它们串起来。

**一条主线：资产数据统一走 staging 加完成票据；替换走“新位置 + 旧位置延迟回收”；回收旧图与旧网格区间要“图形最后使用”和“上传完成”两个条件同时成立。**

## 一、第一关之前：所有 buffer 只有一种建法

`src/render/core/device/memory/` 三个文件定义了全库 buffer 的唯一形态：

- `role.rs` 的 `BufferRole::spec`：每种用途要什么 usage、内存类型必须有哪些属性、最好有哪些属性，只在 `BufferRole::spec` 写一份。
- `contract.rs` 的 `MemoryContract`：启动时查一次内存类型表、堆表和 `nonCoherentAtomSize` 并冻结。`find_type` 在 `memoryTypeBits` 允许的类型里挑：必需属性必须全含，优先属性命中越多越好，同分取小索引。**必需属性给不出就报错，不悄悄降级。**
- `buffer.rs` 的 `GpuBuffer`：按 `requirements.size` 恰量分配、偏移 0 绑定；宿主可见的从创建到销毁一直映射。`write` 在非 coherent 内存上按 atom 对齐 flush，`read` 前 invalidate。

| 角色 | usage 要点 | 必需属性 | 用在哪 |
|---|---|---|---|
| `DevicePool` | 顶点＋索引＋传输两向 | DEVICE_LOCAL | `MeshPool` 两条池 |
| `Staging` | TRANSFER_SRC | HOST_VISIBLE | 上传暂存 |
| `Readback` | TRANSFER_DST | HOST_VISIBLE | 诊断回读 |
| `FrameUniform` | UNIFORM | HOST_VISIBLE | set1 每帧 UBO |
| `Storage` | STORAGE＋传输两向 | HOST_VISIBLE | 模型/材质环、光源表 |
| `DynamicDraw` | 顶点＋索引 | HOST_VISIBLE | UI 顶点环 |
| `DeviceStorage` | STORAGE＋传输两向 | DEVICE_LOCAL | 对象表 |
| `IndirectCommands` | STORAGE＋INDIRECT | DEVICE_LOCAL | indirect 命令环 |

**`GpuBuffer` 不防 GPU 在飞读写。** 映射指针随时能写，“等 GPU 用完再写、再销毁”是上层用票据和帧槽 fence 保证的；`Drop` 也不等 GPU，退出时由 `teardown_vulkan` 先 `device_wait_idle`。

跨队列族共享：`create_with_families` 收到两个不同队列族时按 CONCURRENT 创建。专用 transfer 族存在时，池和对象表都走 CONCURRENT——它们被 transfer 反复写、被图形长期读，每批做一次所有权转移不划算；写→读可见性由票据等待保证。

## 二、第一关：CPU 侧整形

这一关零 Vulkan 调用，只把 Bevy 的数据改成 GPU 能直接收的字节。

**网格**（`mesh_convert.rs`）：

- 交错顶点 32 B：POSITION 12 + NORMAL 12 + UV_0 8。
- 索引一律 U32，不为省内存保留 U16。
- 只收 TriangleList；POSITION 缺失、格式不对或长度不符就拒收；NORMAL/UV 缺失补 0 继续。
- 同时扫出局部包围盒，写进对象记录。

**贴图**（`image_spec.rs` + `bcn.rs`）：

- 只收 2D、`Rgba8Unorm`/`Rgba8UnormSrgb` 且有像素数据的 Bevy `Image`。
- sRGB 与否沿用 glTF 加载器定好的格式，本层不推断；`ImageSampler::Default` 解析为线性采样。
- mip 级数按 `floor(log2(max(w,h))) + 1` 算。
- 如果材质把它当 normal/occlusion/base color/emissive 用，可以走 BCn 压缩支路（见第五节）；metallic-roughness 不压缩。

**对象记录**：48 B，字段是 `first_index / index_count / vertex_base / material_index / aabb_min / aabb_max`。它属于实例表，但在上传批次里跟网格一起搬。

## 三、第二关：搬运

`src/render/core/device/transfer/` 的 `Uploader` 把一批拷贝合成一次 transfer 提交，完成后用 timeline 信号量的单调值（`Ticket`，u64）表达“这批数据什么时候能用”。

**构成**：2 个轮转槽。每槽一块 staging（初始 1 MiB，不够时整槽扩容）、一条 transfer 命令缓冲、一条 graphics 命令缓冲（mip 续批用）、本槽最后一张票据。另有全工程共用的 timeline 信号量、`next_ticket` 和 `chain_ticket`。

`submit_batch` 的顺序：

1. 空批直接返回 `None`，不发票据。
2. 取下一个槽；若这个槽上一批票据还没完成，CPU 在这里等。**这是 staging 复用的唯一等待点。**
3. staging 不够大就整块换新（旧块的 transfer 读已被上一步证明完成）。
4. 把整批字节写进 staging（非 coherent 时自动 flush）。
5. 录制：buffer 拷贝 → 图像段 → 设备侧拷贝及其写后读屏障 → 队列族 release（生产路径为空）。
6. 提交到 transfer 队列，signal 新票据，fence 传空。
7. **提交成功之后**才记下本槽票据并让 `next_ticket` 加一。

**图像段**：

- 首次使用的图像从 `UNDEFINED` 迁到 `TRANSFER_DST_OPTIMAL`。
- 块压缩图像：整条 mip 链按块算术逐级拷入，收尾一次性迁到 `SHADER_READ_ONLY_OPTIMAL`。
- 多级未压缩图像：只拷 mip0，迁到 `TRANSFER_SRC_OPTIMAL`，留给 graphics 队列续批 blit；整链完成后再迁到可采样布局。
- 单级未压缩图：没有续批，直接迁到可采样布局。

**mip 续批**：blit 只能在 graphics 族命令池里录（transfer-only 池录 blit 违规）。所以有多级未压缩图时，上传器再向 graphics 队列提交一段：等 transfer 票据 N → 逐级 blit → 整链迁到可采样布局 → signal 票据 N+1。**发布给调用方的票据是 N+1。**

**票据单调性**：两条队列的 signal 不按提交顺序结算。上一次续批的 N+1 还没兑现时，下一次 transfer 提交若先 signal 更大的值，时间线会倒退。`chain_ticket` 就是为此保留的：后续 transfer 提交发现续批未完成时，先在自己的提交上等它。

**谁在等票据**：

| 等待方 | 怎么等 | 用在哪 |
|---|---|---|
| 图形提交（GPU 侧） | `queue_submit` 的 wait 列表，值取 `last_issued_ticket()`，阶段 `ALL_COMMANDS` | 每帧提交；等“截至目前发出的全部上传” |
| `Uploader::wait_until`（CPU 侧） | `vkWaitSemaphores`，超时 5 秒 | staging 槽复用、池扩容迁移、回收队列排空、fallback 白图 |

图形侧这次等待同时承担跨队列内存可见性：资源按 CONCURRENT 共享，没有所有权转移屏障，transfer 写对图形读可见全靠这条信号量依赖。

## 四、第三关之一：网格池

`src/render/resident/assets/pool.rs` 的 `MeshPool` 持有一条顶点池、一条索引池，全部 mesh 都住在里面。

**分配**：

- 懒建：第一次 `ensure_capacity` 才建池。
- `alloc` 先在空闲区间表里 first-fit 找空洞（整段用或切头留尾），找不到才推进 bump 游标。
- 顶点区间按 32 B、索引区间按 4 B 对齐，碎片不合并。
- `MeshSlot` 记两段区间、顶点/索引数、包围盒和**发布它的上传票据**；绘制引脚由区间换算：`vertex_base = 顶点字节偏移 ÷ 32`，`first_index = 索引字节偏移 ÷ 4`。
- `residency: HashMap<AssetId<Mesh>, MeshSlot>` 按资产身份去重。

**扩容迁移**：

```text
等全部在飞上传完成 → 建两条新池 → 设备侧整段拷贝 [0, used)
→ 等迁移票据 → 等全部帧槽 fence（没有在飞 draw 还在读旧池）
→ 换上新池、销毁旧池
```

这是一次显式停顿，记在 `MaintenanceLedger` 里，与正常上传分开计账。数据按原偏移平移，已发出的引脚不变。

**替换与卸载**：`replace` 和 `retire` 都把旧区间连同旧票据放进回收账，不立即复用。`drain_graveyard` 先等全部帧槽 fence，再按最大票据 `wait_until` 一次，然后把区间还给空闲表。

## 五、第三关之二：贴图与 BCn

链路是 `image_spec.rs`（规格）→ `bcn.rs`/`bcn_cache.rs`（可选压缩）→ `images.rs`（Vulkan 对象与缓存）。

**BCn 按材质角色选格式**：

| 角色 | 格式 | 说明 |
|---|---|---|
| normal | BC5 | 只保住 R/G（切线空间 XY），shader 采样后重建 Z |
| occlusion | BC4 | glTF 只读 R |
| base color / emissive | BC1 或 BC3 | alpha 全 255 用 BC1，有插值 alpha 用 BC3 |
| metallic-roughness | 不压缩 | 要同时保住 G/B，得 BC7；当前编码库没有，留在 RGBA8 |

烘焙流程：alpha 探测 → 选格式 → 源图边缘扩展到 4 的倍数（Vulkan 压缩格式要求 level-0 宽高是 4 的倍数）→ 2×2 box filter 逐级减半并逐级编码 → 各级块数据连排。编码用 texpresso 的 RangeFit 档，运行时烘焙承受不了离线级质量的时长。

**磁盘缓存**：键 = 烘焙版本 + 角色 + 宽高 + mip0 像素字节的哈希；文件头带魔数与版本，长度按块算术核对。命中直读，未命中现烤后写回（temp + rename）。缓存是优化不是正确性，损坏或版本不符按缺失处理。

**上传对齐**：块压缩图各级字节天然是块字节数的倍数；staging 排批时还要把整段起点对齐到块字节数（`bufferOffset` 必须是块字节数的倍数）。块压缩图不走 blit 续批，整条 mip 链由烘焙预生成、一次拷入。

**`GpuImage::create`**：

- OPTIMAL tiling，usage = TRANSFER_DST + TRANSFER_SRC + SAMPLED，建前核对格式的 optimal tiling feature。设备侧的 `textureCompressionBC` 在 `Context` 启用；具体格式能不能用，仍在 `GpuImage::create` 按 optimal tiling features 再查一次。
- 未压缩图缺 blit/线性过滤支持就降为单级；块压缩图按烘焙产物建全链级数。
- 每张图一块 dedicated `VkDeviceMemory`（必需 DEVICE_LOCAL），view 覆盖全部实际 mip 级。
- 采样器不在这里建：同参数的贴图共用一个采样器槽，采样器本体归 `BindlessTextureTable`（见《[绑定](绑定.md)》）。
- 跨队列族按 CONCURRENT 建。除了省所有权转移，还避开一个验证层误报：EXCLUSIVE + release/acquire 时，验证层对“已写入但还没被 draw 访问的 UAB 数组元素”的布局记录不随 release 更新。

**`ImageCache`**：`resident: HashMap<AssetId<Image>, (GpuImage, Ticket, SlotBinding)>`。

- `swap_commit`：新图入账；同身份旧图带旧票据进回收账，旧槽位交回 bindless 表。**必须在 `publish` 之后调用**，先发布新槽再交回旧槽，同参数采样器的引用数才不会中途归零。
- `retire`：卸载，同样进回收账、交回槽位。
- `drain_graveyard`：等全部帧槽 fence 加 `wait_until(最大票据)`，之后才销毁旧图。

## 六、一轮上传怎么串起来

编排在 `src/driver/upload.rs` 的 `flush_uploads`（`Last` 调度，在 `draw_frame` 之前）：

1. **排空回收账**：贴图、网格区间、bindless 待回收槽、对象表旧实例槽、overlay 图集旧代，各自判空，非空才等帧 fence。
2. **消费卸载事件**：驻留条目出账进回收账，下一轮第 1 步再排空。
3. **盘点脏行**：收集要传的 mesh、贴图和要写的对象记录。贴图按材质五槽反查角色。
4. **准备资产**：转换、规格映射、BCn 查缓存或现烤；未到货的下帧重试。
5. **容量与建图**：`ensure_capacity`、建 `GpuImage`，在一个 `Vec<u8>` 里连续排好网格两段、每张贴图数据、每条对象记录。
6. **一次提交**：`submit_batch`，拿到票据。
7. **提交成功后登记**：网格 `commit`/`replace`；贴图逐张 `publish` 拿槽位，再 `swap_commit`。

“提交成功才登记”保证失败路径不会留下指向未上传数据的账本行。

## 七、三种“完成”别混用

| 要证明的事 | 证据 | 不能替代 |
|---|---|---|
| CPU 写的字节对设备可见 | 非 coherent 内存 flush（`GpuBuffer::write` 内建） | 不能证明 GPU 已读完旧内容 |
| 上传拷贝已完成 | 时间线票据 | 不能证明图形 draw 已不再读旧位置 |
| 图形侧最后一次使用已结束 | 全部帧槽 fence（`wait_all_inflight`） | 不能证明上传完成：窗口最小化时上传仍提交，但没有图形提交 |

所以回收旧区间和旧图要等**票据和帧 fence 两个条件都满足**；bindless 描述符槽只等帧 fence。

## 八、检查点

- staging 槽什么时候可以复用？靠票据还是 fence？
- 多级未压缩贴图的 mip 链在哪条队列生成？为什么不能放 transfer 队列？
- `chain_ticket` 防的是什么时间线倒退？
- 一块 BCn 贴图从 Bevy `Image` 到可采样，改了哪些规格字段？哪一步保证 `bufferOffset` 合法？
- `metallicRoughness` 为什么没压缩？接 BC7 要改哪几处？
- 网格扩容迁移的顺序是什么？为什么迁移前要等在飞上传，迁移后要等帧 fence？
- 回收旧图/旧区间为什么要两个条件？bindless 槽为什么只需要一个？
- “提交成功才登记”防住了什么？
