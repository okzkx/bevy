# 绘制

这一篇读“每个渲染功能画什么”。每个 pass 都按四件事读：**写哪个目标、用哪条管线、绑哪些集、在帧内第几段**。算法细节放最后。

## 一、标准件

- `PipelineHandle`（图形管线）：`vk::Pipeline` + `vk::PipelineLayout` + 建管线时的 set 序列。`PipelineRef` 是它的轻量录制句柄。
- `FullscreenPipeline`（全屏管线）：画一个全屏三角形，无顶点输入，动态 viewport/scissor。
- `ComputeHandles`：compute 管线的录制句柄，绑定、push、一维 dispatch、交接屏障。
- `target/`：颜色/深度附件与格式常量。`HDR_FORMAT = R16G16B16A16_SFLOAT`，`DEPTH_FORMAT = D32_SFLOAT`。
- 录制助手：`bind_graphics`、`bind_vertex_index`、`set_viewport_scissor`、`color_attachment`、`load_color_attachment`、`reverse_z_depth_attachment`、`FullscreenPass`。

所有管线都走 `PipelineDesc::build`：先和 shader ABI 对账，再组装 layout、建 module、交给各自的状态装配。新加一条管线必须登记进 `layout_registry.rs`，否则契约测试报。

## 二、G-buffer：不透明物体写四份目标

`passes/gbuffer/` + `shaders/scene/gbuffer/gbuffer_write.wgsl`。

| 附件 | 格式 | 语义 |
|---|---|---|
| albedo | R8G8B8A8_UNORM | 线性反照率（采样端做 sRGB 解码，写入已乘 base_color） |
| normal | R16G16B16A16_SFLOAT | 世界空间法线 xyz 直存，w 未用 |
| matparam | R8G8B8A8_UNORM | r=metallic / g=AO / b=perceptualRoughness / a=reflectance |
| depth | D32_SFLOAT | reverse-Z：清 0、比较 `GREATER` |

- 逻辑槽 2 预留给 motion vectors，不分配，所以 matparam 的附件下标是 2。
- 每帧槽一套，随 swapchain 尺寸重建。深度本体归 `FramePool`，G-buffer 只借用视图。
- **一次 `cmd_draw_indexed_indirect` 画完所有不透明物体**；命令环由 build_indirect 写，`firstInstance` 带实例槽号。
- 不剔除背面（有双面材质），不混合；viewport 用正高度——Y 已在 shader 里由 naga 翻过，再用负高度会翻两次。
- 管线配方：set0 bindless / set1 frame / set2 instance，无 push。

## 三、阴影：四张固定尺寸的深度图

`passes/shadow/` + `shaders/scene/shadow/`。

- **四张 2048² 级联深度图**（`SHADOW_MAP_SIZE`），reverse-Z，清 0。尺寸固定，不随窗口 resize 重建：级联覆盖面和屏幕分辨率无关。
- **级联划分**：4 级 PSSM（log 与均匀按 λ 混合），覆盖 `SHADOW_NEAR_DISTANCE` 到场景 AABB 最远视深（夹在 min/max 之间）。高机位俯瞰时整场景仍在带内。
- **XY 拟合用切片包围球**：球半径只取决于切片形状，相机转动/平移不变，texel 世界尺寸恒定；盒中心在光空间按 texel 网格取整，阴影边缘不爬行。
- **深度向太阳侧延伸到场景顶**：比切片更靠近太阳的投射体必须在深度盒内，否则被近平面裁掉、缺影。
- **shadow 域全收在一个 set**：b0 UBO（736 B）、b1..4 级联深度图、b5 交错标记环、b6..9 四条 cascade 命令环。不动实例集。
- 两段工作：`shadow_build`（compute，读标记与 LOD 档位，逐 cascade 写命令）→ `shadow_write`（depth-only 图形管线，逐级联一次动态渲染 + 一次 indirect，共四次绘制；push 4 B = 级联索引）。
- 深度图**不分帧槽**，四张图跨帧共享；每帧进场从上一帧的片元采样读完开始（WAR），出场转可采样供合成读取。
- 矩阵、texel 尺寸、bias 全按世界量纲算，换级联不失真。

## 四、光照合成：全屏读 G-buffer 和光源分簇

`passes/lighting/` + `shaders/scene/gbuffer/gbuffer_composite.wgsl`。

- **分簇**：视锥切成 32 px tile × 32 深度片。`cluster_build` 每帧算每格被哪些点光照到；CPU 侧 `cluster_reference` 是同款参照，供 BRP `cluster_census` 对照。
- 光源本体在 `LightTable`，分簇集只在 b1 引用它；b0 是参数、b2 每格列表、b3 每格计数。
- **合成 pass**：全屏，无深度附件。set0 frame / set1 G-buffer 采样集 / set2 光源分簇 / set3 shadow。读 albedo/normal/matparam/depth，算完写 HDR 目标。
- 背景判定看 `depth == 0`（reverse-Z 远平面）。
- 着色模式（`FrameUniforms.mode`）可以让合成 pass 直出 G-buffer 单通道调试视图。
- 透明层在合成之后画，所以不透明光照先落 HDR，再把透明物体混上去。

## 五、透明层：GPU 自己收集、排序、出命令

`passes/transparent/` + `shaders/scene/transparent/`。

- **容量固定**：索引列表、深度键、命令环都按 `TRANSPARENT_CAPACITY = 16384` 分配；在场行超过它时 collect 直接报错。
- **三段 compute**：
  - `transparent_collect`：读 instance 集、光源分簇集、透明集，把 alpha < 1 的行写成索引列表，深度键按视深算。
  - `transparent_sort`：对固定容量做 bitonic 排序，空位键预填 `-inf`，真实条目推到尾部，gather 反向取。
  - `transparent_gather`：按排序结果写透明命令环。
- **透明前向**：合成之后，在同一个 HDR 目标上 `LOAD` + 混合，深度测试但不写。一次 indirect 消费透明命令环。
- 与合成之间没有光栅序保证：合成写 HDR → 透明混合读写必须有显式内存屏障；深度在本段从只读转回附件，⑥ 段 Hi-Z 再转回只读。

## 六、后处理：Bloom → tonemap → SMAA

`passes/post/` + `shaders/post/`。

- **Bloom**：HDR 域 dual-Kawase。prefilter（软膝阈值）→ N-1 级降采样 → 升采样（tent 上采样 + 对应级 down）→ `up[0]` 是半分辨率 bloom 纹理，供 tonemap 采样。三条全屏管线。
- **tonemap**：ACES 曲线，HDR + Bloom → LDR。写 LDR UNORM 中间目标，线性域，UNORM 只做 clamp。
- **SMAA（1x，三 pass）**：edge 检测 → blend 权重（读 edges + 两张 LUT）→ neighborhood 混合，最后写 swapchain。关闭时跳过 edge/blend，neighborhood 直通。
- **sRGB 只编码一次**：中间目标全是 UNORM 线性存储，最后写 swapchain 的 SRGB view 时 ROP 做唯一一次编码。
- 录制收在 `PostChainDraw::record`：Bloom → tonemap → SMAA → neighborhood；neighborhood 开渲染不关，UI 接在同一次渲染里按光栅序盖上去。

## 七、overlay：egui 的 GPU 侧

`passes/overlay/` + `shaders/ui/overlay_draw.wgsl`。

- egui 每帧镶嵌出顶点，经 `UiVertexRing` 写进宿主可见的顶点/索引环（`DynamicDraw` 角色）。
- 图集 `AtlasGpu` 管理字体图集和用户贴图；换图集走“新图发布 + 旧图延迟回收”，与贴图缓存同一套双条件。
- 管线只声明 set0（bindless 常驻表），UI 无 UBO。切换管线后 set0 要按本管线的 layout 重绑（同一个集，不同 layout 对象）。
- push 16 B：`screen_size`（points 域，与顶点同域）+ `tex_index` + `sampler_index`，逐 draw 打包。
- 深度格式照声明、读写全关：渲染实例带 D32 深度附件，未启用 `dynamicRenderingUnusedAttachments` 时管线 `depthAttachmentFormat` 必须与附件相等，不能填 UNDEFINED（VUID-08914）；“不用深度”靠关测试/写入表达。
- 混合用预乘 alpha（`ONE, ONE_MINUS_SRC_ALPHA`）；不剔除（epaint 不保证绕向）。

## 八、管线与布局登记

`src/render/layout_registry.rs` 是宿主建的全部管线与 set 的全量清单：22 条管线配方、13 份 set 声明。新增管线或 set 必须登记，否则 `layout_contract_tests.rs` 的 `every_shader_entry_has_a_pipeline` 会报。

`layout_contract_tests.rs` 是不需要 GPU 的契约测试：每条配方与 ABI 对上、每份声明自检通过且不重名、每个 shader 入口都有配方使用；负例覆盖 set 顺序互换、少 binding、种类错、阶段缺、runtime 数组缺 `PARTIALLY_BOUND`、push 缺失/偏小等。运行期还可以用 BRP 只读方法 `ash_renderer/layout_contract` 现场查看声明表。

## 九、检查点

- 读一个新 pass，先回答哪四件事？以 shadow 为例说出答案。
- G-buffer 三个颜色附件各是什么格式、什么语义？为什么深度采用 reverse-Z？
- 阴影为什么用四张固定尺寸深度图？级联 XY 为什么要按 texel 网格取整？
- 分簇网格怎么划？合成 pass 读哪几份数据？透明层为什么在合成之后？
- 透明层的 collect/sort/gather 各写什么？排序键怎么处理空位？
- Bloom、tonemap、SMAA 的顺序是什么？sRGB 编码在哪一步只做一次？
- overlay 的 push 16 B 各是什么？为什么深度格式不能填 UNDEFINED？
- 新加一条管线要改哪几处？契约测试会拦住哪些错误？
