# 路线

六段读序。顺序不是按目录排的，是按“一帧数据从哪里来、到哪里去”排的：先知道有哪些资源，再知道帧怎么转，然后依次看数据、取数、决策、组装。每一段都在前一段的基础上读，不会突然出现没见过的类型。

**每一段只问四个问题：这个东西谁持有、谁写、谁读、什么时候可以复用或销毁。** 算法细节放最后。

## 代码地图

路径相对 `ash_renderer/`。

| 位置 | 装什么 |
|---|---|
| `src/common/` | 横切工具：错误类型与统一通道、字节打包、错误处理语法糖 |
| `src/render/core/device/` | 设备地基：context、swapchain、内存契约与 buffer、队列传输与票据、诊断回读 |
| `src/render/core/target/` | 颜色/深度附件与格式常量 |
| `src/render/core/binding/` | 绑定契约：set 布局声明、shader ABI 表、管线布局配方与对账 |
| `src/render/core/pipeline/` | 管线骨架：图形、compute、全屏 |
| `src/render/core/record/` | 命令录制助手：绑定、屏障、dispatch、全屏 pass |
| `src/render/resident/` | 常驻 GPU 数据：网格池、贴图缓存、采样器、槽位分配、四张描述符表 |
| `src/render/passes/` | 渲染功能：可见性、G-buffer、阴影、光照、透明、后处理、UI |
| `src/render/frame/` | 帧槽、九段录制、功能输入束、场景资源规格、帧率同步、着色模式 |
| `src/render/stats/` | GPU 计时、帧样本账、监控历史 |
| `src/scene/` | ECS 侧场景机制与内容，零 Vulkan 调用 |
| `src/driver/` | 编排：初始化/拆除、上传、DrawList、帧循环 |
| `src/overlay/` | egui 调试 UI 的 GPU 侧与工具窗口 |
| `src/remote/` | BRP 远程通道：只读读数、写操作、场景编辑 |
| `shaders/` | `common/` 公共片段、`gpu_driven/` 可见性、`scene/` 场景、`post/` 后处理、`ui/` overlay |

## 第一段：先拿到全貌

**目标**：知道程序里有哪些 Vulkan 资源、谁建的、谁借谁、退出怎么拆；知道一帧由哪个系统驱动。

**读**：

1. `src/main.rs`：装哪些插件、禁哪些插件、为什么。
2. `src/driver/host/mod.rs`：init、上传、帧循环、拆除各在哪个调度。
3. `src/driver/host/init.rs`：把 `try_init_vulkan` 当目录读，只看参数和注释，不钻构造函数；最后看 `init_chain!` 的拆除顺序。
4. `src/lib.rs`：六个顶层模块的依赖方向。

**读完能回答**：

- 禁了哪些 Bevy 渲染插件？为什么 `PbrPlugin` 必须连带禁？
- `try_init_vulkan` 分哪五段？每段建了什么？
- 资源分成哪六类？`FrameUniformTable` 为什么在帧级阶段创建却算 GPU 表？
- 拆除顺序为什么不是创建顺序的倒序？举三条有真实借用关系的“A 先于 B”。

**深读**：[地基](地基.md) 的第一、二节。

## 第二段：帧怎么转起来

**目标**：一帧从 acquire 到 present，CPU 和 GPU 各自在等什么。

**读**：

1. `src/render/core/device/context.rs`：设备、两条队列、启用的特性、`MAX_FRAMES_IN_FLIGHT`。
2. `src/render/core/device/swapchain.rs`：输出格式、呈现模式、`PresentTarget`、过时重建。
3. `src/render/frame/frame_pool.rs`：每帧槽的命令缓冲、`image_available`、fence、深度附件；`render_finished` 在 swapchain 里。
4. `src/render/core/record/barrier.rs`：`ImageBarrier` 与 `MemoryBarrierDesc`。
5. `src/render/frame/record.rs` 的 ① 进场与 ⑨ 出场提交两段：先只看这两段，知道屏障和提交在哪里。

**读完能回答**：

- 为什么是两帧槽？帧槽和 swapchain image 为什么是两个循环？
- fence、binary 信号量、timeline 票据各管哪一段等待？
- fence 为什么在提交前一刻才重置？
- 屏障的 stage 和 access 分别回答什么问题？布局迁移为什么算一次写？

**深读**：[地基](地基.md) 的第三至七节。

## 第三段：数据怎么上显存

**目标**：一份 mesh 或贴图从 Bevy 容器到 GPU 可读，经过谁；旧数据什么时候能销毁。

**读**：

1. `src/render/core/device/memory/`：`role.rs` → `contract.rs` → `buffer.rs`。
2. `src/render/core/device/transfer/`：`types.rs` → `uploader.rs` → `uploader/image.rs`。
3. `src/render/resident/assets/mesh_convert.rs` → `pool.rs`。
4. `src/render/resident/assets/image_spec.rs` → `images.rs` → `bcn.rs`/`bcn_cache.rs`。
5. `src/driver/upload.rs` 的 `flush_uploads`：只读顺序，不追每个分支。

**读完能回答**：

- staging 槽什么时候可以复用？靠票据还是 fence？
- 多级未压缩贴图的 mip 链在哪条队列生成？为什么？
- 一块 BCn 贴图如何选格式、补边、对齐、上传？
- 网格区间和贴图的回收为什么要“票据 + 帧 fence”两个条件？
- “提交成功后才登记驻留”防住了什么？

**深读**：[数据](数据.md)。

## 第四段：shader 怎么取数

**目标**：一条 indirect 命令怎么让 shader 找到网格引脚、矩阵、材质、贴图和光源。

**读**：

1. `src/render/core/binding/set_layout.rs`：`SetLayoutDesc` 声明与自检。
2. `src/render/core/binding/descriptor_writer.rs`：按声明的写入校验与完备性。
3. `src/render/resident/slot_allocator.rs`：两种归还。
4. `src/render/resident/tables/`：bindless 表、帧 UBO、实例表、光源表。
5. `shaders/common/instance.wgsl`、`frame.wgsl`、`mesh.wgsl`；`shaders/scene/gbuffer/gbuffer_write.wgsl`；`shaders/gpu_driven/build_indirect.wgsl`。

**读完能回答**：

- set 编号为什么不是布局自带的属性？同一份声明在两三条管线里分别排第几？
- bindless 槽“按槽发布、从不写满”怎样通过写入器的完备性检查？
- 实例槽和材质槽为什么是两套索引空间？
- 一个材质记录 64 B 里每个字段由谁写、缺贴图时写什么？
- 跨端布局有哪三道防线？

**深读**：[绑定](绑定.md)。

## 第五段：GPU 怎么决定画什么

**目标**：场景有十万级实例时，CPU 不逐对象判断，GPU 上的可见性链怎么串。

**读**：

1. `build.rs` 的 ABI 段：`reflect_abi`、`assert_host_layout`。
2. `src/render/core/binding/shader_abi.rs`、`pipeline_layout.rs`：shader 表与管线配方对账。
3. `src/render/core/pipeline/compute.rs`、`src/render/core/record/compute.rs`：compute 建管线与录制；`Handoff` 六个变体。
4. `src/render/passes/visibility/`：`cull.rs` → `occlusion.rs` → `lod.rs` → `indirect.rs`，再看 `hiz.rs`/`hiz_frame.rs`。
5. `shaders/gpu_driven/` 共 6 个文件：可见性链读其中五个（`cull`/`occlusion`/`lod_select`/`build_indirect`/`hiz_downsample`），`cluster_build.wgsl` 属光照分簇，不在本段。
6. `src/render/core/device/readback.rs`：诊断回读。

**读完能回答**：

- `Handoff` 的六个变体分别对应哪些下游？屏障的 src/dst 各是什么？
- 剔除为什么一个 dispatch 同时产主视图和阴影视锥标记？
- 遮挡测试在哪几种情况下整段跳过？读数为什么是两帧前的？
- LOD 的阈值和迟滞怎么用？为什么没有跨帧真值？
- indirect 命令的 `firstInstance` 为什么等于实例槽号？透明行为什么 `instanceCount = 0`？
- Hi-Z 的“遮挡读旧、归约写新”为什么不需要额外跨帧同步？

**深读**：[可见性](可见性.md)。

## 第六段：把一帧画出来

这一段分两半读。

### 6a 渲染功能

**目标**：每个 pass 写哪个目标、用哪条管线、绑哪些集、在帧内第几段。

**读**：

1. `src/render/core/pipeline/graphics.rs`、`src/render/core/pipeline/fullscreen.rs`、`src/render/core/record/graphics.rs`、`src/render/core/record/fullscreen.rs`、`src/render/core/target/`：标准件。
2. `src/render/passes/` 按功能读：`gbuffer`、`shadow`、`lighting`、`transparent`、`post`、`overlay`。
3. `src/render/layout_registry.rs` 与 `layout_contract_tests.rs`：22 条管线、13 份 set 的全量登记与契约测试。

**读完能回答**：

- G-buffer 三个颜色附件各是什么格式、什么语义？为什么深度是 reverse-Z？
- 阴影为什么有四张固定尺寸的深度图，不随窗口 resize？
- 光源分簇的网格怎么划？合成 pass 读哪几份数据？
- 透明层为什么在合成之后画？collect/sort/gather 各做什么？
- Bloom、tonemap、SMAA 的顺序是什么？sRGB 编码在哪一步只做一次？

**深读**：[绘制](绘制.md)。

### 6b 场景与整帧编排

**目标**：ECS 侧的一份变更，怎么变成这一帧的环写入和一条提交。

**读**：

1. `src/scene/mechanism/assets/ledger.rs` → `residency.rs` → `assembly_cache.rs`；`asset_events.rs`、`asset_readiness.rs`、`lod_registry.rs` 按需。
2. `src/driver/upload.rs` 的 `flush_uploads`：这一遍细读每个阶段。
3. `src/driver/host/drawlist.rs`：可绘行与四个环。
4. `src/driver/host/frame.rs` 与 `frame/` 子模块：`draw_frame` 的顺序。
5. `src/render/frame/record.rs` 的九段录制；`render_features.rs` 与 `scene_resources.rs`。

**读完能回答**：

- 账本里一行存什么？哪些变更会置脏？
- 驻留管理器在 `Last` 里做什么？为什么排在 `flush_uploads` 之前？
- `flush_uploads` 的七个阶段各失败会怎样？
- 模型环、材质环、在场环、LOD 表环分别怎么更新？
- `draw_frame` 从 resize 到 present 的顺序；`FrameInput` 为什么卡在 16 个字段？
- 九段录制的段界为什么就是布局迁移点？每段的输入来自 `RenderFeatures` 还是 `SceneResources`？

**深读**：[编排](编排.md)。

## 走法

- 每段先读模块头注释，再读实现；模块头注释通常已经写了“谁写、谁读、容易错在哪”。
- 读到任何结构体，先找它的四个位置：持有者、写点、读点、回收点。找不到就先别往下读。
- 不确定的结论用 BRP 只读方法现场取数（`ash_renderer/layout_contract`、`cluster_census`、`transparent_sort_check` 等），不要靠记忆。
- 阅读中发现的疑问写成问题清单；确认后的结论再写成文档，不把猜测写成事实。
- 一次只读一段。读完一段先回答检查点，答不上来就回源码，不要带着空白进下一段。
