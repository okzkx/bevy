# 7.12.1-7.12.3-资产加载指示弹窗施工记录：latch判据、Background层弹窗与节拍集成

> 2026-10-21 当日立案当日施工收官（进度条→菊花的修订版，纯存在性提示）。结论先行：**弹窗判据三腿（进场根全展开 ∧ pending 清零 ∧ 票据在飞清零）+ 冷却 30 帧；菊花动画经 7.8 force_next 位自动逐帧直跑；Background 层零交互**。像素级读图本会话受 DLP 海报持续遮挡，判定线 1 的机制级证据已齐、像素证据如实报"未过（环境受阻）"。

## 0. 判据设计与钉明（7.12.1）

- **latch 制**（待决钉明，计划倾向）：`LoadActivity` 启动即 active——覆盖 glb 解析窗口（资产请求未发起、pending=0 的时段，账本差值判据漏亮）。
- **完成判据三腿**：①所有 `WorldAssetRoot` 已展开（根有 `Children` = 实体树已反射展开）；②`AssetReadiness` pending（mesh+image）清零；③Uploader 票据在飞清零（`last_issued_ticket <= completed_ticket`，completed 读取失败保守视作在飞）。
- **runtime 重载解析窗口补腿（实抓订正）**：首版判据在 BRP `load_world` 运行期重载时 3.3s 误收账（旧场景 primitive 仍在场 + pending=0 的解析时段被当完成）——补"进场根全展开"腿（占位根无 Children = 还在解析）后 runtime 窗口全覆盖。
- **失败路径（诚实语义）**：坏路径加载失败的根永无 Children = 菊花如实长转不消失（实测：坏路径后 pass 100% 持续直跑、无新收账行）；失败详情走 BRP readiness 既有读数，不误报完成。
- **冷却时长**（待决钉明）：30 帧 ≈ 0.5s——加载末期逐行到货的抖动不闪窗。

## 1. 弹窗本体（7.12.2）

- 右下 `egui::Area`（`Align2::RIGHT_BOTTOM`，offset −16pt）+ `Frame::popup` + `Spinner`(16pt) + "加载资产中…"一行文本——**计划待决 2 的文本行落定：带一行字**（位置语义更明确）。
- **零交互**：画在 `Order::Background` 层——`layer_id_at` 指针仲裁只认非 Background，弹窗不拦相机控制、不进面板仲裁面（机制钉明，计划待决项）。
- 不做进度口径（分母拼账全退役，菊花版不需要）——判据走 4.3 pending/账本稳态，bevy 0.20 无聚合进度 API 的限制不再构成约束。

## 2. 节拍集成（7.12.3）

- **加载期直跑**：菊花动画 `request_repaint`（delay ZERO）走 7.8 门控 `force_next` 消费位 + `panel_due` 显式并上 `load_activity.active` 双保险——加载期面板 pass 每帧直跑（实测：加载 35s 窗口 BRP 10Hz 轮询 pass_ms>0 **136/136 = 100%**；旧二进制的 6% 读数是 exe 被占用未替换的陈旧产物，重建后消除）。
- **稳态回落**：弹窗隐藏后动画触发自然消失，pass 回落 7.8 节拍（消失后 0.8s 内 8 连零 pass 实测）；隐藏后触发自然消失零成本。
- **新增子 pass 补记层可见性**（7.8 收官钉子的兑现检查）：弹窗画在面板 pass 内（非新子 pass），无需补记——7.8 的钉子在 7.12 的落点核对过，无新义务。
