> **一句话说明**：本段在宿主右下角加一个纯显示的小弹窗，进场加载期间显示旋转菊花、加载完成后自动隐藏；只做"在加载"的存在性提示，不做进度口径——分母拼账全退役，判据走 4.3 pending/账本稳态；不主张加载提速、不改 BRP 行为面。

## 0. 现状核实（2026-10-21 立案期，均源码复读/实测）

- **进场链现成、无任何加载提示**：`--scene <path>`（`scene/content/world_asset.rs`）→ WorldAsset 读盘解析 → 反射展开实体 → mesh/贴图异步加载（4.2/4.3）→ GPU 上传驻留。zero_day 全程 ~40s（含 10s warn = glb 解析大头，7.2 已归档口径），期间画面无任何提示——用户感知"没加载出来"。
- **菊花版不需要进度口径**：bevy 0.20 无聚合进度 API（属实，server/mod.rs:1053/1075/1123）——原立案为绕它拼三段分母；改菊花后整块退役，只需"加载活跃"布尔，4.3 `AssetReadiness` 的 pending 计数（pub 字段，flush 维护）即够。
- **加载活跃判据仍有解析窗口坑**：glb 解析段（~10s）资产请求尚未发起，`pending` 可能为 0——"活跃"判据须覆盖该窗口，否则菊花晚亮 10s（候选口径见待决）。
- **egui 原语在位**：`egui::Spinner` 内部走 `animate_value_with_time`→`request_repaint`；7.8 门控只认 `repaint_delay == ZERO` 强制位——动画的重绘请求**不会**自动触发面板 pass，须显式触发源（这是菊花版与进度条版同样要接 7.8 的原因）。

## 1. 任务拆解

### 7.12.1 加载活跃判据与完成判据

- 活跃判据钉明：覆盖 glb 解析窗口（pending=0 时段）；候选 = 启动 latch（进场期置位、readiness 稳态复位）vs `InstanceLedger` added≠processed——施工钉明（倾向 latch 制，语义最直白）。
- 完成判据钉明：pending 清零 ∧ Uploader 票据在飞清零（`last_issued_ticket` vs `completed_ticket`，upload.rs:294/308）；与"全行可绘"（BRP stats 口径）对照核。
- 失败路径：不单开显示——失败重试令 pending 非零则菊花如实长转（诚实语义），失败详情走 BRP readiness 既有读数。

### 7.12.2 弹窗本体

- 右下角 egui `Area`（anchor `RIGHT_BOTTOM`）+ `Spinner` + 一行固定文本（如"加载资产中…"）；纯显示零交互（不进指针仲裁面——弹窗命中区对 camera_control 的影响施工钉明，倾向不产生交互层）。
- 完成后自动隐藏（完成判据 + 短冷却稳态确认，防加载末期抖动闪烁）；菊花无进度语义，淡出机制不需要。

### 7.12.3 节拍集成与零回退

- 与 7.8 门控协同：加载活跃期置面板触发（**每帧直跑**——菊花动画要相位推进，0.5s 快照节拍会看着卡顿；加载期帧本就慢，pass ~0.15ms 量级可忽略）。
- 稳态回落 7.8 节拍，弹窗隐藏后触发自然消失、零成本。
- 交互零回退：弹窗存在期间相机控制/面板交互逐项过（弹窗不拦仲裁，施工实测钉明）；7.8 判定线读数不回归。

## 2. 判定线草案

1. **可见性**：zero_day 加载期弹窗出现且菊花在转（连拍截图，旋转相位变化=在转的证据）。
2. **消失收账一致**：弹窗消失时刻与"零 pending ∨ 全行可绘"BRP 读数一致（对照 stats/draw_stats）。
3. **零交互回退**：弹窗存在期间相机/面板交互零回退（悬停仲裁不受干扰，实测）。
4. **回归**：库测试全绿 + 九脚本抽测四条 parity；7.8 节拍行为零回退。
5. **工程闸门**：零 VUID、exit 0、clippy 全净（手工排版，禁 fmt）。
