## 定位与现状

三个挂账/观察项（属实，前段施工记录）：

1. **宿主唯一相机卫兵（7.2 首钉，机制缺陷）**：进场 glTF 带 camera 节点（zero_day 实抓）时 World 出现多相机，residency_stats/draw/取景 VP 的 `cameras.single()` 全崩。7.2 用压测脚本"保留最早实体"清理解堵——机制层无卫兵，任何真实场景带相机就复发。修复方向：进场场景的相机不接管取景（despawn 或标记排除），落点 scene/mechanism 或 remote/load_world 链，施工时定。
2. **egui 树窗性能观察项（7.2 遗留）**：实体层级树窗口开着时（15776 实体）fps 掉到 20（CPU p50 1.3ms 与 48ms 帧时间差 = egui 重建开销嫌疑，渲染链 p50 1.36ms 无恙）。裁决方式：开/关窗 A/B 帧时间对照实测，归因后按结论处置（egui 侧虚拟化属 egui 层改动，若确认为 egui 重建成本且影响使用，立外置条目或轻量修，不在此扩工程）。
3. **步骤级验收归档**：步骤 5/6 收官时步骤级验收归档均未做（路线图总览注记），步骤 7 收官时一并补齐——按[4-验收复核](../../4-可靠增量链路/4-验收复核.md)先例对账。

1. **相机卫兵**：zero_day（内嵌相机场景）load_world 后 residency_stats 无需脚本清理直接可用；多相机负例不再复发（sponza/zero_day/polyhaven 三脚本各自的相机清理解堵逻辑可退化为空转）。
2. **回归零回退**：九脚本全绿 + 库测试全过 + clippy 全净 + 零 VUID + exit 0。
3. **egui 观察项有结论**：归因明确（开/关窗 A/B 数据），处置落地或有据顺延。
