# 帧率同步流程：从开关动作到帧循环节拍的各级账面

面向下一个读代码的人：7.6 给宿主装了"帧循环节奏对齐显示器刷新率"的同步机制。这篇按"一个开关动作如何走到 winit 的 ControlFlow"走读全链，文末附代码改动简要解析。先钉一句语义：**"同步 vsync"= 帧循环节奏对齐刷新率（winit wait），不是 Vulkan present mode 切换**——swapchain 始终 MAILBOX（免 vsync 背压），本机制只动 bevy_winit 的 update 节流。

## 1. 各级账面全景

| 层 | 账面 | 谁写 | 谁读 |
|---|---|---|---|
| 设置 | `FrameSyncSettings`（enabled 默认 true + refresh_millihertz） | `apply_frame_sync` 回填读数；UI checkbox / BRP 写开关 | 三方共用 |
| 读数 | `Monitor.refresh_rate_millihertz`（bevy_winit 建 Monitor 实体） | bevy_winit 同步 OS | `apply_frame_sync` |
| 节拍 | `WinitSettings`（focused/unfocused 两档 `UpdateMode`） | `apply_frame_sync`（逐位不等才写） | bevy_winit 每轮循环重提取 |
| 呈现 | 监控窗口两行 + BRP `monitor_stats`/`frame_sync` | 只读 | 人 / 脚本 |

## 2. 逐时刻走读

**稳态帧（同步开，默认）**：`apply_frame_sync`（Update）→ 查主窗 `OnMonitor` 目标的 `Monitor`，回填 `refresh_millihertz` → 算目标两档 `reactive(1/refresh)` + `reactive_low_power(1/refresh)` → 与 `WinitSettings` 逐位比较，相等不写（零 change detection 噪声）→ bevy_winit 事件循环跑完 app 后重提取 update_mode（`state.rs:676-688`），Reactive → `ControlFlow::WaitUntil(next)`——update 每 1/refresh 秒醒一次，事件（拖拽/输入）仍即时唤醒。

**UI 开关**：checkbox 写 `FrameSyncSettings.enabled` → 同帧 `apply_frame_sync` 读到 → 关：聚焦档换 `Continuous`（跑满）→ 下轮循环生效。从点击到生效 ≤2 帧。

**BRP 开关**：`ash_renderer/frame_sync` 带 `enabled` → `RemoteLast`（Last 后）写同一资源 → 同一应用系统消费——UI 与 BRP 是同一状态的三个观察面，不养两份。

**刷新率不可用（头几帧 / Monitor 未就绪）**：读数 `None` → 同步开档位退回 reactive(1/60)（与历史初值同值）→ 读数就绪后下帧自动跟上，如实显示"不可用"。

**多屏**：只跟主窗 `OnMonitor` 所指显示器，跨屏拖动后 bevy_winit 更新关系，下帧自动换到新屏刷新率。

## 3. 失败与稳态路径

- `refresh_rate_millihertz` 为 `Some(0)` 病态值：过滤回 `None` 档（`Duration::from_secs_f64` 遇 inf panic，防线在此）。
- `WinitSettings` 资源：宿主插件自己 insert（历史初值），不依赖 WinitPlugin 时序。
- 禁渲染宿主：本机制全部在 host/overlay 层，不碰 Vulkan，照常工作。
