# 施工计划：帧率与刷新率同步拆解（7.6）

> **一句话说明**：本计划把"默认场景只有 60 fps"的需求拆成三步——先把宿主帧循环节奏从写死的 1/60 reactive 节流改成可观察可控制（刷新率读数 + 帧率同步开关 + 首次运行自动同步），再把读数与开关接进监控窗口 UI，最后补 BRP 读写通道供脚本无人值守 A/B；本计划不主张渲染机制特性，也不动 swapchain present mode（MAILBOX 保持）。

## 0. 现状核实（2026-10-21 立案期）

- **锁帧根因属实**：`ash_renderer/src/driver/host/mod.rs:67` 写死 `WinitSettings` reactive(1/60)（注释自述动机：MAILBOX 无 vsync 背压，默认 Continuous 会空转烧 CPU）。swapchain 本身 MAILBOX 免 vsync 背压（`vulkan/swapchain.rs:135`），**这个 reactive wait 就是唯一帧率上限**——7.5 收官记录"fps 锁 60.0"实为此节流，非渲染瓶颈。
- **刷新率读数可用（属实）**：`bevy_window::Monitor` 组件带 `refresh_rate_millihertz: Option<u32>`（`crates/bevy_window/src/monitor.rs:42`），Monitor 实体由 bevy_winit 创建，带 `PrimaryMonitor` 标记，Window 侧 `OnMonitor(Entity)` 关系指向所在显示器。
- **运行时改 WinitSettings 生效（属实）**：bevy_winit 每轮循环跑完 app 后重提取 update_mode（`crates/bevy_winit/src/state.rs:673-676`），Reactive → `ControlFlow::WaitUntil(next)`；`UpdateMode` 为 `Copy + PartialEq`，可整体比较避免逐帧重写资源。
- **UI 侧底座已有**：监控窗口（7.5）首行已显示 fps 当前值（FpsMeter 0.5s 快照）；加刷新率读数与同步开关不新增窗口、不新增采样节奏。

## 1. 任务拆解

### 7.6.1 帧率同步底座

- 新资源 `FrameSyncSettings`（住 `driver/host/frame_sync.rs`）：`enabled: bool` 默认 **true**（= 首次运行自动同步）+ `refresh_millihertz: Option<u32>`（应用系统每帧回填读数，UI/BRP 只读）。
- 应用系统 `apply_frame_sync`（Update，host 插件注册）：主窗 `OnMonitor` 目标的 `Monitor.refresh_rate_millihertz` 优先、`PrimaryMonitor` 实体兜底、都取不到 `None`（保持现状 1/60 并如实显示"不可用"）。
  - 同步开：聚焦/非聚焦两档 wait 都取 1/refresh（对齐现状两档同 1/60 的对应关系）。
  - 同步关：聚焦 `Continuous`（跑满，MAILBOX 无背压）、非聚焦保持 `reactive_low_power(1/60)` 节能。
  - 目标 `(focused, unfocused)` 与当前 `WinitSettings` 逐位相等则不写（避免逐帧 insert 噪 change detection）。

### 7.6.2 监控窗口增补

- 首行 fps 后并列屏幕刷新率读数（`屏幕刷新率 165 Hz` / `不可用`）；"同步 vsync" checkbox 写 `FrameSyncSettings.enabled`（开关即时生效——应用系统同帧读、下轮循环生效）。
- 不动调试窗口、不动采样节奏。

### 7.6.3 BRP 通道

- `monitor_stats` 增补 `refresh_millihertz` / `frame_sync_enabled` 两字段（tools/monitor.py 整包落 JSONL，零脚本改动）。
- 新方法 `ash_renderer/frame_sync`：`params.enabled` 可选——缺省只读返回 `{enabled, refresh_millihertz}`，带 `enabled` 则写开关（写侧同 cull_set_enabled 家族形状）；`tools/brp.py` 增子命令。

## 2. 判定线草案

1. **刷新率读数与系统实际一致**：监控窗口/BRP 读数与 Windows 显示设置对照同值。
2. **首次运行自动同步**：默认场景启动无人操作，monitor.py 采样 fps 稳态 ≈ 显示器刷新率（不再 60 封顶）。
3. **开关 A/B 生效**：BRP 关同步后 fps 明显超刷新率（跑满）；开回后 ≈刷新率；UI 读数与 BRP 同值。
4. **回归零回退**：库测试全绿 + 九脚本抽测（hiz/lod/stream/fine 至少各一）。
5. **工程闸门**：零 VUID、exit 0、clippy 全净。

## 3. 待决项

- **"同步 vsync"语义钉明**：= 帧循环节奏对齐显示器刷新率（winit reactive wait），**不是** Vulkan present mode 切换（MAILBOX 保持不变）——UI 文案与文档行文按此，避免与 FIFO-vs-MAILBOX 的 vsync 混淆。
- **非聚焦档取值**：同步开两档同 wait；同步关聚焦 Continuous、非聚焦保 reactive_low_power(1/60)（7.5 现状的节能语义不动）。
- **多显示器**：只跟主窗所在显示器；`OnMonitor` 每帧现读，跨屏拖动后下帧自动跟上新屏刷新率（如实记录，不单列判定线）。
