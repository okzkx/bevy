## 1. 实际做了什么

### 7.6.1 帧率同步底座

- 新模块 `driver/host/frame_sync.rs`：资源 [`FrameSyncSettings`]（`enabled: bool` 默认 **true** = 首次运行自动同步；`refresh_millihertz: Option<u32>` 每帧回填，UI/BRP 只读）+ 应用系统 `apply_frame_sync`（Update，宿主插件注册）。
- 刷新率读取：主窗 `OnMonitor` 目标的 `Monitor.refresh_rate_millihertz` 优先，`PrimaryMonitor` 实体兜底，都取不到 `None`（保持 1/60 并如实显示"不可用"）。`OnMonitor` 在窗口创建后才插入——头几帧 `None` 属正常时序，读数就绪后自动跟上（实测宿主启动首查即有读数）。
- 档位维护（按计划待决钉明）：
  - **同步开**（有刷新率读数）：聚焦 `reactive(1/refresh)`、非聚焦 `reactive_low_power(1/refresh)`——两档同 wait，非聚焦保持 low_power 节能形态（对齐历史两档同 1/60 的对应关系）。
  - **同步关**：聚焦 `Continuous`（MAILBOX 无背压跑满）、非聚焦保 `reactive_low_power(1/60)` 节能。
  - 目标与当前 `WinitSettings` 逐位不等才写（避免逐帧 insert 的 change detection 噪声）；刷新率读数为 0 的病态值过滤回 `None` 档（`Duration::from_secs_f64` 遇 inf 会 panic，属"非必要不 panic"防线）。
- `mod.rs` 接线：`init_resource::<FrameSyncSettings>()` + `add_systems(Update, apply_frame_sync)`；原写死的 `WinitSettings reactive(1/60)` 保留为"显示器信息就绪前的初值"（注释钉明）。

### 7.6.2 监控窗口增补

- `MonitorWindow` 增 `frame_sync: &mut FrameSyncSettings` 输入（`DebugUiParams` 增 `ResMut<FrameSyncSettings>` 一员，不撑 pass 签名）。
- 首行 fps 后新增两行：`屏幕刷新率 59 Hz`（不可用时如实显示）+ `同步 vsync` checkbox（悬停提示钉明语义"帧循环节奏对齐显示器刷新率（winit wait），非 present mode 切换；关闭后聚焦时全速跑满"）。checkbox 即时生效——`apply_frame_sync` 同帧读、bevy_winit 下轮循环生效。

### 7.6.3 BRP 通道

- `monitor_stats` 增补 `refresh_millihertz` / `frame_sync_enabled` 两字段（tools/monitor.py 整包落 JSONL，脚本零改动——实测同包读出）。
- 新方法 `ash_renderer/frame_sync`（住 `remote/monitor.rs`）：`params.enabled` 可选——缺省只读返回 `{enabled, refresh_millihertz}`，带 `enabled` 则写开关（同 `cull_set_enabled` 家族形状）；参数 null/缺省走只读分支。
- `tools/brp.py` 增 `frame-sync` 子命令（`--enabled true|false` 可选，缺省只读）。

## 2. 待决项落定（计划 §3 三项）

- **"同步 vsync"语义**：= 帧循环节奏对齐显示器刷新率（winit reactive wait），**不是** Vulkan present mode 切换（MAILBOX 保持不变）——checkbox 悬停文案、模块注释、BRP help 文案三处按此钉死。
- **非聚焦档**：同步开两档同 wait（非聚焦保 low_power 形态）；同步关联焦 Continuous、非聚焦保 reactive_low_power(1/60)。7.5 现状的节能语义不动。
- **多显示器**：只跟主窗所在显示器（`OnMonitor` 每帧现读，跨屏拖动后下帧自动跟上新屏刷新率）；`PrimaryMonitor` 兜底覆盖主窗关系未就绪的窗口期。未单列判定线（按计划）。
