## 1. 两层 pass 节拍化（7.8.2，实际做了什么）

**触发集落定**（代码即文档，`run_egui_pass` 触发判定段）：

- 面板层：首帧 ∨ fps 快照到期（0.5s）∨ 窗口尺寸/ppp 变化 ∨ egui 自身请求立即重绘 ∨ `DebugWindowsOpen`/`SelectedEntity`/`EntityTreeState` 资源 Changed ∨ 面板相关输入事件。指针移动事件**只在**"悬于 UI 层（`layer_id_at` 非 Background，与 camera_control 仲裁同式）或拖拽始于 UI"时才算触发——纯场景上的移动（漫游环视）不重跑面板。
- gizmo 层：首帧 ∨ 尺寸/ppp 变化 ∨ 显隐变化 ∨ 相机旋转变化（gizmo 只表达旋转，平移不重画）。环视拖拽期间 gizmo 每帧重跑（~0.1ms 量级），面板层冻结在缓存——立案期"相机变化触发全量则优化白做"的担忧由此拆掉。

**两层 pass 形状**：egui 0.36 的 begin/end pass 每趟独立（`context.rs:418/2664`——`viewport_stack` 成对进出、`cumulative_pass_nr` 逐 pass 递增），同一帧连续两对合法。面板 pass 吃真实事件（含积压合并）；gizmo pass 只喂 `screen_rect/time/focused` 空事件——指针/按键状态由 egui 跨 pass 自持，事件不重复消费。插件钩子抽成 `plugin_hooks_begin/end`，两 pass 各自完整配对（LabelSelectionState 纪律不变）。

**镶嵌按代数复用（本段成立前提的钉子）**：`ClippedShape` 直持 `Shape` 非 Arc（epaint `lib.rs:117`），"跳过帧从缓存深拷贝 shapes 补齐"每帧要付几 MB 级 memcpy+分配，会吃掉优化收益——复用下沉到**镶嵌产物**：`OverlayLogState` 存 `(shapes 代数, Vec<ClippedPrimitive>)` 两层各一份，shapes 代数未变的帧直接复用缓存产物，pass 帧才重镶嵌。egui 官方在 `tessellate` 注释里自注"shapes 相等即复用"不值得做（逐形状比较占 tessellate 一半成本）；按代数判等零比较成本，绕开该顾虑。顶点环写入按计划边界保留逐帧执行（≤1.6MB memcpy）。

**积压语义（待决 1 落定：合并喂入）**：桥侧新增 `pending` 账——面板 pass 跳过帧的事件攒账（桥簿记无条件更新、读取器每帧排空的纪律不破），下次 pass 旧事件在前一次性喂入；连续 `PointerMoved` 折叠成最后一条（指针用最新值，`PointerGone` 与其余事件保序保留）；门控翻转帧（跳过 ≥1 帧后的首个 pass）补发一次当前位置——悬停高亮不冻结在旧形状。实测拖选/环视无丢帧感。

**快照底座移位（待决 2 落定：复用 FpsMeter 0.5s 节拍）**：`fps.tick` + 监控历史采样 + 分位缓存刷新从 pass 内移到系统入口每帧执行——跳过帧照常推进采样账（"窗口显隐不影响记账"语义保持），快照到期即置面板触发。

**egui 自身重绘请求消费**：面板 pass 出口读 `viewport_output[..].repaint_delay`，为 0 即 egui 要求下帧立刻重画（动画/悬停渐变/文本光标闪烁）→ 置 `force_next`。官方集成同款消费路径，egui 自管动画不因节拍化冻结。

**系统参数收拢**：触发判定引入 7 个跨帧 Local，`run_egui_pass` 参数表达 22，超 bevy 16 上限——收拢成 `PassGate` SystemParam 束（DebugUiParams 同款打法）。

**逐帧写资源陷阱的两枚处置**：①`apply_frame_sync` 的无条件写——本段不把 FrameSyncSettings 列入触发集，frame_sync.rs **零改动**；②`collect_selected_details` 每帧 insert——不列触发源（预存边界），`SelectedEntity` 的 Changed 作为点选联动触发（点击帧写 → 下帧 collect 出新快照 → pass 显示，实测一帧内生效）。

## 2. 字符串节拍化（7.8.3，设计决定如实记）

pass 节拍化后 `format!` 只发生在 pass 运行帧（事件/快照频率，稳态 ~2Hz），egui shaping 缓存按内容命中承担"快照未变行不重排版"——两者合计兑现计划目标，**不另建 Rust 侧字符串缓存**：那会重复 shaping 缓存的职能（内容键命中的排版复用），违反"已重复模板必须下沉"的判据。逐帧必变的行（诊断读数在运动期）如实保留 miss，属内容侧必要成本。

## 4. 待决三项落定

- **积压语义**：合并喂入（旧事件在前 + 指针最新值 + 门控翻转帧补发当前位置）——实测无丢帧感，落定。
- **快照到期归属**：复用 FpsMeter 0.5s 节拍，tick 移出 pass 到每帧门控底座——落定。
- **max_passes/图集交互**：跳帧不影响字形栅格化与图集代际——截图字形正常、图集整传/代数/停尸房排空日志正常，零回退，落定。

## 5. 钉子

- **ClippedShape 非 Arc**：shapes 复用不能靠深拷贝补齐，镶嵌代数缓存是整个复用设计成立的前提（本段最大的形状订正）。
- **egui 多趟 begin/end 合法**：pass 是 egui 的节拍单位而非"帧"——本段设计的合法性依据（源码行号见 §1）。
- **参数 16 上限**：新增跨帧状态一律走 SystemParam 束，不再撑签名。
- **预存缺陷两枚（建议 F28 一并挂账）**：虚拟鼠标点击 checkbox/[×] 不生效（树行 selectable_label 生效）；树窗滚轮滚动无效（默认态无溢出 + 溢出态也不滚，7.7 记录已留"未深测"口）。
- **环视期间 pass 尖峰观察项**：快照帧与重负载同帧叠加时 egui_pass_ms 可到 ~24ms（24 样本中 2 次，dev 构建）——不拦判定线，7.10/7.11 归因时复核。

## 6. 边界如实记

- 复用帧的顶点环写入仍逐帧执行（计划 §2.5 边界保留）；tessellate 已随本段免掉。
- 跳过帧面板内容（剔除/LOD 诊断读数等）延迟到下一 pass 才上屏，0.5s 快照兜底；BRP 直读读数不受影响。
- `collect_selected_details` 仍每帧采集（未动），属 7.10 归因候选。
- 面板全关底价 0.55ms 未复测——本段收益集中在"面板开着"的开发态。
- 环视拖拽期间面板层静止（fps 等读数最多 0.5s 不刷）——环视优先的设计取舍，快照兜底。
