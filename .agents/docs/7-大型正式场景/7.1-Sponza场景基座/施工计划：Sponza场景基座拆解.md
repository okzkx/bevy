# 施工计划：Sponza 场景基座拆解（7.1）

**一句话说明**：本段把 Khronos Sponza（已拍板首推场景）接入 ash_renderer 现有加载链与 4.x/6.x 账面，让步骤 7 有长期验收场基座并为 7.2/7.3 提供对照基线读数；本段只做内容接入与核验，不主张任何渲染画质特性（归步骤 8/9），也不做剔除/LOD/流送的机制扩展。

立案日期：2026-10-20（随步骤 7 拆解立案；施工用 `/plan-execute` 开工）。上游拍板见[路线图步骤 7 节](../../学习目标实现步骤.md)。

## 定位与现状核实

Sponza 是 GI/遮挡剔除的业界经典室内场景：单 mesh、103 primitive、25 材质、69 贴图（属实：解析 `assets/sponza/glTF/Sponza.gltf`，2026-10-20）；贴图槽用 baseColor + metallicRoughness + normal 三种，无独立 AO/emissive 槽。规模约 14MB，相对 6.3 驻留预算（默认 0=全常驻）零压力——它检验的是**加载链与账面在真实资产多样性下的正确性**，不是规模；规模归 7.2 zero_day。

现状核实（属实，2026-10-20 代码出处）：

1. **进场形状**：`scene/content/world_asset.rs` 三行进场（load + spawn + 轮询到货），FlightHelmet 路径写死在常量；换场景 = `SceneEntryPlugin` 组清单增删组（`scene/content/mod.rs` 组机制注释钉明"一个元素 = 一个 spawn + 一个就位核验"）。
2. **期望值内容耦合**：到货报告（`report_scene_arrival`）与采集核验（`collect_report.rs`）的期望值（"期望 6"）写死在 content 层随场景走，注释自认"随当前场景写死"——换 Sponza 必须同步改写。
3. **资产根**：`main.rs` AssetPlugin `file_path` 编译期拼仓库根 `assets/`，Sponza 落位 `assets/sponza/glTF/Sponza.gltf` → AssetServer 路径 `sponza/glTF/Sponza.gltf`（用户已预落贴图与主文件，Khronos 布局）。
4. **驻留默认全常驻**：`ResidencySettings` 默认 `budget_mesh_bytes: 0`（不设预算），Sponza 全量驻留无压力；预算行为可经 BRP `residency_set` 运行时改——预算负例可低成本做进本段。
5. **观察面**：BRP 端口 15702（tools/brp.py），residency_stats/cull_stats/gap 族 6.x 已就位；5.5 计量底座（GPU 帧计时/分位数）直接复用；场景脚本化定例（6.2.1）= 生成序列落 tools/ Python 脚本。

## 判定线草案

1. **加载零失败零 panic**：Sponza 进场 10s 内到货，到货报告 primitive=103、材质=25、贴图=69（+内置 2）与解析清单一致；全程零 panic、exit 0。
2. **画面读图**：中庭+柱廊结构可见、baseColor 贴图正确上墙、无 fallback 白图泛滥、无全黑——读图对照按画面功能视觉验证规则执行。
3. **账面零泄漏**：Mesh/StandardMaterial/Image 容器数与 InstanceLedger/residency_stats 账面一致；静态游历零重传；wm_close 退出干净。
4. **预算负例**：小预算下无悬空引用/幽灵绘制，恢复预算 0（全常驻）后画面回到基线——A/B 开关语义沿用 6.3 口径。
5. **工程闸门**：clippy 全净、库测试全过、零 VUID、exit 0。
