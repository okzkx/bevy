# 施工计划：帧残余区归因收账拆解（7.11）

> 2026-10-21 立案。帧治理四段（7.8~7.11）收账段——F26（zero_day 帧时间空洞）的正式立案承接。
>
> **目标口径（2026-10-21 用户校准）**：全静态/纯漫游场景的帧 CPU 应≈宿主底价（1ms 级）——静态场景合法的每帧 CPU 工作只剩"拿交换链图像 + 录恒定小命令 + 提交 + present"，全部"每帧全量重算"类常驻项都应清成事件驱动；本段列账即以此口径验收。

> **一句话说明**：本计划把 `frame_wall_ms − cpu_total_ms` 的未计时区（Last+winit 区 ~8ms + First/PreUpdate ~1.5ms，2026-10-21 粗口径实测）按段劈细归因——draw_frame 各段之外还有什么在花帧预算、各花多少；可修小项顺手修，结构级大项如实立账写明去向；本段不主张重写帧循环 runner 结构、不主张改 winit/执行器。

## 0. 现状核实（2026-10-21 立案期）

- **缺口仪器在位（属实）**：`FrameSample.frame_wall_ms`（相邻两次 draw_frame 起点的墙钟间隔）+ `cpu_total_ms`（wait/acquire/assemble/rings/submit/present 六段合计）——差值即"未计时区"，7.5 落地的 F26 方向仪器，BRP perf_stats/perf_samples 已可读（frame_wall 尚未序列化进 perf_samples，施工时补字段）。
- **粗口径实测（2026-10-21）**：zero_day 稳态 wall ~29ms、cpu_total ~9.5ms → 未计时区 ~19.5ms（含调度段已测的 Update/PostUpdate ~14.6ms——7.8/7.9/7.10 各归其主后，本段只兜"Last 调度内 draw_frame 之外 + winit/执行器胶水 + First/PreUpdate"的残余）。
- **打点探针的两枚坑已钉（7.8 立案期实抓）**：①调度内无序打点的触发点漂移（分段口径噪声，打点系统必须显式锚定）；②Last 段含 draw_frame（打点劈不出 draw_frame 与 winit 的边界，需要 frame_wall 与 cpu_total 差值口径互补）。
- **本机环境钉**：DLP 反调试拦截进程外线程采样（RIP 恒 0）——归因只能进程内仪器。

## 1. 任务拆解

### 7.11.1 残余区劈细

- `frame_wall_ms` 序列化进 perf_samples（补字段，离线汇总用）。
- 有序打点劈 Last 段：flush_uploads（draw_frame 之前）与 draw_frame 之外的部分逐段计时；First/PreUpdate 段复核。
- 执行器/winit 胶水量化：app.update() 墙钟 vs 各调度段合计的差 = 执行器+事件循环成本，实数钉出。

### 7.11.2 治理与立账

- 可修小项（候选，以归因实数为准）：可缓存分配、无谓系统空转、诊断读数的逐帧成本。
- 结构级大项：如实立账写明去向（F 挂账/引擎侧议题），不硬凑"已修"。
- **tessellate 门控候选（2026-10-21 用户校准口径后升格）**：7.8 复用帧的 overlay shapes 未变仍逐帧重镶嵌（paint_overlay 的 tessellate+顶点环写入）——静态面板下也是常驻白烧，按"shapes 未变即复用镶嵌结果"门控；归本段或 7.8 施工时按耦合度钉明。

### 7.11.3 F26 裁决与回归

- F26（zero_day 帧时间空洞）在本段收敛：缺口劈细后若真凶已在本段或 7.8~7.10 治理，关闭；仍有残差则转正写明。回归：九脚本抽测 + 库测试 + 零 VUID + exit 0 + clippy 全净。

## 2. 判定线草案

1. **缺口列账**：frame_wall − cpu_total 差值按段列账（每段毫秒实数），四段治理前后对照。
2. **可修项有实数**：修的项有前后对照，立账项有去向。
3. **F26 有裁决**：关闭或转正，写明证据链。
4. **工程闸门**：库测试全绿 + 九脚本抽测零回退 + 零 VUID + exit 0 + clippy 全净。
