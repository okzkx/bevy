# 7.7.1-7.7.3 egui 重建裁剪施工记录：基线取证、树拍平缓存与视口裁剪构建

> 2026-10-21 `/plan-execute 7.7` 当日施工收官（分支 `goal/7.7`，起点 main=81fecf54b）。三个任务同日连续施工；代码改动简要解析在[流程导读](egui树重建裁剪流程：从脏信号到视口行的各级账面.md)文末。

## 1. 实际做了什么

### 7.7.1 基线取证

- 优化前实数（egui pass 墙钟 p50，`EguiPassTiming`/monitor.py 采样，取证落 `.temp/7.7/`）：
  - zero_day（16156 实体 / 15670 相关）：树窗开 **9.05 ms** / 树窗关 4.98 ms——树窗份额 ~4.07 ms/帧。
  - 轻场景（~490 实体）：树窗开 5.23 ms（基线构建同配方补测）——实体少时全量重建本来就便宜。
- 说明：默认场景 Sponza 资产本机缺失（`assets/sponza/` 为空目录，7.6 施工记录已挂账），基线与优化后对照统一用 zero_day 满规模 + 轻场景两端取证。

### 7.7.2 树拍平缓存（脏重建）

- 新资源 `EntityTreeState`（住树窗模块）：`rows: Vec<TreeRow>`（拍平等高行：entity + depth + label + has_children + expanded）、`relevant`/`total` 计数、`dirty: bool`、`expanded: HashMap<Entity, bool>`（展开状态自持，首见按历史默认"深度 < 2 展开"落账，不靠 egui 记忆倒推）。
- **脏信号 = 三观测器**（OverlayPlugin 注册）：`On<InsertEvent>`（实体 spawn 与组件替换，含换柄）/`On<RemoveEvent>`/`On<DespawnEvent>` 裸事件（无组件模式，`EventPattern` 对 `Event` 有 blanket impl）任一触发置脏——实体增删、层级变更、Name/Mesh/材质标签形态变化全覆盖。观测器用 `Option<ResMut>` 兜 Startup 期资源未插的窗口期。稳态（无事件）零成本。
- **重建只在维护系统**（`maintain_entity_tree`，Update 链上先于采集与 egui pass）：脏才全量走访（relevant 表形状同 BRP `scene_tree`），只收展开节点成等高行，同时清扫展开态账里的死实体；稳态直接返回——`Query` 不迭代、零分配。
- Name 的 `Mut` 改写不走 Insert 不触发重建——本工程 Name 只在进场/spawn 时写入（走 Insert），边界如实记录。

### 7.7.3 视口裁剪构建

- 树窗滚动区改 `ScrollArea::show_rows(ui, row_height, rows.len(), …)`：每帧只构建视口内行（几十行），与实体总数解耦；行高取 `interact_size.y` 与 Monospace 字高的较大者，逐行 `set_height` 钉死 stride（滚动算术不失真）。
- 折叠头从 `CollapsingHeader` 改**自绘箭头行**（▸/▾ + selectable_label，等高、无动画——动画高度会破坏等高前提）；点击行为与历史一致（展开/收起 + 选中）。展开/收起在闭包外写展开态账并置脏，下帧重建生效（≤2 帧延迟）。
- 属性区（SelectedDetails 采集/渲染/TransformDragCache 拖拽/编辑队列）零改动；点选落账走同一 `SelectedEntity`。

## 2. 待决项落定（计划 §3 三项）

- **拍平结构与展开状态归属**：归**树窗私有**（呈现态）。共享层 = `is_relevant`/`node_label`/`EntityRow` 三件套（单实现未动），BRP `scene_tree` 不吃 UI 缓存——它是一次性嵌套序列化，接缓存反而引入 UI 态耦合。"不养两份逻辑"以共享语义三件套为准绳守住。
- **滚动锚定**：完全交给 egui `show_rows` 原语（行单位偏移），自管偏移未启用。默认展开态树内容不溢出（~10 行 < 380pt 上限），滚轮深滚未逐一深测——行为背书来自 egui 标准原语而非本段代码。
- **收益边界**：字体图集/绘制半边不受益（照计划预期）；计划行文提到的"过滤词"在现 UI 并不存在（无此功能，无语义可回退）——如实记录，不虚构判定项。

## 3. 判定线对照（计划 §2 五条）

1. **基线证据链** —— ✅ zero_day 同场景树开 pass 9.05 → 6.92 ms（−24%），树窗份额 4.07 → 1.77 ms（−57%）；轻场景树开 5.23（基线）vs 5.21（优化）持平。解耦实锤：实体 490 → 16156 时基线树开成本 +3.8 ms（随实体数线性走），优化后仅 +1.7 ms（残余 = 可见行数差与窗体布局，非重建）；优化后稳态 15 s 采样 max 5.82 ms 零重建尖峰（重建只在事件帧发生）。顺带把 Update 侧省出的 ~3 ms 还给帧预算（同机位 fps 30.7 → 36 一例）。
2. **交互零回退** —— ✅ 展开/收起往返（BRP 虚拟鼠标点击 + 截图对照，子行出现/消失、缩进正确）；点选联动属性面板（选中高亮 + 详情区 populated）；拖拽编辑写通全链（平移 X 0 → 1.0 = 20 pt × speed 0.05 精确命中、旋转 X −0° → 25°，`world.inspect` BRP 读回核对）；过滤词无此功能（见上）。一处微小视觉变化如实记录：选中高亮统一为 selectable_label 内建样式（历史折叠头是自染浅蓝、叶子是内建样式，现两种形态统一）。
3. **不养两份逻辑** —— ✅ 共享三件套单实现未动；BRP `scene_tree` 与树窗同源同数（relevant 15670 / total 16160 两侧一致，实测）。
4. **回归** —— ✅ 零回退：库测试 29/29；hiz 6/7（⑤ 既有挂账）、lod 7/7、fine 7/8（④a 既有挂账）、stream 3/7（既有，main 基线同败已差分）——失败集合与 7.6 期基线完全一致。
5. **工程闸门** —— ✅ 零 VUID（两次运行日志验证层零命中）、exit 0（WM_CLOSE 优雅退出 ×3 次实测）、clippy 全净（all-targets）。

## 4. 钉子与遗留

- **箭头字形**：首版用 U+25BE/U+25B8，两款已装字体（Ubuntu-Light + msyh）皆缺字渲染豆腐；换 U+25BC/U+25B6（msyh GB2312 区有字形）实测可渲染。egui 图标走 painter 绘制不受字体影响，自绘文本箭头必须选字体里真实存在的码位。
- **虚拟鼠标拖拽坐标换算**：PrintWindow 图像坐标 → 客户端 points 的纵向偏移实测 ~57 px（非标题栏 31 px 的直觉值，含非客户区加成）——首拖命中旋转行而非平移行即此坑。
- **观察项**：zero_day 场景 GPU-bound ~30 fps 与 F26（帧时间空洞）口径一致，本段 Update 侧收益不改变 F26 归属。
