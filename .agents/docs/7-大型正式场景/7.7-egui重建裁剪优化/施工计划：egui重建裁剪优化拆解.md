# 施工计划：egui重建裁剪优化拆解（7.7）

> **一句话说明**：本计划把实体树窗口从"每帧全量重建全部实体行"改为"拍平缓存 + 只构建可见行"——树拍平成等高行数组、只在结构脏信号时重建、每帧仅声明视口内的行（egui `ScrollArea::show_rows` 原语）；本计划不主张任何新 UI 功能，也不改 BRP `scene_tree` 的行为面（共用行语义不养两份）。

## 0. 现状核实（2026-10-21 立案期）

- **全量重建属实**：实体树窗口（`overlay/windows/entity_tree_window.rs`）每帧对全部相关实体跑 `EntityRow` 查询、逐实体算 `node_label`（含 String 分配）、声明整套 widget——立即模式"每帧重建的是声明"，看不见的行也全量声明。zero_day 7159 行规模下 pass 求值是数量级开销。
- **tessellate 侧已有裁剪、不受益**：clip rect 外的形状在镶嵌时被丢弃——裁剪收益的主战场是 pass 求值与逐帧分配，不是绘制半边。
- **虚拟化原语在位（属实）**：egui 0.36 `ScrollArea::show_rows(ui, row_height, total_rows, |ui, range|)` 按滚动位置算可见 range，调用方只构建 range 内的行；树行等高、按深度缩进，符合等高前提。
- **脏信号基建现成**：4.1 变更发现（Added/Removed/账本）与 `is_relevant`/`node_label` 共享层（模块注释钉明 BRP scene_tree 与 egui 树同一套语义、不养两份逻辑）。
- **测量仪器在位**：7.5 `EguiPassTiming`（Update 侧 egui pass 墙钟）可直接出基线与优化后对照。

## 1. 任务拆解

### 7.7.1 基线取证

- 默认 Sponza 与 zero_day 两场景，`EguiPassTiming` 读数 + monitor.py 采样树窗开/关两态的 pass 毫秒——把"全量重建"的实数钉出来，作优化前对照基线。

### 7.7.2 树拍平缓存（脏重建）

- 展开状态自持（Resource，按实体 Id；不靠 egui 滚动/记忆状态倒推）。
- 拍平：展开子树 → 等高行数组（行 = 实体 + 深度缩进），只收展开节点；**只在结构脏信号时重建**——实体增删（4.1 变更发现）、展开/收起、过滤词、Name/相关性变化。
- 稳态（无操作无变化）零重建，每帧只读行数组切片。

### 7.7.3 视口裁剪构建

- 树窗改 `show_rows`：每帧只构建可见区间行（几十行），与实体总数解耦。
- 交互零回退：点选（SelectedEntity）、拖拽编辑（TransformDragCache/编辑队列）、过滤词、属性面板联动全部保持现语义。
- BRP `scene_tree` 行数据、`is_relevant`/`node_label` 复用关系不破坏——拍平结构落哪侧施工时钉明（倾向：共享的行数据层，CLI 树与 egui 树同源）。

## 2. 判定线草案

1. **基线证据链**：优化前后同场景同机位 pass 毫秒对照，稳态每帧成本与实体总数解耦（zero_day 7159 行级对照）。
2. **交互零回退**：展开/收起、点选联动属性面板、拖拽编辑、过滤词逐项过；画面级（树窗内容）与 BRP scene_tree 输出一致。
3. **不养两份逻辑**：行数据/相关性过滤/节点命名仍是单实现，egui 树与 BRP CLI 树同源。
4. **回归**：库测试全绿 + 九脚本抽测（含 scene_tree 相关零回退）。
5. **工程闸门**：零 VUID、exit 0、clippy 全净。

## 3. 待决项

- **拍平结构与展开状态的归属**：共享行数据层（BRP 复用）还是树窗私有——以"不养两份逻辑"为准绳，施工时钉明。
- **滚动锚定**：行数随展开/收起变化时 egui `show_rows` 的滚动位置表现，施工时实测，不理想则自管偏移。
- **收益边界如实记**：字体图集/绘制半边不受益；过滤输入态等每帧变化路径的重建节奏单独核。

## 4. 测试方案

- 取证：EguiPassTiming + monitor.py 前后对照（两场景 × 树窗开/关），落 `.temp/7.7/`。
- 画面：PrintWindow 截图 + 当前会话模型读图（树窗内容与基线一致、展开状态正确）。
- BRP：scene_tree 输出与 egui 树对照（同一套行数据）。
- 代码验证线：clippy 全净（手工排版仓库，禁 cargo fmt）+ 库测试 + 宿主 exit 0。
