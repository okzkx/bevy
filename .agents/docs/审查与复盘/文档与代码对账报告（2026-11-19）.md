# 文档与代码对账报告（2026-11-19）

> 一次全库对账的做法与结论：340 篇文档对 `HEAD=10686d9ea`（工作区 `a3396352d`，仅多一篇阅读路线提交，代码无差异）。机械层全量扫，语义层按文档类型分工；修改只落在文档，`ash_renderer/src` 零改动。
> 本文留档两样东西：**怎么查**（可复跑的方法与工具）与**查出了什么**（已修 + 未修）。

## 结论

文档主体可靠：核心机制、九段录制、四张常驻表、同步与内存常量都能在代码里对上。问题集中在三类：

1. **代码改名/搬目录后文档没跟**——`FrameDraw`、`CollectedScene`、`frame_draw.rs`、`src/vulkan/*` 等已不存在的符号与路径；
2. **状态快照过期**——段 README 还写"未施工"、`F25/F26/F27` 已修仍挂"未修复"、路线图停在步骤 6；
3. **相对链接层级写错**——文档搬目录后 `../` 深度不变，117 条链接指向不存在的文件。

没有出现"文档凭空编造一套机制"的系统性问题；错的是**指代**（名字、路径、数字、状态），不是**原理**。

## §1 判定标准：先分文档类型，再定"正确"

同一句"已实现 X"，在两类文档里的判定完全不同：

| 文档类型 | 判定 |
|---|---|
| 现状文：`笔记/`、`阅读路线/`、`错误处理/`、各 README、功能流程导读、`待修复清单`、`学习目标实现步骤` | 必须与当前代码一致；旧名字、旧路径、旧数字一律算错 |
| 历史记录：施工记录、施工计划、验收复核 | 保留当时路径与数字；只要求**不自称现状**。路径漂移靠步骤 README 的旧→新映射表解释 |
| 索引 | 覆盖目录内文档；链接可达；状态与子面板一致 |

这条线定错，会把大量历史记录误判成错误，反过来也会放过"记录体里偷写现状"的过期句。

## §2 机械层：三张表 + 索引覆盖

四类检查，全部落成脚本（`tools/` 下，可复跑）：

| 检查 | 判据 | 本次结果 |
|---|---|---|
| 相对链接 | 解析后文件存在 | 119 断 → 修复 117；剩 3 条是文档生成器的宏示例字符串（形如方括号包住 `bevy_app::PanicHandlerPlugin`），非真链接 |
| 反引号代码路径 | 路径能解析，或同名文件唯一（判"已迁移"） | 1060 处"已迁移"来自映射表左列与历史记录，属预期；真实缺失按类型处置 |
| 符号存在性 | CamelCase / snake_case / `::` 形态的 token 在 `ash_renderer` + `crates/` 中出现 | 628 条未命中，绝大多数是外部词汇（Unity/Filament/egui/Vulkan 特性名/历史类型名），逐条人工分诊 |
| 索引覆盖 | 每篇 md 至少被另一篇链接（README 除外） | 13 → 2；剩余 2 篇是 `.agents/skills/*/SKILL.md`（技能入口，不经 md 链接） |

工具与用途：

- `tools/doc_code_audit.py`：全库审计，输出 `.temp/doc_audit/report.json`（links/path/symbol/orphan 四张表）。
- `tools/doc_link_fix.py`：按"唯一同名文件"重写链接目标；多义项走脚本里的 `MANUAL` 人工映射表（16 条）；不动链接文字，历史记录里的旧路径文字保持原样，点进去是新位置。
- `tools/doc_eol_normalize.py`：把文档拉回 UTF-8 无 BOM + CRLF。**坑**：Python 文本模式读写会把 CRLF 静默转成 LF，git 会报 "LF will be replaced by CRLF"；批量改文档后必须跑一次。

## §5 代表性发现

挑几条最能说明问题性质的：

1. **录制契约已拆成两个类型**。`整帧录制流程.md` 与 `src 顶层目录依赖分层.md` 共 7 处仍写 `FrameDraw`；代码是 `RenderFeatures`（功能门控）+ `SceneResources`（场景资源），录制体在 `src/render/frame/record.rs`。不是改名，是拆账——照旧文读会把"功能开关"和"资源规格"混成一件事。
2. **错误处理专题的工具篇整体失效**。`错误处理语法糖` 写"已移植 8 件控制流宏 + `LogDebug` + `UnwrapPanic` + 第 9 件 `unwrap_or_panic!`"；`common/syntax.rs` 现在只有两个 trait、3 个自由函数/结构、1 个宏。该篇是 2026-09-21 的历史定案，已加"现状追记"，正文标为当时；README 与宪法篇按现行事实改写。
3. **`fatal_gate` 挂在 `First`，文档写 `Update`**。三篇错误处理文档 + 定案注释三处口径，代码是 `main.rs:42 .add_systems(First, fatal_gate)`；已统一。
4. **Hi-Z 滞后两帧，不是一帧**。`GPU-Driven 本质`、`延迟渲染管线一帧全景`、`CMD时序` 都写"上一帧"；代码读的是本帧槽上一轮输出（= 两帧前）。`阅读路线` 与 `笔记/` 里的两篇口径互相矛盾，已统一。
5. **材质记录 64B，不是 32B**。5.1 的"32B/条、5 条 160B"在 5.3 后已扩到 64B（`MATERIAL_RECORD_SIZE`），5 条 320B；`GPU驱动第一课` 保留历史数字但补了现状注。
6. **`F25/F26/F27` 三条清单状态落后于事实**。F25/F27 已由 `bd48cb0a2` 九套回归 9/9 修复，F26 已由 7.11 裁决关闭；清单仍写"未修复"。已改状态并补证据。
7. **链接断在"搬目录没改 `../`"**。`已实现缺陷与修复验收.md` 迁到 `3.2-buffer侧上传/` 后，7 处 `../材料/` 全部失效；`3.5` 的配图层级多写一级 `../`。这类占断链的九成。
8. **BCn 工作没进路线图**。代码与施工记录都在仓内（`resident/assets/bcn.rs`、`bcn_cache.rs`），路线图与"当前位置"完全看不到这项；已补进总览表与追加项节。
