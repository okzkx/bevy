# 低保真常驻保底流程：从锚解析到需求位图盘点的各级账面

> 6.5 功能流程导读（2026-10-20 收官，面向下一个读代码的人）：floor_anchor 开启后，"行可绘"的判定、上传的盘点、淘汰的豁免如何围绕**保底档（最粗变体）**重新组织。验收证据归[施工记录](6.5.1-6.5.6-低保真常驻保底施工记录：可绘锚迁移、需求档按需与保底常驻.md)，机制背景见[6.4 CPU/GPU 交互篇](../6.4-细粒度流送/粗细粒度流送的CPU与GPU交互：现状与稀疏请求.md)。

## 0. 一图看懂：锚换位之后谁动了

```text
ResidencySettings.floor_anchor (BRP residency_set / 场景脚本)
  └─ residency_tick (Last，先于上传)
       ├─ needed[floor]=true 取代 needed[0]=true        ← 需求集换锚档
       ├─ 期望档缺失检查全档化（level 0 也触发请求）      ← 高档回流的命脉
       ├─ LodDemand.levels[base] = 位图                  ← 逐帧发布
       └─ 淘汰：fine 循环从 level 0 起步，保底恒需求恒不淘汰
  └─ flush_uploads (同帧，位图消费方)
       ├─ 锚腿 = 保底档（对象记录/实例槽以锚槽位落笔）     ← 记录引脚即保底
       ├─ 基准高档腿 = 位图 bit0 点名才进批               ← 上传按需
       └─ 变体盘点 = 位图点名才盘点                        ← 6.4 遗留缺口闭合
  └─ drawlist::assemble (帧循环)
       └─ 行可绘判定 = 锚驻留（anchor_level 纯函数同源）   ← GPU 链零改动
```

GPU 侧（lod_select/build_indirect/cull）一行未动：对象记录的引脚在 floor_anchor 下就是保底引脚，`pick_lod_entry` 的 rec 回退天然落到保底——**换锚是 CPU 侧账面语义迁移，不是 GPU 链改造**。

## 2. 逐时刻走读（scene_floor 场景为线）

1. **进场（管理器关）**：spawn_lod → Added 置脏 → flush 全常驻（位图缺席不过滤）——四档全进池，与 6.4 无差别。
2. **开 floor_anchor + 预算压紧**：锚切换沿全行置脏 + LOD 脏 → 锚腿以保底槽重写记录（bound 换形）→ 需求集变为 {保底, 期望档} → fine 淘汰从 level 0 起步逐个 shed 高档 → 远景组只剩保底仍可画（判定线 1）。
3. **相机接近角落**：期望档算出 level 0 → needed[0] 进位图 → fine 请求分支触发 → flush 基准高档腿重传 → 基准回流（判定线 3）；远处组期望档=保底，基准保持缺席。
4. **关 floor_anchor（A/B 的 B 面）**：切换沿全行置脏 → 锚回基准 → 基准缺席的行整行暂缓（远景蒸发，判定线 2 对照面）；floor 变非需求档可被 fine 淘汰——9 组保底驻留掉到 5。
5. **关管理器 + 预算 0**：激活态下降沿全行置脏 → 重传链消化 → 全常驻基线恢复（判定线 4 的 B 面）。

## 3. 失败与稳态路径

- **失败档**：保底上传失败 = 行锚缺席 = 行暂缓（readiness failed 集止重试）——与 6.4 基准失败同语义，降半级到"无画面"；高档失败 = 保底照画（哨兵回退）。
- **预算挤压**：需求总量超预算时 coarse 循环逐个 shed（视锥外∧距离远优先）、`over_budget` 如实报——floor 不在候选集，最坏情况是"高档全灭、保底全留"。
- **稳态**：锚/需求集不变时零盘点零上传（增量链语义不变）；thrash 由既有冷却窗吸收。
