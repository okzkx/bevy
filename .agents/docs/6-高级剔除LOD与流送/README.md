# 步骤 6：高级剔除、LOD 与流送（M5）

对应[执行路线图](../学习目标实现步骤.md)。本 README 是步骤索引与材料目录；各段任务面板在段目录 README（开工时立），段施工计划随立案入段目录。

**目的**：在常驻 GPU-driven 已成立后，减少不可见/过细工作，并让大于驻留预算的世界可持续加载卸载。

**一句话说明**：6.1～6.4 已完成遮挡、GPU LOD 与 CPU 预算驻留的机制验证，但尚无最低保真 mesh 常驻保底或 GPU→CPU 驻留缺口请求；后续追加 6.5 建立低保真常驻与高档按需，6.6 再实现 GPU 稀疏需求驱动，供步骤 7 的正式资产场景检验。本步不主张步骤 8/9 的画质特性，也不将外置 VT 页级方案算入 6.6。

**当前验收状态：⬜ 步骤级未验收——6.1～6.4 四段 + 6.5 ✅ 施工收官（6.5：2026-10-20 当日立案当日施工）；6.6 ⬜ 已立案+段施工计划已立（2026-10-20）、待施工（前置依赖已满足）**。原四段施工记录（2026-10-19，按当时验收范围五条/六条/六条/五条）：[6.1 记录](6.1-Hi-Z遮挡/6.1.1-6.1.6-Hi-Z遮挡施工记录：测试实体载具、深度金字塔、遮挡第二pass与A_B计量.md)/[6.2 记录](6.2-GPULOD/6.2.1-6.2.6-GPULOD施工记录：场景脚本化、LOD变体表与选档联动.md)/[6.3 记录](6.3-粗粒度流送/6.3.1-6.3.6-粗粒度流送施工记录：驻留管理器、超预算游历与A_B基线.md)/[6.4 记录](6.4-细粒度流送/6.4.1-6.4.6-细粒度流送施工记录：LOD档逐档驻留、贴图字节预算与fallback保底.md)。6.4 的 mip 分级驻留、贴图主动恢复等缺口见[交互篇](6.4-细粒度流送/粗细粒度流送的CPU与GPU交互：现状与稀疏请求.md)；原四段未因此重记为 6.5/6.6 已完成。**
