## 0. 判定线（验收草案）

1. **保守语义不误剔（红线）**：遮挡测试只可多画不可错杀——同一场景下"视锥 ∧ 遮挡"开关开启时的可见实例集合 ⊇ 只开视锥的集合；BRP 驱动遮挡案例——遮挡对与墙体样本由测试实体方法族布置（任务 6.1.1 先行交付）：被大遮挡体挡住时剔除量上升、移出遮挡立即恢复绘制，与 CPU 参照对照零误杀样本。
2. **不长期误剔除**：历史深度天然滞后（见 §5 待决 4），滞后窗内的短暂误剔除如实计量；但快速移动/转镜头/相机跳变不产生**长期**误剔除——相机大幅跳变有显式 fallback（该帧跳过遮挡测试），移出遮挡的对象在数帧内恢复、不残留永久消失的对象。
3. **金字塔归约正确**：逐级归约结果与 CPU 参照一致（把金字塔限制在小分辨率、CPU 读回逐级对照——只做验证，不进绘制路径）；**reverse-Z 下归约极值与比较方向的保守性形状有单测钉明**（深度值大小与远近关系和正向 Z 相反，取错方向=系统性错杀，这是本段最危险的单点，必须数学钉死）。
4. **A/B 成组记录**：遮挡开关前后——GPU 图形段帧区间计时（5.5 计量底座现成）、实际剔除量读数（视锥剔除量与遮挡剔除量分列）、金字塔构建开销单列；结论按[统一验收与性能口径](../../学习目标实现步骤.md)成组报告，不只给"流畅"截图。
5. **既有判定线零回退 + 红线延续**：CPU 不回读可见集驱动绘制（5.2/5.3 口径不变），遮挡读数只进计量通道并单独标注；4.x 增量链全量、5.1/5.2/5.3 判定线回归（cull-stats 零 mismatch、draw_calls 恒 ≤1 口径）、零 VUID、WM_CLOSE exit 0、clippy 全净、resize/最小化与金字塔资源生命周期共存、拆 Device 排空不炸。

**画面语义辨析（立案期钉明）**：5.2 的画面判定是"与基线逐像素一致"（标记不进绘制路径）；6.1 的遮挡标记**进绘制路径**——遮挡开启时被完全遮挡的对象合法消失，三模式基线对照须在**遮挡关闭**档位下取证，遮挡开启档位的画面证据走"被遮挡消失/露出恢复"的读图对照，不套"逐像素一致"判定线。

## 1. 定位：现状与要补的东西

5.5 收官后的链路：视锥剔除（5.2）→ 在场环/命令环（5.3）→ 一次 indirect 绘制；三档压测结论 = GPU 图形段主导（36/137/254 ms，预算不可达），提交侧平坦解耦——**剩下能省的就是"在视锥内但被挡住"的那部分绘制**。6.1 补遮挡剔除：

- **深度链现状**（[vulkan/depth.rs](../../../../ash_renderer/src/vulkan/depth.rs)）：D32_SFLOAT reverse-Z（`depth.rs:18`），帧槽每槽一张、随 swapchain 重建；loadOp CLEAR 清 0 + GREATER 比较成套（`pipeline.rs:182`、`frames.rs:368`）。**立案期核实：深度附件 usage 仅 `DEPTH_STENCIL_ATTACHMENT`（`depth.rs:64`）——不可采样、不可 blit/copy 出去，Hi-Z 的取数通道必须新建或扩 usage（§5 待决 2）**。
- **剔除链现状**：`cull.wgsl`（112B push 六平面 + bump bound，8 角点世界推导，与 CPU 参照逐位同语义）；标记环 set2 b3（HOST_VISIBLE ×2 帧槽）；build_indirect 消费标记写 `instanceCount=0`。遮挡测试的天然落点 = cull pass 内扩展或其后第二 compute pass（都必须在 build_indirect 之前，§5 待决 3）。
- **归约形状参照**（当前 checkout 实存）：bevy [occlusion_culling.wesl](../../../../crates/bevy_pbr/src/render/occlusion_culling.wesl)——AABB 投屏四角、按包围盒像素尺寸选 mip 层、4 tap textureLoad 取极值做保守判定；[mip_generation/downsample.wesl](../../../../crates/bevy_core_pipeline/src/mip_generation/downsample.wesl)——金字塔逐级下采样。学机制与保守化形状，不搬整套架构。
- **计量底座现成**：5.5 交付的 GPU timestamp 帧区间 + PerfLedger 分位数 + BRP perf 读数族 + egui perf 行——判定线 4 的 A/B 对照零新建计量。
- **滞后语义先例**：标记环"读数 = 两帧前 compute 输出、计量允许陈旧 ≤2 帧"（cull.rs 模块注释）——历史深度的滞后量问题同链（§5 待决 4）。

## 5. 待决问题（施工时钉明，不写死）

1. **金字塔格式与归约形状**：compute 逐级归约写独立格式（倾向——min/max 归约只有 compute 能做；D32 的 STORAGE 支持非必保，候选 R32_SFLOAT 按能力实测定型）vs depth blit 逐级缩（5.4 mip 链同形状；但 depth blit 只允许 NEAREST 过滤，做不出 min/max 归约，且 blit 语义对"2×2 取最保守值"不保证——倾向否决，除非实测推翻）。**reverse-Z 下保守极值方向必须先单测钉死再用**：深度值大小与物理远近成反比，"取哪个极值代表本 tile 的遮挡上界"与正向 Z 相反，参照 bevy downsample 的符号约定与本仓库 pipeline.rs 的 reverse-Z 成套注释核对。
2. **深度取数通道**：扩 `DepthTarget` usage（SAMPLED/TRANSFER_SRC，compute 直接采深度——改动最小，一行 usage + 能力查询）vs 帧末另立可读副本 pass——倾向前者；扩 usage 动帧槽重建路径，连带核对该 usage 变化对既有附件形状声明（VUID-08914 管线深度声明先例）无影响。
3. **遮挡测试落点与 descriptor 落位**：cull.wgsl 单 pass 内扩展（视锥+遮挡一次 dispatch，省一次 pass；但 cull 已有 112B push 与既定形状）vs 独立第二 compute pass（隔离清晰，多一次 dispatch 与中间屏障）；Hi-Z 纹理 binding 落 set2 追加 vs 独立小布局（照 5.2 待决 3 的 set2 追加倾向）。倾向独立第二 pass + set2 追加——遮挡语义独立成 pass 便于开关 A/B 与 fallback 跳过，与 build_indirect 的既有依赖链只多一条屏障。
4. **历史深度滞后量与跨帧依赖**：2 帧滞后（金字塔 ×2 帧槽，读另一槽 = 上轮 fence 已过的输出，随既有帧槽 fence 免费、零新同步形状，与标记环读数同纪律）vs 1 帧滞后（需要跨提交的 device 侧依赖，信号量/屏障链是新增同步形状）——倾向 2 帧起步（滞后窗误剔除由 fallback 与判定线 2 兜底），1 帧留给压测证明滞后不可接受时再评估。
5. **标记合并语义与 fallback 信号**：遮挡结果合并进既有标记（视锥 ∧ 遮挡一位）vs 独立遮挡标记位（视锥剔除量/遮挡剔除量天然分列，A/B 归因干净）——倾向独立标记位；fallback 判定信号（首帧、相机位移超阈值、金字塔未就绪）落 CPU 侧每帧判定随 push/buffer 进 compute，具体阈值施工时钉。
6. **金字塔规模与重建节奏**：分辨率 = swapchain 尺寸逐级减半取整、级数复用 `full_mip_chain` 同式；每帧重建（深度每帧变，无隔帧空间）——构建开销进判定线 4 的 A/B 账；10 万档下金字塔构建本身是否进预算，压测读数说话，不预先声称。
7. ~~遮挡墙等大遮挡体的形状来源~~ **已收（2026-10-19 用户拍板"立方体也要"）**：cuboid 进形状清单（五形状），墙体遮挡样本=cuboid 非均匀缩放直出，不需要其他形状拼凑；球/圆柱/胶囊作遮挡对与密集体块样本。形状清单再扩展仍=BRP 参数枚举加项，无结构性代价；方法名 `spawn_shape` 与参数面（transform/scale 入参、颜色格式）施工时随 6.1.1 钉明。
