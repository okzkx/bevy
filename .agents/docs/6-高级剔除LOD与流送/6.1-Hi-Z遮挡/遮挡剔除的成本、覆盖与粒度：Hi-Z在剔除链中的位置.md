# 遮挡剔除的成本、覆盖与粒度：Hi-Z 在剔除链中的位置

> 收 2026-10-19 [原理篇](Hi-Z遮挡原理：深度金字塔与保守遮挡判定.md)定稿当日的讨论沉淀。原理篇讲"这套机制为什么成立"，本文记它的成本口径、覆盖证明的展开、与深度测试及逐图元方案的分界——三块都是原理篇刻意没展开的横向知识。

## 一、成本口径：什么免费，什么不免费

GPU-driven 管线里 Hi-Z 常被说成"近乎免费"，这个说法要拧紧一格：它免的是**同步税**，不是成本。真实账单有三笔：建塔是逐像素的全屏归约链，随分辨率线性涨（GPU 计时单列 `gpu_hiz_ms` 就是给这笔账的）；逐实例判定虽是 O(1)，也是一遍 compute dispatch；深度 storeOp 从丢弃改 STORE、再写一份 R32F 副本，都是带宽。它划算的前提是省掉的绘制成本大于这张固定账单，而省多少由场景形状决定——所以收益永远是测量对象（A/B 开关 + cull_stats 分列），不是功能常量。最坏情形不是"剔错"而是"纯开销"，且纯开销的场景（少数铺屏大物体）实例数本来就少，亏得有限。

传统 CPU 管线的账要分开记。**同步回读路线确实判死刑**：GPU 渲完深度 → 读回 → CPU 判定 → 再喂绘制，流水线排空互等，拿到的还是旧数据——可见性本是流水线的免费副产品，帧首决策点把它变成等待（回读墙）。但由此推出"CPU 管线做不了遮挡剔除"就过头了，历史上三条路都真实跑过：

| 路线 | 做法 | 代表 |
|---|---|---|
| 预计算烘焙 | 离线算好可见性集合（PVS/portal），运行时查表 | Unity 传统 occlusion culling |
| CPU 软光栅 | CPU 上光栅化遮挡体代理，攒出自己的深度图 | Intel 软光栅方案等 |
| 异步遮挡查询 | 发 GPU 查询、隔一两帧读结果，读不到按"可见直到被证明被挡"处理 | 老式 GPU occlusion query |

注意第三条：异步查询其实也是"滞后参照 + 保守处理"的思想，和 Hi-Z 一脉同源，只是滞后更长、粒度是查询而非金字塔。而 Hi-Z 这个**思想本身**（层级化深度上界）与 CPU/GPU 正交——CPU 自己攒一张深度缓冲照样建塔。所以准确的分界线是：**GPU-driven 判死刑的是同步回读这一条路，不是遮挡剔除本身；GPU-driven 的真正贡献是把可见性决策整体留在 GPU 闭环内，让"上一帧副产品当证物"零回读可用。**

## 二、覆盖证明：从"点"到"全身"的推理链

一个自然的疑问：单点被挡能证明全身被挡吗？不能——墙可能只盖住你采样的那一个像素，物体其余像素底下可能是背景。任意单像素采样做判据，错误剔除真实存在。真实方案里没有"任意点"参与判定，靠的是**两侧各压成一个标量，再配对**：

- **物体侧**用最近角点（8 角点 NDC z 取 MAX）。物体全身里最"占便宜"的位置就是最近点，最近点都被证明被挡，其余更远的点必然被挡——这一步归纳严密，所以物体侧用一个标量没有问题。
- **tile 侧**存的不是任意像素，是该 tile 的**最弱遮挡者**（reverse-Z 归约 MIN = 区域内最远已缓冲表面）。连最弱者都够不着 = 被 tile 内一切表面挡住。若用最强者（最近表面）下结论，只能证明"被某个表面挡住"，会错杀仅被部分遮挡的物体。

两侧标量怎么配对成 O(1) 判定，靠选层公式接上。物体投屏取 8 角点投影结果的**屏幕轴对齐包围矩形**（比实际投影多边形又保守一层）；tile 网格固定锚在屏幕原点，物体落在哪、多大都是任意值——**覆盖证明从不需要网格对齐**。`ceil(log2(最大边))` 买到的保证是：tile 边长 t ≥ 矩形边 s > t/2 ⇒ 每轴至多压到 2 格 ⇒ 以左上角所在格锚定的 2×2 tap 必覆盖全部相交 tile。这也是"只能用同一个 mip 层级"的原因："至多跨 2 格"是相对于一个固定均匀网格的命题，混层后不再是同一个划分，证明断裂。方向上有单调性：往粗混安全（粗 tile 是细 tile 的并集，其 MIN 必然 ≤ 细层那几格的 MIN，只会更保守），往细混危险（回到单点反例）。一些引擎的 HZB 实现有渐进细化变体（判可见时往粗一层复验），核心命题不变。

选层公式卡在**仍保证"≤2 格/轴"的最细层级**这个膝点上：再细一格覆盖证明就破（矩形可能压到 3 列），再粗一层仍正确但 tile 更大、更易混进背景 0（MIN 被拉到 0，该格失去遮挡力），白丢剔除力。tap 覆盖超出物体矩形是常态而非误差——多读的区域只会把 MIN 拉得更小、遮挡者更弱，永远倒向"宁多画"。

这条证明链的边界也要钉住：它全部相对于**参照深度**（上一帧）成立，遮挡物本帧刚移开的物体仍会晚一帧出现——那是滞后税，不是几何论证的漏洞（原理篇 §五）。

**大物体退化**是覆盖证明的自然推论。横陈全屏的圆柱选层到金字塔顶层，整层只剩一两格，tap 几乎必混背景 0 → MIN 归 0 → 恒判可见。三点口径：其一，全屏物体的可被遮挡概率天然趋近零（要挡住它，遮挡者得几乎同样大且更近），测试对它本来就没任务；其二，金字塔仍是全分辨率，其他小实例照常在各自层级被便宜地杀掉，失效限定在这一个实例；其三，"只能 4 tap"是本仓与 bevy 同构选的形状，不是原理上限——工程外延有按屏幕覆盖率阈值直接跳测、大物体在细层循环覆盖 tile（O(面积)，只付给少数大物体）两条路。真正让 Hi-Z 失效的场景是"少数铺屏大物体构成整个场景"——那时剔除的对象本来就不存在，不是测试钝了。

## 三、与深度测试的分工：像素侧重叠，几何侧是净增益

遮挡剔除和深度测试在像素侧有重叠，把重叠剥开，剔除的**净增益**才看得清。Early-Z 在光栅化之后、片元着色之前拿当前帧深度逐像素精确裁决，零错杀——所以"这个物体最后会被深度挡住"里，像素着色的成本 early-Z 本来就不会付。若遮挡剔除只是抢这份收益，它确实近乎白做，还做得更糙（保守、滞后）。

它的增量在 early-Z 够不着的上游。Early-Z 是像素级最后一道闸，出手之前几何侧全链已经跑完：顶点/索引 fetch、顶点着色、裁剪、图元装配、光栅化遍历照跑，然后逐 quad 拒绝。一个 10 万三角形、完全在墙后的 mesh，early-Z 会忠实地跑完全部顶点着色和装配再把这个实例的每个 quad 拒掉——几何成本一分没省。Hi-Z 剔除让 `instanceCount=0`，几何侧归零。所以：

- **深度遮挡优化像素侧**：省 PS 执行与 ROP 写入，精确、零延迟、当前帧真值；
- **遮挡剔除优化实例侧**：整个实例从命令流消失，省顶点着色、fetch、装配、光栅化前端，外加 GPU-driven 链上它的槽位之后的全部每实例账。

**遮挡剔除相对深度测试的边际收益 ≈ 全部几何侧成本。** 由此直接推出收益画像：顶点重的场景（高模、蒙皮、细分）赚得多；低模小实例、PS 重灾区，early-Z 已把像素侧收干净，增量主要还是省 VS 和前端。两个补充：PS 写深度、`discard`、alpha test 会让 early-Z 退化成 late-Z，像素侧的省也拿不到——此时剔除在像素侧的提前量才有独立价值；反过来，间接绘制虽然整帧只有一次 draw call，GPU 前端仍要逐实例取顶点数据跑 VS，这部分不会因"一个 draw"摊薄。

两者不是二选一，是三层漏斗：视锥剔除（实例级、精确、零成本）→ Hi-Z 遮挡剔除（实例级、保守、上一帧参照）→ 深度测试（像素级、精确、当前帧真值）。前两层只负责"别把明显画不出来的喂进管线"，最后一层永远是最终裁决者——Hi-Z 零错杀的保守性要求，正是被这个分工兜底的：它漏掉的，深度测试都会正确处理。

## 四、粒度：剔除决策由它的消费端决定

剔除这个动作的输出是 `instanceCount=0`——整个实例从 indirect 命令里消失，这是管线里唯一成批跳过的开关。假设精确知道某个 mesh 的第 4567 号三角形被挡住了，没有任何机制让它单独缺席：一个 draw 内部的三角形必然走完 fetch → VS → 装配 → 光栅化全程，深度测试是它们唯一的裁决者。**三角形级的遮挡知识在正常管线里没有消费者**——知道得再细，也变不成省下的工作。剔除粒度必须跟"能省掉的账单"同粒度，实例就是那个粒度；视锥剔除、遮挡剔除、将来的 LOD 与流送决策全部落在这个单位上，不是巧合。

逐三角形测试还有一层归谬：每个三角形都要投影、包围盒、选层、tap，10 万三角形的 mesh 就是 10 万次——成本与直接画了（VS + 硬件光栅化）同量级甚至更贵，等于用通用 compute 重新发明光栅化；而逐三角形的遮挡裁决，深度测试已经在硬件里免费、精确地做完了。在深度测试前面放一个又慢又保守的复制品，是负优化。

逐图元可见性不是没人做，而是做的地方**用它替代光栅化**，而不是在光栅化前面当过滤器：Nanite 按 cluster（约 128 三角形）做可见性并用软件光栅直接写 vis-buffer，vis-buffer/deferred 材料类方案先跑可见性 pass 再决定 shading——整条光栅化路径被换掉，cluster 级信息才有了消费者。那是"换掉光栅化"的深水区；在正常前向管线里，过滤器的经济粒度就是实例。

最后是代理的经济学，和 mip 选层是同一个模式：AABB 比真实几何胖（投屏更大、最近角点更近，两头都更难判遮挡，剔除力折损），换的是"几个乘加就得到、不碰网格数据"；tile 比物体足迹大（过覆盖），换的是 O(1) tap 封顶。**保守代理 + O(1) 判定，宁可放过，不做贵的精确**——Hi-Z 全链从归约方向到包围盒到选层，反复出现的都是这一条。
