## 0. 判定线（验收草案）

1. **选档语义正确（红线）**：GPU 选档结果与 CPU 参照（同一公式同一次投影）逐实例一致——BRP 逐实例档位 census 对照；遮挡/视锥标记与 LOD 档位互不污染（三标记各自归因）。
2. **切换稳定（迟滞生效）**：近换远有迟滞带、远换近即时升档——相机在阈值附近往复不产生档位抖动；快速移动/转镜头无长期停留错误档位。
3. **不访问未驻留 LOD（红线）**：绘制只引用已上传档位；本段全档常驻下由驻留账面校验兜底，fallback 逻辑（未驻留→最近常驻档）就位但由 6.3/6.4 正式驱动。
4. **命令联动正确**：档位改变命令的 indexCount/firstIndex/vertexOffset——画面读图对照（近清远粗、LOD 关闭档与基线一致）；draw_calls 恒 ≤1 口径不回退。
5. **A/B 成组记录**：LOD 开关前后 GPU 图形段帧区间（5.5 底座）+ 顶点/三角形吞吐读数（draw_stats 是否已有口径施工时核实，无则扩）；视锥/遮挡/LOD 三开关矩阵成组报告，按[统一验收与性能口径](../../学习目标实现步骤.md)。
6. **既有判定线零回退**：4.x 增量链、5.1/5.2/5.3/5.5、6.1（遮挡判定线、金字塔重建）全量回归；零 VUID、WM_CLOSE exit 0、clippy 全净、库测试、resize/拆 Device 排空共存。

## 1. 定位：现状与要补的东西

6.1 收官后的链路：视锥剔除（5.2）→ 遮挡测试（6.1）→ build_indirect → 一次 indirect 绘制；所有实例仍按各自 mesh 最细档绘制——**"看得见但不必画细"的那部分开销还没省**。6.2 补 LOD：

- **对象记录自带 mesh 区间副本**（[instance_table.rs](../../../../ash_renderer/src/vulkan/instance_table.rs)）：48B 记录 = first_index/index_count/vertex_base/材质槽/局部包围盒（`instance_table.rs:56`、布局镜像 `:77-96`）——每实例一份区间副本，LOD 换档即改写这三字段，命令组装侧（build_indirect.wgsl 读记录写 20B 命令，[indirect.rs](../../../../ash_renderer/src/vulkan/indirect.rs) `:255-270`）天然是联动点。
- **MeshPool 按 `AssetId<Mesh>` 驻留**（[pool.rs](../../../../ash_renderer/src/vulkan/pool.rs) `:181`）：LOD 档 = 同一逻辑 mesh 的多个独立 Mesh 资产、各占一个 MeshSlot（细分阶梯由生成器/测试实体出，见 §2 核实 1）；GPU 侧需要"对象槽 → 各档区间"的新形状（§5 待决 3）。
- **标记链现状**：视锥标记 u32/槽 + 6.1 遮挡标记独立 u32/槽（`instance_table.rs:62-64`）——LOD 档位的传递通道待决（独立环 vs 位打包，§5 待决 2）。
- **cull push 有余量**：112B（六平面 96 + bound + 垫 16，[cull.rs](../../../../ash_renderer/src/vulkan/cull.rs) `:40-43`），maxPushConstantsSize ≥128 保底——LOD 参数（判据阈值/迟滞带/开关）有 16B 余量可用（§5 待决 5）。
- **投影现成可共用**：6.1 金字塔选层已做 AABB 投屏 + 按像素尺寸选 mip——LOD 选档判据同族（屏幕覆盖尺寸），一次投影两处消费（§5 待决 1）。
- **bevy 参照**（当前 checkout 实存）：**无传统 per-mesh LOD 组件/系统**（grep 无 `Lod` 组件实抓）；[meshlet](../../../../crates/bevy_pbr/src/meshlet/mod.rs) 是 cluster 级更细路线（cull_shared.wesl 含 screen-size 思想），学判据思想、不搬 cluster 架构（cluster 级归外置，见 §6）。

## 5. 待决问题（施工时钉明，不写死）

1. **选档判据**：屏幕覆盖尺寸（AABB 投影像素面积，与 6.1 金字塔选层同族、可共用一次投影——倾向）vs 相机距离（简单但无视锥形状/FOV/分辨率因素）——倾向屏幕尺寸，公式与 6.1 的 mip 选层口径互相引用。
2. **档位传递通道**：标记环加独立 u32 LOD 环（6.1 遮挡位先例、归因干净——倾向）vs 视锥标记位打包（省一条环、读数归因混）。
3. **LOD 表数据形状**：独立 LOD 表（对象记录不动，加"槽位 → 各档区间集"新 storage 表——倾向，冻结边界不破）vs 对象记录内联变体数组（48B 布局解冻）。选独立表时表条目按逻辑 mesh 组织还是按槽组织，随 6.2.2 钉明。
4. **LOD 状态存所**：GPU 持久 storage buffer（compute 读写，跨帧存活）vs CPU 侧持久镜像随帧重写（宿主写纪律）——迟滞状态是跨帧数据不是瞬态数据，倾向 GPU 持久 buffer；与 §2 核实 2 联动。
5. **参数面**：判据阈值/迟滞带/开关走 cull push 垫余量（16B 够否）vs 独立 push vs 小 UBO——随 6.2.3 按参数量定。
6. **场景脚本录制器**：手写脚本（6.2.1 先交付）够用后，是否补"录制器"（自动捕获 BRP 调用序列成脚本）——看 6.2/6.3/6.4 手写脚本总量与重复度再定，不预先立项。
7. **吞吐读数口径**：draw_stats 是否已含顶点/三角形口径——施工时核实，无则扩（判定线 5 依赖）。
