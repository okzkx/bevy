# GPULOD原理：投屏选档、迟滞与按档引脚

> 面向想弄清"为什么是这套形状"的读者：本文只讲原理与取舍——判据为什么是投屏尺寸不是距离、迟滞为什么单向、档位为什么落成引脚改写而不是换实体、投屏为什么复用"模式"而不共享"产物"。一帧里的数据怎么流转归[流程导读](GPULOD流程：从阶梯样本到按档命令的各级账面.md)，判定线证据与施工钉子归[施工记录](6.2.1-6.2.6-GPULOD施工记录：场景脚本化、LOD变体表与选档联动.md)。

## 0. 先立住三句话

1. **LOD 回答剔除答不了的第三问**：视锥说"在不在视野里"，遮挡说"画不画得出来"，LOD 说"看得见，但该画多细"——远处实例画全量网格是纯浪费，把"画多细"变成逐帧逐实例的 GPU 决策。
2. **判据 = AABB 投屏覆盖尺寸，不是距离**：`raw = floor(log2(threshold / s))`——投屏尺寸天然含 FOV/分辨率/视锥形状因素，距离只是它的粗糙近似；这一式与 6.1 金字塔选层同族（"屏幕足迹 → log2 → 层级"同一骨架）。
3. **判完不换实体、不在 CPU 上逐对象切换 mesh、不重绑 buffer**——本帧从已驻留档的引脚中改写 indirect 命令三个字段（indexCount/firstIndex/vertexOffset）。不同档 mesh 占池中不同区段；CPU 仍负责这些档位资产的上传与回收，GPU 负责绘制时选引脚。

## 一、判据：为什么是投屏尺寸，不是距离

LOD 档位本质上回答"这个物体在屏幕上占多大"。距离判据（distance-based）是它的粗糙近似：要为每个物体配一张距离表，换相机 FOV、换分辨率、换屏占比预期就整体失真。投屏尺寸把这三个因素都含在投影里，一次算完。

做法（[`lod_select.wgsl`](../../../../ash_renderer/shaders/lod_select.wgsl)，CPU 参照 = [`lod.rs`](../../../../ash_renderer/src/vulkan/lod.rs) 纯函数两件）：

1. 对象表 AABB 的 8 角点经 model × view_proj 投到像素坐标（与 6.1 遮挡同款推导，见 §四）；
2. 取 clamp 进屏幕后的像素矩形**最大边**为 s——clamp 的约定是"离屏部分不渲染"，完全离屏 s = 0 → 最粗档（反正不画）；
3. 自然档位 `raw = floor(log2(threshold / s))`，clamp 进 `[0, MAX_LOD_LEVELS−1]`：s ≥ 阈值（默认 256px）→ 档 0，s 每减半升一档。floor 语义 = 半档不跳档，s = T/2 恰为档 1，s 略低于阈值仍在档 0。

保守方向钉：任一角点 `clip.w ≤ 0`（在相机平面背后，透视无意义）→ 恒判最细档 0。LOD 判错的方向不对称——往细档错只是多画（安全），往粗档错会糊（可见降质），所以存疑一律往细判。这与遮挡的"恒判可见"同构但语义相反：遮挡的保守是"多画"，LOD 的保守是"画细"。

## 二、迟滞：为什么向粗要余量、向细即时

只用自然档位会在阈值边界抖动：物体投屏尺寸在 256px 附近每帧波动几个像素，raw 就在档 0/档 1 之间反复横跳，换 mesh 的瞬间画面看得见"弹一下"。迟滞是给状态切换加的摩擦力。

裁决规则（状态机本体 `lod_hysteresis_level`，库测试钉全部分界）：

- **向粗切换（远离）**：必须 `s ≤ 该档自然边界 × (1−h)`——不只是越过边界，还要越过阈值带 25%（默认 h=0.25）的余量才降档；
- **向细切换（靠近）**：即时升档；
- 相等保持。prev 从档位环本槽读 = 本帧槽两帧前的选档输出（fence 纪律与标记环同一条），2 帧滞后由迟滞带吸收——静态场景收敛值不受影响，只有动态往返的切换点略钝化。

**不对称的方向是刻意选的**，根据是两种误差的可见性不对称：靠近时晚一帧升档 = 多糊一帧，几乎不可见；远离时早一帧降档 = 画面上看得见弹一下。所以"即时"给变细，"余量"给变粗。

与 Hi-Z 对照能看清迟滞为什么只在这边有：Hi-Z 选 mip 无状态、无迟滞——它是个保守读，选粗了只是遮挡判定偏松（宁多画），且每帧重算、无跨帧代价；LOD 换 mesh 是**可见事件 + 跨帧状态**（档位环存 prev），所以不取"最保守"而取"带宽最省 + 迟滞防抖"。

## 三、应用：档位环 → 变体表 → 命令三字段

选档结果落地为档位环 b8 里一个 u32（每实例槽一个）。真正的"应用"发生在 build_indirect（[`build_indirect.wgsl`](../../../../ash_renderer/shaders/build_indirect.wgsl) `pick_lod_entry`）：拿档位查 LOD 变体表 b7（每槽 4 条 `LodEntry` = `(first_index, index_count, vertex_base)`，`index_count = 0` 为该档未驻留哨兵），改写组装中命令的三个引脚字段。

三层兜底，对应判定线 3"不访问未驻留 LOD"：

1. 选中档在表内已驻留 → 直接用（正常路径）；
2. 该档未驻留 → **档号递减，向更细档逐档找**最近已驻留条目；缺粗档会画细档，绝不会从缺失的细档向更粗档搜索。
3. 全哨兵 → 回退对象表 b0 的基准引脚；这个兜底只对 DrawList 已确认基准 mesh 驻留的可绘行成立。6.3 预算若淘汰基准，整行暂缓，不进入命令构建。

**"换 LOD 资产"的本质**：顶点缓冲是同一个 MeshPool，不同档的 mesh 只是池中不同区段——所以换档不需要重绑任何 buffer、不需要 CPU 知情，indirect 命令三字段一改，GPU 执行时就画了另一份索引区间。`instanceCount` 语义不变（仍取剔除标记），`firstInstance = 槽号`（VS 按 instance_index 读 set2，5.3 定案）。

CPU 侧的配套只有两件，都在账面层：[`LodGroups`](../../../../ash_renderer/src/scene/mechanism/lod_registry.rs) 登记"基准 mesh 身份 → 各档变体柄"（level 0 复用实体自己的 mesh，零新资产；细分阶梯是程序化网格，同参共享缓存）；flush 上传链按它把档位资产一并盘点上传，draw_frame 把各档引脚写进 b7 表。

## 四、与 Hi-Z 的关系：复用模式，不共享产物

像素空间的 **AABB 8 角点投屏**在 `occlusion.wgsl`（6.1 遮挡）与 `lod_select.wgsl`（6.2 LOD）中各算一次；`cull.wgsl`（5.2 视锥）用包围盒与六平面判相交，**不生成供这两者复用的投屏像素矩形**。原计划的“一次投影两个消费端”没有落成运行时共享 buffer，目前是两个独立 pass 各自执行同型投屏逻辑、各自消费结果。将来可抽公共 WGSL 函数减少源码重复，但这也不等于跨 dispatch 共用计算结果。

数学上是同一族映射——"屏幕足迹 → log2 → 层级"，但三处参数各钉各的：

| | Hi-Z 选 mip | GPU LOD 选档 |
|---|---|---|
| 输入 | AABB 投屏像素最大边 | 同一个 s |
| 映射 | `ceil(log2(s))` | `floor(log2(threshold / s))` |
| 选什么 | 深度金字塔 mip（采样粒度匹配足迹） | mesh 档（几何密度匹配屏占比） |
| 取整方向 | ceil（tile ≥ AABB，过覆盖只会更保守） | floor（每减半升一档） |
| 状态 | 无（每帧现算，读错只损一帧精度） | 有（迟滞环，换档是可见事件） |
| 消费金字塔 | 是（4 tap 采样） | 否（连 hiz 布局都不挂） |

**为什么不用一个 buffer 共享投屏结果**（把 occlusion 算好的像素矩形存下来给 LOD 读）——四条理由按分量排：

1. **生产者要独立于遮挡开关**：三开关（视锥/遮挡/LOD）需独立归因。若 LOD 直接读遮挡 pass 的投屏结果，遮挡关闭时就没有生产者，会读陈旧值；可以另设始终运行的 prepare pass 解决，但即使遮挡关它也要计算/写 buffer，须把开关组合与成本一起设计。不是数学上必须维护 2³ 种单独生产者。
2. **重算还是缓存要测 GPU 成本**：每角点是模型变换和视图投影（两次 mat4×vec4），重复两遍投影有实际 ALU 成本；共享则要付写/读 storage buffer、描述符布局与屏障成本，并处理两种独立开关。5.5 的 CPU 提交侧约 0.4ms **不能证明 GPU 投屏免费**；没有逐 pass A/B 计时前，只能说本段优先较少数据依赖的实现，不能宣称共享必然亏。
3. **产物形状不齐**：遮挡投屏顺手算 obj_depth_max（LOD 不要），LOD 只要 clamp 后的最大边——共享产物要么存超集，要么横竖分叉。
4. **升级点是收益实测，不是消费者个数门槛**：独立 prepare pass 在多处需要同一个投屏矩形时可以降低重复计算，但也增加全局写读和调度；按目标 GPU 的两种路径计时，再决定是否共享。这里没有“消费者达到四个才划算”的通用阈值，也没有已立案的 5.4 回改任务。

收拢：当前两次投屏可让遮挡与 LOD 独立开关；若想共享，要明确单一生产者、结果格式、同步点及其 A/B 实测收益，不能用 CPU 提交时间替 GPU 投影成本作证。

## 五、管线位置与 A/B

第三个 compute pass 的时序是刻意排的：**视锥 → 遮挡 → LOD 选档 → build_indirect**。在遮挡之后，被完全遮挡的实例也已参与选档（浪费一次投屏，换"不需要先压缩再选档"的链路简单——只对可见实例 dispatch 是压缩合批的活，归 5.4）；在组装之前，因为它的输出就是组装命令的输入。

A/B 开关（[`LodSettings`](../../../../ash_renderer/src/vulkan/lod.rs)，egui checkbox 与 BRP 方法族写）：关 = 不 dispatch，档位环 host 填 0（全最细档）——命令三字段回到对象记录基准，B 面画面语义精确等于 5.3。LOD 关闭不设任何特殊绘制路径，数据层的 B 面自然退化，这是三开关能独立归因的原因（判定线 5）。
