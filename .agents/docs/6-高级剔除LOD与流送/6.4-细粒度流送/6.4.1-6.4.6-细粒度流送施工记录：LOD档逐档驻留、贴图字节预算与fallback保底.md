## 1. 逐任务实录

### 6.4.1 子资产驻留条目与预算下沉

- **`ResidencySettings`/`ResidencyStats` 扩 6.4 段**（[residency.rs](../../../../ash_renderer/src/scene/mechanism/assets/residency.rs)）：`budget_image_bytes`（贴图预算第二列，0=不限）+ `fine_grained`（细粒度开关，默认 false = 6.3 整资产粒度）+ 读数（used_image_bytes/over_budget_image/lod_levels_resident/lod_levels_ejected_total）。
- **`EjectCooldown` 双表**：mesh/贴图身份分列（键型不同、防抖语义同源）。
- **AssetId 表达**（待决 3 钉明）：LOD 档位条目直接用既有"档位=独立 Mesh 资产身份"（6.2 阶梯结构），**不派生子 Id**——失效/热重载联动（4.2/4.4 判定线）零改动即兼容。

### 6.4.2 LOD 档逐档驻留（6.2 fallback 正式被驱动）

- **需求集语义**（判定线 1 的关键钉明）：组内引用行的期望档位 = 6.2 选档公式 CPU 参照（同 threshold 同 screen，`lod_raw_level` 无迟滞——管理器的迟滞由请求半径+冷却承担）；需求 = 每行 `{0} ∪ {L_row}` 的并集——**管理器目标需求**：远处行（raw=3）为基准+最粗档、近处行（raw=0）为基准；非目标变体档列入淘汰候选。注意上传链处理脏行时仍会盘点该组**全部**缺席的非基准变体（`upload.rs` LOD 组段），实际驻留不保证始终等于此需求集。管理器判定无迟滞时 GPU 侧迟滞由 6.2 表内回退兜底（选档保持细档 → 表条目缺席 → 回退更细常驻档）。
- **level 0 不参与 6.4 的逐档淘汰**（最细基准）：它仍是行可绘前提和表内回退终点；但 6.3 的 mesh 预算淘汰可移除基准驻留，届时整行暂缓。这里的“基准永驻”仅指 6.4 变体档策略不主动淘汰它，**不是任何预算下都留在显存**；“行换绑粗档”代理柄方案未采用。
- **档位淘汰连带 `mark_lod_dirty`**（首钉②，见 §3）：变体区间进停尸房/free list 后 b7 表条目残留引脚会画错几何——同步清哨兵。
- **请求合并**（判定线 3）：行置脏一次，flush 的 LOD 组盘点段收集该组全部未驻留档（6.2.2 既有形状）；这虽复用了去重上传，却也意味着按需目标档并未限制实际上传集合。

### 6.4.3 贴图整资产流送与粗档保底

- **贴图字节预算**：`used_image_bytes = image_cache.resident_bytes()` 现读；超支按"引用行最近距离远优先"淘汰整资产（`AssetRetirements::eject_image` 新方法——与 eject_mesh 同款：同一回收账、不进事件累计）。
- **粗档保底 = fallback 白图**（待决 2 钉明按"极端形式"落定）：缺席档由永驻 0 号槽兜底——零悬空采样由 fallback 槽保证（验证层零告警 + 读图无黑洞）；**整图替换（粗/细双 GpuImage swap）不做**——整资产粒度压测未证伪，替换式留待步骤 7 真实资产（待决 1 落定）。
- **重驻留限制（事后代码复核）**：预算内分支的 `image_groups` 只收已驻留图片，随后在该组上查缺席的条件不能主动发现被淘汰的贴图；行若因其他原因置脏，材质五槽盘点仍可重传。回访缺图的自动恢复不能只凭该分支宣称成立，后续须补请求来源与专项测试。

### 6.4.4 合流与 A/B

- `fine_grained` 关 = 档位不请求不淘汰（全驻留，6.2 语义）；开 = 逐档管理。**两面的档位驻留计数统一统计**（首钉①，见 §3——关面读数也要如实）。
- 6.2 的 GPU 表内回退（`pick_lod_entry`）在本段被真实驱动：细档缺席场景全程 draw_calls 恒 1（压测 ①b/③）。

### 6.4.5/6.4.6 验证通道与回归

- BRP `residency_stats` 扩 `fine` 段（fine_grained/贴图账/档位账）+ `residency_set` 扩 `budget_image_bytes`/`fine_grained`；brp.py `--image-budget`/`--fine`。
- **`tools/scene_fine.py`**：unique 阶梯网格（LOD 档载具）+ 默认 Helmet 场景（贴图账载具，零新资产）——判定线八项采证（§4）。
- **读图两态**（.temp/fine_shot_white/restored.png）：贴图缺席态头盔主体降级 fallback 白图（木底座小贴图仍驻留）、恢复态全纹理回归——无黑洞无花屏，判定线 2 的读图半边成立。

## 3. 施工钉子（首钉在前）

1. **首钉①：预算 0 = "不限"被读成"全淘汰"**——mesh 淘汰条件 `used > budget_mesh_bytes` 在预算 0 时恒真（贴图账联调实抓：mesh 预算 0 + 贴图预算激活时全场景 mesh 无限淘汰-重传拉锯，68 批次 mesh 6 个重传）。修复 = 淘汰只在预算非零时执法（`budget > 0 && used > budget`）；贴图段同款语义自始正确。
2. **首钉②：变体档淘汰不 清 b7 表 = 画错几何**——变体区间进 free list 复用后，残留表条目引脚指向新内容；淘汰同步 `mark_lod_dirty`（表重写查无 → 哨兵）。
3. **首钉③：eject 当帧排队重请求 = 自我拉锯**——贴图 eject 后无条件把引用行塞进重驻留队列（同帧重传，used 恒定全量、eject 空转，诊断实抓 candidates=15/cooling 增长/used 不动）。修复 = 淘汰不排队，重请求交给冷却过期的"预算内"分支。
4. **mesh thrash 让行永在置脏集 → 贴图 eject 被排除法饿死**（压测④ 实抓，"本 tick 置脏行的贴图跳过"的排除法与 mesh 淘汰拉锯互斥）——压测解法 = 两账分开采证（④ 先解除 mesh 预算再压贴图账）；工程口径：贴图淘汰的稳定条件是行不置脏，混合预算场景的公平调度留步骤 7。
5. **关生效前的在途请求消化**：BRP 写值次帧生效，②末 pending 行完成可能短暂触顶淘汰（scene_stream ④ 判定实抓 +5）——判定容差 = 场景资产数口径。
6. **档位驻留计数两面统一**：fine_grained 关面也要如实统计（首版只在细粒度分支计数 → 关面读数恒 0 假 FAIL）。

## 5. 遗留与顺延

- **整图替换（粗/细双 GpuImage swap）**：本段未实现 mip 分级驻留，待步骤 7 真实资产压测证伪整资产粒度后再议（待决 1）。
- **贴图缺席后的主动恢复**：`image_groups` 当前只包含已驻留图片，预算内缺图请求分支缺乏缺席项来源；需要从材质引用建候选并单测回访，不能用本段白图/恢复读图两态代替该条件验证。
- **目标档与物理上传不一致**：LOD 需求集只控制请求/淘汰策略，脏行上传仍扫全组缺席变体；将来若要严格按需、预算可预测，上传端须按目标档过滤。
- **混合预算的公平调度**：mesh thrash 与贴图 eject 的互斥（钉子 4）——预算充裕侧先稳的启发式留步骤 7。
- **mip 判据投屏联动**：替换式立项时一并（待决 6）。
- **步骤 6（M5）步骤级验收归档**：四段施工收官，验收归档未做（沿 5/6 惯例留用户拍板）。
