# 细粒度流送流程：从整资产账到子资产条目的各级账面

> 6.4 功能流程导读（2026-10-19 收官定例）：本段把 6.3 的驻留管理器从"整资产粒度"扩展到"LOD 档位 + 贴图字节"两个子资产维度，按定例写"从入口动作到最终落点"的走读。面向下一个读代码的人；验收证据归[施工记录](6.4.1-6.4.6-细粒度流送施工记录：LOD档逐档驻留、贴图字节预算与fallback保底.md)。

## 0. 一句话全景

`residency_tick` 在 6.3 的 mesh 整资产三段（聚合→请求→淘汰）之后追加两段：**LOD 档段**（fine_grained 开时，按组内引用行期望档位逐档请求/淘汰变体，基准永驻）；**贴图段**（贴图字节预算第二列，超支按距离淘汰整资产、缺席由 fallback 白图兜底）。两段都只写既有账（脏标/回收账），零新 Vulkan 形状。

## 2. 逐时刻走读（tick 内五段）

**前置（6.3 原样）**：读数刷新（mesh/image 两列）→ B 面（关闭沿全行置脏）→ 身份聚合 → 冷却双表走账 → mesh 请求 → mesh 淘汰（**预算 0 不执法**——"不限"语义钉明）。

**LOD 档段（6.4.2）**：对每个登记组（账本聚合里的基准身份 ∩ LodGroups）——逐行算期望档位（`aabb_screen_rect` + `lod_raw_level`，与 GPU 选档同公式同 screen）→ 管理器目标需求集 = 每行 {0, L_row} 并集 → 目标档未驻留 ∧ 组在半径内 ∧ 冷却过期 → 引用行置脏；**现有 flush 对脏行会盘点该组全部缺席的非基准变体，并不只上传目标档**，因此目标需求集不等于最终实际驻留集。非目标变体驻留中 → eject + 冷却 + **`mark_lod_dirty`**（b7 表条目清哨兵——残留引脚在 free list 复用后画错几何）。fine_grained 关 = 不做逐档请求/淘汰。

**贴图段（6.4.3）**：材质 → 行距离聚合 → 已驻留贴图身份聚合（五槽展平）→ 超支按距离远优先 eject_image（跳过冷却内与本 tick 置脏行引用的贴图——后者材质腿同帧重传会让 eject 空转）；缺席期间 GPU 采样走 fallback 白图（永驻 0 号槽）。**重驻留限制**：代码的预算内请求分支只遍历已驻留贴图聚合表，无法单靠该分支重新发现被淘汰的贴图；若行因其他原因置脏，flush 的材质腿仍会尝试重传。完整的缺图主动请求循环尚待补齐，不能把此处写成已实现的半径内自动恢复。

**消费侧（零改动）**：mesh 变体回收走 4.4 停尸房；贴图回收走 ImageCache.retire（描述符槽待回收账）；重传走 4.2/4.1 盘点；GPU 选档走 6.2 build_indirect 表内回退。

## 3. 语义要点

- **管理器目标需求集 = {0, L_row} 并集**（非 {0..L_row}）：level 0 是最细基准，远处目标为基准+所选粗档，近处目标为基准；但脏行上传可把同组其他缺席档一并传入，不能据此声称物理驻留始终恰是需求集。6.3 的整资产预算仍可淘汰基准，届时该行暂缓。
- **预算 0 = 不限**：两列各自独立执法，任一非零即激活管理器；全 0 = B 面（全常驻，关闭沿全行置脏）。
- **eject 当帧不排队重请求**：重驻留只从冷却过期的请求分支发起（同帧重传 = 自我拉锯，实抓钉）。
- **两账分开采证**：mesh thrash 让行持续置脏会饿死贴图 eject（排除法的结构性互斥）；已淘汰贴图的主动重请求也需从材质引用而非已驻留贴图集合发现。混合预算公平调度和缺图请求闭环均未由本段完整解决，须在后续施工时专项复验。
