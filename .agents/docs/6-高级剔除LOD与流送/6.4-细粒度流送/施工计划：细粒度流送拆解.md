## 0. 判定线（验收草案）

1. **细节渐进不闪回（红线）**：接近对象时细 mip/细 LOD 档流进、画面由糊变清；远离后细档可淘汰、回访恢复——中途不出现"清了又糊"的闪回（连拍读图取证，闭环 5.4 遗留的"mip 远景不闪"连拍半项）。
2. **回退零悬空采样（红线）**：未驻留细档的采样落在常驻粗档上——零未定义采样（验证层零告警 + 读图无黑洞/花屏），回退路径在最高细档缺失、多级同时缺失下均成立。
3. **请求合并与预算下沉**：同资产多级请求合并（相邻/连续级一次请求）；子资产条目进 6.3 预算账且账面与实测对账一致；6.3 判定线在子资产粒度下零回退。
4. **A/B 成组记录**：细粒度开关对照（关=退化到 6.3 整资产粒度）——驻留 byte 曲线（细粒度省多少）、GPU 图形段区间、游历吞吐（5.5 底座 + 6.3 读数族）；按[统一验收与性能口径](../../学习目标实现步骤.md)成组报告。
5. **既有判定线零回退**：4.1~4.4、5.x、6.1/6.2/6.3 全量；mip 链静态资产路径（5.4 判定线）在子资产驻留存在下不回退；零 VUID、WM_CLOSE exit 0、clippy 全净、库测试、resize/拆 Device 排空共存。

## 1. 定位：现状与要补的东西

6.3 收官后：chunk/整资产级进出已成立，但**资产内部仍整块驻留**——一张贴图的全部 mip、一个 mesh 的全部内容要么全在要么全不在。步骤 7 的真实资产（高分辨率贴图、高面数 mesh）会让"整块"粒度浪费显存：可见细节只值一两个 mip 级。6.4 下沉驻留单位：

- **mip 生成与上传能力现成**（5.4）：全 mip 链生成 + blit 续批（graphics 队列续批先例，[施工记录](../../5-GPU驱动与常驻大场景/5.4-常驻大场景组织/5.4.1-5.4.5-常驻大场景组织施工记录：生成器、chunk组织与mip链.md)）——缺的是"按级驻留"的账与替换动作。
- **替换式细化有先例**（4.2）：swap-on-commit 重传链（AssetId 内容变化→新驻留条目→发布→旧条目停尸房）——"低清整图 → 高清整图"的替换照此形状；图像没有"部分 mip 存在"的常规形状（要么全尺寸图全填充，要么换图），替换式是最短路径（§5 待决 1）。
- **sparse 的边界**（[VT 调研笔记](../../笔记/渲染/虚拟纹理调研：页表、feedback%20与流送.md) §4）：sparse residency 只解决"地址空间稀疏映射"（省尾 mip/空洞），没有驻留策略层——"要'省尾 mip'用 sparse；要'按视口流送'才是 VT"；本段若走 sparse 只是用它省尾 mip，不是上 VT。
- **回退消费端现成**：6.2 的"未驻留档回退最近常驻档"（fallback 逻辑就位待驱动）+ 采样侧 mip 回退（§5 待决 2）——缺档期间画面是"粗一点"不是"坏"。
- **预算账下沉**：6.3 驻留条目状态机从"资产粒度"扩"子资产粒度"（同一状态机、更细条目），不另起第二本账（§5 待决 5）。

顺序理由：账面先行（没有子资产条目，流进/回退无据）；流进与回退次之（本段核心动作），合并与淘汰再次，LOD 合流随后（依赖前两步的条目与回退就位），验证通道最后。6.4.1~6.4.2 是本段主体。

**与冻结边界的关系**：对象表/材质表/标记环/命令环布局不动（6.2/6.3 同款边界）；贴图驻留若走替换式，材质环 tex_index 指向的驻留条目语义扩"子条目"（材质环记录布局不变、指向对象换——照 4.2 swap 语义）；sparse 路线若采纳，图像创建/绑定路径是新增形状（随待决 1 落解冻清单）。

- **BRP 驱动 + 场景脚本**（6.2.1 载具扩展）：高分辨率程序化纹理（load_image 动态加载）与多档 mesh 混布；`set_camera` 沿接近/远离轨迹扫掠；逐级驻留与预算由 BRP 设定。

- **截图读图**（按[画面功能视觉验证](../../../rules/画面功能视觉验证.md)）：细粒度关闭档=6.3 整资产档基线；开启档接近扫掠连拍——由糊变清单调、无闪回无黑洞；最高细档缺失负例读图——粗档兜底画面完整。

## 5. 待决问题（施工时钉明，不写死）

1. **mip 流进实现**：替换式（整图 swap，低清→高清换驻留条目——4.2 链复用，最短路径——倾向）vs sparse residency（按级绑定省尾 mip，特性面新增、绑定路径新形状）——倾向替换式起步，sparse 留压测证明替换式带宽不可接受时再评估。
2. **回退机制**：视图 mip 范围截断（ImageView 只露常驻级，采样自然落粗档——倾向，GPU 侧零查询成本）vs shader 端按驻留表选级（灵活但每采样加查询）；与 6.2 LOD fallback 的口径互相引用。
3. **子资产 AssetId 表达**：同 Id 内容版本（4.2 语义）vs 子 Id（AssetId+级号派生键）——影响失效/热重载联动（4.2/4.4 判定线），随 6.4.1 钉明。
4. **粗档保底策略**：最粗级/最低 LOD 档永驻（回退恒有落点——倾向，保判定线 2）vs 全粒度预算化（极端挤压下连粗档都让位，回退落"整资产缺席"=chunk 级语义）；倾向前者起步。
5. **管理器同体 vs 分层**：6.3 驻留管理器直接扩子资产条目（一本账多粒度——倾向）vs 独立细粒度管理器（两本账对账）——倾向同体，避免两本账打架。
6. **mip 选择与 LOD 判据的联动**：贴图 mip 流进判据（屏幕占用/采样粗细）是否复用 6.2 选档投屏——倾向共用投影，随 6.4.3 钉明。
