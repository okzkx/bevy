## 0. 判定线（验收草案）

1. **预算硬约束（红线）**：驻留显存 ≤ 配置预算（顶点+索引+贴图 byte 总账，口径随待决 3 钉明）；超预算时请求排队、淘汰先行，预算读数（budget/used/请求队列深度/淘汰计数）BRP 可查且与账面一致。
2. **可持续游历（红线）**：超预算场景连续漫游不中断——无悬空引用（GPU 只消费已发布行）、无无限显存增长、淘汰区域回访可重新请求恢复；游历全程零 panic、零 VUID。
3. **可用性发布语义**：未就绪资产不进绘制（4.3 readiness 语义延伸：请求中→就绪→发布三态，arrive 才发布）；缺档期间消费侧不炸（LOD fallback / chunk 整块缺席都是合法画面状态，读图留证）。
4. **淘汰不产生幽灵绘制（红线）**：先撤引用后回收——被淘汰资产对应的实例在淘汰瞬间从可绘集合消失（对象表/在场环/命令环一致性），不重演 5.3 幽灵对象盲区；回收复用 4.4 停尸房/free list，槽位复用不串内容。
5. **A/B 成组记录**：流送开关对照（预算=∞ 退化为全常驻基线）——GPU 图形段帧区间（5.5 底座）、驻留 byte 曲线、请求/淘汰吞吐、静态场景零重传（4.1 判定线延续：不动的世界零上传）；按[统一验收与性能口径](../../学习目标实现步骤.md)成组报告。
6. **既有判定线零回退**：4.1~4.4 增量/异步/回收判定线全量、5.x 全量、6.1/6.2 判定线；热重载链（4.4）与失效重传（4.2）在驻留管理器存在下照常工作；零 VUID、WM_CLOSE exit 0、clippy 全净、库测试、resize/拆 Device 排空共存。

## 1. 定位：现状与要补的东西

6.2 收官后的链路：视锥 → 遮挡 → LOD → build_indirect 一次绘制；**驻留侧仍是"进场即上传、永驻显存"**——4.1 账本 + MeshPool 只在 despawn 时卸载（4.4），"放不下的世界"还没被承载过。5.5 十万档全常驻成立，但 chunk 总量继续涨时显存线性涨，需要"用完让位"：

- **chunk 是天然进出单位**（[scene_gen.rs](../../../../ash_renderer/src/scene/mechanism/scene_gen.rs)）：`SceneChunk` 组件挂根实体、实例为其子实体，**chunk 不进 GPU 侧**（CPU 组织与增删粒度，`:149-158`）——请求/淘汰以 chunk 为主单位、单资产引用计数兜底（§5 待决 1）；census/despawn 方法族现成（[remote/mod.rs](../../../../ash_renderer/src/remote/mod.rs) `:78-79`），批量增删实测精确且零重传（5.4）。
- **请求→上传→发布链的地基全在**：4.3 [asset_readiness.rs](../../../../ash_renderer/src/scene/mechanism/asset_readiness.rs)（pending/arrive/fail/revive 显式账面，`:70` 起）+ `load_mesh`/`load_image` BRP 方法族（remote/mod.rs `:82-83`）+ uploader 批次链（driver/upload.rs）——本段把"手动 load 触发"换成"管理器按预算与相机自动请求"，账面语义不另起炉灶。
- **淘汰→回收链的地基全在**：4.4 双停尸房（mesh 停尸房 + 实例槽停尸房，`instance_table.rs:15,622`）+ MeshPool free list（[pool.rs](../../../../ash_renderer/src/vulkan/pool.rs) `:137-138,346`）——本段补的是"谁该被淘汰"的策略与"淘汰时实例侧一致性"的撤引用时序。
- **预算挂靠点**：MemoryContract（[context.rs](../../../../ash_renderer/src/vulkan/context.rs)，既有显存契约声明）——流送预算是其上的运行期可配子账，不推翻既有契约。
- **消费半边已备**：6.2 的"未驻留档回退"与 chunk 整块缺席（对象槽消失）都是本段的合法画面状态；6.2 fallback 逻辑在本段被真实驱动。

顺序理由：管理器与预算账先行（没有账面，请求/淘汰都是无据操作）；请求侧次之（有预算才能谈排队），上传发布再次（有请求才有流进），淘汰回收随后（有流进才有让位），验证通道最后（有开关与读数可对照）。6.3.1~6.3.4 是本段主体。

**与冻结边界的关系**：对象表/材质表记录布局不动（5.1 定案，本段是资产驻留层的账，不碰实例记录形状）；标记环/命令环/在场环不动；新增的驻留账与预算账是 CPU 侧资源层新账（照 4.3 AssetReadiness 资源层先例），GPU 布局零解冻。

## 4. 测试方案与证据形态

- **BRP 驱动 + 场景脚本**（6.2.1 载具扩展）：场景脚本生成超预算 chunk 场景（预算档与 chunk 总量配对）；`set_camera` 沿游历路径推进；预算/请求/淘汰由 BRP 设定与读取。
- **CPU 参照专项**：驻留状态机转移表库测试；预算账与 MeshPool/纹理 usage 实测 byte 对账（账面 ≠ 实测即失败）；淘汰后 free list/停尸房读数对账。
- **计量读数**：驻留 byte 曲线随游历的时间序列、请求/淘汰吞吐、GPU 图形段区间对照（5.5 底座）、静态场景零重传计数；egui 挂现有 perf 面板加驻留行。
- **截图读图**（按[画面功能视觉验证](../../../rules/画面功能视觉验证.md)）：预算=∞ 档与全常驻基线一致；超预算档读图对照（远处 chunk 缺席/回访恢复、无黑洞无残影）；游历连拍——画面状态随驻留变化平滑、无悬空引用征兆。
- **负例**：预算=0（全淘汰态存活不 panic）、请求风暴（同帧大量请求不炸不重传重复资产）、淘汰中回访（状态机竞态）、热重载/失效重传与驻留条目共存、despawn 与淘汰并发、拆 Device 排空（驻留账随排空清零）。
- **回归矩阵**：4.1~4.4 判定线全量、5.1~5.5 判定线、6.1/6.2 判定线、三模式基线、零 VUID、WM_CLOSE exit 0、clippy 全净、库测试、增删后 resize×2 不炸。

## 5. 待决问题（施工时钉明，不写死）

1. **淘汰单位**：chunk 级整块进出（与请求对称、组织现成——倾向）为主 + 单资产引用计数兜底（多 chunk 共享资产不被误杀）；纯资产粒度 vs 纯 chunk 粒度的极端方案的否决/采纳随 6.3.4 实测定。
2. **淘汰策略**：距离 LRU vs 视锥外优先 vs 两者加权——倾向"视锥外 ∧ 距离远"优先、LRU 兜底；防抖动（刚淘汰的 chunk 短期不重进）是否要冷却窗，压测读数说话。
3. **预算口径**：顶点+索引+贴图 byte 总账（单一数字——倾向，读数简单）vs 分类分账（vertex/index/texture 各自预算）；staging 环不计入驻留账（瞬态）钉明。
4. **请求优先级公式**：距离、视锥内外、相机朝向投影各占多少权重——从"距离+视锥外延一档"最简式起步，压测不出的次序问题再加重。
5. **暖启动**：初始进场是"预算内全请求"还是"相机周围渐进"——影响首帧体验与首帧上传风暴，随 6.3.2 钉明。
6. **chunk 身份与空间归属**：5.4 留的"运行期归属更新语义另立账"（scene_gen.rs `:158`）是否在本段顺带解决（淘汰/请求天然按空间查 chunk）——若牵扯过大则维持 chunk 身份=生成期组织不变，只加"空间→chunk 根"的查询侧索引，随 6.3.2 钉明。
