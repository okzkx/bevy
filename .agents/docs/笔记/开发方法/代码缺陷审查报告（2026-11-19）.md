# 代码缺陷审查报告（2026-11-19）

> 范围：`ash_renderer/src`（198 文件 / 约 3.4 万行）+ `shaders/`，基线 `HEAD=a3396352d`。
> 方法：6 个模块审查员并行（设备/帧循环/绑定常驻表/各 pass/可见性/场景与远程），每条必须给 `file:line` + 触发条件 + 机制；随后逐条复核、修复、跑验证。
> 结果：**确认缺陷 19 项（P0×2、P1×6、P2×6、P3×5），已全部修复**；另有 12 项确认但未修（需设计拍板或属调参/精度取舍），列在 §4。
> 验证：`cargo clippy -p ash_renderer --all-targets -- -D warnings` 零告警；`cargo test -p ash_renderer --lib` 93/93；实跑 Sponza 3 次（含开启同步验证）零 VUID、零 `SYNC-HAZARD`、零 panic。

## §1 结论先说

代码主体质量高：视锥/Hi-Z/LOD 的数学、barrier 链、上传票据、帧槽账本都经得起逐行核对。问题集中在**边界计数**（写多少条 / 画多少条）、**声明与实例的一致性**（管线深度格式 vs 实例附件、设备 feature vs 实际用法）、**失败后的状态推进**（fatal 后还继续录帧、提交后出错直接 Drop 目标）。这些都是"正常路径看不出、换设备/换场景/换时序才炸"的类型。

## §2 已修缺陷（按严重度）

### P0

1. **透明命令环只写 `t_count` 条，绘制却按在场行数消费**（`shaders/scene/transparent/transparent_gather.wgsl:31`、`driver/host/frame/transparent.rs:52`、`render/frame/record.rs:326`）
   gather 对 `i ≥ 透明行数` 直接 return，`[t_count, presence)` 保留两帧前的旧命令或分配初值；透明行数下降时重放旧对象（幽灵绘制），首用执行未初始化命令。改为**尾部写零命令**，并对 `TRANSPARENT_CAPACITY` 双重夹界。

2. **`drawIndirectFirstInstance` 未查询、未启用**（`render/core/device/context.rs`）
   所有 indirect 命令都用 `firstInstance = 槽号`，但 `base_features` 只开了 `multi_draw_indirect`。未启用时规范要求该字段必须为 0（VUID-vkCmdDrawIndexedIndirect-None-02705），而 Vulkan 1.4 才强制支持它。修法：查 `features2.features.draw_indirect_first_instance`，不支持则明确报错退出，启用位补进 `base_features`。

### P1

3. **SMAA edge 目标 `loadOp=DONT_CARE` + shader `discard`**（`render/passes/post/smaa.rs:529`、`shaders/post/smaa/smaa_edge.wgsl:59`）
   非边缘像素永不写入且不清，内容未定义，blend 采样会读到上一轮的旧边缘（运动鬼影）。edge pass 改为清零（`clear: Some([0.0;4])`），blend 仍不清（写满全屏）。

4. **overlay 管线声明 D32，但所在渲染实例没有深度附件**（`render/passes/overlay/overlay_pipeline.rs:48`）
   UI 画在 SMAA neighborhood 开的实例里，该实例只挂 color。实例深度为 NULL 时管线 `depthAttachmentFormat` 必须是 `UNDEFINED`（VUID-vkCmdDraw-dynamicRenderingUnusedAttachments-08913，已用本地 `validusage.json` 原文核对）。改为 `depth_format: None`。

5. **BCn 非方形贴图 mip 末级少算一级**（`render/resident/assets/bcn.rs:81`、`bcn_cache.rs:121`）
   `level_bytes` 用 `height >> level` 未 `max(1)`，末级 1×0 算成 0 字节；而 bake 实际写一个块。后果：staging 按 `total_bytes()` 少分配、磁盘缓存长度校验永不命中（每次加载重烤）。改为 `max(1)`，缓存头同时补 `format`/`mip_levels` 语义校验。

6. **`VkValidationFeaturesEXT` 进了 pNext 却没启用扩展**（`render/core/device/context.rs:163`）
   违反 VUID-VkInstanceCreateInfo-pNext-10243，同步验证实际没生效。修法：按**层名**枚举扩展（`None` 只返回全局扩展，这是本次实跑抓到的真坑），有 `VK_EXT_validation_features` 才启用并加入扩展清单。

7. **致命错误后帧循环还继续跑**（`common/error.rs`、`driver/host/frame.rs:76`、`driver/upload.rs:223`）
   `tier_handler` 只置位，`fatal_gate` 下一帧 `First` 才写 `AppExit`，同帧 `Last` 的 `draw_frame` 仍执行；若上一帧停在"fence 已 reset、submit 失败"，`wait_for_slot` 会永久阻塞，退出都轮不到。修法：FATAL 不再被 gate 清位，新增 `fatal_pending()`，`flush_uploads`/`draw_frame` 入口直接早退。

8. **`submit_batch` 在 transfer 已提交后仍可能返回 Err**（`render/core/device/transfer/uploader.rs:404`）
   续批 blit 录制失败时直接 `?`，调用方按"未提交"处理并 Drop 目标图像 → 在飞拷贝写已销毁对象。修法：失败先 `wait_until(ticket)` 再上报。

### P2

9. `readback_buffer` 零长度输入会建 0 字节 buffer、录 0 字节拷贝（两条规范 VUID）。空切片直接当成功。
10. `load_world`（BRP）与 `--scene` 用 `from_asset(String)`，非法路径走 `AssetPath::parse().unwrap()` panic。两处改 `try_parse`（BRP 回协议错误，CLI 回退默认场景）。
11. 账本"同柄重插"分支把行重置为 `instance_slot=None` 且不回收旧槽 → **每次重插泄漏一个对象表槽**（容量 131072 耗尽后致命）。改为保留 `instance_slot`/`bound`。
12. 预算淘汰 mesh 不重挂 LOD 脏标：`floor_anchor` 下行仍可绘（锚档），LOD 表指向已回收区间。改为淘汰时对这些行 `mark_lod_dirty`。
13. 贴图预算淘汰后**永不回流**：`image_groups` 聚合时过滤了未驻留贴图，导致"预算内重请求"分支恒为空。改为聚合包含未驻留，淘汰分支自行过滤。
14. LOD 迟滞判据用 `B(raw)` 而非 `B(prev+1)`：跳档时阈值被压到 `1/2^(raw-prev)`，物体长期画最细档再一帧跳多档。WGSL 与 Rust 同步改为"每次至多向粗一档、按下一档边界判定"，并补回归测试（单档用例行为不变）。

### P3

15. `paint::blit` 起点在界外时 `copy_w` 裁成 0 但切片起点仍越界 panic；补 `x0 >= mw || y0 >= mh` 早退。
16. `InstanceTables` 描述符写入失败只回收 layout/pool 的一半（写循环里的 `?` 直接走）；补 `inspect_err` 回收。
17. `FullscreenPipeline` 忽略配方的 `depth_format`；补 `unwrap_or(UNDEFINED)`，与图形管线同一条声明纪律。
18. 光源脏账"剩余帧槽数"硬编码 2；改 `MAX_FRAMES_IN_FLIGHT` 并注明"只记次数不记环"的隐患。
19. present 返回 `VK_SUBOPTIMAL_KHR` 被丢弃；现在也置 `out_of_date`，与 acquire 侧统一。

## §4 确认但未修（需拍板/风险较高）

按影响排序，行号为实现处：

1. **`LodGroups` 无注销**（`scene/mechanism/assets/lod_registry.rs:29`）：`spawn_lod_ladder(unique)` 的强柄让资产永不 `Unused`，despawn 后 CPU/GPU 驻留都不回收。修法要接"最后一行消失"的注销路径，属生命周期设计变更。
2. **CPU 参照用 `row.mesh` 而非锚档**（`remote/census/ring_census.rs:149`、`features/{cull,lod,shadow,cluster}.rs`）：`floor_anchor` 下行会被判"记录不一致/行缺失"，诊断假阳性。修法：抽与写侧同源的锚解析 helper。
3. **材质贴图显式 `textureSampleLevel(..., 0.0)`**（`shaders/common/mesh.wgsl:51`、`gbuffer_write.wgsl:75`）：mip 链白建，缩小贴图闪烁。改 `textureSample` 需读图验收。
4. **LDR 中间目标 `R8G8B8A8_UNORM` 线性存储**（`present_tonemap_pipeline.rs:29`、`smaa.rs:267`）：暗部 8bit 线性量化，SMAA 阈值按 sRGB 域标定却算线性 luma。改 SRGB 目标要重排编码次数。
5. **Bloom 目标不分帧槽**（`post/bloom.rs:278`）：后链跨帧串行。按帧槽复制约 +5 级 HDR 显存。
6. **透明全容量 bitonic 无门控**（`transparent_passes.rs:173`）：无透明行也跑 105 次 dispatch + 105 条屏障。需宿主侧透明行数。
7. **`submit_batch` 提交后 commit/publish 失败仍在飞 Drop**（`driver/upload.rs:846-910`）：只走致命退出路径，退出时可能报在飞销毁；建议失败先等票据。
8. **swapchain 重建把 `DEVICE_LOST`/OOM 当可重试警告**（`resize_gate.rs:75`）：会每帧 warn 不退出。
9. **swapchain caps 未校验**（`swapchain.rs:175`）：`compositeAlpha`/`usage`/`colorSpace` 未按 caps 选，换平台 surface 可能违 VUID 或色彩错。
10. **panic/异常拆除的 Drop 顺序**（`context.rs:633`、`swapchain.rs:413`）：World 析构顺序不定时 surface 可能先于 swapchain 销毁。
11. **D32 线性过滤能力未查**（`gbuffer_targets.rs:321`）：桌面必支持，移动/特殊平台需查 `SAMPLED_IMAGE_FILTER_LINEAR`。
12. 诊断/参数小项：`hiz_census` 的 `slot` 取模不校验、`light_remove` 越界回 INTERNAL、灯参数不校验 NaN、采样器丢弃 LOD 参数、mesh 索引未与顶点数对账、零尺寸贴图会 panic、BC4/BC5 SNORM 缺 `block_bytes`。
