# 工程内存落位总表：按写者分组的分配点

新增一块渲染数据时，第一个要定的不是显存位置，而是谁来写：CPU 每帧直接写、上传批次写一次、GPU compute 写、作为图像附件，还是一次性中转缓冲。写者决定内存属性、同步方式和安全机制，位置只是结果。

本仓库把 buffer 的用途位（usage）和内存属性收在 [`BufferRole::spec`](../../../../ash_renderer/src/render/core/device/memory/role.rs) 的八种角色里：`DevicePool`、`Staging`、`Readback`、`FrameUniform`、`Storage`、`DynamicDraw`、`DeviceStorage`、`IndirectCommands`。创建 buffer 和挑内存类型都读这份规格；必需属性（HOST_VISIBLE——宿主可见；DEVICE_LOCAL——设备本地）不满足就报错，不降级。图像不走角色系统：附件和资产图各自创建，统一 DEVICE_LOCAL。

**写者相同，安全机制就相同；写者不同，内存属性与同步纪律就不同。** 全工程的分配点按写者分成五组，下面逐组列出数据、角色、写时机和消费者。

## ① 宿主每帧直写：HOST_VISIBLE 双帧槽，fence 之后写

这一组是 HOST_VISIBLE 的帧槽环。环指按帧槽各一份、轮转使用的一组缓冲；本仓库 `MAX_FRAMES_IN_FLIGHT = 2`，所以每个环两份。宿主写之前先等本帧槽的 fence（CPU 用来确认 GPU 已执行完某次提交的同步对象），写的是 GPU 上一轮已经用完的那份，不会撞上在飞的 draw。HOST_VISIBLE 内存在创建时持久映射（map 一次，直到销毁），写入就是往映射地址拷字节；非一致（non-coherent）内存由 `GpuBuffer::write` 自动 flush。

LOD 档位环是这一组里的例外：它由 `lod_select` compute 每帧写，只有 LOD 关闭时才由宿主填 0。把它放在这一组，是因为它与宿主填值共用同一套双帧槽与 fence 语义。

落点：`render/resident/tables/`（`frame_uniform_table.rs`、`light_table.rs`、`instance_table.rs` 的 HOST_VISIBLE 环）、`render/passes/`（`lighting/cluster.rs`、`post/bloom.rs`、`post/smaa.rs`、`overlay/ui_vertex_ring.rs`、`shadow/shadow_map.rs` 的 shadow UBO）。

| 数据（内容） | BufferRole | 写者·时机 | 消费者 |
|---|---|---|---|
| 帧 UBO（208B）：相机矩阵 `view_proj`、逆矩阵 `inv_view_proj`、环境光 `ambient_color`、方向光方向 `dir_to_light` 与颜色 `light_color`、着色模式 `mode`、相机位置 `camera_pos` | FrameUniform | 宿主在 `wait_for_slot` 后整块重写 | 场景 G-buffer、透明前向、合成、tonemap（场景 pass 的 set1 b0；合成/tonemap 里绑成 set0 b0） |
| shadow UBO（736B）：四级阴影级联（把视锥按视距切成四段，每段一张阴影图）的矩阵、4×6 视锥平面、分割带、相机朝向/位置、map 尺寸与开关、逐级阴影图像素对应的世界尺寸与深度盒倒数 | FrameUniform | 同上 | 剔除（四级级联内联标记）、`shadow_build` 与阴影绘制、合成（选级联） |
| Bloom/SMAA 参数 UBO（各 32B） | FrameUniform | 同上 | Bloom 升采样与 tonemap；SMAA edge/blend/neighborhood |
| cluster 均匀数据（160B：`view_proj`/`inv_view_proj`、near/far、tile 网格、`light_count`、渲染尺寸） | Storage | 同上 | `cluster_build` compute（b0） |
| 模型环（64B/槽：模型矩阵） | Storage | 宿主增量：`draw_frame` 按奇偶脏集写改动行，新增/换槽的行写满两个帧槽；静态场景零写 | 场景/阴影/透明顶点着色器；`cull`、`occlusion`、透明收集 compute |
| 材质环（64B/槽：基色、metallic、perceptual roughness、reflectance、四贴图槽、采样器槽、alpha 模式/阈值） | Storage | 宿主全量：每帧把可绘行的唯一材质从资产容器与驻留缓存（驻留：资产数据常驻显存、一直留着不撤）重投影一遍，不写空槽 | 场景/阴影/透明片元着色器；`build_indirect` 与透明收集 compute（透明判定） |
| 在场环（u32/条：可绘行槽号列表） | Storage | 宿主全量：`draw_frame` 每帧写列表 | `build_indirect` 的 dispatch 上界与遍历列表；透明收集 |
| LOD 变体表环（LOD：同一网格的多档精度；12B/档 ×4 档/槽：first_index/index_count/vertex_base） | Storage | 宿主增量：换槽或档位资产到货时写该槽，未驻留档保持 0 | `build_indirect`、透明 gather（b7） |
| LOD 档位环（u32/槽：本帧档位，兼作迟滞状态） | Storage | `lod_select` compute 每帧写；LOD 关闭时宿主填 0（最细档） | `lod_select` 读写、`build_indirect` 与透明 gather 读（b8） |
| 灯光常驻表（64B/槽：位置+半径、颜色×强度、flags；只装点光，方向光在帧 UBO） | Storage | 宿主增量：`LightLedger` 脏行，每个改动行写满两个帧槽；灯不变时零写；回收槽写死灯并可立即复用 | `cluster_build` 与光照着色（cluster set b1） |
| UI 顶点/索引环（20B/顶点、u32/索引） | DynamicDraw | 宿主全量：每帧整份重写，容量固定，超容丢弃当帧 UI | overlay 图形管线 |

## ② 上传批次写一次：换绑/换内容 = 新槽 + 旧槽等票据回收

这一组的数据在 DEVICE_LOCAL，宿主不能直接读写，只能通过 staging（中转缓冲：宿主写、transfer 拷贝队列读）加一次 transfer 提交写入。每次提交返回一个票据（transfer 完成的时间线信号量值），GPU 侧的后续提交等票据，确认写入可见；宿主要在回收、扩容、退出时才等它。对象表的换绑与换内容不走原地覆盖：先写新槽，旧槽进延迟回收账，等在飞 draw 用完再复用。

落点：`render/resident/assets/`（`pool.rs`、`images.rs`）、`render/resident/tables/instance_table.rs`（对象表）、`render/core/device/transfer/uploader.rs`。

| 数据（内容） | BufferRole | 写者·时机 | 消费者 |
|---|---|---|---|
| 网格顶点/索引大池 | DevicePool | 上传批次 `cmd_copy_buffer` 写一次；扩容时建新池整段迁移，旧池等帧槽 fence 后销毁；卸载区间等排空后复用 | 场景/阴影/透明绘制的顶点/索引拉取 |
| 纹理（每资产一份 GpuImage，OPTIMAL 平铺 + 每张图独占一块内存） | ——（图像） | staging → `vkCmdCopyBufferToImage` 一次；非压缩图在提交内 blit 生成 mip 链（逐级减半的图像层级） | 片元按槽号 bindless 采样（bindless：按槽号在描述符数组里取图和采样器） |
| fallback 白图（1×1，采样器槽 0 共用） | 同上 | 建 bindless 表时上传一次，永不回收 | 缺 base_color 贴图的 draw |
| 对象表（48B/槽：first_index、index_count、vertex_base、材质槽号、局部包围盒 AABB） | DeviceStorage | staging 批次写一次；换绑/换内容 = 新槽写、旧槽延迟回收，从不原地覆盖 | 顶点着色器读材质槽号；`cull`/`occlusion`/`build_indirect`/`shadow_build`/透明 compute 读绘制引脚、材质号与包围盒；BRP（Bevy Remote Protocol，从外部查询运行中程序的接口）对账回读 |

## ③ GPU compute 写：结论留在显存，宿主只读少量结果

这一组由 compute pass 写。间接命令环（indirect command ring：GPU 写出的 draw 参数数组，一次 `cmd_draw_indexed_indirect` 消费整段）留在 DEVICE_LOCAL，下一步 GPU 工作直接读；宿主需要看的少量结果才放在 HOST_VISIBLE 环里。两种内存都是双帧槽，宿主读取发生在 fence 之后，读到的是本帧槽上一轮（两帧前）的输出。

落点：`render/resident/tables/instance_table.rs`、`render/passes/`（`visibility/`、`shadow/`、`transparent/`、`lighting/cluster.rs`）。

| 数据（内容） | BufferRole | 内存 | 写者·时机 | 消费者 |
|---|---|---|---|---|
| indirect 命令环（20B/在场行：`VkDrawIndexedIndirectCommand`） | IndirectCommands | DEVICE_LOCAL ×2 帧槽 | `build_indirect` 每帧按在场列表全量重写；不可见行 `instanceCount=0` | 场景绘制一条 `cmd_draw_indexed_indirect`；绘制路径宿主不读，BRP ring census 可一次性回读抽查 |
| 阴影命令环（20B/条，每级联一份） | IndirectCommands | DEVICE_LOCAL ×2 帧槽（每帧槽 4 份） | `shadow_build` 每帧写四份 | 各级联 depth-only（只写深度）绘制 `cmd_draw_indexed_indirect` |
| 透明命令环（20B/条） | IndirectCommands | DEVICE_LOCAL ×2 帧槽 | `transparent_gather` 每帧写；空位写零命令防重放 | 透明前向一条 `cmd_draw_indexed_indirect` |
| 透明索引表/深度键表（各 16384 条） | DeviceStorage | DEVICE_LOCAL ×2 帧槽 | 键表先由录制段 `vkCmdFillBuffer` 全填 -inf；透明收集 compute 写真实条目；双调（bitonic）排序 105 次 dispatch 读写索引与键 | 排序 compute 与 `transparent_gather` |
| 簇列表（tile → 灯号，每格 68B：count + 最多 16 个灯号） | DeviceStorage | DEVICE_LOCAL ×2 帧槽 | `cluster_build` 每帧全量写（每格独占写 count，无需原子） | 合成与透明前向的光照计算（cluster set b2） |
| 缺口标记环（u32/槽位图：bit L = 选中档 L 未驻留） | Storage | HOST_VISIBLE ×2 帧槽 | `cull` 每帧对 bound 全部清零，`build_indirect` 对在场槽置位；cull 整体跳过时宿主在采样后补零 | 宿主在 compute 段采样本帧槽（两帧前输出）→ GapSnapshot → 驻留管理器；BRP |
| 可见标记环（u32/槽：视锥可见性） | Storage | HOST_VISIBLE ×2 帧槽 | `cull` 每帧全量写；主视图剔除关闭时宿主填全可见 | `build_indirect`（b3）；宿主 BRP 对账读 |
| 遮挡标记环（u32/槽：遮挡独立结果） | Storage | HOST_VISIBLE ×2 帧槽 | `occlusion` 每帧写；关闭、剔除关、金字塔未就绪、相机跳变时宿主填全可见 | 宿主诊断读（区分视锥与遮挡各剔了多少）；不参与画什么 |
| 阴影标记环（[槽][级联] 4×u32） | Storage | HOST_VISIBLE ×2 帧槽 | `cull` 每帧写四级级联视锥标记 | `shadow_build` 读（b5）；宿主 `shadow_stats` 对照读 |
| 簇计数（u32/格） | Storage | HOST_VISIBLE ×2 帧槽 | `cluster_build` 每帧写 | BRP `cluster_census` 读（CPU 诊断） |
| 透明计数（u32） | Storage | HOST_VISIBLE ×2 帧槽 | 宿主每帧清零；透明收集 compute 原子累加 | `transparent_gather` 读；BRP 读 |

## 为什么有的 GPU 产物必须 HOST_VISIBLE？

② 组的东西在绘制路径上宿主一件也不读：网格池、对象表、纹理全在 DEVICE_LOCAL，写只能走 staging 和 transfer 命令。③ 组里多数 GPU 产物同样留在 DEVICE_LOCAL：indirect 命令环、簇列表、透明索引/键表，下一段 GPU 工作直接读。只有宿主确实要读的几类小数据走 HOST_VISIBLE：缺口标记、可见/遮挡/阴影标记、簇计数、透明计数。

代价是实打实的。在独显上，HOST_VISIBLE 内存通常不是设备本地显存，GPU 读写更慢；所以不能把绘制主链的大块数据放进这类内存。这些回读数据都是每项 4B 量级的标记或计数，用途只有诊断、驻留请求和读数。角色系统把这个取舍压成一行规格：`Storage` 的必需属性是 HOST_VISIBLE，`DeviceStorage` 的必需属性是 DEVICE_LOCAL。这也是「写者不同，内存属性不同」的由来：GPU 写、GPU 读的东西可以留在显存；GPU 写、宿主读的东西必须付出宿主可见的代价。

## ④ 附件与交换链：图像统一 DEVICE_LOCAL，布局转换不复制

图像不走 `BufferRole`。附件（渲染时作为颜色或深度输出的图像）和资产图各自建 `VkImage`，查格式能力后要求 DEVICE_LOCAL 内存。附件每帧槽一套，随 swapchain 尺寸重建；阴影图尺寸固定，不随窗口变。跨 pass 复用靠布局转换，不复制内容。

落点：`render/core/target/attachment.rs`、`render/core/target/{color,depth}.rs`、`render/core/device/swapchain.rs`、`render/passes/`（`gbuffer/`、`shadow/`、`visibility/hiz.rs`、`post/`）。

| 数据 | 内存 | 备注 |
|---|---|---|
| G-buffer 附件（albedo R8G8B8A8_UNORM、normal R16G16B16A16_SFLOAT、matparam R8G8B8A8_UNORM） | DEVICE_LOCAL，每帧槽一套 | 不透明几何 pass 写；合成采样 |
| HDR 光照累积目标（R16G16B16A16_SFLOAT） | DEVICE_LOCAL，每帧槽一张 | 合成写 + 透明混合；Bloom/tonemap 采样，全程线性域 |
| 阴影图（4×2048² D32_SFLOAT） | DEVICE_LOCAL，进程级固定尺寸 | 阴影 pass 写，合成采样；resize 不重建 |
| Hi-Z 金字塔（R32_SFLOAT，完整 mip 链） | DEVICE_LOCAL，每帧槽一份 | 归约 compute 逐级写；遮挡测试读；诊断可回读单级 |
| Bloom/SMAA 中间目标（Bloom 5 级 RGBA16F 半分辨率起；SMAA LDR/edges/blend RGBA8 UNORM） | DEVICE_LOCAL，每帧槽一套 | 后期链逐段写读 |
| 深度附件（D32_SFLOAT） | DEVICE_LOCAL，每帧槽一张 | G-buffer 写 → 合成采样 → 透明 LOAD 只测 → Hi-Z 归约采样；只换布局，同一张图跨 pass 复用，不复制 |
| swapchain 底板 | DEVICE_LOCAL，交换链图像 | B8G8R8A8_UNORM 底板 + B8G8R8A8_SRGB view 别名（别名 view：同一张图的另一种格式视图，靠 MUTABLE_FORMAT 实现）；写 SRGB view 时做唯一一次 sRGB 编码 |

## ⑤ 中转与一次性缓冲：staging 按票据复用，回读一次一建

这两类都不承载跨帧渲染状态：staging 里的数据只活到 transfer 读完，回读的结果只活到本次 BRP 调用结束。

落点：`render/core/device/transfer/uploader.rs`、`render/core/device/readback.rs`。

| 数据 | BufferRole | 内存 | 生命周期 |
|---|---|---|---|
| staging（上传批次暂存） | Staging | HOST_VISIBLE 必需，HOST_COHERENT（宿主一致，写完不必手动 flush）优先；2 个槽，初始 1MB/槽，不足扩容 | 宿主写 → transfer 读；同一槽等上一批票据完成后复用，buffer 本身不随批次销毁 |
| 一次性回读（Hi-Z 层级、透明索引/键、对象表/命令环诊断） | ——（裸 buffer；`BufferRole::Readback` 目前没有创建点） | HOST_VISIBLE 必需，HOST_COHERENT 优先；`TRANSFER_DST` | 每次调用现建 staging + 命令池 + fence，提交后等 fence 读，Drop 即销；只在 BRP/低频诊断 |
