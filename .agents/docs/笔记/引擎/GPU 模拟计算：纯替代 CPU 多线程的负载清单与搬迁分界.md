# GPU 模拟计算：纯替代 CPU 多线程的负载清单与搬迁分界

> 2026-10-20 沉淀（6.1～6.4 全四段施工收官后的问答：用户问"粒子系统这些纯用 GPU 替代 CPU 多线程计算的是哪些"——真实项目里把原 CPU 多线程数值计算整体搬进 compute 的负载清单与搬迁分界）。
>
> **一句话说明**：本篇把"纯 GPU 替代 CPU 多线程计算"的负载钉成一张清单（粒子/流体/布料/海面 FFT/毛发物理/动画求值/破坏残骸/群集行为），并给搬迁分界线——判定不是"算在哪"，而是"原来 CPU 上是什么"加"游戏逻辑当帧要不要读结果"；本篇是《GPU-Driven 本质》的模拟类应用面清单，与本仓库已做的决策类（剔除/LOD/流送）互补，不做任何新施工主张。

## 0. 判定线

- **决策类与模拟类的区别不是"算在哪"，是原来 CPU 上是什么。** 决策类（本仓库 5.2/6.1/6.2/6.3）替代的是 CPU 的**逐对象决策循环**——本来就不并行、O(总对象数)每帧；模拟类（本篇清单）替代的是 **CPU 多线程数值计算**——job system / 线程池时代真实在算的积分、约束求解、FFT。前者的 GPU 收益来自成本形状改变（跟可见工作量走），后者的收益来自并行吞吐碾压。
- **搬迁判定线 = 游戏逻辑这一帧要不要读结果**（回读墙的具体化）：不用读 → 整个模拟闭环留 GPU，CPU 只发参数（风速、发射率、全局时钟）；要读 → 三种下场：留 CPU（刚体物理）、CPU 留逻辑副本（GPU 算视觉版、CPU 算近似版，两套轻不同步）、容忍异步回读延迟（几乎没人用于逐帧 gameplay）。
- **模拟类的输出端与本仓库 5.x 架构同构**：模拟 compute 写完实例数组，后面接的还是"可见性剔除 → build_indirect → 一次 indirect draw"——GPU 活账本就是一张 GPU 自维护的在场环，本仓库的地基（常驻表、indirect 闭环、标记环家族）全部现成。
- **能搬的共同物理性质**：逐单元独立（粒子）或规则邻域耦合（网格 stencil、约束迭代），且无当帧回读需求；搬走后连 CPU 侧的管理成本（粒子池分配/压缩/清理、island 划分）一并消失。

## 1. 清单：八类典型负载

| 应用 | 原来 CPU 上是什么 | 为什么适合搬 |
|---|---|---|
| **GPU 粒子**（Unity VFX Graph、UE Niagara GPU sim） | 粒子池逐帧 update：位置积分、寿命、发射、碰撞——DOTS/job system 时代的经典多线程负载 | 逐粒子独立更新零耦合；粒子数上来后 CPU 的管理负担（分配、压缩、清理）本身也是成本 |
| **流体/烟雾**（欧拉网格法或 SPH） | 早期游戏在 CPU 上算小规模流体（job 并行切片） | 邻域耦合但规则（网格 stencil），compute 的共享内存/组同步正好吃这一口 |
| **布料**（Verlet/PBD 约束求解） | 约束迭代按 island 拆分多线程（PhysX cloth 旧路线） | 约束迭代是"重复 N 遍同一批 kernels"，GPU 一次迭代一个 dispatch，吞吐碾压 |
| **海面 FFT**（频谱法） | 逆 FFT 每帧算波高场，CPU 上是真·多线程 FFT 库 | 大规模规则变换是 GPU 原生强项，结果直接喂顶点纹理，全程不落 CPU |
| **毛发/草的物理摆动**（strand 物理、风场） | CPU 按 strand/簇并行解算 | 单根独立 + 风场这类全局量只读，零回读需求 |
| **动画求值/蒙皮**（GPU 动画库、群集矩阵贴图） | 旧路线：job system 并行采样曲线 + 算骨骼矩阵，再传矩阵给渲染 | 全部变成顶点着色器里按时间采样矩阵贴图——CPU 连每实例成本都没了，只剩发一次全局时钟 |
| **碎片/破坏残骸** | 大量小刚体在 CPU 物理引擎里 simulation island 并行 | 改成 GPU 上"位置+速度数组 + 简单碰撞"的粒子式解算，真刚体语义不要了（战地系列路线） |
| **群集行为**（boid 类 steering） | CPU 上邻居查询 + 力合成，空间分格多线程 | 密度网格在 GPU 建一遍（排序/分桶原语，与 compute 剔除链同族原语），逐 boid 独立求解 |

## 2. 分界线：为什么不是所有"计算"都搬

判定就是回读墙具体化成一个问题——**"游戏逻辑这一帧要不要读结果？"**

刚体物理至今主流仍在 CPU 多线程（Havok/Jolt/PhysX），不是算不动，是**游戏逻辑是它的唯一消费者**：角色命中判定、拾取、AI 感知天天读位置，一读就得同步回 CPU，模拟闭环就断了。同理寻路、AI 决策都没搬。

Unity 的对照是这条分界线的实体化：**VFX Graph**（GPU sim，纯视觉，不进 gameplay）与 **DOTS 粒子**（CPU sim，逻辑可读）两条产品线并存——同一个需求按"逻辑要不要读"分成了两个产品。

## 3. 与本仓库的接口

- 模拟 compute 的输出端就是本仓库现成的消费链：模拟写实例数组 → 视锥/遮挡/LOD compute（5.2/6.1/6.2）→ build_indirect（5.3）→ 一次 indirect draw。要练模拟族，缺的只是模拟 kernel 本身和"CPU 不持有清单"的心态转变。
- 现路线图（步骤 7/8/9）不含模拟族；要立项挂[外置拓展需求](../外置拓展需求.md)新条目。**粒子起步成本最低**——一个积分 kernel 加现成的间接绘制链就能跑通闭环。
- 边界提醒：模拟类接管后，CPU 侧的调试手段变了——数据在 GPU 里，读数只能走异步回读或诊断通道（与本仓库 cull_stats 只进验证不进绘制的红线同款纪律）。
