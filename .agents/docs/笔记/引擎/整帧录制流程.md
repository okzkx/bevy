# 整帧录制流程：record_frame_steps 九段

`FramePool::record_frame_steps`（ash_renderer/src/render/frame/frame_draw.rs）是每帧唯一的命令缓冲录制点：一个 ONE_TIME_SUBMIT 的 command buffer，按固定顺序录完九段，末尾 `queue_submit` 一次提交。帧的全部输入由 draw_frame 组装进 `FrameDraw`，录制体只读不找——层界见《src 顶层目录依赖分层》。段间没有隐式状态，衔接只靠 image layout 屏障；GPU 计时打点 `mark(0~7)` 挂在段界，帧样本按打点分桶，所以段界也是性能归因的边界。

## §0 分段判定线

- **段的边界 = image layout 迁移点 + 计时打点**。一段的开头通常是"上一段的产物转成下一段要的布局"（附件→只读、只读→附件），打点紧跟其后。
- **屏障只有三个产地**：各 pass 自己的 record 函数内（compute 各 dispatch 之间、Hi-Z 归约、indirect 写读）；段界自录（进场/出场接缝）；acquire 与上传票据的等待在提交参数里，不占命令缓冲。
- **①⑨ 是槽基建段**：cb begin/end、fence 重置、等待列表组装、queue_submit——消费槽私有物（cb/fence/image_available），不属于任何业务模块，封装时留在 `record_frame` 本体。
- **②~⑧ 一段对应一个业务模块**，每段的输入是 `FrameDraw` 的一个字段组。
- **Option = 整段跳过，恒录 = 例外**：`Option` 字段为 None 时整段不录；但 shadow 级联布局屏障与 tonemap 的 LDR 进场屏障恒录（下游描述符恒绑定，布局必须恒定），pass 本体可跳。
- **transparent 是跨段字段**：compute 段（collect/sort/gather）、合成段（前向绘制）、Hi-Z 段（深度状态判断）三处消费，封装时作为整体组传入，不拆。

## §2 各段要点与坑

### ① 进场

- 三个屏障对象三类身份：swapchain image 跨帧，srcStage 等 image_available（提交在 COLOR_ATTACHMENT_OUTPUT 等 acquire）；本槽深度/G-buffer 同槽上轮已 fence 等完，srcAccess 空；贴图**不录**进场屏障——CONCURRENT 双族共享无所有权转移，上传后的跨队列可见性由提交时的票据等待兜底。
- 透明排序键预填 -inf 必须在所有 compute dispatch 之前：bitonic 全容量升序排序把真实条目推到尾部（gather 反向取），空位键必须是最小值。

### ② compute 前置

- 顺序即依赖，屏障全在各 record 函数内，录制体只管顺序调用。
- 六个 dispatch 全 Option：开关关闭或空场为 None，整段跳过（LOD 关闭时 host 已把档位环填最细档，运行语义仍完整）。

### ③ shadow depth

- 布局屏障每帧恒录：合成 pass 的 shadow 描述符总是绑定，四张图布局必须始终是 SHADER_READ_ONLY——pass 关闭也得走 UNDEFINED→附件→只读一个来回。
- UNDEFINED 作 oldLayout 从任何状态都合法（每帧 CLEAR 重写全图）。

### ④ G-buffer

- 一条 `cmd_draw_indexed_indirect` 消费整个命令环，draw 调用数不随对象数增长；实例槽号经 firstInstance 进 VS（按 instance_index 读 set2）。
- 顶点/索引池缺席 = 上传链与绘制链状态矛盾，按 Contract 致命退出而非静默跳过整个场景。

### ⑤ 合成 + 透明前向

- 深度一趟三态：只读（合成采样）→ 附件（透明测深不写）→ 只读（Hi-Z 归约读）。没有透明层时中间态不发生。
- 两次动态渲染之间没有光栅序保证：合成写 HDR → 透明混读必须显式 memory barrier。
- 深度转回附件的屏障 srcAccess 含 WRITE：布局迁移本身是写，必须排在 G-buffer pass 的深度 store 之后（syncval WRITE_AFTER_WRITE）。

### ⑥⑦ Hi-Z 与 Bloom

- 归约链恒录：warmup 阶段的走账与录制一一对应（录制后 note_reduced）。
- Bloom 目标不分帧槽：跨帧共享，进场屏障等上一帧片元采样读完（WAR）。

### ⑧ 后链 + UI

- tonemap 恒录，且必须录 LDR 的 UNDEFINED 进场：LDR 上一轮停在 SHADER_READ_ONLY，漏录触发 VUID-09592 布局不符。
- UI 段切 overlay 管线：自有 layout（只有 set0），切过去后 set0 要按它的 layout 重绑；场景分支不一定跑过 viewport，UI 自己设。
- push 常量整帧不变，循环外打包一次；每个 clip 设一次 scissor。

### ⑨ 出场 + 提交

- `reset_fences` 在提交前一刻才做，这里到 queue_submit 之间不得有提前 return：reset 失败时 fence 仍 signaled，下帧照常通过；submit 失败则没人 signal 它，帧循环报错退出，不会回来死等。
- 等待列表两态：wait_ticket = 0（从未上传）只等 image_available——不能等 timeline 的 0 值（VUID-03242）；否则追加上传票据（ALL_COMMANDS），这个内存依赖同时兜 transfer 写池/贴图的跨队列可见性（CONCURRENT 共享没有所有权屏障，全靠这里）。
- 提交在 GPU 侧等，CPU 不阻塞；完成时 signal render_finished 与槽 fence。

## §3 模块封装对齐

按模块封装时的对应关系：**共享句柄留顶层**——set0/1/2、顶点索引池、gbuffer、cluster_set、shadow_set、indirect_count/buffer 跨多段消费，收进任何单段组都是假归属；**单消费段收组**——compute 段六 dispatch 一组、shadow 段一组、post 链（⑦⑧ 的 composite/tonemap/bloom/smaa）一组、overlay+ui 一组；①⑨ 的槽私有物（cb/fence/信号量）不进 FrameDraw，录制体经 FramePool 自取。
