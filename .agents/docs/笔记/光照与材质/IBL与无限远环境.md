# IBL：无限远环境光照的表示与边界

要在渲染器里加"从四面八方来的光"，有三件事容易混在一起：IBL（image-based lighting，用环境图当光源的间接光）到底指什么、它能表示什么、它到哪儿为止。**核心判断是：IBL 的判据在光源——光来自一张环境图；而"无限远环境"是一种没有遮挡、没有位置、没有多跳的光源模型，IBL 是它最通用的表示，两者都不等于全局光照（GI）的终点。** 读完这篇，应该能判断一个做法算不算 IBL、它能不能表达你手上的环境，以及它和世界空间缓存、光线追踪的分工在哪里。

## IBL 的判据在光源，不在数据形状

IBL 不是某一种数据结构，而是一类做法：先把环境记录成图，再用这张图去算每个表面的入射光。图可以存成 cube map（六面立方体贴图）、equirect（经纬展开图）、八面体图或半球图；也可以先压缩成系数再存。压缩之后的形状不影响它是不是 IBL。

| 表示 | 能表达什么 | 光源是图像吗 |
|---|---|---|
| 常量 ambient（一个颜色） | 每个方向相同的光 | 是均匀环境图的退化 |
| 半球/双色 ambient（上色、下色） | 上下方向粗略不同 | 不是，解析近似 |
| 解析天空模型（如物理天空） | 模型自身能生成的环境 | 不是，公式求值 |
| SH 系数（球谐，用少量系数近似方向分布；L1/L2/L4） | 低频方向分布 | 通常是环境图的投影 |
| SG、HL2、wavelet 等其他球面函数基 | 比 SH 更局部的方向分布 | 通常是环境图的压缩 |
| cube / equirect / 八面体 / 半球图 | 任意环境（太阳、窗户、HDR 资产） | 是 |

所以"每像素直接采 cube map""预滤波 cube 加 DFG LUT""投影成 SH-L2""投影成 16 桶八面体"，都是 IBL 的不同编码，区别只在精度、成本与使用方式。项目里 9.2 计划的环境 cubemap 与 9.3 计划的 GlobalProbe 16 桶，是同一份天空的两种编码，不是两代方案。

常量 ambient 也属于这一类，只是退化到 0 阶。均匀环境辐亮度为 `L` 时，任意法线的辐照度都是 `E(n) = πL`；Lambert 表面出射辐亮度 = `diffuseColor/π · E = diffuseColor · L`，`π` 正好抵消。所以步骤 8 的 `albedo × ambient_color`（`shaders/scene/gbuffer/gbuffer_composite.wgsl:298`、`shaders/scene/transparent/transparent_forward.wgsl:64`）等价于"每个方向都是 `ambient_color` 的常量环境图"，只是它没有高光那一半，而且乘的是 `albedo` 而不是 `diffuseColor`。

## 任意环境只有图像能承载，系数基是有损压缩

上表里真正的分界是"能不能承载任意环境"：

- **图像参数化**（cube、equirect、八面体）能原样记录任意分布，包括太阳这种小立体角高亮和窗户这种高对比结构。它是唯一无损（到存储精度为止）的通用表示。
- **SH/SG 等系数基**是对图像的低频压缩。L2 只有 9 个系数/通道，保留大尺度方向分布，太阳与窗户会被抹成一片；阶数越高越贵，但仍不适合表达高频。
- **解析天空模型**只能表达模型自己能生成的环境：换一套天空、加一栋挡光的建筑，它就不适用。
- **半球图**只记录半个球面；做漫反射的半球积分时，另外半球的贡献要么假设成地面色，要么置零。用完整 cubemap 或 equirect 就没有这个假设。

本项目的顺序正好说明这条分界：9.1 的物理天空是**解析模型**，可以每像素求值，但漫反射要做整个半球的积分，逐像素代价高；9.2 把它**捕获成 cubemap**，图从此成为唯一来源，之后 SH-L2、16 桶、预滤波 mip 都从这张图投影出来。捕获不是"换了一种天空"，而是把解析函数变成可被着色器廉价查询、可被压缩的通用表示。

## 无限远环境没有遮挡、没有位置，所以它不是 GI

把光当成"从无限远处来的环境图"，等于同时接受了三个假设：

| 缺什么 | 现象 | 谁来补 |
|---|---|---|
| 遮挡 | 室内天花板被天光照亮，墙角没有变暗（漏光） | 光线追踪、阴影、带可见性的缓存 |
| 位置 | 走廊两端、室内室外拿到同一份环境光 | 探针网格、世界空间缓存 |
| 多跳 | 红墙不会把红色反弹到旁边的白墙上 | 缓存自查询、路径追踪 |

这三样都不是编码问题：换成 SH-L3、换成 4096² 的 cubemap，漏光依旧、位置不变、也没有色渗。所以 IBL 是环境基线，不是 GI 的完成形态。项目把两者分成两层：9.2～9.3 的 IBL 覆盖所有受光材质，9.7 的 SCGI 只在不透明像素、Volume（GI 的作用范围盒）内用世界空间缓存替换漫反射项。完整的分层与注入公式见[SCGI 的间接光注入端](SCGI间接光注入端.md)，四族方案的取舍见[全局光照谱系](全局光照谱系调研.md)。

## L2 与 16 桶是同一层的两种编码

经常被读成"9.3 用 GlobalProbe 取代了 9.2 的 IBL"，实际关系是：

- 两者都**直接从同一张源 cubemap 投影**，互不依赖，不是"L2 再生成 16 桶"的流水线。
- 天空重烘时两份都算、都存：SH-L2 存成 9 行 `vec4`（144B），GlobalProbe 16 桶存成 1KB；成本相对捕获可忽略。
- 着色时由 `ibl_mode` 二选一：`0` 用 SH-L2 求值，`1` 用 16 桶选桶后求 `l0 + l1·n`。切换不需要重烘。
- `ibl_mode=1` 只是**绕过 L2 的求值**，不删除数据；L2 除了漫反射求值没有别的用途，所以在这一项上它确实被完全接管。
- **高光不受影响**：预滤波 cubemap（按粗糙度预先模糊成 mip 链，即同一贴图逐级减半的缩小版本）与 DFG LUT（把 BRDF 的入射/菲涅耳积分预积分成一张二维表）永远走 IBL，与 `ibl_mode` 无关。

选 L2 还是 16 桶的差别在平滑度与对接成本：L2 连续、无接缝；16 桶是分段 LUT，桶边界硬切换，但输出格式与 patch（贴在表面上的缓存条目）的 RGBL1（每桶存 l0 与 l1 的 RGB 系数）同构，9.7 体积外兜底可以只换查询函数、不换数据格式。详细对照见[SH 与光照探针](SH与光照探针.md)的"16 桶 vs 单个 L2/L3"。

## 光追是求解手段，不是和 IBL 并列的方案

讨论"除了 IBL 还有什么"时，要先分开两个轴：

- **光的数据住在哪**：贴图上（烘焙）、空间点上（探针）、屏幕上（SSGI，屏幕空间全局光照，用当帧的几何与深度在屏幕内收集间接光）、世界空间结构里（缓存）。
- **光怎么被算出来**：解析公式、预积分、光线追踪、缓存更新。

光线追踪属于第二个轴，它可以算阴影、镜面反射、环境光遮蔽和漫反射间接光。它看起来"更适合镜面"，原因是采样成本：

- 镜面反射是**窄锥积分**，反射方向集中，一条射线就能给出方差很小的结果。
- 漫反射是**整个半球的余弦加权积分**，方差大，单像素要几十到几百条射线才收敛；再乘多次弹射，成本难以承受。

所以常见的工程形态不是"每像素打漫反射射线"，而是**用射线更新缓存或探针，着色时廉价查询**：射线预算花在缓存条目上，不随像素数增长。近年也有产品级的逐像素漫反射光追（低分辨率、时域累积、降噪、一两次弹射），但那是另一条成本量级。项目的 SCGI 正是"射线更新缓存"的形态：9.4 建光线索交基建（Vulkan 的 ray query，硬件光线求交），9.6 用射线更新 patch，9.7 在屏幕上按 1/4 分辨率查缓存、滤波、上采样。各方案买什么、放弃什么，见[全局光照谱系](全局光照谱系调研.md)的选型阶梯。

顺带一个常见混淆：SSAO（屏幕空间环境光遮蔽）只压暗、不传颜色，它是遮蔽近似，不是 GI；把它加在 IBL 上只改变暗部，不会产生色渗。

## 本项目的落点

| 阶段 | 环境光的来源 | 算 IBL 吗 | 状态 |
|---|---|---|---|
| 9.1 | 物理天空解析求值（背景可见） | 不是，解析模型 | 已落地，`shaders/common/sky.wgsl` |
| 9.2 | 天空捕获成 cubemap → SH-L2 漫反射 + 预滤波高光 + DFG LUT | 是，IBL 本体 | 计划 |
| 9.3 | 同一张 cubemap 投影成 16 桶 RGBL1 | 是，另一种编码 | 计划 |
| 9.7 | Volume 内不透明像素换成世界空间缓存 | 不是 IBL，是 GI | 计划 |

三个开关的分层回退是：`ibl_enabled=false` 回到步骤 8 的 `albedo × ambient_color`（均匀环境的退化）；`gi_enabled=false` 回到 IBL 基线；`sky_enabled` 只管背景是否画天空，与 IBL 正交。天空变化会触发重烘（脏标记 + 节流），可见天空每帧解析求值，IBL 最多滞后一个更新间隔。

一个具体的成本量级：源 cubemap 256²×6 RGBA16F 约 3 MiB，预滤波 mip 链约 4 MiB，DFG LUT 128² RG16F 约 64 KiB，SH-L2 144B，GlobalProbe 1KB。这些都记录在[9.2 施工计划](../../开发步骤/9-表面缓存全局光照/9.2-天空盒IBL/施工计划：天空盒IBL.md)的显存账里。
