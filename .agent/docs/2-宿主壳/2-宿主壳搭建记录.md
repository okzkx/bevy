## 0. 一句话总结

**禁渲染 Bevy 宿主 + ash 裸 Vulkan 渲染链验证成功，M1 达成。** 无 wgpu 初始化；Vulkan 全链（RTX 2060，API v1.3.289）+ 两帧在飞动态渲染清屏 + resize 幂等重建 + 两 Tier 错误处理（全程零 panic、失败优雅退出退出码 1）。完成标准全数通过：清屏窗口稳定运行、resize 不崩、退出干净、失败自关窗口。

## 1. 终态架构

### 模块分层（生命周期四层）

| 模块 | 生命周期 | 内容 |
|---|---|---|
| `vulkan.rs` `Context` | 进程级 | Entry（libloading 防卸载）→ Instance（1.3+验证层按可用性+debug messenger）→ Win32 Surface → PhysicalDevice（graphics+present 同族、离散卡优先）→ Device（+dynamicRendering）→ Queue |
| `swapchain.rs` `Swapchain` | resize 级 | swapchain + images + **views** + format/extent；`rebuild()` 幂等（尺寸没变不重建、最小化 extent=0 跳过）；acquire/present 封装 |
| `frames.rs` `FramePool` | 帧级 | 命令池 + `MAX_FRAMES_IN_FLIGHT=2` 组（命令缓冲 + image_available/render_finished 双信号量 + in_flight fence），跨重建轮转复用 |
| `error.rs` `VulkanError` | — | thiserror：`SwapchainOutOfDate`（控制流）/`Vk(vk::Result)`/`Init(String)` |
| `syntax.rs` | — | 错误处理糖（frenderer 移植 + 自创，9 宏 + 3 trait），见语法糖篇 |
| `host.rs`（步骤 3 开工整理新增） | 编排层 | 宿主桥插件 `AshHostPlugin`：下表三系统 + 禁渲染补位（`CompressedImageFormatSupport` 自报）；不持有 Vulkan 状态，只编排三个生命周期模块 |

### 宿主壳编排（Bevy 侧接线；2026-09-22 步骤 3 开工整理：三系统自 main.rs 迁入 `host.rs`，main 只做插件组装）

| 时机 | 系统 | 职责 |
|---|---|---|
| `Startup` | `init_vulkan` | `try_init_vulkan` 用 `?` 串链创建三资源（**全有或全无**）；失败 → `error!` + `AppExit::error()` 优雅退出 |
| `Last` | `draw_frame.run_if(resource_exists::<Context>)`（2026-09-22 自 Update 归位，`.before(OnAppExitSystems)` 钉退出帧次序） | 帧循环（采集之后的最后槽）：resize 闸门（最小化整帧让路；尺寸变化帧首按需重建）→ 等 fence → acquire → 录制清屏并提交 → present；OUT_OF_DATE = 立即重建（控制流）；挪位理由见 3.1.4 记录 §6，闸门机制见《[窗口闸门：最小化死锁与resize卡顿的实测与修复](材料/窗口闸门：最小化死锁与resize卡顿的实测与修复.md)》 |
| `Last` | `teardown_vulkan.in_set(OnAppExitSystems)` | AppExit 写入后、despawn_windows 杀 hwnd 前反序拆除（官方先例 = bevy_time 的 `silence_delayed_command_queues_on_exit` 同款钩子） |
| `main` | `-> AppExit` | `Termination` 传出退出码（Success=0 / Error=1） |

### 关键决策一览

| 决策 | 定案 | 要点 |
|---|---|---|
| crate 落位 | workspace member `ash_renderer`（lib 渲染器 + bin 宿主壳） | 增量编译复用 bevy 缓存、单一锁文件；代价 = 根 Cargo.toml +2 行；未继承 workspace lints（unsafe 大户独立对待） |
| surface 方案 | 手写 Win32（零新依赖、练 Vulkan、仅 Windows；ash-window 弃） | 句柄取 `RawHandleWrapper::get_window_handle()`（bevy 安全方法）；hinstance 缺失 `GetModuleHandleW` 兜底 |
| 清屏路径 | Vulkan 1.3 动态渲染（`vkCmdBeginRendering`，loadOp=CLEAR） | 无 RenderPass/Framebuffer/管线；`PhysicalDeviceVulkan13Features.dynamic_rendering(true)` 须 push_next 显式开；views 本就是 步骤 3 管线必经件 |
| 帧同步 | 当前实现为 2 帧在飞 | frame fence 只证明相关提交完成，不证明 present 用完 render_finished；该信号量按帧槽复用的设计待修，不能继续宣称全部同步对象都应与 image 解耦 |
| 命名 | `vulkan::Context` / `swapchain::Swapchain` / `frames::FramePool` | 名字=生命周期（模块名担语境；`swapchain_fns` 字段名保留） |
| 错误处理 | 两 Tier（非必要不 panic） | 专篇见《错误处理体系：两Tier思想与优雅退出》 |

## 2. 四项施工精要

### ① crate 落位（✅）

决策见上表。依赖：`bevy = { path = ".." }` 默认 feature + `ash = "0.38.0"`（frenderel 已归档，取最新不迁就 0.37）+ raw-window-handle 0.6（bevy 不再出口）+ thiserror 2。

### ② 禁渲染（✅）

- **disable 名单 = 渲染族 8 件**（RenderPlugin / PipelinedRendering / CorePipeline / PostProcess / AntiAlias / SpriteRender / UiRender / GizmoRender，0.20-dev 路径未变，`default_plugins.rs:44/57/59/61/63/67/75/89`）+ **连带禁项 PbrPlugin**；
- PbrPlugin 必炸根因链：`load_shader_library!` 无条件分配 `Handle<Shader>` → `Assets<Shader>` 注册在 `RenderPlugin::build`（bevy_render/src/lib.rs:385）→ 禁渲染后 init_asset 找不到注册 → 炸。0.19.1 分类表"PbrPlugin 优雅降级可保留"结论被推翻（分类表 §0.3 已勘误）；**材质缝（`Assets<StandardMaterial>` / GltfExtensionHandlerPbr）随禁失效，步骤 3 手动接线**；
- 手动 `insert_resource(CompressedImageFormatSupport(NONE))`（0.20 文档化用户责任，bevy_image/src/image.rs:2467；步骤 3 按 ash 实际 VkFormat 改写）；
- 实测：启动无 WARN、无 wgpu、帧心跳持续。

### ③ 窗口句柄链（✅）

- 时序假设实测成立：首窗建于 runner `resumed` 回调（非 PreStartup）→ Startup 时 `RawHandleWrapper` 必在；`NonSendMarker` 钉主线程；
- **ash 0.38 关键事实**：loader 在 `ash::khr::*`/`ash::ext::*`、NAME 常量在模块级、**全套无 `impl Drop`**（销毁全部手动反序）、Entry 必须持在结构体（防 vulkan-1.dll 卸载）、Win32 字段是 `.hwnd()`；
- 深挖：《[VulkanContext字段释义：从Entry到Swapchain.md](材料/VulkanContext字段释义：从Entry到Swapchain.md)》（逐字段三问 + Unity-D3D 映射）、《[Context与Swapchain分家：按生命周期拆分.md](材料/Context与Swapchain分家：按生命周期拆分.md)》（拆分账 + 求值顺序教训）、《[窗口链路侦察：WinitPlugin、RawHandleWrapper与事件进ECS.md](材料/窗口链路侦察：WinitPlugin、RawHandleWrapper与事件进ECS.md)》（开篇侦察）。

### ④ 帧循环（✅）

- **清屏录制**（`record_clear_and_submit`）：进场屏障（UNDEFINED→COLOR_ATTACHMENT_OPTIMAL）→ `cmd_begin_rendering`（loadOp=CLEAR 上色，无管线）→ 出场屏障（→PRESENT_SRC_KHR）→ `queue_submit`（等 image_available、发 render_finished + fence）→ `queue_present`（等 render_finished）；
- **resize 桥（2026-09-22 定稿 = frenderer 三件套）**：present mode MAILBOX 优先（FIFO 兜底；MAILBOX 不构成 acquire 永不阻塞的规范保证）+ `ResizeGate`（最小化整帧让路保消息泵；尺寸变化只标 pending、帧首按需重建，acquire 永远落在新 swapchain 上）+ `WinitSettings::Reactive(1/60)` 官方节流（MAILBOX 无 vsync 背压，防 update 裸奔烧 CPU）；acquire 的 SUBOPTIMAL 画完标 pending、OUT_OF_DATE 立即重建；用户定案"宁要渲染卡顿不要冻结"，背景与两轮返工见《[窗口闸门：最小化死锁与resize卡顿的实测与修复.md](材料/窗口闸门：最小化死锁与resize卡顿的实测与修复.md)》；
- **退出时序（0.20 实情）**：`exiting` 回调**先杀 hwnd 后清场**（`world.clear_all()` 对 Resource 任意序）→ 不能等清场；最终帧 Last 内链 = ExitSystems（写 AppExit，bevy_window）→ OnAppExitSystems（bevy_app set）→ despawn_windows（bevy_winit 杀窗），拆除挂 OnAppExitSystems 抢在杀窗前；
- 详见《[错误处理体系：两Tier思想与优雅退出.md](../笔记/错误处理体系：两Tier思想与优雅退出.md)》。

## 3. 坑与解法（合并）

| 坑 | 解法 |
|---|---|
| PbrPlugin 禁渲染后必炸 | 连带禁；材质缝 步骤 3 手动接线 |
| `ERROR_NATIVE_WINDOW_IN_USE_KHR`（首个真 Vulkan bug，实测抓获） | `*self = Self::new(ctx)?` 的 RHS 先求值 = **先建新 swapchain 后拆旧**，而 Win32 同 hwnd 同时只能挂一个 swapchain → 显式 `self.destroy()`（幂等，句柄清 null）**先拆后建**；取 images 失败也要就地销毁（防坏 swapchain 占死 hwnd） |
| `macro_rules!` 跨 crate 再导出报 E0364 | 全部挂 `#[macro_export]` + 模块内 `pub use` 双路径 |
| `pub trait` 再 `pub use` 报 E0255 | trait 与宏导出规则不同：pub trait 模块内已公开，勿重复导出 |
| `resource_exists::<Context>()` 报 bool:SystemCondition | 0.20 条件是带参函数，传函数名**不加括号** |
| `From<AppExit> for ExitCode` 不存在 | bevy 已实现 `Termination`（bevy_app/src/app.rs:1597），`fn main() -> AppExit` 是正路 |
| `Query::single()` 0.20 返回 Result 非 Option | `map_err` 折叠成 VulkanError 冒泡 |
| `Time::elapsed_seconds_f64` 编译错 | 0.20 改名 `elapsed_secs_f64` |
| `vk::CommandBufferRenderingInfo` 不存在 | `vkCmdBeginRendering` 的 info 真名 `vk::RenderingInfo` |
| 验证层缺失 | 本机无 VK_LAYER_KHRONOS_validation（裸奔 + ERROR 日志声明；装 Vulkan SDK 即补，messenger 代码已就位） |

## 4. 错误处理体系

两 Tier 思想（非必要不 panic：①不影响运行 → warn 丢弃继续；②影响运行 → error 冒泡到 main 优雅退出）与优雅退出全链（`try_init ? 串链 → AppExit::error() → resource_exists 守卫 → 反序拆除 → 退出码 1`）已独立成篇：**《[错误处理体系：两Tier思想与优雅退出.md](../笔记/错误处理体系：两Tier思想与优雅退出.md)》**。工具层（9 宏糖家族）见《[错误处理语法糖：frenderer syntax与ash_renderer移植.md](../笔记/错误处理语法糖：frenderer syntax与ash_renderer移植.md)》。

## 6. 给 步骤 3 的接口

1. **管线/描述符在 Vulkan 录制模块生长，编排住 `host.rs`，main 只组装。**`draw_frame` 已于 2026-09-22 挪到 Last，保持 PostUpdate 采集后同帧提交。**撤回“同步骨架与函数结构不动”的绝对承诺**：2026-09-23 发现的 fence、present 复用和退出等待问题必须先修；模块职责与函数名可以保留，错误的生命周期边界不能作为接口继承；
2. **`Assets<Mesh>` 永久可直读**（禁渲染后无人释放主世界顶点数据——M2 取数落点，见 glTF 链路篇）；

5. 验证层与同步验证前移到 3.2 上传之前，先确认实际启用，再验现有同步缺陷；未安装/未启用不能记作零告警；
