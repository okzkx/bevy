## 步骤 1：简单熟悉 Bevy 的结构

**目的**：建立"Bevy 由哪些 crate 组成、哪些归我用的宿主、哪些是要绕开的渲染栈"的心智地图。**熟悉到"能组装"即可**，不求深——深度理解在后面步骤里按需补。

**做什么**（纯读 + 跑，不写代码；每项半天以内）：

1. 跑三个最小示例建立手感：
   ```bash
   cargo run --example hello_world       # 最小 App
   cargo run --example empty_defaults    # DefaultPlugins 全量骨架
   cargo run --example 3d_scene          # 最小 3D：mesh+材质+灯光+相机
   ```
2. 读 App 生命周期：`crates/bevy_app/src/app.rs`——`App`/`Plugin`/`SubApp` 是什么；`run()` 之后每帧经过哪些阶段（Startup → PreUpdate → Update → PostUpdate → Last）。
3. 数一遍 DefaultPlugins：`crates/bevy_internal/src/default_plugins.rs`——把插件按"宿主族（留）/ 渲染族（禁）/ 无关"分三类列清单。这份清单就是步骤 2 `disable::<>()` 名单的依据。
4. ECS 心智模型：精读 `examples/ecs/ecs_guide.rs`，重点 Query、Res/ResMut、Commands、变更检测、调度排序。
5. crate 分工速览：对着入口篇第三节的用法边界表，把 `crates/` 下每个 crate 标注"用 / 不用 / 只读抄"。
6. 窗口链路定点侦察：`crates/bevy_winit/src/winit_windows.rs`——窗口从哪来、事件怎么进 ECS；步骤 2 要在这里拿 raw handle 建 VkSurface。

**产出**：新建 `1-熟悉Bevy结构/Bevy结构笔记.md`（材料统一放 `1-熟悉Bevy结构/` 文件夹），至少回答四个问题：

1. 从 `App::new().run()` 到第一帧渲染，经过哪些阶段？
2. `RenderPlugin` 禁掉后，DefaultPlugins 还剩什么在跑？
3. 一个 system 的执行时机由什么决定？变换传播在帧内哪个位置？
4. glTF 文件从磁盘到 `Mesh3d` 实体，链路经过哪几站？

**完成标准**：合上资料能白板画出"帧循环时序图 + DefaultPlugins 分类图"；`3d_scene.rs` 每行都能解释给别人听。

## 步骤 2：宿主壳——禁渲染 Bevy + ash 清屏循环（M1）

**目的**：验证本项目根基——`DefaultPlugins.build().disable::<RenderPlugin>()` 与 winit 窗口、自建 Vulkan 能否共存。

**做什么**：

1. **定渲染器 crate 落位**（建议：在 `F:\okzkx\bevy` 内加 workspace member，与 `examples/large_scenes/bevy_city` 同模式，路径依赖各 bevy crate 零成本；不想动上游 Cargo.toml 就独立仓库 + path 依赖，二选一）；
2. 建 crate：组装 App，禁 RenderPlugin（必要时连带禁报错的渲染族插件），保留 winit；
3. 窗口句柄链：`PrimaryWindow` 实体上的 `RawHandleWrapper` 组件 → ash Instance / Device / Surface / Swapchain（侦察结论见 2-宿主壳/材料/《窗口链路侦察》——0.19.1 `WinitWindows` 已是 thread_local 非 NonSend，首选路径不经过它；窗口创建是事件驱动，首窗在 runner `resumed` 回调里建好）；
4. 帧循环：acquire → 清屏 → present，处理 resize 与关窗。

**产出**：可运行的宿主壳工程 + `2-宿主壳搭建记录.md`（坑与解法）。

**完成标准**：清屏窗口稳定运行、resize 不崩、退出干净；全程无 wgpu 初始化（可用 RenderDoc / 调试日志确认）。

## 步骤 3：静态取数链路（M2）

**目的**：打通入口篇"渲染前准备"第 1 层（常驻池）的静态版本。

**做什么**：spawn 一个 glTF 场景 → 渲染系统 Query 采集 `Mesh3d`/`GlobalTransform`/`MeshMaterial3d`/`Handle<Image>` → 上传 ash buffer/VkImage → descriptor indexing（bindless 起步形态）→ 画出来。
> 链路预备知识见 [步骤 1 材料/glTF加载链路：从磁盘到Mesh3d.md](1-熟悉Bevy结构/材料/glTF加载链路：从磁盘到Mesh3d.md)（§6 取数起点、RenderAssetUsages 结论：主世界顶点数据一直可读）；上传策略对照基准 = frenderer（staging 逐 buffer 单发提交 + main_mutex 串行，`F:\okzkx\rust-frenderer` modules/render/vulkan/src/buffer/）——本步要超越的就是"每 primitive 两次 wait_idle"，合批 + 拷贝队列起步。

**验证**：与 bevy 自带 wgpu 渲染同屏对照，几何、贴图、光照方向一致（临时开一个 wgpu 渲染的窗口做对照）。

## 步骤 4：增量链路（M3）

**目的**：实现第 2 层（变更检测 = 脏标记）。

**做什么**：`Changed<GlobalTransform>` / `Added` / `RemovedComponents` → 脏列表 → 只上传变更；资产热重载（改 glTF 文件）联动；补 descriptor 池的分配/回收。

**验证**：移动物体、增删实体、热重载，全部帧内生效且不整帧重传。

## 步骤 5：大世界组织层（M4）

**做什么**：照抄 bevy_city 的世界组织层——消息驱动加载流（Loaded→合并→Ready→spawn→Spawned）、observer 补组件、`StaticTransformOptimizations::Enabled`、`merge_car_meshes` 网格合并；GPU 剔除抄内核架构（`bevy_pbr/src/render/mesh_preprocess.wgsl` → `build_indirect_params.wgsl` → `gpu_preprocess.rs`，抄架构不抄代码）。

**验证**：`cargo run -p bevy_city --release -- --no_cpu_culling --size 50` 同量级实体（数万）流畅。

## 步骤 6：GPU-driven 全链（M5）

**目的**：实现第 3 层 + 收尾。

**做什么**：GPU frustum/遮挡剔除 → 生成 indirect 参数 → bindless 绘制；LOD（参考 `examples/3d/visibility_range.rs` 思路）；descriptor buffer 替换 descriptor indexing 收尾；资产驻留/流送管理器（mip/LOD 换出）进阶。外部阅读清单见上游《Bindless 与 GPU 驱动渲染参考》。

**验证**：CPU 每对象成本趋近零；与 frenderer（bound 管线）同场景 A/B。

## 编号约定（2026-09-22 定案，可无限扩层）

步骤体系用**层级累积编号**（父号打头，全局唯一，永不重数）。文件夹名与文档引用里的序号以此为准：

| 层级 | 编号 | 文件夹/落点 | 行文写法 |
|---|---|---|---|
| L1 步 | `N`（1~6） | `N-中文名/` | "步骤 N"（英文语境 Step N） |
| L2 段 | `N.M` | `N-…/N.M-中文名/` | "施工 N.M"或"N.M 段" |
| L3 任务 | `N.M.K` | 任务面板 checkbox | 直接写编号（如"见 3.3.2"） |
| L4+ | `N.M.K.j` | 任务内再拆 | 续数字，不设专名 |

配套规则：

- **文件夹名纯数字前缀**：不带 step/施工 字样，层级由数字本身表达（`1-宿主壳`、`3.1-ECS侧取数`）；"步骤/施工"字样只出现在行文，不进路径（2026-09-22 定案）；
- **里程碑 M1~M5 是验证刻度不是层级**——与步骤的映射固定在总览表，不参与编号；
- **文档自身章节号（§N）与步骤编号无关**——引用时注意别混（"计划 §3"是文档章节，"3.1"是施工段）；
- **编号只增不复用**：段间插新段拿下一个可用号，已收官段落不重排；
- **历史映射（不回溯改写收官文档正文）**：步骤 2 四项施工①~④ = **2.1~2.4**；步骤 1 的四问 Q1~Q4 与待深入清单是知识清单编号，不属施工序列，保留原文。
