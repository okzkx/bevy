# 实现规则：渲染器跨段施工的实现要求

> **规则篇（宪法层）**（2026-09-29 建档，承[3.4 施工记录](../3-静态取数链路/3.4-管线与绘制/3.4.1-3.4.5-管线与绘制施工记录：正式着色器、图形管线与DrawList同帧消费.md)定案提炼）。本篇是"必须"，不是"建议"：3.4 起对 3.5 与后续所有施工段生效。
> 用法：动笔前扫一遍；施工中发现规则过时/有误，**在本篇修订并写明缘由与日期**——不在施工记录里悄悄绕过（与主计划 §5"更改验收口径必须说明缘由"同款纪律）。判例与证据（排障过程、截图、对照实验）在 3.4 施工记录，本篇只留"要求 + 一句缘由 + 出处"。

## §1 接口与布局：三方互证

- **R1.1 接口三方同步**：着色器接口（set/binding/push/UBO 字段）任何改动，**同一次提交内**同步 WGSL、pipeline layout / push range、Rust 镜像三方；Rust 侧用 `offset_of!`/`size_of` **编译期断言**钉死。缘由：`repr(C)` 和"低于上限"都不证明对齐——编译事故便宜过画面事故。〔3.4 记录 §2〕
- **R1.2 字节手工排布**：push/uniform 的字节由 pack 函数按偏移常量写（`to_le_bytes` 纪律），不赌 repr 内建序与平台字节序巧合。〔3.4 记录 §2〕
- **R1.3 WGSL 语法**：函数以显式 `return` 收尾（块尾裸表达式 naga 拒收）；新增 wgsl 后确认 build.rs 产物生成（目录级 rerun-if-changed 已钉；`include_bytes!` 找不到产物即构建错误，早于一切运行期）。〔3.4 记录 §2 过程〕
- **R1.4 数值单源**：顶点 stride、表容量、帧数这类跨文件常量只在定义处写数值，其余一律引用（`VERTEX_STRIDE`/`TABLE_CAPACITY`/`MAX_FRAMES_IN_FLIGHT` 同款）。〔3.4 记录 §2/§3〕

## §2 数学与色彩

- **R2.1 法线矩阵 = cofactor**：列取 `[b×c, c×a, a×b]`（列 a,b,c 为模型矩阵上 3×3），normalize 兜底；不找 `inverse()`、不为 normal matrix 扩 push（冻结 96B 不给新字段开例外）。det=0（退化缩放）在资产假设外。〔3.4 记录 §2〕
- **R2.2 颜色空间恰一次**：sRGB 解码只在采样端（格式角色决定）、编码只在输出端 ROP（SRGB view）；着色器全程线性、**零 gamma 代码**；任何新增着色路径同守此链。〔3.4 记录 §2/§5.2〕
- **R2.3 线性域直进**：材质基色等任何进 push/UBO 的颜色，先 `to_linear` 再写字节。〔3.4 记录 §6〕

## §3 管线状态成套

- **R3.1 reverse-Z 三件套同源**：无限反向投影 + depth 清 0 + GREATER，成套声明成套核对；任何新管线不得混 LESS / 清 1。〔3.4 记录 §3〕
- **R3.2 viewport 正高度直出**（本机定案，E5 光栅级实验 + 官方对照实证）；遇颠倒/镜像类症状先查 3.4 记录 §3.3，**不做负高度翻转**。〔3.4 记录 §3.3〕
- **R3.3 渲染附件颜色格式取 `swapchain.view_format`**（SRGB 别名），不直接用底板格式；别名不可用的回退分支必须响亮 warn，不静默。〔3.4 记录 §5.2〕
- **R3.4 不透明调试路径 blend 关**；开混合属新材质策略，另立判定（镜片类以实测 alpha 为准，不按 glTF 预设）。〔3.4 记录 §6〕

## §4 深度与帧级资源

- **R4.1 深度附件按帧槽**（数量 = `MAX_FRAMES_IN_FLIGHT`），D32_SFORMAT 先查后用；每帧 `UNDEFINED` oldLayout（与 loadOp CLEAR 配套）、storeOp DON'T CARE、无出场屏障。〔3.4 记录 §4〕
- **R4.2 帧级资源随 swapchain 尺寸重建**：幂等（extent 不变空手而归）+ 销毁前 `device_wait_idle`（在飞引用不可能成立后才拆）。〔3.4 记录 §4〕
- **R4.3 同槽重用隔 fence**：帧级资源两次使用之间必须隔 `wait_for_slot` 的帧 fence；**同步证据要代码内可见**——不采信跨 present engine 的时序推理（"acquire 蕴含上一轮完成"属此类，可作旁证不作主证）。〔3.4 记录 §4〕

## §5 跨队列与同步

- **R5.1 跨族资源一律 CONCURRENT**：`{transfer, graphics}` 双族共享（池与图像同则，同族设备退回 EXCLUSIVE 空集）；**不在生产路径新增所有权让渡**（release/acquire 机制实证保留在 image_probe 组 C）；CONCURRENT 图像屏障的族号必须 `QUEUE_FAMILY_IGNORED`。〔3.4 记录 §6〕
- **R5.2 可见性由票据收口**：图形提交在 `ALL_COMMANDS` 等 `uploader` 票据 timeline（值 = 已发出最高票据，0 跳过）；该等待即 transfer 写对 graphics 的内存依赖——**禁止 CPU 逐批阻塞等上传**，等待发生在 GPU 执行依赖处。〔3.4 记录 §5〕
- **R5.3 错误可恢复性边界**：acquire 成功后任何失败走 Tier② 优雅退出（D2）；fence 重置到 submit 之间**零提前返回**；录制段新增代码不得引入新的提前返回点。〔3.4 记录 §5〕
- **R5.4 探针形状覆盖消费形态**：探针全绿只对它测过的形状负责——新增消费形态（如"acquire 后经描述符采样"）上线前先补同构探针组，**不让宿主首跑当探针**。〔3.4 记录 §6 反思 1〕
- **R5.5 验证层是裁判**：验证层报错修**结构**，不关/不弱化验证；解释不通的报错如实挂账，不静默、不绕过。〔3.4 记录 §6〕

## §6 DrawList 与帧编排

- **R6.1 组装三本账**：DrawList 行 = 池引脚（vertex_base/first_index/index_count）+ 材质基色（R2.3）+ 槽位（ImageCache）；缺贴图走 **fallback 槽 0** 照画，mesh/材质未驻留**整行暂缓**（Tier①，下帧重试，日志去重）——不阻塞帧循环。〔3.4 记录 §6〕
- **R6.2 帧级写的时机**：每帧 UBO 等宿主侧写一律发生在 `wait_for_slot` 之后；帧级资源的复用安全一律以帧 fence 担保。〔3.4 记录 §6〕
- **R6.3 屏障有归属**：帧录制新增屏障必须写明"谁罩谁、内存依赖在哪收口"，与 D6/D2 定案形状对照；不留"顺手加的屏障"。〔3.4 记录 §5〕
