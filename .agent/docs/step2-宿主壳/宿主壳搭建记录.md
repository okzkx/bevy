## §1 crate 落位决策（2026-09-21，✅ 完成）

**结论：workspace member，crate 名 `ash_renderer`，位于仓库根 `F:\okzkx\bevy\ash_renderer\`。**

### 决策依据（对照"独立仓库 + path 依赖"方案）

| 维度 | workspace member（选定） | 独立仓库 + path 依赖 |
|---|---|---|
| path 依赖 | `bevy = { path = ".." }`，同 bevy_city 模式，零成本 | 同样可行，但要维护两层 Cargo.toml |
| 锁文件/target | 共享根 Cargo.lock 与 target 目录，增量编译直接复用 bevy 缓存 | 独立 lock，首次全量编译 |
| profile | 自动继承根 [profile] 调优（members 可覆写 profile 属 workspace 根权限，子 crate 反而拿不到） | 无继承 |
| 上游合并成本 | 根 Cargo.toml members +2 行（1 行注释 + 1 行路径），跟随 release tag 升级时若冲突手工保住即可 | 零冲突 |
| 撤退成本 | 删目录 + 删 members 行，回到纯上游 | 天然隔离 |

workspace member 的"动上游文件"代价是一行级、可预期的，换取增量编译复用与单一锁文件——学习仓库场景下收益明显更大，选定。**crate 名可随时改**（改 `Cargo.toml` name + members 行 + 目录名三处）。

### 落位形态

- `ash_renderer/Cargo.toml`：lib（`src/lib.rs`，渲染器本体）+ bin（`src/main.rs`，宿主壳入口）双 target；edition 2024、publish=false，对齐 bevy_city；
- 依赖：`bevy = { path = ".." }` **默认 feature**——对齐 step1《DefaultPlugins分类.md》"默认 feature 下 34 条插件"的审计口径，禁名单直接照抄《DefaultPlugins分类.md》§1 的 8 件；若施工项②实测发现默认 feature 引来连带报错，再评估收窄（备选：feature 级不编 bevy_render，wgpu 根本不进编译产物，比 disable 更彻底）；
- 依赖：`ash = "0.38.0"`——**取环境可用的最新版**（2026-09-21 用户定：frenderer 已归档，新工程不做版本兼容对齐；本环境 crates.io 镜像可拉到的最新即 0.38.0+1.3.281）。ash-window 暂不引入（surface 方案是待决问题，见 step2 README）；
- **未继承 workspace lints**（不加 `[lints] workspace = true`，同 bevy_city）——workspace lints 里 `unsafe_code = "deny"`、`missing_docs = "warn"` 是给 bevy 源码用的，渲染器必然大量 unsafe，独立对待。

### 坑与解法

1. **ash 版本线认错**：初写 `ash = "0.8"`（与 bevy 同代 0.19 幻觉联想），实际 ash 版本号跟随 Vulkan SDK patch 计数（0.37.x、0.38.0），从无 0.8 线。报错信息会列出可用版本，按报错修正即可。
2. 本环境 crates.io 镜像最新 ash 为 0.38.0+1.3.281——若日后上游发新版拉不到，先怀疑镜像同步滞后。

### 验证

`cargo check -p ash_renderer` 通过（2026-09-21，含全量 bevy 默认 feature 树 + ash 0.38.0）。运行验证（窗口弹出）不在本项范围——main 仍是空壳，属施工项②。

## §2 建 crate：组装 App，禁渲染族插件（2026-09-21，✅ 完成）

**结论：disable 名单 = 渲染族 8 件 + 连带禁项 PbrPlugin，共 9 件；另需手动注册 `CompressedImageFormatSupport`。宿主壳在 0.20.0-dev 上实测：启动无 WARN、窗口创建、帧心跳持续、无 wgpu 初始化。**

### 0.20.0-dev 复核（step1 分类表按 0.19.1 审计，逐项复核结论）

- **渲染族 8 件路径与门控全部未变**（`default_plugins.rs:44/57/59/61/63/67/75/89`），默认 feature 下全部激活，照抄禁用即可；
- `PipelinedRenderingPlugin` 的早退守卫仍在（`pipelined_rendering.rs:143-147`，无 RenderApp 直接 return）——disable 属保险，非必需；
- 门面模块名复核：`bevy::{render, core_pipeline, post_process, anti_alias, sprite_render, ui_render, gizmos_render, pbr}`（`bevy_internal/src/lib.rs`），0.20 换 WESL shader 不影响插件名。

### 连带禁项实测：PbrPlugin 不可保留（0.19.1 审计"最后未验证点"验证结果）

运行即 panic（`bevy_asset/src/server/info.rs:865`）：`Cannot allocate an Asset Handle of type 'bevy_shader::shader::Shader' because the asset type has not been initialized`。

- **根源链**：`PbrPlugin::build` 无条件 `load_shader_library!`（`bevy_pbr/src/lib.rs:183-192`，0.20 起为 WESL）→ 分配 `Handle<Shader>` 要求 `Assets<Shader>` 已注册 → 而注册在 `RenderPlugin::build`（`bevy_render/src/lib.rs:385`）→ RenderPlugin 已禁 → 无人注册 → 炸；
- **为何不能预注册绕过**：`init_asset` 第一步就 `world().resource::<AssetServer>()`（`bevy_asset/src/lib.rs:658-662`），AssetServer 由组内 AssetPlugin 创建——自有插件插不进 DefaultPlugins 组内顺序，此路不通；
- **代价与 step3 备选**：PbrPlugin 同时是 `Assets<StandardMaterial>` 容器与 `GltfExtensionHandlerPbr`（glTF 材质接入缝）的注册者——禁掉后 step3 取材质需**手动接线**：`init_asset::<StandardMaterial>()` + 自行注册材质扩展 handler（或放弃 StandardMaterial 容器自研材质容器，待 step3 实测定）；
- **caller 清单佐证**：全仓 `load_shader_library!` 调用者 = core_pipeline/pbr/post_process/render/solari/sprite_render/ui_render 七 crate——其中只有 PbrPlugin 不在禁用名单，其余全被 8 件名单连带覆盖，无需再禁。

### 手动注册：CompressedImageFormatSupport（0.20 新增的用户责任）

0.20 实测 WARN：`CompressedImageFormatSupport resource not found. It should either be initialized in finish() of RenderPlugin, or manually if not using the RenderPlugin or the WGPU backend.`

- 该资源原本由 wgpu finish() 从 `device.features()` 生成（`bevy_render/src/settings.rs:193`），消费方 = GltfPlugin（`bevy_gltf/src/lib.rs:289`）与 ImagePlugin 的 ImageLoader（`bevy_render/src/texture/mod.rs:50`）；
- `bevy_image/src/image.rs:2467` 注释原文明说"不用 RenderPlugin/WGPU 的用户自行指定"——**0.20 文档化的用户责任**，非 hack；
- 宿主壳初值 `CompressedImageFormats::NONE`（诚实：渲染器尚未声明任何压缩格式支持）；**step3 接 ash 后按实际查询到的 VkFormat 支持改写**。
