## §0 一句话总结

**禁渲染 Bevy 宿主里，"取数链路"的 ECS 半边全链落地：FlightHelmet 六 primitive 带着材质柄与贴图柄进 World、相机与灯光引擎层手动就位、`CollectedScene` 拓扑快照每帧在 PostUpdate 产出——全程零 Vulkan 代码（GPU 侧仍是纯清屏循环），段判定线全过、步骤 2 行为零回退。** Vulkan 半边自施工 3.2 起步，输入已备好：快照里的 `mesh` 柄就是上传环节的第一批数据源。

## §1 终态数据链（ECS 侧一帧之内）

```text
Startup     load FlightHelmet.gltf#Scene0 + spawn WorldAssetRoot        ┐ 3.1.2 场景进场
            spawn 相机组（Camera+Projection+Transform）/ 灯光组          ┘ 3.1.3 引擎层自建
    │ 异步：GltfLoader 解析 → 逐 primitive spawn 实体（Mesh3d + 变换 + …）
    │        AshMaterialHook 三钩子（3.1.1）：on_material 转 StandardMaterial 入容器
    │                                    on_spawn_mesh_and_material 插 MeshMaterial3d
    ▼ 到货（~0.5s，含 15 张 png 解码）
Update      report_scene_arrival（报到货即歇）/ sync_projection_aspect（宽高比幂等修正）
    ▼
PostUpdate  TransformSystems::Propagate 传播定稿（GlobalTransform 本帧终值）
    → collect_scene 采集 → CollectedScene（entity + mesh/material 双柄 + model 终值矩阵）
    → report_scene_collected 核验（报一次即歇）                        ┐ 3.1.4 采集系统
    ▼                                                                 ┘
Last        draw_frame：清屏录制 + 提交（同帧 relay 消费端；3.4 起录制段长成"上传 + 清屏 + 绘制"）
```

## §2 四项任务精要

### 3.1.1 材质缝接线（补 PbrPlugin 连带禁用留下的缝）

缝断在两处：`Assets<StandardMaterial>` 容器无人注册，官方 handler `GltfExtensionHandlerPbr` 又是 `pub(crate)` 拿不到——后果不是报错，是**静默缺料**（spawn 出的实体只有 `Mesh3d` 没有 `MeshMaterial3d`，材质数据链从此断头）。接法：自写 AshMaterialHook 三钩子（on_root 兜底 / on_material 转换 / on_spawn_mesh_and_material 插组件）逐字同构官方语义，注册进 `GltfExtensionHandlers`；材质转换不手写——直接调官方 pub 函数 `standard_material_from_gltf_material`，30 余字段不吃自抄漏字段的亏。判定线全过；"hook 实际触发"诚实留待 3.1.2 兑现（没有资产加载就无从验证，不谎报）。

### 3.1.2 场景进场（三行代码 + 三个禁渲染补位）

进场本体只有三行（load + spawn WorldAssetRoot + 轮询到货）；肉在三个补位——都是 PbrPlugin/RenderPlugin 被禁后没人做、直到场景进场才炸出来的缺员：**资产根路径**（两种跑法皆到不了仓库根，`AssetPlugin.file_path` 编译期指根）、**ImageLoader 永久 Pending**（`TexturePlugin::finish` 被禁无人注册 loader，15 张贴图 handle 永远 Loading 且无任何错误日志——最深的一个）、**MeshMaterial3d 反射注册 panic**（WorldAsset 展开逐组件反射写入，注册点在连带禁用的 MaterialPlugin 里）。3.1.1 的 hook 触发验证在此兑现：primitive 6/6 带材质、6 材质 15 贴图入库。附带机制注记：on_root 兜底材质不驻留容器（无引用标注子资产随加载清退）——容器 6 而非 7 是健康态。

### 3.1.3 相机与灯光（引擎层自建 + 第四补位）

**引擎只搭台，不代建演员**：Camera 与 DirectionalLight 实体从来是场景代码自己 spawn 的（bevy 连 Unity 那种"模板代建"都没有），资产侧也指望不上（glTF 只有灯光扩展、没有相机概念）。裸 Camera 三件套不用 Camera3d——携带的渲染族组件全是死重，我们只消费从哪看（GlobalTransform）/ 怎么投（Projection）/ 活没活（is_active）。环境光真身订正：0.20 里 `AmbientLight` 已是相机组件（`#[require(Camera)]`），全局真身 = `GlobalAmbientLight` 资源（LightPlugin 预插默认亮度 80）。**第四补位 = 宽高比**：维护者 `camera_system` 住渲染族被禁，宽高比会永远停在初值 1.0——spawn 按主窗口写初值 + Update 幂等修正。取景参数抄官方 FlightHelmet 示例（`CAMERA_POS`/`CAMERA_TARGET` 常量），**同源是为了 3.5 同屏对照可比**。相机/灯光解耦成组（用户定案）：组 = spawn + 核验（+专属修正），组间零耦合，任意搭场景 = SceneEntryPlugin 组清单增删。

### 3.1.4 采集系统（PostUpdate 帧末直读 + CollectedScene 快照）

官方 Extract 缺位后，"渲染侧要从 ECS 拿数"改由我们在主 World 自己拿：**钉在 PostUpdate、排传播链之后**——Update 读 `GlobalTransform` 会差一帧，帧末直读拿到的才是本帧终值。快照**只带拓扑不带内容**（entity + 双柄 + 终值矩阵）：内容读柄去 `Assets` 容器取（禁渲染后主世界数据常驻），与官方 Extract 只抽 Handle + 变换同构；增量/脏标记的复杂度不先付（步骤 4 的活）。空帧容忍是正常态不是失败（两 Tier 落点：异步到货静默等、10s 凑不齐 warn 一次）。传播契约核验 0.0000°——FlightHelmet 六节点全恒等的诚实边界，非恒等父链 3.4 由画面判定。**收官讨论触发结构订正：draw_frame 自 Update 挪 Last**——"N 帧末采、N+1 帧初画"是单线程宿主里的伪流水线纯支出，挪后同帧 relay（Update 变更 → PostUpdate 传播+采集 → Last 提交），与官方 bevy 未开流水线同形。两处 API 订正：`TransformSystems::Propagate`（0.20 唯一变体）、`to_matrix()`（旧名 compute_matrix）。

## §6 给 3.2 的接口

1. **输入已就绪**：`CollectedScene.mesh` 柄 → `Assets<Mesh>`（禁渲染后主世界数据常驻，读柄即得）——3.2 的第一件事就是把这批柄的内容（顶点交错重排 pos+normal+uv）送进上传 pending；快照每帧重建，增量/脏标记归步骤 4；
2. **边界已钉**：帧循环生长只动 `host.rs` 编排 + `frames.rs` 录制段，`draw_frame` 函数名与"编排住 host.rs"承诺不变；main 冻结只许增删 add_plugins；新模块照 scene/ 样式自含插件落位；
3. **方法论可复用**：遇到"官方在渲染族里做 X"，先查 `finish` 钩子（TexturePlugin::finish 先例）；空帧容忍是正常态不是失败（两 Tier 纪律延续）；
4. **挂账**：开工首图 = 施工计划 §2 图按同帧 relay 重制（tech-illustration 全验证流程，旧图已标存档）；3.3 兑现验证层（装 Vulkan SDK）+ `CompressedImageFormatSupport` 按实际查询的 VkFormat 改写。
