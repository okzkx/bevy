# 描述符索引特性族：能力位全景、三层配套与限额双轨

> 2026-09-28。3.3.2 特性与限额开工前的讨论沉淀。起点是一个问题："这些开关看起来都是在关掉安全性校验？"——结论是只有一半对，而这另一半恰好决定了 3.3.2 该启用哪些位、查哪些限额。本篇不产出代码，产出是 3.3.2 施工时的**启用位清单与限额对账表**的依据。

## 0. 判定线

**特性位不是"关掉安全校验"，而是两件不同的事：能力分级 opt-in（不启用就根本无法表达，谈不上安全与否）与默认契约的显式放宽（把"绑定即冻结"的默认保护换成应用自负的资源生命周期责任）。两类都不触碰验证层执法——VUID 全程照收，前置闸门组 D 已经实证。**

把任务清单里点名的开关按此分成两类：

| 开关 | 类别 | 放弃了什么默认保护 |
|---|---|---|
| `runtimeDescriptorArray` | 能力类 | 无——纯表达力（无长度数组），不启用连 SPIR-V 都不合法（VUID-04680） |
| `shaderSampledImageArrayNonUniformIndexing` | 能力类 | 无——纯表达力（非一致下标），不启用则一组线程必须同下标，bindless 无意义 |
| `descriptorBindingSampledImageUpdateAfterBind` | 契约类 | 默认模型保证"set 绑进 command buffer 后内容冻结"；UAB 允许运行中改写，**于是应用第一次有合法手段制造"覆盖正被读取的槽"的竞态**——这个责任转移给 3.3.4 的发布纪律 |
| `descriptorBindingPartiallyBound` | 契约类 | 默认模型保证"set 里所有描述符合法有效"；partially bound 允许空槽存在，合法性条件从"全部有效"收缩为"不访问就不违规" |

所以"关掉安全性校验"的说法要修正为：**能力类开关和安全性无关；契约类开关不是关校验，而是换契约**——验证层对旗标配套、feature↔capability 一致性的执法一点没少（VUID-03000、VUID-08740 都是这类执法的实锤），真正松动的是**时序安全**：默认契约下应用不可能写出"改写正被读取的描述符"，UAB 之后可能了，防它的不再是 API 默认而是我们自己的槽位纪律（不覆盖 pending draw 可能读的槽、最后使用完成再回收——3.3.4 任务清单已钉）。

## 1. 为什么 Vulkan 要这样设计

默认模型：draw 前 `vkCmdBindDescriptorSets` 绑定即生效，驱动可以按"内容冻结"自由优化（描述符解析提前、按 set 缓存）。bindless 打破冻结：一张常驻大表初始化时绑一次，运行中随时塞新槽——驱动失去了冻结保证，就得走另一条慢一些的解析路径。

Vulkan 的处理方式是**不替你选**：两条路径都给，走哪条由 feature bit 在 device creation 时一次性声明。这符合 Vulkan 的一贯哲学——device 是能力契约的签署时刻，签了才有资格用；事后不能补签（device 不可变）。这也解释了为什么 3.3.2 必须排在 3.3.3 之前：layout 的 `UPDATE_AFTER_BIND` 旗标会回头查 feature（VUID-08740 的执法方向之一），device 建完再想开就只剩重建一条路。

## 2. 特性族全景：总开关 + 20 个分位

descriptor indexing 在 1.2 进核心：`VkPhysicalDeviceVulkan12Features` 里挂着 1 个总开关（`descriptorIndexing`）+ 20 个分位（等价于旧 `VkPhysicalDeviceDescriptorIndexingFeatures`）。**进核心只是"结构体存在"，每个分位默认仍为 0，支持与否依设备而异，必须查询 + 显式启用。**

总开关只做两件事：宣告"本设备支持 descriptor indexing 家族"；作为其他 20 位不为 0 的前提。**它自己不解锁任何行为**——任务原文"descriptorIndexing 不代替具体特性"指的就是这个。

20 个分位按职能分四组：

### 2.1 NonUniform 按类型七位

"数组的下标可以每线程不同"是**按描述符类型**逐位授权的：

| 特性位 | 对应类型 | 本项目 |
|---|---|---|
| `shaderSampledImageArrayNonUniformIndexing` | 采样图像**与采样器**数组 | **启用**（set0 b0/b1 的下标都是逐 draw 数据） |
| `shaderUniformBufferArrayNonUniformIndexing` | UBO 数组 | 不需要（set1 是单个 UBO） |
| `shaderStorageBufferArrayNonUniformIndexing` | SSBO 数组 | 不需要 |
| `shaderStorageImageArrayNonUniformIndexing` | storage image 数组 | 不需要 |
| `shaderInputAttachmentArrayNonUniformIndexing` | input attachment 数组 | 不需要 |
| `shaderUniformTexelBufferArrayNonUniformIndexing` | uniform texel buffer 数组 | 不需要 |
| `shaderStorageTexelBufferArrayNonUniformIndexing` | storage texel buffer 数组 | 不需要 |

纹理和采样器两种数组共用一个位：SPIR-V 侧也只有一枚 `SampledImageArrayNonUniformIndexing` capability，闸门组 B 实证采样器取数的 NonUniform 装饰补丁后合法（spirv-val + 设备双过），说明规范把两者绑在同一枚下。

### 2.2 DynamicIndexing 按类型三位

"数组的下标可以是变量（但全组一致）"——大多数类型**默认就允许**，只有三类例外需要位：`shaderInputAttachmentArrayDynamicIndexing`、`shaderUniformTexelBufferArrayDynamicIndexing`、`shaderStorageTexelBufferArrayDynamicIndexing`。**采样图像/SSBO/UBO 数组的动态一致下标不需要任何特性位**，本项目用不到这三位。

这组存在的意义是画出两级的分界：一致动态下标（免费）→ 非一致动态下标（NonUniform 位）。

### 2.3 UpdateAfterBind 按类型六位

"绑后可改写"也是**按描述符类型**逐位授权的：

| 特性位 | 对应类型 | 本项目 |
|---|---|---|
| `descriptorBindingSampledImageUpdateAfterBind` | SAMPLED_IMAGE | **启用**（纹理表 b0 运行中发槽） |
| `descriptorBindingUniformBufferUpdateAfterBind` | UNIFORM_BUFFER | 不需要（set1 UBO 每帧整 set 更新/重绑，不走 UAB） |
| `descriptorBindingStorageImageUpdateAfterBind` | STORAGE_IMAGE | 不需要 |
| `descriptorBindingStorageBufferUpdateAfterBind` | STORAGE_BUFFER | 不需要 |
| `descriptorBindingUniformTexelBufferUpdateAfterBind` | UNIFORM_TEXEL_BUFFER | 不需要 |
| `descriptorBindingStorageTexelBufferUpdateAfterBind` | STORAGE_TEXEL_BUFFER | 不需要 |

值得注意的**缺位**：清单里没有 SAMPLER 类型——SAMPLER 描述符的 UAB 不需要任何特性位（03003～03008 的 VUID 清单只覆盖上面六类）。这与闸门实测素材互证：我们的采样器表 b1 带同样的 UAB+PARTIALLY_BOUND 旗标组合，规范层面没有单独的门槛。此条为 VUID 清单缺位推得，3.3.2 施工时以实测收账（建带 UAB 旗标的 sampler binding 跑一遍验证层即可）。

### 2.4 通用四位（不分类型）

| 特性位 | 职能 | 本项目 |
|---|---|---|
| `runtimeDescriptorArray` | 允许描述符数组不带固定长度（SPIR-V `OpTypeRuntimeArray`） | **启用**（路线已定 runtime+补丁器） |
| `descriptorBindingPartiallyBound` | 允许 binding 带空槽，只要不被访问 | **启用**（3.3.4 fallback 槽的前提） |
| `descriptorBindingUpdateUnusedWhilePending` | 允许改写"可证明未被在飞命令使用"的描述符（不用 UAB 旗标的 binding 上） | 不需要——我们直接走 UAB 旗标，它管的是没走 UAB 的场景 |
| `descriptorBindingVariableDescriptorCount` | 建 set 时才定容量 | 不用（固定容量），见 §5 |

**本项目启用清单 = 1 总开关 + 4 分位**：`descriptorIndexing`、`runtimeDescriptorArray`、`shaderSampledImageArrayNonUniformIndexing`、`descriptorBindingSampledImageUpdateAfterBind`、`descriptorBindingPartiallyBound`。与闸门组 C "设备五位全支持"的实测对上。其余 16 位不启用，但按 D1 惯例**支持值照查照打日志**——3.4 若要 SSBO 大表，查已查过，只差启用。

## 3. 三层配套：一个 UAB binding 的完整资格链

feature bit 只是三层中的第一层。一个"绑后可改写"的 binding 要合法，三层的旗标必须同时到位，缺一层验证层就开抓：

```
device 层   VkPhysicalDeviceVulkan12Features.descriptorBindingSampledImageUpdateAfterBind = 1
   ↑ 执法：VUID-08740（capability↔feature，闸门组 D ② 实锤）
layout 层   VkDescriptorSetLayoutBinding.flags |= UPDATE_AFTER_BIND
            且 VkDescriptorSetLayoutCreateInfo.flags |= UPDATE_AFTER_BIND_POOL_BIT
   ↑ 执法：VUID-03000（binding 旗标 ↔ layout 创建旗标，组 C 首跑被抓实锤）
pool 层     VkDescriptorPoolCreateInfo.flags |= UPDATE_AFTER_BIND
```

（PARTIALLY_BOUND 旗标同构：feature 位 `descriptorBindingPartiallyBound` + binding 旗标 + layout 创建旗标 `UPDATE_AFTER_BIND_POOL_BIT`，pool 层不要求——partially bound 不涉及 pool 的绑后分配语义。）

闸门记录的定案"旗标三层配套在 3.3.3 施工时照此全套"就是这张图：**3.3.2 只负责 device 层 + 把这三层对应关系钉死，后两层是 3.3.3 的施工内容**。写成文档是因为它们是跨任务的契约——3.3.3 建 layout 时若漏掉任何一层，报错的 VUID 指向的可能是另一层的缺失，不预先记下排查就要绕弯。

## 4. 限额双轨：UAB 有一套独立的账本

描述符限额是**双轨制**：普通轨道（`maxPerStageDescriptorSampledImages` 等）与 UAB 轨道（`maxPerStageDescriptorUpdateAfterBindSampledImages` 等）**分开记账、互不挪用**。带 UAB 旗标的 set 只查 UAB 轨道——哪怕 UAB 轨道限额比普通轨道更小也不许越界。1024 候选容量对的是 UAB 轨道的账。

本项目相关的 UAB 轨限额（3.3.2 逐项实查落账）：

| 限额 | 记什么 | 对应 |
|---|---|---|
| `maxPerStageDescriptorUpdateAfterBindSampledImages` | 每着色器阶段 | b0 纹理表容量 |
| `maxDescriptorSetUpdateAfterBindSampledImages` | 每个 set | b0 纹理表容量（同一张表的第二道闸） |
| `maxPerStageDescriptorUpdateAfterBindSamplers` | 每着色器阶段 | b1 采样器表容量 |
| `maxDescriptorSetUpdateAfterBindSamplers` | 每个 set | b1 采样器表容量 |
| `maxUpdateAfterBindDescriptorsInAllPools` | 所有 UAB pool 总额 | 两表之和的池级上限 |

三个核对要点：

1. **数组容量按元素计**：1024 个纹理槽 = 1024 个 sampled image 描述符，不是"1 个 binding 算 1 个"。
2. **每阶段与每 set 是两道独立闸**：容量必须同时 ≤ 两者（fragment/vertex 各自算一次每阶段账）。
3. **普通轨道的实测素材不作数**：README 待决区已记本机 `maxPerStageDescriptorSampledImages = 1048576`，那是普通轨道——UAB 轨道要另查，多数实现两者同值，但不能靠猜。

## 5. PARTIALLY_BOUND 与 VARIABLE_DESCRIPTOR_COUNT 的边界

**partially bound**：带此旗标的 binding 允许部分槽从未写入。合法性条件唯一——**shader 不访问空槽就不违规**。访问了就是未定义行为，验证层不保证能抓（空槽里是垃圾还是留空是实现相关）。这决定了 3.3.4 的两条纪律：空槽要么由 fallback 槽填上有效资源，要么发布侧暂缓 draw。

**variable descriptor count**：解决的是另一个问题——"建 set 时才定容量"（free list 按实际用量缩放）。它不是本项目的需求（固定容量 1024 是拍给设计的），且有两条硬约束使它更不适合我们：

1. 只能放在 set 里**编号最高的 binding** 上；
2. 一个 set 只能有**一个** binding 用它——set0 有 b0 纹理、b1 采样器两个数组，想同时用都不行。

固定容量路线下这两条约束根本不会触发，但写下来是因为它解释了 set/binding 表冻结时的一个设计事实：**两个数组并列的布局事实上排除了 variable count 路线**，未来若要改成 variable count，动的不只是分配代码还有 set 结构。

## 6. 与 naga 补丁器的对应：capability ↔ feature 的名字映射

闸门定案的补丁器往 SPIR-V 插两枚 capability + 一条扩展；device 侧 3.3.2 启用的 feature 位与之**同名对偶**，执法由 VUID-08740 闭环（模块声明 capability 而特性未启用 → 收账，组 D ② 实锤）：

| SPIR-V capability（补丁器插） | Vulkan feature（3.3.2 启用） |
|---|---|
| `RuntimeDescriptorArray` | `runtimeDescriptorArray` |
| `SampledImageArrayNonUniformIndexing` | `shaderSampledImageArrayNonUniformIndexing` |

（第三枚 capability `ShaderNonUniform` 由 naga 自动声明、不需要补丁器，它只是 NonUniform 装饰的声明性挂载；非一致访问本身的合法性由上表的 per-type capability↔feature 对执法。）

这张映射表的意义：**补丁器和 feature 启用是一个整体的两半**，改任何一边（比如未来加 SSBO 数组）都要同步另一边，检查点就是 VUID-08740——验证层已经替我们把它变成了自动化对账。

## 7. 3.3.2 施工落点清单

1. `vulkan/context.rs` 扩 feature 链：`Features2` + `push_next(VkPhysicalDeviceVulkan12Features)`，置 §2 的启用清单（1 总开关 + 4 分位）。
2. 查询阶段照 D1 惯例：20 个分位的支持值全部打日志（不启用≠不查），总开关不支持则 Tier② 退出并报真实值。
3. 实查 §4 的五项 UAB 轨限额，落账到本段文档，与 1024 候选对账——不够则容量下调并回填 set/binding 表文档。
4. SAMPLER-UAB-无需特性位的推论以实测收账（建 UAB+PARTIALLY_BOUND 旗标的 sampler binding 过一遍验证层）。
5. §3 三层配套表作为 3.3.3 的输入留给面板引用。
