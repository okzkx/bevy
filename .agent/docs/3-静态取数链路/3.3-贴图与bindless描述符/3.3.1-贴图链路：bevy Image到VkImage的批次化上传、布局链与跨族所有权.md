# 3.3.1-贴图链路：bevy Image到VkImage的批次化上传、布局链与跨族所有权

> 2026-09-28。3.3 任务 3.3.1 施工记录。目标（README 任务清单）：`Assets<Image>` → VkImage/view/sampler，
> 核对格式与使用角色，base color 走 sRGB 解码、数据贴图走线性；读取 sampler 设置，静态 mip0；
> 上传沿用 3.2 票据，补图像子资源范围、布局转换、跨族 release/acquire 与 shader-read 依赖；
> 依赖按真实访问建立，不套 buffer barrier 模板。

## 0. 判定线

**贴图随 3.2 合批链一次性进场：一帧的 mesh + 贴图合成一个 staging 范围、一次 transfer 提交、
一张票据；图像段自录屏障（UNDEFINED → TRANSFER_DST →（拷贝）→ SHADER_READ_ONLY，带 release
时合成为一条屏障），不套 buffer barrier 模板；探针四组 + 宿主实跑在验证层与同步验证下
目标路径零 VUID。**

三条机制约束（显存机制篇 §0）全部落进实现并各有实测证据：

1. **OPTIMAL tiling 内容不能按字节读写**——上传走 `vkCmdCopyBufferToImage`（紧 packing，
   行距由驱动按格式推导），读回走 `vkCmdCopyImageToBuffer`；组 B 读回逐字节一致 =
   copy 引擎完成 swizzle 重排且字节无损的双向证据。
2. **image 分配独立于 MeshPool**——`GpuImage` 每张 dedicated `VkDeviceMemory`
   （M2 形态，`maxMemoryAllocationCount` 本机 4096 余量充足；memory 层子分配等显存压力出现再立）。
3. **布局转换与 buffer 读写次序是两类问题**——图像段屏障携带 old/new layout 与
   COLOR/mip0 单层子资源范围，uploader 里与 buffer 段分开录制。

## 2. 关键决策

1. **格式与角色：以 `texture_descriptor.format` 的 Srgb 后缀为准，不二次推断。**
   glTF loader 已按 texture 语义决定 sRGB/线性（bevy_gltf/src/loader/mod.rs:1210
   `is_srgb = !linear_textures.contains(..)`），落到格式名上。本层映射
   `Rgba8UnormSrgb → R8G8B8A8_SRGB`、`Rgba8Unorm → R8G8B8A8_UNORM`，其余格式显式拒绝
   （Tier① warn 一次跳过）——"核对格式与使用角色"的核对就是这一步。
2. **`ImageSampler::Default` 的解析：按官方 ImagePlugin 全局默认，不发明新默认。**
   出处 bevy_image/src/image.rs:181（`ImagePlugin::default()` = `ImageSamplerDescriptor::linear()`）
   ——禁渲染宿主里 ImagePlugin 的全局默认没人注册，本层照常量解析并落代码注释；
   `Descriptor(d)` 透传。VkSampler 侧 `max_lod = 0` 钉死可采样 LOD（静态 mip0 模式，
   覆盖描述符默认的 32）；anisotropy 不开特性、一律不启用。
3. **mip 策略 = 静态 mip0**：只收单级贴图（带 mip 链的数据 Tier① 拒绝，避免解析
   `TextureDataOrder` 排布只取 level 0 的复杂度），usage 三用途
   `TRANSFER_DST | TRANSFER_SRC | SAMPLED`——TRANSFER_SRC 是显存机制篇读回条款的载体，
   创建时按 optimal tiling features 逐一核对（mandatory 格式也要查过才用）。
4. **贴图与 mesh 同帧合批**：一个 staging 范围 + 一次 transfer 提交 + 一张票据，
   批内日志一条（"mesh 6 个 + 贴图 15 张"）。贴图身份从材质五槽解引用（快照只带拓扑
   的 3.1.4 契约不破），与 mesh 柄一样走"驻留缓存查无此身份才上传"的去重纪律。
5. **跨族 release/acquire**：release 挂产方（transfer）提交末尾——与 buffer 侧 3.2 预演
   同形状；acquire 挂消费方提交（图形侧），3.3.3 描述符表接线时落地。本任务的 acquire
   全链由探针组 C 实证（§3），并钉出配对语义（§5 坑 ②③）。

## 5. 新钉号与坑

1. **wgpu-types 直接依赖**：`TextureFormat/TextureDimension/Extent3d` 真身在
   `wgpu_types`，bevy_image 只是私有 `use` 不再出口——`bevy::image::TextureFormat`
   路径不存在。ash_renderer 增 `wgpu-types = { version = "30.0.1", default-features = false }`
   （lock 内已有，版本对齐 bevy_image 同款）。
2. **VUID-vkCmdCopyImageToBuffer-srcImageLayout-01397**：读回的源布局不收
   SHADER_READ_ONLY——必须先迁入 TRANSFER_SRC（首跑实抓，组 B 的迁入/迁回屏障对因此存在）。
3. **所有权转移屏障按"对"生效**：release 与 acquire 必须声明**同一对 old/new**——
   图形侧 acquire 以转换前布局为旧态重新声明（`TRANSFER_DST → SHADER_READ_ONLY`），
   而不是想当然地写"当前已是 SHADER_READ_ONLY"。声明成后者会被布局跟踪判为
   "当前仍是 TRANSFER_DST"（首跑实抓）。配对语义：转换由 release+acquire 这一对
   共同表达，接收侧重新声明同一转换。
4. **`ImageFilterMode` 的 default 是 Nearest（本 fork）**——`ImageSamplerDescriptor::default()`
   ≠ 官方 ImagePlugin 默认（linear），解析 `ImageSampler::Default` 时必须用
   `ImageSamplerDescriptor::linear()`，不能 `..Default::default()`。
