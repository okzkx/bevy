# 3.4.1～3.4.5-管线与绘制施工记录：正式着色器、图形管线与DrawList同帧消费

> 2026-09-29 施工，feat + docs 双提交。对应[任务面板](README.md)与[主计划](../施工计划：Bindless起步五段拆解.md) §3 施工 3.4。
> 本段是**第一次在正式帧循环画出完整 FlightHelmet**——清屏循环长成绘制帧。

## §0 判定线收账（先看结论）

1. **几何完整可核对**：FlightHelmet 六个 primitive 全部画出，贴图/轮廓/取景与[官方 color_grading 示例](#§7-朝向定案：正高度-viewport（教科书直觉的反例）)同相机对照同向（[_assets/helmet-debug-first-render.png](../_assets/helmet-debug-first-render.png)）。
2. **深度与变换正确**：盔体自遮挡正确（软管绕到木座后方、面罩在前）；非均匀缩放 (1.6, 0.7, 1.2) + Y 轴 0.6rad 旋转下几何、法线光照、自遮挡全部正常（[_assets/helmet-nonuniform-scale-rotated.png](../_assets/helmet-nonuniform-scale-rotated.png)）——法线用 cofactor 矩阵（§2），非 reverse-Z 的 LESS 混用。
3. **颜色空间恰一次编码**：采样端 SRGB 贴图解码 → 着色全程线性 → 输出端 ROP 经 SRGB view 自动编码（§2.4）。
4. **同步验证实际执法**：全程 `VK_LAYER_KHRONOS_validation` + VkValidationFeaturesEXT 同步验证常开；定稿运行 + resize/最小化/退出全程**零 VUID/WARN**（§7）；验证环境缺失会响亮报错，不以零日志充数。
5. **架构落点**：main 只组装；编排住 host；录制住 vulkan/frames；管线住 vulkan/pipeline；DrawList 组装在 host（读快照+账本）、录制层只消费。回归：resize 重建（swapchain + 深度附件双双随尺寸重建）、最小化整帧让路、WM_CLOSE → 退出排空 → 反序拆除 → **bash wait 取退出码 0**。
6. **等待口径**：正常上传仍零逐批 idle；图形提交对上传数据的等待发生在 GPU 执行依赖处（timeline 信号量 @ALL_COMMANDS），CPU 不阻塞（§5.3）。
7. **两 Tier 延续**：DrawList 缺行（mesh/材质未驻留）= Tier① 暂缓重试；UBO 写失败/录制提交失败 = Tier② 优雅退出；record 非空却无池 buffer = 状态矛盾（录制路径 panic 退进程，比静默画空场景诚实）。

**边界**（未做、不冒充）：RenderDoc 工具验证仍无环境（承 3.3）；光照是调试 Lambert（分项对照归 3.5）；blend 关闭、四槽贴图（metallic/occlusion/normal/emissive）不进调试着色；运行时槽位淘汰归步骤 4。

## §1 本段长出来的三件套与数据流

```
PostUpdate  collect_scene（3.1.4 快照：entity+双柄+终值矩阵）
Last·flush_uploads（3.2/3.3，先行）  快照去重→合批 transfer 提交→票据 #N
Last·draw_frame（本段）：
  resize 闸门（swapchain + 深度附件双双按需重建）
  → wait_for_slot（帧 fence）→ acquire
  → 组装 DrawList：快照 × MeshPool 驻留账本 × ImageCache 槽位 × 材质 base_color
  → 相机 get_clip_from_view × view → 写本帧槽 UBO
  → record_frame：清屏 + 逐 draw push/draw_indexed，提交等 image_available + 上传票据
  → present
```

新增/改动的模块：`vulkan/pipeline.rs`（新）、`vulkan/frames.rs`（深度附件 + record_frame）、`vulkan/swapchain.rs`（输出编码）、`vulkan/context.rs`（swapchain_mutable_format）、`vulkan/resources.rs`+`pool.rs`（CONCURRENT 池）、`examples/shaders/debug_draw.wgsl`（新）、`host.rs`（DrawList 编排）、`upload.rs`（共享族接线）。

## §2 正式着色器与三方布局冻结（3.4.1）

**`debug_draw.wgsl`**：@vertex 做坐标变换，@fragment 按 push 索引采样 base color 贴图 × 材质基色（线性域），调试方向光 Lambert + 环境。接口逐字段沿用 3.3 前置闸门冻结的 set/binding 表：set0 b0/b1 runtime binding_array（build.rs 补丁器补 capability，补丁后过 spirv-val）、set1 b0 每帧 UBO、`var<immediate>` push 96B。

**三方偏移互证**（"repr(C) 或低于 128B 不能独立证明对齐"的执法形态）：

| 字段 | WGSL PushParams | pipeline layout | Rust `pipeline.rs::PushLayout` |
|---|---|---|---|
| model: mat4x4f | 0 | range 0..96（VERTEX\|FRAGMENT） | `offset_of! == 0`（静态断言） |
| tex_index: u32 | 64 | （单一 range 覆盖全 96B） | `== 64` |
| sampler_index: u32 | 68 |  | `== 68` |
| base_color: vec4f | 80（align 16） |  | `== 80`，`size_of == 96` |

Rust 侧 `pack_push` 按偏移常量手工排字节（与 3.2 mesh_convert 的 to_le_bytes 纪律同款，不依赖平台内建序）。**教训一枚**：WGSL 块尾裸表达式（Rust 习惯）naga 不收，显式 `return`——build.rs 的解析错误现在带源码定位（`emit_to_string`），此坑 30 秒定位。

**顶点输入**：32B 交错（pos 0 / normal 12 / uv 24），与 3.2 `mesh_convert` 是同一份契约，pipeline.rs 只声明不另立。

**法线矩阵 = cofactor 矩阵**：WGSL 无 `inverse()` 内建。设 mat3 列为 a,b,c，则 (M⁻¹)ᵀ ∝ [b×c, c×a, a×b]（cofactor 矩阵），行列式倒数这个标量在 normalize 中消失——不除法、不带 det 符号陷阱，非均匀缩放正确。det=0（退化缩放）不在资产假设内。非均匀缩放验证见 §0.2 的截图证据。

**颜色空间链**（纹理格式与Gamma篇 §0 的落地）：glTF loader 已按用途把 base color 落在 R8G8B8A8_SRGB（采样时 TMU 解码）、数据贴图线性；着色器全程线性；输出端编码见 §2.4。

## §3 图形管线（3.4.2）与朝向定案

### 3.1 管线状态

dynamic rendering（color = swapchain view 格式，depth = D32_SFORMAT，见 §2.4/§4）、TriangleList、动态 viewport/scissor、光栅化 FILL + **剔除关**（M2：负向绕向核验未做 + HoseMat 双面 + 镜片按不透明覆盖，三者齐备后才选正面方向与剔除变体）、深度 test+write on、**compare GREATER + 清 0**（reverse-Z 成套，混 LESS 即错）、blend 关、1 采样、push range 96B。

### 3.2 输出编码：UNORM 底板 + SRGB view 别名（3.3 待决翻面）

定案沿既录推荐（wgpu/bevy_render 同构）：swapchain image 保持 B8G8R8A8_UNORM（DWM 母语），**view 套 B8G8R8A8_SRGB 别名当渲染附件**——写入时 ROP 自动做线性→sRGB 编码，blend 在编码前的线性域，present 直接读 image 本体不经 view。三件套合法性：① 设备扩展 `VK_KHR_swapchain_mutable_format`（context.rs 查支持+启用，缺一出局）；② swapchain 创建挂 `VkImageFormatListCreateInfo` 双格式清单 **且必须同时带 `SWAPCHAIN_CREATE_MUTABLE_FORMAT_BIT` 旗标**（首跑验证层实抓 VUID：viewFormatCount=2 而旗标为空 → swapchain image 不是 MUTABLE 形态 → 三个 SRGB view 创建全被拒）；③ SRGB 变体的 COLOR_ATTACHMENT 格式支持查过才用（证据落日志），不满足回退 UNORM 直出并响亮 warn。

### 3.3 朝向定案：正高度 viewport（教科书直觉的反例）

**定案：正高度 viewport 直出，不做 Y 翻转。**证据链（施工中实测，截图已入档）：

1. **E5 光栅级实验**（[_assets/e5-known-clip-probe.png](../_assets/e5-known-clip-probe.png)）：顶点着色器直出已知 clip 坐标（`vec4(position.xy * 0.8, 0.5, 1.0)`，绕过全部矩阵），模型本地 +y（盔顶）落在画面上半——**正高度 viewport 下 NDC +y 落屏上方**，矩阵变量被排除。
2. **应用侧矩阵取证**（E4 一次性日志，已删）：`get_clip_from_view() × global.affine().inverse()` 实测把世界上方映到 NDC +1.25（glam directx 变体源码与文档同证：Y-up NDC、Z ∈ [0,1]）。
3. **官方对照**：官方 `color_grading` 示例（同 FlightHelmet、同取景 (0.7,0.7,1.0)→(0,0.3,0)）wgpu 渲染与我们正高度直出**同向**。
4. **反例**：负高度 viewport（y=extent.height、height=−height——wgpu-hal 同款写法）渲染上下颠倒（[_assets/viewport-negative-inverted.png](../_assets/viewport-negative-inverted.png)），E5 同款实验同样翻转。

**诚实边界**：教科书口径（"Vulkan NDC Y 向下、负高度翻转"）与 wgpu-hal 30.0.1 的 `y = rect.y + rect.h; height = -rect.h // flip Y` 都与本机实测相反——wgpu 栈内必有别处补偿（或 wgpu 30 改了 NDC 约定），未深挖，超出 3.4 范围；以"E5 + 官方对照"为裁决，将来出现镜像/颠倒类症状先回本节。

## §4 深度附件（3.4.3）：按帧槽分配

**待决定案：帧槽 × `MAX_FRAMES_IN_FLIGHT`（2 张 D32_SFLOAT），不挂 swapchain image。**两份同步证据（面板要求"必须有同步证据，不把'归 Swapchain'当无冲突证明"）：

1. **并发不撞图**：在飞的两帧各用各的槽位深度，并发写不可能落在同一张图上；
2. **同图重用隔着 fence**：同槽深度的两次使用之间，`wait_for_slot` 在录制前 CPU 等到了上一轮提交的 fence（signaled = 全部命令完成）——冲突不存在是被 fence + 槽位隔离证出来的。

D32_SFORMAT 支持先查后用（optimal tiling DEPTH_STENCIL_ATTACHMENT，1.3 mandatory 仍不省查询，证据落日志）。**随 swapchain 尺寸重建**：`FramePool::rebuild_depth` 幂等（extent 没变空手而归），销毁旧深度前自带 device_wait_idle（在飞帧可能还引用旧深度），host 的 resize 闸门在 swapchain.rebuild 成功后紧接调用。布局纪律：每帧 UNDEFINED→DEPTH_ATTACHMENT_OPTIMAL（UNDEFINED 作 oldLayout = 声明旧内容不要，与 loadOp CLEAR 配套），storeOp **DON'T CARE**（深度从不读回，无出场屏障）。

## §5 record_frame 与 DrawList 同帧消费（3.4.4/3.4.5）

### 5.1 record_frame（清屏生长为绘制帧）

`record_clear_and_submit` → `record_frame`，录制序：颜色进场屏障（D6 形状不变）→ 深度进场屏障 → dynamic rendering（清屏 + 逐 draw）→ 颜色出场屏障 → 提交。提交等待列表：`image_available @ COLOR_ATTACHMENT_OUTPUT`（D6 语义不变）+ `上传票据 timeline @ ALL_COMMANDS`（值 = 已发出最高票据；票据 0 从未发生——fallback 批在 init 就提交——留形状完备分支）。**等待点语义**：顶点处理可与 acquire 重叠；上传数据的消费依赖发生在 GPU 执行处，CPU 不先阻塞（施工计划 §2，探针组 D 同款形状）。

### 5.2 DrawList（快照 × 账本 × 材质，同帧不跨帧）

host 侧每帧组装：快照行 → `pool.resident(mesh_id)` 取池引脚（vertex_base/first_index/index_count）→ `Assets<StandardMaterial>` 取 base_color（**to_linear**，线性域直进 push）+ base_color_texture → `image_cache.slots(tex_id)` 取槽位，缺贴图走 **fallback 槽 0**（面板：缺资源用有效 fallback 或暂缓，贴图缺不拦几何）；mesh/材质未驻留 = 该行暂缓（Tier①，上传链自愈后消失，日志去重）。**材质调试覆盖**（报一次即歇）：六 primitive 全部不透明绘制——blend 关、unlit 标志忽略、统一调试 Lambert；实测 6 行 alpha 均 =1（glTF BLEND 镜片的半透明在 bevy_gltf 转换后未落在 base_color.alpha，M2 不透明策略下无可见差异，如实记录）；镜片照画不丢弃。

### 5.3 跨族定案：CONCURRENT 双族共享（本段最大的取舍）

本机有专用 transfer 族 → 池与贴图都被 transfer 写、graphics 读。**定案：buffer 池与图像一律 CONCURRENT `{transfer, graphics}`，EXCLUSIVE 的 release/acquire 让渡在生产路径退役**（机制实证保留在 image_probe 组 C）。取舍：

- **为什么不用 EXCLUSIVE 乒乓**：池被 transfer 反复写、graphics 长期读，所有权乒乓需要"下一批 transfer 的 acquire 排在上一帧 graphics 的 acquire 之后"的跨队列排序链——只能拿信号量串，上传延迟 +1 帧再加一套状态机；图像侧虽是单次发布，但见下条。
- **压垮图像 EXCLUSIVE 的一根稻草**：09600 排障（§6）实证——EXCLUSIVE release/acquire 成对语义下，同步验证层对"已写入但未被本 draw 访问的 UAB 数组元素"的布局账本**不随 release 更新**，Draw-09600 保守断言污染目标路径（三轮 bisect：换等待列序无效、纯 timeline 等待无效、CPU 等票据完成仍报）。CONCURRENT 下无所有权语义，release/待办账本整套拆除，图像屏障族号一律 IGNORED（CONCURRENT 上显式族号被 VUID 拒，首跑实抓）。
- **可见性不放松**：transfer 写 → graphics 读的内存依赖由图形提交等票据信号量收口（ALL_COMMANDS 等待点的内存依赖）；bump 分配保证批次间写区间不相交，migration 前有 wait_all_uploads（池内已有）。
- 与 wgpu-hal 的资源创建同构（多族访问走 CONCURRENT 共享集）。

### 5.4 相机接线（3.5 任务 1 的"相机"半件提前）

`view_proj = projection.get_clip_from_view() * global.affine().inverse()`（与 bevy compute_frustum 同一乘序）→ `to_cols_array` 列主序 64B → 写本帧槽 UBO（写时机在 wait_for_slot 之后，在飞安全由帧 fence 担保——3.5 的"复用前等对应帧使用完成"对相机部分已生效）。相机缺席 = identity 兜底 + warn 一次（Tier①）。灯光/环境光仍归 3.5。

## §6 排障实录：Draw-09600 三轮 bisect（方法论钉子）

首跑 14 条 VK-ERROR，全部是 **VUID-vkCmdDraw-None-09600**（draw 的描述符布局断言：描述符声明 SHADER_READ_ONLY，验证层账本停在 TRANSFER_DST），错误数逐跑波动（9/10/12+2）且 acquire 屏障自身零点名。三轮受控实验：

| 实验 | 改动 | 结果 | 结论 |
|---|---|---|---|
| E1 | 票据信号量挪到等待列表第 0 位 | 依旧报 | 排除"binary 抢占 index 0 破坏链接" |
| E2 | 等待列表只留 timeline | 依旧报（还引出 WRITE_AFTER_PRESENT 族） | 排除混合等待列表 |
| E3 | 录制前 CPU 等全部票据完成 | 依旧报 | **排除"在飞 release 时序"——账本根本不认 release** |

关键观察：错误数 ≈ 已发布贴图数 − 被 draw 实际采样的 base color 数（10 ≈ 15−6±批次波动）——验证层对 UAB 数组"已写入但未访问"的元素做保守 09600 断言，而其布局账本在 EXCLUSIVE 让渡形态下不更新。**方法论**：探针组 C（release→等票据→acquire→**拷贝读回**）当时是绿的，但"acquire 后**经描述符采样**"这个组合从未被探针覆盖——探针形状与生产形状差一环，生产首跑才暴露。修复不是绕过验证（关同步验证 = 烧掉裁判），而是把资源共享模式改成 CONCURRENT（§5.3），从结构上消掉让渡。**新钉号：VUID-vkCmdDraw-None-09600 在 EXCLUSIVE 让渡 + UAB 数组下的验证层账本局限；CONCURRENT 图像屏障族号必须 IGNORED。**

同轮另收两案：swapchain 少挂 `MUTABLE_FORMAT` 旗标（VUID-07781 族，首跑实抓）；CONCURRENT 图像带显式族号的屏障被 VUID 拒（源族必须 IGNORED）。

## §8 边界与未决

- **RenderDoc 描述符可见性验证**（承 3.3 条款 3）：仍无环境，不冒充。
- **光照对照**：调试 Lambert 只服务几何/法线/深度判读；方向光/环境光 UBO 化与四类对照条件归 3.5。
- **背剔/绕向**：cull NONE 是 M2 材质策略（双面 + BLEND 覆盖 + 正高度下绕向未镜像）；开剔除时的 front face 判定与变体另立。

- 池的图形侧最后使用等待：M2 静态资产不淘汰、不扩容回收，账本归步骤 4；退出排空覆盖当前所有路径。
