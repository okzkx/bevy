# 写文档纪律：帧流程三轮返工的教训

> 2026-09-22。帧流程原理篇同日被推翻三轮（看不懂 → 漏核心原则 + 图误导 → 繁琐），本篇是返工沉淀的方法论，适用于本仓库所有 `.agent` 文档与配图。案例：《[2-宿主壳/帧流程：一帧之内各Vulkan对象如何接力.md](2-宿主壳/材料/帧流程：一帧之内各Vulkan对象如何接力.md)》。

## 0. 总原则

**先讲清机制，再上修辞；先立判定线，再铺细节；先预演读者，再动笔。** 三轮返工，每一轮都是这个顺序写反的代价。

## 1. 三轮各输在哪

| 轮次 | 用户反馈 | 病根 |
|---|---|---|
| 一 | 完全看不懂 | 比喻先行：自造"回执单 / 闸门 / 接力棒"黑话，读者得先学我的词汇再学 Vulkan |
| 二 | 原理懂了，但最重要的没写 | 判定线（CPU 只配置、不读取、无法感知信号量状态）埋在表格里，没立成明文；配图还把信号量画成回到 CPU 的箭头，与文字矛盾 |
| 三 | 繁琐，很多字没意义 | 同一事实换措辞说了三遍；砍 40% 字数，零事实损失 |

规律：两次差评都发生在我觉得"写得很完整"之后——**完整感与可读性冲突时，选可读性**。

## 2. 四条纪律（正文）

1. **机制先于比喻**：先写谁调用什么、谁置位、谁等待，再考虑修辞。比喻是理解后的奖励，不是理解的路径。自检：文档里的每个词能不能一一对回代码？
2. **判定线立 §0**：动笔前先问"这页的不变量是哪一句"，加粗放最前。表格是答案的集合，判定线才是组织方式——没有判定线，读者读完表格还得自己归纳，归纳不出就是你没写。
3. **对着读者的下一个问题写**：预演读者会卡在哪（"这两处为什么都在等它""没有代码激活"），把答案立成可引用的断言。按"我懂了什么"的顺序写，必然同时犯"太抽象"和"太啰嗦"。
4. **精简 = 删重复不删信息**：同一事实只出现一次，换措辞重说即删。初稿完成先做一遍"删重复"通读。

## 3. 配图纪律（技术说明图）

1. **图是断言**：每根箭头都有语义（数据流 / 控制流 / 登记关系必须区分），锚点从哪个框出发是主张——图错了读者会信，比错字严重；
2. 生成后三层验证：OCR 查错字（已知误报：帧→顿、渲染→染）、视觉查版式、**逐箭头审语义方向**；
3. 锚点钉死到框级别（如"栅栏线从 GPU 框顶边出发，不能从呈现引擎框出发"）——生图模型默认就近连线，约束不钉死就重掷；
4. 文字量：标签不超过两行，原则句放说明条、不塞进箭头。

## 4. 给后续的纪律

1. 动笔前列读者问题清单（用户上次问了什么、顺着机制还会问什么）；
2. 定稿前两道检查：先"删重复"，再"判定线是否立住"；
3. 配图走 tech-illustration 全验证流程，箭头语义审计不可省。
